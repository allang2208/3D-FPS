## 2. 装配（`Scripts/build.py`）

坐标系：源 +X 为枪口、+Z 向上、射手右侧在 -Y；宿主（`M4TacticalToss20260910/M4_Hand_MAT_Editable.blend`）为 +Y 向前、+Z 向上、+X 射手右侧。

- 变换：绕 Z 旋转 +90°，缩放 0.0242 m/单位（全长 34.68 单位 → 0.873 m），平移 `(0.0559, 0.16607, -0.04817)`。
- 锚点：**握把后缘对齐已认可的 M4 握把后缘、握把底对齐 M4 握把底**。由此枪机在 M4 扳机前方 6 mm 内（M4 扳机 Y=0.190，本枪 Y=0.1765），前握持区落在左手掌心（左手食指 Y=0.383，护木 Y=0.270–0.410）。
- 绑定：`v' = rest[bone] @ base[bone]⁻¹ @ base[root] @ xf @ v`，几何按零件刚性绑到 `WPN_root`；`WPN_SOCKET_Magazine` 移到本枪弹匣井、`WPN_Trigger` 移到本枪扳机（连通体 78，165 顶点）。参考姿态采样必须发生在骨骼定位**之后**——M4 的弹匣骨在动作里 basis 恒为 0，用定位前的采样绑定会把弹匣整体错位 26 cm（本轮已修）。
- 私有骨架标记：`WPN_RearSight`/`WPN_FrontSight` 置于提把导轨（源 X=-5.6 / +1.4，Z=4.26）、`WPN_SOCKET_Muzzle` 源 X=14.6、`WPN_SOCKET_Eject` 源 (4.5, -0.9, 1.3)（**位置未在引擎内核对**）。
- 游戏网格含 7 个材质槽：Upper / Lower / Front / Sights / Flash_Hider / Magazine / Magazine_Base（末两项命名含 `Magazine`、枪口含 `Flash_Hider`，供运行时按槽名隐藏）。

**暂未进网格的源分件**：垂直前握把（材质 12）、激光（15）与镜片（16）。它们保留在 `ASH12_Editable.blend` 中，留待改造配件工序按真实导轨装配。

## 4. 动作

`Scripts/build.py` 逐帧重采样已认可的 M4 动作并重打到本枪骨架，命名 `A_ASH12_<kind>`，60 fps 源 / 120 Hz 采样：

| 片段 | 源 | 时长 |
|---|---|---|
| idle | M4_idle | 3.0 s |
| aim | M4_aim | 0.033 s |
| fire / aim_fire | M4_fire / M4_aim_fire | 0.767 s |
| reload | M4_HK416_reload | 2.1 s |
| reload_empty | M4_HK416_reload_empty | 2.7 s |
| equip_charge | M4_HK416_equip_charge | 0.633 s |

换弹的左手位移按**弹匣井在机匣坐标系里的位移量**给出：本枪弹匣井比 M4 靠后 26.2 cm、靠上 5.6 cm，整个左臂按这个量平移，抓匣窗口 `reload` 为帧 10–104（空仓换弹已改为下节的斗牛犬编排，不再走这条路）。`reload` 仍沿用两个要点：

- 位移量取自**定位前的弹匣骨采样**与定位后的 rest 之差。用重采样后的 `base[socket] − to_fit(socket)` 会得到 0（参考姿态已在骨移动之后重采），位移会静默失效。
- 位移向量按**当帧**的机匣四元数旋转，不是 idle 的。空仓换弹枪身大幅旋转时，用 idle 方向会算错方向、手臂 IK 够不到目标。

### 实机反馈第五轮（2026-09-18，本轮定稿）：换匣手也按指节定位

用户反馈"最后改一次，不行就先搁置"。剩下最影响观感的一条是换匣段右手指节仍陷在枪托底 **63.6 mm / 246–353 个顶点**——与拉栓手同一类病因：腕点靠估值、手指是扳机指。

### 实机反馈第四轮（2026-09-18）：ADS 手糊脸、拉栓手没握上柄、关节扭曲

1. **ADS 里那"一坨手"是右上臂本身，不是手。** 量出真眼位到手部网格只有 **45.6 mm**（idle 里 10.7 mm），同时前臂/上臂有 **51–70 mm 陷在枪托里**。根因是几何的：本枪照门在提把中段，`ADSRearEyeDistance = 18 cm` 让相机比 M4 的 12 cm 眼位**再靠后约 14 cm**，正好坐进射手自己的上臂里；而斗牛犬枪托向后伸出 46 cm（M4 没有），已认可 M4 持握的右前臂本来就穿过它。
   **修法**：给所有片段（不只换弹）加一条**右臂极向量** `RIGHT_ARM_POLE (-0.95, 0.12, -0.26)`，用手臂 IK 把肘绕到枪托外侧——手不动，只重新解肘。实测 ADS 眼到手 **45.6 → 77.0 mm**、手臂进枪体 **51.6 → 6.0 mm**；idle 眼到手 10.7 → 34.6 mm。`render_ads_eyes.py` 可按眼距渲染 ADS 构图，`probe_ads_hands.py` 出这两个数。
2. **拉栓手确实没握上柄**：指尖（食指/中指第二三节）到拉机柄的距离实测 **98 mm**——手悬在柄外一个手掌远。原因是柄位一直按"腕点偏右下几厘米"摆，而这只手保持的是握把的卷曲姿态，**指尖相对腕点指向别处**。
   **修法**：改用**实测的腕→指节向量**反推腕位（`knuckle = index_01 − hand`，本机 0.098 m），腕点坐在柄后方 10.4 cm 处，指节正好落在柄上。实测指尖到柄 **98 → 30 mm**，同时手对枪体的穿透降到 9.9–19.1 mm（基线 19.8 mm）。
3. **手指不再是"伸出一根食指"**：那只手原来冻结的是 M4 握把姿态，食指沿机匣平放（扳机指），手一转过来就成了"戳出一根手指"。现在拉栓段套用 `HANDLE_FIST`（各指节绕局部 Z 收到 58/62/34°，与 M4 自身卷曲同一根轴），帧 98→110 收拳、帧 140→150 松开。
4. **关节扭曲**：手朝机匣转的 42° 原先全落在腕上。现在按 `TURN_SHARE = 0.6` 让前臂承担 60%、腕部只剩 40%（与滚转的 `TWIST_SHARE` 同一手法）。



### 实机反馈第三轮（2026-09-18）：换弹"太快"、拉栓手角度太高

**"太快"不是片段的问题，是技能加成。** 三件事依次查过：

1. **视频没有被加速**。视频 HUD 标称 400 射速（=0.15 s/发），逐帧跟踪弹药数字变化的中位间隔 0.133 s，两者一致——视频是实时的。
2. **参考的整段动作比我原先量的长**。用逐帧帧差剖面重新划边界：动作从 7.0 s 持续到 9.4 s，**约 2.4–2.9 s**（早先只量了 7.3–8.75 的"看得见手"的那段）。本片段 2.7 s，**基础时长本来就是匹配的**。
3. **实机多出来的速度来自 `巧手` 技能**：每级换弹速度 +1%，`FPSGAMECharacterProfile.cpp:116` 把它乘进 `EmptyReloadDuration`，播放速率 = 1 + 等级/100（50 级即 1.5×）。角色面板也写着"基础耗时 ÷（敏捷 × 快手 × 附魔）= 实际换弹时间；普通、空仓换弹均生效，动作与音效同步加速"。**要按 1.0× 对比视频，得看面板里的实际换弹时间或换一个没练巧手的档案。**

片段本身做的是**把快慢不均抹平**（`measure_pacing.py` 逐帧量手/弹匣/机匣的位移）：拉栓释放那一帧曾是峰值的 57.8%，而帧 98–114 只有 4–6%——眼睛比的是这些"冲刺"。改后：右手起手从帧 10 提前到帧 3（0.30 s 走完而不是 0.18 s）、拉动表提前到帧 108–133、回位拉到帧 152，帧 94–114 抬到 6.6–22%。

**拉栓改成从右侧侧向**：肘极向量从"外展+上抬"改成"外展+下垂"（`RIGHT_POLE` 帧 108–140 `(-0.92, 0.25, -0.30)`），再给这只手加一个**朝向偏转**（`RIGHT_HAND_TURN` 帧 108–140 绕机匣上轴 42°），因为手冻结的是握把的持握卷曲、不改朝向就像"把手掌拍在机匣顶上"而不是从侧面抓柄。改后手落在机匣右肩（机匣局部 `(-0.05, -0.03, 0.07)`）、前臂从侧下方上来；网格穿透 27–42 mm（基线 19.8 mm）。


### 实机反馈第二轮（2026-09-18）：看不见换匣、拉栓穿模

用户报"弹匣卸下和装上时几乎看不到动作"、"拉栓时手穿模"。两条都先用**可量的指标**定位，再改，改完复测：

- **弹匣可见度**：从游戏真眼位（ADS 标定反推：照门后 18 cm 沿瞄准轴，`probe_reload_visibility.py`）向弹匣顶点投射、统计首命中面是否为弹匣。改前**帧 14–34 是 0%**（弹匣完全被枪托挡住），全程最高 40%。
- **枪身姿态扫描**（`sweep_mag_visibility.py`）：滚转是唯一有效变量——15° 以下全看不见，30° 约 17%，45° 约 26%，60–90° 到顶约 30%；俯仰（枪口上抬）**帮不上**。**30% 就是上限**：斗牛犬弹匣只有下部约 35% 露在枪托外，其余本来就在托内。
  结论：滚转必须在**换匣段就到位**（45° 上下），不能等到后段。改后帧 21 24%、帧 34 63%、帧 42–48 **97.6%**、帧 54 66%，出匣与入匣全程可见。
- **穿模**：把手臂**网格**顶点对枪体做深度统计（早先只探骨骼原点，量不出问题）。改前拉栓段（帧 104–136）最深 **116 mm**、585–963 个顶点在枪内；根因是 `shift_arm` 的肘位继承已认可持握的高肘，前臂直接穿过机匣。给 `shift_arm` 加**极向量提示**（`RIGHT_POLE`：取匣段肘朝下后方、拉栓段肘外展到射手右侧）后，拉栓段降到 **18.8 mm / 655 顶点**，与已认可 idle 自身的 19.8 mm 同级。
  量具注意：`BVHTree.find_nearest` 的法线朝内判据在离表面远的点会误报（左前臂在机匣外 0.14 m 也被判"内部"），奇偶射线判据在这套非流形网格上同样不稳——只用**相对量**（与已认可基线的比值）下结论。

**仍未解决**：换匣段右手手指（`index_03_r`）仍陷进枪托底约 63 mm——手指冻结的是握把持握姿态，抓弹匣时指节朝向不对，属"腕向/手指"那一项。

### 参考的节拍（逐帧量出来的，第二遍按此改过）

用 HUD 弹药计数器定位硬时间：**7.73 s 仍是 0 发、7.80 s 变 20 发**，即新弹匣在 7.75 s 入位。整段换弹 7.30（右手离握把）→ 8.75（枪身回位）= 1.45 s，帧差检测确认无剪辑点。

| 参考时刻 | 占整段 | 在做什么 |
|---|---|---|
| 7.30–7.75 | 0–31% | 右手取换弹匣，**枪身只是斜着**（约 25–35°） |
| 7.75 | 31% | 新匣入位（计数器 0→20） |
| 8.0–8.6 | 48–90% | **枪身才深度侧滚**（60° 峰值在这里），右手这时才绕到机匣右侧够拉机柄 |
| 8.75 | 100% | 回位 |

**第二遍改的三处**（第一版把滚转放错了半段）：滚转从"帧 42 就冲到 60°、之后回落"改成随参考的形态——换匣段保持一个稳定的倾角、拉栓段最深；弹匣改成**紧凑换位**（全程不离手，不再掉出画面）；右手起手从帧 14 放缓到帧 10 起步、帧 21 到位。**第三遍**按用户实机反馈把换匣段的滚转从 22–34° 提到 44–50°（见上节的可见度测量）。

**时钟：机械音效的 cue 帧就是编排帧。** `bUseASH12` 走 `bUsingM4Infima` 分支，`MechanicalCueTimes` 为 `{21, 54, 80, 130}/60 s`，按**片段自身秒数**比较。因此节拍一律写在 M4 原始帧上：21 出匣、54 新匣到井口、80 压实（含 2.5°/8 mm 入位顿挫）、130 枪机释放。上一版为对齐参考节奏加的 `TIME_WARP` 把姿态整体推到 cue 之后（旧弹匣实际 44 帧才离井，比声音晚 0.38 s；压实晚 0.83 s），已删除。

**上一版查出的三个机械层缺陷**（都已改）：

1. 弹匣位移是**叠加**在基底动作上的，而 M4 空仓换弹自身就把 `WPN_SOCKET_Magazine` 甩出 0.7 m 的弧线——结果本枪弹匣在帧 48 跑到井下 0.55 m、帧 54 窜到左上后方 0.45 m。现在弹匣、枪机、拉机柄都按机匣局部坐标**整体改写**（`pose[bone] = pose["WPN_root"] @ Translation(...)`），不再继承。
2. 右手在基底里恒被钉在握把（接收器局部 `(-0.037, 0.107, -0.052)` 全程不动），现已改为作者路径。
3. M4 基底自身的枪身表演是野的（实测滚转：帧 18 −46°、帧 24 +101°、中段稳定 −50°）。叠加本枪的 60° 后实测到 141°，枪几乎翻过去。现在机匣**整体由本片段驱动**：取片段帧 0 的世界矩阵，再施加本片的俯仰/偏航/滚转/进退。

**做法（可复用）**：两只手都按帧 0 的**机匣局部矩阵**冻结（`holds[side]`，含手与五指），位置由作者路径给定、朝向保持在这把枪上的自然持握。这样 M4 片段自带的手部旋转与**手指开合**都进不来——上一版左手在护木上仍在做 M4 的取匣开合。手臂用现有 `shift_arm` 反解（它按当前姿态取骨长，所以必须在移位**前**调用）；滚转由前臂承担 `TWIST_SHARE = 0.55`，其余留在腕部，避免 60° 全压在一个关节上。

**可达性预算（实测，写路径前先量）**：右肩机匣局部 `(-0.001, 0.342, 0.207)`、臂长 0.550 m；左肩 `(0.347, 0.297, 0.010)`。护木上的支撑手在**已认可的 idle 里就已占 97%** 臂长，故 `LEFT_BIAS` 把护木抓点沿轨后移 2.4 cm 换取余量（帧 0 降到 93.7%）。右手向下最多只能到井口下方约 0.17 m，**弹匣下探量就是按这个上限定的 16.6 cm**；再深会超伸（`shift_arm` 会偷偷挪肩，属可见断裂），`build.py` 会打印 `ASH12_REACH_WARNING`。

**校验数值**（读回导出的 FBX 复测，`verify_reload_export.py`）：滚转帧 12 35.6°→帧 24–60 44–48°→帧 84 50°→帧 120 **61.3°**→帧 162 0.4°；弹匣位移帧 48 最深约 0.20 m（机匣局部、相对井口）、帧 84 归零；枪机全程保持 3.4 cm 后移、帧 120–132 被拉动、帧 138 复位；拉机柄帧 126 拉出 6.8 cm；弹匣可见度帧 42–48 97.6%；手臂网格对枪体最深 18.8 mm（已认可基线 19.8 mm）。

## 7. 未完成与风险

**未实测**：按用户规则，本轮所有内容（模型、装配、材质、动作、接入、数值）均未进游戏运行验收。用户首轮实测反馈了两项，见下。

### 用户反馈二：模型在引擎里扭曲粗糙——根因是硬边全丢（已在源侧修复）

对比源模型与导出网格的自定义法线（同一顶点上不同 loop 法线的最大夹角、>25° 记为硬边）：

| | 自定义法线 | 最大夹角 | 硬边对数 |
|---|---|---|---|
| 源 `weapon.FBX` | 有 | 180° | 113,832 / 418,169 |
| 本任务首次导出 | "有" | **0.0°** | **0** |

即整把枪变成**全平滑着色**，所有倒角、面板缝都不见了，观感就是糊 + 糙。原因在 `build.py` 的顺序：先 `normals_split_custom_set()`、后 `use_smooth = True`——在平面着色的多边形上设自定义法线会被 Blender 丢弃。改成先平滑再设法线后，导出网格的硬边恢复为 96,128 对、最大夹角 180°（数量按本轮丢弃的分件等比减少）。**该修复尚未写入引擎**（见「待办」）。

### 用户反馈三：光学瞄具下的 ADS 可能偏

共享瞄具的挂点公式把瞄具鞍座放在「照门标记线下方 3.2 cm」——这是 M4/QBZ 的标记高度约定（它们的照门标记在导轨之上）。本枪的标记是量在**提把导轨面**上的，所以照 M4 的常数挂会把瞄具压进提把 3.2 cm，开镜随之偏。已加入按枪取值的 `ASH12WeaponAssets::OpticRailDrop = 0`。**同样待编译生效。**

### 用户反馈一：ADS 里枪身歪——根因是模型自带 4.7° 滚转

用户反馈"弹孔落在准心上，但开镜时枪是歪的"——这句把范围锁死在**纯视觉滚转**上。三条独立测量一致（面积加权法线是主判据）：

| | 枪身上表面相对世界竖直（瞄准姿态） | 相对照门标记骨骼的"上" |
|---|---|---|
| M4（已认可基准） | **−0.03°** | −0.03° |
| 本枪（修正前） | **+3.92°（向右倾）** | +3.92° |

根因：源模型**枪身相对它自己的瞄准标记线就带 4.7° 右倾**。我按"枪口 +Y、上方 +Z"对位时把这个斜度当成正的绑了进去；而 ADS 标定只把视线轴对齐、不约束滚转（代码里那段 `FindBetweenNormals` 只映射一个轴），所以开镜时玩家是顺着一条斜的枪身看出去的。髋位下同样是斜的，但不开镜时不容易察觉——与用户"特别是 ADS"的描述一致。M4 的绑定自身抵消了这个量，所以它瞄准姿态下是 0°。

**修法**：在 `build.py` 的装配矩阵里绕**握把接触点**（0.056, 0.117, −0.114）沿枪管轴反向旋转 4.7°，握持关系不变。修正后同一测量为 **+0.19°（aim）/ +0.72°（idle）**，与 M4 的 −0.03° / +0.37° 同量级。该修正在**网格绑定**里，属纯资产改动，不需要编译。

### 用户反馈一（上一轮）：ADS 眼距——已修

先排除了装配：装配矩阵只有绕 Z 的 90° + 缩放 + 平移，没有滚转/偏航；枪的视线轴在 idle 与 aim 姿态下均为水平 `(0.0008, 1.0000, −0.0001)`，与 M4 的约定一致。握把倾角差（M4 后倾 24.8°、本枪 −2.2°）也不会造成持枪姿态错误：以“手指根部连线 vs 握把长轴”衡量，本枪 149°、M4 基准 154°，已在 5° 内。

真正的原因是**开镜眼距**。新增实机静帧夹具 `Source/FPSGAME/ASH12IntegrationAudit.cpp`（`-ASH12SightCapture -ASH12Run=<名> -ColdSteelProfile=ASH12SightAudit`）会在实机里装上本枪、按 ADS、连拍 hip 与 12/18/24 cm 三档眼距：

- **12 cm（沿用 M4）**：相机贴在照门后方、正好卡在枪尾，画面里几乎只有枪的背部与腹部（弹匣朝下、提把在上），看起来就像枪竖着——这就是玩家看到的“歪斜”。
- **18 / 24 cm**：枪身水平、照门居中，与 QBZ 同夹具的参考画面（`Saved/QBZ191IntegrationAudit/ref/`）一致。

实机标定日志也证明标定本身没错：本枪 `GUNPLAY_ADS_CALIBRATED rotation=R(P=0.00,Y=89.96,R=0.01)`，与 M4/QBZ 的 `Y=89.99` 相同，轴都指向 −Y。

**结论与改动**：本枪照门在提把中段（M4 在机匣尾部），需要更大眼距，已把默认值改为 **18 cm**（`ASH12WeaponAssets::ADSRearEyeDistance`）。对比图在 `Saved/ASH12SightAudit/v2/`。
