# Super90 战术冲刺左臂修复：NativeHingeR2

用户反馈战术冲刺左手扭曲，要求按 SKILL 成熟案例排查并修复。本批只修改 Super90 的冲刺作者算法、三段基础动画和四份握把配置中的冲刺条目。枪体、右手握柄、V7 网格、骨架参考绑定、衣物装备和装填器动作保持。

## 依据

- `skills/ue5-fps-arms-animation/references/grip-arm-refinement.md` 与 `Docs/Weapons/akm-sprint-left-wrist-relax-20260917.md`：腕关节在前臂局部空间放松，肩心弧线下垂，并采用 AKM V4 的提前退握时间窗。
- `skills/ue5-fps-arms-animation/references/thrust-elbow-clearance.md`（PKM / 201 ArmHinge55）：上下臂共用物理肘弯轴，手掌旋前沿实际前臂蒙皮站位分配。根据 Super90 自己的绑定和已接受 idle 校准，未照抄 PKM 骨名、110° 限制或 20° 褶皱补偿。

## 本次根因

1. 四类握把的 UE AnimPose SOURCE 带有导入根节点的 0.01 继承缩放，旧作者脚本直接将它与 Blender 的米制轨迹混用。握把参考臂长、位置和全局骨缩放变为正确值的 1/100，收手却使用 4.5/5.5 cm 等固定距离。现在先用未修改的 base 根姿态求出 `evaluation_to_author`，再还原握把姿态。该转换仅作用于作者输入，不缩放网格、骨架或游戏组件。
2. 旧 IK 把固定的原肘位投影到不断变化的肩腕轴上，投影经过零附近时肘极突翻。再分别最短旋转上下臂，导致可见收手过程的弯曲轴偏差最大 179.9°。现在将原待机弯面随肩腕轴连续搬运，上下臂按同一实际弯曲轴构造旋转。
3. 原脚本只放松手腕，前臂辅助骨还保留握姿滚转，并硬编码 0.2/0.5/0.8。Super90 的实际站位为肘端 aux≈0、twist_02≈1/3、twist_01≈2/3。现在按本骨架参考位置计算站位，松握时同步放松皮肤辅助骨，保留进入与退出端点的原握姿。

## 针对性排查结果

`diagnose_arm.py` 按用户此次“排查”要求逐帧复算作者骨链及真实 V7 肘部蒙皮权重，没有打开游戏或渲染截图。

| 项目 | 旧版 | 修复后 |
| --- | --- | --- |
| 原厂收手上臂弯曲轴相对起始握姿的偏离峰值 | 137.4° | 数值精度内为 0° |
| 四握把同指标峰值 | 176.3–179.9° | 数值精度内为 0° |
| 四握把作者参考全局缩放 | 0.01 | 约 1.0 |
| 四握把 120 Hz 相邻采样左侧骨骼旋转峰值 | 77.4–93.7° | 13.8–22.3° |
| 完全下垂时腕局部相对参考的最大旋转 | 3.6–7.0° | 保持 3.6–7.0° |

弯曲轴指标是相对该握把已接受待机的连续性度量，不代表人体医学角度或视觉验收。旧版循环末态腕角本来就小，真正问题在中途的肘极、辅助骨和握把单位；不能仅凭首末帧判断正常。

进入/退出仍为 0.30 秒，循环 0.60 秒，120 Hz；运行时仍使用同一进入轨道正反向采样，并按已有脚步相位叠循环。本批不改原生 C++，无需重新编译。
