# WS1.1 前期制作包

对应规范：`Docs/Weapons/weapon-surface-contract-20261001.md`。

本目录提供离线配方准备，不安装 UE 材质，不自动改变现有枪械效果。176 个实例记录来自已有制作配方和保存回执；没有加载 UE 资产读取当前有效参数，没有进行渲染或测试。

## 已提供

- `profiles.json`：普通深色金属、金属弹匣的细节候选参数，以及保留当前效果的策略；含普通 WS1／SVD `WS_` 参数名适配。
- `slot_template.json`：新槽配方模板，记录颜色空间、ORM、法线方向、UV、区域、物理尺度、AO 组合和湿润接入。模板中的空字段需要按实际源资产填写，不是可直接导入的材质。
- `shared_functions.json`：七个共享 Material Function 的职责、输入输出和要保留的适配层。仅接口方案；相应 UE 函数资产尚未创建。
- `prepare.py`：使用已保存配方和回执生成三枪逐实例准备文件。只写 `Prepared/`，不依赖 Unreal Python。
- `Prepared/A762.json`、`ASH12.json`、`SVD.json`：源实例、网格槽引用、已记录覆盖、参数推导口径、保护项和候选修改。
- `Prepared/preparation_receipt.json`：制作来源 SHA-256、实例数量和完成状态；`assets_installed=false`、`tested=false`。

## 生成方式

在 `D:/FPS3D/FPSGAME` 执行：

```powershell
py -3.11 SourceAssets/WeaponSurface20260930/WS11/prepare.py
```

这是准备文件的生产入口，不是测试或材质安装入口。每次从当前保存的输入重新生成，覆盖本目录的 `Prepared` 输出；后续人工制作应写新的具体资产配方，不直接修改这些派生记录。

## 如何消费准备文件

1. `recorded_overrides` 是回执中的覆盖；`authoring_value_view` 对 A762／ASH12 补入当前源卡默认值，只是制作数据推导，不证明现有母材质资产已同步该源卡。SVD 只列 Refine03 已记录覆盖，不补猜其他继承值。
2. ASH12 的七个区域图先保持原状。其金属、聚合物和内腔共用部分细节阶段；后续先提供按区域控制，再决定微调，不能把普通金属候选直接整槽应用。
3. SVD 从 `Refine03/apply_receipt.json` 和其配方续接，保留后续浅压纹、部件分层与倒角法线，不能重新运行旧初版材质配置覆盖它。
4. A762 已有真实倒角、几何去噪和弹匣细分。后续细节微调不重复做这些几何，不自动叠加 SVD 的倒角法线。
5. `textures_to_convert_now` 为空：已知输入首先继承，未要求把三枪所有贴图重新打包或去光照。已有 SurfaceMask 不是 ORM。
6. 下一次实际接入应先取得目标资产的真实有效参数与源输入，按单独生产版本保存具体修改及回执。模板、候选配方、UE 函数资产和已绑定实例分别报告完成状态。

进一步安排见 `Docs/Weapons/weapon-surface-preparation-20261001.md`。遵守用户默认后台制作、无主动测试的规则。
