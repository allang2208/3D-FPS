## 三、复核时发现的两个真问题

### 1. 9-25 记录的"资产内 314.9 ms"是错的（不影响已交付结果）

`BGM_FINDINGS.md` 写"CoverOpen 因 `atempo 0.72`，原始时刻 437.3 ms 在资产内对应 314.9 ms"。
那是把源时间**乘**了 0.72；但这套链是把 0.515 s 源窗**拉长**到 0.692 s（×1.344），
正确的资产位置是 587.8 ms。逐样本相减证实实际切点在 569.3 ms（= 587.8 − 15 ms 交叉淡化），
**即当时按源时间取的 437.3 ms 是对的，只有文档里的换算写反了**。已在新文档与清单中更正。

### 2. 供体窗口是按"没有高通"的余量选的，长尾重建会把音乐复制回来

9-25 用 `ChargeRelease`（25.010–25.215 s）当供体，理由是"100 % 帧都 ≥6 dB 压制背景床"。
那个余量是在**没有 80 Hz 高通**的原始解码上算的；而实际制作链（`author_audio.py` 第 34 行）
是要加高通的。补上高通后：

| 条件 | 供体最小余量 | 帧 ≥6 dB 占比 |
| --- | --- | --- |
| 无高通（当时的量法） | +7.3 dB | 100 % |
| **80 Hz 高通（实际链）** | **−2.3 dB** | 71.4 % |

高通削掉的主要是撞击的低频厚度，背景床几乎不变（床能量基本都在 80 Hz 以上，两种口径下总量都是 −47.2 dB），
于是 96–139 ms 掉到 **2.5–5.1 dB**，那段里音乐是露出来的。

- 9-25 只重建了 77.7 ms 和 43 ms 的尾音，供体切片落在 0–85 ms 的干净头部内，**所以那两声没问题**；
- 但直接把这套供体推广到 130–224 ms 的尾巴（本轮第一次尝试就是这样）就会把音乐切回来。
  因此本轮重新搜了整个解码，改用 **20.843–21.077 s**：234.7 ms，最小余量 **12.5 dB**、均值 **19.7 dB**，
  长度足够覆盖最长的尾巴，无需拼接。

供体余量就是重建的抑制度：供体 = 撞击 + 床，供体带多少音乐，重建尾巴就带多少。

### 3. 判据上的另一处修正

原来的规则取"最后一个 ≥6 dB 的帧"，会把 **BoxOut 中断处的音乐空洞**（267–341 ms，余量 0.6 ~ −2.3 dB）
留在保留段里，因为撞击在 363–373 ms 又短暂回到 5.5 dB。本轮改成滞回判据：
≥6 dB 归撞击、<3 dB 归音乐、中间为过渡带，从尾部向回走，遇到第一个归撞击的帧才停。

## 五、实测验收

契约（每一行都是脚本断言，`out/verification.json`）：

| 项 | 结果 |
| --- | --- |
| 保留段逐样本一致 | 5/5 达标（差异起点 == 交叉淡化起点） |

| 峰值变化 | **0.000 dB**（5/5） |
| 整体 RMS 变化 | −0.04 ~ −0.30 dB |
| 差值信号相对电平 | −8.3 ~ −19.5 dB（只动了尾巴） |
| 拼接跳变 | 0.015 ~ 0.090，均远低于同一文件本体的最大阶跃 |
| 新尾音 RMS 对旧尾音 | 低 3.0 ~ 5.5 dB，且**永不高于**被替换段（脚本护栏） |
| 音乐抑制度 | 供体最小余量 12.5 dB、均值 19.7 dB，即新尾音里的音乐比被替换处低至少 12.5 dB |

**两个谱域代理指标已被判为无效并退役**（`trash/pkm-reload-debgm-20260928/`）：
`peakiness` 与"音乐分音突出度"无法把背景床的谐波梳与宽带机械瞬态的共振峰区分开 ——
在本素材上，干净供体窗口的梳状对比度（5.7 dB）**比纯音乐床（4.0 dB）还高**。
这类数字不能作为判据，改用"供体余量 = 抑制度"这条可验证的构造性论证。
