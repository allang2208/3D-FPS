## 〇、第二轮（v2）：用户实测后反馈"还是有夹杂的 BGM"

第一版交付后用户实测，仍然听得到 BGM。回读自己的配方 + 重新测量后，找到两个真原因，
两者都在**方法本身**，不是参数没调好：

### 原因 1：我把替换材料"染成了音乐床的样子"

第一版（以及 9-25 的原始配方）里有这两步：

```python
timbre = timbre_reference(group)        # 返回的正是 BED_WIN，也就是背景音乐自己
g = sqrt(band_power(timbre)) / sqrt(band_power(donor))   # 11 频带色彩传递 → 对齐到"床"的音色
new_tail *= oenv / cenv                 # 包络跟随"原始尾音"，而原始尾音的包络就是床的电平
```

也就是说：**新尾音被塑造成背景床的频谱、被拉到背景床的电平、套上背景床的慢包络。**
它不是"没有音乐"，它是**用干净素材把音乐床重新合成了一遍**。频谱和动态都还是床，
所以听起来仍然像 BGM。这是第一版失败的主因。

### 原因 2：只处理了尾音，而音乐铺满整条 cue

参考源是连续音轨，每一刀都带着一段音乐。用 6 dB 判据量，**每条 cue 有 23 %–74 % 的帧
是"音乐未被掩蔽"的**，不只是尾巴。第一版只重建了尾部，头段和中段照旧。

### v2 的改法

| 项 | 第一版 / 9-25 | **v2** |
| --- | --- | --- |
| 替换材料的音色 | 对齐到**背景床**（= 音乐的音色） | 保留供体自身的机械音色，不染色 |
| 替换材料的电平 | 包络跟随**背景床电平** | 合成衰减：从拼接点电平**衰减到比床低 30 dB** |
| 高通 | 加在整条资产上（未做） | **只加在替换材料上（1000 Hz）** |
| 覆盖范围 | 5 条（+2 条 9-25） | **9 条全部**，统一从原始裁切重做 |

第二、三条是关键。物理上，一段没有音乐的录音，撞击之后是**衰减到本底噪声**，
而不是像音乐床那样维持恒定电平。所以正确的替换是"从拼接点自然衰减下去"。

而"只给替换材料加高通"把 DW715 的经验安全地搬了过来：床是低频嗡鸣
（250–1000 Hz 占 78 %（reload）/ 90 %（charge），音调分音在 **340 / 504 / 680 Hz**），
所以给供体加 1000 Hz 高通就能滤掉它携带的大部分床。
**但同一个滤波器加在资产上被实测否决**：ChargePullMove 会掉 5.4 dB 峰值、8.1 dB RMS
（这条 cue 的能量几乎全在 1 kHz 以下）。加在供体上则取其利而无其害。

## 三、复核时发现的两个真问题

### 1. 9-25 记录的"资产内 314.9 ms"是错的（不影响已交付结果）

`BGM_FINDINGS.md` 写"CoverOpen 因 `atempo 0.72`，原始时刻 437.3 ms 在资产内对应 314.9 ms"。
那是把源时间**乘**了 0.72；但这套链是把 0.515 s 源窗**拉长**到 0.692 s（×1.344），
正确的资产位置是 587.8 ms。逐样本相减证实实际切点在 569.3 ms（= 587.8 − 15 ms 交叉淡化），
**即当时按源时间取的 437.3 ms 是对的，只有文档里的换算写反了**。已在新文档与清单中更正。

### 2. 供体窗口是按"没有高通"的余量选的，长尾重建会把音乐复制回来

9-25 用 `ChargeRelease`（25.010–25.215 s）当供体，理由是"100 % 帧都 ≥6 dB 压制背景床"。
那个余量是在**没有 80 Hz 高通**的原始解码上算的；而实际制作链（`author_audio.py` 第 34 行）
是要加高通的。补上高通后：

| 条件 | 供体最小余量 | 帧 ≥6 dB 占比 |
| --- | --- | --- |
| 无高通（当时的量法） | +7.3 dB | 100 % |
| **80 Hz 高通（实际链）** | **−2.3 dB** | 71.4 % |

高通削掉的主要是撞击的低频厚度，背景床几乎不变（床能量基本都在 80 Hz 以上，两种口径下总量都是 −47.2 dB），
于是 96–139 ms 掉到 **2.5–5.1 dB**，那段里音乐是露出来的。

- 9-25 只重建了 77.7 ms 和 43 ms 的尾音，供体切片落在 0–85 ms 的干净头部内，**所以那两声没问题**；
- 但直接把这套供体推广到 130–224 ms 的尾巴（本轮第一次尝试就是这样）就会把音乐切回来。
  因此本轮重新搜了整个解码，改用 **20.843–21.077 s**：234.7 ms，最小余量 **12.5 dB**、均值 **19.7 dB**，
  长度足够覆盖最长的尾巴，无需拼接。

供体余量就是重建的抑制度：供体 = 撞击 + 床，供体带多少音乐，重建尾巴就带多少。

### 3. 判据上的另一处修正

原来的规则取"最后一个 ≥6 dB 的帧"，会把 **BoxOut 中断处的音乐空洞**（267–341 ms，余量 0.6 ~ −2.3 dB）
留在保留段里，因为撞击在 363–373 ms 又短暂回到 5.5 dB。本轮改成滞回判据：
≥6 dB 归撞击、<3 dB 归音乐、中间为过渡带，从尾部向回走，遇到第一个归撞击的帧才停。
