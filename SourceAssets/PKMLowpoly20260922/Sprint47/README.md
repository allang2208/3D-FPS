## 推理更正：为什么"跟着皮肤动"不能排除自阴影

这是本轮最该记住的一条。

我最初怀疑第一人称手臂**自阴影（shadow acne）**。用户回答"条纹固定在皮肤表面、
放大缩小都跟着皮肤走"，我把它当作"是贴图"的证据，从而转向贴图方向。

**这个推理是错的。** 自阴影的投影体与接收体是**同一个网格**，所以它必然：
- 跟着手臂一起移动、旋转、缩放
- 换姿势时形状改变
- 看起来"长在皮肤上"

纹理与自阴影在这几点上**表现完全一致**，无法据此区分。
要区分只能靠**改变光照条件**（转视角、改太阳角度、开关阴影），而不是改姿势或距离。

图集**整体是均匀的暖棕肤色**，没有任何一块独立的橙色区域（判据把 100% 图集都算作"橙"
—— 因为那就是肤色本身）。所以截图里的橙色斑块**不是**采到了图集里非皮肤的区域。

**但这组数字暴露了真正的疑点**：图集是**浅暖棕**，而截图里小臂渲染成**深灰褐**。
有东西把手臂**压暗**了；那块"橙色斑块"很可能是**没被压暗的底色**，
与周围压暗部分对比才显得橙。同一张截图里同时存在**发白的手、深灰褐的小臂、橙色斑块**
三种外观 —— 这是**光照特征，不是贴图特征**。

## 用户确认后的定位：是皮肤微表面贴图，来自原手模一脉

用户确认：**条纹固定在皮肤表面、放大缩小跟着皮肤走（像贴图细节）**，出现在**换弹**状态。
这排除了自阴影，指向贴图。顺着材质链查到了确切来源：

裸臂皮肤的**法线不是网格法线，也不直接用贴图法线**，而是由 `M_BareFamily_Arms` 里一个
`MaterialExpressionCustom` 节点**在着色器里程序化合成**的
（`Tools/ModularOutfit/import_bare_arms_family.py:58-80`）：
输入 `RestPosition` / `RestNormal` 取自 TextureCoordinate 索引 1/2/3（记为 `CanonicalUV123`），
HLSL 里用 `f.rnm(AnatomicalNormal, detail)` 把"解剖法线"和 **`detail` 微表面贴图**合成。

那张 `detail` 就是 **`T_M4OriginalShape_SkinMicro.png`**，由
`Tools/ModularOutfit/bake_smooth_skin_m4.py` 生成。它的参数是问题所在：

```python
size=1024; tile_cm=2.0; depth_cm=.0025
for _ in range(6600):
    diameter = rng.uniform(.013,.028)          # 0.13–0.28 mm 毛孔
    ratio    = rng.uniform(.75, 1.28)          # ← 各向异性：椭圆，长宽比最大 ~1.7:1
    angle    = rng.uniform(0, np.pi)           # ← 每个毛孔随机朝向
    a = (dx*cos(angle)+dy*sin(angle))/(sigma*ratio)
    b = (-dx*sin(angle)+dy*cos(angle))/(sigma/ratio)
    pit = -rng.uniform(.00055,.00155)*exp(-.5*(a*a+b*b))
```

**每个毛孔都是随机朝向的各向异性椭圆**。再叠加两个放大因素：

1. **一张 1024×1024 的贴图只覆盖 2 cm 皮肤**（`tile_cm=2.0`）。小臂长约 25 cm，
   纹理沿小臂重复约 12 次。
2. 截图是**极端近距离**，单个毛孔被放得很大。

随机朝向 + 椭圆 + 高倍放大 = 一根根斜向的深色条带，也就是用户看到的"脏条纹"，
并且**固定在皮肤上、随皮肤缩放** —— 与用户描述完全一致。

**回答用户的问题：这不属于 PKM，也不是网格问题，而是"原手模一脉"的共享皮肤微表面贴图
（`T_M4OriginalShape_SkinMicro.png`）本身的内容特征。** 所有 profile、所有武器共用同一张，
所以任何武器近距离看都会一样。

### 顺带发现：已经存在一个"柔化"先例

V7 烘焙脚本 `bake_native_bare_defaults_v7.py:77-78` 已经在同一个 HLSL 行上打过补丁：

```python
'AnatomicalNormal.xy*lerp(1,.58,palmar*(1-nail))',
'AnatomicalNormal.xy*(1-ForearmMode)*lerp(1,.58,palmar*(1-nail))'
```

即：**`SOFT_PALM` 把掌心的解剖法线压到 58%**，并且存在一个 **`ForearmMode`** 开关，
在它开启时把 `AnatomicalNormal.xy` **整个归零**（`*(1-ForearmMode)`）。
这说明"按部位衰减法线"是本工程已有的、惯用的手法，缓解方案可以沿用同一机制。

但要注意：这条补丁只作用于 `AnatomicalNormal`，**不会削弱 `detail` 微表面贴图**，
而条纹来源正是后者 —— 所以仅靠 `ForearmMode` 不足以消除条纹。

## 优化方案（待用户选方向）

改 `bake_smooth_skin_m4.py` 重新烘焙 `T_M4OriginalShape_SkinMicro.png`。三个可调项：

| 方案 | 改动 | 效果 | 代价 |
|---|---|---|---|
| **A. 各向同性毛孔** | `ratio = rng.uniform(.75,1.28)` → `1.0`（或 `.92,.1.08`） | 椭圆变圆点，**条纹消失**，皮肤颗粒感保留 | 毛孔失去"拉伸"细节，宏观观感几乎不变 |
| **B. 降低微表面强度** | 毛孔深度 `.00055–.00155` 缩小，或材质 `normal_strength 1.20` 下调 | 整体皮肤更平滑 | 近距离皮肤质感变平淡 |
| **C. 加大贴图覆盖** | `tile_cm` 2.0 → 3.0~4.0 | 同样的毛孔在屏幕上更小、重复更少 | 皮肤颗粒在正常视距下变弱 |

**A 是最对症的一项**：它直接消掉"条纹"这个形态特征，而不减少皮肤细节量。

注意这是**共享皮肤资产**（全部 profile / 全部武器 / 可能还有别的使用者），
不是 PKM 专属，改它属于全局外观改动，需要用户确认方向后再动。

## 已实施：频谱各向同性化（方案 1）

### 做法

新增可复用模块 `Tools/ModularOutfit/skin_grain.py`，提供
`isotropise()` / `anisotropy()` / `angular_energy()`。

`isotropise()` 把频谱能量在**每个半径上**按方向拉平，同时**完全保留该半径的总能量**：

1. 对高度场做 FFT；
2. 按 log 间距切成 44 个半径带 × 64 个方向扇区，统计每格的**平均幅度**；
3. 每格增益 = 该半径的方向均值 / 该格值 —— 这样每个尺度上的方向分布都被拉平，
   而每个半径的能量总和不变，**特征尺寸谱原封不动**；
4. 增益在方向（环形）与半径方向各做一次高斯平滑，避免格与格之间出现台阶；
5. 靠近 Nyquist 处增益渐隐到 1（那里每格样本太少，强行拉平只会放大噪声）；
6. DC 项不动。

**关键正确性**：增益只依赖角度，且角度取 `mod π`，因此共轭频点 k 与 −k
**必然拿到相同增益** → 频谱保持 Hermitian 对称 → 反变换结果**严格为实数**。
最后按 p99 重新归一，保证幅度与原来一致。

接入点：`bake_refined_skin_m4.py` 高通之后、归一化之前，并打印一行可核对的日志。

### 实测结果

| 指标 | 修改前 | 修改后 |
|---|---|---|
| 扫描原图方向性 | 2.259× | — |
| 烘焙日志 | — | `SKIN_GRAIN_ISOTROPISED 2.259 -> 1.114` |
| **最终 RefinedV3 高度场** | **2.12× @ 62.5°（有方向性）** | **1.21× @ 112.5°（各向同性）** |
| 谱熵（1.0 为理论上限） | 0.948 | **0.999** |
| 径向频谱 log-log 相关 | — | **0.9996**（特征尺寸谱几乎不变） |
| 各频带能量比 | — | 中位 0.951，p5 0.812，p95 0.975（±20% 内） |
| std | 0.072329 | 0.072382 |
| p99 幅度 | 0.185655 | 0.185655（完全一致） |

**结论：方向性从 2.12× 降到 1.21×（谱熵 0.999 已到理论上限），
而特征尺寸谱相关 0.9996、幅度完全一致 —— 没有变糊、没有丢细节，只去掉了方向偏置。**

目视对照：原贴图是致密的斜向"梳状"条纹；新贴图是**多方向的斑驳颗粒**，斜向梳纹消失，
柔和斑块保留。（对照图见 `grain_before.png` / `grain_after.png`。）
