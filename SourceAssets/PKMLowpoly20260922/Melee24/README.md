# PKM 快速近战（Melee24，2026-09-23）

已在后台导入并保存五条现有运行路径的 `quick_melee` 动画。没有启动交互编辑器或 PIE；游戏内手感由用户测试。

## 问题与处理

原 Combat17 把 QBZ191 的枪托位移移植到更长的 PKM 上，源动画的左腕最大折角约 113.3°，击打段的上臂还会遮挡枪托。枪身较长、原始左手握点较前，不能只更换枪托坐标后沿用短枪的整组轨迹。

- 参考 M4 N 与 QBZ191 O 的节奏和完整双臂解算方法，重新编写 PKM 枪托轨迹：收枪、侧转、枪托前送、缓冲回收。压低长枪管侧扫，限制倾倒角，使弹箱保持在机匣下方。
- 以 PKM 自身原始／vertical／canted／prism／angled 的 idle 为基准，锁定枪根相对双手矩阵及手指姿态。调整整枪和双手后，重新解算肩、肘、前臂与辅助扭转骨。
- 肩部支撑相对 PKM 自身 idle 调整，防止右上臂顶入源预览镜头。回正时肩根、肘位、手腕与枪根一同回到各自 idle。
- 提前解算起势时的肘位；肘极方向不累计整圈再缩放，避免回正阶段绕腕轴旋转。
- 240 Hz 导出，总时长 0.9 秒；命中时点仍为 1/6 秒。运行路径、伤害、冷却、音效及现有动作混合逻辑未变。

本轮只导入五条近战动画；没有重导枪械网格、骨架、冲刺或换弹资产。Motion21 动态部件、Finish20 材质和 OpticMount23 均继续使用当前资产。

## 本次按用户要求进行的检查

同空间源骨架测量的左腕最大折角：原始 28.3°、vertical 33.9°、canted 32.1°、prism 33.8°、angled 28.0°。右腕最大约 31.2°，最大值来自保留的 idle。

对最终烘焙的五条 Blender 动画逐帧检查：枪根相对握点位置误差最大约 0.0046 mm，骨段长度误差小于 0.001 mm，首末帧骨骼位置与各自 idle 的差异小于 0.001 mm。细小数值属于浮点计算误差。这些是源动画结果，不代表 UE 压缩、实时混合与运行画面已验收。

以当前 Motion21 网格查看关键姿态，源预览相机按代码中的 PKM 腰射／动作位置近似设置；没有包含 UE 镜头运动、第一人称渲染和实时动作混合，因此不能视作游戏截图。

导入记录见 `import_receipt.json`：五条动画已保存，UE 读取长度均为约 0.9 秒。此次资产修改无需 C++ 构建。

## 文件与复现

1. `prepare.py`：读取五种 PKM 的既有 idle。
2. `fit_motion.py`：以自编枪托轨迹拟合整枪／双手组；需要本机 Python、NumPy、SciPy。
3. `author_melee.py`：完整双臂解算、240 Hz 烘焙、保存可编辑 Blend 并导出仅动画 FBX。
4. `import_melee.py`：后台 FBX 动画导入，使用现有 PKM Skeleton 和 M4Viewmodel 压缩设置，仅保存指定五条动画。

`inspect_source.py`、`inspect_baked.py`、`review_motion.py` 是本次明确要求检查时使用的工具，后续制作不应默认运行它们。

`BeforeImport/<family>/` 保留了覆盖前的五条 `.uasset`，`PKM_<family>_Melee24.blend` 是新动作源。第三方网格、FBX、Blend、密集骨骼数据和备份资源留在本机，不代表可公开再分发。
