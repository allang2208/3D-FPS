# PKM LeftArm48 — 左臂与肘部修复

后续发现本轮未同步 PKM 手套与衣袖，导致腕口开缝。已转入 [ArmJoint49](../ArmJoint49/README.md) 补齐服装绑定，并继续改善换弹肘腕配合；该目录的最终换弹轨道优先于本轮历史轨道。

用户反馈：待机、换弹均明显；最近 Elbow39/41/42、Sprint44/46 以及阴影/皮肤方向的调整没有解决实际问题。

## 排查与修复计划

1. 从当前原生 PKM 武器读取真正使用的 V7 裸臂、权重、参考骨架和已安装动画，区分源制作、导入、压缩与姿态问题。
2. 废弃旧的逐帧分档开关和“表面滚转倒退”优化。以实际肩/肘/腕与掌宽方向建立整段皮肤坐标框架，保持同一骨段的辅助骨协同。
3. 只调整 PKM 左前臂蒙皮：按真实骨骼站位连续混合相邻骨骼，保留上臂、手指、右手及共享 V7 母版。
4. 同步制作基础/四种配件握持的动画。待机与换弹为重点；相关瞄准、开火、装备等姿势使用同一分配，避免状态切换又混入旧扭转。
5. 通过原生动画轨道控制器和 Geometry Script 保存资产、源数据与回执。默认后台，不启动游戏或追加视觉验收。

## 已取得的诊断证据

- `current_mesh.json` 来自 `/Game/Weapons/PKMLowpoly20260922/Accessories14/SK_PKM_Manny_Modular` 的实际皮肤 section。
- 当前网格位置与 V7 PKM Authored 源的最大差异约 0.0000044 cm，权重 L1 最大差异约 0.000067（量化）。不是只写源文件、没有接入。
- 19 个直接相关动画的起始帧 RAW/COMPRESSED 矩阵差异均很小（最大约 0.00031）；不支持再次通过压缩或阴影开关解决。
- 基础 idle 实际来源是 Elbow42，而 reload/reload_empty 仍来自 Elbow39。相同握持端点的小臂 skin 朝向不同。
- Elbow39 的离散强度开关问题在 Sprint44 已记录，但换弹尚未重做；Elbow42 只处理基础 idle。
- **明确的源动作选择错误**：Elbow39 的四种配件 idle 读取 `PKM_Game_idle`；GripContact15 的正式动作实际为 `A_PKM_<family>_idle_Contact15`。当前四种配件 idle 的手掌位置完全相同，已丢失各自握持。其 aim/fire/reload 仍保留各自姿势。本轮从 GripContact15 正确 FBX 恢复四种配件的左臂完整轨道。
- 当前前臂骨实际站位为 0、1/3、2/3、1，旧代码采用 0.23、0.35、0.85、1。旧表面指标还对包裹角度做算术平均并只惩罚一个方向，不能代表肘部体积质量。
- F2 隐藏武器阴影修正已被用户反馈无效并回滚，本轮不复用；不修改共享皮肤材质。

## 修复边界

基础动作的原始肩/肘/腕位置和手掌世界轨迹保留；配件 idle 先恢复各自 Contact15 左臂与手指握持。重新制作两根上臂辅助骨、三根小臂骨和手骨补偿轨道；其余动作的手指与全部枪械轨道保持原资产数据。权重调整会改变左臂及腕掌过渡处的表面形态，实际接触与轮廓由用户实测。

## 最终制作方法

- 小臂框架由肘腕轴和掌宽方向投影建立，去掉手腕屈曲对滚转的干扰。三根小臂骨使用同一 skin rotation，各自骨头仍在原骨段位置，消除骨段内部独立拧转造成的绞缩。
- 上臂辅助骨把该框架沿实际肘部弯曲方向传递到上臂。处理完整骨段，避免只修小臂后把变形集中到肘侧。
- 不使用逐帧档位、正负 180 度角度分支、跨帧累计一整圈的 roll 或逐帧优化分数。
- PKM 左侧 2,462 个源顶点调整四根前臂/手骨之间的权重。上臂与手指权重、右臂、几何位置/拓扑、UV 与材质保持源数据。
- 保存范围：基础 + angled/canted/prism/vertical 五组各 12 个现行动作，共 60 条；原生武器中的裸臂和独立 V7 PKM 裸臂同时更新，LOD 按原数量重建。
- `Before/Packages` 保存被修改资产的原始包；`InputTracks` 保存当前装载轨道；`RestoredContacts` 记录正确配件来源；`AuthoredTracks`、`PKM_authored.json` 和制作脚本为本轮可编辑源。

制作源是可重放的 JSON 轨道及 Python 脚本，直接写入 AnimSequence；旧 FBX 再导入会恢复旧动作，后续应从本轮轨道继续制作。
