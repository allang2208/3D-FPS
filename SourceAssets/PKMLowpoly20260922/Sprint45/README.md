## 尝试过的两种 A 实现（都无效）

**A1：逐帧搜索额外扭转**（等量加在 `lowerarm_l / twist_02 / twist_01` 上，即小臂整体刚性扭转）。
逐帧最优确实能达到峰值 **0.7963**（低于 0.85 阈值），**但逐帧最优解在相邻帧之间正负振荡**，
做时间平滑后整个收益被抹掉，最终峰值 **1.1147**，且引入 33°/帧的扭转台阶、小臂表面 34.2→46.9 劣化。

**A2：平滑包络 + 搜幅度**（升余弦窗，时间上天然连续，直接对"最终要落盘的序列"求最优）。
5 种沿小臂的分配比例 × 25 个幅度全域搜索，最优只有 **1.2021 → 1.1689（2.8%）**，
代价是 54.3° 的扭转、33.5°/帧的台阶。
（副产品：小臂表面指标 34.2 → 34.2、TV 176.7 → 176.7 **完全不变** —— 再次确认该指标看不见刚性扭转。）

## 为什么 A 在原理上不行

掌心塌陷由 `hand_l` 与 `lowerarm_twist_01_l` 之间 **164°** 的相对朝向造成，
而绕小臂轴的扭转只能削减其中沿轴的分量（0.83），
剩下的垂直分量（约 √(1−0.83²)≈0.56，对应约 100°+）**绕小臂轴怎么拧都拧不掉**；
而且把三根骨一起拧，对一部分掌心顶点是靠近 `hand_l`，对另一部分是远离，净收益被抵消。
要把 164° 降到安全区需要约 100°+ 的姿势改动，那已经不是"放缓"，而是改姿势。

## 建议

- **B（推荐）**：调整手掌混合带权重 —— 让掌部更刚性地绑到 `hand_l`，缩小与 `lowerarm_twist_01_l`
  的 50/50 混合带。这是线性混合蒙皮在这类近 180° 相对朝向下的标准解法。
  代价：会同时影响所有用到这只手的 clip（idle / 换弹 / 装备 / 冲刺），需要整轮复核。
- **C**：接受现状 —— 峰值 1.20 vs 基准 0.69，仅在过渡的 4 帧（120 fps 下 0.033 s）出现。
