# Sprint44 — PKM 战术冲刺（sprint_enter / loop / exit）左手小臂扭曲修复

## 结论先行

PKM 的"战术冲刺"就是 `sprint_enter` / `sprint_loop` / `sprint_exit` 这三条 clip，
不是另一套资产：`UM4TacticalSprintComponent::Configure`（`Source/FPSGAME/Weapons/M4TacticalSprintComponent.cpp:38-44`）
对所有武器都只加载这三条，PKM 走 `PKMLowpolyWeaponAssets::AnimationPath`。

**上一版（Elbow41，已接入）在这三条 clip 上引入了逐帧"拧一下"的跳变**，这就是用户看到的扭曲。
根因已定位到具体行，不是推测。

## 根因

`Elbow39/author_elbow39.py` 用"把每根小臂骨放到锚骨到手骨连成的直线上"来决定拧多少：

```
slope = (roll[hand_l] - roll[ANCHOR]) / (station[hand_l] - station[ANCHOR])   # 第 257-262 行
```

`roll` 只做了**帧内**解缠（anchor → lowerarm → twist_02 → twist_01 → hand）。
sprint_enter 里左小臂滚转扫过约 200°，链条跨过 ±180，于是 `hand_l` 的分支在第 3→4 帧翻转：
真实值 −212.7° 变成 +138.0°（同一朝向），但 `slope` 因此反号。后果（实测）：

| 帧 | lowerarm_l | lowerarm_twist_02_l | 说明 |
|---|---|---|---|
| 3 | −75（触 CAP） | −35（触 CAP） | |
| 4 | +4.8 | +35 | 单帧跳 80° / 70° |

叠加更明显的一处：`SCALES = (1.0, 0.75, 0.5, 0.25, 0.0)` 的**逐帧独立**守卫，
在 sprint_enter 第 18–20 帧选了 0.0（sprint_exit 第 22–24 帧同理），
于是修正在单帧内被整体关掉又打开 —— 120 fps 下单帧转 90–105°，正是肉眼看到的"扭曲"。

**原始授权动画本身没有这个问题**：逐帧骨滚转变化 ≤ 44.8°，且四根小臂骨收敛到同一滚转值
（无相对拧转）。问题完全由 Elbow39/Elbow41 的算法引入。

## 本轮做法

保持 Elbow39 的算法不变，只改**解缠**：把每根骨相对锚骨的偏移量**跨帧**解缠，
使直线目标和修正都随时间是连续的；同时不再使用逐帧离散的 scale 守卫。

另外两条实测结论：

1. `sprint_loop` 是静态姿势，实测最优修正 `(65.0, 65.0, 64.64)`，
   其**相对均值的偏差只有 (0.1, 0.1, −0.2)** —— 几乎是三根骨等量的整体拧转，
   而不是把拧转分散到各骨（`pick_loop_constant.py`）。
2. `sprint_exit` 是 `sprint_enter` 的精确逆放（位姿探测：手部行程同为 54.6 cm、方向相反，
   原始统计完全相同），因此直接**反向复用** enter 的修正，避开手骨分支歧义
   （直接推导时该 clip 的最差台阶是 414.7，反向复用后为 34.2）。

未做显式收尾渐变：`SprintLoopAlpha = SmoothStep(.65,1,Progress)`
（`M4TacticalSprintComponent.cpp:138`）本来就在 enter 的最后 35% 把 loop 淡入，
引擎已经承担了这段过渡；把它硬塞进 clip 内会让本 clip 的表面质量差约 10 倍。

## 不变的部分

- **手部、手指、握把、枪械根、带/栓时序、时长、采样率、关键帧时刻均未变。**
  修正只拧 `lowerarm_l` / `lowerarm_twist_02_l` / `lowerarm_twist_01_l` 三根骨，
  绕**当前帧小臂轴**过各自骨头原点；其余骨（含 `hand_l`）的局部通道由其**保留的世界矩阵**
  反推，因此任意修正量下手都不可能移动。
- 实测手部世界漂移 **0.000e+00 m**（比之前几轮的 float32 量化 1e-6 更干净）。
- 修正本身逐帧变化 ≤ 24.02°，小于动画自身运动的 44.8°，不构成新的跳变。

## 追加检查：用户反馈"手部仍有扭曲形变"（2026-09-25 复查）

**结论：残留的手部形变不在本轮修正范围内，它在原始授权动画里就有，本轮改动既不产生也基本修不掉它。**

三组证据：

1. **本轮修正碰不到纯手部顶点。** 手部区域（20 根手/指骨权重占比 >0.5）共 5442 顶点，
   其中 4159 个"纯手"顶点（>98% 权重在手骨上）对三根小臂骨的权重**上限只有 0.0016**。
   只有 406 个处于腕部混合带的顶点带小臂权重（>1%），211 个 >20%。
2. **渲染逐像素一致。** `render_hand.py` 把相机贴到 `hand_l` 上，对 original 与 Sprint44
   各渲染 9 帧 ×3 个视角（`Review/hand/sheet_hand.png`），两行画面一致。
3. **线性混合蒙皮的非刚性指标几乎不动。** 对每个手部顶点算混合矩阵 `B=Σw·skin`，
   取 `‖BᵀB−I‖_F`（越接近 0 越刚性）：

   | 版本 | 手部整体 max | p99 | 手掌 p99（峰值帧） | 手指 p99 |
   |---|---|---|---|---|
   | `A_PKM_idle`（已认可基准） | 1.0148 | 0.6567 | **0.6929** (f0) | 0.3316 |
   | `sprint_enter` 原始 | 1.4085 | 1.3625 | **1.2344 (f4)** | 0.3812 |
   | `sprint_enter` Sprint44 | 1.3676 | 1.3091 | **1.2021 (f4)** | 0.3658 |
   | `sprint_loop` Sprint44 | 0.9444 | 0.6412 | — | — |

**定位结果**：扭曲集中在**手掌**（palm），不在手指（手指各版本都是 0.33–0.38，与 idle 同级）；
且集中在 **第 3–5 帧**这个 3 帧窗口（120 fps 下 0.025 s）：

```
帧:      f0     f1     f2     f3     f4     f5     f6     f7    f8…
palm:  0.693  0.693  0.748  1.090  1.234  0.995  0.703  0.679  0.677   ← 原始
palm:  0.693  0.693  0.693  0.861  1.202  1.183  0.861  0.681  0.678   ← Sprint44
finger:0.332  0.325  0.337  0.346  0.381  0.335  0.290  0.231  0.225   ← 两者相同
```

即：冲刺过渡最快的那 3 帧里，手掌的混合蒙皮塌陷到 **1.23，约为已认可 idle 基准 0.69 的 1.8 倍**；
`Sprint44` 把它降到 1.20（f3 由 1.090→0.861 改善，f5/f6 略升），峰值仍在。
`Sprint_loop` 全程 0.64，与 idle 同级 —— 干净的，符合"只在过渡瞬间看得出来"的现象。

**成因方向**：手掌顶点在 `hand_l` 与三根小臂骨之间混合，而在这 3 帧里小臂骨滚转每秒变化
23–45°/帧、`hand_l` 只变约 9°/帧，腕部相对旋转变化过快，线性混合蒙皮因此塌陷。
这是原始授权的姿势节奏问题，不是权重缺失（手指权重完全正常）。

**可选修法**（都触及用户关心的既有内容，未擅自执行）：

- **A. 放缓 f3–f5 的腕部相对旋转**：只改这 3 帧的插值，clip 长度、关键帧时刻、采样率不变，
  手部接触姿势不变（冲刺时左手本来就脱离护木）。风险最低。
- **B. 调整手掌混合带权重**：把掌部更刚性地绑到 `hand_l`，减少小臂骨影响。
  会同时影响所有用到这只手的 clip（idle/换弹/装备），需整轮复核。
- C. 接受现状：它是原始资产属性，峰值 1.23 只在过渡 3 帧出现。
