# 战锤单机与联机接入检查

范围：普通三连击、重击与冲刺砸地、上挑、旋风、快速近战、格挡、体力和伤害权威、破防、旁观者动作及专用音效。

## 已定位并修复

1. **服务器缺少格挡与攻击互斥。** 本机已经检查动作占用，但服务器的格挡请求没有检查战锤攻击、蓄力、上挑、旋风和快速近战。攻击入口也没有排除服务器格挡。现已在两侧入口加入互斥，取消攻击时同步释放服务器恢复占用。
2. **旧格挡回执能影响同武器的新一次格挡。** 原来只有装备实例 ID。现在每次抬挡生成独立序号；旧请求不能重新开启已释放的格挡，旧松键不能取消新格挡，旧拒绝或受击回执不能夺取新动作。已经发生的体力消耗仍正常结算，不因动作结束而免单。
3. **快速近战未在服务器执行战锤动作中断。** 客机本地取消旧攻击后，服务器旧攻击的命中定时器可能仍存在。现已在快速近战获准时中断该玩家的战锤执行器，清除旧命中和格挡；不会调用会重用主机档案的本地输入中断入口。快速近战期间不能再次进入格挡，破防输入锁期间不能申请快速近战。
4. **破防回执与复制组件可能重复启动同一动画。** 破防姿态改由复制的输入锁组件统一启动，RPC 不再重置动画。另修正了共用双手剑破防动作被自身输入锁视为“不可操作”而取消的问题。
5. **迟到的受击反馈可能替换收回动作。** 受击动画现在要求仍处于格挡；松键收回后不再被迟到反馈切回撑挡。

## 验证与边界

- 正式 Game / Editor 构建成功；最终记录见 `build_receipt.json`。
- `WarhammerNetworkAudit`：**52 项通过，0 失败**；`WarhammerModificationAudit`：**103 项通过，0 失败**。合计 **155 项通过**。
- 新增 `WarhammerNetworkAudit`，使用独立审计档案执行真实生产服务器入口、格挡伤害和回执处理，不改用户存档。
- 复用 `WarhammerModificationAudit` 检查已有改造、正常攻击/重击/冲刺的权威费用和回执。
- 保存资产读取检查五条格挡动画的实际时长和骨架。
- `audit_receipt.json` 及两份同名 JSON 记录后台运行结果；正式构建结果见 `build_receipt.json`。
- 这些后台测试没有建立真实网络连接，不能证明延迟、丢包、重连时的实际画面和音频表现。未启动编辑器或可视游戏。
- 两组测试使用隔离档案，不保存引擎资产；已有其他无界面联机游戏进程得到保留，没有为测试强制关闭它们。
- 构建期间遇到并行改动的编译阻塞，按最小范围修正：炼金界面两处局部 `Slot` 重名；食物审计 `TSharedRef` 的多余 `ToSharedRef()`；篝火审计函数的私有访问友元；体素凸包错误的 `VertexBuffer` 字段名和局部 `NoShapes` 重名。未改动这些模块的布局、数值或算法，也未运行它们的专项验收。

结论：原有战锤主体已接入，检查发现的状态与权威逻辑问题已修复；旁观者专用音效仍是明确剩余项，真实双端联机验收尚未完成。
