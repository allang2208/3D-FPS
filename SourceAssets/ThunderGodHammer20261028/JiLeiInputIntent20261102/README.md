# 疾雷短按与长按动作分离 — 2026-11-02

## 原因与此前记录

此前 `NormalGripFix20261031/repair.md` 修正的是普攻动画与握柄之间的左掌接触位置。
本次问题来自 `BeginPrimaryAttack()`：按下时立即启用单手蓄力姿态，松开后才按持键时间转成普攻。因此短按也可能先播放左手下放，再接双手普攻。

## 本次实现

- 共用 `ThunderHammerCallIntent` 判定待确认、蓄力、蓄满三个阶段。
- 待确认窗口为 0.24 秒（极短蓄力配置最多占总时长的 25%）。窗口内维持待机/移动握姿；松开直接普攻，不采样疾雷蓄力动画，不做蓄力姿态向普攻的交接。
- 超过窗口才下放左手、举锤并播放已接入的随机电流音效。第一人称动画、全身动作、服务端特效时钟及持续体力/法力消耗都使用同一确认条件。
- 已进入蓄力但未蓄满时松开，取消蓄力并回握，不再转入普攻。若松开发生在刚越过阈值且尚未呈现举锤动画的帧，不凭空插入回握动作。
- 蓄满后沿用疾雷释放流程。举锤动画映射至确认后的剩余时间，总蓄满时间不变。
- 疾雷普攻 RPC 保持普攻语义，避免服务器接收延迟将短按误判为普通锤子的重击。普通锤子和贯雷继续使用原有轻重击判定。
- 保留此前普通连击握柄修正、疾雷/贯雷模型、图标及随机电流 MetaSound。
