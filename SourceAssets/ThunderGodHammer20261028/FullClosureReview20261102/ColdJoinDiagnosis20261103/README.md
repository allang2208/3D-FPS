## 已确认的直接原因

**身体先显示，头部异步装配还未完成；首次外观缺少统一的就绪条件。**

1. `FPSPlayerBodyComponent.cpp:286` 的 `InitializeBody` 先执行 `Body->SetVisibility(true)` 和 `SetHiddenInGame(false)`；到第 313 行才调用 `ApplyAppearance(ReplicatedAppearance)`。身体与头部是独立的网格。
2. `FPSPlayerBodyAppearance.cpp:96–138` 把选定头部、材质、毛发和绑定加入同一个 `RequestAsyncLoad` 请求。头部组件要到完成回调的第 171 行才创建，第 180 行注册，第 261 行更新显示。此前身体已经可以被渲染，没有完整基础外观或首次就绪屏障覆盖这段空窗。
3. `remote_009` 拍摄于 UTC 03:43:31.924：锤子已经回到手中，头部仍缺失。随后 03:43:32.154 日志记录 `SKM_Jason_head` 蒙皮资产就绪等待；03:43:32.930 的 `remote_010` 显示完整头部。对应本地时间均加 8 小时。

这解释了“过一会儿自行恢复”：异步请求完成后，头部才创建并加入显示。当前证据支持通用人物首次外观装配问题；没有证据表明头部资产永久缺失或锤子动作状态机导致头部消失。
