# 人物首次外观就绪修复

2026-11-03，用户明确要求修复上轮定位的冷加载头部缺失。实现沿用通用人物外观组件，未修改雷神之锤攻击、召回、存档或复制字段。

## 实现

- 新增每个人物组件自己的首次外观等待状态。身体、服装、世界武器、持物和阴影共同读取该状态，避免主体未完成时先显示无头身体或孤立装备。
- 选定头部、材质和毛发仍按原有异步请求加载。完成装配后等待头部第一次骨骼变换完成回调，再一次性解除首次显示限制；没有增加固定延迟或同步加载全部头型。
- 等待期间身体与头部继续刷新骨骼，避免隐藏导致姿态永远无法就绪。玩法更新、碰撞、伤害和网络状态发送照常运行。第一人称裸臂、腿部和相机偏移沿用既有规则。
- 已经完整显示的角色换装时继续保留旧外观，直到原有异步切换完成。请求编号仍拒绝过期回调；更换头部和 EndPlay 时解除首次姿态委托。
- 资产确实缺失或配置无对应头部时，保留错误日志并退回原来的显示行为，避免将资源错误变成永久不可见人物；本次不替换或修复资产内容。

## 用户要求后的源码复查（2026-11-03）

本次复查覆盖首次加载、外观请求替换、失败、销毁、专服分支及世界装备显示入口，并对照先前联机记录。10 个修复文件均与交付快照相同；当前 Editor DLL 和 Game EXE 的 SHA256 均与最终构建回执相同。本次未修改生产源码、未启动 UE 或重新运行联机。

**尚不能把这项修复判为完成，仍有以下问题：**

1. **P1：冷加载等待变成整个远端人物不可见。** `FPSPlayerBodyAppearance.cpp:47-58` 的门控由每个人物在 BeginPlay 启用，隐藏身体、已创建装备及阴影；门控没有参与输入、碰撞、伤害或权威攻击条件。晚加入者可暂时看不到仍能交战的角色。本次从源码确认这个行为，没有测量新版持续时间，也不沿用旧捕获的时长。应先提供可见的完整临时外观，再在目标外观就绪时替换，避免以隐藏活跃角色掩盖缺头。
2. **P2：首次就绪只等待头部，未覆盖整个装备装配。** `FPSPlayerBodyAppearance.cpp:282-285` 只等待头部骨骼回调；衣物在 `FPSPlayerBodyEquipment.cpp:906-928`、模块服装在 `FPSModularOutfitComponent.cpp:536-555`、头盔在 `FPSPlayerHeadEquipment.cpp:66-107` 各自异步处理。如果这些请求比头部更晚完成，解除门控后仍可能先显示不完整穿戴，再补齐。此前“共同显示”只保证已创建部件遵守隐藏标志，不能解释成所有资源和部件已经就绪。
3. **失败分支未彻底解决缺头。** `FPSPlayerBodyAppearance.cpp:104,156-159` 遇到缺失头部、材质或毛发资源会直接解除门控；首次加载没有旧完整外观时仍退回缺头显示。这是已实现的失败策略，不是本轮确认有生产资产缺失。完整临时外观也需要覆盖失败分支。

已检查的清理路径中，请求序号拒绝过期完成回调，EndPlay 取消加载并解除首帧委托，等待期间强制刷新身体与头部骨骼，专服不进入渲染等待状态。没有从这些路径发现新的确定性崩溃。`IsAppearanceLoading()` 仅覆盖流送句柄而未覆盖首帧等待，但当前调用者为调试面板和开发检查，没有发现游戏入场流程依赖它，因此未列作玩法缺陷。

先前的改造回执保护、满蓄力延后结算及重生档案初始化修复仍在。共享 PlayerState 相比旧快照还有其他技能的改动，不能将旧二进制的 24/24 结果直接移用于当前整合版本。历史斧类辅助文件的移除未发现活动源码引用，本次未还原或改动其他功能。
