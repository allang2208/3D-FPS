# 冷加载首次人物显示 V2

2026-11-03，接续用户要求的遗漏复查，修复初版等待期间整个人不可见、穿戴装配未纳入就绪、失败后显示缺头身体三个问题。

## 实现

- 使用项目现有完整 `SKM_Manny_Simple` 作为临时人形。类默认对象持有资源，首次人物装配时创建临时组件，不等待目标 MetaHuman 头部/毛发，也不修改现有模型资产。Mannequins 目录已有正式 cook 配置。
- 临时人形跟随实际身体骨骼及同一网络动作时钟。Manny 与 Jason/Kaitlin 的参考骨轴不同，复用已有姿态发布组件，缓存骨映射和参考旋转修正，随身体骨骼完成回调提交姿态；没有直接跨骨架使用 Leader Pose。真实世界武器继续按实际持握/收起规则显示。
- 只有正式身体及其穿戴保持隐藏，临时人物继续显示和投影；第一人称手臂、相机和腿部规则保持原路径。完整临时网格在第一人称死亡镜头中对本人隐藏，避免其内置头部挡住镜头；其他观察者仍可见。
- 首次切换要求：目标头部完成首帧、头部加载未失败、当前普通穿戴装配完成、当前头盔完成、当前世界模块衣物配方完成。只等当前世界穿戴，不被无关武器视模加载拖住。模块衣物在选择变化、身体重建时撤销就绪，部件提交后恢复。
- 切换当帧同步模块衣物可见性，再销毁临时人物，避免等衣物下次 Tick 才显示。等待沿现有组件更新检查少量状态，不增加定时器、同步热路径加载或全场遍历。
- 头部/资源失败保留完整临时人物；已经显示完整外观的角色继续保留旧外观。失败的相同头型请求不再每次档案刷新重复加载，选择另一头型/发型可发起新的请求。
- 首次等待中更换头型会取消旧请求、解除旧首帧委托并重置就绪；EndPlay 取消请求及委托并销毁临时组件。未新增复制属性、RPC 或存档字段，服务器攻击和伤害规则不变。

## 交付范围

`Before/` 保存本次 9 个源码文件的修改前副本。差量与编译记录由同目录脚本落盘，不是干净 Git 基线；不覆盖并行功能。新增的是运行时临时组件，没有新生成/导入资产。

**常规 Editor/Game 后台构建均成功，9 个源码文件在构建期间保持一致。** `build-receipt.json` 记录产物路径、SHA256 和构建结果，`delivery.json` 记录交付范围，`source-changes.patch/json` 记录本次差量。未运行游戏、联机、渲染或截图；之前 24/24 和 15/15 记录不能作为 V2 的运行证明。临时人形的实际观感、首帧衔接及真实主客机表现仍由用户测试。
