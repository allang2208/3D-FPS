## 实际修复

1. **旧服务器镜像覆盖刚安装的改造。** 给雷神之锤的免费改造增加独立确认序号，随冻结上传和镜像传递。旧库存回执保留仍存在的同一锤子实例的待确认改造，再在服务器库存基线上重新上传；匹配拒绝正常回滚；已删除物品不会被恢复。材料消耗型改造的事务规则不变。
2. **首次满蓄力帧释放会被服务器间歇拒绝。** 发起和释放的收包间隔受抖动影响。远端完整释放若提前不超过 250 ms 到达，使用可取消的计时器等到服务器真正蓄满后结算，继续保留资源、取消、死亡、武器实例和地面校验。实际 UDP 取证：服务器首次收到释放时仅计时 1.583805 / 1.739130 秒，等待至 1.769443 秒后成功结算一次。
3. **死亡重生后无法继续疾雷蓄力。** 新 pawn 曾先应用上一条生命的 0 血量，客户端初始复制因此关闭输入和更新。现在接管新角色时先绑定并重置重生档案；PlayerState 仍清理旧生命的镜像与账本。实际复跑记录新角色 `health=200、actor_tick=1、input=1、charging=1`，随后蓄力中死亡及再次重生也通过。

额外构建修正：HatchetDualChop / HatchetSprint 生成头文件及生成器改为引用原有精确时间常量，解决小数舍入导致的严格相等断言失败；没有重新制作或改变动作时长。
