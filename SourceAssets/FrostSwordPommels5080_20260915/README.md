## 模型与接口

- 三视图分别由内置 imagegen 制作，原图及完整提示词保存在各变体的 `three_views.png` / `reference_prompt.txt`。生成参考用于本次原创部件设计；不覆盖此前 `WeaponBallast20260915` 的候选模型。
- 三视图按图像实际尺寸拆为正、左、背三个条件，分别去背景后输入 `Trellis2MeshWithVoxelMultiViewGenerator`。安装颈在图上方，glTF Y-up 经 Blender 原生导入转换为 Z-up；映射记录在 `view_mapping.json`。
- RTX 5080 / TRELLIS.2-4B / SS32 / 16、32、24 步 / 4K 纹理母版 / 50 万面导出目标。按用户选择，硬化配重保留已经运行的 `1024_cascade`，符文配重及魔力球配重改为 `512` 级几何，4K 贴图不变。`resize_pending.py` 只替换本任务的两条排队作业，未中断硬化配重。实际输出保存在各目录，未把母版面数目标写成最终游戏面数。
- 初始 SS64 圆实体尝试的低分辨率形状采样耗时 12 分 44 秒，随后继续长时间处理高分辨率阶段。改为 SS32，其他主要参数与种子保持一致。初始记录在各变体 `ss64_attempt/`，替换入口为 `resubmit_compact.py`。自定义采样循环没有响应定向中断；在本地及远端两次确认队列全部属于本任务后，通过 `restart_owned_generation.py` 保存队列、重启生成进程并恢复三款 SS32 工作流。没有删除其他任务条目，完整重启记录在 `queue_before_owned_restart.json`、`owned_restart.log` 与各目录回执。
- 三个 seed：硬化 915361、符文 915367、魔力球 915373。各目录的 `workflow.json`、`receipt.json`、`history.json` 保留实际调用与生成结果。
- `author_pommel.py` 从生成母版制作游戏网格、烘焙结构法线；保留原装配重锤安装口及其下方 4 mm 原表面，向生成主体的切口制作连续过渡面。来源为上一轮模块化可编辑源，安装口位置、原 UV 和法线继续沿用。
- 部件本地原点就是握把—配重锤接口，UE 组装位置继续读取原装配重锤的 `[0,0,-22.7] cm`；使用 `frost_hilt_v1`。主体尺寸按设计调整，实际连接面不按生成模型包围盒猜测。

## 表面材质

金属主体通过独立 UV1 从原装配重锤表面转移原剑的 BaseColor、Metallic、Roughness；原安装口和过渡部分保留原材质。UV0 用于生成母版烘焙的法线及符文掩模。符文配重保留生成模型上的银白图案，采用轻微周期发光。

魔力球的蓝色表面使用原剑刃区域的 UV/颜色与粗糙度贴图，独立设置半透明材质：Opacity=0.48、Metallic=0、折射输入=1.12，少量同色自发光。原剑材质仍保留；只给配重球的蓝色区域改变光学模式，古铜安装座和金属肋保持不透明。Blender 源材质以 Transmission=0.70、IOR=1.45 表达水晶，属于两种渲染器间的材质对应，不宣称输出完全相同。

## 属性与结算

| 选项 ID | 效果 |
| --- | --- |
| `ballast_hardened` 硬化配重 | 重击倍率直接 +0.15；攻击击退 ×1.10；攻速 ×0.90；耐力消耗 ×1.10 |
| `ballast_rune` 符文配重 | 魔法技能冷却 ×0.85；魔法值消耗 ×0.85 |
| `ballast_magic_orb` 魔力球配重 | 魔法伤害 ×1.10；魔法值消耗 ×1.15 |

- “重击倍率 +0.15”是加值，例如 2.50→2.65，修正此前目录用 `heavy_damage_mult=1.15` 表达的差异。现有倍率乘项保留兼容，新增 `heavy_damage_add` 独立累加。
- 普通伤害面板继续提前计入属性附加伤害；动作倍率在出招时记录，之后沿现有物理/魔法分项减免。此次没有另造一套附加伤害路径。
- 耐力修正覆盖轻击、重击及防御受击。魔法消耗同时接到火球和冰锥，施法时记录消耗和冷却。
- 击退距离与硬直时间分离。单次命中全部伤害分项结算后，对存活且可击退目标执行一次推退；20% 立即移动，余量在 0.16 s 内衰减推进，使用角色移动组件碰撞扫描。不会因为基础/附加两次伤害重复推退，也不附加弹反眩晕。
- 改造台对比与物品摘要显示真实重击倍率、击退距离、魔法值消耗倍率。既有存档中的相同改造 ID 自动使用新模型目录，无需重建物品。

## 接入路径

运行模型：`/Game/Weapons/FrostCrystalSword20260915/Pommels5080_20260915/<id>/SM_FrostPommel_<id>`。

`import_pommels.py` 仅更新 `Content/ColdSteelData/frost-sword-modules.json` 的三个配重锤条目，保留原装及其他槽位。现有共用模块组装入口负责持剑、检视、改造台草稿/应用/撤销、物品预览与世界掉落。模型目录在既有 FrostCrystalSword 打包范围内。

`make_icon.py` 从本轮实际模型制作改造选项的 1024 RGBA 图，安装方向 +Z 向上，正面观察方向 -Y。输出 PNG 与对应 UE Texture 使用武器专属命名 `ue_frost_crystal_sword_pommel_<id>`。这是界面素材制作，不是游戏或视觉验收。

## 作者入口及状态

1. `generate.py submit <id>` 提交该变体一次；已有回执不重复提交。`generate.py fetch <id>` 保存生成历史、raw 与纹理母版，不启动预览。
2. Blender 执行 `author_pommel.py -- <id>`，写入可编辑 Blend、静态 FBX、烘焙贴图及作者记录。
3. Blender 执行 `make_icon.py -- <id>`，制作并安装选项图标。
4. UE Python 执行 `import_pommels.py`，导入并登记实际运行模型。

原生构建后缀 `9152146`，FPSGAME、AutoFootstep、AutoFootstepEditor 同后缀；本轮新增文件触发 unity 编译单元的既有名称冲突，使用 `-NoUBTMakefiles -DisableUnity` 完成构建，没有改动无关建筑或战斗公式文件。
