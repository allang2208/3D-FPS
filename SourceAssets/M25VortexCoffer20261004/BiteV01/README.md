# M-25 正前方撕咬 V01

用户要求制作撕咬动作，正前方攻击范围内优先使用；进一步明确近战和魔法分两个计算通道，释放魔法不影响撕咬。

## 独立通道

- 新增 BiteExecution，只拥有撕咬动画时钟、物理伤害、命中去重和自己的冷却。
- MagicExecution 保持原魔攻 60、普通闪电 CD 3 s、雷枪 CD 20 s，原有提前量与蓄力行为保留。
- 正前方撕咬条件满足时，共享 Behavior Tree 优先启动撕咬。已有魔法蓄力、释放或收势不会阻挡这个入口；也不会因为撕咬启动而被取消。
- 撕咬进行时，魔法通道就绪仍可以由同一棵树启动，两通道各自推进。物理攻击不引用 MagicAttack。
- AI 的 Hold 条件只在已有攻击运行、并且另一通道不能启动时保持；没有在 Tick 另建攻击决策。
- 两通道共用角色骨骼刷新预算，由角色统一持有，避免其中一个结束时关闭另一个所需的骨骼刷新。
- 目标失效、AI 关闭或硬控仍可取消对应攻击。死亡/受击生命系统仍沿用前一阶段未制作的边界，不在本次扩展。

## 动作和数值

| 项目 | 设置 |
|---|---|
| 动作 | A_M25_Bite_V01，1.4 s，30 fps，43 帧，非循环 |
| 蓄势 | 前半身回缩，八组口缘向外张开 |
| 咬合 | 前半身前探 18 cm，口器额外前探 15 cm，随后环形收紧 |
| 接触窗口 | 动作第 0.60—0.76 s；只命中一次 |
| 收势 | 口缘恢复，身体缓慢收回，与已有 Idle/Move 混合 |
| 物理攻击力 | 65；玩家实际损血经现有物防、格挡/闪避处理 |
| 冷却 | 2.5 s，从进入接触窗口开始，与两种魔法完全独立 |
| 起手范围 | 口器正前方 ±40°，口器到玩家胶囊表面不超过 85 cm |
| 接触形状 | 跟随 socket_maw 的 55 cm 球体扫掠，另加前方与遮挡限制 |
| 朝向 | 起手方向固定，过程中不瞬间追转侧后方目标 |

- 接触窗口前没有伤害；目标在咬合前走出嘴部扫掠范围可以躲避。
- 身体到嘴部的射线以及嘴部接触射线都保留墙体遮挡，避免嘴部变形穿墙造成隔墙伤害。
- 底部支撑骨与触须尖保持原位，根骨不移动。使用原来 147 骨骨架和既有权重；没有重导或减面本体。
- 施法没有全身施法片段，因此撕咬可以完整驱动身体，背部蓄能与电流继续跟随电极。
- 冷却中的撕咬不会阻止魔法使用。未到接触窗口就被取消，只加 0.35 s 撕咬重试间隔。

## 文件与交付

- author_bite.py：从已认可绑定母版制作单独动作。
- M25_Bite_V01.blend：可编辑的动画骨架源，完整网格仍保留在 RigV01 母版。
- A_M25_Bite_V01.fbx：同骨架动画 FBX。
- import_bite.py：后台导入动画，匹配 FBX 根单位，保存动画、骨架与原怪物蓝图。
- animation_receipt.json / asset_receipt.json / delivery_receipt.json：分别记录动作导出、实际资产保存和构建状态。
- Before/：改动前相关源码和被保存资产备份。
- Source/FPSGAME/Monsters/M25BiteComponent.h/.cpp：独立近战执行。
- VortexCofferM25、M25AnimInstance、MonsterCombatComponent：角色接入、动画混合与共享树适配。
- M25MagicComponent：仅将骨骼刷新预算交给角色共同管理，魔法参数与伤害管道保持原值。

仍使用 F6 → 怪物生成 → 涡电匣 M-25。未自动启动游戏、截图、渲染或验收，动作观感与玩法由用户测试。
