## 发现与修复

原 `ReactionClip` 在客机收到 `Dying + bFromKnockdown + DeathLead=0` 时仍返回站立死亡动画首帧，因为客机不会启动服务器的物理回退标记。反应状态先到、尸体姿态包后到时，会出现短暂站起/弹起。

修正：在线客机原生动画图保留上一帧倒地/起身姿态，等待服务器尸体姿态接管；没有历史姿态或骨骼缓存失效时，使用已修正的倒地末帧。服务器物理交接和正常站立死亡沿用既有逻辑。保留本地骨骼空间快照，接地修正不重复叠加。

另一个遗漏位于 `ApplyRig`：按当前网格足部和边界放置组件后，没有同步 `ACharacter::BaseTranslationOffset`。客户端网络平滑会读取旧缓存，在复制角色初始化顺序不同于主机时恢复蓝图旧偏移。现通过 `CacheInitialMeshOffset` 同步实际位置和旋转；网络夹具同时比较服务器/客机的基础偏移及模型世界位置。

正式构建还遇到 `FPSPlayerBodyActions.cpp` 的独立编译错误：`TObjectPtr<UAnimSequence>` 不能由 `const auto*` 直接推导。仅在 `FindRef(Clip)` 后补 `.Get()`，保留原工具格挡行为与其他并行修改。
