# M16 后托与均衡后握把表面修复 R2

本轮针对用户截图里的 M16 异常大片反光、后握把破碎花斑，以及伸缩后托细节损失进行排查与修复。

**后续反馈（2026-10-15）**：用户否决本轮 M16 后托的实际坑洼表现，并明确选择 M4 合格版本直接复用。M16 后托的后续移植入口为 `../M16StockDonor20261015/README.md`。下列源数据复核是历史记录，不构成用户视觉认可；均衡后握把的独立修复仍保留。

## 确认的原因

- M16 伸缩后托的 81,536 个原配件三角形在 UV0/UV1 上全部塌缩。原图集错放在 UV2，而且经过旧流程精度损失，主体中又有 5,687 个塌缩图集三角形；材质仍采样 UV0，切线曾改用 UV2，二者不一致。
- 当前均衡后握把的 35,445 个主体三角形指向原厂接口槽，1,152 个连接颈三角形指向握把主体槽，208 个原厂接口三角形指向连接颈槽。因此握把主体采样了整枪的原厂图集。已核对真实 section → slot 映射，不以静态槽数组的顺序猜测。
- 当前 PIE 中实际组件使用这些网格，天气 MID 的 WeaponWetness 为 0；此次异常不能归因于湿润状态。

## 修复内容

1. 用 M16 旧制作脚本的真实装配变换，将当前 M4 源网格的全精度角点 UV0/UV1、正常角点法线转入 M16。匹配最大误差约 0.005 mm，保留 M16 原有接口与涂层 UV3。
2. 均衡握把恢复主体/连接颈/原厂接口的三角形材质分区；从 M4 同源模型恢复 34,665 个对应三角形的精确 UV，5 个切割后的微小塌缩 UV 三角形在原图集中心附近局部修复。主体的 MetalRegion 恢复为聚合物，安装颈与接口保留原数据。
3. 对均衡握把实际主体做受限表面整理，最大修正 0.25 mm，连接颈和原厂接口几何固定。处理不到 1.5 千个顶点，不整体磨掉防滑槽和轮廓。
4. 将后托高模按已修整低模的位移场贴合，只清理高密度表面微毛刺，再烘焙 4K 结构法线，保留孔槽、螺钉与伸缩机构细节。替换上一轮全图 0.18 强度的过度减弱法线；新的共享结构法线供现有 10 个后托枪型使用。
5. 法线和切线统一以有效 UV0 为依据，保留全精度 UV 与高精度切线；没有重生成枪械或改动游戏数值、手部动作。

## 文件

- `Input/`、`inputs.json`：当前资产、源模型数据、材质图和实际运行组件读取。
- `Before/`：本轮修改前网格与专用法线纹理的恢复副本。
- `Plans/`、`production.json`：逐角点 UV、材质分区和局部位置修订。
- `Detail/`：对应修整后高低模的法线烘焙源、可编辑 Blender 与最终 4K 图。
- `Final/`：保存后的 UE 网格导出和可编辑 Blender 几何源。
- `install_receipt.json`：实际保存回执；`complete` 才表示所有资产保存完成。
- `diagnosis_after.json`：用户明确要求排查范围内的源数据复核，不是游戏视觉验收。

入口：`collect.py` → `read_sections.py` → `author_repairs.py` → `bake_stock_detail.py` → `install.py`。从 SOURCE_MODEL 读取，保留三角形编号；不重跑旧版整批 M16 导入器覆盖后续修订。已保存网格的重导入来源指向本轮 Final FBX。

## 边界

两个网格和共享结构法线均已保存，`install_receipt.json` 的 `complete=true`。最终互斥桥执行返回成功；按用户要求复核两个资产的 SOURCE_MODEL：UV0 塌缩面为 0、零角点法线为 0、读取到的零切线/副法线为 0，均衡握把主体/颈/接口区域错配为 0。此处的切线计数是 GeometryScript 的逐顶点读取，未代替逐像素视觉检查。

本轮先通过现有 UE 编辑器的批次互斥桥读取。制作期间编辑器退出，曾使用后台 commandlet 保存后托；编辑器重新出现后，剩余保存转回同一互斥桥。为修改正在使用的网格结束当前 PIE；本任务没有关闭、启动或重启编辑器，也不自动重新进入游戏。实际表面观感由用户查看，源数据修复与游戏视觉认可分别记录。
