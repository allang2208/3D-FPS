# 201 左肘与前臂蒙皮修复（Skin07）

用户继续反馈左小臂与肘关节扭曲。本版替代 ArmSprint06 的前臂旋转分配，继承其握点、手指和战术冲刺收手轨迹。12 条动画已后台导入保存到现用 Production20260927 路径。

## 实际原因

这次从现用 `SK_LMG201_Manny` 提取实际皮肤、绑定、权重，并读取 UE 压缩动画。原生 V7 绑定没有被改坏；问题在前臂旋转分配。

待机时，肘端 `lowerarm_l` 承担约 126.47° 轴向扭转，两个辅助骨继续累加到 163.30°、200.14°，手腕却回到 130.63°。前臂因此在肘部集中扭转，远端又反向回拧。ArmSprint06 的“辅助骨相对关系保持不变”检查没有识别这个问题；在主骨朝向已经改变后，该关系不能直接继承。

## 使用已有 Skill 方法

- `ue5-fps-arms-animation/references/two-handed-melee.md` 的 V46 前臂旋前分布：肘端归零，沿实际皮肤站点分配累积扭转，固定骨位置和手部接触。
- 直接复用 `SourceAssets/RuneSword20260913/ChargedErgoV43/twist_distribution.py::forearm_roll` 的上臂传递与无轴拧基准。
- 201 原生 V7 的两个辅助骨是主前臂骨的兄弟子节点，不能把它们旧局部角度相加。使用当前手掌相对无轴拧基准的轴向分量作为腕端目标。
- 按现用皮肤主导权重测得的站点分配：肘端 0、近端辅助骨 0.273869、远端辅助骨 0.847869、腕端 1。没有照搬另一武器的具体比例。

作者仅改 `lowerarm_l`、`lowerarm_twist_02_l`、`lowerarm_twist_01_l`、`hand_l` 四条轨道；`hand_l` 的局部补偿保证世界握点与手指不动。连续动作的轴向角跨 ±180° 时按前帧展开。网格、权重、骨长、共享参考姿态及 C++ 未改；右手、枪体、拉柄动作继承上一版。

## 用户指定排查结果

后台导入之后，回读 UE 压缩后的待机、瞄准、冲刺进入/循环和空仓换弹关键帧，共 11 个样本，并用实际权重计算皮肤变形。

- 待机累积扭转由 `126.47 / 163.30 / 200.14 / 130.63°` 改为约 `0 / 35.77 / 110.76 / 130.63°`，没有旧辅助骨扭转叠加。
- 740 个肘部顶点的混合旋转矩阵行列式中位数由 `0.5390` 到 `0.9224`，最小值由 `0.2058` 到 `0.8831`。这是线性蒙皮收缩指标，不是人体体积测量或视觉验收。
- 同一肘缝皮肤顶点带变形后的短轴 RMS 半径由 `1.62 cm` 到 `2.57 cm`，直接反映实际蒙皮表面的收缩减轻。
- 采样骨头位置最大差小于 `0.000030 cm`，手和手指方向最大差小于 `0.000113°`。已有托枪接触与冲刺撤手轨迹保留。
- 安装网格的顶点、权重和三角面未改变。

上述是针对用户反馈的资产与皮肤排查。未启动 UE GUI、PIE、截图或渲染；最终游戏观感仍由用户测试。
