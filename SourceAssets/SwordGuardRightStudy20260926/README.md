# 待机转格挡：右臂路径诊断（只读）

2026-09-26 用户反馈右手过渡不符合人体运动、僵硬，要求查看处理与优化办法。仅做针对性读取、测量及离线关键帧观察，未修改正式资产或运行代码，未启动 UE 或游戏。

## 现状

普通柄与长柄 Guard 正式包散列均与 V23 保存回执一致。V23 只写左臂轨道，因此右臂沿用 V22 保存读回数据；离线图将 V23 左臂键重建到完整姿态。`study.py` 和 `diagnosis.json` 为本轮诊断输入及结果，`guard_*.jpg` 为 V7 裸手参考画面。

- 举起长度 0.20 s；右手相对剑柄旋转约 161.92°，同时右手指仍为原握紧形状。
- 0.075 / 0.100 / 0.125 s，相对握柄转角分别约 21.35 / 80.96 / 140.57°；中间 50 ms 完成约 119.21°，源轨道相对握柄角速度峰值约 2842°/s。
- 手腕原生世界位置端点相差约 6.57 cm，路径总长却约 21.08 cm；肘端点相差约 27.95 cm，路径长约 77.50 cm。肩关节端点相差约 6.77 cm，路径却约 62.46 cm。说明不仅是节奏快，还存在过大的绕行。
- 作者脚本先 `w=ease(t/duration)`，再将握柄旋转套 `ease(w)`，导致转向集中于中段。前臂方向、上臂滚转、肩部位置又按不同阈值接管；保持腕部 14° 目标时，肩肘被迫追随急剧变动的握姿。
- 运行时待机入场另有 0.10 s 姿态混合。它会影响最终实机速度曲线；本轮数值为已保存源轨道，不是实机速度测量。

## 建议顺序

1. 先重选待机与格挡之间的右手／柄相对姿态，使剑跟随稳定握持的右手转向，避免闭握期间绕柄接近半圈。保留剑身的斜挡主方向，但允许微调右手终点握姿；必要时通过剑面绕自身长轴的朝向适配处理握姿差，不能承诺所有终点变换一律不动还能取消 162° 相对转动。
2. 固定肩带的活动范围，给肘部指定下方、略向外的连续弧线，再解腕部。保持骨长，避免用移动肩根补偿全部握姿变化；将恒定腕角改成有起落的小幅曲线。
3. 在原 0.20 s 举起预算内拆出抬臂、转向和制动，消除双重缓动。只在路径仍需要更长时间时再讨论延长视觉动作，不能直接改变格挡生效、招架或输入响应。
4. 保留左手张掌支撑意图；处理现有入场混合及松开格挡时的倒放恢复，避免自然进入、机械退出。

下一轮应先解决相对握柄旋转与肘肩绕行，再调速度和轻微跟随。当前只提出方案，未接入修改。
