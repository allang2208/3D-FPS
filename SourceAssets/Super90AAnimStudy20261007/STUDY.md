# AAnim M1014：Super90 快速装填器动作学习评估

**续研结论（2026-10-07）：** 已进一步分析 RTM 的真实父子骨关系和分指节奏，并把本项目装填器的单位问题追到手腕接触与推杆绑定。当前原厂装填动作的对口阶段，`hand_l` 缩放约为 0.01、手腕距握柄中心约 52.99 cm，推杆参考绑定反向放大约 100 倍。独立研究计算中加入根空间校准后，分别恢复到约 1、8.82 cm 和约 1。8.82 cm 是腕关节到握柄原点的距离，不是指腹接触误差。完整结论、参考分段、下一轮制作范围见 [快速装填重制研究定稿](RESEARCH_RESULT.md)。本轮未修改生产作者脚本、正式动画、模型或运行时。

本轮是用户要求的参考读取与方案评估，不修改运行时代码，不制作或导入新的正式动作，不启动 UE、游戏、截图或渲染。

`read_rtm.py` 实际解析得到：479,568 字节，RTM_0101，89 个采样、67 条骨骼轨道，总位移为零。采样 phase 为 0 至 0.988764，RTM 本身没有秒数或 FPS。解析结果和散列见 `rtm_metadata.json`，变形矩阵见 `rtm_frames.json`。

轨道包含肩、上下臂、上臂/前臂 Roll、双手五指和 Weapon/weapon1，也含身体及腿部。没有名称明确的装填管、推杆或弹药专用轨道。本文件也不含网格、模型材质、父子骨架和参考绑定，所以不能据此确认它就是用户视频中的快速装填器动作，不能直接当作完整装填器资源包接入。

## 可以学习的部分

1. **接触释放与回握时段。** M1014 配置的左手 IK 在 phase 0.012–0.041 从 1 降到 0，0.041–0.941 使用源动作，0.941–0.982 恢复 IK。此数据可作为“先脱离握点、操作阶段不受待机握点牵制、末尾再回握”的参考。曲线语义见 [Bohemia 配置文档](https://community.bistudio.com/wiki/CfgMoves_Config_Reference#leftHandIKCurve)。这不是装填器接触时刻，不能照抄为本项目填弹事件。
2. **完整骨链和分指运动。** 源数据具有手臂 Roll 与指节轨道，可研究腕部如何相对前臂变化、哪些手指先释放或接回。必须结合原始参考骨架还原后再解释；变形矩阵的平移项不是手腕坐标，不能直接拿去做两骨 IK 目标。
3. **时间分布。** 配置 speed 为 0.28，按相位速率推算完整周期约 3.57 秒；未运行 Arma 确认最终播放。不能将 89 个采样直接当作 60 FPS 的 1.48 秒动作。参考格式见 [RTM 文档](https://community.bistudio.com/wiki/RTM)。

读取途径已成立：本轮已独立读取矩阵，无需先安装插件。需要源骨架回放时，可用 [Arma 3 Object Builder](https://github.com/MrClock8163/Arma3ObjectBuilder) 的 RTM、model.cfg 和骨架功能；实际导入要保持源参考绑定和 phase 时间映射，再转入本项目作者流程。其 [import_rtm.py](https://github.com/MrClock8163/Arma3ObjectBuilder/blob/master/Arma3ObjectBuilder/io/import_rtm.py) 明确使用参考绑定还原局部动画。旧 rtm_import 面向 Blender 2.80，不能据此宣称已兼容本机 Blender 5.1。

## 对照当前装填器发现的确定问题

`read_current_loader_basis.py` 只执行当前作者脚本的输入还原阶段，不执行导出、保存或导入。

| 输入家族 | 制作空间左臂长度 | 相对基础姿态 | 手部全局缩放 |
| --- | ---: | ---: | ---: |
| base | 0.422807 | 1 | 约 1 |
| vertical | 0.004228 | 约 0.01 | 约 0.01 |
| canted | 0.004228 | 约 0.01 | 约 0.01 |
| prism | 0.004228 | 约 0.01 | 约 0.01 |
| angled | 0.004228 | 约 0.01 | 约 0.01 |

源文件 `SourceAssets/Super90Speedloader20261007/author_speedloader.py` 仍以 `Ci @ world @ Ki` 直接还原 UE SOURCE 姿态，缺少上一轮冲刺作者脚本的 `evaluation_to_author` 根空间校准。它又使用 `idles['vertical']` 制作 `hand_in_handle`，因此这个问题影响共用的抓装填器手型，不仅影响装了前握把的枪。

同时，该作者脚本仍使用固定旧肘极投影、上下臂独立最短旋转，以及 aux/twist 的 0.2/0.5/0.8 分站。Super90 冲刺前一轮已根据原生绑定调整过这些处理；装填器尚未同步。该发现解释制作数据存在问题，不表示已通过画面确认所有不达标原因。

## 建议的下一轮制作顺序

1. 先修当前装填器的根空间校准、完整骨链弯面与本骨架辅助骨站位；不缩放网格或武器组件来补偿。重新求当前 V7 手型的手掌—把手接触关系。
2. AAnim 先作为人体动作研究供体，还原其源骨架并拆出脱手、搬运、操作、撤离、回握阶段。只有确认动作内容后，才选能用于装填器的片段。
3. 用户 Bilibili 40–44 秒继续决定装填器的行为顺序和节奏；对口、推杆行程、撤管以本项目实际道具和枪械挂点制作。管口在推送期间锁定枪体接触点，手掌跟随推杆，肩肘从完整骨链求解。
4. 保留右手与枪体的握持关系，分开拇指、四指和腕前臂的通道，避免用单一手指开合参数替代抓杆过程。
5. 先完成一段完整装填母版及原厂手型；在母版接触关系明确后派生 1–7 发、空仓、打断和四种握把的接入/回握。保持基础 1.3 倍速度与弹药事务约定，不直接套用 AAnim 的总时长。

README 明确允许下载、分发和 fork；已查看资料中没有独立的标准许可证或源角色/参考骨架许可说明。因此当前结论是可用于动作研究；不能仅以“open source”字样断言整套源数据可直接作为 UE 商用动画分发。正式重定向接入前需明确所用动画和参考骨架的范围，工具自身的 GPL 许可不等于输入资产许可。

结论：有可用学习路径。AAnim 能提供实际手臂/指节数据和接触交接设计，但尚不是已确认可直接替换的快速装填器动画；当前制作空间错误应先修，随后用该参考帮助重建中间姿态。
