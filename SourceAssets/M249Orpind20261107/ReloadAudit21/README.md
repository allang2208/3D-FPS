# M249 换弹自查与修复 · 2026-11-09

本轮按用户“自己检查一下换弹动画”的要求，在后台 UE 预览场景中播放实际动画图、配件、弹链动态、关节修形和动作相机。没有启动 UE 编辑器窗口、PIE 或游戏关卡。

修复内容：

- M249 待机距离修正原先只有定义，没有接入角色赋值。现在实际使用 `(15, 9, -11)`；ADS 分支不变。
- 弹箱换弹开盖时手臂进入相机近裁面。将该动作的枪体锚点移至 `(24, 0, -5)`，同时重算双臂，保持肩部截面在第一人称画面外，保留原生上臂、前臂长度和关节扭转分配。
- 斜握把和倾斜握把的左腕修正原先由距离门限在两帧内撤销。改为独立的松手、回握时间窗，接触时刻保持一致。
- 弹箱铺链后右手经过原厂倍镜和机匣盖。重做抬手侧向绕行、盖板法向避让、随盖压实和松手轨迹，重新求解右臂；普通与空仓动作及五种前握把配置同时更新。
- 换弹尾部直接切回当前待机相位，原先存在约 20 度的手臂跳变。增加只作用于手臂的入场/收尾混合，枪体、弹箱和弹链继续使用动作源姿态。
- 五个握把配置的待机修正含有一段非循环的起始过渡，导致每秒循环接缝跳动。将手臂相对枪根的持握姿态整理为闭合循环；不改枪体原始待机运动。

已保存两条弹箱换弹动画与五个握把 Profile，共 7 个资产。30/45 发侧弹匣换弹资产沿用 Repair20，使用新的运行时回握混合和闭合待机 Profile。弹药逻辑、动作总时长与机械事件时刻没有改变。原资产保存在 `Before.zip`，最终资产路径和 SHA-256 记录于 `install_receipt.json`。

`FPSGAMEEditor Win64 Development` 后台完整构建成功，见 `build_receipt.json`、`build_editor.txt`。之后的修改仅为动画和 Profile 数据，已通过后台 commandlet 导入并保存。

检查记录：

- `release/receipt.json`：39 个场景组合。覆盖弹箱、30/45 发弹匣的普通/空仓换弹、五种前握把、第一人称和左右观察视角。动画计算 60 Hz，完整第一人称画面每秒导出 20 帧。
- `delivery_final/receipt.json`：最后一次右手盖板避让修正的 6 个定向复核组合，包括两条完整第一人称换弹、两条密集右侧接触采样和两条斜握把换弹。
- `motion_metrics.json`：角度连续性及相机位移记录。斜握把普通换弹松手处左腕最大相邻计算帧角度由约 18.92 度降至 4.81 度；空仓由 16.23 度降至 4.98 度。这是该处问题的前后比较，不是整段动画统一速度上限。
- `handoff_metrics.json`：末段回握与下一轮待机接缝。原约 20 度接缝已消除；查看各骨骼记录可区分动作运动与状态切换。
- `clearance_delivery.json`：使用 UE 原生渲染顶点及骨骼映射，对右手和原厂镜体、盖板、机匣做定向表面相交采样。普通抓握接触、全枪所有位置以及其他瞄具不等同于这一项检查。
- `Preview/M249_reload_review.mp4`：六条最终第一人称动作的静音预览，带运行时间和动作源时间。

最终定向采样中，两条动作的右手与原厂镜体均未检出表面相交。盖边分别剩余 1 个、7 个手指接触三角形；原先掌心穿过镜体、盖板的大面积交叠已消除。机匣表面计数包含回到后握把后的正常贴合，不据此宣称全枪所有接触处零相交。最终落盘校验与各检查批次见 `delivery_receipt.json`；7 个资产均与导入保存清单中的哈希一致。

本轮确认动作相机在普通、空仓及拉栓阶段有输出；没有做关卡运行、联机、声音或不同服装组合的验收。原厂镜体和盖板近景的单色 Blender 图仅用于看清表面接触，完整视频使用 UE 实际资产材质。
