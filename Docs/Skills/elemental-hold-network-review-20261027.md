# 元素箭维持消耗与队友搭箭表现：联机复查

本轮用户明确要求检查上一轮交付的遗漏、bug，重点联机。范围为三元素箭 V4 数值、持续拉弓资源、准备／取消／拒绝／收尾，以及队友元素包裹、箭雨脉冲、照明箭头表现。后台构建和隔离 commandlet 执行，不启动交互编辑器、不重新打包。

## 发现与修复

| 问题 | 触发与影响 | 修复 |
|---|---|---|
| 同库存版本的旧档案返还维持消耗 | 客机先上传档案，再拉弓扣 MP／体力；旧上传到达时版本仍相同，会覆盖权威资源。取消后也缺少区分旧上传的版本点。 | 元素箭准备中或仍有待落盘维持消耗时，合并档案保留服务器资源；取消时一次性保存资源检查点、递增库存版本，并给拥有者发送带准备 ID 的绝对资源回执。箭雨准备阶段同时保护同版本上传。 |
| 取消没有立即结束权威拉弓会话 | 技能取消与 PlayerState 的结束请求分属不同路径，技能已退出时服务器可能还按拉弓扣体力。缺蓝处理原先另发不带准备 ID 的通用取消回执，晚到时可能影响后续拉弓。 | 技能取消同步清除权威拉弓时钟，不再为缺蓝另发通用取消回执；拥有者收弓由带准备 ID 的技能回执负责。 |
| 服务器残留“等待取消”标志 | 服务器因换武器、动作中断等主动取消元素／照明箭时，设置了只应由拥有者等待的标志，却依赖客户端 RPC 清除服务器本地字段。之后其他魔法箭会误判仍被占用。 | 匹配的服务器取消入口同时清除本地等待标志；旧准备 ID 仍不能清除新准备。 |
| 放箭被拒绝使用成功收尾 | 库存版本等前置校验拒绝射击后，原入口调用 ShotCommitted，会把已经发生、尚未保存的维持消耗当成完成。 | 独立 ShotRejected 路径：先保存维持资源再退休准备状态；不扣箭、不扣射出基础费用、不启动 CD。 |

维持资源每帧只记待提交标志，不每帧写存档。成功发射沿用原库存事务保存整次资源。保存失败时保留服务器资源所有权，旧上传仍不能返还消耗；实际 CancelFromBow／离场收尾可重试一次性检查点。重复取消与重复回执不再次扣费，也不会把新发生的资源变化回滚。缺蓝提示后仍等待权威资源与清理回执，避免提前解锁下一次准备。

## 覆盖入口

- 主机本地与客机影子档的 TickRuntime：三元素各 3 MP/s，自然回蓝暂停，持续体力仅扣一次；搭箭待机恢复自然回蓝。
- ApplyGuestProfile：正在拉弓、取消后、射击拒绝后、模拟保存失败期间的旧上传；箭雨已预留时的同版本上传。
- ServerCancel／CancelFromBow／ShotRejected：权威时钟、准备 ID、资源落盘与等待标志；旧取消不影响新的准备。
- ClientHoldResources：绝对资源同步、重复回执、错误准备 ID、晚于其他库存事务才到达的旧回执。
- 1–20 级火焰／寒冰／闪电倍率及射出蓝耗；三元素独立 CD；原弓射击、物理命中和修炼回归。
- 第三人称五种搭箭类型：服务器选型、拒绝伪造类型、身体状态归档回读、可靠动作变化识别。
- 15 个现有特效资源引用实际加载；五类搭箭表现创建原生组件；每次切换／清理后旧网格、粒子、曲线和照明灯均释放。

没有新增美术资产或遗漏的导入步骤；技能详情、20 级成长、射出 1.5 倍蓝耗及持续 3 MP/s 的说明与当前数据一致。本轮不再改变已确认数值。

## 验证边界

这不是实际双端通信：没有 NetDriver/socket、两个游戏进程之间的 RPC 传输、真实延迟／丢包、完整地图 BeginPlay 或断线重连。身体状态使用真实反射序列化回读，但不是网络包。NullRHI 能证明资产解析和组件生命周期，不能证明画面亮度、粒子可见度和帧率。

后续双机实测应覆盖：临界蓝量松手／收弓后立即重新搭箭；快速切元素与普通箭；两端观察五种持有特效的出现、切换与消失；晚加入、切武器、死亡及重连；加入延迟／丢包后复查资源和输入状态。各端必须使用同一轮新二进制。
