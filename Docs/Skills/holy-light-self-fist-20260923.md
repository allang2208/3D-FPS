# 圣光自疗：左手握拳

2026-09-23 用户要求：圣光对自己释放时使用新制作的握拳动作，对外释放继续推掌。

## 行为

`FPSHolyLightComponent::ServiceQueue` 在真正开始施法时，按已经选定的目标选择手势：目标为玩家自身时进入 PowerFist；其他友方或敌方保持现有推掌。排队的 Alt 自疗请求保留原来的自疗标记，不由后续松开 Alt 改变目标或动作。

默认施法速度下，自疗动作总长 1 秒：左手小幅提起，随后用 0.09 秒向下压 6 cm。治疗、声音和圣光效果在 0.26 秒下压握紧到位时，通过原来的 `ReleaseAtContact` 一次性触发。魔法值、冷却、治疗量、续疗、修炼和目标规则沿用原圣光逻辑。

| 时间（基础速度） | 阶段 | 被切武器或快速近战打断 |
| --- | --- | --- |
| 0–0.17 秒 | 小幅提手蓄势，`ReadyingRelease` | 返还实际魔法值消耗，取消未生效治疗 |
| 0.17–0.26 秒 | 快速下压并握紧，`Releasing`，尚未成功 | 保留消耗、取消治疗及特效，不补发 |
| 0.26–0.52 秒 | 治疗已提交，小幅制动与持拳后摇 | 已发生治疗及特效保留，立即让出动作 |
| 0.52–1.00 秒 | 收手，`Recovering` | 已发生治疗及特效保留，立即让出动作 |

施法加速同时缩放本动作与治疗接触时钟。沿用共用的成功提交标记和优先级清理；治疗已经发生后，不因中断后摇而撤回。

## 姿态来源与实现

- 姿态与节奏复用 `SourceAssets/LeftHandPowerFist20260923` 的独立握拳动作 V2。基于已接受的符文剑 V21，进一步调整四指的逐节累计弯曲和侧向排列，拇指继续从外侧扣住。保留原手套、蒙皮权重、指骨长度和缩放。
- `publish_runtime_pose.py` 将 `motion_config.json` 与 `fist_profile_v2.json` 发布到 `Content/ColdSteelData/Skills/left_hand_power_fist.json`，作者源与运行时共同消费同一拳形参数，由现有 `ColdSteelData/...` RuntimeDependencies 随项目打包。
- `LeftHandPowerFistMotion.*` 与独立作者源使用相同的相机空间路径、收拢先后、短促整臂制动和时间预算。手指屈曲参数是相对掌面的累计骨段方向，不是给各局部指节重复施加累计角。
- 运行时通过 `FPSCastingMeshComponent` 的共用左臂层适配当前武器骨架，仅影响左锁骨及其子骨骼，右手和枪械继续原动作。没有整副手臂切换到 M4 FBX，也没有改写各枪换弹资产。独立 Blend/FBX/UE 动画保留为作者资产。
- 腕肘衔接使用 V21 的整段变换，前臂旋转沿最短转向传给上臂，肩口支撑随之调整；指骨旋转带着弯曲平面法线越过 90°，避免握拳时指尖翻转。
- V2 收拢时按完整目标拳形计算各指节的局部旋转，再分别插值。修正以尚未收拢的父指节计算目标局部旋转、导致末节抢先过弯的问题。下压的肩、肘也随手腕同步移动，腕部不单独折弯制造发力。
- 起手捕获当前握持姿态；收手交还当时实际的武器握姿。取消时从实际退出进度收回，正常完成或优先级中断后清除握拳分支，后续火球、冰锥、闪电和对外圣光不会继承拳形。

拳形制作使用实际变形手套的手指／掌心分区表面约束，在 V21 周围小范围调整；记录在 `fist_fit_v2.json`。该制作约束只覆盖所选表面及目标拳形，不代表所有武器、收拢过渡或游戏镜头已完成视觉验收。
