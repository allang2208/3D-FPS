## 当前方案：进入游戏后后台异步加载（用户要求回退）

用户反馈仍停在冰锥 94% / 超过 90 秒，明确要求撤回进场强制等待，改成进游戏逐步自动异步加载。以下当前规则替代本文后面的进入门槛设计；后文仅保留失败历史和构建记录。

- `FinishPreparation()` 恢复只等待场景准备，技能不再影响进度条、输入、移动或失败提示。快速进入不额外创建技能加载遮罩。
- 加载页淡出后，从现有 `TransitLoadingSubsystem::Tick()` 自动开始已学资源队列；依旧战技在前、魔法在后，同组目录顺序不变。
- 每次最多发出一个新资源的异步请求，普通异步优先级；缓存引用每帧最多推进 8 项 / 0.5 ms。资源保留并去重，队列结束停止额外 Tick。
- 此队列只负责加载资源，不调用同步等待、强制 Niagara 编译、PSO 预热，也不轮询 `IsReadyToRun()` 或材质 ShaderMap。渲染与编译继续由引擎和原有特效宿主管理。
- 单项缺失、请求失败或 30 秒仍未完成时记入日志并跳过，后续技能继续；不弹加载失败、不锁住游戏。
- 打开启动菜单/暂停时不推进；开始换图取消未完成请求，已完成资源继续保留。进到新场景后重新按当前档案排队并复用缓存。
- 对已经卡在旧技能预载阶段的当前实例，热更新后撤销旧队列及其技能错误，场景已准备好即可放行。未改角色、武器组件原有初始化行为。

本次不自动运行游戏或验收；编译与生效范围另行补记。

2026-10-15 用户要求：进入游戏加载时，按顺序加载玩家学会的战技与魔法，避免等到释放才加载。

## 顺序与范围

1. 初始化冷钢状态模型，读取并迁移玩家存档。
2. 沿用现有地图、地牢或丘陵装配；完整预载模式继续完成可见场景资源准备。
3. 准备已学战技：重击、上挑、大旋风、冲刺攻击、快速进战，按 `SkillCatalog()` 的现有目录顺序。
4. 准备已学魔法：火球、冰锥、冰墙、暴风雪、陨星、灼锋焰甲、龙息、闪电、雷暴领域、雷枪、圣光，同样沿用目录顺序。
5. 完成后才解除加载遮罩的输入占用。快速进入也执行技能阶段，完整预载不再是唯一入口。

仅将存档 `Skills` 中等级大于零、有资源的条目加入此队列。纯数值被动与程序化闪避没有独立资产批次；不按 TMap 遍历顺序、不按快捷栏/圆盘槽位筛选。未绑定快捷栏的已学技能仍会准备。原有角色、武器初始化的提前加载继续保留；本阶段补齐首次使用依赖并形成有序放行条件。

## 资源与生命周期

- `PlayerSkillAssets.cpp` 列出当前运行时资产：主体、命中/落地、预览、材质、音效、战技动作；暴风雪直接复用 `ZoneAssetPaths()`。
- 战技动画使用玩家随身物品实际安装的握柄动画目录；覆盖背包、装备和夹层，长握柄共享动作配置也保留。大旋风只包含这些武器/握柄实际引用的前景材质替换项，遵守运行时特性开关。
- 一个技能完成异步加载和逐资产准备后才开始下一个技能。每帧按 2 ms / 最多 16 个已就绪资源推进；新 Niagara 编译或 PSO 请求主动让出当帧，不同步等待整组特效。
- Niagara 请求渲染管线预缓存并等待 `IsReadyToRun()`；独立材质等待有效渲染 ShaderMap。此阶段不实际释放技能，不创建伤害、扣费、冷却、音效播放或模拟。
- `NS_IceImpactMist` 是世界级附加效果，已由 `UFluidPresentationSubsystem::OnWorldBeginPlay()` 异步加载并预建池；不再重复进入技能强制就绪清单。原世界系统仍保留它的加载和播放，并未删除冷雾或改冰锥主体效果。
- 已完成的 streamable handles 由 GameInstance 的加载系统持有，换图复用并去重；取消只中断当前未完成批次，退出 GameInstance 释放全部句柄。
- 单项最长等待 180 秒，资源失败/超时显示技能名并保留重试与返回操作。退出、换图与重试重置队列游标。
- 联机客户端继续跳过服务器负责的场景装配，只等待本地已学资源；显式清理地图加载标志，保留原先防止 PIE 客机永久卡在过场的处理。
