# M1911：沉稳可靠 + 要害特化（2026-10-19）

用户决定（2026-10-19）：采用方案 A + B，并与此前加入的「要害特化 +120%」结合——更稳的枪更好命中弱点。

## 一、最终效果

M1911 = **稳定的底子 + 要害收益**：

- 后坐更小、回正更快、腰射更紧、连点不劣化、移动不劣化（A+B）。
- 命中头部/弱点时伤害 +120%（上一版的「要害特化」，保持不变）。

两者相乘的效果：稳的枪更容易把子弹送到头上，加上要害乘区，形成"打头才值钱"的高上限用法；打身体依然是手枪里最弱一档。

## 三、代码接线

1. `Source/FPSGAME/Weapons/WeaponHandling.h`：`FWeaponHandling` 增加 `SpreadGrowthScale` / `RecoilLoadScale`（默认 1，随结构体复制，`WithStabilityMultiplier`、沉稳/两脚架叠加都保留）。
2. `Source/FPSGAME/Weapons/GunsmithSystem.h/.cpp`：
   - `FGunsmithStats` 增加 `SpreadGrowth` / `RecoilLoad`；
   - 读取 `base.spread_growth_mult` / `base.recoil_load_mult`（缺省 1）；
   - `Calculate` 里把两者 clamp 到 [0.05, 4] 后写进 `R.Handling`。
3. `Source/FPSGAME/FPSGAMECharacter.cpp`：
   - 连点扩散：`CurrentSpread` 的每发增量与上限同时乘 `SpreadGrowthScale`（`0.003→0.0015`、`0.018→0.009`）。
   - 后坐反馈：`RecoilLoad = 1 + 额外项 × RecoilLoadScale`，只缩放"扩散/移动/滞空带来的额外部分"，静止基础项保持 1.0。
4. `Source/FPSGAME/UI/ColdSteelItemTooltipData.cpp`：详细浮窗在腰射系数后新增两行，只在偏离参考值时显示——`连点扩散增速 50%`、`移动/滞空后坐 50%`。
5. `Content/ColdSteelData/gunsmith.json`：特性表新增「沉稳可靠」`special` 行。

既有浮窗行（稳定性、首发上跳、连射上跳、回稳、腰射系数）本来就由 `S.Handling` / `S.Spread` 计算，数值会自动跟着变，无需额外接入。

## 五、空仓换弹：加速播放，不裁剪动画

`reload_time` / `empty_reload_time` 在 `GunsmithSystem.cpp:120-124` 会被动画片段长度覆盖（M1911 = 1.75 / 2.25 s），所以直接改 JSON 的 `empty_reload_time` 无效。

但角色端的换弹动作本来就是**按时长求播放速率**的（`FPSGAMECharacter.cpp:1340-1393`：`WeaponStateDuration` 取换弹时长，`PlayWeaponAnimation(Clip, false, ClipLength / WeaponStateDuration)`），音效与机械提示点也按 `WeaponStateDuration / SourceLength` 一起缩放（`:1395-1399`）。也就是说：**只要把 resolved 的空仓时长改小，动画和音效会自动按比例加速，不需要裁剪片段。**

实现：

- `GunsmithSystem.h`：`FGunsmithStats` 新增 `EmptyReloadMult`（默认 1）。
- `GunsmithSystem.cpp`：读取 `base.empty_reload_mult`；在 `Calculate` 末尾 `R.EmptyReload *= clamp(EmptyReloadMult, 0.2, 3)`。**只改 resolved 值，`W->Base.EmptyReload` 仍是动画原长**，这样角色端的 `DurationScale = 实际时长 / 原长` 才会产生 0.78 的压缩比。
- `gunsmith.json`：M1911 增加 `"empty_reload_mult": 0.78` → 空仓换弹 **2.25 s → 1.755 s**，播放速率 **1.28×**（比普通换弹只慢 0.005 s，等于取消惩罚）。
- `M1911DevelopmentAudit.cpp`：两处"空仓时长 = 片段原长"的断言改为断言 78% 压缩与加速后的时长。

浮窗与改造台：`empty_reload` 行读取 resolved 值，会自动显示 1.76 s；改造台"改造前/后"列分别是 2.25 s / 1.76 s。

保留项：如果之后想做成"完全无惩罚"（空仓 = 1.75 s），把系数改成 0.7778 即可，代码不用动。
