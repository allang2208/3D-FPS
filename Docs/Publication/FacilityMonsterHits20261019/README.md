## 公开范围和共享宿主

- 可独立重放的本段 C++ 修改直接提交到原路径，工作区中的其他数值、音效、热成像、武器和 UI 修改保留原状。新增 `HumanoidHitVolumeData`、`MonsterNetworkHitHistory` 也在正式 Source 路径。
- 共享地牢、Nurse 职业倍率、F6 名册及玩家命中 RPC 依赖尚未完整公开的宿主。相关修改放在 `Integration/*.patch`，每个目标有具名基线和 SHA-256，见 [接入清单](integration-manifest.json)。依赖这些宿主的 7 对 commandlet 和 2 个生活区实现文件以新增文件补丁保存，避免在缺失前置的公开模块中自动编译。
- 补丁按目标文件分别应用，不是一个可直接套在当前公共 HEAD 的大补丁。`baseline_sha256_lf` 与 `result_sha256_lf` 是 UTF-8/LF 文本散列；共享基线本机路径见清单。先恢复相容宿主、核对前置，再在自己的集成工作区应用对应补丁。完整本机工作区已经含这些改动，不要重复应用。
- 工具中的 `D:/FPS3D/FPSGAME` 和 UE 安装路径是当前本机约定；移机先适配路径。公开配方不会自动提供授权模型或全工程依赖。此公开切片不等于干净检出即可构建完整游戏。

## 资产恢复顺序

模型、纹理、Meshy 输入、供体动作、Blend/FBX、UE 包、密集蒙皮/姿态数据、日志和存档均留本机。制作脚本公开不授予其输入素材的再分发权；商用许可也不等于原素材再分发许可。[保留依赖](local-recovery.json) 与历史回执列明本机位置。

1. 恢复既有 M 系列、无面职员、共享人形行为、地牢区域与多人命中框架及对应合法资产。供体身体为安保 Body V09、接待 Body V04、研究员 Body V01；动作和来源见 [员工制作记录](../../Monsters/StaffLivingEmployees20261017.md)。
2. 恢复本批共享增量与所需 commandlet 后，按需要构建 Editor/Game。员工作者入口为 `Tools/StaffLivingEmployees/read_sources.py`、`install_assets.py`、`save_assets.ps1`；本机已保存三份 `/Game/Monsters/StaffLiving/BP_LivingStaff*`。
3. 女性肩部恢复保留的原生作者输入与 Diagnosis 绑定数据，再使用 `Tools/StaffLivingShoulder/repair_shoulders.py`，由 `install_repaired_assets.py` 保存两份 ShoulderV02 和原员工蓝图。早期 `repair_female_b.py` 已退役，不重跑覆盖最终两角色结果。
4. 人形命中作者为 `HumanoidHitVolumeAuthoringCommandlet` / `Tools/HumanoidHitRepair/install.ps1`。先恢复整体 Revision 1，再为 `BlindSupplicantM07` 恢复 Revision 2（`-Only BlindSupplicantM07 -Revision 2 -Label m07-cranium`）。最终盲祷者使用 `PA_BlindSupplicantM07_R2`，其他模型按保存回执。保留源模拟/布料资产和作者 Before，不用新查询形体替换模拟约束。
5. 非人形作者为 `NonHumanoidHitRepairCommandlet`。保留的 `baseline-full.json` 是原始几何输入；不得用修复后的采样覆盖。干净原始资产可按 `complete.ps1` 的首次流程制作，已含本批形体的资产用 `refit.ps1`/`repair.ps1 -Refit`，只移除自身命名形体；预算最多 384 个新增凸包。本机最终结果已经保存。
6. 诊断工具只在用户明确要求测试时运行。不要为了恢复资产顺带调用整批 audit、PIE 或主客机测试。仅需保存时使用独立 authoring/repair 入口。
