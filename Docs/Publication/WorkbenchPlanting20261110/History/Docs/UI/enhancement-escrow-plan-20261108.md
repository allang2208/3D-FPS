## 信息结构与响应布局

- 固定顶部：工作台名称、Esc 返回、强化／附魔切换。
- 正文第一卡片：工作台暂存、实际武器名与强化等级、已有词缀、放入／替换说明。
- 正文第二卡片：卷轴来源提示、全部／前缀／后缀筛选、横向卷轴列表、本次消耗。强化模式继续显示强化材料。
- 正文第三卡片：附魔／强化项目、实际前后属性和变化、对比当前／基础入口。完整详细汇总保留。
- 固定底部：空台／已暂存状态、实际失败或成功原因、等宽取回背包与确认按钮。空台禁用取回；取回结果由业务入口返回。
- 沿用共享 FColdSteelEnhancementLayoutMetrics：宽屏并列；可用宽度不足或矮窗时面板移至场景下方。正文纵向滚动，卷轴横向滚动；小于 410px 的面板保持可读内容宽度并横向滚动，不压缩整个画布或背包格子。
- 当前武器完整卡片留在正文滚动区，避免紧凑高度下挤掉材料／结果；底部保留一行暂存状态，操作时始终可见。
- 短标签和按钮明确关闭自动换行；长说明可正常换行。长名称省略并保留全文提示。不采用逐字竖排。

## 样式与生命周期

继续使用 ColdSteelUIStyle 颜色、标准操作高度与 GunsmithUI 像素字号入口；普通文字为 Noto Sans SC，纯数字为 JetBrains Mono。世界面板只使用一个外层玻璃模糊，内部分区复用 RowBrush。无新纹理或捕获队列。

UMG 宿主承载 Slate，继续由现有变化事件刷新数据与报价。新增状态属性只读取当前 ItemId，不扫描背包、不读写 JSON、不增加 Tick 或计时器。Construct／Destruct、输入焦点、拖放取消、关闭时阻止攻击穿透沿用现有控制器与宿主入口。

## 数据与状态合同

1. 放入：真实装备从背包或装备槽转移到每玩家持久化工作台暂存位；保留实例 ID、强化、附魔、配件及物品数据。不是保留可装备副本的预览选择。
2. 替换：在同一事务快照中移出新武器并尝试将旧暂存武器放回背包。容量或占格不允许时整笔不提交；旧武器继续暂存，新武器保持原位置。不得先销毁旧物品再失败。
3. 取回：显式取回背包，成功后清空暂存与选择；背包空间不足时保留物品并显示原因。关闭面板不等于取回，避免满包造成丢失。
4. 关闭／重开：暂存由档案持有，Widget 生命周期不拥有物品寿命。重开读取真实暂存物品；空台不默认从背包抓取武器。
5. 强化／附魔：预览与提交针对同一暂存实例；成功后物品继续暂存，更新真实属性与世界预览；不自动装备。
6. 卷轴：仅背包正数量堆叠，按现有规则合并。仓库独有或未持有卷轴隐藏；已持有但不兼容者禁用并说明。列表、数量、默认选择、报价及扣除同源。用尽或移出背包后清除失效选择。
7. 其他资源：魔法粉尘、强化石继续使用现有背包＋仓库范围，灵魂读取独立钱包。缺材料可预览但不能提交。
8. 持久化迁移由档案层负责；旧存档无暂存记录时视为空，不从已有背包／装备记录复制出新物品。UI 不单独新增存档结构。
9. 无卷轴、未选择、不兼容、材料不足、空间不足与提交失败均保留真实原因；不伪装成操作成功。图标继续目录图回退及原完成通知。
