# 家具坐卧、双人床占位与源码发布

本批公开椅子／沙发／床铺的休息组件、原生全身镜像、床上 SAN 恢复、动作配置和制作工具。当前配置包含 25 种家具、45 个位置：12 种座椅／沙发类，13 种床；其中 7 种双人床有独立左右槽，另 6 种床仍为单槽。四款上下铺只配置下铺，上铺未接入，不能把模型数量当成所有可见铺位均支持交互。

## 行为与发布范围

- E 键、搜索容器同类高亮、鼠标自由看向与动作占用沿用公开主线已有的角色、PlayerController、HUD 和相机入口。本批补齐此前尚未公开的 `FPSFurnitureRestComponent` 与 `FPSBodyFurnitureLayer`，并精确加入镜像节点、原生眼位来源校验和 SAN 消费者差量。
- 双人床的一侧占用后，另一玩家可在正常交互范围内选择空侧，不必先走到特定床边。服务器按组件、ISM 实例和槽位判定预约；单人床与单座椅被占用后拒绝其他玩家。对齐至退出完成都保持占位，客户端提示不替代服务端重新判定。
- 镜像使用原生参考骨架上的完整 pose，进入偏移、朝向、退出点和眼位随同一状态映射。不是负缩放网格。当前休息状态为运行期状态，不保存成跨会话床位占用。
- 躺稳 Idle 后由服务器恢复 SAN，默认 5 点/秒并限制上限；原地牢消耗继续叠加。进入、退出、坐椅阶段不恢复。
- 当前上床动画 3.3 秒加 0.6 秒对齐，共 3.9 秒；下床采用匹配的反向源时钟，3.4 秒。男女身体各 54 个动作角色，共 108 条动画引用；运行表和眼位字段见 `body-fields.json`。
- `Config/DefaultGame.ini` 显式保留男性家具动画目录，女性动画由已有 Kaitlin Cook 目录覆盖。动作由 JSON 引用，不能只依赖资产注册表推断 Cook。存在打包规则不等于已经执行打包。

这不是完整游戏或完整素材备份。公开主线仍有其他批次尚未完整公开的共享前置；本批仅重放家具所属差量，没有复制本机完整共享宿主，也没有重新构建裁剪后的公开树。不能将本机整合构建成功当成干净检出可直接运行的证明。其他任务已经暂存的内容通过独立发布索引隔离，原暂存修改保留。

## 恢复和继续制作

1. 工程仍从 `D:/FPS3D/FPSGAME/FPSGAME.uproject` 打开。`Content` 联接到 `F:/FPSGAMEData/Content`；DDC 使用 `D:/FPS3D/DerivedDataCache` → `F:/FPSGAMEData/Caches/DerivedDataCache`。当前路径和各目录职责见 `WORKFLOW.md` 第 4.1 节。Git 不保存 NTFS 联接目标的数据，恢复时应先还原真实资产，再建立对应入口。
2. 合法保留 Fab 家具、Jason/Kaitlin 身体及用户 Meshy 多动作 GLB。原 GLB 的 `*_sleep` take 是完整休息过程；不能仅凭 `Sit Lie Bed` 名称选取一个局部躺卧循环。付费商用许可不自动授权在公开源码库再分发原文件。
3. 原始文件、密集骨骼／几何／蒙皮数据、作者采样、UE `.uasset` 和完整回执在 `SourceAssets/FurnitureRest20261022`、相关身体制作目录及正式 Content 中保留，本批没有移动或删除。108 条当前动画路径列于 `local-assets.json`。这些输入需从本机/NAS 和合法素材来源恢复；配方脚本不是素材替代品。
4. 坐姿当前链：`RelaxedSeatV5` 的坐稳、`HangingEntryV6` 的自然下垂进入、`ReversedExitV7` 的退出；其他椅子使用 `ChairReuse20261024`，有扶手的办公／会客椅退出使用 `ArmrestExit20261024`。旧作者与标定工具仍用于重建，不按日期退役。
5. 上床当前链：Meshy 提取／原生重定向 → `MeshyBedSupportedHands20261024` → `MeshyApartmentBed20261024` → `ApartmentLegTransfer20261024R2` → `ApartmentFastRest20261024R2` → `ApartmentReverseExit20261024`。其他床使用 `BedFamilyReuse20261024`，医院／病床／下铺的最终进入与退出修订在 `BedFamilyReuse20261025`；当前 Idle 仍保留其各自有效源。
6. `BedNaturalV8`、`BedSupportedV9`、`BedHandDriveV10` 旧发布结果已被替换，但部分作者函数、几何和标定仍是上述流程输入。其旧保存／发布入口已经归档；不能按旧说明重新发布被否定的版本。保留的初代作者工具仅为恢复配方，不是当前生产安装入口。
7. 制作依赖 NumPy、SciPy、Blender、UE 5.8.2 及项目原生动画作者接口。当前包装脚本按原生男女动画分别采样，`should_retarget=False` 防止二次重定向；相机轨迹必须与实际 clip 和身体变体匹配。
8. JSON 写入使用 `Tools/PlayerBody/config_transaction.py` 的具体字段归属；家具数组从新读取内容合并并持有家具配置锁。先保存资产，再更新对应角色／时长／相机；跨多个文件不是一个原子事务，按保存回执恢复未完成步骤。不要直接重跑旧配方去覆盖当前全部配置。
9. `publish_double_occupancy.py` 为 7 款双人床添加左右槽，运行镜像复用当前资产，不生成一套负缩放模型。适配新床时先给出实际锚点与可用槽数，不把本案偏移数值推广给任意模型。

## 已有证据与待体验范围

本批整理前，完整本机的双人占位版本已完成 Editor 和 Game 后台构建，两个回执 `runtime_tested=false`。没有为这次仓库整理启动 UE 或重新运行游戏。

此前单占位版本完成 437 项隔离组件检查，覆盖配置中的 25 个模型、当时的 38 个位置、108 个男女原生动画包、服务器单占位拒绝、SAN 阶段、受伤退出和状态恢复。角色交互夹具使用男性角色并人工推进阶段时间，女性仅检查资产匹配；它不是最新双人占位检查。

此前六阶段本机三进程 UDP 夹具配置了 60 ms 延迟和 5% 丢包，服务器注入 Phase 3/0，只证明初始／晚加入状态和清理同步，没有执行真实 E 键抢位、双人同步上下床或网络 SAN 验收。双人版的同时抢位、退出交接、断线、晚加入、实际服装碰撞、跨机器和打包版本仍需用户体验或后续明确授权测试。不要重用旧通过数字扩大验收结论。

`review-summary.json` 摘要保留上述边界。`run_completion_audit.ps1` 和 `FurnitureRestAuditCommandlet` 是旧单占位夹具，未经更新不代表能完整验证新双槽镜像；本次只发布以便后续维护，没有自动执行。
