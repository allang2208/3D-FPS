# 村庄店员源码恢复

本目录承接 `ArtisanVillage20261119`。入口清单为 `native-baselines.json`，清单中的 `path` 均相对于 UE 项目根目录。恢复时先读取每条记录的种类和输入摘要，再处理对应文件。补丁只修改这次交付的功能；开发宿主内其他功能的版本需要和目标工程匹配。

## 恢复顺序

1. 从 Git 提交 `c8d8c3b8502274e38b297462753c213a53aabbec` 取得上一批目录。按其 `Integration/GAMEPLAY.md` 恢复丘陵存档、村庄流送、教堂修女、两家工坊、交易与个人档案、工匠课程及联机审计宿主。保留该批没有更改的文件，清单的 `unchanged_inherited` 列出此次对比过的同名文件。
2. 依 `kind=implementation` 将上一级 `Implementation/Source` 内的 45 份源码按同名路径并入目标工程。包含两名工匠的权威生命、警戒、武器、倒地和挽救，三名店员、对话、药草师闲逛、店面恢复、柜台交互、局部后处理，以及三个可按开关启用的联机探针。已有定制实现时逐项合并。
3. `kind=normal-source` 的酒馆陈设实现在仓库的正式 `Source/FPSGAME/WorldGeneration/HillsTavernInterior.cpp`。其头文件沿用上版。贴图、蒙皮网格、地图和后处理材质仍需目标工程中对应的 UE 包。
4. 按下表选择 71 份共享宿主补丁的输入。同一宿主本批只有一份补丁。先从工程根目录对对应文件执行 `git apply --check <补丁路径>`，再用 `git apply <补丁路径>` 合并。保持现有其他功能时，以补丁的上下文、两侧代码及其函数位置逐段核对。已有本地生产版本若与输出摘要吻合，该项已经恢复。

## 共享宿主的具体前置

- 村庄修复与刷出需要已接入的方案版本 1–8、村庄流送完成回调、风车修复、施工区域占用检查、工作站可用性以及服务端生成的店员。药店使用原字节的位 16；面包店在版本 9 使用独立布尔值 `bVillageBakeryRepaired`。修复请求的临时位值为 256，旧存档的字节布局继续沿用。面包屋地图需带 `VillageBakery.Site`，酒馆需带 `VillageTavern.Site`。烘焙店面恢复使用现有工程的 `VillageChimneySmoke`。
- 输入和界面需要现有村墙和普通交互共用的 `FUseTargets`、`TraceUseTargets`、家具与容器优先级、Cold Steel 进度条样式、角色眼位及第一人称相机实现。将柜台候选保留到普通 E 交互之后，倒地挽救在普通对话之前处理。柜台规则同时进入拾取遮挡、HUD 提示和服务器触达判定。绿色轮廓和店内受光层使用两个正式后处理材质及已有渲染模块和 Groom 组件。
- 敌对逻辑需要丘陵导航、AI 感知、遭遇范围、怪物共享近战/远程判定、丢失目标时的替换流程和可选的私有不明人形攻击宿主。公共补丁把具体怪物原本只找玩家的命中、范围和死亡判定接入 `MonsterTargeting`。共享 AI 和不明人形的后续改动按本地宿主处理。
- 交易使用玩家状态现有的 `Shop` 请求、角色个人钱包、权威回执应用和重连续传。共享控制器只负责发起与结束，单次库存变更由原有权威档案事务落盘。运行三个开发探针需要上一批村庄联机审计组件及客户端/房主回执和加载支持。

本包逐份对补丁输入与输出做过文本重放并记录摘要。该步骤不覆盖从公开仓库单独构建、重新烹饪资产或启动联机游戏。
