# 草地倒伏与恢复表现提升计划

2026-09-27。初版为只读评估；用户随后批准调整，P1/P2 制作状态见 [v12 制作记录](grass-response-v12-20260927.md)。下文保留评估时的 v11 问题和提议，不作为 v12 实测结论。

## 结论

设计和编码都有问题。当前 v11 已修正先前逐顶点位移造成的宽三角，但尚未达到用户想要的“明显压倒、留下痕迹、清楚抬起”的表现。主要缺口是**没有完整设计交互的时间过程和可见范围**；现有代码还缺少静止保压、连续恢复和统一方向输入。继续只增加 BendAngle 或把 18 秒改大，不能同时解决倒伏与恢复不明显。

保留现有 GPU RT + PivotPainter 路线及 v11 防拉伸修正，补充接触与草痕两层表现。原方案的性能方向可保留，但“CPU 近零”“1 次采样”等预算不能代替效果目标，也不能当成已测事实。

## 2. 当前实现为什么不够明显

| 发现 | 代码／现有证据 | 判断 |
|---|---|---|
| 全强度倒伏带过窄 | 默认胶囊半径 42 cm，踩踏半径 max(75,42×1.8)=75.6 cm；stamp 只有半径内侧 40% 保持全强度，所以核心宽约 60.5 cm，小于 84 cm 胶囊直径 | 范围设计缺口，已由公式确认；实例／蓝图覆盖尺寸时应重新计算 |
| 范围外半圈看起来还站着 | 距路径中心 60 cm 时，当前平滑衰减得到约 .273 强度，对应约 21.3° 旋转，直立草的理论剩余高度仍约 93% | 不应把总影响直径约 1.5 m 叫作明显倒伏带宽 |
| 压下就开始恢复 | `FADE_CODE` 直接 `max(0, old.r-Step)`，`RegrowthSeconds=18`，没有 Hold 时间 | 时间设计缺口；18 秒不是保持倒伏 18 秒 |
| 回弹没有节奏 | `angle = 78° * amount`，RT 默认 6 Hz 更新，材质没有在两次更新之间解析持续的恢复过程 | 显示约每 0.167 秒改变一次，整体角速度缓慢；不是有保持和抬起阶段的动画 |
| 停住后草会继续起身 | `UpdateTrampleSource` 要求累计位移及速度 ≥60 cm/s；角色站在草里也不再写接触 | 对“人体持续压住草”的目标而言是编码缺口 |
| 重复踩踏只有强度覆盖 | stamp 使用 max(old,new)，没有独立接触年龄、保持时间或累计踩踏状态 | 无法独立配置重复踩踏的停留／恢复行为 |
| 脚步方向未传给形变 | Feedback 算出 TravelDir 后只传给 PlaceDecal；StampGround 仍只传位置、半径、强度，得到径向 stamp | 注释与实际实现不一致，弱草痕重叠时存在方向竞争 |
| 素材和机位削弱差异 | 参考截图为宽叶、绿色、轮廓整齐的第三人称草地；本项目为混合细碎枯草卡片，第一人称高草遮挡；测试 HISM 还关闭投影 | 从图片及场景代码得出的辅助因素，不能当作强度／时间问题的替代解释 |
| 原验收判据不足 | 24 项主要证明 RT、移动、门控、脚步池等有效，没有规定倒伏带宽、最低草高、保持／抬起时间和正常视角识别度 | 过程缺口；数值通过不代表用户观感通过 |

源码入口：`Tools/GrassDeform/setup_assets_m1.py:184`（形变）、`:282`（stamp）、`:300`（fade）；`GrassDeformTuning.h:55`；`GrassDeformSubsystem.cpp:130`、`:799`、`:873`；`GrassFootstepFeedbackComponent.cpp:202`。

一个说明现有时序的简化模型：以满强度、原本竖直的草为例，忽略风、原始倾斜及位移限幅，剩余高度约等于 `cos(78° × (1-t/18))`。刚压下约 21%，2 秒后约 35%，6 秒后约 62%，9 秒后约 78%。这不是实机测量，但说明“18 秒才完全恢复”和“18 秒内一直明显压倒”不是一回事。

## 3. 首版目标参数

先做一个明显、可读的高草预设，下列为调校起点，不冒充参考项目默认参数或已达成效果。

| 阶段／指标 | 建议起点 |
|---|---|
| 人体拨开／压下 | 接触边缘约 0.10–0.20 秒内进入受压姿态；运动和静止都维持身体占据范围 |
| 明显倒伏核心 | 宽 0.9–1.1 m；外围连同过渡共约 1.5–1.8 m。优先将核心占比从 .4 调至约 .65，而非无限扩大总半径 |
| 核心姿态 | 最大倾倒约 75–80°；实际草顶高度目标降至原来的 25–35%，以真实网格为准 |
| 离开后保持 | 默认约 2.5 秒，核心维持低姿态；从最后一次实际接触开始计时 |
| 明显抬起 | 随后约 3.5 秒完成主要恢复，使用两端缓、中段清楚抬起的曲线，材质逐帧连续计算 |
| 重复经过 | 更新局部最后接触时间，延长该处保持；不让整个世界的旧草痕一起重置 |
| 风 | 保持阶段保留 0–5% 弱风；恢复后半程再逐步接回正常风，避免压倒的草还横向漂 |
| 长痕迹预设 | 后续可加保持约 15–25 秒、恢复约 4–6 秒；与默认明显回弹预设分开 |

优先通过可读性目标后，再允许轻微个体差异。首版不增加强震荡、随机抖动或颜色闪变。

## 4. 实施顺序及交付

### P0：固定行为基线

保留 v11 资产备份、原高草密集场和现有截图。明确上述“宽度／高度／保持／恢复”四项为新目标；将人体经过、单脚印、爆炸分成不同响应预设，避免一个参数牵动全部效果。后续运行对比以同样网格、密度、天气和机位进行，先不要同时换草和改光照。

交付：草响应配置表／DataAsset 或等效集中配置；前四阶段参数可在制作端调整，不再散落在 C++ 常量和 Python/HLSL 默认值中。新版本和实际已保存的两个主材质应有可查询标识。

### P1：明确压倒范围和接触行为

保留每片草根部采样、完整旋转和整片统一限幅。扩大全强度核心，将“向两侧拨开”的外沿与“明显低伏”的核心分开。行走方向稳定传给轨迹，单脚印不在弱区域无意覆盖为随机径向方向。

增加独立的人体接触层：着地时身体范围持续维持受压，离开／跳起才释放；无需每帧逐草查找或逐实例变换。MPC 的角色位置驱动连续近身响应，历史 RT 负责离开后的痕迹。一次接触的边缘过渡及后沿写痕要衔接，避免 10 Hz 事件瞬间把草跳到满角。

交付：改 `GrassDeformSubsystem.*`、`GrassDeformTuning.h`、`GrassFootstepFeedbackComponent.*` 和 `setup_assets_m1.py`；两个实际主材质同时制作、编译、保存。先以现有网格得到明显通道，不恢复逐顶点方向场。

### P2：重做保持与恢复时序

将“触压强度”和“最后接触时间”分开，恢复不再靠 6 Hz 每次减一点 R。材质根据每个位置的接触年龄，连续计算 Hold 后的恢复曲线；新事件合并前要计算旧事件在当前时刻的有效强度，不能把陈旧最大值重新激活。

推荐第一条实现路径：保留 RGB 形变 RT 对，再增加一对 **R32F 接触时间 RT**，与形变数据成对 stamp/recenter。时间使用 32 位，不往原来没有有效 Alpha 写入的 Opaque Emissive 路径硬塞时间，也不把长时间绝对秒数放进半精度通道。1024² 下额外约 8 MiB，合计约 24 MiB（不含引擎额外开销）。

首版沿现有绘制接口时，每事件可增加为最多两个 RT 绘制；不能继续沿用“永远一次 DrawMaterial”的旧承诺。取消仅为动画而执行的逐步 fade，保留必要清理及有界活动时间。确有性能证据时再考虑单 pass 多目标输出，不先扩成全场物理模拟。

人体静止接触的时间刷新可节流，近身形态由材质连续计算；离开后的恢复起点误差应小于该刷新间隔。关开关、离开窗口、换地图时两个 RT 对统一复位，整数像素 recenter 规则保持。窗口外痕迹仍不永久保存，这不是持久化足迹系统。

交付：明显的“低伏保持→抬起→接回风”过程；相关参数进入同一响应配置。第一版使用共同踩踏时序，之后才细化短草／高草的独立预设。

### P3：补自然感和视觉对比

P1/P2 的形态与时序达到目标后，再调整侧沿的渐变、同丛草叶之间小幅差异和风衔接。原素材偏枯黄、细碎，不默认替换为参考项目的绿色宽叶风格。

必要时在测试场增加独立对照小区：现有草与更竖直的兼容草各一组，保持生产草不变，分辨素材轮廓对观感的影响。是否加近景投影、法线随旋转或轻微受压着色，按实际画面决定；不能靠贴花、隐藏草、减密度或改黑地面来冒充倒伏。

## 5. 后续视觉确认标准

本轮只制定标准，不自动执行；用户自行体验，或明确要求后再采集对照。

1. 正常第一人称机位经过 5–8 m 高草后回望，能直接识别连续倒伏带，不要求低头贴地或放大截图。
2. 核心宽度达到 0.9–1.1 m、草高约为原来的 25–35%；两侧有过渡，无大块三角、断片、草根滑动或穿地消失。
3. 最后接触后约 0／1／2.5／4／6 秒，同一机位能看到低伏保持、开始抬起和恢复完成的不同阶段。应使用短视频或连续帧确认节奏，不能只看前后两张图。
4. 站在原地 10 秒，身下仍受压；离开后才按约定保持并恢复。慢走、蹲走、冲刺、拐弯和重复经过不造成忽有忽无或方向突然翻转。
5. 恢复发生在原世界位置，跨纹理窗口边界不漂、不变糊；关掉交互后正常风与原网格外观仍成立。
6. 新视觉标准之外继续保留已有 RT／门控／脚步池检查，但不再以“24 项通过”代替观感。传送、水体、武器及其它玩法不作为这一轮效果完成范围。

## 6. 范围与决策

优先实施 P1 + P2，它们直接解决用户当前两项反馈；P3 是后续精修。保留 GPU 实现，不因参考项目使用 Blueprint 或部分实例变换就否定其设计，也不立即重写成全场 CPU 草模拟。若后续现有草片刚体旋转仍达不到所需曲率，再单独评估保长度的分段弯曲，并要求所有 LOD 适配后才能推广。

完成制作时分开交付源码、DLL、实际保存资产、运行证据与用户视觉确认状态；本计划不宣称任何新效果已实现。
