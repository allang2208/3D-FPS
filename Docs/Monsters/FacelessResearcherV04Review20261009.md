# 研究员 M-05 V04 复查（2026-10-09）

用户反馈 V04 基本合格，授权回查 bug 和遗漏。本轮只读检查当前 UE 蓝图／网格／动画数据、对应播放代码及 Blender 作者数据；未启动 PIE、生成怪物、施加伤害、截图或渲染，未修改已认可的游戏资产与玩法代码。

## 发现

### 1. P1：击倒与起身动作没有接入研究员骨架

当前 `BP_FacelessResearcher` 的 Knockdown 已启用，但 `FallClip`、`GetUpClip` 和 `ProneGetUpClip` 均为空。`UHumanoidKnockdownComponent::BeginPlay` 根据角色分组加载 Nurse 默认动作；这些资源使用 `/Game/ZombieFemale/Asset/Meshes/SK_ZombieFemale`，研究员网格使用独立 `/Game/Monsters/FacelessResearcher/SKEL_FacelessResearcher`。

`HumanoidKnockdownComponent.cpp:59` 严格比较骨架对象，不相同就清空三段动作；`:117` 又在缺少倒地／起身动作时直接拒绝 `Launch`。因此研究员目前不能按共用流程进入可恢复的击倒，普通受击正常并不能覆盖该遗漏。该结论来自实际资产读回及确定的代码分支，未通过游戏触发复现。

同一遗漏还影响死亡降级：物理预算不足或启动物理失败时，`:238` 使用 `FallClip`，而空片段在 `:428` 退为保持当前姿态。常规布娃娃可用不代表动画降级有正常倒地表现。

建议单独派生 Nurse 的倒地、仰卧起身和俯卧起身至研究员骨架，补齐各片段衣物适配，再明确绑定本角色组件。不要删除共用骨架一致性保护来绕过问题。

### 2. P2：眩晕循环动作未接入

当前 Combat 的 `DizzyClip` 为空。`MonsterStunPresentation.cpp:36–48` 加载 Nurse 的 `A_Nurse_Dizzy`，随后因同样的骨架对象不一致将其清空；`:65` 的持续摇晃入口依赖该片段，所以长眩晕只能沿受击／停留逻辑表现，缺少共用人形的持续眩晕摇晃。状态控制效果本身与动画缺失分开，未声称眩晕数值失效。

建议制作研究员自己的眩晕片段并适配衣物，配置 `Combat.DizzyClip`。

### 3. P2：攻击结束切待机／移动缺少姿态过渡

`NurseZombie.cpp:124` 直接 `PlayAnimation`，攻击结束后 `MonsterCombatComponent.cpp:242` 通过 `SetState` 重新从待机／移动开头播放，没有姿态混合。保留的本轮动作输入进行离线端点测量，攻击末帧到待机首帧左手相差约 34.47 cm、双脚约 19.59／21.06 cm；到移动首帧左手约 51.90 cm、右脚约 24.53 cm。数据为未乘角色 1.043208 组件缩放的源骨骼坐标，不是游戏录屏测量。

这说明切换存在明显姿态不连续；是否在具体距离、AI 切换时刻显著可见，仍需游戏确认。建议仅为研究员补攻击收势到待机／移动的连续过渡，同时让衣物曲线随姿态混合，保留命中窗口和四段已认可动作主体。
