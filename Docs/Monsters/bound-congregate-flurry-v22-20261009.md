# 缚群 V22：四前肢连续拍打

用户明确要求检查并优化僵硬的拍打动作，并寻找《艾尔登法环》王室幽魂的拍打方式。本轮范围为连拍动画、相应命中肢体及指定的动画检查；保留 V21 网格／布料、撕咬、触手、移速与伤害数值。

## 参考获取情况

定位到 EIP Gaming 自制攻略的王室幽魂 `Flailing Advance` 演示入口：<https://eip.gg/elden-ring/guides/how-to-beat-the-royal-revenant/>。页面描述多臂连续挥打并前冲，包含连拍及起手动图链接；媒体服务器下载返回 HTTP 403，未进行逐帧时序测量，也未取得原游戏可导入动画。Gamer Guides 的独立来源同样返回 403，未继续绕过访问限制。

因此 V22 是按多肢交替、身体前压与连续衔接的方向，适配缚群已有专用骨架重新制作的动作；不声称移植或逐帧复刻法环资源。没有法环游戏文件或网页媒体进入 Content。

## 原动作检查所得

- 现行 V17 只让 L1/R1 两条前肢攻击，其余肢体一直承担支撑，缺少多臂接续。
- 旧 `forelimb()` 将抬手、提肘、预备、接触、回收串成多段轨迹。一般段的 quintic 插值在各关键点归零速度；出掌段使用不同加速公式，接触后又立刻进入 35 ms 固定停顿。动作因此出现重复停顿和速度突变。
- 旧四次普通拍击重复相同轨迹，双臂同时进入高位等待，收势变化有限。运行时已经保留作者肘面，单改地形 IK 不能解决这些源动作问题。

## 制作与接入

- 四拍次序为 **L1、R1、L2、R2**，末拍仍为 **L1+R1 双掌重拍**。每肢独立起手、弧形回收、手腕滞后；第二对前肢先回到支撑，第一对完成重拍后错开落回。
- 使用带通过速度的 Hermite 路径，接触后经过短暂下压再弧形退出，不在所有抬手／回收节点停住。
- 躯干先前压、左右承重，后部作反向平衡；前部、嘴部参与小幅延迟回弹。六条后部支撑肢继续做离线落点约束，肢长不缩放。根据可达范围最多小幅收束身体行程。
- 仍为 120 Hz 作者动画，长度 2.15 s；出掌起点 `0.44 / 0.64 / 0.84 / 1.04 / 1.50 s`，命中 `0.52 / 0.72 / 0.92 / 1.12 / 1.60 s`，转向截止 0.38 s 均保持。
- `motion_contract.json` 同时生成 `BoundCongregateMeleeTiming.h` 的时序和攻击肢体掩码。原生扫掠只查询当前拍的实际手掌；双掌重拍仍只结算一次伤害。没有新增命中次数、逐帧 IK 或角色 Tick。
- 导入器只写原蓝图的 `flurry_clip`，不重写当前网格、撕咬、伤害／距离／CD 或触手设置。新动画目录 `/Game/Monsters/BoundCongregate/FlurryV22/`。

## 本轮指定检查

源动画以 240 Hz 采样，并把 V17/V22 两段动作加载到同一 V21 显示模型制作灰模对比。它用于观察肢体，不模拟或验收布料，也不是 UE 游戏录像。

- 两版动作首尾位置差均为 0；所有采样数值有限。
- 最大片段关节旋转变化：V17 为 12.0618°／采样，V22 为 6.5327°／采样。该量说明局部急转减小，不单独作为自然度通过依据。
- 六条后部支撑末端最大漂移：V17 约 0.02155 cm，V22 约 0.00326 cm；V22 骨段长度最大变化约 0.000095 cm（浮点采样误差范围）。
- 对比 GIF：`SourceAssets/BoundCongregateMeshy20261006/FlurryV22/Review/Flurry_V17_V22.gif`；关键帧图与 `source-review.json` 同目录。
- UE 已保存压缩动画按 240 Hz 取样：时长 2.150000095 s，与合同一致；全部数值有限。最大关节旋转变化 6.5313°／采样，骨段长度变化最大 0.000146 cm，六条支撑末端最大漂移约 0.5883 cm。源与压缩动画精度不同，未把源端的毫米以下漂移冒称为引擎结果。
