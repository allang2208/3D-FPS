# 缚群衣物、蒙皮与动画修复 V3

> 历史阶段记录。2026-10-08 用户否定整体衣物并暂停；V18、V19 均未获认可。当前状态、最新参数和已归档证据的取回位置以[暂停与发布记录](bound-congregate-paused-publication-20261008.md)为准。

本轮用户明确要求排查右腿衣物穿模、部分腿瞬移，以及全部肢体和主体的动画/骨骼。以下检查仅针对缚群。原 Meshy 主体几何、UV、贴图、56 骨骼命名和参考姿势保留。

## 已查明的问题

- 原右腿袖布的静止姿态有 74 个采样顶点进入皮肉；袖布整个绑定一根上肢骨，与周围多骨混合变形不一致。
- 原披布和左右袖布共用 `BC_RagFabric` 的同一个 cloth render/simulation section，不能保证邻近布片的传递独立。
- 原脚锁超过伸展/位移范围后，直接取消锁定并额外抬高 7 cm，下一支撑帧又可以重新锁定，产生不连续目标和反复锁定。
- UE 实际压缩后的旧 Idle 触手末端循环接缝位置相差约 37 cm，部分触手骨骼相差约 14.4°。旧三段 V2 移动源动画首尾闭合，没有发现位置断跳。
- 原蒙皮局部权重变化过急；源 Walk 抽样中存在较大的短边拉伸。
- 首次动画初始化曾出现一帧参考姿势；快速中断停止/转身混合时，快照已包含脚部 IK，后续求值会重复叠加修正。
- 逐块绑定衣物时触发的网格重建早于 section 用户数据同步，导致保存后的网格保留 cloth GUID、却缺少实际变形映射。
- FBX 顶点颜色经过 sRGB 编码，直接读取字节作为活动距离，将源文件约 1–2 cm 的范围放大为 7–10 cm；粗略肢体胶囊还会把邻近布片顶开。

## 源文件与代码修复

- 左右袖布从实际 L2/R4 肢体表面重建。四块衣物分别使用独立的 render/proxy 材质槽；同样的布料材质仍可以复用。
- 在焊接后的主体表面平滑原有解剖分区权重，保留最多 8 个影响，避免相邻但不相连的捐献肢体互相抢权重。主体仍为 153072 个分裂顶点、197398 三角面。
- 衣物转移对应皮肉的混合权重，对 76 个姿态调整间隙；夹在独立活动肢体间的小片段修成破损衣边。右衬布保留贴合的单层表面，以双面布料着色，避免厚度层在尖锐褶皱内侧穿入皮肉。袖布和左披布保留厚度。
- 新 Idle 按整数周期制作触手波动；Bite、Hit 和备用 Death 使用一致的父骨空间求解。Bite 伤害时点仍为 0.92 秒，死亡主路径仍为连续软体尸体。
- 原 V2 的 Walk/TurnLeft/TurnRight 步态保留，导出对应 V3 动画包，统一使用 50 cm/s 标定速度、1.6 秒周期。
- `BoundCongregateAnimInstance.cpp` 将脚锁改为每个支撑段只释放一次；移除 7 cm 硬抬高，渐退支撑末端锁定，并限制水平/垂直地面修正速度。
- 初始化直接设置 Idle；中断混合保留 IK 前的姿势快照，避免再次施加脚部修正。Idle 与移动循环也可以连续混合。
- 布料绑定统一延迟网格重建，保证四块映射与 section 用户数据一起保存。活动距离先解码到线性值；皮肉接触改为随蒙皮运动的逐顶点 backstop（半径 8 cm、内侧偏移 0.3 cm），不再使用会与无关布片重叠的肢体胶囊。命中检测的主体物理资产保持独立。

## 可复现制作路径

外部 Python 执行 `repair_skin_v3.py`，然后用 Blender 后台依次执行 `repair_model_v3.py`、`author_actions_v3.py`、`fit_cloth_motion_v3.py`。最后执行 `audit_rig_v3.py -- --after`。源文件在 `SourceAssets/BoundCongregateMeshy20261006/RigRepairV3/BoundCongregate_RigV3.blend`；动画和网格 FBX 在同一目录。

UE 的姿态检查必须将 `AnimPoseEvaluationOptions.incorporate_root_motion_into_pose` 设为 false，从而采用实际的 `force_root_lock + RefPose`。默认忽略 root lock 会漏掉此 Blender 骨架根骨上的厘米换算，错误地把骨骼尺寸读小 100 倍。
