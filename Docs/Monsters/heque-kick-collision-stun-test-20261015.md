# 合阙踢击撞障碍眩晕：联机测试

用户于 2026-10-15 明确要求测试主客机同步、2 秒眩晕与操作恢复。

## 场景与判定

- 两个独立进程：真实监听主机和客机，空测试地图、复制地板与障碍物。使用独立 `ColdSteel_HeQueKickAudit_*` 测试档案，不修改正式角色存档。
- 从保存的 `/Game/Monsters/HeQue/BP_HeQue` 生成怪物，通过正式 `StartAttack` 发起踢击，经过原始碰撞采样、伤害接收和击退代码。只将测试怪物的踢击伤害设为 5 以防连续用例致死，动作、命中范围、10 米击退与撞障碍眩晕保持正式设置。行为树暂停以确保每例只出这一脚。
- 用例：主机玩家撞墙、客机玩家撞墙、客机玩家在无障碍路径受踢。
- 两端记录目标眩晕状态及状态栏条目；拥有者额外记录输入锁时长、锁定期间输入尝试造成的位置/视角变化、结束后的输入启用状态及实际移动、转向、跳跃。
- 接触后服务器眩晕预期约 2 秒（采样容差 0.15 秒）；两端观察时长及相对服务器到期时间允许最多 0.25 秒采样/传输差。无障碍路径应击退 1000 cm、不产生眩晕或眩晕条目。

## 构建前置修正

首次 Editor 构建被并行开发的 `FPSWeaponFXComponent::MuzzleFlashVisualScale` 阻塞：条件表达式的 `TObjectPtr<UStaticMesh>` 无法推导为 `const auto*`，且组件直接访问了角色的 protected `MuzzleVariant`。仅改成显式静态网格指针，并为角色增加只读 `GetGunsmithMuzzle()` 供该处读取，不改变枪口特效数值或选择条件。保留初次失败日志 `build-FPSGAMEEditor-20261015-185117.log`。

## 首轮发现及修正

`sockets-20261015-190222` 的第一例真实踢击已命中并撞墙：权威眩晕状态持续 2.0052 秒，客机也收到状态及眩晕条目，但主机玩家 `lock=0`。定位为 `UCombatStatusFormula::AddStun` 只查找已有 `UPlayerGuardBreakComponent`，而新玩家不会默认带该组件；未曾受过破防的玩家因此缺失完整输入锁。

已在正式 `AddStun` 入口补齐服务器按需创建、注册复制输入锁组件的路径，随后调用既有 `Apply`，到期继续走原 `Release` 恢复输入。客户端不自行创建权威控制效果。

同轮 `resumed_yaw=0` 属于测试驱动时序问题：UE 在 Actor Tick 后清空 RotationInput，该时机加入的模拟视角输入没有被 PlayerTick 消费。驱动已移到 PlayerTick 前，不改游戏转向逻辑。两种原因分开记录，后续重新运行同三例。

## 最终复测结果

`sockets-20261015-190830/host.json`：`passed=true`。两台独立进程中的三个用例、六份端侧报告和三份服务器伤害/时长报告均通过。

| 客机玩家被真实踢击推至墙面 | 2.0163 s | 2.0024 s | 首次动态创建的输入锁成功复制到客机；主客机状态正确，结束后移动、转向、跳跃成功 |
| 客机玩家无障碍受踢 | 无 | 无 | 两端位移均为 1000.000 cm；没有眩晕、输入锁或眩晕条目，后续操作正常 |

两次撞墙的拥有者在稳定锁定期间持续尝试移动和转向，记录均为 `blocked_cm=0.000`、`blocked_yaw=0.000`；恢复后分别实际移动 1152.196 cm、1175.226 cm，转向及跳跃均成功。两端对眩晕状态到期的观测相对服务器 2 秒截止点最大偏差为 0.0329 秒（本机回环网络，60 FPS 目标）。

最终构建：Editor `build-FPSGAMEEditor-20261015-190700.log`、Game `build-FPSGAME-20261015-190732.log`，均成功。此次正式玩法修正仅为 `CombatStatusFormula.cpp` 中首次玩家眩晕的输入锁组件创建；未改合阙动画、碰撞范围、眩晕时长或击退距离。
