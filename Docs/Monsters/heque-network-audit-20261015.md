# 合阙最终首领与联机检查

2026-10-15，按用户“看看是否都做完了有什么遗漏或者 bug，特别是联机部分”执行。范围包括最终房间流程，以及合阙招式、控制状态和弱点的联机入口。

## 本轮发现及修改

1. **踢击位移未接入客机移动预测/纠偏。** 原实现只在服务器的临时 `UFleshHandPushComponent` 中逐帧 `SafeMoveUpdatedComponent`。改用玩家原生 CharacterMovement 的根运动源，保留 0.16 秒先快后慢的 10 米位移；服务器下发给拥有者，其他玩家读取复制位移，原生网络移动处理重放和纠偏。第一个不可行走障碍消耗剩余推力，禁止贴墙滑动、自动跨障和残余水平漂移。此次仅切换合阙踢击入口。
2. **返程完成状态晚于最后一次队伍保存。** 旧代码先保存所有队员，再 ServerTravel，最后才标记完成，客机主机磁盘副本可能缺少完成标记。改为同一转换栈中暂存完成状态、确认每位队员档案 RunId/完成值、持久化全队后提交换图；保存失败或请求被拒绝时回退完成状态并保存。正式换图前重新确认入口仍有效，最终传送门仍在交互范围且满足权限。单人返程也拒绝在完成状态写入失败时继续换图。
3. **远端心脏弱点信任自报骨骼名。** 客机命中报告原先直接使用 `BoneName`。现在由服务器在合阙实际骨骼碰撞上重查接触，心脏必须命中 `HQ_CoreSwing` 的真实网格组件；无法复核的报告保留既有普通伤害判断，不发放弱点暴击。这里使用服务器当前姿态，未实现历史姿态回溯，高延迟下的弱点手感仍是实机检查边界。
4. **合阙缺少自身状态复制组件。** 原先已有血量、五类招式和反应状态的复制，但未挂同类怪物使用的 `UFPSStatusReplicationComponent`。已补齐，使玩家施加给合阙的减速、冻结等战斗状态进入既有网络通路。

- `TaskTrackingContract`：使用正式共享进度结构和反射序列化，覆盖最终击杀/搜刮分阶段推进、重复/旧包、迟加入、新 RunId，以及返程取消的完成回退。
- `HeQueAudit`：加载真实已保存的合阙蓝图、动画、特效、心脏碰撞和软体绑定；临时物理世界测试 30/60/120 Hz 下 10 米位移、斜向撞墙停止、停止后不漂移，以及真实心脏/普通部位命中复核。不加载正式地图或玩家存档。
- `HeQueNetAudit`：空地图中的真实监听主机和两个独立客机进程，第二位客机在搜刮阶段后加入。使用独立 `ColdSteel_HeQueAudit_*` 存档，复制正式共享进度结构，检查新一局重置、合阙状态复制和正式玩家移动组件的击退。它不等同于实际随机地牢完整通关，不覆盖真实搜刮 RPC 和队伍返程的端到端操作。
- 构建与运行记录：`SourceAssets/HeQueBoss20261014/NetworkAuditV01/Records/`。结果以本轮最终记录为准。
