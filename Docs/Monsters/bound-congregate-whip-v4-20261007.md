## 证据与根因

- 蓝图实际引用为 `TentacleV3/SK_BoundCongregate_TentacleV3`，0.90 / 0.24 秒配置已存在。不能归咎于用户没有加载新版。
- 从 UE 导出 V3 再读回：根部 1726 个匹配顶点没有显著权重差异；骨骼参考位置误差低于 0.001 cm。
- V3 源网格静止参考姿态连续；同一模型播放原待机时，根部出现与用户截图相同的黑色横缝。只焊接边界并把单圈顶点固定到 body 没有解决周边权重突变，附近三角形在动作中折叠。
- V4 保留连续原表面，对整个肩部支撑区域重画渐变权重；固定带外侧逐步回到原权重，不再硬切一圈顶点。源文件的待机和移动近景中，原位置的横缝消失。
- V3 的释放仍以目标点和 Bezier 曲线驱动全部骨段，无法表达根部发力后波形向末梢传递的时间差。

## GitHub 参考与制作方式

- 参考：[MosesAndLily/whip-project-targeting](https://github.com/MosesAndLily/whip-project-targeting)，commit `8025f9f156bf3cf591afbedca18eaa03e3846d4a`。
- 原项目作者 Moses C. Nah / MIT NEWMAN LAB，BSD-3-Clause；仓库有二维、三维甩鞭演示与论文链接。参考源码和完整许可保留于本版 `Reference/` 目录，不把它描述为现成 UE 怪物动画包。
- 借鉴其近端最小加加速度运动和关节阻抗控制方法。为本怪物独立制作 MuJoCo 关节链，按原触手骨段长度和粗细设置质量、刚度、阻尼。
- 准备姿态由怪物主动收向身后；释放期间只驱动近端关节，细端由动力学带出，没有目标点吸引力或尖端位置控制。
- 离线烘焙后生成 `BoundCongregateWhipMotion.inl`；运行时采样，按目标调整攻击平面，保持原骨段长度。无需在游戏里安装或运行 MuJoCo。
- 近端固定到第 7 根骨骼以前，避免用粗根部充当折弯铰链。蓄力 1.10 秒，完整甩出波形 0.62 秒；原缠绕、伤害、拖拽与碰撞扫掠保留。
- 后续近景排查又发现最初物理候选的发力段过短、释放中途下坠触地。最终制作参数改为 10 段近端发力、后撤弧线 120—200 度、较强关节阻尼，以及身体避让代理；只截取首次向前甩出的波形，不包含落地反弹。
- 对骨段方向作 1.15 段宽度的空间平滑，再按原长度积分，去除小尺度折弯。肩部用 6 段连续切线过渡，整个录制动作按目标调整方向，不在出手时用尖端 IK 拉扯网格。
- 蓄力使用保持弧长的连续展开：待机曲线向身后准备曲线过渡，把中间多出的长度放入上方宽弧，前 78% 时间完成后撤，剩余时间停留。修复旧准备方式逐关节旋转绕圈、触发限速后在出手首帧追赶的问题。
- 物理制作阶段的不可用候选包含不稳定积分、直接移动坐标架和过强根部反馈，均未进入游戏。最终数据由实际受力关节积分产生，不以移动 mocap 坐标架冒充惯性。
