# 螺柱 M-14：死亡飞起与全黑修复 V18

> 此为该阶段的制作记录。当前版本、归档位置与恢复依赖见 [整理发布](SpiralPillarM14Publication20261005.md)；不将中间方案视为当前安装入口。

2026-10-05。用户反馈 V17 死亡后整个模型飞起并全黑。本次针对这两个缺陷修复，不把 V17 的编译与资产保存当成效果认可。

## 定位证据

从当时运行的编辑器导出实际 `DA_M14_XPBDCorpse_v17`，记录在 `ProductionV18/Records/data.t3d`。523 个软组织节点和 8 个金属区域的 `RenderBone` 全部为 49，应分别指向不同骨骼。

制作代码在 `FReferenceSkeletonModifier` 添加骨骼期间使用 `GetNum()` 取新骨骼编号。引擎此时只扩充 Raw 骨骼数组，Final 数组要等 Modifier 析构才重建，所以每次返回的编号都相同。原表面因此全部绑定在第 49 根骨骼；运行时该骨骼又被所有节点依次覆盖，最终由最后一个金属区域的位置与旋转控制整个尸体。这解释了整体突然移位、旋转和飞起，不能靠降低重力或限制根节点高度修复。

尸体材质还使用了世界空间法线和额外的 `TwoSidedSign` 翻转。世界空间法线通路不会像切线空间法线一样自动执行背面修正；可见背面的法线反向会导致折叠组织受光错误。旧公式在几何或 UV 退化时也没有可靠的归一化退路。

## 修改

- `M14SoftBodyAuthoring.cpp` 改为添加期间读取 `GetRawBoneNum()`，得到每个新骨骼的实际唯一编号。
- 从未改动的活体 V15 网格重新生成 V18 尸体、独立骨架和代理数据，重新写入所有表面蒙皮权重；不能只改旧 DataAsset 的编号，因为旧表面蒙皮同样写错。
- 四份 V18 尸体材质保留原贴图、颜色、粗糙度和金属度。用相机相对位置计算表面导数，将几何法线朝向当前可见面，去除额外的背面翻转，并处理退化几何/UV 的法线归一化。
- 正式蓝图 `SoftBodyDeathData` 切换至 V18。旧 V17 资产保留为问题追溯资料。

活体动作、攻击和 V16 绿色毒液沿用现有内容；软体求解器参数未作猜测性调整。
