# 未知攻击客户端与加入／重连检查（2026-11-16）

本次接续 `unknown-network-review-20261116.md`，范围是实际 `AFPSGAMECharacter` 受击及新连接恢复未知的状态。只在隔离后台宿主中运行；不启动交互编辑器，不改玩家或怪物的伤害配置。

## 已修复的源码问题

- 受击减伤、月影庇护和续命判定仍存在影子档案为空时回退主机 GI 档案的路径。统一按受击 Pawn 通过 `ColdSteelAuthority::ForPawn` 取档案；闪避奖励同样按 Pawn 归属。远端玩家的档案尚未接入时，暂不接受角色伤害，避免按临时默认血量／防御结算后再被档案覆盖。
- `AFPSGAMECharacter::TakeDamage` 原来直接返回引擎分发的伤害，即使生命组件因月影庇护拒绝了这次伤害，法术也会收到正数。现在通过栈内回执返回实际接受的伤害；嵌套 `TakeDamage` 各自保有回执。冰锥、暴风雪、闪电、陨石／龙息等后续命中状态沿用既有成功条件。
- 客户端角色直接执行 `TakeDamage` 会进入减伤／格挡／闪避相关逻辑，虽然生命组件最终拒绝扣血。现在非权威角色在入口返回零。
- 生命组件 `BeginPlay` 无条件执行 `Health=MaxHealth`，可能覆盖晚打开 Actor 通道时已收到的伤残血量。仅权威端初始化血量，客户端保留初始复制值。
- 冰墙阶段年龄只记录切换时的值，晚加入会从零计时，并无条件重播落地特效／镜头震动。增加服务器阶段时间戳，客户端据当前服务器时钟恢复年龄；超过 0.75 秒的历史落地／碎裂事件不重播一次性表现。
- 首轮真实 UDP 连接复现冰墙打开复制通道即闪退：`GetLifetimeReplicatedProps` 注册了未标记为复制的 `Health/MaxHealth`。移除两项重复注册，沿用 `NetHealth` 与 `NetTuning.MaxHealth` 的既有同步路径。
- 重连检查复现了影子档案采样间隙丢失最后血量：Pawn 已经销毁时，断线保存只能拿到上次采样值。现在每次接受伤害及原地续命完成后，立即同步该 Pawn 的权威档案内存状态；不等下一次 PlayerState Tick，也不逐次伤害写盘。场景故意暂停 PlayerState 采样以稳定覆盖这个窗口。
