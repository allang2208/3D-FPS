# M-14 与通用软体死亡整理发布（2026-10-05）

## 当前交付

本机正式活体为 M-14 V15 连续支撑蒙皮，V19 连续 XPBD 尸体，V16 绿色毒液，V20 旋风判定范围。已有快速伸嘴撕咬、预判喷吐、躯干重砸及短蓄力六转旋风；喷吐最远 30 米，命中叠一层中毒；旋风 CD 12 秒，范围在 V12 基础上增加 30%。嘴部 `maw` 及后代通过统一弱点入口结算。

非人形推广的本机资产保存和原生构建已完成，范围见 [连续软体死亡标准](continuous-soft-corpse-standard-20261005.md)。本次仅执行用户要求的归档、技能沉淀与发布检查，没有运行游戏、追加构建或视觉验收。新拆出的 V18 材质恢复脚本未执行；原材质资产保持现状。

## 公开边界

公开原创 C++、作者配方、六份毒液 HLSL、设计/制作记录及 SKILL。PositionBasedDynamics 的 XPBD 内核参考源随 MIT LICENSE 和来源散列公开，见 `Source/ThirdParty/PositionBasedDynamics`。

用户 Meshy GLB 的生成套餐及公开再分发权未核准。GLB、PBR、Blend/FBX、概念图、UE 资产、密集表面/权重、模拟数据、回执、日志和 trash 均只保存在本机；本仓库不是完整资产备份。

共享代码只发布 M-14 与本轮通用死亡接入。推送期间远端新增 M25 提交 `20a763c3`，本轮在其基础上整合公共接口，并将 M25 的 `OnRep_Death` 软体挂接直接加入正式源码；M25 原交接说明同步注明已接入。本轮不会重新发布其独立实现。M08 尚属另一对话未发布的实现，通过 Wolf 基类继承通用入口，完整 11 角色作者目标表仍需恢复该本机物种。

## 恢复次序

1. 准备合法的原 Meshy GLB 与 PBR，匹配上述本机来源散列；恢复项目已有怪物公共依赖。制作脚本使用 `D:/FPS3D/FPSGAME`，换机器时先调整根路径。Python 外部制作依赖 NumPy / SciPy，绑定和动画作者步骤需 Blender Python。
2. M-14 原始整理与逐版作者链为 V01→V02→V03→V05→V06→V07→V08→V11→V12→V13→V14→V15。`read_hardware_source_v11.py` / `resolve_hardware_v11.py`、V13 / V15 的诊断与求解脚本是后续蒙皮输入生产步骤，不是废弃测试。历史安装脚本只在恢复对应中间源时使用，不应覆盖当前最终设置。
3. 从 V11/V13 原绑定生成 V17 笼体，再运行 `author_continuous_corpse_v19.py` 生成 V19 连续绑定。需要重建材质时运行独立 V18 材质恢复入口；最终安装用 `import_death_and_range_v20.py`（V19 尸体与 V20 旋风范围）。毒液先 V09 / V10，再 V16 绿色设置。活体应最终保持 V15 支撑蒙皮。
4. 通用推广在对应原生类型完成构建后，运行 `Tools/MonsterSoftCorpse/build_assets.py` 或其三步入口，保存 `/Game/Monsters/SoftCorpseV1` 与活体网格元数据。缺少 M08 时先恢复对应独立模块；不要把缺失目标静默算作成功。
5. UE 未打开时使用适用的 commandlet 后台制作；已打开时沿用桥的批次互斥，不另起会话写相同资产。制作完成默认交由用户测试。

技能经验同步保存在个人和工程 `ue5-monster-workflow/references/continuous-soft-corpse.md`。重点是新增骨骼的原始索引、连续附件绑定、死亡交接、约束累加器和变形法线，而非固定照抄 M-14 的几何与尺寸。

发布时因共享暂存区存在另一批 M25 内容，使用 `trash/m14-publication-worktree-20261005` 临时隔离本轮提交，不修改原暂存区；推送完成后归档发布快照并解除临时 worktree 注册。
