## 制作入口和回退

- `Tools/MonsterAI/author_meshy_remesh_v3.py`：Blender 后台逐只制作。每只 `authoring.json` 记录作者源、输入散列、恢复内容、材质及导出的实际面数。
- `Tools/MonsterAI/Invoke-MeshyRemeshV3.ps1 -Species <ID> -Stage import`：短批次导入现成 FBX、贴图、材质并保存活体；输出 UE 坐标的 `surface.bin`。已有编辑器走 MCP 批次互斥，否则使用后台 commandlet，不主动启动 GUI。
- `Tools/MonsterAI/embed_meshy_remesh_v3.py <ID>`：离线复用当前软体代理，生成新 `embedding.bin`。
- 同一 PowerShell 入口 `-Stage corpse`：保存新尸体与 DataAsset、接回活体死亡绑定。
- UE 新纹理、材质和尸体位于 `/Game/Monsters/RemeshV3/<ID>/`；活体路径保持原样。
- 改动前的活体、必要蓝图包位于各物种 `Before/`。只在相应包未加载、无未保存编辑的窗口恢复指定包，不回退整个项目。

这次资产接入不依赖此前中止方案的原生尸体多 LOD 改动，也不需要为资产导入重编 C++。此前构建受独立 UI 编译错误阻挡的记录保留于旧文档，不把它描述为通过。
