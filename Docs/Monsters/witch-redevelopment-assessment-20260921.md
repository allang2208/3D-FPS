# 巫婆重新开发：资产评估、问题归因与调整计划

日期：2026-09-21。范围：用户要求的只读排查、现有资产适用性评估、GitHub 方案调研与计划。没有修改角色代码、SKILL、模型、动画、UE 包或游戏设置；没有启动 UE/PIE、生成新模型或制作验收渲染。新增的只有本报告和 `Saved/WitchReassessment20260921` 内的读取脚本、统计及日志。

## 结论

**现有普通巫婆 V06/V07 不满足正式人形持械怪物的开发标准。现有资产足以开展重建，不必先重新生成整只巫婆。**

推荐保留完整 Quinn 动作基础、原巫婆造型与 PBR、高密度表面和道具；以完整人体骨架和正确手脚蒙皮为基础，重新适配外观、制作真正独立的袍服与模拟代理。不要继续把旧裙脚连接、原 24 骨权重与逐帧接地补丁作为新母版。

用户对 Quinn 待机/慢走的肯定，是有价值的可用基础，但当前两版在模型、骨架、动画、移速、动画驱动上都不同，**不能据此证明全部问题只来自网格**。下面区分本轮直接读取的事实、旧记录和需要以后动态对照的推断。

## 2. 主要问题及证据

### P1：长袍与脚的结构关系错误，骨骼动作和裙摆互相牵制

当前 V06 的可见部分是帽、头发/头、左右手、上袍、下袍、原脚七件；不存在一套独立完整的盆骨、大腿、小腿实体网格。腿部骨链存在，但袍服下面没有与之对应的完整人体基础。

直接读取 V06 源及最终 FBX：

- 下袍 50,202 顶点、30,502 三角面，其中 **26,517 个顶点（52.8%）的主导权重为脚或脚趾**，余下主要归骨盆。
- 原脚只有 870 顶点、805 三角面。脚和袍的切口共享 98 个原始顶点，腰口与上袍共享 216 个。
- `clean_robe_v06.py:37` 的 `repair_seams()` 将下袍按高度混合到最近脚部权重；`WitchMonster.cpp:518` 把 26 cm 以下代理区固定，腰部 82 cm 以上固定，中段最大位移 6 cm。

这些设置可限制旧切口开裂，但把本应独立垂落的袍布与两脚运动绑定起来。它不是合理独立长袍的最终结构。由此推断，迈步/抬脚/脚部 IK 会同时拉扯大量裙面；各类画面异常中它占多大比例，仍需同动作隔离对照。

**处理：人体腿脚连续；服装形成自己的腰口、内侧、下摆和破边；裙摆与裸脚不共享一条必须同步变形的接缝。** 保留破袍外观，不沿用其错误连接关系。

### P1：右手存在确定的非解剖权重污染，持物驱动不一致

V06 源及最终 FBX 的 `Witch_Hand_Right`：

- 2,048 个顶点全部以 `RightForeArm` 为主导权重。
- 按所有顶点平均，前臂权重约 72.0%，右手约 22.1%；还包含右大腿约 3.69%、骨盆约 2.16%。局部顶点右大腿权重最高约 14.6%。
- 这不是“右手完全没有手骨权重”；实际问题是手腕控制较弱，并混入不应驱动手部的腿/骨盆权重。
- 运行代码 `WitchMonster.cpp:113` 把瓶子挂在 `RightHand` 上。因此瓶子和可见手掌不会天然获得相同的完整手骨变形，腕转、投瓶和腿动时存在握持偏离的明确结构风险。
- 原巫婆仅 24 骨，没有独立手指；左手 V02 是固定卷握外形。不能交付自然抓杖、握瓶、松手和恢复握型的完整手指动作。

**处理：保留手部外观参考，重新制作/适配可变形手掌与手指，绑定完整人体的手骨；按指节控制两套握型和投瓶释放。** 不是继续只调道具 Socket 偏移。

### P1：现有两套动作系统不能当作同条件对照

代码当前引用：

| 普通巫婆 | 动作基础候选 |
| --- | --- |
| `/WitchMeshy/OriginalRobeV05` 内 V06 身体，24 骨源 | `/WitchFoundation`，完整 Quinn；本轮 Blender 源为 88 骨，含手指、扭转骨与 IK 目标 |
| V05 待机、走、死亡；V07 两段攻击 | 只有待机和慢走 |
| 行走片段约 3.2667 s，最大移动约 22.3955 cm/s | 源走路 1.5 s、300 cm/s；步幅 0.5，候选最大速度 82.5 cm/s，满速播放倍率 0.55 |
| 姿态快照与单片段显式采样；V07 支撑求解仅用于攻击及退出 | Idle/Walk 混合 → FK/IK 目标拷贝 → StrideWarping → FootPlacement → LegIK |

V05 制作脚本 `original_robe_v05.py:223` 按每帧脚部网格最低点修正 `Hips` 高度；V06 复制原动作键。V07 攻击已重新从较干净的云端源制作，不能说它仍完整沿用 V05 接地烘焙，但旧行走仍是旧路线。

`WitchSpellAnimInstance.cpp:148` 在攻击状态将两脚锁定权重同时设为 1，没有按左右脚支撑/摆动曲线选择落脚过渡。对从不同走路相位起手的情况，存在过早锁住摆动脚、强行收腿的风险；这是代码推断，本轮没有运行确认。

**处理：在同一完整身体上先完成慢走、停步、转向、举杖、投瓶，统一脚接触定义；随后只增加外观，保留同一动画和速度作对照。**

### P2：“七分件”尚不等于人体和多层衣服的语义拆分

`layered_v04.py` 以高度、位置及原自动蒙皮权重分配面片。V06 仍有头帽/上衣、手/袖口、裙/脚共享原始顶点的切界。原始造型的披肩、袖布、袍身和破布细节并未因此自动成为可独立运动的服装层。

原表面由大量分裂索引构成：不能直接把原始连通分量数量当成破碎实体数量。本轮进行了只在内存中的同位置顶点归并统计；下袍由 10,053 个索引分量归为约 10 个位置连通分量，主要一块含 49,297 个原始顶点。UV/法线分裂是主要因素，**不支持“裙子实际碎成一万块”的结论**。小分量也可能是破布造型，不能自动删除。

**处理：区分造型层与物理层。** 贴身上衣和固定披肩可主要蒙皮；独立下袍用低密度模拟代理；需要独立摆动的外层布片另列层级。人体覆盖面可在最终显示版本隐藏，但完整人体作者源、骨架与碰撞依据保留。

### P2：版本与行为耦合增加恢复和误覆盖风险

`OriginalRobeV05` 包名现在承载 V06 网格，动作来自两版；导入器先把代理导入同一个最终包提取布料，再用可见 FBX 重导入。`WitchMonster.cpp` 还依据资产路径与材质槽名选择制作分支。

这能维持旧引用，但不宜作为重建母版。新候选应采用单一清晰目录，单独记录身体、骨架、衣服、动作、单位和运行引用。编辑器布料制作与运行战斗职责分离，使用明确数据而不是历史包名判断版本。

### 已修复历史问题不能重复算作当前问题

- V04/V05 错误内部身体及误带双手，在本轮读取的 V06 源/最终 FBX 中均不存在。
- V06 最终 FBX 只有七件可见部件，不含模拟代理。作者源代理为隐藏对象，2,368 顶点、4,608 三角面，本轮基础测量没有零长度边或近零面积三角形；不能直接沿用 V05 代理退化的旧结论。
- 1.9 cm/190 cm 导入错误已有修复记录和显式单位设置。Blender 中骨架对象 0.01 的转换层本身不证明 UE 再次缩小；本轮读取源表面高度约 1.9 m。没有实时读取 UE 包内容，不能宣布运行状态重新验证通过。
- PBR 输入存在，基础色为已打包的 4K 图；法线、粗糙度等独立输入也在本机。单独导入 FBX 的贴图路径缺失，不等于工程原 PBR 丢失；UE 导入器另外指定现有材质。

## 3. 资产是否满足标准

| 资产 | 当前结论 | 后续用途 |
| --- | --- | --- |
| 原巫婆整套 24 骨成品、V06/V07 | **不能作为正式母版直接继续** | 保留问题对照与制作参考 |
| Quinn 完整身体、待机/慢走、现有 IK 链 | **可作为动作基础**；用户认可仅覆盖已看过部分 | 保留完整骨架和关节拓扑，不再切腿拼脚 |
| 原头脸、帽、头发 | **可条件复用造型** | 适配同一身体，重整颈部/帽边的连接和权重；不宣称可直接无修改装配 |
| 原上袍、下袍、破边及 PBR | **可保留外观母版；当前绑定不可照用** | 按服装结构局部重拓扑/独立建衣，必要时投射原细节和贴图 |
| 原左右手与裸脚 | **不满足最终动作要求** | 作为老年枯瘦外观参考，重新蒙皮或重建可变形部位；与完整肢体连续 |
| 法杖与毒瓶 | **可继续用作道具基础** | 重做手部接触与挂点；瓶的玻璃/液体分材质仍待完成 |
| V06 布料代理 | **可留尺寸/排查参考，绑定不可直接迁用** | 新身体和独立长袍确定后重新制作碰撞和约束 |
| 现有 Meshy 五段源动作 | **保留并逐段选用** | 两段攻击保留动作意图和时序；无手指部分需补作，不在失败成品上再叠烘焙 |
| 专用受击、候选攻击/死亡 | **尚未完整具备** | 列为明确制作项，不能由待机/走路认可替代 |

本轮不建议重新付费生成整个人物。真正缺口是适配完成的连续人体手脚、独立衣物结构、正确权重和完整动作集。如果原袍重拓扑后无法保留所需轮廓/破边，再只补做服装；如果完整人体无法满足老年女性比例和裸露皮肤外观，再引入合法人体基础，不推倒头帽、道具和 PBR。

**推荐组合：现有完整人体/骨架 + UE 原生动作处理 + 离线服装拟合与权重转移 + Chaos 次级布料。** 这些工具各负一项职责，不把自动拟合、自动绑骨和物理模拟串成无判断的一键流程。

UE 侧的具体选择：

1. **脚步**：继续 Foundation 已存在的 StrideWarping、FootPlacement、LegIK。脚掌速度/接触曲线决定支撑与释放，实际移动速度驱动播放；重定向时可用 Speed Planting。官方说明见 [脚滑修正](https://dev.epicgames.com/documentation/en-us/unreal-engine/fix-foot-sliding-with-ik-retargeter-in-unreal-engine) 和 [Pose Warping](https://dev.epicgames.com/documentation/unreal-engine/pose-warping-in-unreal-engine)。[FootPlacement API](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/AnimationWarpingRuntime/FAnimNode_FootPlacement) 仍标 Experimental：已有用户认可片段可保留，不能因此推断所有攻击/地形状态均成熟。
2. **衣服叠加**：显示网格与模拟网格分开，先决定真实层级和初始间距，再设自碰撞与人体碰撞。5.8 的 [SimulationSelfCollisionConfig](https://dev.epicgames.com/documentation/unreal-engine/node-reference/Dataflow/SimulationSelfCollisionConfig) 提供 `SelfCollisionLayers` 面层级；这针对对应 Cloth Asset/Dataflow 模拟数据，不等于任意两个独立组件会自动互撞，也不能通过旧版 `bUseSelfCollisions=true` 获得完整叠层行为。该文还注明旧 Kinematic Collider 已由 SkinnedTriangleMesh Physics Asset bodies 取代，后续按本机版本选择。
3. **实现路线**：第一版只给确需运动的下袍安排独立模拟，固定衣层用蒙皮；需要多个真实活动层时，再集中设计共享模拟/层关系。可参考 [Panel Cloth Editor](https://dev.epicgames.com/documentation/unreal-engine/panel-cloth-editor-overview)，不以换编辑器自动修复几何为前提。
4. **模块装配**：静态跟随部件可共享骨架；需要独立骨动画/物理的部件不能一律套 Leader Pose。根据 [Modular Characters](https://dev.epicgames.com/documentation/en-us/unreal-engine/working-with-modular-characters-in-unreal-engine) 选择 Copy Pose 或 Cloth Component，并保证复制姿态前主身体已更新。分件用于制作隔离，不强制永远拆成七个运行组件。

## 5. 调整计划与交付顺序

每阶段交付可编辑源、明确导出和 UE 引用清单，说明尚未测试。以下“用户判断点”供用户试玩；本计划不自动启动 PIE、回归、截图或验收渲染。

### 第一步：固定新的身体与骨架基础

- 保留现有两个 F6 入口与原包作为对照；另立清晰的新候选源/资产目录，不再向 V05 路径反复覆盖不同结构。
- 保留完整 Foundation 人体与骨架。冻结身体比例、绑定姿态、坐标轴、单位、脚掌支点和左右持物约定；老年佝偻通过整体体型和脊柱分布制作，不靠全局压缩身体。
- 梳理可见手脚的最终来源，制作与手臂/小腿连续的皮肤部分及手指权重。头脸帽子使用原造型适配；身体被衣服覆盖部分可最终隐藏，作者母版不裁掉。
- 若 Quinn 的可见机械外观无法合理改成老年人体，明确使用它作骨架/运动供体，补做连续人体网格；MPFB 是后备选项，不能把机器人换色称为最终皮肤。

交付：完整身体与骨架、人体/外观部件来源表、左右抓握姿态。用户判断点：裸露手脚与比例、原有慢走是否保留。

### 第二步：先补全无复杂衣物的动作范围

- 在同一身体上完成待机、慢走、起停、转身、举杖和投瓶，再补受击与后倒死亡。先解决攻击所需站距、重心、肘腕、指节与道具轨迹，给服装留下真实运动空间。
- 局部上身持物层只在明确脊柱切分后叠加；举杖/投瓶涉及身体重心时使用完整动作，不把两脚无条件锁死。
- 行走支撑脚、摆动脚、抬跟和脚趾滚动分别处理；移动、起停与攻击共用接触曲线语义。停步过渡在正式攻击时钟开始前完成，不漂移已开始攻击的释放时间。
- 保留施法发射 **0.535714 s**、投瓶脱手 **0.75 s**、两段 **1.5 s** 的合同；动画过渡、手指与视觉音效不另建伤害计时。

交付：同一骨架完整动作集、原始源与修正层、接触/释放时序。用户判断点：动作基础能够同时覆盖移动与两段攻击。

### 第三步：重新适配服装外观

- 从原高密度外观保存帽、脸、披肩、袖布、袍身、破边；按实际服装结构整理独立衣片，而不是继续按高度切分。
- 先制作独立袍身和合理内侧、腰口与下摆；必要时局部重拓扑，烘焙/投射原褶皱、磨损与 PBR。宽袍保留运动余量，不贴腿收成裤形。
- 权重从正确人体传递，按衣片语义限制骨链，消除手部受腿/骨盆驱动、裙摆被脚趾大面积拉动等问题；用正确袖口/下摆边界维持连续观感。
- 第一次外观交付采用明确的蒙皮基线。几何本身运动不合理时返回拟合/权重环节，不用加大布料位移掩盖。

交付：保留原身份的独立服装、正确手脚与衣物连接、可追溯材质。用户判断点：同一动作、同一速度下，增加外观后动作质量仍保持。

### 第四步：只为需要的衣片加入物理

- 制作简单、连续的低密度模拟代理；显示的破边和细褶皱跟随代理，不拿全部高密度表面直接求解。
- 腰肩等真实连接区域固定；下摆独立悬垂，不再为维持脚部切口把整圈裙脚固定在脚骨上。
- 人体碰撞、衣层间距、法线与层级先一致，再调阻尼、弯曲和有限位移。明确是否需要两个活动层，避免为视觉多层而无差别开启多层模拟。
- 保留无模拟/简化模拟的距离档。LOD 与同屏数量预算按项目需求记录，不能把源三角面数直接视为性能通过或失败。

交付：独立代理、约束图、碰撞体与显示绑定。用户判断点：慢走、施法、投瓶、后倒时不再出现布料拖脚或明显穿插。

- 玻璃/液体分材质和专用受击随角色补齐；伴生锅、毒区减速、预警与缺失音效单列原功能迁移清单，不与本轮人体/衣服修复混报完成。
- 用户最终确认后再切正式引用和整理废案。此前保留问题对照及合法原始输入，不先删除历史制作依赖。
