# 金属铠甲护手制作计划

2026-09-27 实施记录：完整双手钢甲、钢材图集、22 套原生绑定网格、图标及掉落模型已保存，并注册独立装备 `ue_steel_gauntlets`。详见 [钢甲护手交付](steel-gauntlets-20260927.md)。此前的 [右手结构样件](metal-gauntlet-right-sample-20260927.md) 保留为制作阶段记录。未进行运行测试。

方案制定于 2026-09-27；实施进度以上方记录为准。以下保留整款装备的制作范围与分阶段安排。

## 推荐款式与目标

第一款采用写实分节钢甲护手：完整皮革内手套、手背钢甲、独立指根护甲、分节指背甲和短护腕。掌心、指腹、指缝与虎口保留柔性皮革，给枪柄、剑柄、工具柄和扳机护圈留出空间。内衬使用用户认可的 TailoredFingerlessV1 皮革制作方法，沿用刚完成的 OriginalLeatherV2 全指烘焙路线。

主要难点是关节运动、甲片之间的搭接、握持空间和袖口关系。金属形状必须通过实体厚度、曲率、倒角、分件和绑定成立，随后用 PBR 表现钢材。

当前宿主基线：V7 裸手；`ue_original_gloves` 使用 OriginalLeatherV2；22 个原生装备骨架配置（含 Body 和 Bow）。新物品独立注册，不覆盖战术手套或露指手套。

## 工具与管线

主线：结构参考与分件图 → Blender 精确建模 → 高低模与 UV → 皮革/钢材 PBR 烘焙 → 原生骨架派生 → UE Skeletal Mesh 保存 → 装备及图标接入。

Blender 负责可参数化的甲片轮廓、曲面、厚度、倒角、铆钉及绑定。关键作者参数记录到脚本和部件清单，保留可编辑 Blend。以已有手型和骨节位置为尺寸输入；概念图可以辅助定造型，最终分件和安装空间由精确建模决定。此次不以图生 3D 作为游戏网格主线。

默认后台建模、烘焙、导出与 commandlet 导入。已有编辑器中的必要保存通过项目 MCP 批次锁；不为制作或交付主动启动编辑器。Vibe3D 可用于已有 UE 会话里的局部建模修整，不是本款的必需依赖。

## 分件与活动设计

| 部件 | 几何处理 | 绑定与活动 |
| --- | --- | --- |
| 皮革内手套 | 沿用 V7 掌指轮廓，指腹保持薄，腕口有完整收边 | 按对应侧、对应手指转移软蒙皮权重 |
| 手背甲 | 拱面主甲，真实薄壁与卷边，指根处留退让区 | 主甲刚性绑定 `hand_l/r` |
| 四指指根甲 | 按每根手指分别做短甲片，避免一条连板锁住分指 | 各自跟随相应近节指骨，搭接主甲 |
| 四指指背甲 | 每指按指骨分段，关节处用圆弧端部与重叠唇边 | 每块板的所有顶点 100% 归属一个对应指骨 |
| 拇指甲 | 独立斜向甲片，掌根与指背分件，开放虎口活动区 | 按实际拇指骨链逐段绑定，不套用四指的运动轴 |
| 腕部甲与短护腕 | 手侧和前臂侧分别建件，以搭接覆盖腕部 | 手侧跟手骨，前臂侧跟实际承载该区域的前臂骨；不做横跨腕关节的一整块硬板 |
| 铆钉与扣带 | 铆钉随所在甲片；扣带贴附内衬 | 铆钉继承甲片的刚性绑定，皮带使用受控柔性权重 |

刚性甲片不能直接复制皮肤的渐变权重。不同顶点受到不同骨骼影响，会把钢片拉伸、扭曲。近景关节通过分片、搭接和圆弧退让获得活动空间；软变形只留给皮革和连接带。

金属的主要体积放在手背和指背。壳厚可从约 1 mm 的建模参数起步，倒角与内衬间隙按当前手指尺度决定；这是起始设计值，不是已经适配成功的尺寸。指腹、虎口和指侧不能随着甲片厚度一起整体膨胀。

使用已有抓握、张手、屈腕的源姿态作为制作参考，确定活动范围与重叠方向。固定骨骼旋转本身不等于真实机械滑轨：若所选款式确实需要独立滑动甲片，再单独设计驱动；首版先选择原有骨节可以驱动的形制。

## 高低模与材质

高模保留甲片拱形、翻边、铆钉窝、浅锻打起伏和细微磨痕。游戏网格保留剪影、可见厚度、关节端面和主要铆钉；细划痕、浅凹痕及微小起伏进入法线和粗糙度。按实体部件整理硬边、UV 接缝与切线，固定最终低模三角化后烘焙。

钢材与皮革采用两个明确的材质区。金属选择中等粗糙度的钢色、局部磨亮和克制的使用痕迹；裸钢区域按导体材质制作，皮革按非金属制作。若增加氧化、涂层或污垢，单独用遮罩表达，不能把所有区域都设成金属。

钢甲使用独立 UV 图集和 BaseColor、Normal、打包粗糙度/金属度/AO；皮革沿用认可的制作方法。先以钢甲 2K 图集为预算，近景分辨率需求在后续制作时按实际 UV 利用率调整。第一人称和物品图标使用同一套生产材质输入。

作者场景中的每块甲片是独立命名对象；导出时合并为一个包含多个独立几何块的 Skeletal Mesh，保留每块的刚性权重。每个原生双手 profile 使用一个护手组件，预计两个材质槽。首版双手 LOD0 以约 3–4 万三角为起始预算，最终取决于内衬复用量和甲片结构；这是制作预算，未做性能测量。

LOD 逐级减少倒角段数、铆钉和不可见的小面，保留指节间隙、甲片搭接与内衬遮挡。第三人称使用对应 Body 绑定与适合其距离的 LOD；不把第一人称近景面数直接复制成所有距离的固定成本。

## 附加到现有手上的方式

沿用项目 `FPSModularOutfitComponent` 的装备部件与 `SetLeaderPoseComponent(Source)` 路线。动作先驱动当前武器的源骨架，护手网格读取同一套骨骼姿态；同一护手内，皮革按软权重变形，各甲片按单骨刚性权重移动。

第一版不引入独立甲片骨骼、物理约束或新的护手动画状态机。Leader Pose 从属网格不能依靠源骨架不存在的额外关节获得独立运动；这类需求需要另行扩展 Copy Pose/动画驱动路线，不能只加骨便宣称已接入。

每个原生 profile 保留自己的骨架层级、参考姿态、轴向与绑定矩阵。刚性甲片在母版中先记录所属骨骼的局部坐标，再转到目标骨骼的参考空间；方法为 `目标参考矩阵 × 母版参考矩阵的逆 × 顶点`，不是对不同武器统一复制 M4 的静态坐标。法线按对应的逆转置处理。皮革仍按实际原生手部蒙皮派生。

渲染组件无需为每块甲片各挂一个 Actor/socket。甲片分件是制作与绑定的分件；运行时以一个骨骼装备网格承载。装备部件继续使用现有显隐、异步加载及无独立 Tick 的合同。

当前组件仅在物品 `material` 非空时覆盖全部材质槽。新护手保持该字段为空，让模型自身的钢材与皮革槽生效；不需要为了两个材质先重构装备系统。

完整内手套配方沿用 `covers:[2]` 隐藏裸手基底对应手部区，金属片之间由皮革承接。短护腕与上衣的关系在版型阶段决定，保留独立穿衣，不恢复旧整套衣袖。若将来改变为露指或长臂甲，需要相应覆盖配方，不能沿用整区隐藏强行遮盖。

## 分阶段实施

1. **结构方案与单手样件**：以当前 V7 右手为基准确定手背甲、食指三节、拇指及短腕甲；用简单钢材与皮革材质制作可编辑样件。先落实分件、单骨绑定、接触空间，再投入完整表面细节。
2. **完成同款双手**：推广到五指，镜像外形后分别使用左右真实骨架绑定，补齐甲片背面、腕口、铆钉和内衬。手指长度、拇指朝向和材质接缝按本手保留。
3. **完成生产资产**：制作高低模、PBR 图集与 LOD，保存母版、分件清单、绑定规则和导出数据。
4. **原生派生与 UE 保存**：先保存代表性第一人称配置，再适配不同参考姿态、双持、弓和 Body。当前范围按配置中的 22 个系列处理，新增系列在实施时以实际配置为准。复用现有动作；有具体接触冲突时先处理甲片形状和位置，只有确有必要才单独规划局部动作修正。
5. **装备闭环**：新增独立物品 ID、手套槽配方、物品说明、专属图标及掉落模型，接入库存、仓库、穿脱、切枪、存档与打包目录。防御、重量及其他玩法数值在物品定义阶段确定，不从材质外观自动推导。

实施顺序采用先完成第 1 阶段右手样件，再完成双手及整套 22 个系列的接入；当前交付状态见文首记录。
