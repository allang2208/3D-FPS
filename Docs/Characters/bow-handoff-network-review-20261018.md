# 持弓左手动作复查

范围：持弓施法，以及上一轮持弓单手食物、水、汽水、药水和双手大羊排的进入、结束与中断。没有把此前其他武器、服装或食材制作纳入本轮验收。

当前状态：本轮修复、正式构建和限定范围的联机检查已完成。180 项隔离检查全部通过；真实本地 UDP 共 28 组（两轮各 14 组）全部通过，每端设置 60 ms 延迟和 5% 丢包，主机、首个客机与新客机均以 0 退出。完整回执为 `SourceAssets/BowHandoffReview20261018/delivery.json`。未进行渲染和视觉验收，也未覆盖完整库存经济事务的端到端检查。

## 已确认并修复的遗漏

双手大羊排正常结束会沿用 0.26 秒抬回装备，但 `Cancel -> Finish -> RestoreEquipment` 原先立即复原装备父节点。第三人称食物层仍需要约 0.1 秒淡出，弓却已重新显示并跟随尚未回位的手。

现在取消立即结束消耗品事务、隐藏食物并停止吞咽；保留当时收弓权重，等待 0.1 秒手臂恢复，再用原有曲线在 0.26 秒内抬弓。期间不能再次拉弓、进食或施法。换武器、死亡、翻越及再次优先级中断可以立即释放父节点。无新增库存扣除、效果提交或存档字段。

这段恢复由已有身体态的 `bBowTwoHandConsume/BowStowWeight/BowStowRate` 同步；消耗品已不再 Active 时仍能表达收弓。恢复阶段继续选择 Sparrow Carry。

继续追踪时发现，药瓶丢弃事件为网络传输保留 0.3 秒，但旧分支在消耗品已结束时仍无条件写入 `Action=Consume`，可能覆盖死亡、换武器、翻越或新的施法。现只在实际使用期间写入饮食动作；结束后的丢弃记录仅保留道具身份、序号、挂接与丢弃标记。只有相同装备且没有新动作的首个丢弃帧才保留旧左手接触。新增优先级动作断言覆盖这一点。

首轮隔离检查 62 项中有 18 项入口失败：夹具的基础 PlayerController 被先转换成 FPS 专用控制器，转换失败后又把空值送入通用输入门控，导致全部使用入口提前返回。调用已修正为向 `BlocksOngoingActions` 传递实际控制器；只有 HUD 访问仍使用专用类型。原移动、视角和鼠标菜单限制保留。首轮失败记录完整保留，不算通过。

初始化还报告 `Json Value of type 'String' used as a 'Object'`：`melee-gunsmith.json` 的赤霄 `effects` 条目被写成字符串，而解析器要求 `text/benefit` 对象。UE commandlet 即使 Main 返回 0，也会因初始化错误返回失败。本轮保留文字，改为中性说明对象（benefit=0），未改变武技数值。Saiga12K 检查函数在另一份源码加入前导致的两次链接失败，以及内存不足时主动停止的本轮编译，也保留在构建记录中；这些都不算检查通过。

| 消耗品结算 | 接触时客户端只请求物品实例；服务器检查请求序号、Pawn、存活、库存版本、物品状态后结算。表现包不提交库存。 |
