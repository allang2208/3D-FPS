# 第三人称持剑：楼梯穿头、手臂滞后与扭曲

用户反馈持剑上下楼梯时手部穿到头部，整臂滞后、扭曲。本轮修改世界身体动画节点，不修改第一人称剑动作、握距、伤害或移动。

## 代码定位

`CaptureMotion` 将源剑动作的位移差重定位到 `SwordReady(Crouch)`，这是以脚底为基准的组件空间目标。随后 `FControls` 的地形适配下移骨盆，上身跟随下移；俯仰也会改变胸部和肩膀，但 `ActionHands` 仍覆盖为原先的固定高度目标。上下台阶时因此出现身体与握点不在同一参考系的情况。

旧肘极固定为 `(±65,10,105-40*Crouch)*PoseScale`，也没有跟随楼梯造成的身体位移及俯仰。另一个问题是 `ActionVariant` 随源剑 Idle/Walk/Sprint 变化时，世界手腕再次混合 0.1 秒；源动作已拥有过渡，额外的过渡使手臂落后于武器源姿态。过渡起点又保留在旧组件空间，身体改变高度时会继续追逐旧位置。

本轮只读查看已有游戏会话；采集时角色装备为 `ue_rsh12`，没有切换装备或操控角色，不能把这份现场快照写成持剑楼梯复现。记录为 `SourceAssets/ThirdPersonSwordStairs20261005/before.json`，入口 `Tools/PlayerBody/read_sword_stair_state.py`。

## 修改

- 以站立中立胸部为基准，将待机握持锚点绑定到本帧已完成地形、下蹲和俯仰校正的胸部。源剑的挥动位移差和腕部朝向保持原值，避免再次旋转整条轨迹造成双重俯仰。
- 双手共同平移，继续使用原有握距与整组可达性求解，左手保持与右手实际落点耦合。
- 肘极改为当前肩部外侧、下方的胸部相对方向，不再追逐脚底坐标中的固定肘点。
- 活动中的握持过渡快照每帧随胸部坐标更新，避免楼梯高度变化使旧握点滞留。
- 原生双手剑的普通移动片段变化不再重启额外的手腕过渡；已经进行中的装备/攻击/恢复过渡继续完成。
- 站立中立胸部变换按动画骨骼缓存，换骨骼时重建；没有增加资源加载、场景遍历或网络字段。

## 追加：冲刺沿用普通持剑奔跑

用户指定第三人称冲刺不再同步第一人称的专用冲刺姿态，按普通持剑奔跑播放。`CaptureMotion` 在普通持剑移动期间改由现有世界武器组件独立取样 `Idle` / `Walk`，使用同一握持修正资源。进入、循环、退出战术冲刺都不会改变这个动作选择；移动时冲刺沿用普通 `Walk` 的 1.45 倍播放速度，身体继续使用已有方向奔跑动画。

双手、手指、剑身骨骼和插槽附件使用同一帧普通握持姿态，避免手腕已恢复而模块化剑身仍继承第一人称抬剑动作。Idle / Walk 之间复用现有 0.12 秒过渡，冲刺切换不重置普通移动时钟。攻击、格挡、检视等实际动作仍使用原动作取样。

本次为源码调整，无新增或待导入动画资产。常规 `FPSGAMEEditor Win64 Development` 后台构建成功（28/28，退出码 0），本次冲刺调整与上一轮楼梯手臂修正均已编入 `Binaries/Win64/UnrealEditor-FPSGAME.dll`。日志：`Saved/BuildEditor/build-20261005-221419.log`。未启动编辑器、游戏或进行动作测试，由用户自行体验。
