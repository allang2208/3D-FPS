# 双持手枪第三人称：按手独立过渡（2026-10-20）

用户要求继续开发双持第三人称，并沿用前面的手臂经验。本轮执行源码制作、必要编译与落盘，没有启动检查 commandlet、游戏、PIE、截图、渲染或联机测试。

## 范围与沿用来源

入口是 `PistolDualWieldComponent::LoadHand/Pose`、身体装备捕获、`CaptureMotion/ApplyMotion` 及 `FPSPlayerBodyAnimInstance` 的最终骨骼输出。

共用加载入口支持 M1911、G18、Pit Viper 2011、Dan Wesson 715、RSH-12，左右各自选枪，包含同枪双持与异枪混搭。五枪形成 25 个有序组合；这是本轮代码适用范围，不是已运行 25 组验收。

原生动作继续来自各枪双持资产：M1911／715 的 NaturalAimV3、SprintSmoothV5、RevolverReloadFlickV6，以及 G18／Pit Viper 专用双持目录；RSH 使用自身双持网格及 base 差量。近战转枪继续读取 base／fitted／long 对应 Profile 和原执行器时钟。单持双手包握、G18 单持托鼓与 RSH 单持前握把的支撑层不用于双持。

制作依据包括手臂技能的 `player-world-body.md`、`dual-pistol-quick-melee.md`、`drum-reference-and-dual-startup.md`，以及工程已有双持身体与消耗品交接记录。

## 本轮发现与修改

### 1. 一侧动作重置两侧过渡

原身体图用一个 `HandBlendAge`，并在任意 `ActionWristMask`、全局动作或动作变体变化时同时捕获左右手。因此左枪开始／结束换弹，或左手施法，会重启右手的过渡，即使右枪仍在执行自己的动作。

双持现在按手记录动作通道、装备实例、源进度／速率及回位入口。换弹、装备、近战、施法、推门、消耗品分别按实际占用手判断。只有发生交接的一侧更新自己的过渡。

### 2. 原生收势之后再次回正

双持源图已有独立入场／收势混合，原身体层又统一添加 100 ms 混合。新版保留原生动作入口；正常结束用该手上一帧进度、播放速率及本帧步长判断，直接交回当前持枪基线。提前中断或外部动作交还时，才从实际已显示的手臂姿态进行短回位。

新枪实例不继承旧枪的掌心框架。回位入口存于躯干空间，跟随当前躯干移动；最终手部历史在施法、消耗品及整臂修正之后记录。已有 `Out.Pose=Pose.GetPose()` 的最终写回规则继续保留。

### 3. 双持插值共用全局通道

原 `ApplyMotion` 仅比较 `Contacts.Channel`，左手换到施法或消耗品通道时，右枪也会重置插值。现按左右手派生独立通道，区分手枪相对腕位和外部动作的绝对腕位，保持另一侧动作连续。

### 4. 旧姿态先进入缓存、再被屏蔽

原逻辑先将手部样本写进混合缓存，再判断枪械实例／schema 是否匹配。即使当前帧屏蔽了该手，下一有效样本仍可能与旧值混合。

现先确定接受的手腕和手指掩码，再更新缓存。失配枪械的样本不进入该手历史，下一有效样本从自己的姿态开始；真正由施法、推门或消耗品接管的双持手，不因枪械暂时失配被错误屏蔽。

## 动作归属

| 状态 | 本轮处理 |
| --- | --- |
| 待机、走跑、蹲姿、转向 | 沿各肩部的独立枪腕基线及现有原生整臂适配 |
| 左／右独立射击 | 保留各手开火时间和枪械机械层 |
| 单侧、错峰或同时换弹 | 每手按自己的源进度交接，不重置另一手过渡 |
| 装备、正常结束、中断回位 | 按手处理，使用当前枪实例和躯干相对入口 |
| 快速近战与恢复转枪 | 两手各采自己的原生动作；枪和改造件仍沿所属手腕发布 |
| 左手施法／推门／单手进食 | 左手交接，右枪通道保持独立 |
| 双手消耗品、翻越、死亡 | 沿原占用优先级；翻越／死亡清除双持回位历史 |

没有改变弹药结算、射击输入、双持腰射规则、枪匠挂点或第一人称动画资产；本轮没有新增资产或网络字段。
