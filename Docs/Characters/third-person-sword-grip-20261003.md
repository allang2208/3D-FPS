# 第三人称持剑抓握

用户报告：第一人称握剑正常，第三人称手指松开。2026-10-03。

## 原因

当前 Jason 网格具有左右五指各三节指骨、掌骨及有蒙皮权重的关节辅助骨。不是缺少手指绑定。

`FPSPlayerBodyAnimInstance.cpp` 对 Melee 使用 Unarmed 的行走／待机序列；原来的 `FControls` 只通过两骨 IK 定位手腕。武器挂在右腕，左腕通过 `LeftGripFromRight` 跟随，五指局部姿态仍来自空手序列。因此手掌到达剑柄，手指没有收拢。

## 修改

- 保存独立的 Jason 原生抓握序列 `A_Jason_SwordGrip`，通过 `player_body.json` 的 `clips.Melee.Grip` 加载。
- 以当前第一人称 `A_RuneSword_Idle` 的实际压缩姿态作为抓握输入，沿现有 Manny→Jason 武器挂载坐标转换手指方向。保持 Jason 原生指长、掌骨位置、缩放和蒙皮。
- Jason 指长与 Manny 不同。作者脚本用原抓握中节作为弯曲平面，在固定原生骨长下解算近／中两节到原远节握点，避免只复制角度导致握点偏离。
- 包含 210 条手指／掌骨／辅助骨轨道；`*_half_*` 辅助骨分担一半关节弯曲，其他辅助骨保持原生局部绑定。
- 第三人称动画在手腕 IK 之后叠加手腕以下的局部抓握。持剑走跑、挥砍、突刺和格挡共用此层；翻越时双手释放，施法时左手释放，恢复阶段后段重新闭合。切换到非剑家族时取消该层。
- 复用现有 Family、Action、Motion 和左手握点状态，本机与远端使用同一动画图；没有新增手指 RPC，也不改变伤害、动作时钟或第一人称动画。
- 骨骼列表在动画 CacheBones 阶段建立；运行时不读文件、不遍历角色、不加载新资源。现有身体资源预加载器读取新的 clips 项。

## 重制入口

`SourceAssets/PlayerSwordGrip20261003/`：`capture.py` 读取当前源动作和绑定；`author.py` 生成原生局部轨道；`install.py` 保存独立 UE 资产；`publish.py` 只接入新 clips 项。

后续更换身体骨架、手型或剑柄截面时，应重新制作对应抓握。手腕对准不代表五指已适配；检查范围经用户授权后应包括本机／远端、运动中的接触以及施法／攀爬的松握切换。

本次只进行数据读取、制作、保存及必要编译。没有启动游戏、截图或进行实机／联机验收，画面效果由用户测试。
