# 手枪单持第三人称：左右主握修正（2026-10-20）

用户本轮明确要求排查左手／右手主握时的第三人称装备状态，重点为模型脱离、悬空、方向和位置。按手臂技能及 `player-world-body.md` 的约束，后台执行实际原生动画图及世界装备消费者；未打开编辑器界面或游戏画面。

## 修复前实际发现

- 左主握装备重建仍执行“左支撑手相对右手”的通用分支，右支撑手初始握点和指型没有正确建立。重建还没有清除上次的右支撑标记，切回右主握可残留旧标记。
- 左主握世界武器抓取固定 `base` Profile，漏掉 G18 弹鼓及 RSH 四种前握把实际选中的 `LoneGripFamily`。
- 左主握先单独固定左腕，再让右手追目标，没有保证整组握点同时可达。基础配置支撑误差约 3～5 cm；RSH 前握把最大 **23.099 cm**。
- 普通右主握的世界姿态仍借用通用双手待机腕向，蹲姿枪口相对期望前方偏斜，最差前向点积 **0.5071**（约 59.5°）。
- 普通右主握枪原先分别传递逆手腕与绝对机械骨，插值可能拆开接触框架；动作腕位也仍受第一人称视模位置影响。本地无插值的旧检查中，200 个枪根挂接样本本身没有脱离，不能据此宣称旧版已复现枪体悬空。

原始结果 `before.json`：840 项、74 项失败，分属支撑归属、支撑位置、蹲姿枪口及 Profile。退出时另有检查夹具的 WorldSubsystem 清理告警。

## 修改内容

1. 装备重建按真正的主握手建立另一侧支撑接触、指型和基础回退姿态；清除两侧旧握点和标记。
2. 左主握捕获实际选中的配件 Profile；将 Profile 路径及手腕空间版本纳入装备 schema，避免同型号换配件后继续使用旧布局。
3. 左右单持都使用该枪的原生掌心／枪柄朝向，以及肩部相对的持握和动作差量。右主握不再依赖蹲姿源动画的手腕朝向，动作不再读取视模绝对位置作为世界腕位。
4. 保持原生两手接触关系，平移整组握持到双方手臂可达范围，再求解主握和支撑。使用原生骨长，不拉长手臂，也不对枪体做负缩放。
5. 枪体机械骨和附件共用所属手腕的坐标框架。旧装备快照不匹配时，两手动作样本一起拒收，世界枪及支撑回到当前装备基础姿态。
6. 左主握虽使用 Unarmed 下身步态，仍保留装备手指；原有最终组件／局部骨骼写回修正继续保留。

改动为 C++ 世界身体表现和本轮检查入口；没有重写已接受的第一人称动画、枪网格或配件资产，也没有增加存档或网络字段。

## 后台结果与边界

最终 `after.json`：**1,700 项，0 失败；commandlet 退出码 0**。覆盖 240 个姿态样本：腰射、开镜、蹲姿、抬头转向开镜、低头转向蹲瞄、射击、装备、普通换弹三个阶段、空仓装填、回位。

- 每个样本检查实际输出的枪根／主握手关系、附件位置和朝向、正缩放及有限值。
- 120 个持握样本检查另一只手达到支撑握点，枪口朝向当前设定瞄准方向。
- 动作中移动第一人称视模组件，检查世界动作差量不随该位置变化。
- 每个装备组合注入不匹配旧 schema，检查两手样本拒收、基础握点和枪挂接回退。
- 另外记录全部 240 个样本的支撑位置误差；最大约 `1.3e-13 cm`，属于浮点精度范围。该数字表示腕部接触计算，不表示蒙皮指面自然度或完全无穿模。
- 枪口最小前向点积从旧组的 `0.5071` 改为新组约 `0.998`。

`after-initial.json` 的原 840 项已经无失败，但其进程在夹具退出时因未先结束组件生命周期而报错，不能作为干净退出回执。检查入口已沿用项目已有 commandlet 的 EndPlay／World 销毁顺序；最终 `after-commandlet.log` 正常退出。

这些是隔离的本机原生图和装备检查；没有执行真实网络传输、延迟／丢包测试、运行截图或蒙皮画面验收。实际手臂、手指、衣袖和换弹接触的视觉自然度仍交由用户确认。没有自动打开 UE 或 PIE。
