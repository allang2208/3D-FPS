## 1. 视觉基线与物理身份

### 可以沿用的部分

- 深灰色系、干净缎面、低频斑驳弱、无均匀铺满的划痕；依靠部件粗糙度、结构法线和窄边缘反射形成层次。
- 按钢件、表面处理件、涂层、聚合物、橡胶分别制作；同类配件与枪体匹配，同时保留各自 UV、刻字和接缝。
- 现有 WS1 的独立区域、细纹厘米尺度、凸边／凹腔／AO 遮罩及单层湿润处理继续作为制作方法。

### 必须明确的边界

1. **当前深色金属数值属于本项目的外观配方，不是裸钢、裸铝的通用实测值。** 在 metal/rough 模型中，纯金属的 BaseColor 参与有色反射；不能把 `.02–.037` 的深色配方推广为所有裸金属的反射率标准。沿用时按“项目深色处理金属近似”记录，不把外观名当作物理测量证明。
2. 表面是漆、粉末涂层、聚合物、橡胶时，完整覆盖区域为非金属；暴露的金属基底独立定义。发蓝、阳极等处理依照实际表面和选用模型记录，不能仅凭资产名自动给 Metallic=1。
3. 纯材质区域的 Metallic 以 0／1 为端点；抗锯齿、mip 过滤和有依据的混合覆盖可以出现中间值。禁止用整片无依据的 0.3–0.9 调节“金属感”，不禁止区域边界的正常过滤。
4. 暗色处理金属、裸露钢、镀铬／抛光件分成不同配方。新增真实裸金属配方另取可靠参考，不自动把现有暗色枪体整体提亮。
5. 不通过持续压黑 BaseColor、降低 Metallic 或强行提高 Roughness 来掩盖法线、几何或光照问题。场景变亮不应触发另一套随天气切换的底色补偿。

这些区分依据 Epic 的 [PBR 材质输入说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/physically-based-materials-in-unreal-engine)。本项目选择的外观近似与引擎的物理输入含义分别记录。

## 2. 现有配方基准

下表来自 `SourceAssets/WeaponSurface20260930/surface_card.json`。RGB 均为**线性数值**；Roughness 是干燥基础值，不含细纹、边缘、凹腔与水膜的最终变化。

| 当前预设 | 线性 FinishColor | Metallic | 基础 Roughness | 使用边界 |
| --- | --- | ---: | ---: | --- |
| CleanSatinSteel | .034 / .035 / .037 | 1 | .42 | 本项目深色缎面处理金属基线，非通用裸钢值 |
| CleanAnodized | .020 / .021 / .022 | 1 | .46 | 本项目暗色表面处理近似；按实际区域决定能否复用 |
| CleanPolishedSteel | .160 / .160 / .155 | 1 | .30 | 现有亮件外观参考，不默认用于每把枪的枪机 |
| CleanPolymer | .019 / .019 / .018 | 0 | .55 | 黑色聚合物基线，不复制金属露底逻辑 |
| Rubber | .0103 / .0103 / .0103 | 0 | .70 | 当前软垫参考，保留独立纹理与响应 |
| Interior | .004 / .004 / .004 | 0 | .75 | 当前内腔近似，不能代替所有真实内腔材料 |

这六行只固定可追溯起点，不要求六类材料共用相同颜色，也不表示旧 Rubber／Interior 的全部噪声与遮蔽参数成为新默认。

### 分部件的层次

SVD Refine03 已保存的例子：机匣 .38、枪机 .31、拉机柄 .34、紧固件 .36、瞄具外壳 .43、安装座 .44、凹部 .51；金属弹匣壳 .34、接口／底板 .37。它们体现“少量、清楚的部件层次”，不作为每把枪的强制套值。

- 同一表面处理家族只作有限、可说明的差异；不依靠随机颜色把整枪打碎。
- 同类弹匣与加长弹匣沿用相同表面家族和细纹尺度，保留各自结构法线、UV、边界和几何差异。
- ASH12 的聚合物弹匣仍归聚合物；不能因为 SVD 弹匣使用金属配方就统一改成金属。
- `SourceColorWeight=0`、`SourceRoughnessWeight=0` 是现有 Clean 预设的选择。需要保留迷彩、印字、胶木或其他原色时，必须明确区域和混入方式，不能一边保留零权重、一边声称清洗源底色改善了运行效果。

## 3. 新制作的细节档

以下为 WS1.1 **推荐制作起点**，取自 SVD 已保存的后续修订。先记录到新配方，后续按实际部件制作；本次不覆盖公共预设或存量枪。

| 参数 | 旧 Clean 公共配方 | WS1.1 新制普通深色金属起点 | 缎面金属弹匣参考 |
| --- | ---: | ---: | ---: |
| GrainRoughness | .03 | .012 | .009 |
| MottleRoughness | .02 | .005 | .004 |
| MottleColor | 0 | 0 | 0 |
| ScratchAmount | 0 | 0 | 0 |
| HandlingPolish | 0 | 0 | 0 |
| Stipple | 0 | 0 | 0 |
| EdgeWear | .06 | .025 | .025 |
| EdgeHighlight | .06–.12，依预设 | .060 | .055 |
| CavityDarken | .06 | .025 | .025 |
| CavityRoughness | .04 | .018 | .018 |

这里的 `EdgeWear` 是旧接口参数名；默认 Clean 档的意图是轻微边缘定义，不表示所有凸边都应掉漆露白。后续抽取共享函数时，将“几何边缘反射”和“实际磨损露底”分成不同控制，不把物理身份藏在一个通用亮边参数中。

- 细纹主要影响粗糙度；不新增覆盖整面的强颗粒法线。材料纹理尺度用厘米／毫米表达，转换为实际采样尺度，不直接照搬另一件模型的 UV 平铺倍数。
- SVD 的法线倒角半径 .12–.18 mm 是近景细节参考；真实轮廓、厚度和深槽仍属于几何。不得为了材质统一抹平结构法线。
- 防滑、压纹与加工纹依实际部件设计。SVD .06 mm 的浅纵向压纹只适用于其指定面板，不推广成通用握把纹。
- 法线按同一切线基底组合；现有 RNM 层次为源结构法线 → 局部压纹／倒角 → 湿润。不同 UV 的切线空间法线不能未经转换直接混合。
- 新旧 AO 描述同一遮蔽时不再叠乘；保留明确的来源或合成规则。SVD 当前取较小值是其兼容配方，不作为所有 AO 来源的无条件合成算法。

## 4. 贴图输入与导入约定

| 输入 | 内容与采样约定 | 导入要求 |
| --- | --- | --- |
| BaseColor | 表面颜色／金属反射色；不混入投影、高光与广域 AO | 普通 sRGB 编码颜色图启用 sRGB；线性源先按实际编码处理，避免重复转换 |
| ORM | R=AO、G=Roughness、B=Metallic | 线性数据、sRGB 关闭、Masks 类压缩；通道顺序写入配方 |
| Normal | 切线空间结构法线 | Normalmap 压缩、sRGB 关闭；记录 DirectX／OpenGL，绿色通道只转换一次 |
| SurfaceMask | R=凸边、G=凹腔、B=AO、A=暴露度 | 线性数据；沿用现有语义，与 ORM 分开；记录 UV0／UV1 |
| Region／Marking／Exterior | 材质身份、印字保护、可淋湿外部区域 | 记录来源为纹理／顶点色／计算节点，不能凭名字猜通道 |
| Emissive／Opacity | 发光、透明、遮罩等特殊用途 | 独立记录通道和材质类型；光学、发光混合槽不自动转普通枪钢 |

约束：

1. 只有使用同一 UV、采样变换和适配分辨率的 AO／R／M 才直接打包。跨 UV 的数据不为凑一张 ORM 强行合并；常量 R／M 可继续用参数，不强制制造大纹理。
2. ORM 不替换现有 SurfaceMask，也不要求删除仍有必要的源图。记录最终生效的通道及其权重，避免同一粗糙度或 AO 被重复计入。
3. 分辨率按部件面积、UV 利用率和第一人称细节分档：主体通常 2K–4K，中型配件 1K–2K，小件 512–1K，均为制作起点。已存在的 4K 弹匣结构法线不因该分档自动降采样；不以整枪一律 4K／8K 代替纹理密度设计。
4. 保留 mip 和流送。提高分辨率必须服务可见细节，不强制所有纹理常驻，也不据纹理张数推断实际显存或帧率改善。
5. 扩容弹匣的 UV1 替代采样、UV2–6 接缝矩阵和手臂已有 UV 通道属于资产合同。表面规范化不能丢弃这些数据。

纹理遮罩的线性采样原则见 Epic 的 [Texture Masks 说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-texture-masks-in-unreal-engine)。

### AI 与旧工作流来源

- 去光照是显式可选步骤，只处理确有烘焙光影且仍参与最终表面的输入。先按材质区域保护印字、迷彩、胶木和真实色差，保留原图及处理配方。
- 不把整张图集统一拉到同一平均亮度；金属与非金属、不同表面处理不能共用一个无条件值域阈值。
- 从底色估算 Roughness／Metallic 的结果是制作起点，不能当作实测数据；已有可靠源通道优先保留。
- spec/gloss 转换注明来源、转换方法、颜色空间及输出约定；转换结果不自动证明与旧着色等价。
- 本规范不要求安装 TextureAlchemy、Albedolizer 或其他外部工具；已有后台脚本能完成的步骤继续复用。

## 5. 天气接口

- 继续使用 `WeaponWetness`（0–1）及当前天气系统的积湿／干燥驱动；湿润不是静态编译开关。
- 干燥时恢复干燥基础表面，不残留水珠法线；湿润只应用一次，并在干燥材质分区、法线和细节处理之后执行。
- 受遮蔽内腔、镜片、分划及特殊发光区域按各自合同处理，不一律套枪体水珠。
- 当前直接继承 `M_WeaponSurface` 的实例通过 `WeaponSurfaceStandard::SelfWetSource` 自动识别；ASH12／SVD 私有母图继续使用现有天气表自映射。此差异明确保留，不能漏掉后者的映射。
- 后续共享函数阶段应按深色金属、聚合物、橡胶开放湿膜／水珠响应系数，同时复用同一驱动。当前通用湿膜曲线先保留，不在本次规范制定时改掉所有武器。
- 换母材质不改变基底身份；不通过随湿度把 Metallic 从 0 调到 1 制造湿亮效果。

## 6. 母材质与实例组织

沿用 `M_`、`MI_`、`MF_` 和现有资产路径，不为命名一致而移动或重命名存量资产。普通表面按材质家族选预设，再逐槽建立实例；不把“每枪只建 MI”解释为每枪只能有一个 MI。

后续整理顺序：

1. 先将同一套表面响应、细纹、边缘／凹腔、湿润与法线组合逻辑抽为共享 Material Function。
2. 按真正不同的采样结构保留少量母材质类型：普通表面、区域表面、特殊接缝，以及独立光学／透明类型。静态与骨骼用途按实际使用者设置，尤其不能让七通道静态接缝材质错误获得骨骼用途。
3. 结构一致的源图才合并。保留继承后的有效标量、向量、纹理、静态开关、材质槽身份及天气接入；不要只拷纹理名字。
4. 区别只在颜色、粗糙度、细纹或标记的部件使用 MI。静态开关只表达实际结构选择，不按枪名制造开关排列，也不建立带所有光学／透明分支的万能母图。
5. 批量制作继续通过现有 Python 和 UE 批次互斥执行。减少母材质有助于集中维护，但不承诺材质槽、draw call 或运行耗时按同等比例下降。

以上是下一阶段实现规则，本次尚未抽取共享函数、合并母材质或修改天气识别代码。
