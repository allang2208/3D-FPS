# M24 本轮开发与联机复查

范围包括本轮普通与扩容换弹、装备与补栓、快速近战、后握把和战术挂件、枪托属性、原厂枪托接缝及普通与消音开火声。碳纤维枪托的新造型已按用户要求暂停。

| 触发条件 | 复查发现与改动 |
| --- | --- |
| 客机开枪后切走，随后收到物品交易回执或档案镜像 | 原合并函数只同步待拉栓和空仓标志，可能漏掉“射击中断”的来源。现在按同一物品实例合并中断来源及待抽壳状态，已闭锁的来源会清掉旧标志。 |
| 切走前还没抽壳，或在抽壳与闭锁之间再次切走 | 原待抽壳集合只存在于角色内存，观察端还按收到枪声的时刻独立倒计时。现在待抽壳状态保存在枪实例上，抽壳和闭锁分别结算。第三人称在实际抽壳时接收实例绑定的表现事件。 |
| 客机与监听主机对同一次装备动作的起始时刻不同 | 客机本人的动作时钟负责提交 M24 的补栓。远端副本不再依据自己的抬枪时钟写回客机档案，也不再因空匣自动换弹入口读写主机弹药袋。正常退出保存前先处理尚未结束的 M24 循环。 |
| 同一把 M24 更换消音器后马上开火 | 先前开火事件允许使用该枪声音清单中的任一声音，可能与服务器确认的消音状态不符。服务器现在按已识别的枪实例与消音器选择普通或消音开火声。 |
| 客机开枪，弹丸命中时玩家已经切到另一把武器 | 原服务端主要按命中时的持握组查找步枪。现在开火时通过可靠 RPC 登记枪实例、角色、发射序号、弹种、瞄向、射程及发射时位置。在飞行时间窗口内，普通 M24 子弹使用这次登记处理迟到命中。收枪后的申报另外校验发射方向、重复目标和穿透上限，继续经过既有弹药账本、遮挡、距离与适用的目标历史校验。 |
| 骨架托切回补栓或空仓换弹 | 原来的速度倍率只进入射后动作。现在装备与空仓换弹也按已安装枪托及枪栓的目录倍率处理拉栓段，手、机械声、抽壳和闭锁用同一动作时钟。骨架托速度为 1.20 倍，前段抬枪、取匣与插匣沿用原节拍。空仓总耗时也进入枪匠统计。 |

联机用例原先明确假定 M24 没有战术槽，并强制要求旧版材质目录。已更新为当前装配，检查原厂枪身归一、先进枪机与普通／赐福镭射和手电、枪托与握把组合、5／10 发、枪口消音状态和两种专用声源、远端换弹手部接触和激光端点。

资源核对包括 11 组制作记录所引用的 180 个不同资源包。最近一次装备动作发布的 11 个包散列与现有文件一致，包括 10 份握姿配置和普通装备动画。枪匠目录中先进枪机、骨架托和碳纤维托的倍率与指定值一致。[资源与属性记录](../Publication/M24_20261105/Evidence/disk-and-catalog.json)

联机夹具使用独立档案、本机 UDP 监听主机、客机和新加入的客机。每个连接运行六个阶段，双方各设 60 ms 延迟、5% 丢包。部分动作由夹具固定源时间以重现抽壳前后和闭锁边界。飞行中切枪的用例通过实际客机 RPC 登记发射，在服务端替换活动槽后进入正式命中准备逻辑。夹具使用无图形、无音频输出模式。公网与独立服务器、强制掉线后从真实玩家旧档恢复、完整对战扣血、可见手臂及听感仍需要分别实测。

最终正式模块构建成功。首次连接和重新加入各六个阶段全部通过，监听主机记录 12/12。两次连接均确认切走后的合法命中通过准备流程，并拒绝相反瞄向、重复目标和未登记的收枪后命中。骨架托用例分别核对抬枪、闭锁、弹匣到位和空仓拉栓时长。本次没有运行完整打包。[构建记录](../Publication/M24_20261105/Evidence/build.json) · [主机结果](../Publication/M24_20261105/Evidence/host.json) · [首次客机](../Publication/M24_20261105/Evidence/client.json) · [新加入客机](../Publication/M24_20261105/Evidence/rejoin.json)
