# 双手剑 · 冲刺举顶竖劈（2026-09-16）

用户要求：做一支**将剑举过头顶、垂直向下劈砍**的动作，触发方式是**按住 Shift 奔跑中攻击**。

结果：新增动画 `A_RuneSword_Overhead`（1.30 s），奔跑中按开火即播放；普通站定攻击仍是原来的
蓄力/连段。**没有改写任何姿势**——两支已获接受的蓄力攻击片段被重新计时得到这支动作。

## 一、做法：重定时已接受的重击动作，不重解手型

近战攻击那条 SKILL 记录的经验是：**保留了已接受的空间轨迹时，优先重定时，不要为了改节奏
重新求解手型**。而现有重击里正好已经有这支动作需要的两个姿势：

| 来源 | 内容 |
| --- | --- |
| `A_RuneSword_HeavyCharge` | 起势 → 双手把剑举上头顶（0.00 起，2.00 s 到蓄满） |
| `A_RuneSword_HeavyRelease` | 从头顶点向下劈出，接触窗就是它自己开头的 0–0.075 s，之后是惯性带出与回位 |

两者首末帧都落在同一套待机姿势上，所以拼接不需要任何混合。

V49 的时间表（本片段自身时钟）：

| 本片段 | 内容 | 取自 |
| --- | --- | --- |
| 0.00–0.34 | 举剑过头 | HeavyCharge 0.00 → 2.00（2 s 的抬举压到 0.34 s） |
| 0.34–0.40 | 顶点短停 | HeavyCharge 2.00 |
| 0.40–0.70 | 下劈 + 带出 | HeavyRelease 0.000 → 0.150（放慢 2 倍，看得清） |
| 0.70–1.30 | 收势回位 | HeavyRelease 0.150 → 1.000（略快，回到待机） |

因为只做时间重映射，**双手握点、接触关系、前臂扭转分布、剑在画面里的路径全部逐位继承**，
不需要再做一次接触点或进深推导。

## 二、命中窗对齐可见的劈砍

逐帧量了剑尖位置（`authoring_v49.json`）：

| 本片段 | 剑尖画面深度 | 说明 |
| --- | --- | --- |
| 0.30–0.40 | −0.39 → −0.46 m | 举顶顶点：剑身在相机平面之后（与已接受的重击蓄力一致，玩家看不到那段剑身） |
| 0.44 | +0.25 m | 剑身越过画面平面，进入可见区 |
| 0.50 | **+1.30 m** | 最大伸展，剑尖朝前下方，完成下劈 |
| 0.54 | +0.52 m | 继续向下带出 |

所以命中窗取 **0.44–0.54 s**（该窗内剑尖最近进深 **+0.2484 m**，每一帧剑身都在相机前方），
而不是照抄重击释放的 0–0.075 s——后者落在剑身还在画面之后的阶段，命中判定会打在看不见的
位置。冲锋下劈的采样率沿用释放本身的 480 Hz（见 `RuneSwordOverheadRhythm.h`）。

## 四、构建与状态

### 第一次实机没触发的原因（2026-09-16 23:13 用户反馈"还是普通攻击"）

复核发现：新增片段名 `Overhead` **没有加进 `RuneSwordComponent.cpp:110` 的片段加载表**，
于是 `Animations.FindRef(TEXT("Overhead"))` 为空，而 `BeginOverhead()` 当时的兜底是**静默**
`BeginAttack()`——表现就与"冲刺攻击没生效"完全一样。

修法：把 `Overhead` 加进加载表；兜底改成**先 `UE_LOG(Warning)` 再退回普通攻击**，不再静默；
并在 `FirePressed()` 的剑分支加一行 `RuneSword attack pressed: sprinting=0/1`。

**教训**：新增动作片段必须同时改加载表、`SetClip` 名、组件入口三处；任何"找不到片段就退回旧
动作"的兜底都要留日志，否则和功能没做出来无法区分。

## 六、V50 重做：V49 为什么读起来像"快一点的普通第一刀"（用户反馈核实）

用户反馈"跟近战第一下没有任何差别，只是快了"。逐帧量两支动作的手/剑轨迹后确认**属实**：

| 指标 | Slash1（普通第一刀） | V49 竖劈 |
| --- | --- | --- |
| 手的高度范围 | −0.281 .. **0.000** | −0.293 .. **+0.030** |
| 手抬升量 | 0.282 m | 0.323 m |
| 剑尖竖直行程 | 1.579 m | 1.591 m |
| 剑尖水平行程 | 1.992 m | 2.035 m |

根因：**重击蓄力并不等于"把剑举过头顶"**。它只把手抬高 0.169 m，并用"把剑身转到相机平面之后"
来定义顶点——画面上从来没有"举起来"这一下，剩下的就是一次下扫，而片段又短了 27%，所以观感
就是"快一点的普通第一刀"。这是我把"重击蓄力"当成"举顶姿势"的误判，不是节奏问题。

### V50 的修法：用两骨 IK 把双手真的抬到画面顶部

沿用 V45 已经获接受的 `hold_shift.solve_arm`（两骨 IK，保持每个握点的位置与朝向），把**整组
持握（剑 + 双手）沿世界 +Z 抬 0.28 m**，肩肘随之重解，握点不动的性质保持不变。时间表：

| 本片段 | 内容 |
| --- | --- |
| 0.00–0.16 | 起势：重击抬举 0 → 1.00 s（剑身仍在画面内） |
| 0.16–0.24 | 整组持握上抬 0.28 m（手越过画面中心） |
| 0.24–0.34 | 顶点停一拍（可读） |
| 0.34–0.42 | 交接到重击释放的 0.033 s 姿势 |
| 0.42–0.52 | 释放自身的 0.033 → 0.075（**前下方扫过的下劈**，接触给在这里） |
| 0.52–1.30 | 释放的跟随与收势，回到待机 |

关键点：**交接要接在释放的 0.033 s 而不是它的接触姿势**——直接从顶点混到"刀在下"的姿势会让
剑身从脑后绕过去（实测剑尖深度在 0.40–0.45 s 是负的）；接在 0.033 s 就完整保留释放自己那段
前下方扫掠。
