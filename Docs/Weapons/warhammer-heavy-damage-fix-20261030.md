# 战锤重击等级与雷击伤害修复（2026-10-30）

用户要求修复重击倍率未跟人物技能等级成长的问题，并检查此次伤害链路中的错误与遗漏。

## 最终公式

重击技能倍率读取角色自己的 `heavyStrike`：1 级 2.5 倍，每升一级增加 0.1，10 级 3.4 倍，20 级 4.4 倍。

```text
技能重击倍率 = 2.5 + max(0, 技能等级 - 1) × 0.1
最终重击倍率 = (技能重击倍率 × 改造重击倍率 + 改造重击固定加值) × 改造武技倍率
重击面板 = 普攻面板的各伤害通道 × 最终重击倍率

额外雷击 = 最终魔法攻击力 × 100%
         × (1 + 套装魔法伤害加成) × 改造魔法伤害倍率 × 全攻击伤害倍率

普通雷神之锤重击 / 贯雷落地 = 重击面板 + 一次额外雷击
疾雷落雷 = 上述总量转为魔法伤害，保留基础与附加伤害的归属
```

额外雷击不再乘重击倍率，武器已有的附魔／侵蚀魔法附伤仍随重击面板结算。疾雷没有第二次乘重击倍率，也没有重复追加额外雷击。上述为防御与暴击结算前数值；目标防御、穿透和暴击继续使用既有公共结算。

感电增伤：普通雷击／贯雷只放大额外雷击，不放大物理和非雷电附伤；疾雷转为雷电魔法后的整次伤害获得感电增伤。

## 修复落点

- `ProductionToolStats.cpp`：最终倍率与蓄力时间统一读取角色重击技能；倍率通过既有 `FMeleeModifiers::HeavyMultiplier` 计算，支持乘法、固定加值和武技倍率的既定顺序。
- `ProductionToolComponent.cpp`：直接使用最终倍率，去掉物品固定 `heavy_damage_multiplier` 的第二层计算。旧物品数据仍可读写，但不再覆盖角色技能等级。
- `M4MeleeGunsmith.cpp` 原有总览行自动消费新的最终倍率；`M4GunsmithSelectedDetails.cpp` 同步改为比较实际倍率，兼容固定加值与武技倍率。
- `WarhammerShockwave.cpp`：单独保留原生雷击量，补上普通雷击／贯雷对感电目标的雷击增伤；疾雷继续对完整魔法伤害结算感电增伤。
- `ThunderHammerRecallAudio.cpp`：补上对应头文件作为首个 include，修复完整后台构建的头文件顺序错误；音效行为不变。

蓄力基准也随技能成长：1 级 2 秒、10 级 1.55 秒、20 级 1.05 秒，随后应用蓄力速度改造与既有电光神行倍率。动画仍映射到原有作者动作时间，不重新制作动作。

## 检查方式与边界

后台 `FPSGAMEEditor` 编译；`WarhammerModificationAudit -HeavyFormula` 使用独立 `HammerModsAudit_*` 配置及权威角色影子资料，执行等级、实际目录改造、UI 草稿与伤害分量检查。

当前目录没有固定重击加值、武技伤害倍率的战锤改件，因此这两项用独立 GameInstance 中临时修改的贯雷改件验证顺序，结束后恢复；不写入资产、正式目录或个人存档。实际目录与模拟用例分别记录在 JSON。

检查不启动游戏、不运行世界 Tick、不打开编辑器界面；权威调用检查不等于真实双端网络传输或实战视觉验收。构建、检查脚本及机器报告位于 `SourceAssets/ThunderGodHammer20261028/HeavyDamageFix20261030/`。

最终结果：`FPSGAMEEditor` 后台编译成功；`heavy-formula-20261030-094302.json` 共 465 项断言、0 失败，检查 18 个实际目录改造及独立的固定加值／武技倍率组合。个人存档未修改。第一轮检查的两项失败来自测试预设误以为实际战锤目录已有固定加值、武技倍率改件，已改为明确标注的模拟用例；最终报告区分两类覆盖。
