# 魔法书专注联机与诊断时序修复

本次修复源码检查发现的两处遗漏：客机专注没有权威状态、旧快速近战诊断仍使用旧播放时间。保留现有书页内容、握持、受击收书和接书动画。

## 专注的客户端与服务器职责

- 客机继续立即播放已有开书、合书和受击恢复动作。
- 开始、正常关闭、立即取消通过 `ColdSteelPlayerState` 的可靠 RPC 上报，与已有施法请求使用同一 Actor 通道。
- 服务器按该玩家影子档案核对当前法杖和副手魔法书，用自己的开始时间计算开书阶段。完全展开后参与现有 `ApplySpellbookFocus` 公式：施法速度 ×2，魔法消耗 ×0.75；开始专注即使用移动倍率 0.67。
- 正常收书立即结束数值增益和减速，恢复阶段仍占用快速近战。服务端的快速近战命中入口也拒绝该阶段的攻击。
- 专用服务器保留轻量专注逻辑，不加载第一人称手臂和书页资产；装备失效、翻越、切换武器、推门或死亡清除权威状态。
- 受击只在权威端结算一次最大魔法值 25% 的损失，随后通知拥有者播放现有快速翻页、合书、落下接住和恢复。回执同时携带 Pawn 和专注轮次，旧轮次不得取消新一轮动作。
- 本次没有新增其他玩家视角的书页资产或独立动画复制；沿用已有身体表现通道。
- 同时修复必要的服务器施法提交路径：影子档案仍禁止自行写盘，但允许经过原有规范化和校验的权威内存事务。原先 `bPersistenceBlocked` 直接拒绝 `Begin*Cast` 的扣费提交，导致专注减耗也无法实际落地；主机档案保存继续由 PlayerState 负责，本地损坏存档的写保护保持原样。

## 扣魔与档案合并

`FColdSteelProfile.SpellbookFocusManaLoss` 记录已经计入当前魔法值的累计专注打断扣除量。它是随档案保存、上传和私有镜像复制的数值字段；旧的带字段名存档缺失该字段时默认 0，无须清空或重建存档。瞬时专注阶段与轮次不保存。

权威扣魔、即时回执和周期镜像共用同一累计记录。同一笔扣除被收到两次时不会再次扣魔；打断前捕获但稍后上传的档案会补扣遗漏的差额；较旧的下行镜像不能覆盖较新的扣魔记录。低魔法值仍扣至 0，无限魔法开发选项沿用原有豁免。

## 快速近战诊断

`fps.body.DiagnoseBookPush` 现在使用 `SpellbookQuickCombatMotion` 的实际播放总长和空手接触时刻，再映射到书本原始姿态。总长约 0.551667 秒、接触约 0.171667 秒；原始姿态仍保留 0.43 秒作者时轴，运行时和诊断都通过同一映射取样。
