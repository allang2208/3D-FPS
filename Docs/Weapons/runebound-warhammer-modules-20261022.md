# 符文战锤模块化与通用改造 · 2026-10-22

符文战锤沿用独立物品 ID `ue_runebound_warhammer`，由整体锤体升级为六个实体模块、五栏改造目录。默认六件全部使用本锤原装几何，外表面的 UV、原生刻纹、PBR 和法线保留，只封新增切口。完整原装网格仍保留为世界资源和恢复来源。

## 模块与共享目录

| 实体/栏目 | 原装与通用选择 | 属性来源 |
|---|---|---|
| 双侧锤头 | 原装；重铸方锤、破韧棱锤、轻量鼓锤、双棱尖头锤 | `common-hammer-heads.json` |
| 中央锤座 | 原装；厚壁重铸座、镂肋轻型座、叠片缓冲座 | `common-hammer-seats.json` |
| 锤颈套箍 | 原装固定实体，保留承力结构 | 无改造栏目 |
| 金属长柄 | 原装固定实体，同时承载附加符文 | 无改造栏目 |
| 握持包覆 | 原装；斜纹速握、叠革缓震、菱编蓄力 | `common-hammer-grips.json` |
| 柄尾配重 | 原装；八棱镇击、镂笼灵巧、双盘平衡、无配重端盖 | `common-hammer-pommels.json` |
| 附加符文 | 无附加符文；力量、疾风、共鸣、侵蚀、导魔 | `melee-gunsmith.json` 中五种通用符文 |

通用配件的 ID、数值、说明、图标与锻钢战锤共用来源；本锤仅增加几何适配资产和安装配置。`meteor_core` 陨星熔核继续属于锻钢战锤，不加入符文战锤目录。原装 `false` 与独立 `no_pommel` 状态保留各自含义和数值规则。

## 接口和外观

作者空间沿用 WPN_root，单位米。分界为柄尾 -0.085、包覆上端 0.405、长柄上端 0.780、锤颈上端 0.842；双侧接面位于 X=-0.0354452141 / 0.0345547859，锤头原点 Z=0.916。这些参数来自本锤形状，不把锻钢战锤的安装位置直接当作新锤接口。骨骼缩放抵消继续沿用既有挂载变换。

14 个通用实体配件分别从当前共享作者源派生，按原装和宿主真实截面环连续适配。握持包覆保持原双手接触范围，配重与无配重端盖对接本锤柄尾；锤头和锤座的两侧安装面共用同一截面变换，锤座下端对接原装锤颈。原装接口片段投射本锤 PBR UV，共享配件主体保留其钢材、皮革、织带、缓冲垫及车纹材质。

五种符文放在固定长柄上，沿本锤局部 42.5–76 cm 轴向区间环绕显示，保持共享颜色、明灭和属性。原生锤首刻纹保留，不为名称中的“符文”添加默认额外伤害。原装件和分类图标使用实际新模块制作的灰阶金属方框图；通用配件及符文复用已有图标。

符文长柄沿用常规静态网格覆盖层路径；运行装配对本锤的长柄组件禁用 Nanite，使用已保存的完整回退几何。其他模块按各自制作策略保留。改造界面直接读取已落盘 PNG，不另外依赖未使用的图标 Texture2D 包。

## 运行接入

`runebound-warhammer-modules.json` 驱动手持、改造台草稿/应用/取消、图标配方、预览和世界掉落。五栏读取 `runebound-warhammer-gunsmith.json`，实例继续保存 `gunsmith_parts`。初始整锤版本没有可安装的 `body` 改件；规范化后自然恢复六件原装组合。

两把战锤共同使用 `rune` 槽、五种通用符文身份和既有属性结算；新锤单独选用适配其长柄的符文材质。此修订没有改写手臂、骨架、动画序列、握持配置或攻击时钟。第一/第三人称全部动作继续由既有 `warhammer` 路由与 `animation_manifest.json` 清单消费。

## 制作和交付

制作源位于 `SourceAssets/RuneboundWarhammer20261022/ModulesV1/`：原装拆分与通用配件可编辑 Blend、FBX、安装截面、宿主配方、图标、符文 HLSL 及作者/导入入口全部保留。`prepare.py` 固化标准拆分和图标作者；`author_adapted.py` 制作 14 个通用接口适配；`import_assets.py` 实际保存完成后发布配方。父级 `register.py` 复用新模块配方，避免重跑初始注册时恢复整体锤体。

实际保存记录见 `import_receipt.json`；Editor / Game 必要构建见 `build_receipt.json`；本批汇总为 `delivery.json`。本次不启动编辑器界面、游戏、PIE、验收渲染或测试，装配观感、握持和联机效果由用户测试。

网格与材质已由后台导入批次实际保存；最后的图标/目录阶段通过 `finish_publication.py` 发布，记录于 `publication_receipt.json`。两次仅执行到引擎初始化的后台续接已结束，没有用于运行测试。初始导入中材质槽副本后缀和图标路径报错保留在原日志中，最终回执记录已完成的资源与发布范围。
