# 伐木斧自卫伤害与伐木判定

2026-09-19，接续已接入的双手攻击 V3。用户授权设计低伤害、接入敌人受击，并检查和优化伐木距离判定。

## 数值定位

伐木斧保留工具身份，主用途仍是采集。对敌普通挥砍的基础物理伤害为：

`round(12 + 1.2 × 力量 + 0.3 × 敏捷)`

公式放在 `Content/ColdSteelData/combat-weapon-formulas.json` 的 `tool_axe`，走现有 `ProcessedDamage` → `DamageParts` → `ColdSteelSkills::ApplyHit` → 怪物防御结算。力量/敏捷口径与既有武器公式一致（分配属性加装备属性），不额外叠加角色物理攻击面板。工具不继承当前收起武器的伤害、附魔或刀剑精通固定伤害。当前不开放工具强化、连击、重击、格挡或额外击退。

| 属性条件 | 伐木斧基础物伤 | 当前双手剑基础物伤（智力10、同力量，+0） |
| --- | ---: | ---: |
| 力量10、敏捷10 | 27 | 120 |
| 力量30、敏捷10 | 51 | 190 |
| 力量50、敏捷10 | 75 | 260 |

这是公式比较，未计刀剑专精、部件、暴击等额外收益，也不是实测 DPS。角色现有暴击/暴伤和敌人物防继续生效。比如基础27点、敌人物防30、非暴击时，现有公式 `max(floor(D×60/(防御+60)), floor(D×0.1))` 得到18点。

一次攻击开始后捕获斧头自己的伤害与角色暴击快照；在原来的0.48秒接触点只结算一个目标。普通命中走已有命中标记、伤害/血条反馈和 V3 停帧、拔出、镜头时钟，命中动作总长1.40秒，空挥1.10秒。敌人命中不扣采集进度、不产木材、不播放伐木尘土/木材音效。体力仍按原采集动作扣一次。友方、玩家和已死亡单位不作为伤害目标。

## 原判定的具体问题

- 原 `ProductionToolComponent::TraceResource` 只从稳定眼位发一条320厘米的 `ECC_Visibility` 直线，零横向宽容度；与玩家感知的斧刃宽度不同。
- 普通树的可见实例与碰撞分开，`TemperateHillsStreaming` 用隐藏的树干 ISM 碰撞柱。射线擦过可见轮廓或碰到旁边地面时，不能解析为树干采集目标；这是“足够近但砍不到”的代码原因之一，未通过实机复现归因到某一棵树。
- 近处地面/旁边障碍可先碰到宽探针，所以不能简单把直线改成仅取第一个阻挡的球扫。

## 新的统一命中查询

`ProductionAxeContact.cpp::TraceAxeContact` 同时供接触事件与准星提示使用：

1. 稳定眼位与控制朝向，继续排除 V3 镜头震动对实际射线的影响。
2. 优先准星直线实际命中的可砍树干或活敌人。
3. 直线没有有效对象时，分别收集树干半径32厘米、敌人半径24厘米的球扫候选。
4. 按眼位到真实接触点的三维距离限制：树干320厘米，敌人180厘米；球体端部不额外增加距离，身后目标排除。
5. 每个候选单独做视线遮挡判断；树木必须是相同组件及相同实例，不能只比较 Actor（地形、岩块和许多树干共用同一世界 Actor）。
6. 初始球体重叠时重新求实际表面接触，避免把眼位误作树干命中点。边缘候选优先更接近准星方向，距离作为同等偏差时的次序。
7. 每斧只选一个目标。不可隔实体墙采集，也不同时砍树和扣敌人血。

上述四项距离/半径存于 `production_tools.json`。旧存档工具在既有 `NormalizeProductionState` 中更新描述与调参字段，保留实例、仓库位置、采集进度。物品提示显示同一伤害公式与对敌/伐木距离。矿镐和铁铲的查询保持原流程。

成熟、生长、已采尽、第三斧倒树资产尚未准备好的限制仍保留，扩大范围不会绕过这些资源规则。
