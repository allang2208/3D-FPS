# PKM 镭射 ADS 指向错误（2026-09-22）

用户报告：持有 PKM 并装红色激光镭射时，切换 ADS 会错误指向。要求对照其他枪械的镭射设计修改。

## 现有设计（先读代码，不猜）

全部枪族的镭射/手电共用 `Source/FPSGAME/Weapons/TacticalDeviceComponent.cpp` 一个实现：

- 战术件主体 `Body` 挂到武器网格的 `WPN_root`。
- 腰射：光束方向 = 主体网格的 `Emitter -> AimGuide` 两个 socket 的连线。
- 开镜（`IsAiming()` 或 `WeaponADSFactor > .98`）：改从 `Emitter` 指向
  `ComputeShotDirection()` 在 80 m 处的落点，即"汇聚准星"。
- 遮挡：先做 Eye→Emitter 的遮挡测试，命中则整条光束不出。
- 数值：各枪 `laser` 条目一致（`hip_spread_mult 0.5`、`ads_percent -0.2`），排除数据差异。

挂载变换按枪族分三种：ASH 有专用 `ASH12TacticalMount`（含绕局部 X 旋转 180°），
手枪有 `PistolTacticalMount`，其余步枪族（含 PKM）= `FTransform(Identity, Zero, 0.01)`。

## 实测（`SourceAssets/PKMLowpolyLaserBug20260922/`）

用编辑器内 Python 读出各战术件网格的 socket（`inspect_sockets.py`）：

| 枪族 | Emitter | AimGuide | 连线（网格本地） |
| --- | --- | --- | --- |
| M4 | (5.31, 36.37, 7.80) | (5.31, 39.37, 7.80) | **(0, 1, 0)** |
| AKM | (4.62, 35.37, 5.70) | (4.62, 38.37, 5.70) | **(0, 1, 0)** |
| QBZ191 | (4.75, 33.57, 7.00) | (4.75, 36.57, 7.00) | **(0, 1, 0)** |
| PKM | (4.72, 51.97, 6.98) | (4.72, 54.97, 6.98) | **(0, 1, 0)** |
| A762 | (5.22, 35.37, 6.20) | (5.22, 38.37, 6.20) | **(0, 1, 0)** |
| M16 | (7.81, 46.37, 9.15) | (7.81, 49.37, 9.15) | **(0, 1, 0)** |
| **ASH12** | (4.37, 3.14, 0.00) | (7.37, 3.14, 0.00) | **(1, 0, 0)** |

两件事：

1. 步枪族的插座连线是**网格本地 +Y**，而武器 `WPN_root` 的前向是 **+X**（`inspect_mount.py`
   实测三个枪族 `root fwd=(1.00,0.00,0.00)`，`WPN_root` 缩放约 100，附件相对缩放 0.01，
   合成后 1，与 ASH 文档记录一致）。**插座连线与枪管垂直**。
2. 步枪族在挂载时用的是单位旋转（不修正这个轴向）；ASH 自己额外旋转了网格，
   所以它的插座反倒沿 +X。**插座方向与网格旋转互相耦合、各家不一致**。

另外 `Docs/Weapons/ash12-tactical-devices-20260920.md` 对 ASH 的要求写得很明确：
「Emitter / AimGuide 由旧模型随同刚性变换得到，维持同轴照明」「AimGuide 仍沿枪口前向」。
即设计意图是 **AimGuide 沿枪口前向**，而步枪族实测不满足。

PKM 相对其他枪族还多一处差异：`Emitter` 更靠前（相对 WPN_root 0.520 m，M4 是 0.364 m），
所以位移项在开镜汇聚里的权重大约是 1.4 倍。

## 修复

不再依赖各网格的插座约定，方向改取**武器自身的瞄具轴线**（与 `ComputeShotDirection`
和瞄具标定同一个权威），发射点仍用 `Emitter` 插座——那是玩家看到的发光口位置。

`TacticalDeviceComponent.cpp` 新增 `WeaponForwardAxis()`：

- 取 `WPN_FrontSight - WPN_RearSight`，按 `WPN_root` 的上轴投影去掉俯仰分量；
- 返回**武器根骨骼本地**的前向，调用方再用 `WPN_root` 的 socket 旋转转到世界；
- 前/后瞄具骨缺失时返回 false，回退到原来的 `Emitter -> AimGuide` 插座方向。

骨骼索引取自**参考骨架**（不是动画姿态），所以每个 mesh 只解析一次，
不在每帧的 `TickComponent` 里重复查找。因为方向是刚体绑定的，只在武器根骨骼旋转
变化时才改，逐帧重算没有额外误差；但可以后续缓存。

这样：

- 腰射光束沿枪管，不再横向；
- 开镜仍然汇聚准星（`Emitter` → 描线方向 80 m 落点），位移项是真实的枪口-视线偏移，
  形成自然的"近距离偏高、80 m 归零"行为，与真实激光一致；
- 所有枪族（步枪、手枪、ASH、M16、A762、PKM）走同一条规则，不再各自依赖插座朝向。

## 用户定位：真正的原因是开镜时间（第二次修订）

第一版把方向改到瞄具轴线后，用户指出真正的问题是**"开镜时间"**：
要在 ADS 完全开完之后，再迅速把激光指向准星。

复核 `TickComponent` 的判定：

```cpp
if(C->IsAiming() || C->WeaponADSFactor > .98f)   // 第一版就是这一行
```

`bIsAiming` 在**右键按下的瞬间**就为 true（`SetAimingState(true)`），而
`WeaponADSFactor` 要走完整段 ADS 时长才到 1：

| 武器 | `ads_smooth` | ADS 全程 |
| --- | --- | --- |
| M4 / QBZ191 | 12.482 | 0.240 s |
| ASH-12 | 14.0 | 0.214 s |
| M16A2 | 10.699 | 0.280 s |
| AKM / A762 | 9.986 | 0.300 s |
| **PKM** | **6.657** | **0.450 s** |

所以 `IsAiming()` 那半条分支**从抬枪第一帧就成立**，整段 0.45 s 的过渡期里光束都在
被往准星上扳——PKM 的 ADS 几乎是 M4 的两倍长，这个偏差自然最明显。这就是用户看到的"错误指向"。

### 改动

- 判定改为 **ADS 完全到位**（`WeaponADSFactor >= ADSSettleThreshold`，阈值默认 1.0），
  不再看 `IsAiming()`。
- 过渡期光束**保持沿枪管**；到位后在一个独立的短时窗内对齐准星，
  `LaserConvergeSeconds` 默认 **0.08 s**。
- 对齐用**按经过时间解析求值**，不是逐帧累积插值。这一点踩过一次坑：
  逐帧 `Lerp(direction, aim, dt/T)` 只是指数逼近，60 fps 下把名义 0.08 s 拉成 **0.283 s**
  才降到 2% 残余；改成 `Blend = clamp(elapsed/T, 0, 1)` 后不论帧率都在 T 秒精确到位。
- `ResetLaserAim()` 在 `Configure()` 里清状态，换枪或换挂件不会继承上一件的对齐进度。

修复后的时间线：

| 武器 | ADS 全程 | 到位后对齐 | 合计 |
| --- | --- | --- | --- |
| ASH-12 | 0.214 s | 0.080 s | 0.294 s |
| M4 / QBZ191 | 0.240 s | 0.080 s | 0.320 s |
| M16A2 | 0.280 s | 0.080 s | 0.360 s |
| AKM / A762 | 0.300 s | 0.080 s | 0.380 s |
| **PKM** | **0.450 s** | **0.080 s** | **0.530 s** |

调参入口：`TacticalDeviceComponent.h` 的 `ADSSettleThreshold`（1.0 = 必须完全到位）
与 `LaserConvergeSeconds`（0.08 = 对齐时长）。想让对齐更"瞬发"就把后者调小。

## 未做 / 边界

- **没有实机目测**（用户规则：默认不主动测试）。上述都是离线读 socket 和骨骼的实测，
  以及代码路径分析；"光束现在是否指向准星"仍由用户判断。
- 没有改任何网格资产，也没有改挂载变换，所以配件的外观位置完全不变。
- 没有重新标定激光的"归零距离"（仍是开镜时的 80 m 会聚点）；如果实机感觉近距离偏高，
  这是符合物理的表现，需要的话再单独调。
- 步枪族插座仍是 +Y：本修复绕开了它，但插座本身依旧与文档要求的"沿枪口前向"不符。
  没有去改 8 个网格资产，因为那会牵动已认可的配件外观与 ASH 的旋转耦合。
