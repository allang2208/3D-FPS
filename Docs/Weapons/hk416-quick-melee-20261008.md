# HK416 快速近战：参考当前 M4 缩时与收紧路径

用户反馈 416 的快速近战速度慢、带出距离过大，要求参考 M4 调整。本次只制作并接入六种握持的快速近战，默认不运行游戏、测试或验收渲染。

## 原因与制作依据

- 当前加载入口为 `AFPSGAMECharacter::RifleQuickCombatClip`：优先读取 `AnimationProfiles20261001/ue_hk416/DA_*` 的 `quick_melee`，再回退到 `HK416/Reworked20260930/Animations/<family>/A_HK416_<family>_quick_melee`。
- HK416 原制作器引用 `M4QuickMeleeReplica20260919` 的早期 I 版，而当前 M4 运行资源已经由 `M4QuickMeleeRefine20260919N` 覆盖。目录名相同不代表作者源相同。
- 原 HK416 制作器把参考动作的 108 帧按 60 FPS 计算；制作记录六套近战均为 1.8 秒。M4 N 的相同帧范围以 120 FPS 播放为 0.9 秒，运行入口再以 1.5 倍播放，即 0.6 秒。
- M4 的倍率只匹配 `A_M4_QuickCombat_` 名称，HK416 旧源没有得到该提速。实际导入前的资产时长记在本批 `import_receipt.json` 的 `previous_duration`。

## 调整

采用 M4 N 六种握持各自的武器轨迹，重新适配 HK416 当前原厂、弹鼓、斜握把、垂直握把、侧斜握把、棱镜阻手器待机。以当前 HK416 右手握点为枢轴，参考路径的位移取 70%、旋转取 90%；这是作者配方，不能解释为已测得屏幕带出距离减少了 30%。

两手保持本枪、本配件待机中的枪根相对矩阵及五指局部姿态。双臂复用当前 M4 的完整骨段支撑解算；肩点只迁移参考动作相对于其待机的位移，不能复制 M4 的绝对肩位或后握把枢轴。可达性修正作用于整枪和双手，首尾落回各自待机。

109 个原参考采样按 180 FPS 导出，成品直接为 **0.6 秒**，运行继续使用现有 HK416 的 1 倍率。没有 C++ 或技能数值变更，不需要重新构建原生模块。共用事件分数仍为 5/27 接触、8/27 跟随结束：接触约 0.111 秒，跟随结束约 0.178 秒；展示位归回从 0.36 秒开始，动作权重交接从 0.468 秒开始。命中、声音、占用和姿态共同使用该缩短后的时间轴。

没有更改模型、材质、配件衔接、待机、瞄准、换弹或检视资产。现有 M4 与其他枪型保持原样。

## 制作与接入

- 作者源：`SourceAssets/HK416QuickMelee20261008/author_motion.py`，后台 Blender 执行；输出六个 FBX、`HK416_QuickMelee_Editable.blend` 和 `animations.json`。
- 导入入口：同目录 `import_assets.py`；只保存六份 HK416 近战序列，并按当前实际存在的 Profile 重制相应 `quick_melee` 差量，保留其他动作条目。弹鼓使用自己的握持动作，不能套用空仓换弹帮助函数的基础动作替代规则。
- 保存回执：同目录 `import_receipt.json`，`complete: true` 才表示本批序列及配置已经落盘。原资产备份在 `Before/`。
- HK416 原厂和通用配件两条完整导入入口在末尾重接本批近战，避免重导入恢复旧的 1.8 秒版本。手型源有进一步修改时，先重跑本批作者脚本，再执行导入。

2026-10-08 已通过现有编辑器的批次互斥桥完成导入与保存：6 份动画、5 份现有握姿配置，回执 `complete: true`。导入前六份实际资产均为约 1.8 秒，保存后均为约 0.6 秒。使用已有编辑器会话，没有主动打开或重启 UE，也没有 C++ 构建。

本轮没有游戏手感、握持画面或命中回归测试，效果交由用户体验。
