## 根因

Blender 建骨时原代码顺序是：新建 EditBone → 设置 matrix → 设置 length。新骨骼此时长度为零，矩阵设置没有建立预期骨轴；之后补长度得到的实际绑定朝向与作者目标不同。

动画导出使用作者目标矩阵，网格绑定却使用实际 EditBone 的不同矩阵。原版关键骨段的两者朝向差异约 51～173°，而位置基本重合，解释了为什么只读手腕／弦接触位置会漏掉严重蒙皮错误。

只增加绑定动画首帧与 UE `use_t0_as_ref_pose` 的中间 ArmsV3 尝试没有解决作者骨轴，未成为弓的正式数据引用。随后修正实际建骨顺序：

```python
bone = arm.edit_bones.new(name)
bone.head = (0, 0, 0)
bone.tail = (0, 0.025, 0)  # 先建立非零长度及方向
bone.matrix = world_to_blender(reference[name])
bone.length = 0.025
```

保留显式参考姿态首帧，导出前更新依赖图；网格和动作共用同一原生绑定。

另一处姿态问题一并修正：取消辅助骨朝手掌整体四元数插值的 0.60／0.28 分配，前臂 roll 改由掌宽轴投影确定，辅助骨跟随所属完整骨段。各手指按自己的局部屈曲轴组合，四元数关键帧保持相邻符号连续。
