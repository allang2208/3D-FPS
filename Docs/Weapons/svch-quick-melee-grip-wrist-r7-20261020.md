# SVCH 快速近战握点与右腕 R7

用户明确问题出现在快速近战过程，待机／瞄准不在修改范围。以本枪当前待机握姿为参照，按手臂 SKILL 的整手接触、整臂支撑和姿态交接经验修订；不修改 V9、指骨尺寸、权重、修形或换弹／拉栓。

当前状态：2026-10-20 已完成最终 Editor / Game 构建，五套 Profile 均已保存，并从硬盘重新加载完成本轮指定的动画图、帧间和表面复查。未启动交互编辑器或游戏；实机观感仍由用户确认。

## 原因

R6 的快速近战右掌仍保留早期动作的握点，主体段相对当前本枪待机握点偏移约 2.505 cm、转偏约 7.161°。五指局部姿态基本相同，因此重新卷指不能解决整手错位。旧版腕轴折角最大约 47.8°，收势支撑退出后还会回到旧折腕姿态。

恢复整手握点后，真实 Gunplay 图又暴露出局部骨链混合的接触误差：已从待机起手的作者姿态重复与 idle 混合，入场可产生约 13 mm 掌位偏移；收势也会分离握点。仅比较作者手掌矩阵不能证明最终抓握成立。

## 最终制作

1. 使用当前 SVCH 待机的枪根相对右掌矩阵，整手重新落在同一后握把接触处。五指按原有成组局部姿态跟随，不逐指贴面、不平移指骨、不拉长骨段。
2. 复用 `M870QuickMeleeElbowR3_20261017` / R5 的整臂方法，调整肩肘支撑和前臂旋转分配，保留肘弯轴及原生骨长。修订后作者腕轴折角最大约 29°，这是同一骨架的比较指标，不是通用医学限值。
3. 保留 R6 真实动画图中已有的枪体和左臂入场／回位结果，烘焙为同一动作的姿态。右手和支撑链随同一枪体变换整体搬运；指骨局部姿态保留原运行结果。源时长仍为 0.9 秒，接触仍为 1/6 秒。
4. `FPSGAMECharacter.cpp::UpdateActionPose` 仅对 SVCH 快速近战启用作者姿态的完整所有权，取消重复入场／退出混合。作者末帧回到自己的 idle，原状态时钟、镜头展示归位和完成逻辑保持。其他枪械和其他动作继续原混合规则。
5. 继续沿用 R6 的实际 COMPRESSED 源与局部高密度差量编码，保留 67–68 帧之间已修好的瞬时甩臂。姿态交接烘焙后，差量表示覆盖整条 quick_melee 骨架；枪体和左臂的实际运动仍来自原 R6 运行姿态，而非新设计的动作。

## 恢复与交付

作者目录：`SourceAssets/SVCHReplacement20261018/QuickMeleeGripR7_20261020/`。

重制顺序：`author_grip.py` → `bake_existing_handoff.py` → `encode_profiles.py` → 对应 C++ 构建 → guarded install。前两步须按顺序执行，避免把已烘焙的交接当成未烘焙输入。

- `install_receipt.json` / `SavedReadback/`：五套当前 Profile 的实际保存回执和读回。
- `build_receipt.json` / `build_error.json`：构建状态与时间；发生后续失败时不能把较早的成功回执当作当前代码已编译。
- `grip-runtime-saved-glove.json`：真实 Gunplay 图中的握点、腕角、骨长、手指和臂根复查。
- `dense-check.json`：独立帧间采样，避免重新引入 R6 已消除的甩臂。
- `SVCH_QuickMeleeGripR7_ReloadGrip_Editable.blend`：可编辑姿态源。
- `Review/`：实际 V9 表面的掌侧和手背侧离线对比，不能代替用户实机验收。

范围为原厂、angled、vertical、canted、prism 五套快速近战，tactical_vertical 沿用 vertical。待机、瞄准、射击、检视、换弹和拉栓条目不写入。本轮不宣称第三人称、联机或用户实机视觉验收通过。
