# PKM / 201 握把运行时层 GripLayer56（2026-09-30）

用户要求：分批统一握把的抓握动作，减少各握把整套复制的动画。本轮做了两步：离线验证和运行时层。没有进游戏或 PIE 验收。

## 背景

- 每种握把（angled、vertical、canted、prism）都复制一整套动作：PKM 48 条，201 64 条，共 112 条。
- 运行时按基础 clip 查表换成握把 clip。查表分散在三处：`DrumPose`、战术冲刺、枪托砸击。

## 第一步：离线验证

目录：`SourceAssets/PKMLowpoly20260922/GripLayer56/`
- `collect.py`：只读采集 140 条在用动作的 `WPN_root`、左臂 8 骨和左手指的组件空间姿态。
- `evaluate.py`：握把层参考算法，C++ 按它逐步移植。它把"基础 clip + 握把层"的结果和作者做的握把 clip 逐帧比较。
- `grip_contact.py`：统计基础手偏离握持位的范围，用来定权重阈值。
- `summarize.py`：输出汇总表。

### 第一轮：只移手，保留基础肩和肘平面（v1，失败）

记录在 `evaluate_v1.py`、`study_v1.json`。握把待机和护木待机之间的差别远大于"手的偏移"：

| | PKM | 201 |
| --- | --- | --- |
| 手的位移 | 3.5–5.4 cm | 5.2–10 cm |
| 掌心转角 | 117–146° | 111–155° |
| 锁骨／肩的位移 | 0–2.5 cm | 8.7–9.5 cm |
| 肘的位移 | 5–9 cm | 14–24 cm |

另外，护木抓握本身是解剖上最吃力的姿势：前臂顶到 110° 上限，PKM 还要再加 48° 上臂滚转。握把抓握反而轻松：前臂只有 2–51°，上臂 0°。

只移手时，肘仍停在护木姿势的平面里，要靠最多 180° 的上臂滚转才能够到握把手位，也就是用户之前否决过的上臂扭曲。

### 第二轮：肩、肘、掌心滚转一起迁移（v2）

每帧的做法（弧度和权重的定义见 `evaluate.py` 文件头）：
1. **权重**：看基础手在枪空间里离基础握持位多远。在握持位上为 1，离开（换弹、检视）为 0。每秒最多变化 4，再做缓动。
2. **锁骨**：按参考对"握把 − 基础"的组件空间差值，乘权重后应用，整条手臂随锁骨刚性带动。
3. **手**：基础手（枪空间）× 按权重插值的"基础握持位到握把握持位"偏移。
4. **肘**：基础肘先随锁骨带动，再绕新的肩腕轴转过"权重 × 握把肘的摆角"；摆角以带动后的基础肘为参照。两骨 IK，骨长不变。
5. **掌心滚转**：沿用 ArmHinge55 的解剖框架。新的总滚转取最接近"基础总滚转 + 权重 × 参考对的差值"的一支，不会整圈翻转。前臂上限内那一份的变化加到前臂各站，超出的部分加到上臂滚转。基础手臂原有的分配（含平滑）保持不变，所以权重为 0 时，得到的就是原来的基础手臂。
6. **手指**：局部旋转在基础和握把参考之间按权重球面插值。

参考对：瞄准类（aim、aim_fire）用"基础 aim ↔ 握把 aim"，其余用"基础 idle ↔ 握把 idle"。

## 第二步：运行时层

- `Source/FPSGAME/Weapons/GripPoseLayer.h/.cpp`：`FGripPoseLayer` 是 `evaluate.py` 的 C++ 移植。`FGripPoseLayerNode` 是动画图节点。
- `FPSGunplayAnimInstance`：在待机、冲刺、瞄准、动作四个通道上各挂一个节点，放在通道混合之前。这样仍按握把播放的 clip（砸击、检视、模式 1 下的换弹）和经过握把层的通道混合时，两边的姿势是一致的。第一版挂在 `FinalizeBoneTransform` 的最终姿势上，混合中途手会偏离握把，所以改掉了。
- `FPSGAMECharacter.cpp`：`DrumPose` 对走握把层的 clip 返回基础版本，并给每个通道设置参考对和开关。模式 2 下冲刺改用基础 clip，砸击一直用各握把自己的 clip。
- 控制台变量 `fps.Weapon.GripLayer`：
  - `0`：全部用原来的握把 clip（回退）。
  - `1`（默认）：第一批（待机、瞄准、腰射、瞄准射击）走握把层。
  - `2`：预览，再加上装备、换弹、冲刺，存在上表列出的过渡问题。
- 握把参考姿势在运行时从握把的 idle／aim clip 第 0 帧读取，所以这两条 clip 要保留。
- 所有握把 clip 都原样保留，没有删除或改动任何动画资产。
- `ForegripAudit` 检查的是"待机播放握把 clip"，模式 1、2 下这条检查会失败。它是开发审计，默认不运行。
