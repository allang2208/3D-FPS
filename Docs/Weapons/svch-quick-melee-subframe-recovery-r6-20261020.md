# SVCH 快速近战收势帧间甩臂 R6

用户指出快速近战即将结束时有手臂短暂从右侧甩入镜头。本次只处理右臂的帧间求值，保持 R5 已制作的动作、V9、左手、枪械、时序、换弹与拉栓。

## 根因

R5 的 120 Hz 整帧采样能看到正常姿态，但共享 SVD 基础动画的压缩轨道在原第 67 与 68 帧之间存在快速旋转。原 Profile 只有 120 Hz 的差量关键帧，基础轨道和差量分别插值，不能在两帧之间维持作者预期的抵消。

读取 UE 的 COMPRESSED 姿态后，在源时间 0.5625 秒（67.5 / 120）复现右掌相对预期路径约 27.36 cm 的偏移，肘位约 11.9 cm。此前只取整数帧的动画图诊断因此漏检。这不是已认可的手模或手指尺寸问题，也不是新增加的一套动作。

## 修复边界

仅重编码五套 SVCH Profile 中快速近战的右侧 27 条轨道。保留原来的 120 Hz 作者关键帧，54–90 帧之间按 960 Hz 编码；非线性最强的 66–70 帧局部按 7680 Hz 编码。使用 UE 实际压缩源计算差量，不再假定基础动画在相邻 120 Hz 样本之间按同一条路径插值。

复查采用不参与制作的中间采样：普通窗口 1920 Hz，狭窄窗口 15360 Hz。所有目标仍保持原样，不改变播放速度，也不增加运行时求解器。左侧和枪械 Profile 轨道逐值保留，其他动作条目不写入。共享 SVD 动画、V9 网格、权重和修形不修改。

第一轮 960 Hz 候选虽然消除了大幅甩动，中间采样仍有约 5 mm 的掌位残差，未接入；最终局部补点版以 `dense-check.json` 为准。

## 保存后结果

五套 Profile 已后台保存并复读，文件哈希与保存回执一致。独立帧间复查中，右掌最大偏移从 27.36096 cm 降至 0.008203 cm（0.08203 mm）；整条右侧链的最坏中点位置误差为 0.013312 cm。左手与枪械矩阵差异为零。

原有 120 Hz 真实 Gunplay 图共 550 次采样的全骨骼位置最大差异约 0.000101 cm，朝向约 0.000240°。换弹、拉栓等非快速近战条目与原资产逐项一致。帧间前后对比图已在同一相机、同一源时刻重建，旧版右手扫入屏幕右上方，新版保持握持。

## 入口与证据

目录：`SourceAssets/SVCHReplacement20261018/QuickMeleeRecoveryR6_20261020/`。

- `export_compressed_dense.py` / `export_compressed_window.py`：UE 后台只读源采样。
- `author_subframes.py`：对 R5 同一套动作重新编码，不重新设计肩肘或手形。
- `check_dense.py`：浮点轨道量化、实际差量插值、独立中点采样及原关键帧保留检查。
- `install_profiles.py`、`install_receipt.json`、`SavedReadback/`：带冲突保护的保存和复读。
- `prepare_subframes.py` / `Review/`：实际压缩源与差量层的离线表面重建，展示之前被遗漏的 67.25 / 67.5 / 67.75 帧。
- `native-saved-glove.json`：保留既有 120 Hz Gunplay 图诊断，用于确认接入与原关键帧不回退；它本身不能证明帧间问题已修复。

可编辑动作母版仍是 R5 的 `SVCH_QuickMeleeElbowR5_ReloadGrip_Editable.blend`，因为本轮未改变该动作，只修正共享基础动画加差量的运行时表示。新 Profile 源数据保存在本目录 `Profiles/`。

不启动游戏或新的交互编辑器。离线重建和后台求值不是用户实机视觉验收，第三人称与联机不在本轮测试范围。
