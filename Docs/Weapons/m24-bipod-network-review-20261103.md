# M24 脚架联机复查

复查上一轮支撑判定和镜头限位修复，重点检查请求身份、回执顺序、服务器资格及远端表现。上一轮 58 项是单进程临时世界检查，不是实际客户端／服务器传输验收。

## 已发现并修复的源码问题

1. **请求缺少武器实例身份。** 原 `ServerDeploy` 仅传落点和朝向，服务器维持条件只比较枪型。切换装备后到达的旧请求可能被套到当前武器。请求和复制状态增加 `WeaponInstance`，接受时按影子档案中的实际实例匹配；维持状态同时比较枪型和实例，拥有者回执也校验当前实例。
2. **RPC 确认与属性复制共用同一份客户端状态。** 原 `ClientDeploymentResult` 改写 `NetDeployment`；随后到达的旧属性更新会覆盖它，即使 `OnRep` 丢弃旧序号，加成仍读取被覆盖的字段。现把拥有者已确认状态单独保存；RPC 与 `OnRep` 共用序号／实例过滤，旧属性不再撤销新确认。已解除的一代不能被迟到接受重新激活。
3. **服务器只检查 M24 是否装有脚架。** PKM／LMG201 原先只按型号判断。现在三枪均检查规范化的脚架槽位，生产工具占手时拒绝开始／维持架枪。没有改动各枪的脚架安装选项或属性数值。

## 已阅读的联机路径

- 请求由角色的复制组件发起，落点由服务器碰撞重新解析，不接收客户端的组件指针。
- 取消请求沿可靠 RPC 和递增序号处理，服务器解除同时通过复制与拥有者回执发布。
- `FPSCharacterMovementComponent` 保存／重放架枪意图；服务器批准状态独立限制移动，断流看门狗会清理 ADS 意图。
- 武器切换、菜单、动作中断均已有解除入口；本次实例绑定覆盖这些操作与部署请求交错的情况。
- 第三人称设备采集递归包含脚架底座、两条支腿，M24 部件按稳定标识排序；机械变换经现有身体姿态通道发送。服务器会丢弃已解除状态的架枪接触样本。此为源码核对，未作为远端画面验收。
- M24 射击仍采用现有客户端弹道、服务器命中复核和弹药账本。后坐与散布在拥有者获确认后计算；本轮没有将通用枪械链路重写成服务器发射模拟。不能在命中到达时直接用“当前是否正在收架”拒绝射击，否则会误拒已经发射、稍后才命中的弹丸。
