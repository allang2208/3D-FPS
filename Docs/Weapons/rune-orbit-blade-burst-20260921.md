## 代码排查与修复

| 问题 | 原因 | 本轮修改 |
| --- | --- | --- |
| 身体普通命中错误获得弱点暴击 | `MagicHit` 最后一个布尔参数误传 `Hit.bBlockingHit` | 改为共享的 `ColdSteelSkills::IsCriticalHit(Hit)`，通过 `ApplyPointDamage` 保留命中点、骨骼和方向 |
| 快速按 G 丢发射次数 | `bQueuedLaunch` 只能记一个请求；每发都等待完整手势结束 | 按剩余可发射剑数限制的整数队列，触发接触帧才扣次数 |
| 连发重复收手和推掌 | 缺少延长既有释放手势的入口 | 新增 `ContinueSpellRelease`，只延长当前手势的停留，不重置起势和推掌时钟 |
| 最后一发近距离命中截断停留 | 自然结束飞剑阵列也调用 `CancelSpellGesture` | 自然结束保留最后一次停留/恢复；切换武器、死亡、超时仍取消 |
| 命中后剑体僵停 0.3 秒 | `bFinished` 使 Tick 提前返回，命中时设置的 fade 无法执行 | 接触帧隐藏完整剑体，生成蓝色晶体碎片 |
| 低帧率多飞出一帧射程 | 先扫完整移动步长，再判断射程 | 将扫描步长裁到剩余射程 |
| 新一次召唤改写之前在途飞剑的属性 | 飞行/命中动态读取组件范围和易伤层数 | 每把飞剑 Setup 时保存该次召唤的射程、易伤层数 |
| 阵列无效时仍可保留请求 | 先处理队列再判断装备；未激活时 EndOrbit 不清队列 | 输入、接触与 Tick 均走装备/死亡/菜单/翻越/建造约束，EndOrbit 无条件清请求 |
| 普通剑击的“全部冷却 -0.5 秒”遗漏 G | G 冷却仅存在组件，统一减冷却函数只改 Profile | 统一函数转发 `ReduceCooldown`；飞剑击杀取消重复的单独扣减 |
| 连发被已经死亡的目标消耗 | 扫描命中尸体后直接消耗飞剑 | 沿用冰锥的有界尸体忽略扫描，活目标和墙仍阻挡 |

旧项目原始合同比对：`E:/无尽轮回/长期备份/2026-7-13-1/game-dev/src/entities/components/rune-sword-system.js`。保留基础 4 把、30 秒存续、15 秒结束冷却、随机选择剩余飞剑、`floor((武器攻击+魔法攻击)*1.2)`、击杀减少正在运行的技能冷却 0.5 秒。没有把飞剑阵列尚未结束时的击杀累积成未来冷却折扣，原项目同样只减已经开始的冷却。

## 手势

- 复用现有 V9 推掌与完整腕臂骨段，不修改已修复的手腕、前臂姿态。
- 第一次发射仍在推掌接触帧执行。最短连发间隔 0.10 秒；每次 G 最多对应一把剑。
- 已伸掌时继续发射，不重播起势和推掌；每发叠加短促整臂回震，旧回震自然消退，避免中途重置跳动。
- 最后一发之后停留至少 0.30 秒，再执行原 0.50 秒恢复曲线。连发会延长总动作时间。
- 队列耗尽不占用额外请求；超过剩余剑数的输入不累积到下一次召唤。
