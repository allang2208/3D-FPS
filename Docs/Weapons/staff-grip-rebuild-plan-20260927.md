## 1. 当前实现的差别与失误

| 项目 | 当前握弓的实现 | 当前法杖的实现及影响 |
| --- | --- | --- |
| 抓握输入 | ContactV9 作者读取 GripV5/grasp_native.json，保留完整左手腕关系及掌骨、四指、拇指局部变换 | 闭合供体转为变形旋转后，各指节再乘独立 opening 系数；整手闭合关系被拆开 |
| 接触目标 | 握弓手整体适配真实握把；勾弦手另取实际指腹区域处理 | V10 对每个手指／掌部主要用径向表面距离的最小值；某个点靠近杖身不等于整个指腹包握，避穿模的解可能偏松 |
| 腕臂姿态 | 独立 V7 弓手臂、完整烘焙动作；运行时在已有动作基础上局部混合、保持接触 | StaffArmsMeshComponent 每帧从 RefComponent 重建，分别求手、前臂和肩肘；作者输出的 LowerRotation 也没有直接作为运行时基础姿态使用 |
| 表面问题 | 弓曾独立处理掌面开口／翻折，再拟合接触；同类修补随后写入共享 V7 | 前几轮法杖集中改旋转和支撑，没有针对当前扭曲区区分形变、权重、拓扑和法线来源 |
| 认可范围 | 本次用户明确选择握弓作为参照 | 用户只认可 V10 方向；V11 却冻结了四指，错误保留了尚未认可的闭合程度 |

上表是源码和制作链的差异，不能单凭这些差异认定所有可见扭曲都由同一原因造成。腕轴夹角从约 20° 降到约 5°，并不能说明扭转分布、虎口形态和腕部蒙皮已经正常。

弓配置目前指向 ContactV9 手模、ElasticV15 动作；旧 V9 文档中的动作目录已不是全部当前动作。握弓指的是承力的左手闭合抓握，不是右手三指勾弦，也不是快速近战右手张掌。

另一个交付边界：V11 只有当前编辑器会话的成功热补丁记录，常规基础 DLL 尚未重编；后续正式交付必须包含常规构建，明确展示的是哪个姿态版本。

## 3. 制作顺序与交付物

### 阶段 A：建立同一空间中的握弓对照

读取当前握弓 Idle／Ready 的完整承力左臂和对应变形表面，包括肩、肘、前臂、辅助骨、腕、掌骨、五指及 bow_grip。使用实际引用的 ElasticV15 作者链与 ContactV9 手模，不从旧文件名猜当前版本。

把骨架参考姿态、单位、轴向、表面与蒙皮对应关系整理为一个冻结输入包。法杖加载的是 M4 原生派生，弓是专用单位缩放骨架；不能直接复制四元数或镜像 UE 资产。左握弓转右握杖时，在左右手各自原生解剖空间映射，再恢复目标局部矩阵，避免负比例镜像。

产物：握弓完整参考姿态、右手完整闭合初姿、相机／掌向／杖轴／握点关系图和当前加载版本记录。方案中的图和视觉核对作为后续用户指定的预览交付，不在本轮自动生成。

### 阶段 B：先做好右手真正包紧杖身

以握弓的完整闭合抓握为起点，整体调整右手朝向与握点，再有限适配法杖真实截面。不能直接采用弓的握把尺寸或把每节统一乘同一系数。

接触区域分别定义为掌心支撑区、四指指腹带、拇指指腹及虎口留量。使用有明确解剖身份的表面区域，联合限制接触面积、间隙、各节连续弧线及局部相交；不再以整根手指的单个最近点判断握紧。

四指形成连续包裹弧线，指根与掌骨参与，指尖自然回收。拇指扣住食指附近的可达区域，不能为了绕过杖身强行扭根，也不能把拇指放松到失去对握。允许按真实厚度保留合理间隙，闭合程度由可见形态决定。

逐一使用当前可替换握柄的真实表面建立接触适配；不用所有握柄的统一最大半径让较细型号也保持松握。若实际局部截面无法容纳自然包握，先明确几何冲突和可用握持区域，再决定是否提出局部握区尺寸调整，不擅自缩放整个武器。

产物：一套完整的右手握杖母姿态及各握柄最小必要差异。暂不扩展动态动作，把基础握紧形态先收敛。

### 阶段 C：让肩肘与前臂支撑这只手

在完整握紧姿态上同时处理肩、肘、前臂、腕和辅助骨。分别看腕部弯折、前臂轴向旋转、肘部弯曲平面，避免把三者混为一个角度目标。

参考握弓的腕部修正方法：固定手与杖接触，沿手的中性支撑方向反解前臂和肘，用最小必要肩移满足原骨长；保留自然的小幅腕角，不强制追求 0° 或照抄弓案例的 12°。

整条链先计算完成，再按父子关系重建局部矩阵。完整辅助骨跟随对应骨段，不能给已经旋转的父骨再次叠加累计分数扭角。掌向、相机空间和实际腕背轮廓共同决定姿态。

产物：肩到指尖的完整待机姿态，包含全部相关骨骼，而不只是 HandRotation、Shoulder、Elbow 三组参数。

### 阶段 D：只处理确实存在的局部表面问题

在统一姿态下区分：骨骼扭转导致的收缩、跨关节权重拉扯、掌面开口／翻折、法线形成的假折痕。共享 V7 已有掌面修补记录，不能先假定当前问题是“没有补洞”。

姿态正确后仍存在的缺陷才进入局部表面修正。若涉及权重，只处理对应的腕环／虎口区域并保留边界连续；若涉及拓扑，使用握弓已有的局部修补方法并保留 UV／法线接缝。先落在长杖专用派生，不覆盖其他已认可武器手模，不增加双面材质掩盖翻折。

产物：必要时提供长杖专用 V7 派生及局部修改记录；没有表面缺陷证据则不改模型。

### 阶段 E：采用完整姿态驱动，再恢复动态层

推荐采用与握弓一致的“完整作者姿态／动画 + 运行时轻量叠加”结构。建立长杖专用可编辑源，保存完整肩臂、辅助骨、手掌和手指轨道；握点标记放在右手接触链中。

StaffArmsMeshComponent 从完整基础姿态求值，停止每帧从参考姿态重新拼一只手。运行时保留必要的移动叠加和小范围接触修正，不把作者前臂旋转替换成另一套独立猜测。

武器时钟、完整姿态、握点及杖尖使用同一采样结果；明确先采样姿态、再更新法杖与发射／命中相关位置的顺序。原魔法阶段、消耗和发射时点保留，不能混用上一帧骨骼位置与当前帧施法轨迹。

制作次序为：待机 → 行走 → 奔跑 → 举杖蓄力 → 向前释放 → 收回／取消 → 装备与近战相邻状态。静态基础收敛后才展开动态，避免把错误手型烘进整套动作。

行走以小幅肩肘随动为主；奔跑有明确摆幅、节奏和持杖位置区别；握紧的手指不通过开合制造移动感。施法推动整条手臂和杖身，避免只掰腕骨。

## 4. 用户判断效果的标准

1. 镜头仍看到已认可的右手背面，握持方向没有倒回去。
2. 掌心、四指和拇指形成明确包握，呈现有承重的握紧感，不是空心搭住或指尖捏住。
3. 从手背到前臂轮廓连续，腕处没有绞细、鼓包、尖折或异常凹槽；虎口与指根不过度挤压。
4. 行走、奔跑和施法时，手与杖同步，指腹不滑脱；动态腕部形态不明显劣于待机。
5. 不同握柄都保持合理闭合，配置切换不把某一种握柄的松紧错误传播给全部型号。

这些是后续用户预览／测试的判定内容。本轮只制定方案；依用户规则，不自动运行游戏、截图、渲染或回归。编译结果、姿态数学指标和用户视觉认可分别记录。
