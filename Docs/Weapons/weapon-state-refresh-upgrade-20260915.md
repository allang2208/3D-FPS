# 武器状态刷新升级计划与实施记录

## 目标

自动保存、击杀奖励和属性更新不打断正在进行的射击与换弹；单持和双持各自持有输入与弹药状态，实际换装才交接动作。承接 `automatic-fire-profile-interruption-20260915.md` 的止血修复。

## 实施计划

1. 分离持久化与角色应用：`SaveNow` 捕获运行状态后只保存；装备、属性、补弹等事务仍保存成功后应用角色。保留 A/B 存档、代际编号、校验和失败不提交规则。
2. 明确换装边界：按主手实例、定义、可用状态及双持组合判断切换；先结束旧控制器，再绑定新视模。移除双持退出时递归调用角色档案应用的流程。同一组合刷新保留触发边沿、射击截止时间、换弹时钟和音效事件。
3. 划分输入所有权：角色只保存单持开火输入；双持只保存两只手各自的输入。移动等公共逻辑通过查询当前控制器读取是否按住射击，双持不再写角色的单持开火标志。
4. 按变化应用配件：角色缓存已应用的配件组合，重复刷新不重装相同配件；枪匠预览、撤销、关闭共用同一入口，重建视模时失效缓存。属性重新计算继续以基础值为起点，不改变正在播放动作的时钟。
5. 弹药按当前控制器同步：双持由两只手按物品实例写回，单持由角色写回；不再先写双持主手再用角色显示缓存覆盖。命中回调可能同步触发击杀/修炼事务，发射扣弹必须先于这些回调。
6. 完成正式模块构建并记录结果，交由用户测试。

## 范围

保留步枪按住连射、手枪单次按压一发、双持左右键独立点射、换弹接触结算、施法占用和菜单/翻越/死亡的现有规则。保留原射速计算及自动保存间隔。本轮不改存档格式或引入异步保存。

## 交付状态

上述 1–6 项已实施并完成必要构建。

| 场景 | 当前代码处理 |
| --- | --- |
| 自动/手动保存当前运行状态 | 同步状态、执行现有存档事务、发布档案/UI；不重新应用角色 |
| 击杀奖励、修炼升级、属性或补弹事务 | 保存成功后应用数值；同一装备不重置触发输入、射击截止时间或动作时钟 |
| 单持与双持之间切换，或双持任一武器实例/定义变化 | 角色统一释放旧输入、退出旧双持状态，再绑定新装备；取消递归应用 |
| 枪匠预览、撤销与关闭 | 共用配件缓存入口，按变化槽位设置；重建视模时重置缓存 |
| 双持命中触发同步奖励 | 发射扣弹与运行库存同步在前，两只手的数据各自写回；不使用主手显示缓存覆盖 |
