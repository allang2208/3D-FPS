# M16 复用当前 M4 插匣动作

> 当前发布与本机恢复顺序见 [M16 发布记录](m16-publication-20260920.md)。下文保留本阶段制作历史，最终动作来自 M16RemovalMelee，枪托来自 M16RecoveryStocks；用户已确认最新修复成功。

本轮按用户要求直接移植当前 M4 的取匣／对准／插入／松手片段，重新匹配 M16 弹匣和弹匣井；保留已有空仓拉机柄动作。此文接续 `m16-refinement-20260920.md` 的换弹部分。

## 定位结果

- 实际 M4 普通、扩容弹匣分支加载 `ExtMagContact20260919/A_M4_ExtContact_reload` 和 `A_M4_ExtContact_reload_empty`。作者源和 UE 资产的导入来源已读取。
- 原 M16 普通换弹仍来自 `M4_HK416_reload` 的旧弹匣旋转轨迹。上轮 `M16Refinement20260920/repair_reload.py` 只重新适配左手，并没有换掉该轨迹，因此不能视为当前 M4 插匣段的直接移植。
- 当前 M4 对准之后是沿枪体局部 Z 方向的直线推进：普通换弹第 76 帧对准、第 95 帧坐实；空仓第 54 帧对准、第 80 帧坐实。M16 本轮沿用这些帧与原 60 FPS 时钟。

## 本轮制作

- 作者脚本：`SourceAssets/M16M4Insert20260920/transplant.py`。
- 直接复用 M4 的完整左臂、腕、指、扭转辅助骨和弹匣轨迹；同步移植该段的枪体及右手承托运动。没有重新解算肘、腕或设计指节弯曲。
- 普通换弹第 30–43 帧在离屏取匣阶段切入 M4，43–108 帧使用当前 M4，108–126 帧衔接原 M16 持枪／配件回握。
- 空仓换弹第 21–35 帧切入 M4，35–88 帧复用插匣；88–111 帧使用当前 M4 普通换弹的释放回握进行衔接。第 111–162 帧逐帧保留上一版 M16 的全部姿态，包含既有右手拉机柄及机械部件。没有移入 M4 空仓拍击尾段。
- 弹匣相对枪体的装配终点取自原生 `M16_idle`。移植前先除去 M4 自身的装匣变换，再应用 M16 装匣变换；不直接把两个不同枪型的弹匣骨骼位置相减。
- 对齐后保留直线入井，坐实后固定为 M16 原生装匣位置，去掉旧轨迹在井内的转动与漂移。
- 接触位置按实际金属弹匣外壳调整。完整左臂在枪体坐标内平移 `(-12.0794, -9.6143, -20.0) mm`，该偏移随 M4 已有的抓握／释放窗口淡入淡出；不改变任何手指局部旋转、长度或缩放。拇指根部和指尖的相对形状仍来自 M4。
- 覆盖原位的 10 条普通弹匣动画：基础、直立握把、斜握把、棱镜阻手器、倾斜握把五组各普通／空仓两条。原来的弹鼓动作及非换弹资产不在本次修改范围。

## 资产与接入

可编辑 `.blend` 和导入 `.fbx` 位于 `SourceAssets/M16M4Insert20260920/Animations/<family>/`，清单为 `transplant.json`。基础动画保留 `Gameplay20260919/Animations` 路径，四组配件动画保留 `UniversalAttachments20260920/Animations/<family>` 路径，因此现有运行分支无须新增 C++ 路由。

只运行本目录的 `install.py` 导入上述十条动画，120 Hz 采样，沿用 `BC_M4Viewmodel` 压缩设置。导入记录见 `installation.json`，替换前资产已归档到本机 `trash/m16-retired-20260920/SourceAssets/M16M4Insert20260920/PreviousAssets/`。本轮 Blend 是后续 M16RemovalMelee 的输入，最终运行输出使用后者；前一轮 `repair_reload.py` 会恢复旧的“只改手、保留旧弹匣轨迹”方案，不应再作为最终来源。

按用户要求实际查看了 M4 源模型的插入关键姿态，并针对 M16 的手、弹匣、弹匣井做了局部源模型检查。未启动 PIE 或游戏回归；源模型视图不代表游戏视角验收，实机效果由用户测试。
