# 法杖两段施法：右肘扭转定位与修复

此前枪械锁子甲排查没有覆盖法杖。用户报告法杖发射时右肘异常后，本轮读取实际法杖加载路径、姿态表、共享父组件及衣物配置，并对抬杖凝聚、独立发射准备、发射/停留、收势进行定向离线比较。

## 定位结果

问题存在于**法杖源整臂姿态**，脱掉锁子甲不会消除该源姿态中的异常。法杖使用 `UStaffArmsMeshComponent`、编入 C++ 的完整局部姿态及独立动作时钟，不播放此前排查的枪械换弹动画。初始化没有给法杖手模安装 `UFPSGunplayAnimInstance`，因此此前以该 AnimInstance 为门槛的 `FPSOutfitArmClearance` 不处理这只手臂。

法杖原 V13 的 `support()` 将上臂旋转从握弓供体推导，而前臂旋转另按当前手掌横向建立；保证了肩肘腕位置和骨长，却没有协调两段的轴向关系。抬杖与发射键的该差异明显高于本握柄待机。辅助骨虽然完整跟随各自骨段，肘部跨段权重仍会被两段之间的旋转差压扁。

默认握柄的轴向差诊断量：待机约 **55.46°**，抬杖 **104.57°**，发射接触 **120.66°**，收势起点 **124.32°**。这是按原生绑定运输后测得的骨段变形差，不是人体关节角度。合金握柄略有差异，松木与檀木握柄复用同一握姿关系。

锁子甲配置把法杖 V7 手模注册为 M4 原生骨架 profile，衣袖和裸臂共享源姿态；裸臂和锁子甲都存在受上臂/前臂共同影响的肘部顶点，故两者都会继承这一问题。

## 已制作的修复

- 保留 V13 已接受的掌向、各握柄指部接触、待机/跑姿及 V28 普攻；只重新制作 Raised、Windup、Release、Follow 四个施法键，覆盖四种握柄。
- 以各握柄待机的轴向关系作为本动作基准，把多出的轴向旋转分配到上臂与前臂。上臂约修正 23–34°，前臂约 39–43°；不是照搬其他武器的固定纠正角。
- 根据实际骨骼站位与权重，让肘侧 `upperarm_twist_02_r`、`lowerarm_twist_02_r` 完整跟随对应骨段的修正。肩侧 `upperarm_twist_01_r`、腕侧 `lowerarm_twist_01_r` 保持原组件空间变换，防止把扭转集中转移到肩口或腕口。
- 作者关键帧的肩、肘、腕位置、手和手指矩阵保持原值；重新计算父空间补偿，让运行时继续按完整局部姿态混合。衣袖沿用共享 Leader Pose，没有单独挪衣袖或改权重。
- 运行时改为读取 `StaffAuthoredCastElbow20260930.h`，缓存版本同步更新。动作时间、杖尖路径、发射时点、特效和副手逻辑保持原入口；未新增逐帧求解、Tick 或资产加载。

## 本轮离线结果

比较范围：四种握柄，静止默认构图，抬杖 0.95 s、凝聚收势 0.42 s、独立发射准备 0.20 s、发射/停留 0.38 s、发射收势 0.42 s，120 Hz 加关键时点，共 **1176 个样本**。裸臂使用实际 V7 作者表面/权重；锁子甲使用已保存的当前 M4 渲染 LOD0/1/2，资产散列与快照一致。姿态 JSON 与前后 C++ 生成表的数值差小于 1.4e-10。

默认握柄代表结果：

| 区间/诊断量 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 发射阶段最大轴向差 | 124.32° | 55.46° |
| 裸臂肘部混合权重压缩指标 P10 | 0.449 | 0.686 |
| 锁子甲肘部混合权重压缩指标 P10 | 0.449 | 0.686 |
| 裸臂发射区间最大局部边长倍率 | 2.938 | 2.570 |
| 锁子甲发射区间最大局部边长倍率 | 2.762 | 2.492 |

压缩指标是蒙皮混合矩阵的最小奇异值，第 10 百分位越接近 1 表示该局部线性映射压缩越少；不是实测直径或体积。边长倍率以原始网格边为分母，不能解读为整臂伸长倍数。抬杖与收势也有改善；三档衣袖 LOD 的本项结果一致。

同一采样时点的修复前后手矩阵差小于 3.2e-14、手指矩阵差小于 4.3e-14，骨长误差小于 2.9e-14 cm，均为数值精度范围。

未运行游戏、PIE 或视觉渲染；没有覆盖全部走跑/副手混合、装备切换、材质摆动或完整衣袖—皮肤—杖体相交检测。上述结果用于确认源姿态缺陷与修复方向，实机轮廓和穿模仍由用户确认。
