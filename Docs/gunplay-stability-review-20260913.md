## 发现与建议

### 1. ADS 高频抖动的 0.45 收束系数未同步

**证据：** Godot `scripts/gun.gd:32` 定义 `JITTER_ADS_MULT = 0.45`，`:517` 用 ADS 进度从 1 过渡到 0.45，之后才把脉冲传给枪械和镜头。UE `FPSGAMECharacter.cpp:1057`、`:1058` 使用 `RecoilLoad × ShakeScale`，缺少该 ADS 系数。

UE 已有额外阻尼、视模位移/角度限制，以及 ADS 下减少噪声的设计；这些不会替代源脉冲收束。因此本项是机制差异，不应以最终画面抖动一定达到某个倍率作为未经运行测量的结论。

**建议优先处理：** 在共用脉冲生成处增加随 ADS 进度平滑过渡的系数，枪械和镜头共用一次缩放。Godot 的 0.45 可作起始值；不要分别在两侧重复乘。保留当前后坐力角度、ADS 姿态限制和弹道规则。

### 2. 旧配件把抖动降低百分比当作稳定性评分提高百分比

**证据：** `WeaponHandling.cpp:11` 至 `:15` 的默认评分公式为：

`q = 抖动指数 / 100`

`回稳时间倍率 = sqrt(clamp(q, 0.25, 4))`

`评分 = 100 / (1 + 0.5 × q + 0.5 × 回稳时间倍率)`

三把步枪基础抖动指数为 100，基准评分 50。下面是直接代入当前公式的结果，不是运行测试数据：

| 配件 | 原文案/数据 | 当前实际评分变化 |
| --- | --- | --- |
| 稳固防滑后握 | 此前写稳定性提高 15%；实际 `shake_mult=0.85` | 50 → 53.0229，约 +6.05% |
| 均衡后握把 | 此前写稳定性提高 10%；实际 `shake_mult=0.9` | 50 → 51.9658，约 +3.93% |
| 枪口制退器 | `shake_mult=0.85`，此前写晃动降低 15% | 约 +6.05% 评分，不能直接改称评分 +15% |
| 钛金制退器 | `shake_mult=0.8` | 约 +8.27% 评分 |
| 骨架枪托 | `shake_mult=1.1` | 约 -3.59% 评分 |
| 轻型短枪管 / 重型长枪管 | `shake_mult=1.15 / 0.85` | 约 -5.27% / +6.05% 评分 |

两款消音器使用新 `stability_mult=1.1 / 1.25`，直接提高评分 10% / 25%，继而反推幅度和恢复时间。M1911 的基础抖动指数为 95，基础评分也不同，不能套用上表步枪的绝对分值。

**本轮已做的文案处理：** 旧倍率统一表述为“枪械稳定性提高/降低（抖动幅度降低/增加 X%）”，明确原百分比的实际对象；两款消音器继续展示评分提高百分比。主汇总继续显示真实计算结果。

**建议：** 若设计意图是所有“枪械稳定性 ±X%”都指评分变化，应统一到一个双向稳定性倍率。旧后握把按其原先承诺的 +15%/+10% 改为对应倍率，并同时移除旧抖动倍率，避免双重加成。其他配件也应逐项确定保留当前手感还是采用原设计百分比，不能只替换字段后默认等价。卡片和详情的数值说明最好从同一计算来源生成，减少手写百分比漂移。

### 3. 新稳定性倍率分支缺少减益处理，满分附近不连续

**证据：** `WeaponHandling.cpp:18` 只在 `StabilityMultiplier > 1` 时处理。若将来填写 0.9 表示降低 10%，该分支会直接忽略。当前目录减益仍使用 `shake_mult`，所以骨架枪托与短枪管的现有减益并没有失效；这是新字段尚未覆盖的方向。

同一函数在目标评分达到 100 时，递归使用零抖动。零抖动路径把 `RecoveryTimeScale` 设为 0.5；在目标评分接近 100 的正抖动路径中，这个值却趋近 0。枪械后坐弹簧仍读取该恢复时间，所以满分处的反馈行为不连续。当前已列入目录的配件组合尚未达到该边界，本轮没有声称在游戏中观察到了该症状。

**建议：** 统一处理倍率大于和小于 1 的情形，明确最大评分和最短实际恢复时间，使评分、零抖动以及枪体后坐恢复在边界处一致。此分支是上一轮消音器接入新增，问题也应在后续修正时一并处理。

### 4. 稳定性的作用范围需要保持清晰

UE 的稳定性已影响开火高频抖动、镜头开火反馈、连射噪声和这些反馈的恢复；它未控制静止呼吸摆动、行走起伏、鼠标转向拖曳、FOV 脉冲、后坐模式重置时间，也不会把控制瞄准点拉回原处。入口见 `FPSGAMECharacter.cpp:697`、`:719`、`:815` 至 `:841` 和 `:1041`。

可恢复的 Godot 归档也将摆动、FOV 与模式恢复单独管理，没有证据把这些一概认定为遗漏。**建议保留当前机制边界并在主属性提示中说明；若以后希望“稳定性”也改善持枪呼吸或移动晃动，应另设受控分项，避免用一个倍率连带修改移动镜头与弹道后坐。**
