# 第三人称六种食物：肘部与拇指表面排查

用户要求逐个排查第三人称食物动作，重点为大羊排双手手臂穿模和拇指扭曲，并确认裸手也有问题。

## 实际分支

| 食物 | 第三人称动作 | 本轮处理 |
| --- | --- | --- |
| 普通面包 | Consume.EatBread | 肘部加权辅助骨；拇指根部内侧皮肤辅助点 |
| 法棍 | Consume.EatBaguette | 肘部加权辅助骨 |
| 烤鸡腿 | Consume.EatBread，按 4.8 秒物品时钟采样 | 肘部加权辅助骨 |
| 烤羊肋排 | Consume.EatBread，按 4.8 秒物品时钟采样 | 肘部加权辅助骨 |
| 烤香肠 | Consume.EatBread | 肘部加权辅助骨 |
| 大份烤羊排 | Consume.EatLargeLamb，原生双手 | 左右肘部加权辅助骨；保留现有原生拇指与双手握点 |

## 定位

肩、肘、腕位置正确不等于蒙皮表面正确。当前 Jason 皮肤还受到 `upperarm_twistCor_02`、`lowerarm_correctiveRoot` 与 `lowerarm_twist_02` 的影响。原生进食作者把这些辅助骨恢复到参考局部姿态，缺少与实际肘弯曲相适配的表面过渡。结果是肘部面片局部折回；此前仅检查主关节与躯干相交，没有覆盖这类臂内翻折。

大羊排已保存片段与制作源相符，压缩的最大局部旋转差约 0.182 度。最终动画图的完整握持阶段保留了原生双手与手指姿态。本轮另外比较后处理开关，所采样输出没有差别，没有据此修改全身后处理蓝图。

普通面包的拇指根内侧发现 3 个折回面片，其权重跨越拇指根、`thumb_01_side_inn_l` 与掌骨。尝试限制拇指轴向旋转并不能消除这处问题，因此未采用该候选；实际修复只微调内侧皮肤辅助点，保留原指骨位置和朝向。大羊排拇指在所采样裸手姿态中未复现表面翻折，不能据此声称已复现用户看到的所有拇指异常。

## 修改位置

- `Source/FPSGAME/Characters/FPSBodyConsumePose.inl`：在原生进食和嘴部 IK 完成后，根据最终上臂／前臂姿态调整肘部加权辅助骨。大羊排处理双侧，其余食物处理进食左臂；饮用不启用此修正。
- `Source/FPSGAME/Characters/FPSPlayerBodyAnimInstance.cpp`：缓存原生辅助骨参考框架；普通面包抓握层完成后，给拇指内侧辅助点增加局部 `(0, 0.1, -0.2)` cm 偏移，随进食层权重淡入淡出。
- 不修改骨架资产、皮肤权重、食物网格、已保存动画、第一人称动作或消耗／音效时钟。修正位于最终第三人称姿态层，避免单手食物后续嘴部 IK 再破坏已烘焙的辅助骨适配。

## 排查与交付记录

制作及证据目录：`SourceAssets/FoodThirdPerson20261017/`。

- `read_assets.py` / `saved_clips_before.json`：当前实际保存的三个进食片段、骨架、标记及压缩姿态。
- `FPSFoodPoseDiagnosis.cpp`：仅显式执行 `fps.body.DiagnoseFood <输出JSON>` 时，在临时 EditorPreview 世界运行真实动画图，不启动游戏、不结算物品、不保存资产。六种食物均采样；大羊排额外覆盖持步枪、持法杖及蹲行，并比较后处理开关。
- `graph_before.json` / `graph_after.json`：真实图输出。最初道具诊断未剥除源手骨导入缩放的试读已单独保留在 `Before/graph_scaled_hand_probe.json`，不作为单手进食接触证据。
- `fit_elbow_helpers.py` / `fit_final_graph.py`：从真实皮肤和最终姿态选择肘部辅助骨过渡；`fit_bread_thumb_pad.py`：拇指内侧辅助点拟合。
- 修复后的构建、接触不变性、表面翻折和穿模复查结果，以同目录最终回执为准。

本轮检查针对裸手网格和指定的动画图输入。未启动游戏或 PIE，未进行网络双客户端或所有装备组合验收；最终游戏画面与自然度由用户确认。

大羊排额外的蹲行输入中双肘也为 0。简化持步枪／持法杖输入的可见食物握持段已修正；低权重起止仍有基础库姿态的肘部折面。该诊断没有注入完整的实时武器接触表，不能用这些简化输入判定实际装备交接是否仍有问题，也不据此扩改持枪／持杖待机。

`geometry_final.json` 与大羊排的 `geometry_after.json` 记录进食手臂对躯干表面的定向相交检查。单手食物只输入实时进食左手，未重现完整的右手装备抓握，其右侧相交计数不能用于判定实际装备状态；大羊排输入并检查两手。最终交付汇总为 `delivery.json`。
