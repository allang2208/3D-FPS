结论
这次补上了前几轮缺失的逐资源 WDDM 证据：
1. 一个普通 DEFAULT 32 MiB 父堆，包含三份已对应到具体怪物的 Morph 输出，以及
   十份 SkinCachePositions、四份 SkinCacheTangents，在采集开始和结束 rundown 中
   都报告于该适配器的非本地内存段。它不是误建的 UPLOAD/READBACK 堆。
2. 另一个包含毛发插值/变形缓冲的 32 MiB 堆，在记录内部从本地段迁出；随后同次
   记录的 Hair 范围从约 2.12 ms/帧增至 7.78 ms/帧。
3. 本次 34 次生成中 29 次命中准备实例，但随后仍持续低帧。下一步应转向热缓冲的
   父堆驻留/优先级及本地工作集管理；继续增加刷怪池不能解决已存在角色的慢访问。

已证实的是资源放置和迁移机制，并获得同次时间关联；还没有通过定向修正对照证明
全部帧损失由此产生，也没有证明操作系统/驱动的哪条策略导致了最初降级。
不把“发现异常机制”写成“已经修复”，不把两个非等价运行的差值写成优化收益。

三个 Morph 输出，current/previous 可能别名，不能算成六份：

- BP_FacelessResearcher_C_9.CharacterMesh0，native 0x1cc445f1270，2874992 字节。

链路为 buffers.jsonl 原生资源身份 → D3D12 Resource.pHeap → Heap.hKMAllocation
→ 同 PID DeviceAllocation.hThunkAllocation → VidMm 全局分配/进程分配
→ ReportCommittedAllocation.ulSegmentId → 同 adapter ReportSegment。
上述资源宽度与观察一致，GPU VA 观察稳定，无本轮 Resource Start/Stop；堆和内核
分配也有一致的开始/结束 rundown，未见本轮创建/销毁边界。

该堆在 ETL 0.033165 秒和 16.896578 秒的 ReportCommittedAllocation 都为 segment 3。
同适配器 ReportSegment：segment 2 的 MemorySegmentGroup=0、Flags=0x92c10；
segment 3 的 MemorySegmentGroup=1、Flags=0x101194（含 NonLocalBudgetGroup）。
因此它被报告为非本地，而其余七个稳定 Morph 输出父堆在两个端点均为本地 segment 2。
总计 19 个稳定 Morph 输出关联到八个 32 MiB 父堆；父堆为共享空间，不能按每个输出
重复计算整堆内存。

这个非本地堆还含十份 SkinCachePositions、四份 SkinCacheTangents；17 个稳定子资源
宽度合计 33027264 字节。只有上述三个 Morph 有直接组件身份，其他缓冲不能仅凭
名字分配给某只怪。原始名称也不是逐 dispatch 的绑定元数据。

ETL 2.203014–2.204636 秒有同一全局分配的三条 MigrateAllocation Info、一条
Status=0xc0000001 的 Stop，随后 segment 3 SysmemUncommit / Evict / segment 3
SysmemCommit / PageIn。它不支持“这次成功搬回了本地显存”的说法。
端点报告不是逐页全时段驻留图；但已不再只是总显存使用量或 UE resident 标志。

六、下一步的具体方向
1. 优先处理已证实的热点可写缓冲父堆驻留，覆盖 Morph、SkinCache、相关 Hair 输出。
   以有上限、可关闭、按有效生命周期释放的父堆优先级/分池修正作为首个候选；
   不把整个工程所有资源统一提到最高优先级，不把放大刷怪准备池作为本问题修复。
2. 本机 D3D12PoolAllocator.cpp:144 起只对 BVH 初始访问的 GPU-only 池显式提 HIGH；
   D3D12TransientResourceAllocator.cpp:75 已给 transient heap 提 HIGH。
   D3D12Adapter.cpp:2258 为 SetResidencyPriority 的实际实现。这些是下一步源码入口；
   NORMAL 热池与其他高优先级池的竞争值得定向处理，但源码路径本身不是完整根因证明。
3. 工程目前使用的公共 ID3D12DynamicRHI 接口可取 resource，不能直接取 placed resource
   的父堆。实现必须在正确 RHI/分配层获得真实父堆；不能用 ETL 历史地址当运行指针，
   不能对 placed 子资源直接套 MakeResident，也不能靠私有结构偏移补丁。
4. 同时按实际拥有者减少当前场景不需要的常驻资源，为本地工作集留下余量；应先拿到
   可释放拥有者，再修改生命周期，不机械删除资源或强制每帧 GC。已修过的备用武器
   候选持有、准备队列、退出释放不重复当作新修复。
5. 用户目前无需重录、改驱动或降画质。修正有明确可切换构建后，再由用户做一次同
   场景/同负载的开关对照：同时看热堆是否回到本地、Morph/Hair 范围及帧时间。
   若只位置改变而耗时不变，再定向补硬件执行/等待证据；不先扩大通用采集。
