四、实际 GPU 链路与排除范围
本机引擎：E:/Program Files (x86)/UE_5.8，UE 5.8.3。
Engine/Source/Runtime/Engine/Private/SkeletalRenderGPUSkin.cpp：
- FMorphVertexBuffer 是每实例、每 LOD 的输出，24 字节/顶点；GPU 路径为 Static + UAV。
- 研究员 LOD0 为 119791 顶点（2874984 字节）；接待员 162110 顶点（3890640 字节）。
- UpdateMorphVertexBufferGPU：清零 -> Scatter 原子累加 -> UAV 屏障 -> Normalize -> 读取状态。
- FGPUMorphNormalizeCS 仅绑定该输出 UAV、PositionScale、NumVertices。
  参数函数虽然接收 MorphTargetVertexInfoBuffers，但不会绑定或读取共享压缩输入。
- Normalize 调度为该 LOD 顶点数 / 64 向上取整，没有把全部已保存 Morph 数乘进调度量。
- MorphUpdateNormalize scope 在 UAV 屏障前开始，因此包含屏障及状态转换开销。
- 输出池不会因正常每帧权重更新就重新 InitRHI；SkinCache 正常路径不要求输出双缓冲。

Engine/Shaders/Private/MorphTargets.usf：
- Normalize 每顶点读取 6 个 uint，转换/缩放，写回 6 个 float 位型。
- 相同网格快慢两组的明显差异不能仅用 Normalize 固定算术工作量解释。

D3D12RHI 的 Buffer/Allocation/PoolAllocator/DescriptorCache/Resources 源码：
- 上述 Static UAV 走 DEFAULT heap；没有找到误放入 UPLOAD heap 的证据。
- 可变状态 UAV 用 placed resource；其驻留按 backing heap 跟踪。
- 普通和 bindless 的 UAV/SRV 绑定路径均有 UpdateResidency。
- 资源池搬移会通知拥有者并延迟旧分配释放；没有证明该路径遗漏引用更新。
- 旧详细 trace 的慢 Morph 位于已提交 Graphics command list 的 GPUWork 内；
  已覆盖队列数据不支持简单 CPU 提交空洞或前置驻留栅栏解释。
以上没有排除硬件缺页、驱动内部迁移、命令执行中的抢占或屏障等待。

因此，现阶段不实施 CPU Morph 全局切换、降低 LOD、删曲线、降低更新率、关闭 RT/阴影、
强制提升所有缓冲驻留优先级或改写全局 UAV 屏障。它们缺少定因依据，且可能改变画质
或把压力转移到其他资源。现有数据支持继续查输出 UAV，不支持宣称主因已确认。
