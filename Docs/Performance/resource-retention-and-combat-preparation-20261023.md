# 常驻引用释放与战斗首次使用准备（2026-10-23）

按用户授权完成源码修改和后台常规构建；保持画质、怪物数量、战斗规则，不启动 UE/游戏，不执行测试。没有重新采样，因此本次不报告显存下降量、帧率提升或长帧消除比例。

## 资源持有范围

| 路径/拥有者 | 原问题或已有边界 | 本次处理 |
|---|---|---|
| `FPSBodyAssetPreloader` 的 `heads` 目录遍历 | 将所有头型、发型、绑定和材质路径塞进 GameInstance 长期预加载句柄；实际只显示一种外观 | 去掉整目录启动常驻。沿用 `ApplyAppearance` 已有的按选定头型/发型异步加载、请求版本判定和组件接管引用；身体、动作、服装和库存的原准备路径保留 |
| `FPlayerSkillRenderPreparation::WarmHost` | 完成的隐藏 Niagara、网格、贴花代表组件留到换图；真实技能创建另外的组件，不复用这些缓冲 | 每项准备成功后移除 Actor 的实例组件引用并销毁代表组件；失败和换资源时同样释放。共享小型宿主仍随准备器销毁，无强制 GC 或 GPU 等待 |
| `FPlayerSkillPreparation::Residents` | 资源句柄跨换图累积，只增加，不按新一轮技能/装备需求清理 | 句柄改为按资源路径持有。新一轮所有作业收集、准备和绑定完成后，释放不在当前作业/消费者路径集合中的旧句柄，并移除相应缓存标记；下一次需要时重新异步请求 |
| 实际技能组件、龙息实例和重击效果池 | 属于真实可复用运行对象，仍有使用者 | 保留；不销毁、停用或改变特效 |
| 地牢已生成房间、仍可能出场的怪物候选、当前动作 | 实际 Actor 或未来合法生成路径仍需要 | 保留。远处隐藏不等于无需资源；本次不通过卸载仍被使用的房间网格制造空洞或改变怪物替补规则 |
| 旧武器字面量候选表 | 已默认关闭的历史修复 | 保留原修复，不重复扩大预加载 |

释放的是本系统不再需要的持有关系和临时渲染组件。若还有真实对象引用同一资产，资产会继续存在；本次不强制卸载共享资产、不清空引擎资源池、不降低纹理质量。

技能资源集合在新世界准备完成时收敛，不宣称每次换装都立刻卸载所有旧资产。上一轮仍在用的资源会保留到新一轮消费者绑定完成，避免在换图和加载中间丢失资产。

## 首次使用准备覆盖表

| 路径 | 本次接入 | 运行边界 |
|---|---|---|
| 选中怪物的硬引用 Niagara/Cascade | 从类默认对象和原生组件属性收集，按资产去重 | 不启动攻击、不生成隐藏怪物、不运行粒子模拟 |
| 选中怪物的软引用特效 | 原异步包加载完成后采用已加载资产，继续等待脚本可运行和资产 PSO 事件 | 不把包加载成功当作管线就绪，不等待全局无关编译 |
| 数组、Map、Set、结构体中的引用 | 同样遍历作者属性容器，软引用请求跨类去重 | 只遍历选中类/组件的属性，不递归任意 UObject 资源图，也不扫描全 Content |
| 连续软体死亡显示 | 从真实身体的 `UMonsterSoftCorpseBinding` 取得尸体网格，以 `UPoseableMeshComponent` 和其实际材质准备 PSO | 不更改死亡绑定、变形、碰撞、LOD 策略和尸体模拟 |
| 原生命中特效池 | 地牢准备阶段提交并等待现有实例化渲染器和各表面贴花 PSO；覆盖火花、尘土、碎屑、血雾、血滴、落地冲击/压力波和弹孔/血迹 | 复用原池；只给空闲贴花槽预置一种对应表面材质，真实命中仍按原路径设置材质、位置和显示 |
| 玻璃、怪物身体/附属网格、隐身材质、鼓囊胶囊与碎片 | 保留前序已有准备 | 不重写已有表现 |

新增 `FDungeonCombatEffectPreparation` 负责选中怪物的特效资产准备；`UFPSImpactFXSubsystem::PumpRenderPreparation` 负责已存在的命中特效池。两者共享地牢原有装配帧预算，通过准备完成条件接入最终放行，未新增常驻 Tick。

每项等待有 120 秒超时并带资源名称，沿用地牢失败/取消入口。Niagara 编译请求本身可能是不可拆分工作，提前执行的位置是加载阶段；不宣称每次请求都严格低于装配时间预算。

尸体和静态网格模板未注册到世界；特效资产只准备编译/PSO，不为了预热保留一套永不复用的 GPU 模拟。临时引用随本轮装配状态释放，真实延迟使用依赖沿用本轮布局资源持有。专用服务器跳过渲染准备；监听服务器和客户端在各自地牢装配时走相同渲染就绪条件。

这些是公开预缓存接口能准备的具体路径，不能据此声称所有运行时动态材质、驱动内部或光追几何首次构建已经消失；当前没有新的运行数据作此证明。
