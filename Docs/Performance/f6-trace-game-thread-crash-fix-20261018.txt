F6 GPU 追踪启动触发 AssetRegistry 线程断言：2026-10-18 修复

原因已由本次崩溃日志及本机 UE 5.8 源码对齐：采集器在 TAsync 工作线程调用
FTraceAuxiliary::Start，Start 同步广播 OnTraceStarted；AudioInsights 的
TAssetProvider::HandleOnTraceStarted 调用 UpdateAssetNames，再进入
AssetRegistry.GetAssetsByClass，枚举内存资产时触发仅允许游戏/加载线程的断言。
这是项目 GPU 采集的线程使用错误。上轮权限降级使该既有错误在无 ETW 权限时也能触发。

证据
- 崩溃：Saved/Crashes/UECC-Windows-3B200AE14290350992D21BA1D030853C_0001/。
- 时间：2026-10-18 10:47:35～10:47:37（北京时间）；线程 TAsync 0。
- AssetRegistry.cpp:2518；栈包含 AudioInsights、Core、FPSGAME。
- 同次目录 Saved/PerformanceReports/gpu-E8BBCFCA42DE31BF95042E943E363AD6/
  已有 engine.utrace，buffers.jsonl 为 0 字节，没有 manifest；不能当作完整采集。
- 引擎 Core/Private/ProfilingDebugging/TraceAuxiliary.cpp：Start 广播 OnTraceStarted，
  Stop 也同步广播 OnTraceStopped；两者不能按“仅文件操作”放到工作线程。
- 引擎 Plugins/AudioInsights/Source/AudioInsights/Public/Providers/AssetProvider.h：
  HandleOnTraceStarted -> UpdateAssetNames -> GetAssetsByClass。

修正范围：Source/FPSGAME/UI/FPSGpuTraceCapture.cpp
1. 在游戏线程开始 UE trace，再启动后台 ETW/文件工作；StartUeTrace 与入口约束为游戏线程。
2. 使用仅在采集期间存在的核心 ticker 在游戏线程处理 Stop 及监听器/通道清理。
   启动连接暂未就绪时分帧重试停止，沿用原 3 秒期限；正常运行不在游戏线程等待写盘。
3. 后台先写结束时钟锚点，再通知游戏线程停止；停止结果通过原子状态与事件交回后台。
   trace 关闭确认、ETW 停止、身份文件刷新与 JSON 写入继续在后台。
4. OnEnginePreExit 等待后台之前，主动处理本采集器的停止控制，防止游戏线程等后台、
   后台又等游戏线程的循环等待。没有抽取或执行其他任务的游戏线程队列。
5. 开始下一次采集前，清理已完成的上一采集 ticker/委托与新增通道；只管理自身 trace。
6. manifest 版本升为 3，记录 trace_control_thread=game_thread；保留权限降级及不完整提示。

没有禁用 AudioInsights、跳过 AssetRegistry 断言、删资产、改变音频内容、画质、怪数或战斗。
本轮修复的是点击 GPU 追踪引发的闪退；不是把刷怪持续 GPU 高耗时宣称为已修复。
