## 准备池准入与回收分开

`FacilityHallPreparationBudget.h` 和 `FacilityHallSpawnSubsystem.*`：

| 条件 | 当前策略 |
|---|---|
| 可选新实例准入 | 仍需至少 1 GiB 余量，加本实例估算增量 |
| 数量/估算上限 | 仍为全世界 16 个、256 MiB |
| 开始回收 | 任一有效观测的内存余量低于 512 MiB |
| 回收恢复线 | 物理内存、提交余量和适用的有效 GPU 预算余量均达到 768 MiB |
| 当前区域已到期波次 | 非临界压力时保留，覆盖正常刷怪间隔和失败重试间隔 |
| 临界压力 | 任一有效观测余量低于 128 MiB 时，可回收当前区域预留，仍从较低优先级开始 |
| GPU 观测未知/过期 | 暂停新准入；过期观测本身不授权回收 |

未来波次、远处区域、无效槽位和类别已变化的预留继续回收。原正式刷怪入口、名额、顺序、波次阈值、节奏、随机流、导航、等级、奖励、复制和战斗保持原实现。保护判断使用准备槽位的区域/波次优先级，不用受冷却影响的 `SpawnPriority()` 将即将复用的实例误判为闲置。

F6 的原准备池快照增加回收线、恢复线、临界线和压力保持状态；沿用现有低频预算观察，不增加新的采样循环。阈值是实施策略，尚无本轮性能实测。
