# 手套、衣袖与第一人称武器的几何及材质开销

日期：2026-09-28。范围：用户要求的只读资产调查与优化建议。没有修改游戏网格、材质或画质设置，没有启动游戏、录制画面或测量帧时间。

## 结论

制作中的百万面雕刻模型是烘焙源，不是当前装备引用的游戏网格。此次三款手套升级保留原有运行时几何与蒙皮，细节来自烘焙贴图。不能把 Blender 高模面数或所有武器适配版本相加，当作一帧的渲染三角形数量。

当前 M4 适配版本的双手游戏网格为 23,426–144,026 三角形。以基础 M4、衣袖和钢甲护手组合估算，LOD0 可见几何约 183,075 三角形（18.3 万），没有达到千万面。这个数字不代表所有武器，也不是 GPU 捕获中的跨渲染通道三角形总量。

## 数据与方法

- 原始读回：`Saved/Performance/GloveViewmodelBudget20260928/report.json`，53 个网格、7 个材质。
- 读取脚本：`Tools/Performance/read_glove_viewmodel_budget.py`。
- 完成日志：`Saved/glove-viewmodel-budget3.log`，标记 `GLOVE_VIEWMODEL_BUDGET_COMPLETE 53 7`。
- 后台 commandlet 通过项目 `Run-Authoring.ps1` 互斥执行，不打开编辑器窗口，不调用资产保存。
- LOD0 总数采用已保存资产的 Asset Registry `Triangles` 标签。当前引擎 `USkeletalMesh::GetAssetRegistryTags()` 从 LOD0 RenderData 的 `GetTotalFaces()` 生成此标签。
- 各材质分区数量采用 Source MeshDescription。M4 源几何 60,447，已构建 RenderData 60,445，相差 2 个三角形；因此下面的组合可见量是近似值。
- 材质统计为编译器代表着色器的指令统计，不是耗时。纹理 source PNG 尺寸和导入的 MaxTextureSize 单独读取，不用后台 Texture2D 的当前资源尺寸推导游戏显存。

## M4、衣袖、手套组合

原生 M4 资产 `/Game/Weapons/M4HK416Replica/SK_M4_FoldingSights_HK416` 包含枪体和原手臂。总计 60,445 渲染三角形，不应全部当作枪体计入后再重复加手臂。

源材质分区 0–5 的枪体共 23,325；分区 6–7 的原手臂共 37,122。装备组件通过 `ShowMaterialSection` 隐藏原手臂。全指手套加衣袖时，模块化裸臂的所有覆盖分区同样被隐藏。

| 组合 | 估算可见 LOD0 三角形 |
|---|---:|
| M4 + 衣袖 + 战术手套 | 62,475 |
| M4 + 衣袖 + 黑色皮革手套 | 64,215 |
| M4 + 衣袖 + 棕色露指手套及露出皮肤 | 95,999 |
| M4 + 衣袖 + 钢甲护手 | 183,075 |

普通毛衣和锁子甲衣袖在此算例中面数相同。不同武器的 22 套适配资源是替换关系，不是 22 套同时可见。

即使对钢甲算例把隐藏几何也全算上，四个完整资产总和也只有 60,445 + 37,122 + 15,724 + 144,026 = 257,317 三角形。这仅表示此组合的完整网格规模，不表示隐藏部分完全没有内存或蒙皮成本。

未计入可选枪匠配件、第三人称身体、场景和渲染通道重复绘制。其他武器基底数量存在差异；例如本次读到的部分机枪完整基底约 35–39 万三角形，含原生手臂，不可直接套用 M4 的分区扣减。

## 当前材质的主要开销

三款皮革手套的第一人称材质采用 Cloth + 自定义 UV 视差。露指/战术源贴图实际为四张 4096×4096（颜色、法线、ORM、Relief）；黑色 V4 的已保存材质也是四张贴图、MaxTextureSize 4096。钢甲为三张 4K 甲片图及三张 1K 锁子甲图。当前都允许纹理流送。

`black_leather_relief.ush` 近景最深分支：初始 Relief 一次、最多 6 次步进、2 次细化、最终 Relief 一次、颜色/ORM/法线各一次，最多 13 次纹理查询。分支不执行时是 4 次。现有距离、角度和 mip 衰减已经存在；第一人称近景仍可能执行完整分支。它只移动 UV，不生成额外几何。

| 材质 | 代表像素着色器指令数 | 采样器数 |
|---|---:|---:|
| 棕色露指 | 313 | 5 |
| 黑色皮革 | 310 | 5 |
| 战术皮革 | 313 | 5 |
| 钢甲锁子甲衬底 | 208 | 4 |
| 钢甲甲片 | 207 | 4 |
| 普通衣袖 | 205 | 2 |
| 锁子甲衣袖 | 206 | 4 |

API 对三个 Custom HLSL 皮革材质返回的 pixel texture samples 是 0；代码明确存在查询，不能据此解释为没有纹理采样。指令数、采样器数也不能直接转换为 FPS。

后台 Texture2D 资源尺寸接口统一返回 32×32，与已确认的 4K/1K 源文件和 MaxTextureSize 不同；这组资源尺寸不作为最终 cooked 尺寸或运行时驻留尺寸证据。本次没有读取实际游戏驻留显存，不能提供精确 MB 占用。

## 建议的优化顺序（尚未实施）

**2026-09-29 决策补充：** 用户要求复杂近景物体允许高面数，并将分类预算纳入工作流。当前钢甲可保留 144,026 三角形；下面的 6–8 万仅为有条件的减面候选，不是必须实施或已实施的预算。现有帧时间证据不足以要求强制减面。后续按 [用途预算](../../skills/asset-model-workflow/references/geometry-budgets-by-use.md) 选择局部优化，优先保留连续壳体、小拇指及腕拇指的形状与变形质量。

1. **如有实际几何优化需求，可研究钢甲 LOD0 的局部精简，6–8 万为候选而非必达值。** 当前连续手背/手腕/拇指壳体两手共 76,480，约占总数 53%；其余为手指甲片 26,496、柔性金属衬层 11,480、铆钉 6,144、手套衬底 23,426。候选方向是减少平坦壳面的均匀网格和小铆钉几何，保留外轮廓、厚度边缘、小拇指及手腕/拇指弯曲区。达到候选范围约减少钢甲本体 44–58% 三角形，但不能为此损伤结构，也不承诺相同比例帧率收益。既有皮革只有 2–4 万面，优先保留形状和关节质量。
2. **让贴图精度按用途分配。** 颜色、ORM、Relief 优先尝试 2K；需要近看缝线的法线保留 4K。毛躁和颗粒可以用小尺寸平铺细节图补充，避免所有微细节依赖整张大图。同压缩格式、同 mip 策略下，单张 4K 改 2K 的存储量约为四分之一；不是整套装备显存或帧时间减少 75%。新图颜色/ORM 带 alpha，而材质为 Opaque 且读取 RGB，可在优化导入时去掉无用 alpha；实际压缩收益取决于目标格式。
3. **分档处理视差。** 保留毛躁、法线和粗糙度，常规游玩提供较少步进的视差或法线档；近距离检视提供完整视差档。第三人称、掉落物优先普通 PBR。现有角度/距离衰减保留，不重复堆叠同类分支。
4. **不要仅依赖距离 LOD。** 已有 3 级 LOD，但第一人称双手长期接近镜头；如需降低其几何成本，应考虑 LOD0 本身。优化骨骼网格时保持各武器原生绑定、关键关节拓扑及已有小拇指修正，再按用户要求进行动作比较。

这套路线保留百万面制作源与烘焙成果，把可见轮廓和关节留给真实几何，细颗粒、磨损、缝线主要交给贴图。Epic 官方同样将高模烘焙法线、适当贴图尺寸和降低材质复杂度列为优化手段：[渲染优化指南](https://dev.epicgames.com/documentation/unreal-engine/guidelines-for-optimizing-rendering-for-real-time-in-unreal-engine)。

是否已形成实际性能瓶颈仍需特定分辨率、武器和场景的 GPU/CPU 帧时间；本次仅确认资产规模与可优化项，不声称帧率已验证。
