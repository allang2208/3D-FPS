# 地牢刷怪调度与资源生命周期优化（2026-10-12）

用户授权按采样结论进行首轮代码优化，保留怪物模型、材质、动作与波次数量。诊断依据见 `dungeon-entry-autocapture-20261012.md`：首次创建存在约 70 ms CPU 峰值，主要长停顿则表现为 GPU/提交阻塞传递到渲染和游戏线程。此批不将“队列改好”描述成“GPU 问题已根治”。

## 已落盘的修改

### 共享刷怪调度

- 新增 `Dungeons/FacilityHallSpawnSubsystem.*`，按 World 管理大厅请求，不持有未使用的怪物实例。
- 原来的大厅 200 ms 定时器改为提交去重请求。按 FIFO 处理，每帧最多一次放置/生成尝试，全局两次尝试至少相隔 50 ms，避免两个大厅在同一帧集中初始化。
- 成功生成后插入渲染线程 fence，后续尝试只轮询完成状态，从不阻塞等待。它表示先前渲染注册命令已经通过，不表示 GPU 已经空闲或所有资源已经驻留。
- 单只怪物的 `FinishSpawning` 仍在合法的游戏线程执行，不能中途打断，因此不是单只实例化的硬毫秒上限。
- 出队前重新确认当前 run、generator、theme 的有效性与准备状态；销毁大厅时撤销请求，World 销毁时清空队列。保留原碰撞/导航放置、组合随机流、波次杀敌阈值、门口出怪冷却与完成判定。
- 从类默认对象查询边界时改用 Capsule 半径，避免 `GetSimpleCollisionRadius` 的默认对象警告和可能为零的半径。
- 新增 `FacilityHallSpawn_Admission`、`FacilityHallSpawn_Create`、`FacilityHallSpawn_FinishSpawning` CPU scope，供今后获授权的 trace 直接区分阶段。

### 击倒动画异步准备

- `HumanoidKnockdownComponent::BeginPlay` 原先按路径同步加载默认击退/仰卧起身/俯卧起身动画；这些默认引用不一定随怪物蓝图一并加载。
- 将默认路径生成抽成共享函数，地牢已有的资源准备批次额外请求员工 Nurse 骨架的三段动画，并沿原来的 `GenerationResources` 生命周期持有。
- 动画沿已有异步资源批次提前加载；当前引擎没有公开的逐动画非阻塞编译状态接口，因此不新增动画编译等待，也不调用同步等待编译。此项只承诺提前加载动画包，不将包加载完成等同于 Editor 动画派生数据编译完成。
- 生成时优先解析已经准备的对象。非地牢样板地图保留原来的默认加载行为；蓝图显式配置、动作资产与骨架兼容判定均保留。
- 没有预生成整波怪物，也没有增加永久怪物对象池。

### 完整预加载纹理保护的交接

- 地牢完整预加载结束后，沿现有 `TransitLoadingSubsystem` 做低频、分帧的保护维护。
- 只访问本次准备过的组件，每轮软预算 1 ms，完整一轮后等待 1 秒；共享材质去重，静态材质沿用弱引用纹理缓存，动态材质重新读取当前参数。
- 仍被可显示组件或实际隐藏投影组件使用的共享纹理保持保护。连续至少 5 秒未使用的纹理解除额外的流出保护，交给引擎按需求和预算决定驻留；不强制卸载、压低 mip 或降低贴图分辨率。
- 过场淡出不立即撤销保护，游戏暂停不推进 5 秒计时。切换/取消/销毁仍沿原生命周期清理；全部保护释放后维护停止。
- 修正隐藏组件的判定：仅设置 `bCastHiddenShadow` 而未启用 `CastShadow` 的组件，不算实际投影资源。
- **此路径仅作用于地牢的完整预加载模式**。此前快速模式采样的显存压力不能据此宣称已经消除。
