## 源码修改

- 修正铺装强制 LOD 编码：目标 LOD1 使用 `ForcedLodModel=2`，生成和重复接入采用同一解释。场景组件仍记录原资产 LOD 链，原碰撞保留。
- 面板事件分段从“每个栏目重复遍历全部事件”改为一次汇总；未变化的文本不再重复设置。行控件继续复用。
- 图标完成通知携带配方键，只刷新相关物品的图像/绘制，不再让每个库存订阅者重新执行全量 `LoadIcons()`。
- `InitializeWeaponVisuals(true)` 为图标与掉落物提供展示初始化：只需当前网格、idle 和可见配件，跳过战斗动画家族、音效及 FX 初始化。玩家正常装备路径继续使用默认参数。
- 新增展示资源异步请求，保持 streamable handle 到配方完成；剑的资源清单直接复用模块目录中选中的零件、材质和适配器。只在离线目录图作者入口允许同步等待。
- 模型初始化、各配件、包围盒、捕获准备、掉落物预热拆到不同 tick。CPU 蒙皮包围盒保留全部可见顶点，按约 1.5 ms 合作式预算、每 512 顶点观察一次时间；这不是严格的单帧上限。UObject/组件创建仍留在游戏线程。
- 配件可选资源未预载命中时仍保留原有装配路径；新增 `Icon.AttachmentSlice` 帮助定位剩余单个装配峰值。异步加载本身也不能消除引擎主线程资产后处理的全部耗时。

## AKM 材质归因修正

进一步读取真实资产引用后确认：连续性 Graph 用于静态扩容弹匣，干图直接被 `SM_ExtMag_AKM40_Continuous` 引用，湿图由天气映射关联到同一静态附件；不是骨骼枪体的材质。

原分析建议压缩 UV 以适配 GPUSkin，属于当时尚未确认实际使用面的候选。真正的缺陷是从步枪母材质复制后继承了 `used_with_skeletal_mesh`、morph/cloth 与自动使用标志。修复清除这些不适用的编译用途，并在导入脚本中固定静态附件用途；保留 UV0–6、接缝权重、切线矩阵、法线、粗糙度和雨天图，避免为未使用的骨骼排列改写视觉效果。
