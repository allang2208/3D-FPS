2. 共用特效资产准备步骤

各拥有者保留原超时、强引用、取消、片段组件和实际技能激活逻辑。Dragon Breath 的真实复用体积与避免重复网格的规则保留。没有引入全局资产永久缓存，也没有把素材准备误当全部实例 GPU 就绪。

3. 日常记录与深度观察分离
fps.Perf.RenderResourceSampling 默认由 1 改为 0。普通 F6 帧记录仍保留基础帧时间、每秒最多两次的 RHI 内存预算与有界准备池快照；不再遍历全场角色、骨骼和 Groom，不建立组件 JSON/形变列表。
显式 F6“GPU 驻留/调度：开始”会自动开启详细观察，停止后返回基础观察；人工设置该控制台变量为 1 或已有 MonsterCapture 命令仍可明确启用。精确姿势比较和原生缓冲身份仍只在显式 GPU 采集中进行。
基础样本写 component_details_recorded=false，未观察的怪物/骨骼/毛发数量省略，不把未知写成零。已有单请求在途门控、2 Hz 频率、360 条滚动容量和独立预算读取保留。暂停普通记录不妨碍准备阶段读取必要内存预算。

后续用户采集
1. 使用本批最终 Editor 构建。保存并退出旧编辑器后，通过根目录 Launch-F6-WddmCapture.cmd 启动并确认 Windows 权限提示；本批不会替用户启动或关闭。
2. 刷怪前在 F6 点击“GPU 驻留/调度：开始”，等待“WDDM + UE 正在记录”。普通导出仍可看帧时间，但没有开启深采就没有组件/缓冲身份记录。
3. 保持原装备、画质、分辨率和通常进入路线。出现持续低帧后再保留约 20 秒，直接导出，等待保存完成。期间不要并行编译/烘焙；不要同时变更驱动或系统 GPU 设置。
4. 保留整份 Saved/PerformanceReports/gpu-... 文件夹：manifest.json、engine.utrace、wddm.etl、buffers.jsonl、性能 JSON。状态仍报权限错误时保留失败记录，无需重复战斗。
5. 后续先对齐 WDDM 与 UE 时间线，区分资源迁移、队列等待、外部负载与实际 GPU 执行。缺少逐资源关联时不猜具体缓冲。只有这条证据仍不足时才准备针对性的硬件分析，避免继续泛化预热。
