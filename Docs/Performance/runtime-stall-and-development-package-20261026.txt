3. 有界资源生命周期记录
新增 Diagnostics/FPSResourceLifecycle，F6 JSON schema 提升到 16。
resource_lifecycle 保存最近 256 个边界事件，包含进程会话标识、对象序列身份、
世界/实例身份、时间、帧号、进程内存与各所有者报告的句柄/资源数量。
记录点覆盖 World 初始化/结束、玩家装备准备替换/释放、技能准备完成/取消/销毁、
地牢生成完成/取消/结束和大厅准备池反初始化。
记录不会持有 UObject，不增加每帧遍历，不强制 GC，不等待 GPU。
历史跨同一进程的 F6 清空和 World 切换保留；普通日志同时保留退出事件。
导出线程仅复制已序列化记录，记录时间独立于旧的 F6 面板快照。
这些数量是所有者报告的引用数量，不是去重后的 GPU 分配，也不是实际显存驻留。
释放引用和引擎稍后的渲染清理/GC之间有时间差，不能仅凭相邻两行断定泄漏。

该入口只 Build/Cook/Stage/Archive，不启动编辑器界面、游戏或采样。

用于 F6 的 WDDM 记录；不附加分辨率、画质或帧率参数，打包期间不会执行此入口。

尚不能归因的部分
同一份 Trace 中还存在编辑器 Niagara 首次编译（约 167 ms）、目录变更处理，
以及主线程等待。Cooked 包可移除编辑器专属工作，用于后续与 PIE 分开对照。
大厅和角色的一些长帧仍有未细分区间，不能把整个 scope 归咎于刷怪或动画。
Render/GPU 离线统计已导出至本轮目录；多线程、嵌套和 GPU 时间线不能直接累加。
本轮尚未证明某一个 GPU pass 是持续低帧根因，也未依据猜测降低渲染质量。

用户后续对照方式
先关闭编辑器，再使用独立包进入同一个随机地牢，保持分辨率/窗口模式、画质、
地牢种子、装备和技能条件一致。注意 PIE 实际视口尺寸可能小于编辑器窗口。
独立包和 PIE 的存档位置可能不同；本轮不复制、覆盖或清空用户存档。
仍按原 F6 流程导出完整采集目录，保留首次进入、开始刷怪和后续持续低帧时段。
若只导出 JSON，生命周期记录仍可用于判断引用回收，但不能替代 GPU 事件关联。
性能收益与包内实际行为待用户测试，不以编译成功代替运行验收。

Development 基线入口使用 UE 5.8 源码提供的构建参数：
- 整体资产编译并发 2，骨骼资产在 Cook 时同步构建（asyncskinnedassetcompilation=0）。

以及 asyncassetcompilationmaxconcurrency/asyncskinnedassetcompilation。
