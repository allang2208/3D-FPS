# 区域提前准备与分批刷怪（2026-10-19）

本批按用户同意的方案开发；保持画质、怪物数量、战斗规则和奖励槽位。后台源码与必要构建，不启动 UE/PIE，不执行测试。构建状态在文末更新，不能当作单机或联机运行验收。

## 触发与范围

| 路径 | 提前准备 | 正式激活 |
| --- | --- | --- |
| 迎宾大厅、分流大厅 | 活玩家进入 FacilityEntrancePassage 后，两厅共用预算，轮流准备首波槽位 | 原有服务器区域锁门事件提交两厅首波队列 |
| 医疗、货运、生态、动力、焚化、生活区 | 位于拓扑相连的入口房/通道，距离区域边界 18 m 内；缓存连通节点，不按隔墙直线距离选区域 | 同一主题锁门后提交所有房间首波；仍逐个调度 |
| 最终 Boss 区域 | 同一公共区域机制 | 保留原有区域进入及目标条件 |
| 迎宾增援 | 只在区域开始后，最多为每房保留一个未来波次实例 | 首波普通怪击杀严格超过一半 |
| 货运增援 | 只准备已经产生的槽位 | 原 20 秒时钟、数量上限和服务门条件 |
| 焚化地下层 | 进入地下层并释放槽位后才有资格 | 保留原楼层触发条件 |

“提交整个主题区域”不等于单帧生成全部怪。原全局每次至少间隔 50 ms、每房 200 ms 请求、正常生成后的非阻塞渲染注册 fence 继续使用。准备不推进随机数、不决定最终落点、不增加槽位、不触发 AI/战斗/奖励。

## 有界准备

- 世界共享最多 16 个待激活实例，不为各主题分别复制一份满额池；最多 256 MiB 估算增量缓冲。
- 普通首波全部优先于未来增援；相同级别按每房已准备数轮转，再比较入口距离。低优先级预留不能卡住当前区域。单个怪物超出准备预算或渲染大小未知时跳过其可选准备，不阻塞其它槽位；正式生成仍保留。
- CPU 物理内存、提交余量和最近 GPU 预算均需留 1 GiB 余量（新增对象的估算也计入准入）；专用服务器跳过 GPU 条件。
- 估算采用主体 LOD0 顶点数 × 128 字节 + 每实例 1 MiB；这是保守准入估算，不是显存物理驻留或整个 Actor 的精确内存计量。共享网格/贴图沿用生成器已有资源，不另复制。
- 最多每 100 ms 准入一次可选准备/捕获，每帧最多一个可选动作，回收也消耗可选时间片；GPU 捕获未完成时不再准入可选工作。超过 33.3 ms 的帧让出可选工作。
- 正常刷怪不等待可选 GPU 捕获、可选注册或可选释放 fence；正常刷怪自己原有的注册队列节流保留。
- 路线无关、槽位失效、精英候选变更、内存余量不足时分批回收；换局、销毁区域和退出世界释放全部预留。

## 准备深度及联机

所有已配置的首波怪物可以提前进行原生对象分配；仍延迟 Blueprint 构造、BeginPlay、AI 控制器、战斗计时、奖励绑定。普通职员沿用同一个实例的骨骼/形变 GPU 捕获准备；特殊怪物的附属构件、技能和自定义构造继续在正常激活流程执行，没有冒用通用职员渲染配方。预热捕获完成后停止捕获，准备中的身体不参与主视图、阴影、GI 或 RT。

服务器负责唯一槽位与准备池。待激活对象不复制、不碰撞、不可受伤、无 Enemy 标签，原生组件关闭自动激活；正式激活恢复原始状态，按当前最终落点完成一次构造和正常复制。多个玩家只影响区域优先级，不分别创建怪物。专用服务器只分配对象，不注册职员 GPU 预热视图。

客户端复用 AuthoredDungeonGenerator.OnRep_NetworkRun -> Generate(NetworkSeed) 的现有异步资源与 DungeonMonsterRenderPreparation 材质/PSO 准备；本批不再创建重复的客户端影子怪物或强制驻留贴图。晚加入也沿用当前 NetworkRunId。客户端实例自身的形变输出缓冲仍随真实复制 Actor 初始化，这一部分未宣称已提前完成。

已有全局单机/联机战斗逻辑不改变。该改动针对首次进入区域/连续刷怪的初始化分摊，不能据此宣布活怪持续 GPU 高耗时或原先 400 倍输出缓冲差异已经消失。
