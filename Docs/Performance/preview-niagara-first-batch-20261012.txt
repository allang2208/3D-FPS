首次 Niagara 编译
现有作者脚本已经调用 RainAssetEditor.compile_rain 再保存，不能把问题描述为作者流程完全未编译。
本机 NiagaraSystem.cpp 在资源源图与编译数据不同步时，默认按需推迟编译；异步加载完成不代表这部分编译已经执行。
本批通过 Tools/Performance/prepare_traced_niagara.py，复用既有 CompileRain 的 RequestCompile(false) 与 WaitForCompilationComplete(true,false)，在后台完成 VM 和 GPU shader 编译，再仅保存两项已在轨迹出现的系统：
  /Game/Skills/Lightning/NS_LightningChain
  /Game/Skills/ElectricMagic/StormDomainV2/NS_StormDomainCloud
每次制作先备份原 uasset，逐项记录保存结果与 SHA-256，输出 Saved/NiagaraCompilePreparation/<job>/receipt.json。
CompileRain 补充编译前 deferred/pending 和编译后 pending 日志，并要求 VM/GPU 请求均完成才返回成功。未改编译强制标志、系统图、用户参数、发射器和实际施法时钟。
实际制作日志还发现 M_StormDomainCloud 缺少本机 SM6 shader map。制作脚本进一步调用 MaterialEditingLibrary.get_statistics；本机引擎中该接口会提交缺失的材质编译任务并执行该材质资源的 FinishCompilation，将着色器缓存写入本机 DDC。它不修改材质图或参数，也不强制重编整个项目；此处用于完成后台编译，不是运行性能测试。
补齐材质缓存的第二次制作显示，闪电链跨进程重载仍产生 deferred 编译标记，不能仅凭 uasset 已保存宣称消除了首次使用停顿。TransitLoadingSubsystem 因此在 Editor 单机地牢准备开始时异步取得现有闪电链，提前提交非强制编译并逐帧 PollForCompilationComplete(false)，待 VM/GPU 请求完成才结束加载遮罩。快速和完整加载模式都覆盖；没有在游戏 Tick 中调用 WaitForCompilationComplete 或 FlushRenderingCommands，没有改变刷怪代码。该工作只存在于 WITH_EDITOR，打包游戏不增加这项编辑器编译阶段。
当前电系组件已在并行制作中改用 StormClouds/RollingV1 云系统。本批保存的是旧性能记录明确指出的 ElectricMagic/StormDomainV2 资产，没有覆盖新云系统或把旧云重新接回游戏；不能声称已经预编译新云的所有依赖。
这是编译数据制作和持久化；并不保证所有动态 GPU 管线首次创建都已预热。源图、依赖或引擎变化可能再次使编译数据失效。
