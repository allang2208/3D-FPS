# 天气与附着水滴：第一轮升级

本轮使用现有 UE 体积云、Niagara 和自行编写的程序化材质，没有购买新资产，也没有复制 GitHub 项目的实现代码。付费天气包可以节省预设制作和调参时间，本轮需求不存在必须购买的技术依赖。原始审计及候选比较见 [WeatherAudit-20260912.md](WeatherAudit-20260912.md)。

## 已接入的行为

- 多云、小雨、中雨、暴雨分别驱动 0.30 / 0.52 / 0.76 / 1.00 的云层过渡；开启原有云材质的风动与多尺度细节，积分风位移，避免阵风变化时纹理跳动。
- 测试地图的日夜光照不再与暴雨组件重复压暗。PWL 天空材质通过独立副本逐步过渡到大气背景，避免把不透明天空球直接压成黑色。晴天恢复原材质及光照。
- 四个 Niagara 系统使用独立副本。雨丝缩细、长度和透明轮廓随机变化，雨与雨雾接收运行时风参数；极远雨丝淡出，减少细碎亮点。保留现有池化溅水、屋檐滴水和湿地面系统。
- 屏幕四周加入大小不同的附着水滴、少量下滑痕迹和局部折射。普通持枪时中央宽高各 72% 的区域不发生水滴扭曲；ADS 扩大到 86%，并降低强度。不使用整屏模糊。
- 枪身水膜改变粗糙度，水珠改变局部法线。材质使用枪械自身 UV，跟随骨骼与配件。覆盖 M4、AKM 及本轮识别的配件材质；保留原纹理、金属度和材质参数。手臂、瞄具玻璃和准星材质不在本轮水膜范围内。
- 遮蔽每 0.25 秒探测一次，每帧平滑衰减。停止淋雨后屏幕最多约 32 秒干燥，枪械最多约 120 秒干燥。枪械湿度按库存实例分别保留，切枪不互相串用。该表现状态仅在当前游戏会话内保存。

## 运行与资产

入口为 `AFPSWeatherManager`，继续保留唯一天气管理器和 2160 秒一天的默认约定。相机及枪械逻辑在 `UWeatherViewEffectsComponent`；云和光照在 `UStormCloudComponent`。

正式资产库：`/Game/Weather/NaturalV2/DA_WeatherPresentation`，由管理器的可编辑软引用在 BeginPlay 加载。库内保存屏幕材质、21 个枪械材质来源映射、8 个天空来源映射和 4 个 Niagara 系统的硬引用。生成目录共 39 个资产，约 3.37 MB，不包含原枪械贴图。`/Game/Weather/Natural` 为本轮首轮试验副本，当前运行入口不再引用。

可编辑源：`SourceAssets/WeatherNatural20260912/*.hlsl`。生成脚本：`Tools/Weather/build_natural_weather.py`。脚本仅保存自己生成的资产；需在相关资产未被其他游戏进程占用时运行。现有商用枪械贴图、PWL 材质及引擎资源仍须在本机恢复，生成的衍生二进制不作为开源资源发布。

控制项：`fps.ScreenRain` 默认 0.75，`fps.WeaponWetness` 默认 1；设为 0 可关闭相应表现。原天气质量设为 0 时也关闭这两项可见效果。

## 验收入口与边界

2026-09-12 本轮实测：Editor 与 Game Development 目标均编译通过。`DayNight_Lighting`、`L_Normandy_FPS_Test`、`L_MilitaryTrench_FPS_Test` 的 D3D12 实机流程各通过 20 项检查、失败 0；屏幕最终湿度 0，M4 保留约 0.615 的湿度，材质绑定数稳定为 8。已实际查看三张地图的暴雨画面及主地图 ADS、干湿对比。截图没有使用生成式修图。

主地图额外通过两轮“暴雨 → 晴天”回归：原云材质、可见性和日照恢复，只有一个可见云组件及主太阳，没有累积压暗或重复创建云层。该次采样的整场景 GPU 中位数为晴天 4.109 ms、暴雨 6.567 ms；这包含整套天气、场景及并行工作负载，不能作为屏幕水滴单项耗时或正式性能预算。

村庄天气面板回归同样通过：手动预设、雨量参数、面板输入归还、自动排程恢复、日夜时钟推进及太阳光变化均正常。机器可读记录见 [validation.json](WeatherPreview20260912/validation.json)。

`Tools/Weather/run_natural_weather_audit.ps1` 使用独立玩家存档和真正的 D3D12 离屏渲染，不会关闭用户编辑器。默认依次检查天气变化、湿度积累、ADS、屋顶遮蔽、M4/AKM 切换、雨停干燥和材质数量稳定，并保存截图。`-Mode Storm` 检查重复暴雨及晴天恢复，`-Mode Panel` 检查天气面板、日夜推进和自动排程。`-Sequence` 导出逐帧画面。

最新运行结果与画面记录于 `Saved/WeatherPresentation20260912/`。渲染验收使用 `-nosound`，本轮没有重新验收声音混音，也没有执行完整打包 Cook。编辑器资源生成命令仍会因为工程原有 `GameFeatureData` 扫描规则缺失而返回退出码 1；应分别看脚本成功标记、Niagara 编译结果及真正的运行验收，不把整个 commandlet 宣称为零错误。

Game 目标编译还修正了已有攀爬验收代码中的一处编辑器专用 API：`GetActorLabel` 改用可用于 Game 目标的 `GetActorNameOrLabel`。没有改动攀爬规则或动作时序。

## 后续付费资产的判断

优先评估本轮实机观感，再决定是否购买。只有需要大量美术预设、更多气象类型或统一美术工具时，才值得比较 [Ultra Dynamic Sky / Weather](https://www.fab.com/listings/84fda27a-c79f-49c9-8458-82401fb37cfb) 等完整方案。单独的屏幕水滴或枪身湿润效果，当前已有可调节的替代实现。高级滴水合并、沿模型表面流动、水珠真实几何和不同表面接触角不在本轮完成范围内。
