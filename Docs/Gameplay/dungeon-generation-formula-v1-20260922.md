## 1. 当前基线和首版目标

当前 `/Game/GameMaps/L_Dungeon_Prototype` 是固定装配的工业维修空间，主题、材质、灯具和组合布景可作为美术标准。`SceneTestPortal` 已提供样板入口与返回主城，`TransitLoadingSubsystem` 已提供转场；`ColdSteelFormulaBonuses` 有地牢增益接口。当前源码中尚未有房间布局生成器或地牢遭遇管理器。历史文档中的生成器类名仍是规划。

首版采用一个工业主题、单层 **14 个功能房间**：10 个主线房间 + 4 个支线房间，2 条支线，1 个回环。走廊、转角、门斗不计入功能房间数。目标是一局能选路、进入战斗、取得奖励并返回的完整切片。目标体验时长暂取 12–18 分钟，属于调参目标，不是由房间数量保证的结果。

该规模用于建立完整规则；后续按同一结构扩为双层，再增加到历史规划的 30–60 房。14 房不覆盖旧版 A–F 档位的正式经济数值，也不将工业主题直接等同某个已有地牢系列。

## 2. 生成公式与执行顺序

```text
一局地牢 = 档案参数 + 种子 + 版本
         → 功能房间图
         → 空间排布与连接
         → 兼容的房间模板
         → 战斗 / 事件 / 奖励
         → 分区美术与细节
```

路线、可通行空间和玩法锚点先确定；布景只使用剩余可放置区域。当前样板拆出三类可复用输入：

| 层 | 内容 | 生成器如何使用 |
| --- | --- | --- |
| 结构构件 | 墙、地、顶、柱、门洞、转角、管线、楼梯 | 按占格、接口和净空拼接 |
| 组合布景 | 工作台、配电柜、货架、破损墙、格栅、水渍 | 挂到模板的墙边、角落及凹室锚点 |
| 玩法房间模板 | 维修间、机房、仓储间、分流厅、战斗厅、终点厅 | 提供功能、空间、出口和遭遇约束 |

模板尺寸由有限的规格组合得出；不整体拉伸已制作的房间或工作台。新增美术可以替换组合布景或加入同接口模板，无需改路线算法。

## 3. 路线语法

初始主线固定“节奏槽位”，每个槽位从兼容房型中选取：

```text
入口 → 普通战斗 A → 分流厅 → 普通战斗 B → 事件
     → 普通战斗 C → 精英 → 缓冲补给 → 首领 → 出口
```

两条支线的初始规则：

- 分流厅 → 可选战斗 → 宝物房 → 回到分流厅，构成一个局部回环。
- 已清理的普通战斗 C → 可选事件 → 储藏奖励，形成一条有收益的尽头支线。

这是 **14 房配方**，不是每局固定平面图。变化来自房型、形状、转向、支线方向、空间位置、敌群和事件。第一轮先保证有意义的变化，再放宽语法。

硬约束：

1. 出生点、主线、首领和出口均可达；普通死路只出现在有奖励或事件的支线末端。
2. 首领门要求主线三个普通遭遇和精英遭遇完成，即首领前至少四场指定战斗；支线战斗不替代这些条件。
3. 回环先安排在两个强制节点之间的同一段内。跨段捷径必须带明确解锁条件，不能绕过必需事件、精英或首领。
4. 已锁连接的钥匙或控制器，必须在当前可达区域取得；采用“区域 + 已满足条件”的可达性求解，不能只查无条件连通图。
5. 初始模板最多四个出口，普通房优先两个。分流厅承担主要选路，不把每间房都做成四岔口。
6. 相邻房间不使用完全相同的模板变体；房型重复时至少改变空间组织或玩法内容。
7. 连续强战斗最多两场；精英之后给缓冲空间，再进入首领战。

探索连接使用带条件的有向边表达门锁和单向捷径；普通双向通路记录为互逆边。任务依赖可以是 DAG，探索路线允许回环，两者分别存储，避免“DAG 同时带回路”的矛盾。

## 4. 空间与模板公式

先生成图，再用模板接口约束排布：

```text
候选模板 = 功能匹配 ∩ 尺寸匹配 ∩ 出口匹配 ∩ 怪物净空匹配
候选位置 = 出口对接位置 − 已占空间 − 保留通道 − 楼梯洞口
选择权重 = 基础权重 × 主题适配 × 区段适配 × 重复惩罚
重复惩罚 = 0.35 ^ 最近四房内的使用次数
```

先过滤不满足条件的候选，再按权重抽取；不能用很低的权重代替硬约束。空间排布采用有限回溯；模板对接失败时撤回当前局部选择，不先放物体再靠整体移动修穿插。

建议初始规格，通行尺度须按实际参战胶囊和动作包络继续确定：

| 项目 | 初值 |
| --- | --- |
| 布局网格 | 200 cm；构件接口使用厘米整数坐标 |
| 结构常用跨度 | 400 cm；边界不足由已定义的 200 cm 构件收口 |
| 主连接通道 / 维修支线 | 净宽 600 / 400 cm |
| 通行门口基型 | 净宽 240、净高 280 cm；大型敌人使用更大的接口类型 |
| 普通战斗厅 | 16×16、16×20、20×20 m 三档 |
| 精英 / 首领厅 | 首版 20×24 / 24×28 m，分别制作模板 |
| 战斗空间净高 | 普通 380 cm，大厅 460 cm |
| 后续标准楼层间距 | 暂定 500 cm，楼梯与洞口成套占位 |

使用者看到的净宽、净高从最终碰撞边界计算；门框、管线、踢脚线不能侵入净空盒。样板中现有不同高度的窄开间作为支线布景或视觉凹室使用。现有精修铁门作为格栅美术来源，可通行版本需要独立门扇、门轴、交互和通行净空。

每个模板至少声明：`TemplateId / Revision / Footprint / Occupancy / Connectors / WalkableRegion / ClearanceVolumes / SpawnZones / CoverSlots / LootAnchor / EventAnchor / LightSlots / DressingSlots / SupportedEnemyProfiles`。

连接器声明位置、外法线、宽高、地面标高、类型及门扇扫掠体积。对接要求法线相反、类型兼容、标高一致；跨层只能通过成套楼梯连接器。未使用的出口由封口件关闭。

后续双层模式保留两条层间路线，使第二条楼梯可以承担回程捷径。楼梯体积与上层洞口在排房前预留；同一层公式继续使用，跨层边另外处理。

## 5. 战斗公式

房间先选战术结构，再配敌群：柱列绕行、中央设备、两侧掩体、局部高差等。普通房至少保留两条移动路线，门口有缓冲区，主移动路线不放装饰碰撞；敌人出生锚点须在可导航区域，且与入口、玩家和其他出生点保持净距。

```text
房间威胁预算 B = 档案基础预算
                × 房间类型系数
                × (0.85 + 0.45 × 主线进度)
                × 本局修正规则

敌群成本 = Σ(数量 × 敌人威胁成本)
敌群成本 ≤ B，并满足角色组合、空间和同时存活上限
```

初值：普通房类型系数 1.0，可选战斗 0.85，精英 1.5；首领使用独立遭遇配置，不靠公式无限增加杂兵。基础预算 10 只是编队点数，不是伤害或等级。敌人威胁成本须为实际允许参战的怪物单独登记；不足以填满预算时允许留空，不为了凑满预算强行放大型敌人。

首版使用已有 2–3 类合适怪物，按近战压迫、耐久或特殊干扰分工。生命、伤害、状态效果继续走现有战斗公式。暂定普通房同时存活上限 6、精英房 8、整图 12；这些都是配置起点，没有性能结论。

普通遭遇允许退回和拉扯；精英、首领才使用封闭战斗。玩家完全越过门槛并进入触发区后才关门，避免门扇夹住角色。怪物刷新、门锁和掉落都归对应 EncounterId 管理。

清房条件：该遭遇已启动、待生成波次为空、所属敌人全部死亡或按明确规则结束。隐藏、卸载、离开房间不等于死亡。`CompleteDungeonFormulaBattle` 每个已完成遭遇只调用一次；首领战后再开放结算出口。

## 6. 美术变化与玩法随机解耦

```text
房间外观 = 工业主题 + 区段状态 + 模板变体 + 组合布景槽 + 材质参数
```

工业主题优先分成仍有供电的维修区、潮湿机房区和局部损坏区，状态沿相邻房间连续过渡。潮湿度、锈蚀和碎屑有共同区域来源；水渍优先靠漏水点与排水口，碎屑靠破口，管线沿已规划的连续接口走，不在每间房独立随机截断。

入口保留辨识度；分流厅有地标；奖励房用可识别的光线、栅栏视线或门牌提示方向。美术可以提示探索机会，但不能改变规则保证的通路。

布景仅占 `DressingSlots`，并排除通道、门扇、敌人出生、战斗移动和可交互物操作区。细节缺失时可使用简化或空槽；关键门、地板、导航和敌群依赖缺失时不得把场景标记为可进入。

本批被用户否决的 11 类 5080 地牢资产不进入任何候选列表。当前通过用户反馈形成的手工资产与材质继续使用。

## 7. 可复现、进度与运行时

```text
LayoutSeed    = H(RunSeed, GeneratorVersion, ProfileRevision, "layout")
TemplateSeed  = H(LayoutSeed, RoomId, "template")
EncounterSeed = H(RunSeed, RoomId, EncounterVersion, "encounter")
DressingSeed  = H(RunSeed, RoomId, ArtRevision, "dressing")
```

使用指定版本的稳定哈希与随机算法、固定候选排序。各层使用独立随机流，增加墙面污渍不会改变房间或怪群。运行时保存最终布局及模板版本；只存 Seed 不足以应对日后模板库变化。

最小存档包含 RunId、Seed/版本、布局、已探索房间、遭遇状态、事件结果、门锁与钥匙状态、已生成及已领取奖励、玩家所在房间与安全落点。奖励记录具有稳定 ID；重进房间、读档不能重复刷怪或领奖。

“已探索/已清理”与“是否加载/是否激活”分开：清理进度是永久局内状态，组件回收不重置进度。优先预载当前房、邻房及透视开口可见房；近处房间的灯、AI和物理按预算激活。

布局装配完成后准备导航；门状态通过对应阻断或导航链接处理。入口放行依赖必要结构碰撞、导航、出生安全区和首批内容就绪。旧样板“唯一返回门”的逻辑需要按新宿主区别处理。

正式钥匙、祭品扣除与结算沿用已有出征规划：加载成功后提交，失败不消耗入场物资。生成失败有限回溯、最多八次派生尝试，仍失败报告原因并保留当前安全场景；不能交付半张不可达地图或偷偷删去必需房间。

## 8. 代码职责与实施顺序

先放在现有 `FPSGAME` 模块的 `Dungeon/` 目录，当前依赖已经有 Core、Json、AI 与导航；暂不增加独立插件或第二套地图框架。

| 拟建单元 | 职责 | 不承担 |
| --- | --- | --- |
| `FDungeonLayoutGenerator` | 纯数据房间图、位置、连接、约束及失败原因 | Actor、贴图和游戏世界访问 |
| `UDungeonRoomTemplate` / Profile | 接口、布局、锚点、软资产引用与配置版本 | 运行中清房状态 |
| `ADungeonAssembler` | 外壳与模板实例、碰撞、导航就绪、局部加载 | 掉落结算和拓扑重新抽取 |
| `UDungeonRunSubsystem` | 局内标识、探索、遭遇进度、存档及结束 | 美术散点 |
| `UDungeonEncounterComponent` | 敌群、波次、清房通知和战斗门 | 全图生成 |

职责依赖：配置 → 纯布局 → 装配；Run 管理本局并消费遭遇结果；美术布置只消费房间和锚点。PCG 可以用于后续室内装饰，首版主路线由纯数据生成器负责。

实施顺序：

1. **规则与接口**：落实本文件、14 房档案和 6–8 个空间模板的连接器/净空定义。先用现有材质及简化结构。
2. **生成与可走通场景**：生成房间图、占位和走廊，接入独立生成宿主，接转场和导航。输出可见的房间编号与布局数据用于后续用户指定的调试。
3. **第一局玩法闭环**：接入三场主线普通战斗、精英、首领代理遭遇、两个支线、奖励和返回；存档及奖励去重同时接入。首领可以暂用现有适合的强敌，单独标记代理身份。
4. **美术覆盖与扩张**：把样板组合布景放进模板，按区域控制材质；随后增加双层、第二条楼梯和更大档案。正式 A–F 档位与旧版经济表单独对齐。

不将“生成了一张房间图”称为可玩地牢。第一局完成范围包括实际移动、导航、敌群、触发、奖励、返回与进度恢复。具体测试、种子覆盖和视觉验收只在用户明确要求时执行。
