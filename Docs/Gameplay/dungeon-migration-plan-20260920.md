## 0. 结论摘要

| 问题 | 结论 |
| --- | --- |
| ① 从"节点选路"改为"房间内自由探险" | 可行，且更适合 FPS。本质：从 **UI 玩法** 变成 **关卡玩法**。逻辑层（档位、事件、检定、奖励）几乎原样可搬；表现层（美术、关卡、性能）要重建，工作量全部转移到 3D 侧 |
| ② PCG 能否生成随机房间/路线/楼梯/多楼层 | **布局不要用 PCG**：房间图是"图约束 + 连通性"问题，PCG 没有求解器，且运行时不可离线验证。用**自研纯数值布局生成器 + 模块化装配**；PCG 只用于房间内的装饰散点 |
| ② 是否先积累美术资产 | **是，这是唯一的关键路径**。但顺序必须是：先锁"构件公约" → 做一套垂直切片（1 战斗房 + 走廊 + 楼梯 + 2F）→ 样板实测 → 再扩产。跳过公约直接量产，改一次尺寸就全部返工（门框尺寸统一化那轮已经付过学费） |
| ③ 30~60 间房的性能 | 可以做到，但直觉要修正：**真正贵的不是外壳几何，而是动态内容（灯/AI/物理）**。外壳建议常驻（HISM，封闭房间遮挡剔除天然有效）；动态内容按"房态机"流送；异步加载可行——转场遮罩预载主题包 + 房态预取 + 对象池 + 每帧配额 |

**三个必须在动工前拍板的硬约束**（详见 §5）：
1. **门洞尺寸 vs 怪物体型**——按现有门口径，HandBrain（高 204）与 PoisonMaggot（宽 140）过不了单开门；Witch/Nurse 过不了双开门。地牢门必须重新定尺寸。
2. **光照预算**——全工程 Lumen + 满墙火把是性能与观感的双重陷阱，先定"每房光源上限 + 地图级画质覆盖"。
3. **导航策略**——5 个 agent 档案 × 随机布局 × 动态烘焙，先裁剪地牢参战档案、定"一次烘焙 + 门阻断"策略。

## 1. 模式转换：节点选路 → 空间探索

### 1.1 原项目做了什么（事实）

- 35~40 节点的**有向分层图**（起点 → 9 层中间 → Boss），节点类型 combat 70% / event 30%，另有宝箱岔路、精英、奖励节点；玩家点节点进入，打完回图（`dungeon-map-system.js` / `dungeon-map-generator.js`）。
- 战斗节点**就地生成房间**：在一个 1024×1024 的竞技场里改 `WallSystem.walls` 围出房间（普通 1024、精英 1792、Boss 2048），刷怪、打完恢复。
- 迷雾（visited / revealed / hidden）、属性检定（基础 20%、夹 5–95%、80/20 软限）、5 个通用事件 + 3 套主题限定事件、"一局最少 N 场强制战斗"等规则都已定稿。
- 探索台 UI（v9–v16）是纯 2D 规划台：路线绘制、迷雾、档案、撤离/放弃。

### 1.2 迁移后改变的是什么

| 维度 | 原（2D 节点） | 新（3D 自由探索） |
| --- | --- | --- |
| 路线选择 | 在地图上点节点 | 在空间里选门、选岔路（决策保留，形式改变） |
| 房间 | 就地围墙的抽象房间 | 手工模板装配的真实房间 |
| 战斗 | 独立战斗场景，打完回图 | 房间内直接打，清房开门 |
| 事件 | DOM 对话框 | 场景内可交互道具 + 冷钢事件卡 |
| 信息 | 迷雾 + 档案面板 | 视野偷看（门/栅栏/拱门）+ 自动测绘地图 |
| 撤离 | 起点按钮 | 起点实体返回门 |

### 1.3 映射表（原项目 → 现状工程）

| 原项目 | 现状 UE 工程 | 处置 |
| --- | --- | --- |
| DungeonMapSystem 节点图 | 无 | **保留为数据层**：升级成 3D 房间图（含楼层），驱动生成器与地图 UI |
| 就地生成战斗房 | 无 | 改为"房间模板装配 + 房态激活"（§2、§4） |
| DungeonFogOfWar | 无 | 改为"探索测绘"：进房/开门揭示，驱动小地图 |
| 5 通用 + 限定事件、检定 | 六维属性已存在（`ColdSteelStatusModel`） | 事件数据迁 `Content/ColdSteelData/dungeon/`；检定沿用 roadmap 4.5 口径 |
| 波次 / 精英 / Boss / 宝箱岔路 | 8 种怪 + MonsterAI/BT 已存在 | 波次表 + 房间锁门；怪池按档位 |
| 钥匙 / 祭品 / 出征提交 | `anchorTokenA–F`、`OfferTribute`、`ApplyDungeonFormulaBuff` 已存在 | 沿用 roadmap 4.2/4.7 |
| 结算 / 奖励邮箱 / 事务 | A-B 双槽事务存档已存在 | 沿用 roadmap 4.8 |
| 探索台 UI（v9–v16） | — | **大半不进 3D**：保留出征面板；探索横幅可转做加载图；图内导航由小地图承接 |
| 时空特工入侵（追兵） | 无 | 二期再做（3D 里是实体追兵） |

**一句话**：这次迁移 = "规则数据搬运（便宜） + 表现层重建（昂贵）"。不要低估后者，也不要因为后者重做前者。

## 2. 地牢生成：PCG 的边界与推荐架构

### 2.1 PCG 能做什么、不能做什么

| PCG 擅长 | PCG 不擅长（本需求） |
| --- | --- |
| 表面散点、层次化铺设、样条/体积规则、运行时按需生成装饰 | 房间图约束（连通性、最短战斗路径、楼梯归属、死路预算）——没有图求解器，要自己写 C++ 节点，等于把生成器塞进 PCG 跑 |
| 房间**内部**的碎石/蛛网/杂物确定性散点（按房间种子） | 离线批量验证（1000 种子跑连通性检查），PCG 图跑不起来 |
| 与现有丘陵 PCG 一致的工作流 | 楼梯/多楼层的拓扑正确性（属布局层，不属散点层） |

结论：**布局用自研生成器，PCG 留给装饰**；一期装饰也可以直接由装配器确定性散点，PCG 留到需要"更有机"的层次时再上。

### 2.2 推荐架构：三层分离

1. **布局层 `FDungeonLayoutGenerator`（C++ 纯数据，不依赖场景）**
   输入：`DungeonSeed = StableHash(WorldSeed, DungeonId, Tier, AttemptIndex, GeneratorVersion)`。
   输出：`RoomList[{Id, Floor, Rect(x,y,w,h), Type, Doors[], Sockets}]` + `CorridorList` + `StairList` + `DoorList`（全为整数格坐标，可序列化、可离线校验）。
   约束（沿用原版规则 + 3D 新规则）：
   - 全连通（BFS 校验）；入口 → Boss 最短战斗路径 = 档位下限（保留 `shortestCombatPath` 概念）；
   - 环路 20–30%（回边，让回头路不等于原路）；
   - 层间至少 2 部楼梯；楼梯格正上方必须无房间冲突；
   - 死路只允许是宝箱/事件房，且有数量预算；
   - 生成失败换子种子，最多 8 次，仍失败报错——**不悄悄降级成不可达地图**（沿用工程既有规则）。
2. **模板层（DataAsset）**：每种房间类型的模块摆放清单（相对原点）、门槽、道具槽、怪点、事件锚点、灯槽、装饰种子。
3. **装配层（运行时）**：按布局展开模板 → 静态外壳写入 HISM；动态内容登记为"房态清单"，不生成逐件 Actor。

### 2.3 多楼层规则（v1 严格堆叠）

- 楼层 f = 0..N-1；房间占 (x, y, f)；**v1 用严格堆叠网格**（同 (x,y) 跨层的房间上下对齐），楼梯占"楼梯格"连接 `(x,y,f) ↔ (x,y,f+1)`（或相邻格）。
- 为什么严格堆叠：楼梯位置确定、楼板不打架、装配器简单、导航好烘。中庭/挑空（跨层结构 + 栏杆）留到二期，用专用模板。
- 层数建议：30–40 房 → 2–3 层；50–60 房 → 3–4 层。单层 10–15 房 + 走廊。

## 3. 美术资产：顺序与清单

### 3.1 顺序（不可颠倒）

```
锁公约（§3.2） → P0 构件一套 → 手工样板（1 战斗房 + 走廊 + 楼梯 + 2F + 门）
 → 通行验收（玩家 + 参战怪物：走楼梯、过门、寻路） → 才允许扩产
```

原项目自己的结论同样适用：**"先画结构底稿，再做环境美术；材质和装饰围绕已定结构制作，不允许改变道路出口。"**

### 3.2 构件公约（动工前必须锁定，改一条=全库返工）

| 项 | 建议初值 | 依据 |
| --- | --- | --- |
| 模块网格 | 200 cm | 与现有门/构件 200/240 系对齐 |
| 墙厚 | 20 cm | 与现有构件一致 |
| 净层高 | 战斗房 ≥ 360 cm、走廊 ≥ 300 cm | 最高怪 204（HandBrain）+ 相机/动作余量 |
| 层间高（楼板中到中） | 400 cm | 楼梯两跑切分 |
| **门洞** | **净宽 ≥ 200 cm、净高 ≥ 240 cm** | 覆盖全部参战怪（见 §5.1 算例）；现有门不够用 |
| 楼梯 | 步高 ≤ 30 cm、踏深 ≥ 30 cm、每跑 ≤ 12 步 + 平台 | 玩家与怪物 `MaxStepHeight = 40` 是硬约束 |
| 走廊净宽 | 300–400 cm | 双怪并行 + 走位 |
| 房间尺寸档 | 战斗 16~24 m、精英 28~36 m、Boss 40~52 m | roadmap 草案；先小后大，样板实测后定型 |

### 3.3 资产清单

**P0（垂直切片必需）**
- 墙：直线 400×400、内角、外角、T 字、十字、门洞墙、**拱门墙（无门，视线通道）**
- 地板 / 天花板：400×400（或 200×200 细分）
- 楼梯：U 型双跑模块（≈4.4×2.8 m 占格、升 4 m）+ 直跑半段 + 平台 + 栏杆
- 门：地牢门（木/铁，净 200×240）+ Boss 双开 + 栅栏门（可透视）
- 道具：墙火把、壁灯、宝箱、木桶木箱、碎石堆、骨堆、铁链挂饰
- **事件道具（首批 5 通用事件）**：女神像、恶魔像、补给堆、陷阱（地压板/绊线）、宝箱（可复用 `ChestZiarat`）
- 主题材质：1 套暗砖（可换色）+ 贴花组

**P1（扩产）**：破损/塌方变体、阳台栏杆、锁门/机关门、矿车、储物架、符文石、祭坛。
**P2（主题化）**：矿洞、地堡（可复用 `Content/MilitaryTrench`）、神殿（可复用 Roman 柱/喷泉族）。

**来源**：结构件走 Vibe3D 规则几何；门系统 / 宝箱 / 罗马族 / 战壕套件复用；Fab 补道具（沿用 VaultCache 许可流程）。**材质基准用"暗砖"**（最中性的可换色底），沿用原项目结论。

## 4. 性能：房间级激活与流送

### 4.1 成本结构（先认清什么贵）

| 项 | 量级 | 结论 |
| --- | --- | --- |
| 静态外壳（墙/地/顶/楼梯） | 60 房 ≈ 2–3 万实例 | 走 **HISM 常驻**；封闭房间遮挡剔除天然有效；超预算再开"簇级可见性"降级开关 |
| 动态光源 | 每房 4–8 支 | **最贵**。Lumen 下动态光数量直接决定开销；灯随房态亮，地图级画质覆盖 |
| 怪物 AI | 每房波次 5–15 | 正常预算内；活动房 ≤ 5 时峰值可控 |
| 物理/残骸 | 少量 | 池化即可 |
| 导航烘焙 | 5 agent × 随机布局 | 装配后**一次**整体烘，关门用 NavModifier 阻断，不逐房重烘 |

### 4.2 三层策略

**A. 外壳常驻（默认）**
装配时把全部静态件写入 HISM（按 网格×材质 分组，全地牢 10–30 个组件、2 万实例量级）。**不逐房流送外壳**——封闭房间几乎看不到隔壁，流送收益小、复杂度高。
降级开关：按"楼层×簇"拆 HISM，用可见性开关做簇级流送（一个开关，不动布局）。

**B. 房态机（动态内容）**

```
Dormant(仅外壳) → Armed(道具/灯/门/宝箱就位) → Active(怪+锁门+波次) → Cleared(保留 loot 状态)
```

- 触发：**接近门（N 米内或开始交互）+ 开门动作**；
- 驻留集合：当前房 + 通过开启的门**可见**的房 + 相邻房 = Armed；更远 = Dormant；
- 清房远离后可回收为 Dormant（动态内容入池），loot/事件状态单独存。

**C. 池化 + 每帧配额**
怪物、投掷物、残骸、音源全池化；spawn 走预算（参考既有 `fps.Building.SpawnsPerFrame = 8` 模式）。目标：装配/激活单帧 ≤ 8 ms，无单帧 > 33 ms。

### 4.3 异步加载（回答"是否可行"：可行，且必须）

- 全部内容资产**软引用**；进入地牢时在现有转场遮罩（`UTransitLoadingSubsystem`，带进度与取消）里预载"主题包 + 出生簇"；
- 运行期按房态异步取句柄；**未就绪不激活怪**（先出道具和门，怪后到）；
- 复用丘陵的 **CVar 覆盖模式**（`TemperateHillsStreaming` 的 `FCVarOverride`）：进地牢调 `s.AsyncLoadingTimeLimit`、`pcg.FrameTime` 等，返回主城恢复；
- 为什么不是"门前才加载"：门一开玩家就看到房内，内容必须已就位，宁可提前 1–2 秒，不可晚一帧。

### 4.4 光照策略（Lumen 下）

- 火把 = 小半径动态点光（尽量不投影）+ **自发光材质 + 光晕贴片**承担视觉；
- 灯只在 Armed/Active 房点亮——门是唯一视线通道，Lumen 的变化天然被遮挡，不会穿帮；
- 地图级 CVar 覆盖：Lumen 质量档、阴影距离、RT 特性按地牢下调（沿用既有覆盖模式）。

### 4.5 导航策略

- 随机布局 → 动态 `RecastNavMesh`；**装配完成后整体烘一次**（摊在转场/出生缓冲期）；
- 关闭的门用 NavModifier/NavArea 阻断，避免全图重烘；
- **裁剪 agent 档案**：地牢只用实际参战的 2–3 档（现有 5 档：Nurse/HandBrain/PoisonMaggot/Witch+默认）。

### 4.6 预算表

| 项 | 目标 |
| --- | --- |
| 单房动态内容 | 怪 ≤ 15（峰值）、动态点光 ≤ 6、可交互道具 ≤ 3、装饰 ≤ 40 |
| 同时 Armed 房 | ≤ 5 |
| 全地牢静态实例 | ≤ 3 万（HISM）；超预算走簇级开关 |
| 装配/激活 | 单帧 ≤ 8 ms；无单帧 > 33 ms |
| 转场预载 | 主题包 + 出生簇，在现有遮罩内完成 |

## 5. 盲点清单（你没提但会咬人的）

**5.1 门洞与怪物体型（最硬）**
现有口径：双开门洞口 **184×184**；单开门净宽 ≈ 104（120 框减边梃）、高 ≈ 224。怪物档案：HandBrain 半径 62 / 高 204、Witch 34 / 192、Nurse 34 / 184、PoisonMaggot 70 / 140（`Config/DefaultEngine.ini`）。
算包络：单开门过不了 HandBrain（需 124 宽）和 PoisonMaggot（需 140 宽）；双开门过不了 HandBrain 和 Witch（需 ≥ 204/192 高）。
→ **地牢门必须重新定尺寸（建议净 200×240）**；并先拍板"哪些怪能进地牢"。

**5.2 楼梯与 AI**：现有 `MonsterStairAudit` + `run_stair_acceptance.ps1` 已在测怪物走楼梯——把地牢楼梯模块纳入同一夹具，先验后量产。

**5.3 导航网格**：见 §4.5；5 档全开 × 随机布局不可取。

**5.4 Lumen 与火把**：见 §4.4；最坏情况"60 房 × 8 灯全亮"必炸，提前定规则。

**5.5 自动地图**：roadmap 已列小地图 HUD，自由探索下规则要重定义——进入/开门测绘，未探索空白；原迷雾三态直接映射。

**5.6 存档与续玩**：只存 `seed + 房态 + loot/事件结算`；重进按 seed 重生成（生成器必须版本化——`GeneratorVersion` 已在种子哈希里）。断线/崩溃走"进入提交点"回滚（原项目教训 + roadmap 4.2 已列）。

**5.7 撤离与返程**：起点放实体返回门（安全撤离仅起点可用，沿用原规则）；Boss 后开直达出口——否则 3 层回程是纯步行成本；环路设计（20–30% 回边）让回程有变化。

**5.8 节奏（房间数 × 时长）**：30–40 房按 50% 战斗 = 15–20 场战斗，单局 25–40 分钟，超出 roadmap 的 D/C 目标（20–30 分钟）。**建议按"最短路径战斗场数"控节奏，而不是按总房数**——原版就有 `shortestCombatPath` 概念，保留它。

**5.9 怪物池 × 档位 × 体型**：把原版"按阶级匹配怪种"翻译成现有 8 怪的池子；大体型怪要么禁入地牢，要么只出现在大房间。

**5.10 事件表现成本**：水淹/塌方类环境事件最贵（水网格/物理），一期不做；5 个通用事件纯"道具 + UI + 检定"，零新增系统。

**5.11 音效**：房间混响/氛围/门声/火把循环，按房态开关；沿用现有音频管线。

**5.12 调试工具**：`fps.Dungeon.*` 控制台（生成指定 seed、传送、揭示地图、房态打印、强制激活）+ 离线布局验签（1000 种子）；与工程 audit 文化一致，建议一开始就建。

**5.13 语义隔离**：地牢是 Static Mesh 关卡——不用 20 cm 建造体素、不用丘陵高度场、不用已退役的体素地形（写进技能/规则文档防串线）。

## 8. 验收与测试方法（沿用工程 audit 文化）

- **离线**：布局生成器 1000 种子批量校验（连通/最短路径/楼梯/死路/环路/尺寸）。
- **实机 audit**：扩展 `MonsterStairAudit` 为"地牢通行审计"（每种参战怪：起点 → Boss 跨层寻路，检查卡死/门洞/楼梯）；流送审计（房态切换帧耗时）；光照预算审计。
- **压力**：60 房 + 全探索回程 + 战斗峰值。
- **用户实机验收**：观感、手感、节奏（按项目规则，最终由用户拍板）。
