# 地牢小件：成堆、侧倒与斜靠

## 目标

用户反馈现有小件仍像按标准间隔散布。此次直接改进生成算法：疏密不一的局部小堆、适合物件的侧倒姿态、有支撑的叠放和斜靠；继续避让门洞、主路、平台边缘、栏杆、管道和固定设施。复用 ArtPass20260922 的网格与原材质，不新增下载资源。

## 分布与姿态

- 不再用所有小件的外接圆半径之和圈出一圈位置。每堆共享随机散落方向，近处密集、末端偶有离散物，实际重试可以依附已经落定的其他小件。
- 取消候选间统一的 8 cm 包围盒排斥；最终使用实际网格三角形顶点形成的完整凸包进行保守体积排斥。空隙不再由倾斜物件膨胀后的轴对齐大包围盒决定。
- 桶、灭火器和提灯可以侧倒，绕长轴再随机转动，避免所有倒地物件都露出同一面。湿区、货运区和坍塌区侧倒概率为 55%，其他区 35%；这些是候选概率，最终还要满足空间与支撑约束。
- 货运区可形成双桶和混合杂物堆；盘绳、水桶、提灯等尝试叠放在已成功放下的油桶或盘绳上。最多两层附加叠放，总高不超过 170 cm，不把空水桶、梯子横杆、提灯把手当平台。
- 斜靠姿态为 12–29 度，朝向已落地的油桶；先保持底部接触地板，再沿接近方向求不相交的侧面接触位置。支撑桶太矮、未成功生成或侧面接触不足时拒绝。
- 一件最多 12 次实际位置/姿态尝试；前 5 次可尝试指定的叠放或斜靠，随后退回同一小堆附近的正常落地姿态。仍无合法位置就舍弃，不强行重叠。
- 普通房上限 16 件、宝箱房 7 件、Boss 房 26 件；数量是预算，不要求填满。原有人字梯每房最多一架，蛛网仍沿用墙面附着流程。

## 接触和空间约束

1. 每种已加载小件只提取一次 cooked 三角形数据并构建完整凸包；不使用简化凸包。坐标、比例和离轴枢轴随真实资产处理。缺少可查询数据时跳过，不猜碰撞形状。
2. 落地仍使用当前房间、当前楼层的地面 9 点查询，搜索范围为作者高度上下 12 cm。底部按旋转后的实际凸包最低点落在支撑面上方 2 mm，不能穿过二楼去寻找一楼。
3. 叠放只依赖已经成功放置的下层物件。上层足迹要位于支撑范围内，并从真实下层三角面取得多点接触；接触点必须环绕估计重心，顶面坡度和高差受限。凸包封住的孔洞本身不算支撑面。
4. 斜靠必须同时有地面接触和足够高的侧向支撑；侧面采用有界二分接近，最终仍参与完整体积排斥。
5. 摆件之间用凸包 GJK 查询；与房间结构用凸包对实际三角形查询，并保留封闭实体内部判定。不同缩放的房间零件通过逐顶点坐标转换处理。宝箱等固定物件仍使用保守范围。
6. 每次接触调整后重新应用原门口、主路、战斗点及整层禁放区。主体失败后，其依赖小件不独自生成；主体因避让移动时，附属小件跟随主体实际位置。

## 生命周期与性能

继续使用独立的房间装饰种子流，相同种子可复现，不改变随机路线和 Boss 终点。所有计算都在现有进入地牢加载阶段完成，接入分帧队列；一件的有界接触计算仍可能超过软时间预算，不声称实测加载耗时下降。

最终仍是静态装饰，不开启运行时刚体、玩家碰撞或 Tick，也不影响导航。形状缓存和临时接触数据归本轮 `FAuthoredDungeonBuildState` 所有，提交/取消后随其释放；网格生命周期由已有资源引用维持。仅现有单机生成路径生效，未增加 Blueprint 公共 API 或改动存档结构。

指标新增实际叠放、斜靠、侧倒数量与位置尝试数，分别为 `dressing_stacked`、`dressing_leaning`、`dressing_fallen`、`dressing_placement_attempts`。这些是运行计数，不是本轮已经取得的测试结果。
