# 废弃设施光影、贴地雾与地面导向升级计划

日期：2026-11-07。本文件保留最初方案；用户随后授权全设施制作，当前落盘和构建状态见 [制作与交付记录](facility-atmosphere-upgrade-20261107.md)。方案阶段未修改源码、关卡或资产，也未启动 UE、运行测试或生成预览。

目标：保留地下工业设施的空间和战斗可读性，通过有来源的光、薄雾、磨损标线及使用痕迹，形成长期停用但仍有局部设备运作的压迫氛围。参考《死亡空间 重制版》的环境组织方法，由本项目自己的设施、道具和路线承载。

## 1. 参考方向与工程基础

EA 的美术开发介绍强调恐怖、沉浸和有人使用过的环境，并将灯具、实时光照、烟雾和环境变化共同组织；GDC 的灯光团队分享也把灯具系统、灯光行为与调色作为整体制作问题。这里据此采用“功能光源—空间层次—局部空气介质—使用痕迹”的设计次序，而非照搬场景。[EA 美术开发介绍](https://www.ea.com/ea-studios/motive/amp/news/art-developer-livestream)、[GDC 灯光团队分享](https://www.gdcvault.com/play/1029020/-Dead-Space-Harnessing-the)

本轮读取的工程基础：

- `Dungeons/AuthoredDungeonLighting.cpp` 已有房间／门洞局部灯与几何调度，当前源码按本机视角处理，专用服务器不启动照明调度；已有滞后与渐变，应沿用。
- `AuthoredDungeonGenerator.cpp` 已支持灯具角色、阴影、距离、间接光与体积散射参数；`WardRoomAssembly.cpp` 已支持房间局部曝光、对比度与饱和度。
- 当前作者目录中，货运转运间、货运仓库、净化站、供电三室及部分楼梯已有地面标线，应做统一和补缺。该目录是制作输入，本轮没有读取编辑器内未保存状态，也不以它替代正式关卡资产快照。
- 两厅已有清洁桶、拖把、散纸、干涸痕迹与鞋印组合；接待厅新增沙发、茶几已按用户要求移除，本计划保留该取舍。
- 接待厅已有出怪门黑色内衬及门内雾幕。它承担隐藏门内细节的作用，持续保留；新环境薄雾单独制作。
- 已认可的主吊灯和廊下基础照明作为首轮基线。既有照明修复已强调楼梯、入口与下层回廊可读，不因风格升级重新制造暗区。

## 2. 场景表现标准

### 光影

每个空间分为功能照明、轮廓照明与少量异常光。功能照明照顾通路、楼梯和交互；侧光或背光交代门框、管线、栏杆和怪物轮廓；局部故障灯提供不稳定感。光源必须对应灯具、设备或门外空间，逐盏匹配出光方向和遮挡。

冷白工业照明承担主体，暖白／琥珀色承担维修和应急提示。暗区集中在侧室深处、设备后方及非通行边缘，保留清晰的前景通行面与中景识别对象。入口到深处形成明暗节奏，亮部也有局部层次。

先调整现有灯的角色、射程、遮挡和局部色温；保留大厅主灯效果，避免新增大量重叠光源。走廊与大厅之间的曝光连续性单独处理，防止进入暗处后整个房间被自动提亮。首轮不改全项目曝光或 Lumen／光追策略。

故障灯使用稀疏、不齐步的短暂变化，通路有稳定底光。整段熄灯、追逐事件和恐怖导演系统不属于本次美术升级。

### 贴地薄雾与空气层次

三种效果分开组织：

| 效果 | 拟用位置 | 表现要求 |
| --- | --- | --- |
| 贴地冷雾 | 排水低点、冷凝管附近、设备底部、湿冷门口 | 初始美术目标为离地约 15–35 cm，局部源头可稍高；分片缓慢流动，有断口和干燥空白 |
| 局部蒸汽 | 有残余压力的管口、维修泄漏、泵机／焚化设备 | 从真实开口喷出，短距离翻卷消散；强度与源头规模匹配 |
| 尘埃与稀薄光束 | 干燥大厅、档案区、生活区及高位灯下 | 通过少量颗粒和侧光显示空气深度，保留干燥感 |

主通路、楼梯边缘、拾取物和小型怪物周围保留可读窗口；普通雾使用低饱和灰白，颜色主要来自照明。绿色毒雾、危险地面和技能预警继续使用原有表现，装饰雾不能造成同样的危险信号。

优先采用低矮、软边、低重叠的局部 Niagara 薄雾和短时蒸汽。第一轮不做实时流体模拟、全厅浓雾或角色推动整片烟海。重点门洞／纵深空间再评估少量受光体积区。雾边界结合房间局部坐标、墙体和独立楼层，跨层大厅不共用一张水平雾面。

技术选择注意：UE 的 Local Fog Volume 是球形区域，不支持非均匀缩放；不能把它简单压扁成贴地长条。真正体积雾及其体积阴影有额外成本，快速变化光源还可能出现历史拖影，枪口闪光和故障灯对雾的贡献需单独限制。[Epic 局部雾文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/local-fog-volumes-in-unreal-engine)、[Epic 体积雾文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/volumetric-fog-in-unreal-engine)

### 地面标识与细节

| 元素 | 使用规则 |
| --- | --- |
| 导向线、箭头、区域名称 | 以磨损灰白地漆为主，关键入口配少量低饱和区域色；主线初始宽度建议 10–15 cm，按实际走道尺度调整 |
| 黄黑警戒边界 | 用于设备检修区、闸门开合区、装卸区和高差；标清真实危险或操作范围 |
| 工业编号与停放框 | 加强房间用途，如货位号、检修编号、推车停放框、禁堆区；数量克制 |
| 使用痕迹 | 轮胎／拖曳擦痕、鞋印、旧胶带、干涸水垢和局部补漆，与现有纸张、清洁工具及设备连接 |
| 表面变化 | 湿源附近有粗糙度差异和小范围反光，干区保留积灰与擦亮边缘；避免全地面镜面湿亮 |

标识必须依真实模块端口、当前布局连接与门状态制作，随机旋转、坡道和多层空间都按各自地面定位；静态区名不承诺门已开放。区分已生效的出口与封闭接口，避免箭头指墙或把每次随机路线画成固定地图。

已有标线先保留正确含义，再统一磨损、尺度和颜色。磨损沿通行轨迹、推车转弯和设备边缘形成，不用全表面均匀噪声。门口和转弯关键符号保持辨认，颜色同时配合文字／图形。

重复标识使用少量共用图集和静态实例；局部贴花限制投影深度与接收面，保留地面的原法线。近景新增格栅、检修盖只在轮廓需要时用几何，并继承现有碰撞规范。美术贴地层不改变导航、门扇或容器交互净空。

## 3. 全设施区域安排

覆盖固定地下入口、两厅、连接通道、当前目录中的六类主题区域、档案中心和最终首领区。六类主题表示可用区域类型，不意味着每局都会全部出现；具体投放服从当前生成布局。主神空间不在本次范围内。

| 区域 | 光影与空气 | 地面叙事与引导 |
| --- | --- | --- |
| 固定入口／连接通道 | 冷白功能光与少量暖色维修光交替，湿源处断续薄雾 | 接续原入口材质与遗迹破口；主通行线、检修编号、排水边缘 |
| 接待大厅 | 保留吊灯、廊下底光；入口与楼梯清楚，边缘局部冷凝雾 | 入口引导、旧排队边界、磨损地漆；中心保持开阔，不恢复已移除沙发茶几 |
| 中转大厅 | 高位轮廓、分路门口功能光、设备侧少量蒸汽 | 按实际连通方向布置分区文字与箭头，连接现有清洁和散纸现场 |
| 货运区 | 暖白装卸照明、较干空气，管道局部蒸汽 | 货位框、装卸警戒线、轮胎与拖车擦痕；复用既有标线 |
| 医疗区 | 偏冷白、低饱和空气，边缘局部薄雾 | 区域标识、推床轮迹、受潮纸张及清洁残留 |
| 焚化／处理区 | 暖橙设备光配稳定冷白检修光，设备附近有方向性的蒸汽／余烟 | 耐热警戒边界、滤材搬运痕迹、积灰和净化维护标识 |
| 供电区 | 偏冷功能光与少量琥珀警示，空气相对干燥 | 电气禁入框、检修编号、已有安全标线；仅已故障设备附近留少量异常痕迹 |
| 生活区 | 衰弱暖白光、稀薄尘埃，淋浴侧有冷凝感 | 日常磨损、足迹与少量残留用品，和工业区域形成节奏差异 |
| 生态区 | 湿润中性空气、培养灯的局部色彩 | 灌溉水垢、实验区边界、维护编号；雾保持中性以区别毒雾 |
| 档案中心／最终首领区 | 档案偏干冷、低密度尘埃；泵机区以强轮廓和设备排汽形成规模感 | 档案区识别清楚；首领场地保留回避路线、平台边缘和危险提示的可见度 |

## 4. 接入与性能边界

下列数值是首轮制作上限建议，不是已测得性能：

- 每个本地视角先限制为至多 4 组有效薄雾、2 处蒸汽；重点体积区默认关闭，后续单独试 1 处。粒子数量、尺寸、透明覆盖、纹理采样和重叠同时设上限。
- 首轮通过现有灯重新配光形成层次；为效果确需加灯时登记用途与所属房间，优先保持可见区域动态阴影灯数量不增加。
- 普通／低配置优先收减尘埃、烟层重叠与光束，地面导向、基础照明、门内遮蔽和伤害提示保留。
- 复用房间／门洞候选和共享特效调度，近处启用、边界渐隐、离开停模拟并释放。装饰效果不逐个增加 Actor Tick，不让相邻远房全时运行。
- 资源提前进入异步准备阶段，玩家走入通道时只启用已准备效果，不在刷怪触发点同步读取资源或编译材质。
- 每台客户端按本机视角裁减装饰；专用服务器不生成表现，装饰随机数独立于布局和战斗随机流。若接入现有门／设备状态，读服务端状态，不逐粒子联网。
- 使用模块 cells、端口、楼层与局部锚点限制烟雾；角色移动和镜头方向不改变伤害、寻路或怪物可见状态。
- 沿最新正式目录增量写入，并同步作者配方及 `extend_catalog.py` 重放链；不以旧目录整体覆盖已完成的场景调整。新增资源独立版本目录，可按本批字段回退。

此前的性能记录说明需要保留现有刷怪与资源准备成果，但历史采样不能代表当前性能。实际新增帧时、透明开销和首次进入慢帧需在用户要求性能检查时再采集；本计划不承诺固定 FPS 或零开销。

## 5. 分阶段实施

| 阶段 | 我负责的制作 | 交付与用户关注点 |
| --- | --- | --- |
| 第一阶段：入口与两厅试点 | 固定入口、接待厅、中转厅及一段连接通道；先配光与地面线，再加少量薄雾；各区域保留不同密度 | 可独立开关的本批效果、实际保存资产及配方。你体验明暗、脚下可读性、标线自然度和雾是否过浓 |
| 第二阶段：形成材质与特效模板 | 依据试点反馈确定磨损标线图集、薄雾／蒸汽／尘埃模板、灯光角色与室内曝光衔接 | 统一外观和可控参数，再扩展湿冷、干燥、炽热三个环境模板 |
| 第三阶段：按主题覆盖设施 | 将模板接到六类主题、过渡房、档案中心及最终区域，处理坡道、多层、转弯与旧标识 | 每类区域有独立气质，保留当前房间用途、战斗与通行空间 |
| 第四阶段：按反馈收敛 | 调整过浓区域、曝光跳变、遮挡和重复感；用户明确要求时再做同种子、同机位的性能比较 | 重点观察两厅刷怪、狭窄通道、快速转身、枪口闪光与多人分处不同区域的表现 |

原建议先实施第一阶段。2026-11-07 用户随后明确授权“按你建议全部做完，做完以后我来测试”，实施范围因此扩展到全设施；制作与落盘记录见 [本轮实施记录](facility-atmosphere-upgrade-20261107.md)。这里的用户关注点不是自动测试授权，继续默认后台构建、导入与保存，由用户体验。
