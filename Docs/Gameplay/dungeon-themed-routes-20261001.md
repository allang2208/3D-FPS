# 三条主题路线与货运仓库正式接入

2026-10-01，用户已确认货运仓库可用并授权接入与样板退役。本次只进行制作、必要编译、后台导入和保存；没有运行随机种子测试、PIE、游戏或渲染验收。

## 路线规则

正式地图为 `/Game/GameMaps/L_Dungeon_Randomized`，`AuthoredDungeonGenerator` 使用第 8 版目录。每次种子独立抽取主题与三个分支的对应关系，固定组合内部不抽换、不插入过渡房：

- 货运（按用户后续调整）：货运转运间的仓库连接版本 → 货运仓库 → 地下车站。
- 医疗：排水间 → 隔离病区 → 解剖教学剧场。
- 处理：破损支护室 → 焚化处理厅 → 烟气净化站。

公共入口前段使用 1–2 间基础设施房；按用户后续调整，每条主题组合之前和之后各自独立抽取 1–2 间基础设施房，即每条主题路线为“前置 1–2 间 + 固定 3 间 + 后置 1–2 间”。按 2026-10-01 后续要求，过渡池仅保留管线分配间、排水间、破损支护室、通风循环间。普通货运转运间家族退出随机池，只在货运固定组合中使用 `FreightTransfer_WarehouseLink`，避免相同装卸场景出现不同出口规则。已有重复惩罚继续使用。

房数口径：公共入口前段 1–2 间 + 三条分支各 5–7 间 + 数据档案中心 1 间 + Boss 房 1 间，共 18–25 间主要房间。选择一路通关会经过其中的 8–11 间。此数不包含固定起点、岔路/汇流前厅、楼梯、连接走廊、最终奖励室和随机宝箱侧室。各分支的前置与后置过渡槽独立抽取 1 或 2，两端均至少有一间过渡房。

当前实际入口为 `Source/FPSGAME/Dungeons/AuthoredDungeonThemedRoutes.inl::ConfigureThemedRoutes`。代码先根据种子打乱三组主题与分支的对应，再按 `RandRange(1,2)` 分配公共前段，按两次独立的 `RandRange(1,2)` 分配每条组合的前后过渡槽。核心顺序读取 `themed_routes.routes[].sequence`。过渡槽由 `AuthoredDungeonRoomChoices.inl::RoomChoices` 过滤至上述四类基础设施房并应用重复惩罚，然后进行真实门口与三维空间装配。旧版顶层 `min_rooms/max_rooms` 不决定主题模式下的公共前段数量；上述主题配置阶段覆盖它。

本次房数调整已完成原生 Editor 构建及正式地图配置保存，分别记录于 `Saved/BuildEditor/themed-route-counts-20261001.log` 与 `SourceAssets/DungeonThemedRoutes20261001/Receipts/transition-counts.json`。没有执行布局生成或游戏测试。

随机宝箱侧室沿用每个有合法侧门的普通房 10% 的独立尝试，实际还需能放入且不超通道预算；不保证每局出现。最终奖励室单独保留。

三个分支仍经过各自的真实下降楼梯，在现有汇流前厅会合，再唯一串联数据档案中心和原 Boss 场地。数据档案中心保留已认可的双端口主体，不另外打出三个入口。其出口闸门要求“任意一条主题分支全部清理 + 档案中心清理”；不要求三条分支全部完成。Boss 战与最终奖励门沿用原流程。

2026-10-01 后续修复：所有参与分支清除条件的房间均由进房遭遇完成整组刷怪，包含普通仓库和前后过渡房；普通房不新增封门，既有精英/主题封门战保留。避免普通延迟刷怪受玩家距离和远端名额占用影响，导致玩家清完眼前怪物仍缺少待生成槽位。详见 [档案出口与货运专用池修复](dungeon-archive-exit-and-freight-pool-20261001.md)。

## 空间与生成

主题和房间槽位在空间搜索前一次决定，空间回溯不得换掉主题核心。反向闭合搜索使用反向槽位索引；货运转运间连接版与仓库不能颠倒入口。组合之间只有既有真实通道，不插入其他房间；转运间与仓库只允许短直连。关闭跨分支回环，防止绕过闸门或核心房。

2026-10-01 用户进一步要求缩短连接并允许错层，已替代此前 60 米平面通道后备方案。前两次尝试平面布局；后续将完整主题组合分配到过渡房层的上方、同层或下方，优先尝试 ±16.2 米，再使用 ±10.8 / ±5.4 米的紧凑高差。主题房组前后通过带平台的折返坡道连接，固定三房内部与货运闸门直连规则不变。同层后备补接上限缩至 24 米；坡道连接按真实步行路径限长 46 米，最大的坡道壳体占地约 7×16 米，不能把折返步行距离视作直通道长度。坡道与连接段均不计入主要房数，暂不刷怪。配置、资产与落盘情况见 [错层坡道生成](dungeon-split-level-routing-20261001.md)。

保留工作线程规划、有界搜索和 12 秒期限、实际三维占用、门口尺寸/法线匹配、走行与通道预算。大型房间不再套用旧 48 米中路宽度提示，但没有放松实体重叠约束。无法完整嵌入时沿用既有失败处理，不提交缺房或断开的半成品。未测量本次成功率或耗时，不能据此宣称所有种子都能完成。

## 货运闸门

`FreightTransfer_WarehouseLink` 保留原转运间主体、装卸台、扶手和配套物件，关闭旧侧出口。原后墙闸门改为真实开口，后方用四级踏步将 60 cm 装卸台接回标准地坪，再收口至 300 × 280 cm 门口。

`ADungeonProgressionGate` 复用原精细分体闸门网格，清理所属房间后向上开启。货运版使用独立门罩收纳门叶；档案出口复用同一门叶。碰撞与门叶同步上升，打开后停用碰撞和 Tick；未开启阶段每 0.2 秒读取现有房间状态，不扫描世界 Actor。普通房间清理状态仍由现有遭遇系统报告，不伪造怪物死亡。

仓库生产配置从用户认可的保存地图提取实际静态网格、材质、位置、碰撞、栏杆标记与点光源，保留修订货架、清晰通道、拖车和地面标识。样板无限后处理转换为房间范围内的后处理。生成器按 `guardrail_drop` 的布尔值启用栏杆翻越；值为 false 的普通物件可以继续使用静态实例批次。
