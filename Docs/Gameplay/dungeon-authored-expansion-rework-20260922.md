## 撤回范围

## 本轮实际修改

原地图 `/Game/GameMaps/L_Dungeon_Prototype` 是完整母版。新候选 `/Game/GameMaps/L_Dungeon_AuthoredExpansion` 以 UE 原生复制保留 Actor、组件、材质覆盖、可见性、灯具和灯光参数、贴花以及工作台内部关系。不会重新用默认值拼一间“相似的”房间。

组合为 **两个完整样板段 + 一段 4 米检修连接通道**：

- A 段保持原位置；主走廊 22×4 米、低顶工作间、隔栅设备区、检修壁龛、侧向遗迹破口、折角与末端上升平台均保留。
- B 段只整体旋转 -90° 并平移到 `(2600,-1800,94)` cm；不缩放、不镜像、不重新散布小件。
- 连接取原末端检修门接口，沿门朝向通到 B 段入口。高度继承原平台 94 cm，门的尺度决定连接净宽，不把检修门扩成竞技场大门。
- 只为入口端墙、末端墙与检修门制作开口版本。它们从原可编辑结构和最新碎砖源复制，原 UE 网格不覆盖。保留墙面的 UV、材质槽与细节；检修门只移除连接处门板，保留门框。
- 连接通道有独立可编辑 Blender 源与材质映射，新增一盏有实体灯具对应的低亮度检修灯。原两段的光强单位、色温、范围和曝光不重设。

两个段落目前共用同一母版，因此存在内容重复。这是空间拼接候选，不宣称已经具备多种内容段落，也不再称为已完成的 14 房探索战斗地牢。

## 修正后的生成规则

```text
已认可的完整空间段
    + 段落入口/出口的位置、方向、净宽、标高
    + 段落占地与视线边界
    → 兼容接口对接
    → 完整段落的刚体变换
    → 在原有用途位置绑定探索、战斗、事件
```

生成单位不是通用矩形房壳。主走廊、侧开间与灯光构图组成不可拆散的设计单元。维修台仍在维修开间，设备仍在格栅后，遗迹仍通过侧向破口被发现。管线和排水随建筑段走，不通过随机设备填空表达“工业”。

14 个功能节点可以作为后续内容量目标，不能倒过来决定每处空间都变成一间方房。后续先补齐并列开间段、遮挡转折段、潮湿维修段、局部破损段等真正不同的母版，再让路线规则选择和组合。战斗与奖励框架应绑定这些空间提供的锚点，不改写其尺寸和构图。

## 用户反馈“没有新增内容”后的修复

上面的首次接入记录仅代表复制与保存，不能作为正确摆放或通行的结论。定向读取发现用户当时打开的是扩展地图，A、B 各有 164 个 Actor，但 B 段的实际旋转为 pitch -90°，整段向地下翻转。原因是 Python Rotator 的位置参数顺序被错误地当作 C++ 顺序使用。已改为 `Rotator(pitch=0, yaw=-90, roll=0)`，从 A 段的原始变换恢复 B 段。

还修复了两个接入问题：

- 对变换修改显式调用 Actor.modify，并按本地图路径单独保存外部 Actor 包。仅保存关卡而不标记这些包，会使重新打开后的姿态恢复为旧值。
- 原墙体包含多个相接壳体和修补面片，体积布尔产生堵口面或错误地保留门板。新连接件以六个开口平面裁切原多边形，并插值保留原 UV、材质槽和颜色，不覆盖母版。五处开口的源网格中心射线均已无阻挡，六个扩展网格已重新导入。

脚本：`fix_segment_rotation.py`、`reimport_connections.py`。操作记录：`rotation-fix-02.txt`、`reimport-connections-02.txt`。这次按用户反馈进行定向排查，不将其扩展为全场景视觉或战斗验收。
