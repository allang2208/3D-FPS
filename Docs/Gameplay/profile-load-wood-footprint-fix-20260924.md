# 背包／仓库同时清空的读取回归修复

用户反馈 F6 生成物品提示“当前玩家数据不可写入”，背包和仓库均为空。

## 原因

2026-09-24 的木材调整在 `ColdSteelInventoryRules.cpp::BaseFootprint` 中将 `wood` 固定为 1×2。旧角色档仍含 1×1 木材；`ReloadProfile` 在候选 A/B 档中先调用严格 `Validate`，而木材尺寸迁移位于选中存档之后。两份档案因此在 `Footprint != (Width, Height)` 分支被拒绝，永远无法执行已有迁移。

`Initialize` 已发布的空初始状态留在界面中，`bPersistenceBlocked` 又阻止了物品生成和保存。这是加载被拒绝，并非已证实物品被删除。问题关联木材占格修改，不是手模材质或冶炼建筑档案的版本号。

## 保留与修复

- 修改前保存 `ColdSteelPlayer_A/B.sav` 与两份 SHA1 到 `Saved/SaveRecovery20260924/OriginalSlots`；不覆盖备份，也不直接改写玩家存档。
- 校验哈希并反序列化后，先以明确允许旧 1×1 木材的加载规则检查原布局；其他数据、数量、重复 ID 和占格冲突仍严格拒绝。
- 在内存副本中将旧木材迁移到当前占格。优先保持原格，必要时在原容器找空位；容器已满则将该木材保留到主仓库，按需增加仓库页。保留实例 ID、数量和实例属性。
- 完整迁移通过当前严格校验后才参与 A/B 最新代选择；选中的迁移通过现有校验写回事务保存。普通移动和保存没有放宽校验。
- 为后续读取故障保留带槽位及拒绝原因的日志。

`ColdSteelProfileRead` 是只读诊断 commandlet：不创建 GameInstance，不写存档，仅报告原始严格校验结果和同一迁移函数的内存结果。检查物品字段保持情况及二次迁移是否重复修改；输出 `Saved/SaveRecovery20260924/profile-diagnosis.txt`。
