# 地牢随机性 V3：房间家族、动线变体与路线变化

日期：2026-09-24。状态：设计提案，尚未批准实施；本轮只读源码与目录、查阅一手资料并记录方案，没有修改生成器或地图，没有启动 UE、游戏或测试。

## 判断与取舍

推荐组合推进用户的两个方向：先让五种现有房间各自具有不同的内部走法和受约束的结构形态，再按缺少的空间体验增加少量新房。第一阶段不直接扩到十五种独立主题房。

玩家可感知的变化包括入口第一眼、出口相对位置、可走路线、视线遮挡、遭遇内容和整个关卡的路线结构。单纯改变世界朝向、墙皮或杂物种子，不能覆盖这些变化。结构变体也不能仅凭组合数量宣称等于同数量的全新房间。

## 当前实现依据

- 当前 `SourceAssets/DungeonRoutes20260922/Config/catalog.json` 的 `room_ids` 是 Distribution、Drainage、ShoredBreach、VentilationLoop、FreightTransfer，共五类普通房。连接、宝箱和 Boss 模块不计入这个数量。
- `AuthoredDungeonGenerator.cpp` 的 `Fit` 按门口法向计算旋转；`Chain` 已枚举两个端口作为入口。再次添加整体转向开关的增益有限。
- 每类普通房目前有两个主要端口，另有宝箱侧门；不能把侧门直接作为普通主路线出口使用。现有搜索多处使用 `1 - Entry` 取得另一端，扩展可选门位时需要一起改为显式的合法入口/出口组合。
- `AuthoredDungeonCompactRouting.inl::BuildCompact` 仍生成前段、一个枢纽、三条支路，再向地下终点汇合。组内房间数为 3–5。
- `BridgeRooms` 的评分包含目标距离、末端朝向、上一房间重复惩罚和随机项；`Chain` 没有相同的重复惩罚。缺少统一的房间家族使用配额和跨局记忆。连接评分可能偏向更容易接通的形态；这是代码结构上的推断，没有运行分布统计。
- 当前已启用地下 Boss、最终宝箱房、表面变体与独立装饰随机。新方案保留这些工作及地板、碰撞、导航准备完成后才释放玩家的顺序。

2026-09-20 的旧方案包含全自动格子造房与粗略工期判断，其路线与后续认可的完整作者房间不同。本提案以当前作者房间和接口公约为基础，不沿用旧方案的工期与性能承诺。

## 六层变化

| 层次 | 建议变化 | 对玩家的意义 | 开发次序 |
|---|---|---|---|
| 房间家族与选取 | 使用配额、最近使用降权、控制相邻重复 | 减少刚见过的房间立刻再出现 | 第一阶段 |
| 内部动线与门位 | 隔断、机组、桥位、入口/出口组合 | 同一个主题需要重新观察和选择走法 | 第一阶段 |
| 有限结构形态 | 侧室换边、局部退台、L 形方向、宽深比例 | 改变空间轮廓和第一眼构图 | 第一阶段 |
| 整局路线 | 双路汇合、长短支路、短回环、支路捷径 | 打破每次同样的分岔节奏 | 第二阶段 |
| 内容与事件 | 检修、污染、伏击、精英、资源选择 | 相同空间发生不同事情 | 第二阶段 |
| 新空间家族 | 轨道检修、净水、档案等少量新增 | 补足既有模板无法表达的空间体验 | 第三阶段 |

## 方向一：受约束的结构变化

采用“稳定接口 + 可变结构区域 + 成组设备与管线”的房间家族。

- **稳定部分：** 接口净宽 300 cm、净高 280 cm、接地标高、门口安全通行区，以及楼梯的踏步尺寸。变更门位时同步选择对应墙体开口和端口配方。
- **可变部分：** 侧室在左/右、墙段局部内收、主空间宽深比例、检修槽与桥的位置、机组偏置、非承重隔断、上层平台沿左墙或右墙布置。
- **关联部分：** 墙、楼板、栏杆、楼梯、支架、管道、灯具和锚点由同一配方生成。平台换边时整组迁移，不能只移动平台模型。
- **尺度约束：** 建议第一版单房总可走面积控制在母版约 ±10%，整体占地长宽也各自设上限；主路净宽沿用当前房型的要求。±10% 是初始设计范围，尚未测量验收。局部高度变化必须由完整平台/楼梯组合承担。
- **方向变化：** 首批使用合法门位组合和 90° 刚体拼接。左右版本在作者阶段制作，避免运行时负缩放把文字、机械细节、碰撞一并翻转。

第一版在后台按参数制作有限形态，生成器挑选现成结构；不在玩家推进途中重新切墙、挖楼板或煮碰撞。后续可将稳定的墙段/设备拆成共享构件，但拆分时控制实例和材质数量。

### 五个现有家族可怎样变化

| 家族 | 保留身份 | 可以产生实质差异的形态 |
|---|---|---|
| 管线分配间 | 低顶设备凹室、沿墙管线 | 凹室左/右；主空间宽短/窄长；设备形成单侧通行或中央分流 |
| 排水检修室 | 沟槽、检修桥、护栏 | 中段横桥；偏端横桥；两段桥形成折线穿越；各版成组更新坑口护栏 |
| 破损支护室 | 支护结构、破口与石质侧穴 | 左折/右折；先看到支护再看到破口；破口位于路线侧面或末端 |
| 环廊通风机房 | 贯顶机芯、维护环廊 | 机芯居中形成双侧绕行；偏置形成宽窄两路；部分隔断改变视线但保留可达环路 |
| 错层货运中转间 | 货梯门、卸货台、搬运设备 | 月台靠左/右；双端台阶/同侧双梯；货物集中在两个不同作业区，保留低位贯通路线 |

这些是候选设计，不要求每一种内部配置都与每一种结构组合兼容。按标签维护允许组合，避免把复杂度变成无法维护的全排列。

## 方向三：改变“从哪里进、怎样走出去”

同一间房整体旋转后，玩家若依然从同一扇门看到同一个机组正面，体感差异很小。因此门位和主视线优先于绝对朝向。

为房间定义合法 `port_pairs`：对侧进入/离开、相邻墙进入/离开、绕过核心后离开。每组端口绑定正确的墙体开口、闭合墙段、灯光提示和内容锚点。先定通行骨架，再放大件，最后撒小物。

以排水室为首批样例：第一次从长边看到沟槽，横桥在中间；第二次从短边进入，桥靠另一端，需要沿沟边推进；第三次经过两段错开的桥，在转角重新观察。三次仍能认出“排水检修室”，但不能完全沿用同一条背板路线。

## 方向四：整局路线也进入随机池

提出三种初始路线配方，控制主路径总长度和有效房间数在相近范围：

1. **双路汇合：** 两条侧重点不同的路汇入下降入口；原三条入口中的未使用口由完整闭合模块封住。
2. **主路 + 风险短支线：** 主路直接推进；一条较短支线包含精英/奖励并接回主路，减少原路折返。
3. **不对称三路：** 保留现有骨架，支路长度和内容职责不同，其中一条含短捷径，不再三条都承担同样的清房流程。

所有方案仍通过汇流与下降设施到地下二层 Boss。Boss 战后机械门打开，进入最终宝箱房并可返回基地。可选支线不会绕过 Boss 进入最终奖励；不默认增加“三路必须全部清完”的门禁。

路线先决定连接关系，再布置空间，延续地下 Boss 的紧凑终点预留和连接长度上限。放不下就尝试同家族其他结构或回溯最近的节点；不得用越来越长的空走廊完成闭合。

## 方向五：事件与节奏变化

选择与建筑用途一致的状态，而不是给每间房随机加同一套特效。例如通风室的滤芯检修、排水室的局部蒸汽、货运间的停运/临时堆货、支护室的搜集点。

首批可做三类内容：普通巡游遭遇、局部伏击、带额外风险的物资点。进阶再做启动设备后守住位置、选择消耗资源打开捷径、精英守护可选箱。每类内容绑定合法锚点、敌人可达路径和通路限制，不能只替换敌人数值。

低照度状态仍保证通路可读，不把先前黑场问题当成氛围。事件资源沿用房间灯光调度和装饰清空区。后续“导演”只调度遭遇间隔与组合，维持明确难度预算；不用隐藏的临时血量/伤害补偿抵消玩家成长。

## 方向二：新增房型的推荐顺序

先从五类扩到八类，依据缺少的空间体验选题：

- **轨道/电缆检修间：** 纵向视线、横向设备遮挡、两侧维护带；长度仍受普通房面积预算限制。
- **蓄水过滤室：** 环形或半环形步道、多处可见但不可直接抵达的设备，提供跨侧观察与选择路线。
- **档案/备件库：** 有序货架形成短视线与交错小通路；按玩家与敌人体型留出通道，避免遍地小件替代结构设计。

这些名称只是主题提案；新房首先需要不同的路线和视线结构，再进行高精度美术。八类覆盖仍明显不足时再扩到十至十五类，不按数量平均分配建模工作。

## 算法建议

主算法使用“路线规则 + 有预算的约束搜索 + 房间家族抽取”。现有占位 `cells`、端口兼容、紧凑桥接搜索可以继续使用；WFC 可留作将来局部墙片的邻接选择，不作为当前全局 Boss 路线的首选。

```text
运行种子
  → 选择路线配方与节点职责
  → 按配额和近期使用情况挑选房间家族
  → 选择合法结构形态、门位组合和内部配置
  → 计算真实占位与连接长度，必要时有限回溯
  → 绑定匹配的遭遇/事件与环境状态
  → 从独立随机流选择表面和杂物
  → 预载本次用到的资源，准备地板/碰撞/导航
  → 通过现有加载流程释放玩家
```

选择分成两层：先选家族，再在家族内选变体。避免某一家族拥有更多模型，就意外取得更多抽中机会。候选按兼容性过滤；家族使用次数、近期组合重复、路径长度和连接代价进入评分。同一家族相邻出现通常排除；放置失败时先换变体/回溯，在有限预算内降级到已知可装配配方，而不是无限重试。

若加入“最近几局少重复”，历史应使用玩家实际进入的房间组合，不能把未探索的支路也记为见过；同时记录历史快照/算法版本，使同种子复现含义明确。第一阶段先实施局内配额与重复抑制，跨局存储单独安排。

资源层面把打包可发现与运行时预载分开：目录扩大不能简单把所有家族、结构和装饰变体全部作为启动常驻资源。共享材质/构件，生成计划确定后只请求本次选中的资产，保留现有分阶段预算。当前 `ModuleAssets` 硬引用较多，扩容时需一并安排资源清单与预载策略；这不是已经完成的优化。

## 分阶段交付建议

1. **先做两个家族的样板。** 排水室、通风室各保留原版并新增两种实质动线/结构形态，共六种结构配置；完善合法端口对、内部大件锚点和家族抽取。
2. **推广到现有五类。** 目标五类 × 三形态 = 十五种结构配置，复用材质与核心构件。根据适配程度增加两套内部陈设，而不要求全排列。此时仍是五个主题家族。
3. **增加整局变化。** 接入三种路线配方，先做三类遭遇/事件；控制空走廊长度、回溯预算和不同路线的行走负担。
4. **按体验缺口扩到八类。** 再决定十或十五类是否值得制作。接受范围由用户游玩反馈确定，不自动触发测试或启动游戏。

首阶段验收关注入口构图和实际走法是否变化、房间大小与现有风格是否一致、主通路是否清楚，以及地下 Boss 和最终奖励流程是否保留。具体实现和用户体验尚未发生，不承诺随机数量等于体验数量或性能无成本。
