# 清怪推进闸门与刷怪等待互锁修复

用户反馈：车站主题路线首个货运房的出口闸门在击杀后仍不打开，无法继续进入仓库。

## 本次故障证据

用户运行日志 `Saved/Logs/FPSGAME.log`，Seed=383016320，RunId=383016320-F1FC8A53：节点 14 仅有槽 0 的 FatZombie 生成记录（14:33:47 UTC）；14:36:36 登记该房警报并击杀 FatZombie_2，后续没有该房清除记录。其他节点已有正常清除记录。读取时该地牢 PIE 已结束，未获得该房最终内存槽位快照，未重新启动游戏复现。

目录中 `FreightTransfer_WarehouseLink` 配置 2–4 只怪、`sealed_encounter=false`，并带 `progression_gate`。此前普通刷怪路径会在距房心不足 1500 cm 时跳过整房；落点还要求离玩家至少 1500 cm 且被遮挡。房间只生成部分编成后，玩家进入并击杀现有怪物，剩余槽位可一直等待。`CheckRoomCleared` 正确地阻止有待生成槽位的房间清除，推进门因而持续等待。问题在推进房刷怪策略和清除条件的配合，不是把死亡尸体算作存活。

## 修改

- `DungeonRunSubsystem::ParseCatalog` 从装配器同源的 `progression_gate` 派生运行时 `progression_encounter`，复制顶层刷怪配置，不修改已保存目录或共享嵌套数据。不写死房间名称。
- 刷怪导演把这类房交给现有 `DungeonRoomEncounter`：进房启动整组生成、使用遭遇预留容量、完成全部槽位且无存活怪后登记清除。保留编成、等级、品阶、导航和实体碰撞落点规则。
- `Configure` 新增普通 C++ 可选参数 `bSealConnectedDoors`；推进房传 false，不额外添加封锁入口的格栅。原推进门仍负责出口，原精英封门房默认行为不变。未新增反射成员、Actor 类或每帧全场扫描。
- 推进房没有候选落点时进入现有遭遇的明确放弃流程，而不是直接丢掉清除责任；显式抽到零怪时登记为空波次完成。真实落点失败仍用已有三次重试，不把尚未生成的正常怪物直接算作击杀。
- 推进门实际满足条件开始上升时记录节点和门名，便于区分后续的清怪等待与门体碰撞问题。
- 数据档案中心使用相同推进门配置，因此同步获得进房遭遇处理；“任意一路打通并清完档案中心才开放 Boss 出口”条件不变。
