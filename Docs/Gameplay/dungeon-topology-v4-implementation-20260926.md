# 随机地牢 V4 首批实现与近期缺陷修复

日期：2026-09-26。范围：落实 V4 提案的路线分配、通道选择、额外回路，以及 9 月 25—26 日地牢链路排查。生产代码仍为 `Source/FPSGAME/Dungeons/`。本批没有增加整套房间资产。

后续任务图、风险奖励、通风家族共享配方与多主门已继续实施，见 [后续实施与落盘记录](dungeon-v4-complete-20260926.md)。本文中的“后续阶段”保留首批交付时的历史边界。

## 已实现的变化

- `AuthoredDungeonTopology.inl` 在空间搜索之前确定四段房数及回路偏好。保留 3–5 间配置范围，给中路分配较短房数；可调整的等长分配会在总房数不变的条件下改为长短支路。搜索重试不重新抽取这一计划。
- 回路有跨支路、同支路返回、混合三种**偏好**，目标为 1 或 2 条。普通房使用已有的完整侧门墙体变体，放下两端接口及全部实体通道后才保留开口；失败恢复原墙。候选排序优先连通图距离较远、空间距离较近的普通房。
- 额外回路使用固定 512 次连接候选预算。每条仍不超过 12 m、两次转弯，最多两条新增连接；不连接 Boss/奖励区。实际可用侧门和空间不足时允许 0 条，`loop_count` 记录实际数，`loop_goal` 记录设计目标。
- 直线、单转角、双转角沿用现有网格。通道评分增加按位置/路线派生的种子偏好、连续类型重复代价和稳定扰动，继续计算长度及转弯代价，不任意拉伸房壳。
- 清单版本升至 4，包含真实入口节点、每个模块的占位 cells、连接门洞的位置/法线/尺寸、回路标记和原主线推进深度。灯光使用实际匹配入口，不再假定节点 0。
- 真实邻接/最短房间深度用于活动范围、警报和入口识别；`progression_depth` 排除额外回路，用于怪物等级、精英房选择和箱子等级。捷径不会降低既定推进阶段的奖励与怪物强度。

本批仍保留“前段—岔路房—三路地下汇流—Boss”的基础骨架。新增的是额外普通房连接与通道选择，并非已完成任意任务图求解器。单家族共享房壳/多组主门配方、风险与奖励规则的进一步组合，仍属于后续阶段；现有两个主端口的语义没有被偷换。

## 排查并修复的缺陷

| 问题与依据 | 修改 |
|---|---|
| 地下布局搜索失败后调用旧同层 `BuildOpen`，恢复 compact 标志后仍可能声称地下终点，实际允许旧的 220 m 终点配置 | compact 模式只交付真实地下方案；失败保留原场景。基础房池重试共享同一主搜索截止时间，深层搜索响应取消 |
| 连接段权重为 0，但 Run 深度计算使用首次访问即定值的普通 BFS | 改为可松弛距离计算，入口由真实接口定位 |
| 活动房与警报只处理少量 connector 跳数，多直段/弯头串联后相邻房丢失 | 沿连续连接段遍历，到下一个房间停止；使用占位 cells 识别异形房及玩家实际探索 |
| 精英房门口从两个 AABB 相交推算，异形轮廓及错位口会得到错误中心/法线 | 直接消费生成器的真实门洞；没有门洞数据的旧清单不猜测封门位置 |
| 精英遭遇 Tick 未要求玩家已进入，额外出口未纳入门板 | 入房才开始落怪，整组槽位解决且有存活怪后才封闭全部连接门；玩家胶囊未离开门板范围时延后封门；死亡/离开仍开门 |
| 精英遭遇持有的怪未被导演计入全局上限，精英 +1 可超过每房数量限制 | 普通与精英统一存活预算，普通刷怪为一组待生成精英预留容量；容量不足不扣落点失败次数；每房数量最终再限制 |
| 普通刷怪的玩家阻挡/落点失败标志跨槽位串用，首个不可见性候选失败即停 | 标志按槽位计算，继续尝试其他候选，仅真实落点失败消耗重试；房内采样及导航投影后均约束真实 cells |
| 相同种子打乱锚点前依赖 Actor 枚举顺序 | 先按世界位置稳定排序，再按该房的独立种子打乱 |
| 昨日日志中的四个 Earthwork 父材质编译错误：ORM 被强制指定 Virtual Masks，线性打包法线被强制指定 Normal | 根据贴图压缩格式、sRGB 和 VT 设置选择采样器；Ridge 线性 RGB 法线显式解码；复用同一图构建函数更新导入器 |

材质问题依据：`Saved/Logs/FPSGAME_2-backup-2026.09.25-13.13.47.log` 的 `M_Earth_PebblePatch`、`M_Earth_Pebbles`、`M_Earth_Gravel`、`M_Earth_Ridge` 错误，以及本轮之前的 `Saved/Logs/FPSGAME.log`。这是昨天日志暴露的既有问题，不表示这些材质都是昨天创建。

- 四个父材质位于 `/Game/Dungeons/AtmosphereV2/RoomInteriors/Earthwork/Materials/`，后台 Python commandlet 已保存。原素材包贴图未修改，材质实例和网格继续引用原路径。
- 修复入口：`Tools/AssetPipeline/repair_dungeon_earthwork_samplers.py`；共享图配方：`SourceAssets/DungeonRuinEarthwork20260921/Scripts/earthwork_materials.py`。原 `import_earthwork.py` 同步使用该配方。
- 保存回执：`Saved/DungeonV4_20260926/earthwork-material-repair.json`；执行日志：同目录 `earthwork-commandlet.log`。保存成功不等同于实际渲染验收。
- 本轮修改前的地牢源码和四个父材质副本保存在 `Saved/DungeonV4_20260926/Before/`。没有回退其他任务的未提交修改。
- Game 构建还暴露了 `ProductionFallingTree.cpp` 的既有编译阻塞：诊断函数在 Game 目标读取仅 `WITH_EDITORONLY_DATA` 可用的 `USkeletalMesh::GetNaniteSettings()`。仅给该诊断读取加了同名条件编译边界；Editor 保留原诊断，Game 输出源数据不可用，不改变倒树行为。
- `FPSGAMEEditor Win64 Development` 与 `FPSGAME Win64 Development` 常规构建均已成功，产物为 `Binaries/Win64/UnrealEditor-FPSGAME.dll` 和 `Binaries/Win64/FPSGAME.exe`。最终日志分别为 `Saved/DungeonV4_20260926/build-editor-delivery.log`（3.51 秒）和 `build-game-delivery.log`（23.04 秒）；这些是末次增量构建时间，不是本轮全部构建耗时。
- 没有启动 GUI 编辑器、PIE、种子遍历、自动回归、截图或渲染；运行时体验、成功率与视觉表现交由用户测试。

主搜索有 12 秒截止时间，超时返回失败；成功后额外回路使用固定候选预算。独立种子流避免通道/回路/装饰之间互相消耗随机数，但不把不同机器上受超时影响的成功率称为严格一致。
