## 已写入的生成规则

主线：入口 → 战斗 A → 中枢 → 战斗 B → 供能事件 → 战斗 C → 精英 → 补给休息 → 看守者 → 撤离。

中枢另有“可选战斗 → 宝箱 → 中枢”回环；战斗 C 清场后可进入“供能事件 → 物资库”支路。走廊不计入 14 房。中枢四个方向分别连接不同端口，回环占用独立空白网格，没有共用同一个门洞。普通房允许向来路撤退，向前门由清场条件开启；精英/首领只有玩家完全进入后封门。

首版采用明确的宏观插槽语法。空间随机流决定左右/上下镜像、200 cm 网格上的 4000–4800 cm 房间间距与尺寸。模板流在 8 个角色兼容模板中加权选择，最近 4 次重复权重乘 0.35，不连续选择同一模板。遭遇和陈设使用不同随机流。首次直接进入地图用种子 20260922；主动新建使用随机种子或命令中的指定值。

模板：通行廊厅、服务中枢、错位掩体、柱阵、维修间、供能站、物资库、看守者大厅。当前差异体现在掩体数量/布局、立柱、工作台组件、房间角色与尺度；后续可替换装配层，不改变路线/敌人/存档身份。

装配复用已认可的 Concrete、IvoryTile、PaintedSteel、BareSteel、门漆材质、维护柜和三种工作台蓝图。工作台保持实际尺寸和局部坐标，原样板关卡不改动。现阶段没有把所有世界坐标制作的墙皮、碎砖、管线与积水整体平移复制到 14 房，也不使用已退役的 5080 物品。

## 游戏推进

- `ADungeonGameMode` 复用 FPS 角色和控制器，等待装配及所有房间中心具备导航后生成玩家；独立室内 GameMode 不自动生成室外天气。
- `ADungeonAssembler` 负责壳体、走廊并集边界、门洞、门禁、灯光、互动终端和遭遇激活。导航等待发生在正常运行流程中，非本轮验收操作。
- 胖僵尸成本 2、Mutant3 成本 4。预算按基础 10、角色倍率、流程进度系数解析成固定敌人槽位；普通同时存活 6，精英 8，全局 12。没有空怪物白名单默认通关的分支。
- 首领为 3.2 倍生命、1.3 倍伤害的 Mutant3，附带 2 个胖僵尸；配置明确标记替身。
- 怪物投放前做导航投影和胶囊空间查询。未能投放的槽位保持待生成，无法加载类/模型/动作/控制器时保留未完成状态。
- 供能终端给予两场战斗的防御 +10%；休息房可领 3 瓶生命药剂；宝箱/物资库提供金钱和 5.56 弹药；出口提供结算奖励后返回主场景。背包放不下时不消耗领取机会。
- 当前结构常驻，远处主照明关闭，遭遇按进入触发，不称为完整房间流式系统。

## 保存与奖励

新增 `FDungeonRunState` 作为现有 `FColdSteelProfile` 的可选字段，不建立第二套独立角色存档。旧角色没有此字段时默认无进行中的地牢。

保存解析后的布局、模板版本、怪物类与槽位、探索、活动遭遇、清场、事件、领取和安全房间。重新进入从安全房间开始；未击杀敌人恢复满血，已击杀敌人不再刷新。死亡回执与角色经验写入同一事务，覆盖普通伤害以及火球、冰锥、闪电、圣光的批量奖励入口；仍沿用现有训练自动保存策略。清房与战斗次数 Buff 扣除一并提交，物资与领取记录一并提交。异常销毁或缺失 Actor 不算死亡。

精英/首领是否封门由当前玩家进入决定，不直接恢复一个会把玩家关在外面的物理封门状态。领取与事件状态照常恢复，不重复发奖。

## 使用

1. 主场景：`DUNGEON / Continue / 14 Rooms` 继续上一轮，没有存档时生成第一轮。
2. 主场景：`DUNGEON / New Expedition` 开启新种子，替换当前轮地牢进度。
3. 编辑器直接打开 `/Game/GameMaps/L_Dungeon_Generated` 后由用户运行。
4. 地牢内控制台：`DungeonNew 12345` 新建指定种子，`DungeonNew` 新建随机种子。
5. 终端交互：对准终端机身，2.5 m 内按 E。入口可保存返回，出口需击败看守者。
