## 从代码确认的搜索遗漏与修改

文件：`Source/FPSGAME/Dungeons/AuthoredDungeonCompactRouting.inl`。

1. `GrowCompactRooms` 原本只分配每个 beam state 的预算，然后逐个穷举房型及连接候选。前面的不可放置房型可以消耗这个 state 的全部预算，排在后面的房型无法尝试。现在在 state 总额内，按剩余房型/门位选择数分配当前 choice 的尝试上限；未用额度继续留给后续选择。
2. `ConnectCompactBranch` 原本找到首个完整支路就立即接受；随后另一支路失败，只能反转整个左右构建顺序，无法继续尝试前一支路的其他末端房间/求解方向。现在增加有界的后续连接回调：只有第二条侧路也成功才接受第一条；否则在原终点基础上继续尝试第一条侧路的其他候选。失败时已放置的临时路段按原有数组快照回滚。
3. 后续连接每次最多使用剩余预算中的 5000 次尝试，消耗计入同一 `CompactBudget`，避免一次续接吃完其他候选的机会。原 12 秒总规划窗口、64 次前段尝试、每轮 40000 的预算不变。

门位、墙体碰撞、三条完整支路、地下 Boss、通道 12 m 上限和原有路线预算均保留。这里修正的是已确认的搜索遗漏；尚未重跑该种子，运行恢复情况由用户测试。
