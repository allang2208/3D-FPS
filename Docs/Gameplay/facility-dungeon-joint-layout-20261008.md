# 设施地牢联合布局调整（2026-10-08）

## 目标与边界

保持「侧破洞入口 → 接待厅 → 分流厅 → 三条双主题路线 → 地下汇流厅 → 档案中心 → Boss」配方。六个主题无放回抽取，每个主题三间房顺序不变。整体主题对可以换到不同物理分流门，门头、顺序牌与路线一起更新。

复用现有真实门位、房间、楼梯与坡道，通过整间房刚体平移和旋转求解；不缩放房间、不虚构门口、不删房、不重抽主题，也不关闭碰撞来取得布局成功。当前改动没有在房间墙面新开门。现有合法门位已能覆盖 120 种有序两两组合，暂不需要改造已认可的房间内部。

## 实现

- `AuthoredDungeonJointRouting.inl`：三个六房候选集合共同提出汇流厅位置与朝向，枚举路线到三个落点的匹配，按可用候选数回溯。完整路线跨主题连接与进出坡道均计入原有长度预算。
- 同时考虑 0、±540、±1080、±1620 cm 高差；高差 1620 cm 的坡道步行距离约 3748.5 cm，在 4600 cm 连接预算内横向余量很小，不能强制所有侧路只用这个高差。
- `AuthoredDungeonLayoutBank.inl`：联合搜索失败时，按原抽签的**有序主题对集合**选择预先求得的布局。重新配置对应分流门、逐件通过当前占用检查、检查完整接口图和任务预算。可选宝箱支路不固化进布局库，由实际运行种子重抽；主题第三房的既有内置宝箱不受影响。
- 布局库记录当前目录合同 SHA-1；模型配方、接口、占用、任务或预算数据变更后拒绝旧库。测试专用强制组合与强制重放仅在 `DungeonLayoutProbe` 模式生效。
- 保留原 12 秒总窗口，联合搜索最多使用其中 8 秒，给后备方案校验留出时间。缺少有效后备方案时仍可在剩余窗口使用旧算法；失败保留原场景。
- 修复数值边界：原占用重叠容差为 8 cm。旋转值保存重建会使 8 cm 变为 8.00000000000x cm，导致合法布局重放失败。判定增加 0.001 cm 数值容差，与已有独立结构检查一致，没有放宽实体冲突规则到新的尺寸档位。
