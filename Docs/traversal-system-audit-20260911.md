# 翻越与攀爬系统审计（2026-09-11）

后续用户已授权修复；当前实现与重新验证见 [审计修复记录](traversal-audit-fixes-20260911.md)。下文保留修复前的审计证据。

本轮是审计，没有修改玩法源码、动画或地图资产。新增的观察脚本仅在独立编辑器进程的临时 PIE 世界中施加故障，使用独立玩家存档，不保存场景。审计包含输入、镜头选墙、支撑/路径检测、动画执行、表面手部适配、中断与控制权恢复。

## 1. P1：失去碰撞支撑后仍执行，并把悬空落点记为成功（已复现）

位置：`Source/FPSGAME/Movement/FPSTraversalComponent.cpp:15`、`FPSTraversalExecution.cpp:94`、`FPSTraversalExecution.cpp:183`。

开始攀爬后将目标组件设为 NoCollision，不销毁、不移动它。IsStableSurface 只检查对象有效、非 Pawn、非物理模拟及组件速度；执行器另查变换，均不能发现碰撞关闭。于是动作仍沿旧路线继续，最后 FindFloor 已经没有可站立支撑，却仍输出 success=1。

本轮 PIE 观察：t=6.4667 s 关闭碰撞，t=7.7333 s 仍到达旧落点 `(60146, 10000, 10278)`；结束状态是 MOVE_FALLING，日志却为 `TRAVERSAL_END success=1`。原运行测试仍把此例的“安全落点”判为 PASS，因为只比较 LastExitLocation 和缓存的 Destination，没有确认结束时实际存在支撑。

建议：动作期间复核支撑仍注册、仍对角色提供查询/阻挡碰撞；结束时以实际可站立支撑及胶囊净空决定成功。支撑失效走统一取消流程；增加关闭碰撞、改变阻挡响应/支撑形状的中途用例。不能仅通过更改日志掩盖角色沿悬空路线执行的问题。

## 2. P2：动作中途受到强制控制时缺少交接策略（禁用输入行为已复现，恐惧冲突由代码确认）

位置：`Source/FPSGAME/Movement/FPSTraversalExecution.cpp:88`、`FPSTraversalAir.cpp:16`，关联 `Monsters/HandBrainFearComponent.cpp:16`、`:29`。

开始抓墙前会检查 IsMoveInputIgnored，已经开始后 Advance 不检查新的控制状态，继续关闭 CharacterMovement 并每帧消费输入。恐惧组件恰好通过 SetIgnoreMoveInput 和强制 AddMovementInput 实现逃离；后者在攀爬期间被消费，无法接管角色。

本轮用同一禁用移动输入接口注入：t=12.0667 s 禁用，t=12.2333 s 输入仍被禁用而角色已继续上升，t=13.3333 s 照常完成整个攀爬。没有用真实怪物施放来冒充完整恐惧集成验收。

建议：定义战斗强控与攀爬的优先级。若恐惧应打断，效果应用时调用统一中断并交还移动；若接触阶段允许抗打断，应显式延迟该效果的运动接管。菜单禁用输入和战斗强控应分别处理，不能简单把所有 UI 打开都当成必须摔落。

## 3. P2：中断后的镜头回归过快，且脱离攀爬避碰路径（已复现）

位置：`Source/FPSGAME/Movement/FPSTraversalExecution.cpp:171`、`Source/FPSGAME/FPSGAMECharacter.cpp:627`。

正常结束有 Release 到 Duration 的镜头过渡；中断时立即清除 bTraversing，镜头交给普通相机的指数插值，缺少受距离限制的取消过渡，也不再执行攀爬相机球体 Sweep。

本轮在下落抓墙动作进行约 0.5 s 后销毁支撑。人物位置在取消前后不变，镜头从 `(60129.43, 9996.98, 10237.52)` 变为 `(60109.88, 9997.76, 10267.09)`，16.7 ms 内位移 **35.46 cm**。这是带插值的快速回弹，不是无插值瞬移。现有 AirAudit 只统计动作入口 Elapsed<0.2 s 的镜头变化，没有检查取消后的过渡。

建议：取消和装备中断共用受速度/加速度限制、带球体避碰的短镜头回归；胶囊立即恢复合理物理状态，镜头完成过渡后再交给普通移动相机。补取消时的镜头速度、碰撞和武器恢复检查。

## 4. P2：镜头避碰与角色碰撞通道不一致（代码确认，未复现具体村庄穿墙）

位置：`Source/FPSGAME/Movement/FPSTraversalExecution.cpp:146`。

身体、落点及手部查询遵循角色碰撞 Profile，镜头却固定查 ECC_Visibility。某个模型若阻挡 Pawn、忽略 Visibility，人物检测会认为它是实体，但相机避碰不会看到它。动画相机并不始终处于胶囊内部，不能依赖身体 Sweep 代替相机保护。反方向的差异也可能让镜头被仅阻挡 Visibility 的装饰挡住。

建议：统一相机应遵守的阻挡规则，或使用有明确资产约定的专用相机通道；补 Pawn/Visibility 响应不同的场景。该项是代码层面的覆盖缺口，不代表本轮已经看到村庄中的穿墙实例。

## 5. P2：可抓墙沿与手掌锁定的表面条件不同（代码确认，待补陡沿运行用例）

位置：`Source/FPSGAME/Movement/FPSTraversalComponent.cpp:103`、`FPSTraversalArmsComponent.cpp:62`。

几何准入允许顶部法线 Z>0.2；手部建立接触锚点却要求 Z>0.65。部分已经允许翻越的斜沿/破损石沿会进入动作，但无法建立手掌锚点，转而依靠原动画及局部避碰修正。现有测试只确认 SurfaceCorrections>0、骨长不变，不能证明双手实际抓住了表面。

建议：检测阶段输出左右手的接触点、法线和可达信息，执行器复用这些结果，使准入与动画适配共用合同。优先提高对已允许表面的接触适配，不用整体收紧阈值损害用户要求的宽松判定。新增斜沿、左右高度不同及接触失败的检查。

## 优化顺序与可选改进

1. 先修支撑失效与最终成功条件，同时补对应回归；再做取消镜头衔接。这两项有独立运行证据。
2. 定义并接入战斗强控中断策略；统一镜头阻挡与手部接触合同。
3. 测试分别覆盖开始、进行中、结束、取消。除正常到达坐标外，检查实际支撑、动作结果、退出镜头与控制权。补 30/60/120 Hz 及跨阶段长帧；当前固定 60 Hz 不是多帧率证明。
4. 待正确性修复后再测查询成本。当前每次按住空格的空中失败请求可能重复跑墙沿 15 条射线、落点多次九点采样及 Sweep；`FindTarget` 在同一次查询中还重复计算 RaisedStart 的接近 Sweep。可先移除确定重复的查询、缓存手部骨骼索引，再用实际耗时决定是否需要短时失败缓存。没有本轮 FPS/毫秒证据，不建议先盲目降低探测频率。
5. 当前自动台阶 40 cm，地面攀爬动画下限仍为大于 50 cm。40–50 cm 需要普通跳跃是现有明示策略；若想更连续，可以另行统一阈值，不将这段区间冒充本轮新发现的回归。
