# 消耗品浮窗标准（食物／饮料／药水）· 2026-10-18

用户要求：针对食物，把背包栏浮窗的数值与效果填写完整，覆盖简略浮窗和详细浮窗，并制定后续食物／药水统一遵循的标准格式。本文件即该标准；实现见 `Source/FPSGAME/UI/ColdSteelConsumablePresentation.h/.cpp`。

## 目标与范围

- 背包、装备、仓库、夹层与法典共用同一份浮窗内容；简略浮窗（悬停）与详细浮窗（固定/长看）都从 `ColdSteelConsumable` 的行序生成。
- 适用 `category=consumable`，以及带 `spoilDays` 的可腐败食材（生鸡腿、生羊肋排、生香肠、生大羊排）。
- 只改展示，不改消耗数值、腐败时钟、堆叠、存档与联机结算。

## 数据契约（items.json）

| 字段 | 浮窗用途 | 说明 |
| --- | --- | --- |
| `useEffect.hp` / `useEffect.maxHpPercent` | 恢复生命 | 固定值与最大生命百分比同时结算，合并为「+30 + 15%上限」 |
| `useEffect.mp` / `useEffect.maxMpPercent` | 恢复魔法 | 同上 |
| `useEffect.hunger` / `useEffect.maxHungerPercent` | 恢复饱腹 | 固定值与最大饱腹百分比；百分比按当前 `MaxHunger` 结算 |
| `useEffect.hydration` | 水分 | 正数恢复、负数消耗；食物同时扣水时显示「消耗水分」 |
| `useEffect.sanity` | SAN | 正数恢复、负数消耗；无该键则不显示 |
| `spoilDays` | 新鲜度 | 自然游戏日；只有会腐败的食物/食材填，药水、汽水、矿泉水不填 |
| `useDuration` | 使用时长 | 秒；有进食/饮用动作的填 |
| `useCooldown` | 冷却时间 | 秒；0 或缺省不显示 |
| `maxUses` / `remainingUses` | 剩余次数 | `maxUses>1` 显示「剩余 X / Y」；矿泉水另显示瓶内水量 |
| `buffs` | 持续增益 | 数组，见下；没有限时增益就不填 |

`buffs[]` 单条格式：

```json
{ "label": "体力恢复速度", "value": 5, "unit": "%", "duration": 600,
  "note": "饱腹已满也可食用；重复食用只刷新持续时间。" }
```

- 所有条目的 `duration` 取最大值，生成唯一的「增益持续」行。
- `note` 可选，作为整行说明排在增益数值之后。
- 机制契约：`buffs` 是展示与机制的同一份声明。新食物写入 `buffs` 时，生存/消耗逻辑必须消费同一字段；现有烤香肠、大份烤羊排的机制常量在 `FFPSSurvivalState`，两处数值必须一致（展示优先读 `buffs`，缺省才退回常量表）。
- 消耗品不再填 `stats`：浮窗会忽略消耗品的 `stats`，避免与 `useEffect` 重复或数字冲突（`stats` 继续服务武器/装备/法典等其他物品）。

## 简略浮窗（悬停，最多 4 行）

按消耗品类型固定优先级，不足 4 行时按详细行顺序补足，仍为空才回退「分类」：

- 食物：恢复饱腹 → 恢复水分 → 消耗水分 → 体力上限 → 体力恢复速度 → 新鲜度
- 饮料：恢复水分 → 恢复 SAN → 消耗 SAN → 剩余次数 → 使用时长
- 药水：恢复生命 → 恢复魔法 → 冷却时间 → 剩余次数 → 使用次数
- 生食材：新鲜度 → 用途

## 详细浮窗（主卡片顺序）

1. **使用效果**：恢复生命／魔法／饱腹（固定值与 %上限合并为一行）、恢复／消耗水分、恢复／消耗 SAN。
2. **持续增益**：每条 buff 一行，随后「增益持续」，再排 `note` 整行说明。
3. **新鲜度**：`剩余 X 天 / 共 Y 天`；剩余 ≥50% 用正向色、20–50% 中性、<20% 与「已腐败」用负向色。食物附「腐败后不可食用，会转化为腐败食物」，生食材附「不可直接食用，需投入有燃料的篝火烤熟」。
4. **使用**：使用时长、冷却时间、剩余次数／瓶内水量、单次使用；末尾整行「右键 / 双击 / Enter / 快捷栏」。
5. **物品信息 / 堆叠 / 取出**：沿用现有行，排在效果之后。
- 生食材没有使用动作，显示「用途：烹饪食材」后直接进入物品信息。
- 浮窗头部保留新鲜度进度条：满条新鲜、随时间缩短，颜色沿用 `ColdSteelFoodUI::Color` 的阶段；文字新鲜度与进度条同源。

## 新增食物／药水流程

1. 在 `items.json` 填 `category=consumable`、`useEffect`，按需补 `spoilDays`、`useDuration`、`useCooldown`、`maxUses`、`buffs`；**不要填 `stats`**。
2. 有限时增益时，先接线机制（生存状态或状态效果），再把同一数值写进 `buffs`。
3. 浮窗自动生成，无需改 C++；只有出现新的效果键（新的资源类型、新的增益结构）时才扩展 `ColdSteelConsumablePresentation`。
4. 药水沿用同一键位；新档位只改 `useEffect` 数值，不新增 UI 分支。
