# ST6 战术套：数值设计与套装接入 · 2026-10-22

用户要求：把 ST6 战术上衣、ST6 战术靴、硬壳战术手套、ST6 战术长裤，以及 ST6 战术头盔（占位）做成一套；**侧重枪械使用**；先给合理的防御数值并横向对比其他装备。

定位经用户确认为**轻甲手感流**：三套里防御最低一档，预算放在枪械手感（换弹、开镜、奔跑体力），不做坦装。`perEnhance` 经用户确认补齐。

## 二、单件附加效果

用户 2026-10-22 指定的单件效果（写在 `source-combat-items.json` 的 `bonusStats`）：

| 装备 | 效果 | 键 | 归一化值 |
| --- | --- | --- | --- |
| ST6 战术头盔 | 暴击伤害 +25% | `critDamageBonus` | `0.25`（比例，非百分点） |
| 硬壳战术手套 | 换弹速度 +5%、ADS 瞄准时间 −5% | `reloadSpeed`／`adsPercent` | `0.05`／`-0.05`（10-18 既有） |
| ST6 战术上衣 | 换弹速度 +5%、奔跑体力消耗 −10% | `reloadSpeed`／`sprintStaminaCost` | `0.05`／`-0.10`（10-18 既有） |
| ST6 战术长裤 | 暴击抵抗 +15%、奔跑体力消耗 −5% | `critRes`／`sprintStaminaCost` | `15`／`-0.05` |
| ST6 战术靴 | 移动速度 +5%、奔跑体力消耗 −5% | `moveSpeedPercent`／`sprintStaminaCost` | `0.05`／`-0.05` |

五件全部带效果，且分工不重复：头盔管暴击、上衣管换弹、手套管开镜、长裤管抗暴、靴子管移速。

**奔跑体力是叠加项**：上衣 −10%、长裤 −5%、靴子 −5%，单件合计 −20%；再加套装效果的 −15%，**凑齐后合计 −35%**（`1 + (−0.20) + (−0.15) = 0.65`）。两条来源都走 `EquipmentBonus` + `SetEffect` 的加法合并，未触到「消耗下限 0」的保护，仍有 65% 的基准消耗。

**换弹速度同样叠加**：上衣 +5%、手套 +5%，套装再 +15%，凑齐后合计 **+25%**（乘算进 `Reload` 的速度因子，即换弹时间约为基准的 80%）。

**开镜耗时**：手套 −5% 与套装 −10% 相加，凑齐后 **−15%**（时间约为基准的 85%，`ADSTimeMultiplier` 夹在 0.5–1.5 之间，未触界）。

**移动速度**：仅靴子 +5%，套装不另加移速。

### 两处单位必须注意

1. **`critDamageBonus` 是比例**：装备层 0.25 = +25%，与野行翎羽帽同口径。写成 `25` 会变成 +2500%。
2. **`critRes` 是百分点**：直接写 `15`，面板显示「15%」，与锁子甲套的 `critRes: 25` 同量级。消费端 `Derived("critRes")` 会对装备部分做 `Round()`，整数不受影响。

### 着色判定

四条新键的正负语义经核对：`critDamageBonus`／`critRes`／`moveSpeedPercent` 为越高越好（正值＝增益），`sprintStaminaCost` 在 `LowerBetter` 名单内（负值＝增益）。四行在浮窗里均显示为增益色，不会被误标成代价。

### 计入条件

单件效果只在 `Place==1`（已装备）时计入（`EquipmentBonusFor` 的 `if(Item.Place==1)`），放在背包里不生效。本轮只写了 `bonusStats`、**没有写 `bonusPerEnhance`**，因此强化等级不会放大这些效果——只有 `defense` 随 `perEnhance` 成长。

### 联机与老存档（2026-10-22 自查修正）

`ColdSteelProfileRuntime.cpp` 的 `ReloadProfile` 里有一份硬编码清单 `bSourceCombatStats`，作用是**清掉实例里残留的 `bonusStats`**，让覆盖层生效——因为 `CombatItemFormula::Read` 只在实例缺该字段时才补覆盖层，实例有值就会盖住。

新三件若不在该清单，头盔／长裤／靴的单件效果在**老存档和联机远端玩家**上会被实例残留值挡住而不生效。首版遗漏了这三件，已补齐：

```cpp
I.Definition==TEXT("ue_st6_tactical_helmet")||I.Definition==TEXT("ue_st6_tactical_pants")||
I.Definition==TEXT("ue_st6_tactical_boots")||
```

以后新增任何「效果写在覆盖层」的装备，**必须同时登记到这里**，否则只在全新存档上正确。

## 三、套装效果

`st6_tactical`，五件套（头盔 + 上衣 + 手套 + 长裤 + 靴），效果全部落在既有消费端：

| 效果 | 数值 | 消费端 |
| --- | --- | --- |
| 换弹速度 | +15% | `ColdSteelWeaponStats::Reload`（`WeaponStatEvaluation.cpp:64`） |
| ADS 瞄准时间 | −10% | `UColdSteelStatusModel::ADSTimeMultiplier`（枪械与弓共用） |
| 奔跑体力消耗 | −15% | `FPSStaminaModel.cpp` 的 `SprintStaminaCost` |

选择理由：三条都是枪械操作链上的真实耗时，且覆盖「换弹—开镜—跑动」三个最常打断交火的环节。全部为负向耗时（更快／更省），不带任何惩罚项，符合轻甲手感流定位。

**没有引入新字段**：三个键在 `EquipmentBonus` 里已有一对一的语义与消费端，套装只是把 `SetEffect()` 的结果并进同一处相加，浮窗、角色面板与实机读的都是同一份值。

## 四、占位期状态（重要）

`ue_st6_tactical_helmet` 目前是**数据占位**：有 `items.json` 条目与 `defense`，但 `ue_icon`／`world_mesh`／`ue_equipment_icon_mesh` 均为空串，靠 `icon_fallback: "盔"` 显示占位字。

因此：

- 玩家拿不到头盔，`ArmorSet()` 的三槽检查（头盔 1／铠甲 7／鞋靴 13）不成立；
- `St6TacticalSetComplete()` 恒为 `false`，**套装效果当前不会触发**；
- 浮窗仍会显示「ST6 战术套装（4/5）」并列出三条属性（按 2.24 条，未凑齐时降为次要色），提示还差头盔。

头盔网格做出来后只需填上三个资产路径并保存，效果即自动生效，无需再改代码。
