# 断线、重生和连续换图状态恢复（2026-10-13）

本轮按用户要求追踪源码中的断线重连、死亡换 Pawn、组队连续换图路径；不运行 PIE、游戏或自动回归。用户负责实机测试。

## 修复内容

1. **断线期间主机换图导致钥匙丢失。** 原缓存位于 `UWorldSubsystem`，世界销毁后离线客机的记录消失。新增 `UColdSteelNetSessionSubsystem` 在 GameInstance 中保留房间内缓存。无缝换图沿用 NetDriver；组队换图 URL 传递内存房间 ID，使 PIE 回退到硬切图时也能恢复。新房间使用新的标识和缓存，进程退出后不保留会话钥匙。主机 PostLogin 同样绑定档案 ID 并恢复钥匙。
2. **旧角色的档案分片跨入新角色。** 上传、镜像分片均携带捕获快照时的 Pawn。服务器拒绝已经更换 Pawn 或已经死亡角色的完整上传，并要求客户端重新捕获；不删除本地库存意图。新 Pawn 绑定影子档案时停止旧镜像并安排新镜像。客户端只向对应 Pawn 的已挂载档案应用镜像，复制 Actor 先到、控制关系后到时暂存待应用。
3. **篝火操作在等待上传期间跨越重生。** 篝火意图携带最初操作的 Pawn；服务器拒绝已经更换角色的请求，避免在新角色上执行旧操作。库存请求原有的 Pawn 校验保留。
4. **篝火收到更新库存却一直等待。** 回执解锁由“库存版本必须完全相等”改为“当前版本已达到或超过回执版本”；后续权威事务产生更高版本时同样可以结束等待。

## 本轮范围判断

- 检查了持久档案 UUID 绑定、同档案重复登录、断线影子档案保存、重生前最终资源捕获、影子档案重新挂载、库存回执的原 Pawn 校验、组队换图的准备/保存/成员变化取消及 PlayerState 迁移。
- 检查了引擎 `AGameModeBase::ProcessServerTravel`：当前项目未配置 `net.AllowPIESeamlessTravel`，PIE 可回退为硬切图。因此缓存不能仅依赖原 PlayerState 或同一 NetDriver。
- 本批不修改死亡恢复数值、武器动作、地图资产、背包布局或个人存档格式。新增的是 RPC 参数及一个原生子系统，需要重建基础 DLL。
