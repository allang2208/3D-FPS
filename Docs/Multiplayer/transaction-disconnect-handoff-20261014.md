## 已修复的边界

1. **不确定写入被旧档覆盖。** 物品交易写入返回失败，不能据此断定磁盘完全没写入。原先自动保存和断线清理仍能保存旧内存档案，覆盖新回执。现在仅在交易持久化实际写入、校验失败时标记未确认状态；内存校验失败不误认为磁盘提交。未确认状态阻止后续交易及影子覆盖保存，保留现有文件与日志供重新启动主机后恢复。
2. **断线最后一次普通保存失败丢失内存进度。** GameInstance 房间缓存持有断线客机的影子模型；同房间重连先挂载这份模型，再合并客户端档案。缓存随现有房间 ID 跨组队换图，新房间清除，不写入另一份独立角色档案。
3. **读取失败被当成首次加入。** 现存客机存档无法读取或 UUID 不符时明确拒绝覆盖，并允许以后重新尝试读入；不会因为首次绑定 UUID 失败而在下一包绕过读档。
4. **发送完不等于服务器接受。** 组队 Ready 包现在带实际上传 ID。服务器只对已接受的完整档案放行；被拒绝或未完成的上传会重新进入准备流程。
5. **共享世界只在离图销毁时保存。** 换图前显式保存共享掉落位置与库存，检查共享日志、篝火待恢复状态。失败时保留当前场景并解除本次准备，不继续带着未完成交易切图。
6. **异步换图失败后持续锁定。** 服务器接受 URL 后仍可能加载失败。新回调按当前 World 过滤，只取消该房间的组队准备，避免 PIE 多实例相互影响。

## 恢复边界

- 房间内存缓存用于服务器进程仍存活时的重连；它不等于磁盘保存成功，也不能替代主机进程崩溃后的持久存档。
- 写入结果未确认时保留现场并提示重新启动主机恢复；不会删除损坏文件或猜测性退款/重发物品。
- 本轮没有改变费用、配方、领取奖励或库存布局，也没有改造所有个人存档为新的文件格式。
- 这份台账覆盖上述提交链路，不等于对全项目每个函数和所有网络时序作出了无遗漏保证。
