## 已修复的源码问题

| 范围 | 原先存在的情况 | 本次处理 |
|---|---|---|
| 换图时队员加入/离开 | 换图请求保存在发起者 PlayerState，发起者离开会丢失协调状态；新队员没有收到准备请求，却会被纳入等待 | 登录/退出钩子检查当前旅行，成员变化时取消整队准备并通知现有队员；发起者异常销毁也有取消入口 |
| 换图确认归属 | 保存就绪消息没有旅行标识，旧确认无法与新的换图请求区分 | 每次旅行使用独立 GUID；准备、就绪、失败消息匹配同一标识，世界变化清理旧上下文 |
| 旧上传误作新保存 | 准备换图时已有旧档案正在传输，旧传输结束也会令 `bHasLastSent` 为真 | 等旧上传和库存交易完成后，再强制传一份关闭工作站/取消动作之后的新快照，完成后才确认就绪 |
| 就绪后的状态变化 | 一名队员已就绪、另一名仍在上传时，前者仍可能有已在途的交易/工作站输入或角色死亡 | 新事务使原就绪状态失效并重新准备；真正 ServerTravel 前再次核对 Pawn/死亡状态、结算工作站并保存所有参与者 |
| 退出时存档 | `SaveShadowToHostDisk` 直接保存模型快照，可能没有先采集 Pawn 的最新生命、弹药和生存状态；离开事件与工作站收尾分散 | 保存前调用 `SyncRuntime`；退出前统一取消未释放施法、关闭工作站并保存，失败时保留重试机会，未完成的付费任务也保存记录 |
| 重复角色档案 | 两个在线玩家可用同一 `NetworkProfileId` 创建独立影子模型，却写同一个主机存档槽 | 首次绑定时检查同世界在线档案占用，包括房主，拒绝第二个占用并给出提示；不按临时昵称判定身份 |
| 被拒绝档案的去重缓存 | 反序列化/接纳之前先记录上传字节为已处理，之后同内容可能被直接跳过 | 只有 `ApplyGuestProfile` 成功后才更新去重记录并发布库存基线 |
| 掉线后钥匙 | 重生和在线换图已经保留钥匙，但离开销毁 PlayerState 后没有当前世界内恢复入口 | 世界子系统按档案 GUID 缓存客机钥匙；拾取及离开时登记，重新绑定同档案时恢复；不写磁盘、不共享给其他角色 |
| 工作站过期输入 | 锻造/装配/木工的细粒度输入只有操作参数，PlayerState 跨 Pawn 存活后，延迟输入可能作用到新角色或新任务 | 输入携带发起 Pawn 和任务 ID；服务器核对当前角色与当前任务，木工仍维持原有序列确认机制 |
| 离开锻造台 | 锻造会话的定时推进未像木工一样持续检查有效工作站范围 | 服务端发布锻造状态时检查可操作范围；不再可达时按现有 Finish 规则收尾，保留待领取产物 |
| 多人建造撤销 | 撤销仅记坐标；别人拆除并在同格重新放置后，原玩家的撤销可能删除新方块 | 格子变化时，按体积 ID + 格子坐标使所有玩家的旧撤销项失效；相同材质重建也视为新方块 |
| 重生后的撤销记录 | 网络撤销历史以 Pawn 为键，重生换 Pawn 后历史断开 | 改用 PlayerState 为键，死亡重生保留当前世界内历史，并清理失效玩家条目；历史仍不写存档 |
| 建造请求重复格子 | 实际编辑会去重，但材料扣除和拆除返还按请求原数组计数 | 在服务器对格子列表统一去重，再用于范围检查、扣料、编辑和返还 |
| 过期构件拆除 | 拆除只按锚格找记录，缺少对当前构件实例及所属建筑世界的最终核对 | 拆除前检查所属世界和当前锚格 Actor 身份；旧/已替换对象不能误删当前构件，落体构件仍按原规则处理 |

共享箱子已有容器修订号检查和同步交易日志，本轮没有再增加一套容器事务，也没有把每个本地 UI 操作一律改为 RPC。

## 已执行的资产静态读取

通过 `MultiplayerAssetInventory` 无界面 commandlet 读取磁盘资产。它不初始化游戏会话、不调用 BeginPlay、不执行蓝图事件图，也不保存资产包。

最终结果在 `assets-r3.json`，摘要在 `asset-summary.json`：

- 45 份蓝图资产，另含 2 个关卡脚本对象，共 47 个蓝图对象。
- 20 张地图：`/Game/GameMaps/` 下 19 张主场景/设计场景，以及 Clearwater 地图。
- 542 条相关地图 Actor 记录：项目原生 Actor 和常驻关卡中放置的蓝图 Actor。
- 读取蓝图 CDO 复制/移动复制默认值、实例覆盖、事件图节点与连线、地图 GameMode 及默认角色/控制器/PlayerState。
- 所有选中地图的默认角色均为 `FPSGAMECharacter`，控制器均为 `FPSGAMEPlayerController`，PlayerState 均兼容 `ColdSteelPlayerState`。其中 19 张使用 `FPSGAMEGameMode`，丘陵使用其专用派生 GameMode。
- 未发现所读取范围内关闭原生预期复制的覆盖值，资产加载失败列表为空。本轮因此没有修改 `.uasset` 或 `.umap`。

额外追踪了这些容易误判的图表：

- 原生怪物派生蓝图主要是空入口；ZombieDog V1 的已连线入口只转发父类。
- `BP_FPS_DayNightManager` 有实际照明图表，自身不复制；`AFPSWeatherManager::UpdateNetworkWeather` 已在客机写入服务器时钟并建立 Tick 顺序，这个本地表现 Actor 没有被误改成整 Actor 复制。
- 随机地牢与战壕地图的关卡脚本含设备配置和局部雾渲染控制台命令，未发现额外的玩家移动/伤害/库存逻辑。本轮未改动这些渲染设置。

第一次资产读取已覆盖地图，但蓝图注册表字段名使用不正确，返回 0 份蓝图；随后改用引擎 `FBlueprintTags::NativeParentClassPath` 常量重新读取，并进一步纳入地图实例及 GameMode 默认类。以上数量均取最终 r3 结果，不采用初次空结果。

## 本轮仍未涵盖

- 钥匙重连缓存只在当前服务器世界存活期间有效。客机离线期间房间换图或服务器重启后的钥匙保留，不由该内存缓存提供；在线无缝换图仍走上一批 PlayerState 复制链路。
- 未加载清单中的 104 张第三方示例、预览、归档/测试或程序集地图。此次地图读取针对常驻关卡实例，没有穷尽流送子关卡、世界分区外部 Actor 和所有第三方蓝图/插件内部逻辑。
- 没有新增自动重连、主机迁移或专用服务器支持。丘陵专用服务器仍是已知未支持路径。
- 高延迟/丢包、三人以上、打包跨电脑/外网和长时间并发运行仍由用户实测。

用户优先复测：换图等待时加入/离开或死亡；操作工作站时死亡、移走或拆除工作站；同档案重复加入；客机持钥匙掉线后重新加入当前地图；两人拆建同一格后分别撤销；死亡重生后继续撤销自己的建造。
