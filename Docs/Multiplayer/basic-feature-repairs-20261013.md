## 已接入的物品基础流程

- 每个 PIE GameInstance 使用 `原槽名_PIE_实例号` 的 A/B 测试档。首次从通过现有校验的原档只读复制；后续不写回原档。
- `ColdSteelInventoryRequestTypes.h` / `ColdSteelInventoryRequests.cpp`：拥有者 PlayerState 接收物品使用／泉水请求，验证角色、版本、实例和可用性，服务器提交，压缩分片回传变更物品与资源。短回执优先于周期全档镜像，沿用带宽节流。
- `ColdSteelNetworkInventory.cpp`：客户端合入物品差量并保存；消费期间复用现有库存待决锁；死亡／换 pawn 后不应用旧角色的资源回执。
- `UseConsumableAtContact` 客机在接触时请求服务器，未批准不扣物品。服务器复用原有消耗规则，通过版本化持久提交后回执。
- 喷泉放行客户端瞄准，请求服务器重做可达性与恢复；失败回滚。
- 旧的上行档案／下行镜像不能回滚新库存事务及资源。保存与传输格式继续沿既有归档体系。
- `ColdSteelProfileTransfer` 增加通用 SaveGame 解码入口，供小型物品回执使用；完整档案原入口保留。

以上内容与下列功能合并构建；运行效果仍由用户测试。
