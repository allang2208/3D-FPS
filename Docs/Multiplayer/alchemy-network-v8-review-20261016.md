# 炼药联机逐项排查 V8（2026-10-16）

范围：监听服务器房主与客机的炼药输入、公共器具表现、拥有者进度、材料结算和异常收尾。仅阅读实际源码、修改与后台编译；未打开 UE，未运行游戏、PIE、自动测试、网络模拟或联机验收。下列结论是源码路径审查，不能替代真实主客机运行结果。

## 本轮修复

1. **搅拌角度按服务端还原。** 原先每端依赖各自收到的转速和帧时间累计角度，会发生漂移。现在复制服务端角度、采样时间和输入截止时间，按服务器时钟计算当前姿态；输入过期后停止外推。圈数仍只由服务器积分，重复 RPC 不直接增加进度。服务端也拒绝空锅搅拌并统一搅拌输入的器具索引。
2. **保留先到的小状态包。** 小型炼药状态 RPC 可能先于分片库存回执到达，特别是“开炉已成功，但人物离台后服务器立即暂停”。以前批次不匹配就丢弃，慢回执可能把客机恢复为炼制中。现在最多缓存一份对应未来库存版本的最新状态，在库存基线到达后应用；不同批次的旧状态不能覆盖当前炉。同批次继续比对进度版本与时间，避免一次无关背包更新丢掉有效的暂停收尾；更晚的状态也不会被缓存包覆盖。
3. **修正忙碌时间与回执判断。** 拥有者状态携带服务器采样时间，忙碌剩余时间扣除传输时间。回执以库存版本和状态序号判断是否已经收到本次操作后的状态；较早的调温包不会冒充装瓶确认。已结束的批次不再被慢开炉回执重新标成活动状态；换 Pawn 的旧请求回执不改变新角色的操作状态。
4. **台面与批次共同校验。** 公共台面状态增加 JobId。台面操作者和批次均匹配后才接受可改变炼制过程的点击／输入，期间浮窗说明正在同步；相同配方的新炉也会重新加载材料布局。装瓶在服务器再次校验批次未结束与当前使用者持有坩埚。
5. **同步保存冻结。** 档案交易保存结果未确认时，服务端阻止后续炼制与材料结算，拥有者同步 Saving 状态；即使本炉已停止、进度版本未改变，也发送这项状态变化。
6. **双向调火。** 左键发送服务端“升一档”，右键发送“降一档”，滚轮保留。顺序为关火→低火→中火→高火；反向为高火→中火→低火→关火，端点不循环。浮窗同步修改。

## 入口与异常分支覆盖

| 项目 | 实际入口与权威路径 | 审查结果／本轮处理 |
|---|---|---|
| 开炉扣料 | `Start/Pay`；客机通过 `RequestInventoryAction → ServerInventoryAction → WorldAction → ExecuteStation` | 服务器按各玩家自己的模型扣料；新建 JobId 和 Escrow 与库存一起提交。已有批次或待处理请求拒绝再次开炉；恢复不重付材料 |
| 重复交易请求 | `ServerInventoryAction` | 请求序号必须递增，Pawn 必须是当前角色，库存版本必须等于服务器版本；非开炉操作额外比对当前 JobId |
| 重复器具输入 | `ServerStationInput` | 比对 Pawn、JobId 与炼药输入序号；旧序号和越界操作拒绝。投料另有服务端忙碌时间与剩余份数上限 |
| 投料 | `ProcessInput(Pour) → OpenUnits → Save → Publish` | 数量从已扣除的 Escrow 转为已投，不再次从背包扣料；检查材料索引、配方步骤、剩余份数。选择的材料、动作序号、开始时间、液位和药色复制到台面 |
| 搅拌 | `ProcessInput(Stir) → Advance` | 仅服务端按时间与限幅转速累计；拾取完成后才计圈。零转速保留握持、Stop／超时结束；新增同一服务端角度与截止时间的公共表现 |
| 调温 | `ProcessInput(Heat)` | 左／右键是相对档位意图，由服务器对当前档位加减并限制在 0–3；客户端不上传最终温度。温度由服务端推进，档位和温度同时进入公共／拥有者状态 |
| 装瓶 | 库存事务 `alchemy.bottle → Bottle → Advance → Finish` | 需当前活动批次、非忙碌、合法温度、有效距离和操作者；设置装瓶忙碌后再次请求拒绝。结束只生成待领取结果，不立即发物品；新增结束批次与租用者复核 |
| 领取 | 库存事务 `alchemy.claim → Claim` | 仅成功且结束的批次可领取。所有成品先尝试放入临时库存，全部放得下才与清空 Job 一起提交。背包不足保留整炉；再次请求因旧库存版本或 JobId 已清空而拒绝 |
| 作废退半 | 库存事务 `alchemy.discard → DiscardRefund/Discard` | 已结束批次按每种实付材料总量计算 floor(total/2)，不是逐堆取整。退料和清空 Job 同次提交；放不下时不部分返还。领取与作废只能有一条成功，后一条的 JobId 已失效 |
| 未完成批次废弃 | `DiscardRefund` | 维持既有规则，仅退未开封材料；与已结束后的半数退料区别明确 |
| 公共台面复制 | `SetAlchemyPresentation → DOREPLIFETIME/OnRep_AlchemyState → Present` | 操作者、JobId、配方、材料索引、温度、档位、动作与时钟复制给观察者；晚进入相关范围的客户端获得当前姿态。点击等待自己这一炉的台面基线 |
| 私有状态／慢回执 | `TickStations → ClientAlchemyState → ApplyNetworkState`；库存回执合并 | 比对库存版本、批次、进度版本与已过时间。未来版本先缓存，旧的不同批次拒绝，同炉进度不倒退。库存回执已有 `AlchemyProgress` 合并，不把较新同炉进度倒回旧快照 |
| 保存失败 | `CommitAlchemyProgress/PersistState`、外层 `Commit/AuthorityTransactionFinished` | 扣料／领取／作废由既有事务日志及档案提交负责；外层提交失败回滚会话缓存和台面占用。未确认写盘冻结后续写入；本轮补齐客机冻结通知 |
| 两人使用同一坩埚 | `Acquire/ProcessInput/Bottle/Release` | 游戏线程上按 Operator 独占，另一玩家不能取得租用；输入及装瓶复核操作者，释放只清除自己的占用 |
| 离台／死亡／换 Pawn | `Reachable → Tick/Suspend`、客户端输入停止 | 距离、遮挡、建筑有效性、角色生存及控制器归属失效后收火暂存，保存并释放占用；输入不能改到另一 Pawn／批次 |
| 退出／重连／换图 | `CloseStationSessions`、`PrepareForDisconnect`、`NetworkEnded`、服务器档案恢复 | 已付批次继续来自服务器保存的 Escrow 和配方快照；正常收尾先暂停保存再交接，客户端清除输入及延迟状态。恢复后火力关闭，不重新扣料 |
