# 焚化炉审计与表现接入（2026-10-27）

## 范围与现有规则

本轮覆盖实际建造焚化炉 `incinerator`：面板、普通物品与弹药投入、确认、取回、存档、拆除保护、客机结算、烟雾和声音生命周期。地牢焚化炉场景及 M66 怪物不是本轮对象。

现有流程是个人档案暂存 → 确认清单 → 一次性持久化销毁。没有燃料槽或持续加工任务。当前 `incinerator-recipes.json` 明确允许无产出销毁，配方表为空；本轮不新增燃料、回收收益或延迟扣料。

## 发现与修订

1. **联机焚化直接走本地 CommitState**：新增 `Incinerate` 库存请求，复用 PlayerState 的序号、库存版本、冻结、上传基线、可靠回执及客机落盘。服务端重新核对存活角色、目标炉实例、距离、遮挡、容器身份、完整投入清单摘要及规则摘要，自行计算产出。成功保存后才触发炉体表现；拒绝或保存失败不播放。旧暂存物品格式不变。
2. **客机删除回执漏清理实例绑定**：按本次移除的实例 ID 清除快捷栏和生产工具引用，其他物品绑定保留。原服务端焚化路径已有清理，现在接收端一致。
3. **默认空配方提示像配置故障**：允许无产出销毁时明确显示“无回收产物”，不再声称收益尚未计算。未来配置弹药产物时使用弹药目录名称。
4. **永久销毁说明被拼成长横行**：确认区使用可纵向滚动的说明与完整投入清单、条目数和数量，按钮改为“确认永久销毁”，警示用黄色。标题、按钮和短标签继续横排。请求处理中阻止重复操作，回执后清除等待提示。

## 本轮检查保留的现有行为

- 普通物品与弹药暂存归个人档案，关闭面板保存投入区；不把其他玩家的投入合并进本次清单。
- 弹药袋转投入区使用专用标记，取回仍回弹药袋。取回容量不足时，阻塞条目留在原容器，不丢弃。
- 空清单、无效配置、整数溢出、配方批量不匹配、库存或规则变化、未来产出放不下均在提交前拒绝。
- 装备背包存入前保留夹层与扩展格检查；枪内弹药、改装、强化、附魔按确认说明随本体销毁。
- 拆除检查在线玩家暂存；离线玩家和已失去炉体的旧容器仍可通过仓库“取回焚化暂存”恢复。
- F6 制作免材料不改变焚化销毁行为。

## 二次源码审计与联机修订

用户要求复查后，发现首轮仍有以下遗漏，已补源码修复。原始文件在本轮整理时移入 `trash/incinerator-retired-20261027/NetworkReview/Before`；原路径及散列见 [归档清单](../Publication/Incinerator20261027/archive-manifest.json)。

- **P1：客机弹药暂存被普通物品上传规则改写／过滤。** 当前 26 种弹药中有 14 种没有普通物品目录条目，例如 `ammo_762_ps`、`ammo_762_ap`、`ammo_556_m855a1`、`ammo_556_m995`；普通 `ammo_556` 的堆叠上限是 999。旧 `SanitizeNetworkItem` 会移除前者，并把大于盒装上限的后者截断；再核对确认清单时会拒绝，之后同步也可能丢失暂存数量。现在带专用标记的暂存条目直接按弹药目录、弹药袋上限、容器和占格规则校验，保留原数量；投入和服务端上传共用显示数据构造函数。不将虚拟弹药变成可取回弹药。
- **P1：相同清单在两端算出不同摘要。** 上传校验总会写入占格并重新序列化 `Item.Data`，首轮摘要却比较原始字符串；仅字段顺序、空白或服务端补齐相同目录字段就会造成误拒绝。现在联网双方对副本使用相同目录规范化，并对完整结构及嵌套 JSON 对象按字段名排序再计算摘要。条目顺序、格式化方式不影响结果，实例 ID、数量、容器及实际内容变化仍影响结果。单机不附加联网目录限制，旧物品仍按原焚化规则处理。
- **P2：晚到删除回执和重连快照漏清理快捷栏。** 首轮清理位于“回执版本不同”分支内；完整档案先到时，等版本回执会跳过清理。现在清理不依赖版本差异；断线未收回执而由更高版本完整档案恢复时，也清除本地原先存在、现已删除的确切实例绑定。背包和弹药袋的数量差量仍只应用一次，玩家主动设置的其他绑定保留。
- **P2：单机销毁写盘未确认仍可继续保存。** 单机现在也使用既有事务保存入口；数据写入后校验失败等不确定结果会阻止旧内存继续覆盖存档，与监听服／客机的处理一致。没有新增世界物品或另建事务日志。
- **P2：闲置焚化炉挤满高炉的 32 个登记位置。** 焚化炉改为仅登记附近正在工作的实例，余烟和声音结束后释放登记；独立限制最多 32 个活跃焚化炉登记，不侵占 32 个高炉登记。实际烟雾组件仍共用最多 6 个的预算，不承诺超过预算时所有炉同时出烟。
- **表现与提示收尾。** 淡出中的音频也计入 4 声道限制，重新进入听觉范围／晚加入按剩余燃烧时间播放；视角消失后继续关闭焚化表现，退出世界取消未完成声音加载。监听服的同步请求返回后不再显示“等待服务端确认”。

本轮逐项追踪了：单机／监听服／客机入口、暂存／拆分／取回、普通物品及所有弹药目录、清单失效、服务端角色／距离／遮挡／炉实例校验、重复请求序号、库存版本、成功落盘后触发表现、失败冻结、旧上传合并、断线重连主机存档和完整快照、晚到回执、炉体落体／销毁、专用服务器不创建表现、关闭面板、声音／烟雾的数量和距离预算。客机通过建筑快照的 WorldKey 初始化世界，双方以同一 WorldKey 生成 SaveSlot，再结合炉体实例 ID 构造暂存容器键，没有采用各自玩家的本地档案名。

暂存仍按项目现有个人档案上传模式同步；本轮补齐焚化提交及相关合并，不改造全项目物品移动协议。以上是源码与目录证据，未启动游戏、自动化 commandlet 或双人联机，不代表已完成延迟／丢包、断线重连及声音画面的运行验收。二次构建结果记录在 `NetworkReview` 中。
