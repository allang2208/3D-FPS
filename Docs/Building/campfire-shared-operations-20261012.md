## 入口与行为

- 建造：B → 其他 → 篝火，ID `campfire`。保持现有模型、建造放置、旋转及主机拆除入口。没有扩展客户端建造系统。
- 操作：玩家存活、距篝火 3.5 米以内且可达时，E 打开“篝火 · 共享烧烤”，沿用冶炼面板和背包布局。
- 添柴：从实际操作者背包、专属隔层、主仓库扣除一份木材。每份 60 秒、最多 600 秒；场景储物箱不参加扣料。燃料属于公共篝火，无人操作、关闭面板、离线期间仍按 UTC 消耗。
- 队列：当前一单加最多 8 个等待订单；一次 1–5 份，每份按菜谱时间完成，使用公共燃料。原料从提交者扣除；断线不撤回已接受订单。无燃料保留进度。当前菜谱为空，因此实际界面不能投放或制作菜品。
- 成品：公共架最多 60 份，先到先取；满架暂停制作，燃料照常燃烧。领取按操作者实际背包容量逐份入包，其余留在架上。没有对每名玩家分别复制一份成品。
- 取暖：燃烧时，玩家脚底至篝火底部锚点球形距离不超过 500 cm，自然饥饿及缺水消耗各乘 0.5。多个篝火不叠加；离开、燃尽、拆除、倒塌、死亡／重生不保留乘算状态。生存结算节拍内重新查询，不立即恢复属性，也不改饥饿／缺水伤害。
- 拆除：沿用主机建筑入口；公共成品、未完成订单原料及整份未燃木材退给执行该入口的主机档案，已燃零头不退。不能完成退料或耐久保存时保留篝火；失去支撑时也保留待处理记录，避免丢弃其他玩家已支付的材料。

## 权威与存档

`AColdSteelPlayerState` 是请求入口。服务端检查拥有者控制器、存活角色、实际已放置的篝火身份、距离、视线、操作类型、菜谱、数量、库存和容量。客户端只能提交动作，不上传公共燃料、进度、队列或成品。

客机提交前复用现有可靠档案分片通道上传本人新快照，等待回执期间暂停本机物品事务。服务端用该玩家的 ShadowModel 扣料／入包；主机使用主机自身档案。`CampfireInventoryRevision` 屏障阻止旧全量上传撤销已接受的篝火扣料。回执和私有库存镜像可任意先后到达，匹配版本后才解除等待。断线清除本机等待状态；重连从主机保存的客人档案续接。

公共快照由篝火 Actor 复制，含燃料、单份进度、等待订单、成品及保存阻塞状态。共享建筑调度每 0.1 秒结算，公共快照最多每 0.5 秒更新，按钮事务后立即更新；客户端用同步服务器时间显示倒计时。新放置和加载完成时主动发布，晚加入玩家接收最新快照。没有每帧遍历全世界玩家或火堆。

交易顺序：先保存篝火原状态及放置身份 → 保存 `_CampfireTransaction` 写前日志 → 耐久保存操作者档案 → 写入并同步保存建筑状态 → 删除日志。日志记录篝火的稳定 `InstanceId`，不会给同格重建的另一篝火重放。个人档案为每个建筑世界保留一个最后交易回执版本，避免别的世界的后续交易误认作本次保存成功。启动时按对应世界回执恢复已提交交易；未提交的不改工作台；无法确认的保留日志。恢复从不把日志当作完整玩家档案回写。缺失菜谱的旧订单保留并阻止拆除，不猜测退料。

建筑仍使用既有 VBX 任务／燃料表；普通高炉路径保留。篝火允许“当前订单为空但有公共成品”的状态，拆除成功后清除空任务。客机不调用建筑保存。这里只收口篝火事务，既有联机库存、客人档案身份和其他工作台的整体权威设计没有重构。
