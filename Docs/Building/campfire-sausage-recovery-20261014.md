# 烤香肠：体力恢复增益

时长已按 2026-10-15 用户规则统一为 600 秒；之前回执保留历史意义。最新规则与测试见 [食物与一日消耗](../Survival/food-duration-and-daily-consumption-20261015.md)。

本批按用户确认接入：成功食用烤香肠后，体力自然恢复速度乘以 **1.05**，持续 **600 秒**。重复食用将剩余时间重置为 600 秒，不叠加倍率，也不累加时长。满饱食度仍允许食用来获得或刷新该增益。接触前取消不扣物品、不授予增益。

保持原制作与食用规则：1 生香肠烤制 20 秒成为 1 烤香肠；完整食用 2.4 秒，接触结算 1.86 秒，恢复当前饱食度上限的 15%，水分与 SAN 不变。鸡腿和羊肋排的数据、动作、菜谱未改。没有新模型、贴图、燃料或获取玩法。

## 数值、事务与显示

- `FFPSSurvivalState` 增加默认值为零的 `SausageRecoverySeconds`，固定时长与倍率也在该类型声明。只保留一份时长，不保存永久属性加成。
- `ColdSteelProfileRuntime::UseConsumableAtContact()` 在已有服务器接触事务中赋值 600 秒，与物品扣除一起提交。保存失败不发布新状态；已有请求序号、库存版本、存活角色与 Pawn 身份检查继续有效。
- `UFPSSurvivalComponent` 继续由服务器的既有 4 Hz 更新调度持有状态。运行时单独复制服务器截止时间给拥有者，各端按服务器时钟读取剩余时间。截止时间不写进跨地图存档，保存的是剩余游戏秒数。
- `StaminaRecoveryRate()` 将已有结果乘以食物倍率，体力上限、即时体力和恢复等待时间不变。实际速率、角色面板和状态卡片读取同一组件状态；没有给显示图标赋予数值结算职责。
- 状态栏新增“香肠滋养”，显示剩余分钟／秒；状态图鉴复用 `status_effects.json` 条目。物品浮窗显示 +5%、600 秒和刷新规则，通过稳定物品 ID 使已有香肠实例也能显示新说明。
- 联机继续通过已有 OwnerOnly 生存状态通道同步，不另发全档案。服务器对后续客机档案上传仍保留实际生存组件值，旧上传不能刷新增益。

## 生命周期

采用项目已有饮用泉水限时祝福的生存状态归属：游戏暂停和死亡等待期间暂停计时，死亡重生重建生存状态时清除；正常切图、保存与读取保留剩余游戏时间；退出期间不扣时，恢复时按剩余量建立新 World 的截止时间。客户端换 Pawn 后读取新组件，不会把旧角色的显示倒计时当作新角色增益。联网断线重连沿用主机现有客机存档／会话恢复流程；这些路径本轮未运行验证。

## 用户测试入口

1. 使用新构建启动后，F6 → 基本调参 → 生成物品，生成烤香肠；或 B → 其他 → 篝火，按 E 使用既有烹饪流程。
2. 食用前记下角色面板体力恢复速度。满饱食度食用也应成功；1.86 秒接触结算后显示“香肠滋养”，恢复速度为原值 ×1.05，动作于 2.4 秒结束。
3. 等待一段时间再吃一份，倒计时回到 5:00，速度仍为 ×1.05；到期恢复原速。接触前取消应无增益、无扣物品。
4. 分别观察保存重载／切图保留余时、退出期间不扣时，以及死亡重生清除。多人由主机和客机各自食用，确认只影响本人，并检查重复请求、断线重连和旧角色回执不会重复授予。

以上是供用户执行的步骤，不是本轮已运行的测试结果。
