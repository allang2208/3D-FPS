## 2. 网格怎么来的

`SourceAssets/Window20260918/build_window_meshes_20260918.py`（无头 commandlet）：

- `append_box` 拼 **闭合盒体**，不做布尔——无头 `self_union` 会坏法线／塌曲率（见体素建造工作流 3.8 与凉亭穹顶事故）。
- 窗框 4 条边梃、窗扇 4 条边梃＋1 块凹面板，各盒体互不重叠（只在边上相接），所以 `open_border_edges=0`、包围盒逐轴精确。
- 碰撞必须用 **`AlignedBoxes`**：`ConvexHulls` 会把 70×70 的洞口整个堵死（这扇窗的洞就是通行／透光的地方）。
- UV 走 `auto_uv(XAtlas)`；网格默认材质 `Rounded/M_Voxel_Wood`，实际外观由放置时调色板条目的 `Surface` 整体替换。
- 自检：包围盒 20×100×100 / 8×43.5×87（窗扇 X 含把手）、占格 (1,5,5) `OK`，导出三角汤 OBJ 给离线渲染用，
  并**删除被取代的上一版网格**（40×40、80×80 都已清理）。

## 3. 构件支撑：构件必须有"着落"（本版新增，对全部构件生效）

用户报"拆掉窗周围的方块后窗还浮着"。根因是**构件根本不参与结构系统**——体素有承重图（`FVoxelSupportGraph`），
构件只是摆在格子上的 Actor，所以拆掉周围也不会掉（这是旧文档里写明的"当前范围"，现在按用户要求补上）。

做法（`VoxelBuildWorldPrefab.cpp`）：

| 入口 | 行为 |
| --- | --- |
| `IsPrefabSupported(Instance)` | 三条里成立任一条就算有着落：① 底面下有地形（`IsGroundAnchor`，与体素同一个地面锚定口径）；② 任一占格与**体素**面对面相邻（含正下方那一格）；③ 任一占格与**另一件构件**面对面相邻（凉亭三件叠放、栏杆接柱） |
| `CanPlacePrefab()` | 新增拦截：悬空位置**直接拒绝放置**，提示「该位置悬空 · 构件要与体素、别的构件或地面接触」（与体素"要有支撑才能放"同一口径） |
| `VerifyPrefabSupport(Edit)` | 在 `ApplyChanges()` 末尾调用——**所有**体素增减（玩家放置/拆除、过载压坏、炮弹摧毁、倒塌脱落）都会走到这里；只检查**改动点及一圈邻居**命中的构件，失去支撑的按右键拆除同一条路径脱落（不退还材料，与手动拆除一致），提示栏播报「构件脱落 · 失去支撑」并写日志 `PREFAB_DROP` |

要点与边界：

- **筛选**：每次体素改动只扫"改动点周围一格"命中的占格（`PrefabCellOwner`：占格 → 构件锚格），
  不做全量扫描——凉亭一件就有 8.7 万格。
- **抽样**：单件占格超过 4096 时按步长抽样找接触点（大件通常站在地形上，第一条就短路了）；
  超大构件理论上可能漏判一次接触。
- **地形口径**：`IsGroundAnchor` 只看 40.5 cm 内的地面（射线还排除建筑自身与残骸），所以"吊在楼层中间的窗"
  不会被脚下的远处地形判成着地。
- **不在检查范围内的**：地形被弹坑/铲子挖掉导致的构件悬空（地貌破坏是另一套系统，没有回调到建造世界）；
  存档读取时也不重判（老档里已经悬空的构件要等它旁边第一次体素改动才掉）。
- 这条规则**对所有构件生效**（门、罗马柱、栏杆、凉亭、喷泉、围栏），不只是窗——这是用户的原始诉求"接入建筑的物理系统"。

### 3.1 修正：判定此前没生效 + 脱落改成真落体（2026-09-18 晚）

用户复报"拆掉支撑后窗还是浮空"，用隔离调试世界复现（`SourceAssets/Window20260918/probe_prefab_support_20260918.py`）：
空地建 1 格厚墙 → 开 5×5 窗洞 → 装窗 → 拆掉窗下整根支撑柱 → 再拆掉整圈墙（`blocks=0`），
**修正前 `blocks=0 prefabs=1 windows=1`**：构件记录没被清、窗 Actor 也没掉。

| 项 | 结论 |
| --- | --- |
| 根因 | `IsPrefabOnGround()` 沿用 `IsGroundAnchor` 的探针带"底面 +40.5 cm"，而**构件自己的网格就在这条带里**；忽略名单只有 Pawn／`AVoxelBuildWorld`／`AVoxelCollapseFragment`，占位 Actor 与逻辑构件都没排除 → 任何构件都把自己的碰撞当成"底下有地形"，分支①恒真，永远不掉 |
| 反证 | 同一脚本里：空中孤立窗被正确拒绝（`place_prefab=False`）、贴墙窗被正确接受、把第二件窗叠在第一件上也被接受 → `PrefabCellOwner` 与相邻面判定本身是好的，问题只在地面探针 |
| 修正 | `IsPrefabOnGround()` 只排除**这一件自己**的占位 Actor 与逻辑构件后再采样；体素放置的 `IsGroundAnchor` 口径不动（其他构件与场景实体照旧算表面） |
| 脱落行为 | 由"直接移除"改为**真落体**：`AVoxelBuildPrefabActor::BeginFall()` 给占位网格补上调色板代表网格后切成刚体自由落体；逻辑构件挂到刚体上跟随、打 `VoxelDetached` 标签停止 E 键交互并关碰撞／Tick，8 秒后随落体销毁。没有可用网格／物理体时退回直接移除。构件免料，不涉及退还 |

崩溃/回归边界：本修正未跑承重探针与实机验收（按用户规则由用户测试）；落体只作用于"失去支撑"的构件，
右键手动拆除仍是立即销毁、不落体。

**补丁（2026-09-21）：清理正在坠落的构件。** 脱落瞬间构件就从 `Prefabs` 记录里移除了，
但 Actor 还要飞 `LifeSeconds`（8 s）。于是右键点一个正在下落的构件会走进 `RemovePrefab` 的
"记录里查不到"分支，提示「该构件不在建筑记录中」——**玩家清不掉它**；更糟的是如果同一格
已经放了**新**构件，用 `AnchorCell` 反查记录会命中新构件并把它销毁。
修法：`AVoxelBuildPrefabActor::BeginFall()` 成功后置 `bFalling`（`IsFalling()` 对外只读），
`RemovePrefab()` 对 `IsFalling()` 的构件走独立分支——只销毁自己和它的逻辑构件，
不碰 `Prefabs` 记录、不重判锚定（脱落时已 `ReanchorVoxelsAround` 过）、不退还材料（构件本就免料），
提示「已清除正在坠落的构件」。已通过全量编译（`Result: Succeeded`），未实机验收。

## 4. 开合逻辑（照门那套，两点不同）

`AColdSteelWindow` 与 `AColdSteelDoor` 同口径的部分：

1. **包围盒对齐**：`AlignGeometry()` 一律按 `FBoxSphereBounds` 摆位，网格 pivot 在哪都不影响贴地／居中（门 2026-09-17 的悬空事故就是按 pivot 摆出来的）。
2. **开向跟随玩家**：默认朝玩家的**反侧**开（＝玩家把窗推开），拿不到玩家位置才退回本地 +X 侧。
3. **被挡就反向开**：两扇在 25%／50%／75%／100% 开合角上做重叠查询，只查世界实体（WorldStatic／WorldDynamic／Destructible），**玩家与怪物不参与判定**；首选侧被挡且另一侧通畅就反向。检测位置按**候选开向**的铰链贴面摆（不用当前铰链位置，否则换向判定会偏 4 cm）。
4. **开关过程不挡玩家**：只有「关着且已经静止」的窗扇对 Pawn 为 Block，其余时候为 Ignore。
5. **整体换材质**：`Configure(Surface)` 把窗框与两扇窗扇的**全部**材质槽一起换成调色板条目的材质。

与门不同的两点：

1. **两只铰链固定在外侧**（左扇铰洞口左边、右扇铰洞口右边），两扇**同时朝同一侧**开；
   转角符号：左扇 `−SwingSign·Angle`、右扇 `+SwingSign·Angle`。
2. **铰链贴面随开向走**（`ApplyHingeDepth()`）：向外开时铰链贴窗扇**外面**、向内开时贴**内面**，窗扇整体落在铰链内侧。
   铰链若固定放在窗框进深中间，窗扇转到 88° 时靠铰链的那半个厚度会**切进窗框边梃**。

其余：开角 88°、开合 0.6 s、`AutoCloseSeconds` 默认 **0（保持打开）**。

## 6. 材质渲染

`SourceAssets/Window20260918/render_window_materials.py`——纯 numpy z-buffer ＋ Lambert 的**离线**渲染
（不开引擎、不依赖 RHI），按与 C++ 完全相同的铰链数学摆窗，再分别按三种材质上色。相机／光照写在脚本顶部。

- 材质色：**大理石**从材质图里读出真实基色 `StoneBody = (0.62, 0.61, 0.58)`；
  **木材／石头**（`M_Voxel_Wood`／`M_Voxel_Stone`）是贴图材质，Python 侧读不到可直接用的基色参数，
  渲染用的是脚本里标注的近似色（木 0.44/0.28/0.15、石 0.53/0.51/0.47）——只看形，不看准。
- 光照只做面法线 Lambert ＋ 环境项；深度是**逐像素插值**的（整面共用一个深度时，20 cm 进深的洞口侧壁会与窗扇互相遮错）。
- 参照墙是脚本生成的一层 20 cm 体素墙（洞口两侧各两格、上下各两格，中间挖 5×5 洞），窗抬到洞口里（z 60..160），
用来读尺度；格锚点按洞口起点对齐，洞边才落在格子缝上。

输出（`preview_20260918/`）：`window_material_sheet.png`（木／石／大理石关窗 3/4 对照）、
`window_{wood,stone,marble}_closed.png`、`window_stone_isolated.png`（去掉墙看比例）、`window_stone_front.png`、
`window_marble_inside.png`（室内侧）、`window_marble_handle_detail.png`（中缝特写：两个把手）、
`window_marble_open_isolated.png`／`window_marble_open.png`（向外开）、
`window_wood_open_inward.png`（向内开）、`window_wood_open_top.png`（俯视看两扇摆向）。

装配自检（脚本每次运行都打印，可作为几何回归）：

```
关·  左扇 x=−4.0..4.0   y=−44.0..−0.5   z=66.5..153.5   ← 关着时两扇居中于窗框进深（X 含把手凸出 ±4）
开外 左扇 x=1.7..45.3   y=−44.0..−34.4                   ← 铰链贴外面，两扇都摆到 +X（墙外）
开内 左扇 x=−45.3..−1.7 y=−44.0..−34.4                   ← 铰链贴内面，两扇都摆到 −X
```

85° 时窗扇（含把手）的 Y 恰好停在洞口边（−44.0），再开大就会扫进窗框边梃——这就是开角取 85° 的依据。

## 8. 已知边界与未做

- **没有玻璃**：整扇（含窗扇）与墙体同材质，是门那套「整体替换」口径的延续。
  要保留网格自带的玻璃槽，把 `Configure()` 里窗扇那两处循环改回只 `SetMaterial(0, Surface)` 即可（槽位已预留）。
- **只适合一格厚的墙**：窗进深 20 cm ＝一格体素；两格厚的墙要另做一版深 40 cm 的网格（脚本里 `FRAME_DEPTH` 一处改，占格变 (2,5,5)，C++ 不用动）。
- 铰链是「贴面旋转」的简化口径，没有合页五金；开角固定 88°，没有限位／撑杆。
- 没有音效；构件脱落也不退还材料（与右键拆除一致）。
- 构件**仍然不参与承重**（不传力、不压垮下面的方块），本轮只补了"有没有着落"。
- 未实机实测：编译、资产读回与离线渲染都通过，但**没有进游戏**验证放置、预览对齐、按 E 开合、被挡反向、拆除与存档。

## 9. 交给用户的实测清单

1. 进游戏按 B → 木材／石头／大理石任一栏 →「其他构造」，应看到三扇窗卡（各带对应材质缩略图）。
2. 在 20 cm 墙上挖出 **5×5** 的洞，放置窗：预览与落地应重合（同格对照，工作流 3.8）。
3. **支撑**：把窗周围的墙块拆掉——窗应在失去最后一个接触时**脱落**并在提示栏播报「构件脱落」；在空中悬空的位置**直接放不下**（预览显示「该位置悬空」）。
4. 站在室内按 E：两扇应朝**室外**（玩家反侧）对开；站到室外再按 E：朝室内开。窗口外若被贴着的方块挡住，应反向开。
5. 拆除（右键窗本身）与存档（退出重进）照旧。
6. 顺带验一下既有构件没被这条新规则误伤：凉亭／喷泉／栏杆／门都还能正常放置与保留。
