## 随机性与接入

系统关闭 Determinism。UE 5.8 的 `NiagaraSystemInstance.cpp` 在非确定性系统重新激活时更新 RandomSeed；粒子使用 `Engine.System.RandomSeed` 选择序列及初始参数，对象池复用也能改变外观，不依赖命中坐标重复生成同一张形状。

每次命中只播放一套完整序列，两帧覆盖率加权插值，避免随机跳起始帧或突然切换轮廓。水冠包含已烘焙的运动，不再额外整片执行抛物线导致双重上抛；额外水滴保留弹道运动。

制作入口：`Tools/Fluids/bake_river_splash_natural.py` 与 `Tools/Fluids/author_river_splash_natural.py`。旧 `author_river_pilot.py` 的正式入口已转交新水花制作，避免重跑时回退到旧扇形材质。

## 用户截图中的矩形卡片修正

用户认可水花形态，但报告水花周围出现深色方形平面。本次只调整 `M_RiverCrown` 和对应制作源码，不重烘焙、不改变粒子、纹理、河面或涟漪。

针对问题读取的证据：源 PNG 空白像素 Alpha 为 0；UE 纹理 `compression_no_alpha=False`，材质 RefractionMode 为 None。原采样代码在零覆盖率处将加权后的 RG 置为 0，随后法线解码产生沿卡片平面倾斜的法线，而不是中性的 `(0,0,1)`。高光参数也未限定在水花轮廓内。UE 前层透明 GBuffer 对 Default Lit 材质只排除完全零透明度像素，因此低覆盖率边缘的处理尤其重要。没有进行实机复现或 GPU 通道采样，截图中各渲染通道的贡献不作量化结论。

修正内容：

- 将极低的覆盖率压到精确的 0，像素着色阶段丢弃空白区域。
- 透明区域的法线数据回到中性值，高光乘以轮廓覆盖权重。
- 仅为水冠材质关闭 `Allow Front Layer Translucency`，避免短暂的精灵卡片参与前层透明表面重建；保留实际水花的常规光照和项目全局 Lumen/光追设置。
- 没有增加纹理采样、粒子数量或实时模拟。

单材质接入脚本与保存回执位于 `SourceAssets/RiverSplashNatural20260924/CardFix/`。未启动游戏、截图或追加运行验收，观感由用户测试。

## 二次排查：已定位并修复图集中的空网格帧

用户复测仍见方块。上节的法线和反射修正没有解决根因，不能再以其保存成功作为方块消失的证据。

真正原因是烘焙脚本没有处理零顶点的 FLIP 缓存帧：水花消失后，Blender 将模拟域原始方盒作为回退几何渲染进图集。4 套共 128 帧中，43 帧已经没有液体网格，旧图集对应区域却存在 Alpha=1 的矩形。边角人工设置的两像素透明边框掩盖了第一次仅抽查图像边角的不足。

修复与证据：

- 烘焙入口读取每帧 `.bobj.gz` 的顶点数；零顶点直接生成透明图块，不再渲染模拟域。此次使用 `--repack-existing` 保留原缓存和非空 EXR，不重新模拟。
- 空帧为第 0 套 23–32、第 1 套 21–32、第 2 套 23–32、第 3 套 22–32 帧（帧号从 1 开始）。
- `preserved-frame-comparison.json`：85 个正常帧 RGBA 最大逐像素差异为 0；43 个空帧 Alpha 最大值由 1 变为 0。
- 单修图集后的 GPU 读取仍发现粗驻留 mip 将邻帧混入空帧，最大 Alpha 约 0.056。此单张小图集改为 `NeverStream=True`，保持完整 mip 驻留，理论预算约 2.67 MiB；不调整全局纹理池。
- 材质从烘焙清单生成 `SplashValidFrames=(22,20,22,21)`，动画进入空帧后直接停止绘制；最后一个正常帧只与透明帧插值，不采样下一张空帧。
- `gpu-alpha-after.json`：在独立 D3D12 commandlet 中读取图集，43 个空帧的采样 Alpha 最大值全部为 0，正常水花仍有 Alpha=1；这属于本次用户要求的针对性排查，不等同于游戏画面验收。
- 已重新导入并保存 `T_RiverSplashPacked`，重建并保存 `M_RiverCrown`；见 `empty-frame-fix-delivery.json`。没有修改 Niagara 粒子数量、河面、伤害或涟漪。
