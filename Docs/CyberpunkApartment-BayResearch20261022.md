# 公寓窗外夜景：现有瓶颈与制作路线

> 后续制作已完成并保存到原公寓地图，见 [分层海湾制作记录](CyberpunkApartment-LayeredBay20261022.md)。下文保留方案形成时的研究与旧资产诊断；其中“尚未制作”描述的是研究阶段。

研究日期：2026-10-22。此文件属于本轮用户要求的 GitHub／成熟项目调研；本轮不把调研结论冒充已经替换的新外景。

## 当前资产的实际限制

当前 `SourceAssets/CyberpunkBayBackdrop20261021/cube.json` 记录：输入图 1774×887，输出 Cubemap 六面各 1024，RGBA8 sRGB。`install_background.py` 使用立方体贴图、有限盒投影和一个大球背景。它不是由完整城市几何烘出的高分辨率环境。

主要限制发生在源图：窗框、楼层、霓虹字和水面倒影已经被压到很少的像素中。把这张源图扩成 4K、8K，或者只把 Cubemap 面尺寸增大，不会恢复这些真实结构。盒投影只是在有限移动范围内近似背景视差，也不会生成正确的遮挡关系、建筑深度和水面运动。

另外应分清两个问题：纹理缺少细节，以及极细高亮灯点在运动中闪烁。前者要改善源几何／源图；后者需要合理的灯带尺寸、Mip、抗锯齿与发光范围，不能只追加更多单像素亮点。

这些资料支持的是**分层组合**，并不支持“成熟项目一律使用一张夜景图”或“一律把整座城市缩成一个小模型”的结论。

## 针对此公寓的建议

采用“近处真实结构 + 中景低成本三维 + 远景烘焙”的方式。以下距离和分辨率是本场景建议的制作起点，不是已测出的性能承诺。

| 层级 | 建议制作内容 | 原因 |
| --- | --- | --- |
| 公寓外墙、阳台下方、近岸设施 | 保留真实尺寸的外墙、窗台、栏杆和少量附近楼体，正常深度遮挡 | 玩家贴窗、侧移、向下看时，近处必须有真实位置关系 |
| 海湾水面与出海口 | 独立水面、两岸岸线、河口轮廓；用可控法线和反射处理水纹与灯光倒影 | 不再让水面与楼群一起锁死在同一张照片里；保持“从一岸看对岸”、开阔水域及出海方向 |
| 对岸主要楼群 | 按真实距离布置少量有层次的建筑组，近中远高度错落；楼面用重复立面材质，霓虹与窗灯用共用图集／发光遮罩 | 中景剪影、建筑遮挡和移动视差来自几何；不用给每扇窗单独建网格或实时点光源 |
| 更远城市与天空 | 从同一城市源、同一地平线捕获高分辨率 Cubemap；部分重点楼组可使用多视角 Impostor | 把细节保留在源制作里，再压缩运行时成本；远处不会暴露完整城市的几何开销 |

建议先制作少量代表性建筑组和清晰的海湾岸线，确定构图后再铺开。不要先生成上千座相似盒楼，再希望通过亮点数量弥补美术质量。

### 分辨率与内存

可见窗外主方向的烘焙起点可设为每面 4096 的 Cubemap，前提是从足够清晰的三维源重新渲染，而非放大现有 1774×887 图片。需要透明边缘的独立楼群替身，使用各自的图集和 Mip。

以 BC7、六面、含完整 Mip 粗略计算：2048 面约 32 MiB，4096 面约 128 MiB；实际 UE 平台格式、驻留 Mip 与运行资源另算。不能只为了标题写“8K”就让不可见天空和地面占满同样的高分辨率预算。此处是格式容量估算，不是运行显存测量。

单一远景 Cubemap 适合公寓这样观察范围受限的场景；若以后允许飞行、走近对岸或跨城区移动，应改为真实城市几何、流送与 HLOD，不继续扩大盒投影的使用范围。

### 不采用的捷径

- 把现有低分辨率图片直接超分后宣称城市细节已重建。
- 只加锐化、高饱和发光或几千个单像素灯点；这些可能加重远景闪烁。
- 在公寓每帧运行六面 SceneCapture 来替代离线制作。
- 为此调整全项目纹理池、关闭 Lumen／光追，或直接装入未经适配的旧 UE4 插件。

当前夜景资产保留。本轮已完成尺寸与管线排查、案例研究及可执行的制作分层；新的城市三维源、海湾水面与高分辨率烘焙尚未制作。
