## 现有云统一方案

**统一云的材质来源、纹理和天气驱动，允许各场景设置不同的云层高度、厚度与覆盖率。** 主神空间使用同一套云形成下方云海；不再引入 GitHub 云、另做云图集或叠加第二套云片系统。

本轮从现有源码和制作脚本读取到的关系：

- 共享母材质 `/Game/Weather/Materials/M_FPSLayeredClouds`，共享实例 `/Game/Weather/Materials/MI_FPSLayeredClouds`，由 `Tools/Weather/build_layered_cloud_material.py` 制作。
- 丘陵实例 `/Game/WorldGeneration/TemperateHills/Sky/MI_HillsClouds` 的制作脚本已经将共享实例设为父材质，只保留场景参数差异。
- `FPSWeatherManager` 与 `StormCloudComponent` 负责云量、密度、风向、连续运动、雨云颜色及云内闪电。昼夜仍由现有天空管理器驱动，不新增太阳／天空光或独立天气时钟。
- 现有共享实例已有云分布、高度曲线、遮罩与体积噪声的纹理绑定。后续沿用这些绑定及已有修复，不能只复制母材质而丢失实例纹理。

目前 `StormCloudComponent` 的启用名单包含主场景、诺曼底、战壕和丘陵；它会复用已存在的云组件，并非无条件替换所有场景中的任意云材质。因此这里是**确认后接入的统一方案**，不是“所有地图运行时已统一”的完成声明。

浮空高度需要和控制器一起适配：现有雨云逻辑会将云底插值到固定 **1.55 km**，直接移动云 Actor 不能保证云海留在平台下方。接入时应把晴天／雨天云底、厚度和覆盖率收敛到场景配置，并处理 `SkyAtmosphere` 的高度基准；主神空间与地面场景共用材质和天气逻辑，各自采用适合的高度配置。下表负值均为**相对平台的构图距离**，不能直接作为 UE 云层海拔参数填写。平台是否保留在世界原点附近，待正式接入的高度基准方案确定。

## 下方大地与 GitHub 参考

**推荐：现有统一云海＋低面数背景地表＋远山和现有大气透视。** 地表作为不可抵达的远景，借鉴河谷、山脊与地表颜色分区，优先离线制作贴图和网格。

| 项目 | 核实内容 | 本场景用法 |
|---|---|---|
| [tangrams/heightmapper](https://github.com/tangrams/heightmapper) | MIT 代码；可导出灰度高度图，用于三维位移 | 需要真实山脉时用于离线取形；高程数据授权与工具代码授权分开记录。本版使用原创程序地形，没有下载地理数据 |
| [CesiumGS/cesium-unreal](https://github.com/CesiumGS/cesium-unreal) | Apache-2.0 插件；地理空间生态集成，支持全球地形／影像工作流 | 仅在以后确实需要飞到地面、地理坐标或大范围漫游时考虑；本次静态远景不引入它 |

云体和体积雾不是越多越好。Epic 文档说明采样数量直接影响云质量与成本，并提供反射／阴影采样、保守密度跳步、多次散射等缩放项：[Volumetric Cloud](https://dev.epicgames.com/documentation/en-us/unreal-engine/volumetric-cloud-component-in-unreal-engine)。以下数值是本项目的**设计预算**，没有 FPS 或毫秒实测承诺。

| 深度层 | 建议布置 | 性能实现 |
|---|---|---|
| 近景 | 平台、栏杆、柱廊、主要功能物 | 现有 Nanite／LOD 和空间实例分组；保留接触阴影与可行走碰撞 |
| 下方云海 | 云峰距平台约 150～350 m，主要云体约 280～600 m；先以保留约 40% 地表窗口为构图目标 | 复用现有共享体积云材质、纹理和单套天气控制；通过现有云形与覆盖率形成高低层次，不要求新增两个云层或额外云片 |
| 大地 | 基底约 −1.5 km、丘陵起伏不超过 520 m；河谷、林区、丘陵斑块 | 1 个约 3.3 万三角面的背景网格，目标 2 个材质以内，2K～4K 颜色／宏观遮罩＋mip；无碰撞、导航、交互或植被 Actor |
| 远山与地平线 | 多公里外，越远越蓝、越灰、对比越弱 | 共用低面数山带或烘焙远景；交给现有大气透视，不再生成可玩地形 |

正式 UE 接入时，地表材质必须和当前昼夜曝光／天空颜色联动；云沿用现有光照和天气参数。远景网格的阴影和 Lumen／RT 参与按用途单独设置，不能全局降光追或关闭 Lumen。云质量分档沿用现有体积云采样、反射与阴影开销设置，再针对俯视云海的屏幕占比调节；不增加逐云团 Actor Tick。遥远地表不布置独立植被阴影或交互对象。以上为实现方向，未做性能采样。

这次 Blender 的体积云仅用于说明云峰高度与视差，其外观不作为正式云选型；正式云复用游戏现有素材。远地表目前是程序地形与颜色，不是已经导入的游戏大地贴图。原预览的两处云高度记录仅服务 Blender 构图，不规定正式 UE 必须建立两套云。

## 从预览得出的组件缺口

### 优先补齐

1. **浮空平台底裙／檐线／切角收口**：当前只有上层建筑件；下方可见的分层底座本轮为概念块体，需做统一拼接、UV 和底面。
2. **祭坛宽台阶＋侧面缓坡＋端头栏杆**：新旧台面高度变化需要完整组件；现有一个旧台阶不足以组成新祭坛基座。
3. **主神核心装置**：本版光球与环只是占位，需要决定是纯能量球、环形机关还是更具雕塑感的装置。
4. **地表宏观贴图与远山形态**：补河流／谷地、林区、山脊的远景颜色与轮廓，可借鉴上述地形项目。云素材已经具备，不列入组件缺口；另有现有云统一接入与浮空高度适配的开发工作。

### 可以随后补

5. 生产侧院的矮隔墙／轻屋盖及箱子停放位：当前功能物尺寸很小，侧院仍显空，需要有尺度适当的建筑围合。
6. 传送门底座与统一导向铭牌：门框现成，目标识别和场地接口需要补齐。
7. 简单石凳、窄花池或少量绿植：改善停留点；不建议一开始满场布树遮住云海。

本版没有假造一个已经完成的主神系统；核心、侧院围合与新平台模块都等待本次看图后的设计选择。
