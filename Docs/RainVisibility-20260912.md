# 雨滴可见性与水坑距离修正

用户反馈：下雨时看不到雨滴下落，地面水坑过密且只出现在近处。本次修改下落雨丝的呈现和地面积水分布，继续使用现有引擎及程序化材质，无新增采购。

## 原因与修正

同一 `DayNight_Lighting` 场景、1280×720、雨天预设下，修正前的 GPU SimCache 读取到 1,077 个存活粒子，实际尺寸为 2.1×48 cm，位置跨越相机高度并落到地面以下。发射器保持激活，问题出在呈现环节。原材质又用宽度系数 24–70 的高斯函数压窄雨丝，最大透明度只有 0.24，并从 13m 开始淡出。在暗天空前仍能辨认，亮地面前则接近不可见；上一轮只检查雨量参数和材质绑定，遗漏了这个对比度问题。

新雨丝几何尺寸为 3.2×46 cm，高斯系数改为 3–7，透明度上限 0.58；保留随机长度、柔和边缘、生命期淡出和风向，远距淡出改为 20–30m。没有提高发射数量。近距离仍有淡入，避免贴脸的大片雨卡。

村庄复查发现第二个呈现问题：原材质使用 Volumetric NonDirectional 透明光照，不使用水滴法线计算表面高光，粗雨丝仍会融入暖色背景。现改为 Surface ForwardShading，并用曝光补偿的低强度散射下限提高辨识度。这是游戏可读性的近似，不宣称为物理散射模拟；仍由正常光照提供表面高光，深度测试与碰撞继续生效。该模式逐像素计算光照，不能把前一版材质的 GPU 数据当成本版的性能结论。

水坑原本在 6m 间距的连续网格中重叠铺设，默认仅有 3×3 个近处格子。现在使用 16m 间距、9m 宽贴花，默认及高档使用既有 16 个池槽位；小水坑纹理本身也降低覆盖率。偶数网格按最近边界居中，避免集中到玩家一侧。贴花屏幕尺寸淡出阈值从 0.002 降至 0.0002，让远处积水保留；近处水花在 8–14m 淡出，远处不持续发射难以分辨的小粒子。

仍然保留世界坐标固定、每次最多两次放置、定期屋顶重查、雨停后缓慢干燥和质量档位关闭。16m 指池中积水区域中心间距，每个区域内仍包含数个不规则水洼，并非每隔16m一个规则圆坑。

## 资产与复现

当前库是 `/Game/Weather/RainVisibility/DA_WeatherPresentation`，新增四个本地资产：库、`NS_ReadableRain`、`M_ReadableRain`、`M_SparsePuddles`。库沿用 NaturalV2 的屏幕水滴、枪械湿润、天空和其他雨效引用。

先按 [AssetSetup](AssetSetup.md) 恢复 NaturalV2；编译 Editor 后运行 `Tools/Weather/fix_rain_visibility.py` 的 UE Python commandlet。它只生成本次四个副本，保留源资产。雨丝源代码是 `SourceAssets/RainVisibility20260912/RainStreak.hlsl`。没有导入或公开第三方原始美术资产。

`Tools/Weather/run_rain_visibility_audit.ps1` 在隔离玩家存档中启动真正的 D3D12 游戏进程，固定镜头，采集 GPU 粒子位置、速度和尺寸，再检查远处水坑、关闭效果、屋檐遮蔽和室外恢复。连续截图为原始游戏帧，记录在 `Saved/RainUpgrade`。已有编辑器需重新启动才能加载新 C++ 模块。

## 验收

Editor/Game Development 编译通过；三个场景共 25 项专项检查通过，村庄地面回归 16 项通过、失败 0。地面回归覆盖世界坐标稳定、低/高档位、干燥、脚步涟漪、新建屋顶、屋檐滴水和室外恢复，观测到单次最多 5 条地面射线。结果写入 [validation.json](RainVisibilityPreview20260912/validation.json)。本轮不作独立 GPU 耗时结论，也未执行完整打包。

| 默认测试镜头 | GPU 向下运动雨滴 / 其中视野内且高于地面 | 视野内较远水坑中心 |
| --- | --- | --- |
| DayNight_Lighting | 880 / 46 | 33.94m |
| Normandy | 1147 / 76 | 34.57m |
| MilitaryTrench | 935 / 87 | 31.39m |

实际检查了三张地图的雨丝和地面画面。村庄与战壕截图中仍可能出现原有纹理流送预算提示。斜坡贴花沿法线抬高 2cm，测试允许两侧法线投影造成最多 4cm 的网格测距偏移；脚步回归也改为确实移动超过触发距离并落在水坑区域，避免旧密集网格测试位置失效。

雨丝前后使用同地图、同镜头和雨天预设；天气时间仍在运行，不应当作完全静止的逐像素差分。动态预览是以 4fps 采集的游戏截图序列，未补帧。
