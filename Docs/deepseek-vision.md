# 读图入口与兼容脚本

## 当前使用规则

- 用户要求读图时，优先使用当前宿主提供的图像读取能力；工具名称以本次可用工具为准。原因：旧环境的 `read_image` 名称和图片路由不是所有宿主共有的接口。
- 仅在宿主不能接收目标图片，或用户明确指定外部视觉复核时，使用 `Tools/deepseek-vision.ps1` 或个人 `deepseek-vision-skill` 的兼容入口。原因：外部调用会另行传输图片并产生服务调用，宿主已能读图时没有必要增加这条链路。
- 外部脚本返回的文字应标明为模型描述，不说成自己已直接看到原图。原因：描述可能遗漏细节，文字回执与像素内容是不同证据。
- 使用本次对话提供的图片或明确指定的文件，不扫描其他对话或按“最新附件”猜图片。原因：相邻会话的图片并不属于当前任务，时间顺序不能确定用户指的是哪张图。
- 角度、尺寸、偏移和接触位置以原图像素或几何数据为依据；缩图只用于阅读副本。原因：视觉描述和缩放后的图片不能提供原始精度的定量结论。
- 图片是否缩放、上下文容量和缓存方式以当前宿主行为为准，不保留固定 10 MB / 50 MB 会话预算或“每换候选新建对话”的要求。原因：这些数值来自旧环境单次故障，不能当作当前产品限制。
- 默认不生成预览、截图或调用外部服务来证明读图能力；按用户实际请求处理。原因：文档入口不构成额外测试或渲染授权。

## 工程兼容脚本接口

以下参数来自本机 `Tools/deepseek-vision.ps1`；它们描述脚本接口，不证明远端模型当前可用。原因：脚本默认值与供应商的实时服务能力不是同一事实。

| 参数 | 含义 |
| --- | --- |
| `-Image` | 本地文件路径或 HTTP(S) 图片 URL；相对路径以工程根目录解析；多图逐张请求 |
| `-Prompt` | 具体问题 |
| `-OutFile` | 描述输出文件 |
| `-Model` | 脚本默认 `deepseek-v4-flash`，允许指定 |
| `-MaxTokens` / `-TimeoutSec` | 默认 1200 / 120 秒 |
| `-Endpoint` | 脚本默认 `https://api.deepseek.com/chat/completions`，允许指定 |
| `-ApiKey` | 显式参数或 `DEEPSEEK_API_KEY` 环境变量 |

```powershell
# 仅在上述兼容/外部复核条件成立且本次用户已要求读图时使用
pwsh -File Tools/deepseek-vision.ps1 -Image "D:/shots/arms-closeup.png" -Prompt "左手是否握住握把？" -OutFile "D:/shots/arms-description.txt"
```

- 密钥只通过已有参数或环境配置传入，不写入项目文档、日志或仓库；缺失时报告脚本错误，不输出密钥内容。原因：读图说明不需要凭据值，落入报告会造成无关披露。
- 沿用脚本对 JPEG、PNG、GIF、WebP 的内容识别，以及单图超过 25 MB 拒发、超过 8 MB 告警；不把它们写成供应商或宿主的统一上限。原因：这些是本地实现的发送限制，作用域仅是该脚本。
- 提问限定目标图片和具体差异，并记录实际通道、提示词和返回结果。原因：后续解释需要知道描述对应的输入，不能把不同候选或不同问题的结果混用。
- 交付区分模型描述、几何测量、用户认可和游戏运行结果。原因：任何一种读图通道都不能代替用户视觉验收或证明运行逻辑通过。

## 保留的历史事实

2026-09-15 的合成图探针曾正确识别 `FPS-7-13-KX`、`vault 42 - nine` 及所列形状和方位；天气案例中一张接近全黑的图被描述为黑屏。这是当时指定图片的诊断记录，不代表后续模型、配置或图片已通过。

2026-09-16 的旧宿主会话累计约 49 MB 图片后，在约 51.7 MB 请求处出现 `413 Payload Too Large`。2026-09-22 文档又记录宿主加入图片规范化。这两项保留为故障时间线；当前入口不再据此要求换对话、固定压图或保证原生分辨率。

旧 `-Latest` 参数已不在工程脚本中，历史扫描会话恢复附件的方法退役。`Tools/shrink-for-view.ps1` 仅作为用户需要阅读副本时的尺寸转换工具，不是读图必经步骤。
