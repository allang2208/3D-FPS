## 源码排查发现与修正

1. 夹层直接换装只向同一个原格逐件回填：换下较大装备或主副手同时回填时拒绝。改用共享的有界联合布局搜索，源夹层优先，自动回填可旋转，整组放不下再尝试主背包。
2. 装备拖到夹层中的装备上必然失败：原返回函数不支持装备来源。加入按落点锚格选择兼容替换装备，其余覆盖物和副手一起回填；失败不卸掉任何装备。
3. 夹层交换拒绝所有多件覆盖。共享布局搜索现支持动态列数，背包／仓库／夹层之间保留来源位置域与容器归属。
4. 夹层自动放入路径先找空格，导致后面的自动合堆分支不可达；夹层自动取回主背包在不可旋转且放不下时仍可返回成功。改为先执行原子插入，必要时重试另一朝向，并明确处理失败。
5. 手动夹层落点没有完整边界判定。现先判断矩形是否在网格内，再计算覆盖与回填，预览和提交采用相同规则。
6. 旧背包容量搬移没有移除夹层原实例，且更换列数按旧线性索引判断；扩展格回填还可能使用旧背包行数。改用最终装备容量，按原二维坐标重映射，先移除迁出条目再回填。
7. 主背包／仓库部分合堆恢复了原位置或宽高，却没有完整恢复原朝向。剩余堆统一保留原源实例的朝向与容器数据。
8. 夹层拖至仓库交换时，被换物品错误地回主背包。现在回到夹层；仓库装备替换也采用可转向联合回填，副手放不下时取消整个换装。
9. 装备槽之间交换双手武器会直接拒绝被挤出的副手。现按主背包容量统一回填副手，放不下保持原装。
10. 夹层武器未参加动态图标请求及就绪刷新，夹层回填位置也未绘制。现复用既有事件和同一 proposal 的格位、朝向、所在区域绘制；容量变化时不将新列数坐标画在旧网格上，改为明确提示重新安置。卸包后键盘焦点回到仍存在的主背包。
