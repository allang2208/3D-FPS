## 状态归属与源代码结论

- 私人阅读器、目录页码、鼠标拖动和渲染目标属于本地 UMG/预览实例，不复制指针或 RT，不改变制作配方选择。
- 当前制作配方对应的跨页提交通过 `ServerStationInput` 请求服务器；它的实际声明已是 `Server,Reliable`，保留现有通道。
- 服务器核对 Pawn、批次、递增序号、工作台归属和可达性，再更新 `FAlchemyBenchState::BookPage`；`AVoxelBuildPrefabActor::AlchemyState` 的 RepNotify 驱动各端公共书页。
- 专用服已在 `UPotionWorkbenchVisualComponent::Configure` 中提前返回，不建立纸页、UMG 或 GPU 表现。
- 付费批次沿用自身配方快照；阅读其他配方章节不会向服务器提交配方切换。

本次修复：`AlchemySystem::Input` 在客户端与权威端共同拒绝超出公共书页协议范围 `[0,7]` 的页码。原先负数会被夹成首页、极大整数会被夹成末端值，错误请求仍会改动公共书页；现在直接返回失败。合法页码和本地完整目录浏览不受影响。

追加的实际联机问题：`Records/sockets-20261016-230437/host.log` 中 phase 1–7 全部通过，phase 8 记录 `expected=0/0 actual=1/0 ... open=1 displayed=1`。客机角色销毁后，工作台仍保留旧批次和页码，主机的公共手册未关闭。`Release()` 原先用 `Operator == WorkingPawn.Get()` 判断归属，弱引用在角色销毁后已取不到对象，导致清理跳过。现在在没有有效操作者时使用同一批次 ID 清理旧状态；有效的新操作者不会被旧会话释放。修复后的同一路径 phase 8 已通过，之后主机接管及晚加入也通过。
