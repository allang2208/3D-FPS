# 弹药袋与动态弹种轮盘

2026-09-21。按用户批准的方案接入。未运行游戏测试或额外渲染；概念预览不是实机截图。

## 玩家操作

- Tab → 装备与背包 → 弹药袋。按兼容组查看备弹，当前武器组置顶；背包满时也能获得弹药。
- 只有一种已开放兼容弹种时，R 按下直接普通换弹。
- 存在多种兼容弹种时：短按 R 普通换弹；按住0.30秒打开圆形轮盘，移动鼠标选择，松开 R 确认。
- 轮盘按实际目录数量 N 等分为360°/N。零数量类型保留位置并灰显；当前弹种、零数量、中心区均不会提交切换。新类型无需改 UI 代码。
- 轮盘期间退出 ADS、停止射击，鼠标只控制轮盘；角色仍可移动，世界不暂停。移回中心或 Esc 取消，失焦、菜单、换枪和动作占用取消选择。
- 双持默认主手；轮盘内左键选主手、右键选副手，鼠标选择后仍以松 R 确认。
- 袋页可预选当前主手的其他兼容弹种，再点“返回并切换弹种”，关闭面板并播放空仓换弹。副手使用轮盘选择。

## 数量和换弹

角色 `AmmoPouch` 只保存备弹；武器 `LoadedAmmoType` 和 `Magazine` 保存装填状态。切换请求存于运行时，动画结束才统一退还旧实弹、扣除目标备弹、写入装填类型；取消不会提前扣弹。枪内只装一种类型，目标不足时只装现有数量。单枪、扩容／弹鼓、双持与左轮沿用已有对应空仓动作和音效。

普通换弹继续装当前弹种，不自动换稀有类型。切换弹种的成功装填只授予一次既有换弹经验。训练场虚拟补入部分由 `VirtualMagazineAmmo` 记录，不可通过切弹或缩小弹匣退入真实弹药袋。切换弹种本身需要且消耗实际持有的目标弹药。

旧存档加载时，把背包、仓库与角色档案内旧地面弹药记录并入袋；清除相应旧物品及快捷栏引用。旧地面弹药回收显示通知，不触及未生成奖励或未开启容器。已有枪内弹数保留；旧字段 `Reserve=90` 不计入袋。迁移与正常修改走现有 A/B 档案事务，不另建存档；持久化前仍会规范化旧入口产生的弹药记录，防止重新占格。

## 新增弹种

目录：`Content/ColdSteelData/ammo_types.json`。7.62x39mm 已按用户指定加入 LP、PS、AP（见 [三款弹种接入](../Combat/ammo-762-lp-ps-ap-20260921.md)）；其余兼容组仍为原有普通弹。燃烧等其他效果未启用。

在 `types` 数组增加一行，例如下面是**配置格式示意，未加入正式目录**：

```json
{
  "id": "ammo_762_special_example",
  "group": "ammo_762",
  "group_name": "7.62 mm",
  "name": "新弹种名称",
  "description": "确定后的实际效果说明",
  "order": 1,
  "enabled": true,
  "allow_infinite_reserve": false,
  "damage_multiplier": 1.0
}
```

- `id` 唯一且稳定，用于档案键；不要改已有类型的 ID。
- `group` 必须匹配枪械 `gunsmith.json` 中 `base.ammo_item_id`。A762、AKM 共用 `ammo_762`。兼容性不靠显示名称或口径数字猜测。
- `order` 决定稳定顺序，同值按 ID 排序；轮盘一次打开期间不因余额变化重新排序。
- `enabled` 控制是否开放；已保存但关闭的类型仍保留余额，可在袋页查看。
- `allow_infinite_reserve` 缺省 false；只有显式开启且开发无限备弹开关生效时才无限。现有普通弹显式 true，保留训练场行为。
- `damage_multiplier` 缺省1，为装填类型的伤害倍率；物理护甲穿透使用下方独立字段。燃烧等其他特殊机制仍需要独立实现，不能只改名称声称已获得效果。
- `physical_armor_penetration` 缺省0，范围0–1；0.10表示无视10%物理护甲。仅发射子弹时采样，与武器已有穿透相加并限制在100%以内，不增加魔法穿透或穿墙效果。
- `icon` 为 `Content/ColdSteelData` 内 PNG 相对路径，弹药袋和圆形轮盘共用；图片自动随目录内容打包。
- JSON 在角色子系统初始化时读取。编辑后重新进入游戏；不需要重编 C++、制作模型、修改轮盘或追加背包格子定义。
- 新类型自动出现在兼容轮盘、弹药袋、F6 开发发放目录；实际获得数量仍由既有奖励入口发放。

发放单独弹药调用 `GrantAmmo(Id, Count)`／现有 `AddItem`；与其他奖励在同一事务中结算时使用 `AddAmmoToState(Profile, Id, Count)` 后统一提交。数字扣除使用 `SpendAmmo`。每种类型使用 int64，存储边界为9007199254740991发；HUD 与袋页显示完整数字。旧图标、模型源文件保留，不再作为弹药背包／掉落展示入口。

## 源码入口

- `UI/ColdSteelAmmoRuntime.cpp`：目录、兼容性、余额、迁移与切换事务。
- `FPSGAMECharacterAmmo.cpp`：R 按住／松开手势、轮盘与动作请求。
- `UI/ColdSteelAmmoWheel.cpp`：动态等分环、方向选择、中心取消、边界缓冲。
- `UI/ColdSteelAmmoPouchWidget.cpp`：背包子页、兼容组与预选装填。
- `UI/ColdSteelProfileRuntime.cpp`、`ColdSteelDualPistolRuntime.cpp`、`Weapons/PistolDualWield*`：获得与单／双持换弹。
- `Weapons/GunsmithSystem.cpp`：弹匣缩容将真实溢出弹退回对应袋。
