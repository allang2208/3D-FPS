# 容器逐件搜索

场景搜寻容器和地牢战利品箱打开后，按物品格位置顺序逐件搜索。未识别的物品只显示中性遮盖格和问号；正在搜索的格子显示金色进度条，标题旁显示搜索数量。完成后才显示实际图标、名称、数量和物品样式，并开放原有右键、拖动等交互。分页不改变搜索顺序。

个人仓库、玩家储物箱、商店和生产设备不启用这套搜索过程。容器生成、空箱领取标记、物品持久化仍使用原来的逻辑，不因搜索或重新打开而重新生成物品。

## 时长

配置位于 `Content/ColdSteelData/container_search.json`，单位为秒，在当前世界首次搜索时读取。白色 common 0.6、绿色 uncommon 1.0、蓝色 rare 1.6、紫色 epic 2.3、金色 mythic 3.2、红色 legendary 4.5。装备遵循现有无稀有度规则，使用 equipment 1.2 秒；未知非装备稀有度按普通处理。调整配置后重新进入世界生效。

## 个人搜索与共享物品

- 每名玩家拥有独立的已识别实例集合和当前搜索进度，服务端计时。关闭暂停，再打开同一个容器继续；已识别物品无需重复搜索。
- 进度按玩家控制器、容器键和稳定物品 InstanceId 记录，在当前世界会话内有效。退出重进、断线重连或换地图后重新搜索；它不是共享任务进度，也不写入存档。
- 容器里的真实物品仍然共享。玩家各自收到对应的容器视图，未搜索项只下发几何占格信息，不下发真实名称、图标、稀有度和数量。
- 客户端只预测进度条，是否揭示由服务端回包决定。另一名玩家取走物品后，沿用共享容器修订号和失效通知更新视图；消失的当前搜索项会跳过。
- 未搜索项不能被取走、旋转、合并、拆分或被整理/批量转移间接改动；服务端在提交共享容器事务前比较真实物品的前后状态。单机在 CommitState 入口使用相同规则。
- 成功放入物品后，放入者立即识别自己放入的实例，其他玩家仍需搜索。背包满、过期修订或保存失败均不会提前授予识别状态。
- 离开交互范围、死亡、失去视线或容器失效会暂停服务端搜索；重新打开可继续。关闭面板发送专用关闭 RPC，不改变容器物品。

## 接入点

`UColdSteelContainerSearchSubsystem` 仅存在于 Game/PIE 世界；预览世界不创建。它管理个人进度、遮盖数据、时长、交互限制和低频计时。共享容器打开/事务回包携带搜索快照，只有物品揭示或内容变动才触发原有容器刷新，不逐帧发送网络消息。自动刷新成功不弹出“物品操作”通知。

新增场景搜索容器沿用 `AColdSteelSceneContainer` 的稳定 ContainerId 和 StorageKey 即可；新增物品使用已有 rarity 字段，不要用强化等级伪造稀有度。新的容器入口若不属于该 Actor 或地牢宝箱，需要显式加入 Resolve，并继续走 Begin / FillView / ValidateChange / Close 链路。

按用户规则，仅进行源码接入与必要 DLL 构建；未主动运行游戏、联机测试或自动化验收，实际交互由用户测试。
