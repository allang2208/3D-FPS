# 锻造材质与命中加成

本轮直接接入现有铸造台与实景打铁。用户未要求运行测试或截图，完成必要构建后由用户体验。

## 数值

- 每把武器固定消耗合金胚、木材，另选一种金属锭；同配方不同材质消耗数量相同，不混合金属。
- 铁 / 铜 / 银 / 金的保底伤害加成为 0% / 2% / 6% / 10%。
- 每轮 20 处光圈，每次有效命中增加 0.75 个百分点，最多增加 15%；失误或提前结束不扣材质保底。
- 最终倍率 = 1 + 材质保底 + 0.0075 × 有效命中数。两项相加，金锭满命中为 1.25。

## 面板与状态

沿用 UMG 管理抽屉、现有滚动正文和固定页脚。在配方下方增加单行金属下拉，选项包含保底加成；材料表只列最终实际消耗的三类材料。状态卡显示选中材质的保底与上限；基础参数预览计入选中材质保底，已投入工件预览读取该工件。

实景下方保留三列指标（光圈时间、有效命中、锻造伤害加成），增加一行材质保底与命中提升拆分。金锭开局 +10.00%，命中后 +10.75%、+11.50%……+25.00%；两位小数避免 0.75% 被舍入误读。主题、字体、36px 下拉、DPI、横排和焦点沿用现有冷钢控件；矮窗正文滚动，提示说明可正常换行。

材料/参数只在选择或库存事件脏标记更新时重算；实景刷新仅读已锁定工件字段和命中数，不解析配方。开始后锁定配方与材质；材料不足、等待工具、保存失败沿用系统原因。Construct/Destruct 委托生命周期和抽屉外点保护沿用当前宿主。

## 权威与存档

开始时由服务端解析材质 ID，并将配方、材质 ID/名称、保底数值、实际扣料和成品快照一起提交。F6 免材料模式仍选材质并锁定加成，但无扣料/返料。结束只写实例 `_forgeQuality`，伤害消费者共用一个读取函数，不修改目录基础伤害。

新增工件版本 2；旧工件/已领取旧武器保留原结算，避免升级时改变已支付交易。旧配方成本留作缺少支付记录的旧档回退；新工件返料只读实际支付快照。联机开始请求传材质 ID，由服务器选择表中数值，客户端不上传可信加成。命中、完成、领取继续沿既有工件事务。
