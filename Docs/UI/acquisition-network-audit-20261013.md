# 收获动态栏联机与连续获得检查 · 2026-10-13

用户授权检查主客机独立收获、连续拾取、购买、数量合并与重复／漏提示。本次使用隔离存档的后台 commandlet，不打开编辑器界面或游戏地图。

## 发现与修改

1. 原显示层仅合并年龄小于 1 秒的行，同一物品连续获得稍慢时会在屏幕上重复占行。改为合并仍可见的同类型／稀有度，保持数量准确、延长停留，过期后下一次从本次数量重新计数。
2. 原待显示队列到 64 种时删除最早一条，批量收获可能完全漏播。取消未显示记录的静默丢弃，仍按物品／稀有度聚合数量；队列是待处理事件，不是可丢弃的只读缓存。
3. 原满行时直接截掉末行；矮窗口最多一两行时会过快消失。满行后暂存后续收益，等待空位；可见同类仍能更新。缩小窗口时保留被遮住的行，空间不足或面板覆盖时不消费队列。
4. 原按 Definition 的总量增加筛选，等量换入另一稀有度时总数相同，会漏掉新稀有度。改为先比较实例数量／数据，再按类型和稀有度统计净增加，排序、装备位置变化、拆分合并与主仓库搬运保持静默。

## 联机路径与验证范围

- 监听主机从自己的成功提交产生提示；客机在自己的 PlayerState 回执／镜像接受后产生提示。服务器影子档案即使被误启用显示，也拒绝向本机提示队列发送收益。
- 复用已有 RPC 请求序号、库存版本和进行中事务保护，没有新增奖励 RPC、存档字段或第二套物品计数。
- 后台测试调用正式商店权威交易、物品插入及提交、服务器回执构造与压缩、客机分片接收入口、OnRep 镜像入口，以及正式 HUD 使用的显示时间线。覆盖回执先到、镜像先到、等待中的镜像、旧镜像、重复回执、失败购买、客机落盘失败后的补同步、连续堆叠、稀有度交换、弹药卸载、70 种待显示收益与窄窗满行。
- 拾取测试执行相同库存插入／确认提交路径，不测试场景中的碰撞和交互距离。测试在同一无界面进程中驱动网络接收入口，未建立两台机器的真实连接，未做动画截图或肉眼验收。
