# 木工工作台：进度评估与优化开发方案

日期：2026-10-12。阶段：方案，尚未实施。

后续进展：用户已授权开发并选择优先接弓臂；本方案保留为实施前依据，实际完成内容和构建边界见[实施记录](woodworking-overhaul-implementation-20261012.md)。

## 3. 推荐的整体体验

保留“固定台锯切直线、退料后转向”的玩法方向。当前项目产物定位为毛坯，图样继续采用台锯可达的分段直线轮廓。曲线精修、钻孔或完整雕刻属于后续不同工序，不通过恢复鼠标任意擦除来假装台锯能够完成。

完整流程：

`打开工作台 → 选项目与模式 → 查看用途/图样/加工要求 → 进入台面准备 → 对齐 → 启动 → 进料切割 → 废料分离 → 退料转向 → 完成 → 复盘或领取`

推荐模式：

- **练习**：不消耗、不产出；无硬性倒计时，显示用时；保留损伤和断连反馈，允许重置与有限撤销。即使失败也能查看原因。
- **限时挑战**：后续需要时开放；每个图样配置时间、容差和撤销次数，超时规则明确。现有 90 秒只作为旧版基线，不直接成为所有难度标准。
- **正式制作**：仅在真实配方与产物用途接通后开放。经济版第一期沿用“领取时一次扣料发物”的现有事务，模式切换不隐藏收费时点。

以上是本次推荐改动，尚未修改当前计时、评分或经济规则。

## 4. 面板重构

### 4.1 项目选择

宽屏采用左目录、中预览、右详细汇总，沿用现有工作台布局职责和冷钢主题。

| 区域 | 内容 | 行为 |
| --- | --- | --- |
| 固定标题 | 木工工作台、当前模式、退出 | 不随正文滚走 |
| 左项目目录 | 图样缩略图、名称、用途一句话、可用状态 | 当前只有两项，不增加空分类；保留选择和滚动位置 |
| 中央预览 | 等比毛坯/目标轮廓、木料与废料区别；有实际模型后显示真实工件 | 目标不拉伸，不用无来源的示意成品冒充交付 |
| 右详细汇总 | 用途、加工步骤、完成条件、预计难度；正式模式显示实际材料与产物 | 属性名/实值分列，正文独立滚动 |
| 固定底部 | 当前可执行状态、一个主按钮“进入练习准备”或“进入制作准备” | 禁用原因就近显示；不同时出现语义冲突的启动按钮 |

### 4.2 实景加工

- 中央保留真实 V4 台面、木板和刀口，HUD 不盖住主要进料路径。
- 顶部只放项目/模式、阶段和用时或剩余时间。
- 侧边紧凑工艺区显示清除进度、主体损伤与完成条件；完整度和损伤不作为两个重复主指标。
- 木板上直接显示目标线、废料区、当前切缝和关键连接；超出切割边界时就地提示风险。
- 底部固定主操作与急停，转向/撤销保留可见按钮和快捷键；复位、完整帮助、返回项目放次级区域。
- 进料时提示“沿刀口进退”，可转向时提示“可转向”；无效操作必须有具体原因，不能只是不动。

### 4.3 结果复盘

- 成功、失败均保留实际最终工件，提供目标轮廓叠加和损伤/残余废料定位。
- 明确写出完成状态、用时、清除率、主体完整、边缘贴合；总质量在结果页解释来源。
- 未通过时指出“还有哪里没切完 / 哪处切坏 / 哪个连接断开”，不只显示“未达标”。
- 练习主操作为“再做一次”，其次“换项目”；正式成功为“领取成品”，材料或容量变化时保持结果并说明重试条件。
- “质量”属于工艺评价，不添加装备稀有度标签或颜色分档。

### 4.4 响应布局与视觉规格

以下为拟定布局值，实施时按实际内容区域计算，不以屏幕名义分辨率直接缩放整张画布。

| 可用区域 | 选择界面 | 加工界面 |
| --- | --- | --- |
| 宽 ≥1440px | 左目录约 240px、中央自适应、右详情约 360px，间隔 12px | 主加工区居中，右侧紧凑状态区约 220px |
| 宽 1000–1439px | 左目录约 200px、右侧预览与详情上下排列 | 状态区改紧凑展开层，主动作固定 |
| 宽 <1000px | 项目选择与详情分视图，返回保留选项；固定底部主操作 | 减少常驻文字，次级按钮换行，主操作/急停不依赖横向滚动 |
| 高 <720px | 正文滚动，标题、返回和主操作不进入滚动区 | 帮助默认收起，缩减上下条高度，相机按剩余净区域重算 |

使用 `ColdSteelUIStyle` 的中性黑灰玻璃、银白选中态，Noto Sans SC 正文与 JetBrains Mono 数字；字号用 20/16/14/12px 档，标准操作高度 36px。同级按钮等高等间隔。图样缩略图保持比例；颜色只表达目标、废料、损伤、成功/失败，不增加装饰性彩色边框。

## 5. 小游戏操控与规则

1. **抓取与进料**：按下时记录木板局部抓取点，鼠标给目标位姿；每次执行有界连续切割。超出单次计算步长的位移不能悄悄丢失，也不能在松手后继续自动进料。受刀口约束的方向立即显示锁定提示。
2. **转向**：保留 Q/E 和按钮的可预测角度步进，退离真实锯片占用后才转向；扫掠判定依据剩余木料。先保留现有 5° 图样合同，精细角度作为后续可配置能力，不先破坏图样可达性。
3. **对齐辅助**：显示刀口中心线与实际锯缝宽度，区分目标边和应走刀的废料侧；辅助吸附只能辅助准备对齐，不自动完成切削或自动纠正已经发生的损伤。
4. **可见区域**：按木板包围范围、旋转空间和 UI 净区域规划初始视角；一键回到完整工作视角。拖动过程中不突然改变缩放和抓取映射。
5. **反馈时点**：实际去料才触发木屑、接触声和切口反馈；空拖动只有木板移动，电机空转与接触切割分别表现。
6. **废料分离**：判定仍由连通块提供；表现层接收本次剥离块，短暂脱离/落下后回收。无需给每个像素建刚体，也不能让动画残留木料参与第二次评分。
7. **评分与达标**：操作中以完成条件和缺陷定位为主；结果分项解释。保留主体、连接与外围完成度的意义，再依据图样设置合理容差，避免靠逐像素抠边才凑到 98%。
8. **节奏与学习**：先提供少量直线切割的入门图样，再进入弓臂/木芯；每份图样有建议切割段、推荐顺序及余量说明。提示不作为强制路线，合法替代切法同样计分。
9. **急停与中断**：急停立即停止实际切削和相应声音，挑战模式明确计时继续；失焦释放抓取。关闭/返回提示是否会丢失本次结果，不把退出写成已保存。

## 6. 实景表现

- **木板**：顶面木纹、切口端纹、粗糙度和厚度有清楚区分；复用当前有厚度网格，避免只改变颜色。
- **轮廓**：以清晰细粉笔线表达目标，实际缺口不被一整片亮色填充遮住；缺损位置可短暂高亮，复盘时可切换显示。
- **切口**：显示去料必须服从权威遮罩；可改边界网格组织与材质，不能让美化后轮廓与判定产生明显偏差。
- **设备配合**：锯片、板材接触位置、判定锯缝与显示比例来自同一设备数据；不以调长虚拟刀口改变整张木板实景尺寸。
- **木屑与废料**：把现有 CutFeedback 接到世界表现；粒子和分离块有数量/寿命上限，结束、撤销和退出均清理。
- **声音**：准备、空载电机、接触切削、急停/停机、废料落台与结算分层；只使用来源清楚的工程或授权素材。
- **相机**：固定可预测的加工视角加有限缩放，兼顾锯片、目标线与手动进料空间；不先加入镜头晃动或自动追镜干扰精确操作。

手臂动画、复杂全物理断裂、全套新工具和雕刻系统不作为这轮面板/台锯改造的前置依赖。V4 桌体先复用；具体遮挡问题确定后再局部修改。

## 7. 数据、状态与实现职责

继续使用 UUserWidget 宿主 + Slate 布局/输入 + 世界表现 Actor；不重写整个工程 UI，也不新建通用制造框架。

| 数据或行为 | 权威来源/职责 | 更新与保存 |
| --- | --- | --- |
| 项目、图样、难度、模式 | `woodworking.json` 与 `UWoodworkingSystem` | 加载一次；新增图样级规则和模式字段时保留旧配置解释 |
| 木料、损伤、连通、去料事件 | `FMask` | 实际动作修改；显示、判定和评分同源 |
| 姿态、设备状态、计时、完成 | `UWoodworkingSystem` | 输入命令提交；规则层不读取视口尺寸 |
| 选择/准备/加工/结果界面 | Widget + `WoodworkingEntryFlow` | 阶段、选择和状态事件定向刷新；倒计时单独低频刷新 |
| 图样预览 | 目标数据与有效资产 | 图样变化刷新，异步完成只替换画刷，不重建按钮 |
| 相机、网格、木屑、声音 | WorldView / 专属表现组件 | 从同一姿态和切削事件读取，不反写得分 |
| 正式材料、容量、产出、领取 | 现有 CraftingSystem 和档案事务 | 开始前可制作判断，领取时再次判断；一次提交，失败不扣料 |
| 关闭、返回、工作台失效 | Controller + 幂等 EndSession | 同步归还相机、输入锁，释放捕获/异步引用/效果 |

实现拆分只服务本次职责：把当前大文件中的项目页、加工 HUD、结果页分开；抓取输入和切削反馈从布局构建中分离。布局重排只在断点/DPI 变化时执行，保留选择、滚动和工件状态。静态选择信息不再每 50ms 重写。

保留当前单个异步网格作业及有界提交；先缓存不随切割变化的目标轮廓，必要时再做局部网格更新。计时、损伤、得分不因视觉异步完成而延后。未采样性能前不承诺帧率提升，也不靠解除网格预算解决画面问题。

关键状态：

- 无项目：空态解释配置不可用，主操作禁用；未选择时不显示假成品。
- 准备中/失败：保留项目选择，显示取消或重试；加载完毕之前不启动计时。
- 练习/正式模式：名字、主按钮、说明和实际业务调用一致；无配方项目只显示可用练习。
- 资源或容量变化：只影响正式报价/领取；未领取结果不因面板刷新丢失。
- 成功/失败：使用同一真实最终工件和评价快照；不继续改变已冻结分数。
- 退出/返回：按当前模式说明进度和结果处理，取消操作恢复原焦点。

## 8. 开发批次与交付顺序

| 批次 | 开发内容 | 可交付结果 | 依赖 |
| --- | --- | --- | --- |
| A：第一条完整体验 | 修抓取位移、剩余木料阻挡和相机净区域；完成新选择页、准备 HUD、结果页；先贯通一个简单图样 | 玩家能看懂项目并完成一次对齐、切割、复盘，主操作没有歧义 | 本方案 |
| B：实景反馈完成 | 世界木屑、缺口反馈、废料分离、声音层次；切口材质与比例统一 | 每次真实接触有可见/可听反馈；切掉、切坏、空转可区分 | A 的姿态/切削事件合同 |
| C：图样和难度 | 入门图样、弓臂、木芯的切割引导；练习无硬倒计时；独立挑战参数与结果解释 | 多个完整项目，共享同一套可学习操作，难度按图样配置 | A/B 的交互与表现 |
| D：正式生产闭环 | 明确一个实际产物用途和已有物品/配方入口；接材料、容量、领取、保存；工艺属性如需生效则贯通实例与使用端 | 至少一个正式部件能加工、领取并在目标系统使用 | 真实产物定义与经济决定 |

**先做到 A+B 的一个完整图样，再铺 C 的内容。** 首轮开发不以“继续增加图样、贴更多规则文字”替代交互和反馈重做。

D 的建议：第一版维持现有领取时一次事务，不默认改成预付、退款、工件存档。若用户需要离开后继续制作，再单独设计存档快照、配方变更及丢失工作台处理。品质影响范围只对实际接通的部件参数设计，不能凭评分虚构伤害加成。

## 9. 文件范围与完成标准

预计修改范围：

- `Source/FPSGAME/UI/ColdSteelWoodworkingWidget.*`、`WoodworkingEntryFlow.h`，按职责新增木工专属布局/结果/输入文件。
- `Source/FPSGAME/Building/WoodworkingSystem.*`、`WoodworkingMask.*`、`WoodworkingWorldView.*`、`WoodworkingStockGeometry.*`，需要时调整 `WoodworkingSawVisualComponent.*`。
- `Content/ColdSteelData/woodworking.json` 与木工专用材质/声音/反馈资源。
- 正式生产阶段才触及实际配方、物品定义及接收部件系统；不提前扩大存档和武器修改范围。
- 保留已修复的轮廓数组别名处理、相机恢复、会话隔离和原子领取路径；历史资产、源包与制作记录保留。

由用户后续体验判断的完成标准：

1. 进入面板就能辨认项目、用途、当前模式及下一步动作，预览不变形。
2. 抓取点稳定；快速/慢速拖动不会因输入事件上限丢失位移；停止拖动就停止进料。
3. 看得见的木料、锯缝与实际损伤对应；已切除的废料不形成不可见转向阻挡。
4. 加工区能看清锯片、目标线和进料方向；主操作、急停和退出不需要横向找按钮。
5. 切削、空转、受损与分离反馈有明确区别；撤销同时恢复木料/姿态并清除过期效果。
6. 结果能解释成败和缺陷位置；正式产物只在事务成功后生成一次。
7. 返回、关闭、重入后相机与角色输入正常；无残留锯声和已失效结果。

以上是开发目标和供用户体验的标准，不是本轮已执行的测试。本轮只完成资料分析与方案落盘；未修改游戏代码或资产，未构建、运行游戏、截图、测试或提交 Git。后续制作按授权批次后台开发、必要构建与实际资源保存，默认由用户测试。
