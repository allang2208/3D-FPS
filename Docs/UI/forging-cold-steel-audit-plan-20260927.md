# 打铁面板：材料颜色与冷钢 UI 审计优化计划

日期：2026-09-27。范围：铸造台锻造抽屉、成品预览、实景锻造提示栏及与装备栏的联动。

## 本轮交付边界

用户要求直接调整材料字体颜色，并审计面板、制定优化计划。本轮只实现材料逐项着色；下述其他改动是待实施计划。审计依据是当前源码和正式设计规范，没有启动游戏、截图或进行运行测试。源码能确认的问题与仍需用户体验确认的风险分别标注。

正式规范：[冷钢 UI 设计系统](ui-cold-steel-design-system.md) 第 2–5 节；主题实现：`Source/FPSGAME/UI/ColdSteelUIStyle.h/.cpp`。字体、色板以当前文件为准，不沿用旧版宋体／Consolas 规则。

## 已实现：材料逐项着色

### 后续授权：材料文字层级与分列（2026-09-27）

用户已同意改为“名称银白、数量与状态红绿”的方案。此次实施范围为材料区：三列共用网格，依次为材料名称、持有／需要、状态；名称 14px Noto Sans SC，数量 14px JetBrains Mono，数量和状态右对齐。表头 12px 次要色，来源说明 12px 第三级灰色；只给持有数量与“已满足／缺 N”使用共享 Success／Danger，需要数量及分隔符保持次要灰色。不增加彩色底、发光或额外模糊。

准备阶段读取背包＋主仓库；有已支付工件时改为“本轮已投入材料”，显示支付快照与灰白“已投入”，不再按扣款后的库存标红。旧工件的配方回退由系统统一提供，与废弃返料读取同源，50% 返料与保存事务不变。

布局使用名称弹性列与内容自适应的数量／状态列；长名称可换行，数量保持单行，材料区随既有正文滚动，页脚与输入合同保持原样。行控件按目录最大材料项数预建，支付记录需要更多行时仅在数据更新时补足，后续复用。刷新仍由库存脏标记、配方切换、开始／领取／废弃等原有入口触发，析构沿用现有解绑。没有新增贴图或导入步骤。

修改范围：`ColdSteelForgingWidget.h/.cpp`、`ForgingSystem.h/.cpp` 及本文。其他审计项仍作为后续计划，包括预览底板、时长摘要、页脚窄窗重排和图片缓存。以下整行染色说明保留为上一版记录，由本节的新方案替代；完成与构建状态以文末为准。

- 每种材料独立一行，显示“名称  持有 / 需要”。持有数量大于或等于需要数量时，整行使用共享 `Success` 绿色（#68D5AD）；不足时使用共享 `Danger` 红色（#FF8193）。各材料独立判断，不将整份配方统一染红。
- “材料 · 背包 + 主仓库”标题保持次要文字色。统计复用 `UColdSteelStatusModel::CountMaterial()`，与现有开工判断口径相同。
- 切换配方、材料变化、开始／领取／废弃后的现有刷新入口继续生效。材料行按配方目录的最大输入项数一次创建，刷新仅更新内容、颜色与显示状态；隐藏多余行。
- 沿用现有 14px 字号和 DPI 换算，不修改配方成本、扣料、品质、返料或存档。

实现位置：`ColdSteelForgingWidget.cpp:94`（行创建）、`:195`（数量与颜色），以及头文件末尾 `MaterialLines`。数量来源见 `ColdSteelWarehouseModel.cpp:117`。

## 审计结果与优先级

P1 为优先解决的显示准确性与已明确的风格偏差；P2 为布局、阅读和刷新方式优化。这些级别不代表已发生崩溃或性能故障。

## 当前应保留的合规部分

- 冷钢共享字体入口、20／16／14／12px 层级、字号的 `/Scale` 换算、主题按钮画刷已在使用。不要另建字体或色板。
- 主模糊强度 9、半径 21；主面板 10px 圆角、卡片 8px、按钮 6px、1px 细边；正文滚动条 6px。继续使用共享常量。
- 普通按钮保持 36px 高、同级横向均分、4px 间隔；按钮文字已关闭自动换行，内容槽横向填满并居中。
- 配方来自系统目录；有待处理工件时锁定切换并恢复对应配方。成品预览目前通过 `Configure(nullptr, MoldTexture)` 作为只读参考，实际评分由世界锤击接触负责。
- `OnChanged` 只标记材料脏状态，析构时解绑；材料行不随每次刷新重建。事务仍由 `UColdSteelForgingSystem` 负责，不由 UI 直接写存档。
- `ColdSteelForgingHUD.cpp` 已沿用抽屉展开／收回与输入门控，实景操作时收起抽屉；保持与冶炼、装备栏的现有接续。`ColdSteelInventoryTheme.cpp` 的两栏等宽停靠是已有业务布局，不在此次审计中擅自增加栏间空隙或改独立尺寸。

## 建议实施顺序

1. **信息与底板（P1）**：修正随机时长摘要；准备／待领取分别表达“所需”与“已投入”；预览恢复共享单色卡片并删除二次模糊。这一批不触碰动画、相机或制造公式。
2. **排版与阅读（P2）**：材料名称／数字分列，状态指标使用真实单元布局；待领取时突出成品、品质、命中次数、伤害工艺修正和实际返料。首屏按“配方与材料 → 状态 → 成品预览 → 操作说明”排列，说明放后，页脚常驻。
3. **适配与刷新（P2）**：调整内容高度和窄窗重排，统一预览 DPI；最后减少待机刷新及重复图片解码，保持同一数据与输入合同。

建议沿用三段呈现：准备时显示材料与开始按钮；锻打时使用现有实景简洁 HUD；结算时显示本轮结果、领取和废弃。保留冶炼入口及现有未领取工件规则，不加新的自动入箱流程或重复确认步骤。

## 后续用户测试关注点（本轮未执行）

- 同一配方中既有足够也有不足的材料时，持有数量及状态能分别出现绿色和红色，名称保持银白、需要数量保持灰色；恰好够用应为绿色。库存变化、三种配方切换后颜色与数量对应。
- 两项和五项材料、长名称、不同窗口宽度下，操作按钮保持单行文字且可达；正文可以滚动。
- 已支付的本轮材料与下一轮需求能区分；领取和废弃仍保留原有背包空间检查、50% 返料及保存行为。
- 纯色预览、实际时长摘要、单圈时间与本轮进度的区别，待上述计划实施后再由用户在游戏内确认。
