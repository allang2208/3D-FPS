# 弹药袋与弹种切换方案

日期：2026-09-21。修订3：用户已批准构建，并要求轮盘随兼容弹种数量自动等分。方案的弹药袋、动态轮盘和换弹结算已写入游戏源码；实现及后续配置见 [实施记录](ammo-pouch-implementation-20260921.md)。

下文保留设计依据；当前交付范围为源码、弹药目录、UI 和必要原生构建。未启动 PIE、未执行游戏测试，旧档迁移在用户下次进入游戏加载角色时执行。

## 1. 推荐方向

把弹药从空间背包物品改为角色档案中的数字资源。按“弹药兼容组 → 弹种”管理数量；同组武器共享备弹，每把武器独立保存已装填弹数与弹种。

推荐使用“装备页内的弹药袋子页 + 战斗长按 R 圆形轮盘”。装备页可增加一行当前弹药摘要，点击进入子页；不增加新的全局面板快捷键，不占装备槽或背包格。

已确定的用户需求：弹药不占背包、不做弹药物件模型、获得后直接入袋；后续支持多弹种；长按 R 选择；切换不同弹种完整播放空仓换弹动作。

本方案建议的默认值：无负重、无容量上限的玩法限制；有限数量正常消耗；不混装弹种；不自动改用其他弹种；旧弹退还；0.30 秒长按门槛。数值型存储仍使用整数和现有存档数值边界，不表示数学上的无限存储。

## 3. 玩家规则

### 获得与管理

- 奖励、敌人掉落结算、容器领取、商店购买、制作产出、开发面板发放等实际存在的弹药来源，统一调用发放入口；只在各来源原本的“获得成功”时入袋。
- 背包已满不会阻止弹药入袋。连续获得合并显示，例如“7.62 mm 普通弹 +30”。
- 新掉落规则不生成弹药盒、地面子弹或隐形拾取球。敌人弹药在掉落结算时发放；容器内弹药在原有领取动作时发放，不提前领取未打开的容器。
- 首期不加入弹药拖拽、拆堆、整理、手工丢弃或仓库转移，避免把原管理负担搬进新面板。若已有交易扣除，仍走数字扣除入口；不新增商店功能。
- 弹药袋属于当前角色，切地图保留，不跨角色合并。枪放进仓库、转移或丢弃时，已装填子弹仍跟随枪；备弹仍属于原角色。
- 取消的是弹药物件模型；弹匣、换弹动作、枪口效果与原有射击表现保留。飞行命中由现有弹道逻辑处理，不引入子弹物品网格。

### 分组与显示

- 数据以稳定的兼容组 ID 分组，首期沿用 ammo_762 等已确定的武器映射。界面显示“7.62 mm”仅为现有命名，不意味着任意同直径枪弹都互通。
- 后续如需要区分更具体的规格，新增兼容组，不依赖显示文字判断兼容。
- 普通弹先作为唯一正式弹种。预览中的穿甲弹、燃烧弹仅用于展示扩展状态，不代表已接入或已确定战斗倍率。
- 一把枪的弹匣只装一种弹种。普通换弹补充当前弹种；不够时装入剩余数量，用完后明确提示。
- 不在弹种用尽时自动换成稀有弹种。已有自动空仓换弹沿用当前类型，没备弹时提示“该弹种已用尽，长按 R 切换”。

## 4. R 键与换弹流程

| 输入／状态 | 行为 |
| --- | --- |
| 只有一个已开放兼容弹种 | 沿用当前按下 R 即换弹；不增加等待 |
| 存在多个已开放兼容弹种，R 按住不足 0.30 秒便松开 | 松开即发起普通换弹，不等待剩余门槛时间 |
| R 按住达到 0.30 秒 | 在屏幕中央打开圆形轮盘；虚拟鼠标指针从中心取消区开始，无待切换目标 |
| 保持按住 R 并移动鼠标 | 指针移出中心区后，按相对圆心的方向选中对应弹种扇区；不需要点击 |
| 松开 R | 指针在另一种有备弹的扇区时确认并开始空仓换弹；中心区、当前弹种或已用尽扇区仅关闭 |
| Esc／失焦／菜单打开 | 取消选择，不触发短按换弹，不把关闭输入穿透成攻击 |
| 不兼容弹种 | 不出现在该枪的快捷选择中 |
| 已开放但数量为 0 | 灰显并写“已用尽”；未开放的未来类型不显示 |
| 施法、换弹、装备等已有动作占用 | 遵循当前动作仲裁，不打开第二个可提交选择；不排队偷偷切弹 |

选择时不暂停世界、不改变时间流速，保持角色移动；退出 ADS、停止持续开火，暂时阻止射击和滚轮换枪。鼠标移动只驱动轮盘指针，冻结鼠标对镜头的旋转，防止选择弹种时视角甩动。关闭时清除本次选择手势残留的鼠标位移并恢复视角输入。确认后进入该枪已有的空仓换弹动作；恢复射击／ADS沿用当前动作恢复规则。滚轮不负责选择弹种。

代码应将“R 按键手势”与 `BeginReload(Reason, TargetAmmoType)` 分离。自动空仓换弹、施法结束后续换弹等内部调用直接发起普通请求，不经过长按计时。

### 切换结算

动作原因增加 ChangeAmmo。即使旧弹匣非空、甚至已满，仍可切换；不通过先把 Magazine 清零来骗过普通换弹条件。

1. 确认目标类型、武器实例、兼容性、数量、当前配件容量与动作可用性；建立一次待执行请求，暂不改余额。
2. 播放对应武器／握把／普通弹匣或弹鼓的完整空仓换弹。A762 继续使用已接入的空仓动画和 AKM 音效，不新增动画资产。
3. 对当前以 FinishReload 结算的枪械，在动作完成点用最新档案执行一个事务：旧枪内弹按原弹种退回袋；目标袋扣除本次可装数量；写入新的 Magazine、LoadedAmmoType；记录成功装填类型。
4. 成功后统一更新 HUD、弹药袋和武器详情。换弹技能经验沿用既有成功换弹规则，只结算一次。
5. 提交前中断不改变弹数与类型；提交后按新状态继续，重复回调不能重复加减。保存失败不发布新弹种或新余额。读档不恢复半截动画，读取最近成功提交的装填状态。

例：原弹匣普通弹 18 发，袋内普通弹 480、穿甲弹 96，容量 30。切换成功后：普通弹袋 498、穿甲弹袋 66、枪内穿甲弹 30。若穿甲弹仅剩 12 发，则只装 12 发；不混入普通弹补足。

左轮逐发装填／快速装弹器当前有分次提交与抽壳规则，需专门适配切换事务，不能直接复用会丢弃剩余实弹的普通快速装弹器逻辑。换弹种也遵循“旧实弹退袋”的新规则，但不因此改变普通左轮换弹既有丢弹约定。

双持袋底层共享；长按 R 选择增加主手／副手选择，默认主手，只切所选手且使用该手空仓动作，另一只手的已装填类型不变。两只手从同一袋扣弹时，以各自完成时的最新余额结算，不能同时预支同一批弹药。双持的实际按键提示与现有输入仲裁一起接入。

## 5. UI 结构与预览

### 推荐：弹药袋子页

入口：Tab 打开现有右侧“装备与背包”抽屉 → 装备 → 弹药袋。顶级状态／装备／技能／图鉴结构保留。装备首页只需“7.62 mm · 普通弹 480 | 弹药袋 >”紧凑摘要。

面板按以下顺序组织：

1. 固定标题、返回与子页签。
2. 固定说明“自动收纳 · 不占背包空间”；当前武器、当前装填弹种和枪内弹数。
3. 可滚动口径组。当前枪兼容组置顶并展开，其余按目录稳定顺序；组内普通弹在前，其他类型按目录顺序。组总数只含袋中备弹。
4. 每行弹种名称、当前标记、完整整数数量；有意义时显示兼容／效果简述。缺少战斗数据不编造百分比。
5. 固定说明“已装填子弹单独计算”与长按 R 提示。

背包面板中“选择”仅预选目标；固定按钮显示“返回并切换”。用户点击后关闭抽屉，再走同一空仓换弹请求；不能在菜单内瞬间改好弹种。如果离开菜单时枪械已变化，请求作废，不替另一把枪装填。

### 较紧凑的备选

在装备区与空间背包之间插入可折叠弹药区，显示当前枪口径下的弹种数量，点击“查看全部口径”进入完整袋页。优点是直接可见；代价是挤占背包高度。适合只放一行摘要，不建议始终展开大卡片列表。

### 战斗圆形轮盘（用户指定修订）

- 轮盘位于屏幕中央，由环形扇区组成；打开时收起准星。按实际已开放且兼容的弹种数量 N 等分，每个扇区角度为 360°/N；不限制为固定三项或六项，不补空白假弹种。新增配置后，下次加载目录即可自动重排。超过8项时扇区使用简短编号，完整名称和数量集中在悬停中心；超过24项隐藏小扇区编号，仍可按方向选择全部类型。
- 本次三弹种示例：上方普通弹、右下穿甲弹、左下燃烧弹。弹种顺序在一次打开期间固定；数量耗尽只灰显，避免鼠标移动中扇区突然换位置。
- 扇区仅名称、备弹数量和当前／待切换／已用尽状态。选中扇区提高灰色明度并显示银白弧边，不放子弹模型、3D预览或复杂战斗表格。
- 中心为取消区。初始中心文案“移动鼠标选择”；选中有效扇区时中心显示目标弹种与“松开 R 换弹”；移回中心时显示“松开 R 取消”。悬停已用尽扇区时显示“该弹种已用尽”，松开不换弹。
- 鼠标相对位移驱动可见的虚拟指针，打开时重置到圆心，按方向选扇区；指针限制在外圆内。进入中心取消区即清除选择，不要求精确点中弹种文字。
- 初拟轮盘直径480px、中心取消区直径144px；扇区边界设约4°切换缓冲，避免停在分隔线上时来回闪动。此为可调交互参数，不是本轮已实测手感。
- 固定提示“移动鼠标选择 · 松开 R 换弹”；辅助提示“移回中心取消 · Esc 取消”。全程不需要鼠标点击确认，不显示滚轮选择说明。
- 选择尚未确认时，右下 HUD 仍显示枪内当前弹种；动作中显示“普通弹 → 穿甲弹 · 换弹中”，完成才更新数值。
- 平时 HUD 保持现有武器栏布局，口径旁增加弹种。备弹显示当前弹种数量，不把穿甲、普通等相加成一个误导数值。

### 主题、尺寸与响应式

复用 `ColdSteelUIStyle` 与正式规范 2.18：主底 #1A1A1AF8、主文字 #E8E8E8、次文字 #B7B7B7、银白选中强调、1px细边；主抽屉 10px 圆角，模糊强度9／半径21。禁止重新建立偏蓝主题或做成弹药箱陈列界面。

中文／普通文本 Noto Sans SC，纯数字 JetBrains Mono；标题20、分组16、正文14、辅助12px，重点余量可用24px。概念图用于表达布局，不作为逐像素字体测量依据。

- 1920×1080预览：右抽屉48%视口宽，服从现有720–1040px约束及12px边距；标题、页签和主要操作固定，列表独立滚动。
- 可用内容宽低于640px：当前枪摘要换为两行；口径组内名称／数量仍对齐，效果说明另起一行。
- 高度低于720px：缩短顶部留白；先让列表滚动，保留页签和确认区，不整体缩放文字。
- 战斗轮盘在1080p下以约480px直径为基准；小视口按短边限制外径，保留中心取消区、可读字号及下方操作提示，不拉伸成椭圆。开启期间隐藏准星，轮盘及提示避让底部快捷栏和右下武器栏。
- 无弹药时显示“尚未获得弹药，获得后会自动收纳”，保留当前武器的0余量信息；没有装备枪械时仍可浏览袋，但不能执行装填选择。

预览中的背景为概念场景，不代表关卡变更；穿甲弹、燃烧弹为未来类型示意。独立页和内嵌区预览保留；战斗交互已按用户反馈改为圆形轮盘，旧横排图不再代表当前方案。

## 6. 数据与接入方式

建议新增薄的弹药领域层（命名为方案，实施时服从目录约定）：

| 数据／入口 | 含义 |
| --- | --- |
| `FAmmoDefinition` | 稳定 AmmoTypeId、CompatibilityGroupId、显示名、默认顺序、战斗参数引用；不保存物件网格路径 |
| `FColdSteelProfile.AmmoPouch` | `TMap<FName,int64>`，仅备弹；权威来源为现有角色档案 |
| `AmmoPouchVersion` | 一次性迁移标记，不能借用现有 Version=2 的固定写入行为 |
| 武器 `LoadedAmmoType` | 枪内当前类型，Magazine>0时决定每一发效果 |
| 武器 `PreferredAmmoType` | 下次补弹类型；切换成功时更新；装填中的待选目标不直接覆盖它 |
| `GrantAmmo / TrySpendAmmo` | 奖励与交易的统一入袋／扣袋入口；与原来源同一次事务 |
| `QueryCompatibleAmmo` | 弹药袋、R选择、HUD、实际换弹共用的兼容性与数量查询 |
| `CommitReload / CommitAmmoSwitch` | 袋扣除、旧弹返还、枪内写入、训练经验原子提交 |

初期普通弹沿用旧ID也可，关键是显式定义 AmmoTypeId → CompatibilityGroupId，旧映射以表驱动。新增特殊弹种应为新类型ID，不根据“穿甲”字样或UI颜色决定伤害。

每次开火按枪内 LoadedAmmoType 获取参数，并随该次射击保存效果快照。已发射子弹不会因玩家随后切枪或切弹种而改变；枪械强化、配件、角色技能继续沿用原有聚合顺序，后续弹种倍率另行平衡，本轮不改变 A762 基础数值。

UI 通过现有 OnChanged 与武器状态更新获取数据，构建时订阅、销毁时解绑；不每帧扫描背包，也不在控件里直接扣弹／保存。余额变动保留所选口径与滚动位置。开关菜单沿用当前控制器焦点和输入模式入口。

需要接入的完整路径：单枪、双持、左轮、普通／自动／空仓换弹、弹鼓／扩容弹匣、配件缩容退弹、武器详情、HUD、枪匠摘要、初始物资、所有实际奖励入口、开发发放、背包／仓库迁移及旧地面弹药。

开发场景的“无限备弹”继续是场景／开发选项，不向正式袋注入数值。普通弹的当前无限规则保留；未来稀有弹种只在已开放的训练配置中允许无限，不能因长按 R 免费解锁未获得的特殊弹种。训练中虚拟补入的枪内弹必须与真实持有数量区分，切换弹种时不得把虚拟训练弹退入正式袋；有限模式按完整旧实弹数返还。

## 7. 旧存档迁移建议

采用一次性、保留数量的转换：

1. 用现有 A/B 流程读取最新有效档案；仅当 AmmoPouchVersion 未迁移时执行。
2. 当前角色背包和私人仓库的已识别弹药堆叠，按对应普通弹类型求和并入袋；仓库此后不再保存弹药格子。
3. 对已保存在该角色档案内的旧地面弹药，建议一次性回收入袋并清除旧物件记录，明确显示“旧版地面弹药已回收”的数量。该策略会改变这些已存在散落物的取得时机，属于本方案待用户确认的迁移政策；不扫描或领取尚未生成的关卡奖励／未开启容器。
4. 每把已有枪保留 Magazine，并按它自己的枪械目录补入普通 LoadedAmmoType。仓库和地面枪同样处理，不把它们枪内弹再加进袋。
5. 旧武器结构里的 Reserve 默认为90，不是当前真正备弹来源；绝不能将所有武器的 Reserve 累加，否则会凭空生成弹药。
6. 移除弹药对应的旧快捷栏绑定、空间物品记录；保留其他物品原格位，不借机重排整个背包。
7. 袋、新武器字段、移除记录和迁移版本一起提交。提交成功才发布及移除旧拾取显示；失败保留原档案，重试时不重复入账。

新增奖励从第一天就路由数字入口，不能只迁移现有物品而让旧 AddItem 重新造出弹药堆叠。历史图片／模型文件可暂留归档来源，本轮及首期接入不因停止引用就批量删除资产。
