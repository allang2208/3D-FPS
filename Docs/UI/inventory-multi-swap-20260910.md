# 背包一对多交换（2026-09-10）

## 行为

背包内拖动大物品覆盖多个实例时，把所有被覆盖实例一起回填。优先使用拖动物品原来腾出的矩形，优先保持相对于落点的排列；单件交换仍优先原锚点。如果原区域无法完整安置，尝试周围空位。不旋转物品，不挪动未覆盖的邻居，不合并被回填的实例。原有单目标同类堆叠逻辑保留。

先按面积从大到小、候选数量、原位置和实例 ID 排序，再进行确定性回溯。候选按原区域以外占格数、距首选位置的曼哈顿距离、格子索引排序。先搜索完全回到原区域的方案，再搜索全背包候选。每轮最多访问 20,000 个候选，避免复杂摆放阻塞拖动；达到限制会明确提示调整落点，不声称无解。

只有全部实例安置成功才返回有效 proposal。提交继续使用 StatusModel 的 Generation 和保存事务；空间不足或保存失败不发布部分布局。装备槽仍只能交换单个兼容物品，不能接收多件物品。

## UI

现有 UMG 自绘背包负责鼠标落点和回填高亮，StatusModel 是数据权威。鼠标预览直接使用同一 Move proposal，并显示被交换件数及回填位置；松开时重新校验。保留现有焦点、拖动取消、面板清理和模型事件绑定。键盘移动也使用更新后的规则。
