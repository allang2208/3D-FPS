# 药水工作台魔法炼药开发方案

日期：2026-10-15。下文保留最初设计方案；用户随后授权开发，实际实施记录见文末。

建议沿用铁匠、木工的两阶段流程：管理面板选择配方和备料，实景工作台完成炼制，再返回同一管理面板领取。本次先做坩埚魔法药水；离心机快速注射剂保留独立入口。

文中的时长、热度、评分、成本和产量是本项目的建议初值，不是《天国：拯救 2》的参数，也不是已实现或经过体验确认的规则。

## 1 范围与已有基础

用户已确定：两个小游戏分工；先开发坩埚分支；参考现有工作台布局和流程；以已有书本模型表现配方手册，借鉴《天国：拯救 2》的实景炼金体验。

这里的“魔法药水分支”指坩埚炼制方式，可以制作生命与魔力药水，不是仅制作恢复魔法值的蓝药。

| 范围 | 当前工程事实 | 开发接续 |
| --- | --- | --- |
| 建筑 | potion_workbench 已在 B → 其他登记，目前是普通静态 prefab | 保留稳定 ID、摆放和建筑存档，增加 E 交互 |
| 模型 | 有坩埚、药液、加热环、研钵、灌装组、闭合配方册与离心机 | 导出活动部件，补打开的书页和器具操作锚点 |
| 游戏网格 | 建筑导出已将整台合并为 Static Mesh | 不能直接让其中的书翻页；需接固定桌体与活动器具 |
| 管理 UI | 木工已对齐铁匠的配方下拉、材料表、状态、预览/参数、固定页脚，与背包等宽贴邻 | 沿用这套结构与 ColdSteelUIStyle |
| 制作事务 | 有唯一工件、已付材料、结果保存、待领取与库存原子提交 | 新建独立炼药批次，复用事务，不套用锻造评分 |
| 内容 | 六种 alchemy_* 原料，以及生命/魔力各四档药水已存在 | 使用真实定义和瓶型，保留喝药效果、叠放与快捷栏 |
| 联机 | 已有 Workstation 交易和服务端小游戏输入 | 增加显式 alchemy 分支，不能借用默认木工/普通台分支 |

主要依据：ColdSteelWoodworkingController.cpp、WoodworkingSystem.h、WoodworkingJob.cpp、ForgingSystem.h、CraftingSystem.h/.cpp、ColdSteelStationNetwork.h/.cpp、ColdSteelInventoryTypes.h、items.json，以及药水台 ModelV1/IntegrationV1 制作记录。路径均位于当前 D:/FPS3D/FPSGAME 工程。

木工旧文档曾记录退出即失败，当前源码已有 Suspend、Resume 和 SaveCheckpoint；炼药挂起参考当前实现。

## 2 从天国拯救 2 借鉴什么

公开实操说明展示了配方书、基液、按份投料、研钵处理、坩埚加热、沙漏计时和装瓶/蒸馏。这套结构的价值是让手册上的步骤对应桌上的工具和实际操作。[GameSpot 炼金实操说明](https://www.gamespot.com/gallery/kingdom-come-deliverance-2-alchemy-potions-guide/2900-6200/)

本项目保留“读手册 → 处理原料 → 手动控制反应 → 装瓶”的结构，并按现有设备改造：

| 参考机制 | 本项目采用方式 |
| --- | --- |
| 配方书 | 实体配方册打开、翻页，并提供清晰放大的阅读层 |
| 研磨、剂量与顺序 | 液体倾倒、结晶研磨、分阶段加入；错误有具体后果 |
| 坩埚升降、风箱 | 坩埚已嵌入桌体，改为符文加热环档位控制，不让锅穿台面运动 |
| 沙漏 | 新增小沙漏作为世界内提示，辅助 HUD 显示同一计时 |
| 火候观察 | 温度计、气泡、液面、蒸汽与声音共同表达，关键状态同时有文字 |
| 灌装或蒸馏 | 首版用现有灌装器具；真正蒸馏需要新设备，不把现有量杯当成蒸馏器 |

不复制原游戏的书页、美术、配方文本或药物效果。下文温区与热度均为虚构游戏规则。

## 3 玩家流程

E 使用工作台 → 魔法药水管理页 → 选择配方/翻阅手册 → 资源准备 → 原子备料并保存批次 → 实景炼制 → 灌装并保存结果 → 返回管理面板领取。

管理阶段可以不限时阅读。材料不足仍可查看手册和成品；只有“备料并开炼”禁用。模型、手势与书页资源准备期间不扣料，资源就绪后才创建已付批次。

实景阶段收起管理抽屉与背包，镜头移到 L 形内侧。中央保留清楚的坩埚区域，书、研钵、原料盘、火力调节与灌装器均可操作。可在整体视角和书页阅读视角间切换，不要求玩家在小字和强透视下阅读。

托盘只摆本炉已备好的原料及份数，后排装饰瓶不提供无限材料。允许提前研磨、在熬煮期间处理下一种原料；配方只约束必要的前置关系，不把所有操作锁成自动播放步骤。

装瓶后回到同一管理面板，显示具体失误、工艺评分、实际产量与效果。背包放不下时保留整批待领结果，新批次不能覆盖它。

## 4 手册与界面

### 管理面板

遵守 Docs/UI/ui-cold-steel-design-system.md 和现有木工/铁匠布局。

| 顺序 | 内容 | 布局与状态 |
| --- | --- | --- |
| 固定标题栏 | 药水工作台、关闭 | 关闭保留已付批次 |
| 分支页签 | 魔法药水 / 快速注射剂 | 等宽横排；注射剂首版禁用，说明尚未开放 |
| 配方与材料卡 | 居中下拉、持有/需要、翻阅手册 | 已备料后显示实际备料/已处理，锁定配方 |
| 本炉状态卡 | 准备、炼制、暂存、失败、待领取 | 显示真实阶段及原因 |
| 成品预览与参数 | 图片、效果、产量 | 采用现有等宽左右结构；窄窗改上下 |
| 操作说明 | 当前阶段说明 | 常展开，主体滚动 |
| 固定页脚 | 状态提示、主要与次要操作 | 备料并开炼 / 继续炼制 / 领取成品；另有废弃本炉 |

整体与背包等宽贴邻。使用共享黑灰玻璃和银白文字，金色只用于书签或工艺强调。文字默认横排单行，材料名与数量分列。标题和页脚固定；不靠缩小字体应付矮窗，具体断点复用现有工作台计算。

### 配方手册

左页显示成品、原料图标/份数、效果与预计用时；右页以自然语言配器具小图描述步骤。配方数据是唯一真源，书页、下拉框、材料表和判定逻辑共同读取。

- 提供索引、上一页/下一页、书签、材料页与操作页。
- 可放大阅读；退出阅读返回原操作视角。
- 当前步骤可以提示，已完成步骤淡化；提示可收起，但不自动代玩家投料。
- 记录本炉可解释的失误，如“第二段熬煮超时 2 秒”。
- 准备时阅读不限时；已经开启的火候在翻书时继续推进，阅读层保留小型热度提示。

桌上手册是固定工具，不新增一本必须被消耗的库存书。首版已交付配方直接收录；配方掉落/学习、技能树、随机发现和自动炼制后续再扩展。

## 5 首版小游戏规则

建议普通配方每炉约 45–90 秒，准备和阅读不计入强制倒计时。主要挑战来自步骤组合，不为每一步叠加反应点击题。

| 动作 | 玩家操作 | 可见反馈 | 判定 |
| --- | --- | --- | --- |
| 基液 | 从托盘选瓶并倒入坩埚 | 液面升高、份数变化 | 记录投入量 |
| 研磨 | 将结晶放入研钵并持续研磨 | 颗粒变细、声音改变 | 达到配方要求程度，液体不研磨 |
| 投料 | 选择原料并加入 | 局部变色、扩散与气泡 | 剂量和前置步骤 |
| 熬煮 | 调符文环为关/低/中/高 | 火环、温度计、沸腾声 | 目标温区内累计有效时间，过热/不足有连续容差 |
| 搅拌 | 按住工具沿锅沿画圈 | 勺子、液体旋向改变 | 方向、有效圈数、速度，不接受一帧甩鼠标刷圈 |
| 冷却 | 关火并观察稳定 | 蒸汽减弱、热度下降 | 达到下一步所需温区 |
| 灌装 | 选灌装组/瓶架 | 倒液、装瓶、塞盖 | 结算本炉，不另加装瓶反应游戏 |

左键操作器具，右键放回；滚轮仅在悬停相应控制器时调火或翻页。研磨、搅拌提供按住方向键的等效操作，使用相同判定，减少长期画圈的负担。

Escape 优先关闭阅读层；返回管理界面时执行“收火暂存”。失败原因要能解释，不引入额外随机失败。纯颜色反馈同时配文字和声音。

### 一炉魔力药水示例

使用现有高纯调配基液和蓝髓菌结晶，示例成本各 1 件：

1. 阅读配方，将基液倒入坩埚。
2. 研磨蓝髓菌结晶至细碎。
3. 调至中火，达到手册标出的微沸区间。
4. 加入结晶粉，顺时针搅拌三圈。
5. 保持微沸两轮沙漏，随后关火冷却。
6. 药液稳定后灌装，返回管理面板领取。

起始调参可用：一轮沙漏 8 秒、微沸热度 55–70/100、三圈搅拌。这些值统一写在配方数据中，书页和服务端共用。首版一份原料对应一个完整库存单位，不引入难以退款的 0.1 瓶计量。

## 6 原料、成品与质量

| 当前原料 ID | 名称 | 建议用途 |
| --- | --- | --- |
| alchemy_pure_base_fluid | 高纯调配基液 | 通用基底 |
| alchemy_redvein_extract | 赤脉根萃取物 | 生命药水活性原料 |
| alchemy_bluemarrow_crystals | 蓝髓菌结晶 | 魔力药水与研磨教学 |
| alchemy_active_catalyst | 活性催化晶 | 高浓度配方的后期步骤 |
| alchemy_compound_stabilizer | 复合稳定剂 | 保留现有缓释用途，供后续注射剂/相应配方 |
| alchemy_silverleaf_essence | 银叶花精华 | 后续清明类药水，不强塞进普通蓝药 |

先打通 hp_potion（治疗药水）和 mp_potion（魔力药水）；之后补齐各自 medium、high、special，共八种既有成品。每种仍使用 items.json 的真实效果、瓶型与叠放限制。普通治疗恢复 30 + 最大生命 15%，普通魔力恢复 25 + 最大魔法 15%；其余档位直接引用现有定义，不另外复制公式。

建议首版工艺影响成败和产量，品阶由配方决定。普通配方不能因高分跳成特级，也不按评分改写现有 useEffect。

评分起点：步骤/剂量 35%、温控 35%、原料处理 15%、搅拌 15%；不需要某项的配方重新分配权重。关键材料未投或不可逆焦化直接判失败；其他失误按实际偏差扣分。

- 60–89 分：基础产量。
- 90 分及以上：配方允许时额外 1 瓶。
- 低于 60 分：失败，无成品，不另掷随机数。

普通配方可先以基础 2 瓶、优秀 3 瓶配置。高级/特级配方独立设置成本和奖励上限，不全局强制翻倍。现有原料分为稀有/史诗，成本还需结合获取量调整，避免用稀缺原料只换很少基础补给。

## 7 备料与保存合同

材料范围沿当前 CountMaterial：背包、现有物品夹层、个人主仓库；不取队友库存、任意世界箱子或仓库子容器。材料显示、可开始判断和支付使用同一范围。

开始时一次性将原料从库存移入本炉备料并保存实际条目和数量。开封、研磨或投料时标记该完整单位已处理。独立 JobId 贯穿全程。

| 事件 | 处理 |
| --- | --- |
| 收火暂存/普通关闭 | 保存温度、有效计时、步骤、失误及已处理原料；火力关闭 |
| 继续炼制 | 恢复原批次，不再扣料；保留温度与误差，不免费重置 |
| 暂存期间 | 不推进生产，不继续烧焦；恢复后由玩家继续加热 |
| 未完成时废弃本炉 | 已开封/研磨/投入的材料消耗，只退仍未开封的备料 |
| 完成后作废 | 成功或失败均可作废，按实际支付记录每种材料汇总后退回一半，逐项向下取整；与领取成品互斥（2026-10-15 用户追加要求） |
| 退款或成品放不下 | 保留整个待处理批次，不先清空 |
| 领取成功 | 入包与清空批次同一次 CommitState，不重新按当前配方发奖 |
| 死亡/断线/换图/拆台 | 停止操作、保存并释放台子占用；个人批次可在另一张有效药水台恢复 |
| 旧档缺少炼药字段 | 默认无批次，不向旧档发放或扣除材料 |

消耗、结算、领取使用持久化事务。连续温度等过程数据定期存检查点，阶段切换和挂起时保存，不每帧写档。保存失败保留当前批次并提示，不退回可再次支付的空状态。

建议 FColdSteelAlchemyJob 包含：Version、JobId、RecipeId/RecipeVersion、配方规则快照、实际备料、已处理量、过程检查点、累计失误、结果物品列表和完成状态。保存结果时固定实际成品快照，领取不受后续配方变更影响。

## 8 资产与程序实现

### 配方业务

新增 UColdSteelAlchemySystem，负责手册目录、备料、热度推进、操作判定、评分与领取。UI 只显示状态和提交意图。

独立 alchemy-recipes.json 记录稳定 ID/版本、输入、成品、书页、步骤与前置关系、处理程度、热度/时长、搅拌参数、失败条件、评分和产量。不上架到普通即时制作目录，避免绕过小游戏；复用现有物品统计、创建和放置事务。

### 模型与表现

保留 potion_workbench 的稳定身份和现有占格，参考木工锯片的组件路径增加 PotionWorkbenchVisualComponent：

- 固定桌体保留全台碰撞与摆放包围盒，防止旧建筑漂移。
- 独立导出配方册封皮/页片、研杵、搅拌勺、操作瓶和药液面。
- 完整静态网格继续用于预览；运行时固定体排除已拆出的重复几何。
- 补书本、研钵、控火、灌装和手部接触锚点；新增小沙漏和可操作控火件。
- 书页由同一配方生成，只在换配方/页码时重绘。
- 沿当前 V7 裸手基准制作取用、倾倒、研磨、搅拌、翻页和封瓶动作。
- 药液颜色、液位、旋涡、符文亮度由状态驱动；少量蒸汽采用有界可回收表现，不让粒子决定配方成败。

当前闭合书、烘焙药液和整台静态网格只是制作基础，以上交互资产仍需实际制作。

### 联机与占用

扩展现有 Workstation 交易和服务端输入链。StationInputJobId、StationReach 等需要显式 alchemy 分支，不能落到默认木工/普通台。

输入绑定实际台子/锚格、玩家、JobId、序号及库存修订。客户端提交操作，服务端计算剂量、计时、质量和产物；不接收客户端直接上报的可信分数。

建议一口坩埚同时一名操作者：浏览不占用，开炼/继续时占用，挂起、离开和断线时释放。占用是临时世界状态，材料与批次归玩家。未来离心机可作为同台的第二操作位。

操作者同步完整批次，旁观者只同步阶段、火力、药液和动作。沿当前 ProfileTransfer/ProfileMerge 与重生/换图清理链接入；UI 关闭不删除服务器批次。

### 生命周期与性能

目录加载后缓存，不在 Tick 解析 JSON。UI 用业务事件刷新，连续仪表仅在面板打开时更新。只推进正在炼制的会话，闲置台不各挂高频计时器。

管理、实景、阅读三种状态明确持有输入和相机。进入收起武器，关闭/死亡/台子失效沿 WorkstationViewRestore 恢复，阻止关闭键穿透攻击。释放临时器具、委托和计时器，已付批次留在业务层。
