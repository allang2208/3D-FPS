# 主场景性能修复实施规划

用户已授权完成分析报告列出的修复与优化。沿用交互开发面板的性能页、现有行布局、冷钢字体/玻璃样式、冻结显示/后台采集/导出入口；不新增玩法、存档或画质档位。

- 数据：网格补充强制 LOD 原值、目标索引与 MinLOD，配置和实际渲染区分；导出记录性能页状态和 GPU/Slate 可观测范围。
- 面板：每份快照单遍聚合事件；相同文本不反复触发布局；仍保留空样本、延迟结果、未观测与历史窗口说明，窄窗口继续自动换行与滚动。
- 图标：原 GameInstance 子系统拥有异步加载句柄和分阶段准备状态；退出释放，重试重置，缓存按配方区分；UObject 操作留在主线程。就绪通知带配方键，库存只更新匹配项，原库存变更仍完整刷新。
- 资产：修正铺装 LOD 编码，兼容网格 Nanite、穹顶 LOD、空间分组；不改弹道和碰撞形状。弹匣连续性保留原几何和法线接缝效果，解决材质与骨骼编译路径的 UV 限制。
- Slate/渲染：使用可用的引擎公开事件及现有统计，不修改引擎二进制；缺失的 GPU pass 或等待细节仍明确标为未观测，不编造耗时。
- 范围：`UI/FPSPerformance*`、`DevelopmentPerformance*`、图标相关 UI 和加载路径，`SourceAssets/MainPlaza20260922` 与专用 `SourceAssets/MainScenePerformance20260923` 资产接入脚本。共享文件逐段修改，保留其他开发内容。
- 接入：现有 MCP 桥批次互斥；必要 Editor 构建。用户未要求运行验收，不启动 PIE、不截图、不跑回归，实际效果交由用户测试。
