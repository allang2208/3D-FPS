## 用户以后如何调整产出

正式入口：`Content/ColdSteelData/incinerator-recipes.json`，schema 在相邻的 `incinerator-recipes.schema.json`。

当前正式配置：version=1，allowUnconfiguredDestruction=true，recipes=[]。这意味着允许明确确认后继续原有无产出销毁用途，不代表已计算出某种资源收益。将开关设为 false 可禁止未配置物品的销毁。

每条 recipes 记录填写：

- input：精确物品定义 ID；同一 ID 仅一条规则。
- inputCount：每份配方需要的输入数量（正整数）。同定义投入数量跨堆合计，必须整除；余量需要先拆分取回。
- outputs：item/count 数组，表示每份配方对应的物品定义 ID 与正整数数量；空数组表示明确配置为零产出。

收益按投入物品的 Definition 和 Count 计算。同种产物自动合并；武器改装、附魔、强化和枪内弹药随本体销毁，不额外推算收益。弹药袋投入按该弹种定义 ID 匹配。

预览不发放奖励。最终提交重新读取配置、检查版本/实例完整内容、模拟产物容量与完整档案校验；全部通过后扣除与发放共用一次 CommitState。普通产物进背包，弹药产物进弹药袋；空间不足或保存失败都不销毁投入物。确认令牌在提交前即消费，重复点击不会多次生效。

编辑 JSON 后重新打开面板即可刷新；确认时若规则文件已变化，旧确认被拒绝并要求重新查看。坏配置或不存在的产物 ID 阻止提交并保留投入物。不要把隔离测试配方写入正式表。
