# 坩埚玩法与操作界面 V5

本次目标：让坩埚成为观察与判断的操作对象，手册提供配方知识；初级药水只保留入门操作。后台修改与构建，按用户要求进行源码/数据排查，不启动游戏或验收渲染。

## 玩法

- 新配方开炉时自动加入实际备料中的基液，仍在同一扣料事务里记为已投入；无免费材料。旧批次按保存的旧配方继续，不改变已经支付的材料或工序。
- 初级治疗/魔力药水：投入主料，低火温热并搅匀两圈，温热装瓶。无需研磨、翻沙漏、长熬煮或额外冷却。两种方向均可，目标 12–20 秒（设计估算，未实测）。
- 中级再加入短时熬煮，高级/特级才使用研磨、催化、方向变化和多段温区。保持原材料成本与产出，缩短重复等待。
- 新配方的沙漏是独立十秒计时器，可随时翻转；火候达到配方条件时自然累计有效熬煮，不靠点击沙漏触发。
- 现场不显示下一步骤、步骤进度或即时工艺分。配方的顺序、数量、温区、圈数只在实体书内；火候、颜色、清澈度和器具动作提供现场反馈。允许提前收火装瓶，结果按实际操作结算；过热时只按物理温度限制装瓶。
- 领取和完成后作废退半仍为服务器权威互斥事务；旧存档快照与新版配方并存。

## 界面

UMG 继续拥有管理和操作输入；Subsystem 拥有过程、材料与结算。管理面板沿用现有布局；实体书保留 ManualV4 无背景板、纸面内容、拖动翻页与书签。

实景改为左侧材料、右侧火候/工具，中央留给坩埚；底部只有手册、装瓶、返回三项。两侧正文可以滚动，短标签和按钮单行。窄窗缩小面板至设计最小宽度并使用滚动，避免把长中文挤成逐字竖排。材料剩余数量提供操作事实，不列未来工序；没有研磨内容的初级配方不占用研磨区域。

UI 每 0.1 秒读现有状态，库存/配方变化更新材料缓存；不逐帧创建物品或解析 JSON。关闭和阅读层清理持续输入与捕获，阅读隐藏所有操作浮层，退出恢复现有视角和焦点。

## 水体

直接复用铁匠台 `SM_CoolingWater` 和 `RealismV5/M_QuenchWater`：已有细分圆面、SingleLayerWater 光学、Clearwater 法线、接触涟漪。只创建本台 MID，按锅内壁截面缩放，液位随投料平滑变化，温度/搅拌驱动既有扰动参数，药液颜色通过吸收/散射参数表现。不修改铁匠台共享资产，不新增全屏流体模拟。
