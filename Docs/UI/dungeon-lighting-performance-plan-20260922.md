# 地牢灯光优化与性能栏目

用户已授权按上一轮建议实施。目标为 Win64 Development Editor、L_Dungeon_Randomized；本轮不启动 UE、PIE 或测试。

## 灯光实现

- 在 AuthoredDungeonGenerator 的原生成路径接入，旧地图内嵌目录也使用默认策略，无需重新导入地图；保留种子、房间布局、碰撞、流体和起始区域资产。
- 每个战斗房间优先保留最亮的两盏主阴影灯；辅助灯改为向下的局部补光，半径取原来的 80%、上限 3 米。只有补光横向影响范围能装入原有占地 cell（预留 35 cm 墙体余量）时才关闭阴影，靠墙灯保留阴影，不能保证严格两盏上限。走廊灯使用有阴影的向下聚光灯。聚光灯按 UE 的流明/立体角关系换算，避免直接沿用总流明使中心过亮。目录可逐灯覆盖。
- 仅生成模块中的 Fixtures / Debris 默认退出投影；墙体、门框、服务管线、桥与角色保留阴影；流体继续不投影。可由目录 cast_shadow 覆盖。
- 运行时保存模块 cell、连接门洞与灯引用，以 0.1 秒定时器更新。保留当前房间、穿过连接件的一层相邻房间及视锥可能穿过的门洞链；后者为保守候选，非遮挡实测。关闭延迟 1 秒，亮起 0.35 秒、熄灭 0.8 秒。只在淡变时更新强度，完成后关闭组件。
- 未取得视图或玩家位于生成范围之外时保留灯，由原生距离裁剪接管；编辑预览不运行房间裁剪。EndPlay/重新生成清理计时器和弱引用，不引入逐灯 Tick。
- fps.Dungeon.Lighting.Optimize 在下次生成时选优化/旧灯策略；fps.Dungeon.Lighting.RoomCulling 可即时控制房间调度。不开启 MegaLights、不改全局画质。

## 面板结构与数据合同

- 入口：交互开发面板 → 性能监测。在资源覆盖后新增“灯光 · 配置与视野估算”，沿用当前 Body、Section、ColdSteelUIStyle、自动换行及外层滚动。固定控制条、焦点、开关与导出入口保持现有行为。
- 数据由原有按需场景快照采集；不新增高频全场景扫描。栏目展示总数、启用数、带阴影的启用数、点/聚光/矩形/方向灯数量、受距离和视锥筛选的候选数，以及最近 12 盏明细。完整列表进入 JSON，与网格 Top N 独立。
- 每灯导出路径、类型、房间/角色、可移动性、强度和单位、半径、距离、最大显示距离与淡出、阴影、体积散射、候选资格。距离为厘米（界面米）。候选只用球形影响范围、视锥和距离；不声称是 GPU 可见数或真实重叠像素。
- 保留旧 VisibleLights 字段语义兼容，明确它是组件可见标志；新增 EnabledLights 使用 ComputeLightBrightness 大于零，兼容零/负 EV 强度与 IES。记录当前相关 CVar 值，声明它们不是某个 GPU pass 实际执行的证明。
- GPU 分阶段耗时和实际渲染灯数没有数据源时导出 null，界面显示“未采集”；不以权重换算毫秒。schema 升至 7。
- 无视图时不展示候选数；无灯时显示空状态；暂停刷新时随原快照冻结。只读栏目，无独立保存、扣除或输入事件。

## 交付边界

源码及必要 Editor 构建；完整运行效果、门口淡变、补光漏光/暗部变化和性能收益由用户测试。后续对照应固定 DungeonSeed、视角、分辨率与画质，不能把之前昼夜地图采样当作地牢基线。
