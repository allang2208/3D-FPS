# 丢弃卡顿与背包关闭（2026-09-11）

## 原因与基线

同一宿主的独立审计进程采样 `Saved/WorldInteraction/baseline_drop_20260911.log`：枪械装配约 7.18–15.78 ms，每次丢枪/重建后还发生约 20.89–43.82 ms 的 GC。丢弃事务保存约 9.17–10.82 ms。

旧 `BuildWeapon` 为每次掉落创建并销毁 `FPreviewScene`。UE 5.8 的 `PreviewScene.cpp` 在释放预览世界时默认调用 `ForceGarbageCollection(true)`；因此模型已被背包图标加载仍可能在松开鼠标后停顿。采样确认了这条额外停顿，未声称复现用户所有场景中的秒级停顿。

## 修改

- GameInstance 生命周期内复用两套隔离枪械预览角色，关闭不需要的灯光、声音与物理场景；丢弃时不再销毁预览世界或请求整轮 GC。
- 碰撞边界按枪械定义及完整配件组合缓存，最多 64 个组合；背包图标准备完成时预热对应组合。改造组合变化使用不同缓存键，现有模型、配件和姿态继续复制到地面物理物件。
- 保留原同步 A/B 存档事务及失败回滚；没有通过跳过保存校验来降低耗时。
- 背包打开时 TAB 统一关闭，无论当前在装备页、属性页还是物品菜单。Caps 保持属性面板语义，长按重复事件不反复开关。
- 背景接收点击并在预览鼠标事件中判断实际屏幕几何：点击背包/仓库/详情外关闭全部背包面板，面板内操作和悬浮详情不被误关。拖出时仍属于拖放，松手执行原丢弃事务；拖动结束后外部点击仍可关闭。
- 关闭时沿用原交互取消、浮窗清理及游戏输入恢复，关闭点击被消费。

## 验证

`Tools/UI/run_drop_hitch_acceptance.ps1` 使用真实 Slate 按键和鼠标事件，覆盖 TAB、属性页、独立物品弹窗、内外点击、拖出释放、原实例弹药和落地物理。世界交互脚本继续覆盖改造枪械、遮挡、满包、失败保存及新进程恢复。

- 默认 Editor Development 编译通过（`Saved/DropHitch-fixed-build.log`）；修复了旧物品浮窗的全局 `using namespace ColdSteelUI` 导致 Unity 合并编译时污染其他源文件的问题，改为仅导入该文件需要的符号。
- 真实输入回归 **11 / 11**：`Saved/DropHitch/20260911001938-1280.log`。松手模型处理 **0.917 ms**、世界生成 **1.450 ms**、同步保存 **11.754 ms**、完整 Slate 松手处理 **14.538 ms**。
- 世界交互写入 **25 / 25**，新进程恢复 **27 / 27**：`Saved/WorldInteraction/20260911002020-write.log` 和 `20260911002020-restore.log`。缓存后的枪械模型处理约 **0.23–1.28 ms**，丢弃后不再触发原来的预览世界销毁 GC；日志仍记录测试第 7 阶段显式请求的 GC。
- 新进程首次恢复资产仍有启动加载成本（本次约 57–58 ms），不会以“每次松开鼠标重新加载预览世界”的形式重复发生。
- 已检查 `Saved/DropHitch/native-drag-ground.png`，真实拖放后枪械保持模型与物理落地。

性能数据仅代表该宿主与测试场景，不等同所有地图的帧率保证。
