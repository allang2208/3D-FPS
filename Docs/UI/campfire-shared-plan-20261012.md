# 篝火共享操作接入

本批用户授权：客机共享添柴、排队、领取与公共状态；菜谱仍为 0，不增加食物资产。火焰先完成本地候选盘点；15:07 UTC 用户随后授权采用第一套 `P_Fire_Small` 制作独立副本并替换。

沿用现有右侧冶炼面板、背包联动、字体和主题。篝火页改名“篝火 · 共享烧烤”。上方同时展示当前一份进度、等待队列（最多 8 项）、公共成品（最多 60 份）；中间显示已有食材与一次 1–5 份的投料按钮；下方显示共享木材燃料与添柴。无菜谱显示明确空态。主客机同一界面，客户端只读复制快照。原高炉和铸造面板保留。

按钮请求走拥有者 PlayerState，服务端核对本人控制器、角色存活、篝火实际构件身份、3.5 米操作距离、视线、菜谱、数量、个人材料和背包容量。材料从操作者的背包／分区／主仓库扣除，领取进入操作者背包。公共产物先到先取，满架暂停制作，燃料仍持续燃烧。取暖半径仍为 5 米，燃烧时自然饥饿、缺水消耗各乘 0.5；不影响伤害、不叠加。

上传库存与篝火意图在同一可靠通道排序；等待回执时暂缓本机物品事务。专用版本屏障避免旧全量档案回滚服务端扣料。交易先保存篝火写前日志，再保存操作者档案，然后保存建筑状态，最后删除日志；启动时先恢复日志后推进烧烤。失败保留日志并暂停该建筑世界的篝火交易，客户端不写建筑档。关闭界面不撤销已发送交易；断线释放本机等待状态，主机档案和公共队列保留。

本批仅静态复核和必要 Editor/Game 构建；双端、重连、失败恢复、延迟及视觉效果由用户测试。
