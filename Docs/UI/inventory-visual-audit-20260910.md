# 背包冷钢视觉审计与升级

## 对照依据

现行基准为旧 Godot 归档中的 `docs/apple-glass-ui-standard.md`、`ui/apple-glass-tokens.json`，以及原版 `docs/reference/game-dev-cold-steel/docs/ui-cold-steel-design-system.md`。本机实际参考位于 `E:/3d/trash/repository-ue5-root-20260910/`；旧 E 盘开发路径已经退役。UE 的 `ColdSteelUIStyle` 是运行时字体与配色入口。

对照保留：右侧 45% 全高抽屉、3×5 装备槽、18×4 空间背包、长枪 5×2 占地、宋体 0.5 与 Consolas 数字、20px 抽屉标题、16px 空槽文字、12px 格内名称、10px 加工侧标。占用装备格只显示模型和侧标，空槽只显示部位文字；白底详情浮窗继续沿用已有规则。

## 审计结果

| 项目 | 发现 | 本次落实 |
|---|---|---|
| 分区层级 | 装备、空间背包、快捷物品主要靠相同灰框区分 | 装备统一承托、银色分区标记、分区标题和真实数量；减少单格边线强度 |
| 网格 | 相邻空格各画一圈边框，形成重复接缝；占格难从物品上辨认 | 一次绘制底板和单条网格线，物品底板保留更弱的内部占格线 |
| 物品信息 | 同类物品外框无稀有度/加工辨识 | 六档原版稀有度、强化等级、改造和附魔侧标，全部从当前实例数据读取；未加工物品不造标记 |
| 模型与名称 | 直接叠字，细小模型区域容易干扰文字 | 中央模型避开侧标，名称有局部承托和实测宽度省略，完整名称由原详情入口查看 |
| 数量与冷却 | 数量贴边、冷却和模型混合 | 数量独立底色与右侧界限；960 宽数量使用允许的 10px；冷却使用遮罩及独立数值 |
| 悬停与选择 | 悬停基本只触发浮窗，选中只有细边 | 物品悬停承托、空格定位框、选中银边及“已选中”文字；键盘浏览使用中性色焦点 |
| 拖动 | 预览层位于物品图之下，颜色可能被图遮住 | 候选和回填框在图层上方，合法/非法沿用语义色并显示真实提案原因 |
| 快捷物品 | 数量与按键缺少固定区位 | 数量顶部、按键右下；增加绑定提示，保留现有绑定和使用入口 |
| 操作发现 | 整理没有明确悬停反馈，底部平时没有提示 | 整理悬停边框；底部显示选中/操作反馈，并区分枪械与一般物品提示 |
| 容量反馈 | 只有文字，需要逐字读取 | 保留实际格数/件数，并增加同源容量细条，满格使用提醒色 |

最初怀疑背景颜色重复相乘。核对 UE 5.8 `DrawElementTypes.cpp` 后排除：`MakeBox` 直接使用传入 Tint，不应改成白色。实际修改的是边线强度和分区层级。1px 线条使用零描边，避免透明描边吃掉整个填充。

## 实现与生命周期

UMG 控件继续负责焦点、滚动、浮窗和输入；自定义 Slate 绘制集中到 `ColdSteelInventoryPresentation.cpp`。物品介绍数据在现有 `LoadIcons`/模型变更事件中缓存，绘制不重复解析 JSON，也不写玩法数据。模型图仍按已保存的配件组合生成。原先的构造绑定、销毁解绑、关闭及焦点返回路径保留；鼠标离开清除新增悬停状态。文字按实际字体测量后省略，反馈位于滚动内容边界内。

共用稀有度/加工色来自原版 token，加入 `ColdSteelUIStyle`；本页没有另建字体或全局主题。现有技能/图鉴页签仍处于禁用状态，内容能力不属于此次视觉调整。

UE 5.8.2 Editor Development 编译成功，最终模块后缀 `2026092024`。`run_inventory_visual_acceptance.ps1` 在 960×540、1280×720、1920×1080 三个新游戏进程各通过 8 项检查，使用独立 `InventoryVisualAudit_*` 存档。覆盖六档稀有度、强化/改造/附魔组合、99 堆叠、装备模型、全部 72 个格子的绘制/命中一致性、真实提案的合法/越界预览、物品 ID/数据/数量/弹药/位置/快捷绑定不变。

首次回归把 `Generation` 不变当作浏览验收条件，遇到正常五秒自动存档递增。最终改为检查所有物品实际内容与绑定不变，不把正常存档视为 UI 写入。

三种分辨率截图保存在 `Saved/InventoryVisual/`：`overview-*`、`selected-*`、`allowed-*`、`rejected-*`。960 窗口通过原有滚动区访问下部内容；模型和侧标保持格内边界。`before-1920.png` 为上一轮界面存档，物品配置与本次压力样例不同，不能当作像素差异统计。

`run_inventory_drag_acceptance.ps1 -Widths 1280` 的完整真实拖拽回归通过 127 项检查，日志为 `Saved/InventoryDrag/20260910213041-1280.log`，包含 3750 个原规则样例的兼容核对。只读缓存与表现新增没有修改交易函数，现有回填预览继续显示。

已检查的画面来自真实游戏渲染；未宣称不同场景背景逐像素对比度、手柄全流程或打包验收完成。原生变更由新启动的编辑器/游戏进程加载。
