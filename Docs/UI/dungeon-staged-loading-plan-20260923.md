# 地牢分阶段进入

## 目的与范围

沿用 `UTransitLoadingSubsystem` 的跨地图加载页，把随机地牢的结构、物理碰撞、外观、灯光、摆件和导航准备放在玩家取得操作权之前。入口仍为现有地牢传送门，直接运行地牢地图也走相同准备流程。此次为代码接入；未要求运行游戏或性能测试。

## 界面与数据

- 复用现有全屏遮挡、居中加载卡片、进度条、等待时间及“取消 / 返回主场景”，布局和 `ColdSteelUIStyle` 字体、配色不另建一套。
- 进入传送门后先显示“正在进入地牢”，短暂延后地图切换，让视口有机会绘制遮挡；阻塞地图载入期间仍由原有 MoviePlayer 接管。
- 规划 → 资源 → 地面、连接段、楼梯及碰撞 → 房间外观、灯光、固定物件 → 环境摆件 → 场景切换 → 战斗导航 → 完成。
- 进度取实际任务游标和提交游标的阶段加权值，不表示耗时百分比或剩余时间。导航尚在生成时保留加载页，不用定时器伪装准备完成。
- 不新增弹窗或页面栏目；长状态文字继续换行，窄窗与矮窗沿用现有卡片适配。

## 运行合同

- 仅现有单机地牢生成路径生效，公共 Blueprint/API 不变。
- 结构碰撞优先于装饰；每个新 Actor 配置完成后，在相同的每帧工作预算内创建物理状态。异步物理尚未完成时停留在当前 Actor，不能提前放行。
- 旧布局保留到全部新对象和碰撞准备完毕；之后分帧销毁旧布局、显示新布局，期间保持加载页和移动冻结。
- 所有场景摆件、会影响寻路的物件都在进入前完成。当前版本不在玩家眼前继续补建地板或堆放摆件。
- 所有准备、旧布局退场、新布局显示、导航完成后，才启用危险区域、战斗并恢复移动。失败保留原有取消／返回入口。
- 取消传送时清理尚未执行的切图定时器；关卡销毁时一并清理。生成取消沿用现有回滚和代际控制。
- 每帧预算默认 3 ms，为软预算；单次资源载入、Actor 注册、碰撞创建或渲染线程工作仍可能超过预算，不声称消除了所有卡顿。
