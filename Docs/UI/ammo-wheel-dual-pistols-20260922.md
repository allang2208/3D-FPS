# 双持手枪：左右两盘弹种轮盘（2026-09-22）

用户要求：双持手枪时长按 R，**左右弹出两个圆盘**同时选弹；圆盘直接复用步枪那套（不新做样式）；**鼠标可以在两个圆盘之间随意移动**，移到哪个盘里就改哪只手的弹种；步枪原有的“原点指针”一并综合处理。

入口：双持手枪（`AFPSGAMECharacter::IsDualWieldingPistols()`）时长按 R 0.30 秒 → `UColdSteelAmmoWheel`。手别、盘面合同与弹药袋同一套：见 [动态弹种轮盘与弹药袋](../../skills/ue5-ui-umg-slate/references/ammo-radial-and-pouch.md)；灵敏度参数见 [长按 R 弹种轮盘灵敏度修正](ammo-wheel-sensitivity-plan-20260921.md)。

## 开启门槛（先看这一条）

轮盘不是无条件弹出的。`FPSGAMECharacterAmmo.cpp` 的 `ReloadInputPressed()` 里有：

```cpp
if(Model->CompatibleAmmo(*Gun).Num()<=1&&(!Off||Model->CompatibleAmmo(*Off).Num()<=1)){ReloadPressed();return;}
```

**两只手都只有一种兼容弹种时，长按 R 直接走普通换弹，不创建轮盘**（弹匣满时连换弹动作都没有，表现为"长按 R 什么都没发生"）。2026-09-22 加弹种前，`.45 ACP`（M1911）与 `.357 MAG`（Dan-Wesson 715）各自只有一条"普通弹"，所以双枪长按 R 必然没有反应——那是数据门槛，不是接错线。同日已按用户指定给两个口径各加 3 档（见 [手枪三档弹种](../../Docs/Combat/ammo-pistol-45acp-357-tiers-20260922.md)），现在两条门槛都通过。

只要**任一只手**有 ≥2 种兼容弹种，轮盘就会打开；另一只手只有 1 种时，那只手的盘显示单个"当前装填"扇区、不可提交，不会画空盘。

## 盘面结构

| 项 | 单盘（步枪／单持） | 双盘（双持手枪） |
| --- | --- | --- |
| 盘数 | 1，圆心即屏幕中心 | 2，左＝副手、右＝主手，关于屏幕中心对称 |
| 原点 | 盘心 | **两盘正中的中点**（等于原来的中心取消区） |
| 指针 | 半径比例，钳制在 0.96 半径内 | 同一根指针，可自由穿行两盘之间，只钳制在视口内（留 8px） |
| 扇区选择 | 指针所在盘的扇区 | 只对**指针所在的盘**结算扇区 |
| 活动盘 | 恒为活动 | 指针在哪盘哪盘活动：描亮外沿、扇区高亮、盘心显示待切换 |
| 松 R 提交 | 该盘的待切换弹种 | **活动盘那一只手**的待切换弹种 |
| 取消 | 移回中心／Esc | 移到两盘之间、或任一盘心取消区／Esc |

两盘共用一个盘面绘制函数：扇区等分、图标、名称／数量／状态文字、盘心文字、上方武器名与效果摘要、等级标识，全部沿用步枪那一套，没有第二份样式；材质见下节。

## 盘面材质（2026-09-22 第二轮：回答"中间有间隙、没有拼合"）

用户问：轮盘中间有间隙、扇区没有拼合，是缺陷还是本意？结论分两半：

- **中心孔是本意**：半径 30% 以内是取消死区（移回来松 R 即取消），同时承载盘心文字（待切换弹种／`N 发`／`松开 R 换弹`）。它不能填实，否则既没有取消手势，文字也没地方放。逻辑死区半径提取为 `AmmoWheelDeadZone=0.30`，绘制与命中判定共用同一常量，不再各写一份 `.30`。
- **"没有拼合"是缺陷**：旧的扇区是各自独立的半透明楔形——角向各缩进 `min(.016, Step×.04)`（≈1.8° 缺口）、只有外弧一根线、没有底盘、没有内圈环，缝隙直接透出世界，所以看起来是一圈断开的片。这一轮按冷钢规则重做了材质。

新材质（全部取自 `ColdSteelUIStyle` 与设计规则，没有新色板、没有新贴图）：

| 层 | 内容 |
| --- | --- |
| ① 外沿阴影 | 从 `R` 到 `1.055R` 的暗环（黑 34%→0），整盘从世界里浮起来；不是彩色装饰边框 |
| ② 连续底盘 | `Inner×.92 → R` 一整圈：内深底 `Content` → 外玻璃 `GlassTint`。扇区落在这块面上，**缝隙里露的是底盘而不是世界** |
| ③ 扇区 | 三环渐变（`Content` 暗内沿 → 中圈高光 → `GlassTint` 外沿）做玻璃厚度；角向缝隙收到发丝级 `min(.0045, Step×.012)`；悬停扇区外沿抬升到 `1.03R` 并混入银白 |
| ④ 内圈环 | `Inner×.94 → 1.12` 的三环凸起（深—亮—深）+ 两道 1px 细边，把每个扇区的内沿**连成一整圈**，中心孔因此读作"凹陷的玻璃中心" |
| ⑤ 等级标识 | 每个扇区在内圈环上占自己那段弧（`Inner×.99 → 1.07`）：可用＝等级色，当前装填＝银白 `Accent`，已用尽＝等级色 35% |
| ⑥ 外沿收口 | 半径 `R` 一整圈 1px `Border`；双盘时活动盘再描一圈 2px 银白 |
| ⑦ 盘心 | 两层凹陷：`Content` 底盘（半径 `.94×Inner`，1px 边）+ `GlassTint` 玻璃面（`.78×Inner`）；指针进死区时底盘边线转银白，提示"松开 R 取消" |
| ⑧ 图标格 | **中性凹槽**（`Content` α150 + 1px `Border`，不掺等级色）+ **中心裁切的等级图**（`FramedIcon`：共享画刷副本、UV 收到中间 82%，主体放大约 1.22 倍）；图标边长 `min(96px, R×0.40)×Fit`，悬停再 ×1.06 |
| ⑨ 指针 | 银白圆点 + 深色 1px 描边；悬停在**可提交**弹种上时加一圈 28% 银白光晕（松 R 会发生什么是可预期的） |

规则对齐与刻意取舍：

- **不做彩色装饰**：扇区填充改中性玻璃，等级色降级为"内圈标识弧 + 图标底板"两处语义标记；银白（`Accent`）只表示交互与当前状态。这符合设计规则"不使用蓝色染底、彩色装饰边框"。
- **不做矩形模糊背板**：抽屉类面板用 `UBackgroundBlur`（强度 9／半径 21），但轮盘是圆形 HUD 覆盖层，`UBackgroundBlur` 是矩形控件、给不了圆形遮罩；强行加一块矩形模糊会破坏"轮盘"的形。因此改用分层中性玻璃（`Content` / `GlassTint` / `Border`）表达同样的玻璃语言，这是 HUD 元素在本项目里的既有做法。
- **字号对齐六档 24/20/16/14/12/11**：扇区名称 16→14、扇区数量 24→20；盘心标题 16、盘心说明 12、底部提示 14／12 保持不变。被悬停的名称改用 `TextFont(..., bMedium=true)`（规则里 Medium 500 用于选中项）。
- **不动的东西**：布局与半径、命中判定与死区、滞回、指针积分、松 R 提交事务、全部文案，逐值不变。单盘（步枪／单持）也一起升级材质——用户这次要的就是观感提升，不再保留"单盘与改动前逐像素一致"的约束。

编译核对：`Source/FPSGAME/UI/ColdSteelAmmoWheel.cpp` 用本模块自己的 rsp + SharedPCH 直接调 `cl.exe`（工作目录 `Engine/Source`，输出到系统临时目录）**退出码 0**（2,487,404 字节 obj，日志无警告）。这是翻译单元级核对，不等于整模块构建。11:37 有编辑器占用工程，命令行 UBT 构建会被拒绝；请在编辑器内按 **Ctrl+Alt+F11** 应用 Live Coding 补丁。

### 第三轮：图标格（用户反馈"弹的背景色几乎把主体覆盖了"）

先看清素材本身，再改画法。实际图片是：

| 素材 | 实际内容 |
| --- | --- |
| `Icons/Ammo76220260921/762_*.png` | 写实照片：弹药盒 + 散弹，**背景是一整块不透明的等级色**（LP 为绿），主体只占画面约七到八成 |
| `Icons/ammo_556.png`（= 5.56 三档图；手枪三档也是它的副本） | 写实照片：弹药盒 + 散弹，**背景透明**，主体同样只占约八成 |
| `Icons/ammo_58.png`（= 5.8 三档占位） | 旧通用图标组，256²、主体很小 |

轮盘上的图标只有 80–96 px，于是"照片自带的底板色 + 我上一轮加的等级色底板"叠成两层色块，主体被淹没——这是画法问题，不是素材缺陷。三处改动：

1. **中心裁切**：轮盘新增私有 `UColdSteelAmmoWheel::FramedIcon(Id)`（`UI/ColdSteelAmmoWheel.cpp`，常量 `AmmoWheelIconFrame=0.82`）。它复制模型那张共享画刷、只把 UV 收到中间 82%，主体放大约 1.22 倍；纹理仍由模型持有，弹药袋／背包／仓库用的原件不动。裁切比例是一行常量，最终图若主体更满就调大、更小就调小。放在轮盘内部而不是模型上，是因为 `ColdSteelStatusModel.h` 被大量文件包含，为一次观感调整让整个模块重编不值当——轮盘头只有轮盘自己和 `FPSGAMECharacterAmmo.cpp` 用。
2. **去掉等级色底板**：图标后面改成中性凹槽（`Content` α150 + 1px `Border`）。照片自带的色场成为这一格唯一的彩色来源；等级色只留在内圈标识弧上（7.62 那套图本来就在照片里带等级色，再叠一层反而糊）。
3. **图标放大**：`min(80px, R×0.34)` → `min(96px, R×0.40)×Fit`，悬停再 ×1.06；凹槽留白 5px → 4px。文字偏移不变，双盘时随 `Fit` 一起缩，不会压到扇区文字。

### 第四轮：图标居中（用户反馈"各图标不在其扇形格子中间"）

原因是**内容的偏移量加在屏幕竖直方向**，而不是沿扇区中线：

```cpp
// 旧：锚点在扇区中线上（0.67R），但图标与三行文字都沿屏幕 y 偏移
const FVector2f TextAt2=Center+Dir*R*.67f;
const FVector2D IconAt=FVector2D(TextAt2)-FVector2D(Side*.5,Side*.5+24*Fit/Scale);
TextAt(Choice.Name,TextAt2+FVector2f(0,26*Fit/Scale),...);
```

只有 12 点那个扇区（中线 −90°）碰巧对齐；30° 与 150° 的扇区整组内容被推向一侧。按 R=240、图标 96px 算切向偏心：

| 元素 | −90° 扇区 | 30° 扇区 | 150° 扇区 |
| --- | --- | --- | --- |
| 图标中心 | 0.0 px | **−20.8 px** | +20.8 px |
| 名称 | 0.0 px | +22.5 px | −22.5 px |
| 数量 | 0.0 px | +42.4 px | −42.4 px |
| 状态行 | 0.0 px | **+63.2 px** | −63.2 px |

改法：用极坐标排布，所有元素都落在扇区中线上。

```cpp
const FVector2f Dir(FMath::Cos(Middle),FMath::Sin(Middle));
auto Along=[&](float Rho){return Center+Dir*Rho;};          // Rho 是距盘心的半径
const FVector2f TextAt2=Along(R*.67f);
const FVector2D IconAt=FVector2D(Along(R*.67f+24*Fit/Scale))-IconSize*.5;
TextAt(Choice.Name, Along(R*.67f-(Icon?26.f:-21.f)*Fit/Scale),...);   // 数量 49、状态 73 同理
```

核对（离线算，非 PIE）：三个扇区的图标/名称/数量/状态切向偏心全部为 **0.0 px**；径向仍在盘内——图标格 136.8..232.8（盘沿 240，悬停 ×1.06 后 235.7 仍在盘内），状态行内沿 79.8 > 盘心 72。`ColdSteelAmmoWheel.cpp` 编译核对**退出码 0**。

**顺带说清一个几何约束**（用户若要图标"真正在格子正中"需要选方案）：扇环可用径向空间是 72..240 共 168 px，而图标格 96 px 加上名称/数量/状态三行约 73 px，已经占满——所以图标中心只能落在 0.77R（贴着盘沿一侧），内容组中心 156 与扇环质心 141 相差不多，但**图标本身不可能同时居中于扇环中部又让文字留在格内**。两个可选方案（均未实施）：

- **图标格独占扇区**：格子只画图标并居中于扇环中部（可达 ~130 px），名称 / 数量 / 状态全部由盘心承担（盘心已显示悬停项名称、"N 发"、"松开 R 换弹／取消"；当前装填由内圈银白标识弧表示）。代价：一眼看全各档剩余数变成需要逐个悬停，弹药袋页仍可看全。
- **缩小图标换径向位置**：去掉状态行、图标格降到 72 px，图标中心可从 0.77R 移到约 0.71R（格位 134..206），文字仍在格内。代价：图标变小（主体可视尺寸回落）。

### 第五轮：整格内接（用户反馈"图标又超出了整个面板"）

第四轮把内容摆到扇区中线上之后，暴露了另一个错误：**图标格是轴对齐正方形，我只验算了"沿半径的外沿 ≤ 0.97R"，没有算四角**。正方形相对中心在半径方向上多出 `√2/2 × 边长 ≈ 0.707 × 边长`，所以 96 px 的格子在 30°／150° 扇区角点距离达到 **251 px > R=240**，四角戳出盘沿（12 点方向的格子碰巧不越界，这也是为什么之前没发现）。

改法：按**整格内接于 0.97R** 反解边长，自上而下把径向空间分完。

```cpp
const float Rim=0.97f*R;                     // 允许的最外半径
const float HubOut=Inner+6.f/Scale;          // 盘心外沿
const float NameDrop=8.f*Fit/Scale;          // 图标格内沿 → 名称中心
const float CountDrop=29.f*Fit/Scale;        // 名称中心 → 数量中心
const float TextBlock=NameDrop+CountDrop+12.f*Fit/Scale;
const float CellSide=FMath::Clamp((Rim-HubOut-TextBlock-2.f/Scale)/1.2071f,
    FMath::Min(48.f/Scale,R*.20f),96.f/Scale)*Fit;
const float CellRho=Rim-0.7071f*CellSide-2.f/Scale;        // 图标中心半径
const float CellNameRho=CellRho-CellSide*.5f-NameDrop;
const float CellCountRho=CellNameRho-CountDrop;
```

`1.2071 = 0.7071（角点余量）+ 0.5（中心→内沿）`，另外 0.5（中心→外沿）已经含在 `CellRho` 里；`0.7071` 取 `√2/2` 是最坏情况（45° 扇区，8 档轮盘），对任何扇区数与角度都成立。悬停放大改成**只向内长**（外沿与角点留在原处），否则 ×1.06 会把角点再推出去。

**代价与取舍**：格内从"图标 + 名称 + 数量 + 状态"减为"图标 + 名称 + 数量"。"当前装填／已用尽／待切换"不再占格——盘心已显示悬停项名称、剩余发数、松开 R 的动作提示，当前装填另有内圈银白标识弧，状态行是冗余的；去掉它才腾出图标的位置。若要把状态行放回格内，图标格只能用 71 px（`TextBlock` 增加约 30 px）；若反过来把名称/数量也交给盘心，图标格可以做到 ~130 px 并真正居中于扇环中部。

### 第六轮：名称净空与缺图留空（用户反馈"调整弹药名称位置，然后接入图片"）

第五轮为了把图标格缩进盘内，径向空间被压得很紧，结果**名称盒上沿压在图标凹槽的下边框上**：名称外沿 128.0 > 凹槽内沿 123.0，压住 5.0 px。改法是给相邻元素留净空，代价由图标格承担：

```cpp
const float NameDrop  = 18.f*Fit/Scale;   // 图标格（含 4px 凹槽留白）内沿 → 名称中心（原 8）
const float CountDrop = 26.f*Fit/Scale;   // 名称中心 → 数量中心（原 29）
```

## 指针与原点（本次综合处理的部分）

- 指针仍是**位移积分**的虚拟指针（`fps.AmmoWheel.PixelsPerRadius`，默认 180 屏幕像素走满一个半径），不是系统鼠标位置，所以打开轮盘时画面不会跳。
- 单盘：原点＝盘心，`Pointer` 长度钳在 0.96 半径内 —— 与改动前逐值一致。
- 双盘：`Pointer` 以**组中心**（两盘正中的中点）为原点；指针从组中心出发，因此刚打开时两个盘都不选中、松 R 即取消，与原来“从中心取消区开始”完全同义。左右移动即可进入任一盘：盘心距组中心约 1.05 半径，越过盘沿只需要约 0.05 半径（约十几像素）。
- 每盘各自判定：指针到该盘圆心的距离 ≤ 半径即进入该盘；只有活动盘参与扇区结算，另一个盘的悬停立即清空，跨过两盘之间时两边都不选中。
- 光标点仍是一个 8px 白点，画在共用指针位置，可以横穿两盘之间。

## 布局与自适应

- 单盘半径：`clamp(220+N×5, 240, 340)/Scale`，再按视口 `min(宽×0.44, 高×0.35)` 收缩 —— 未改。
- 双盘半径：同上限，再按 `min((宽×0.94−间隙)/4, 高×0.35)` 收缩，保证 `4R+间隙` 放得下；间隙 28 屏幕像素。两盘圆心水平间距 `2R+间隙`。
- 双盘盘径小于 300 屏幕像素时，扇区文字与图标按 `R/300`（下限 0.70）等比缩小，避免文字越出盘沿；单盘恒为 1，观感不变。
- 一只手取不到物品时自动退回单盘（组中心仍在屏幕中心），不会画空盘。

## 输入与提交

- 长按 R 达 0.30 秒：退出 ADS、停止射击、取消双手输入，创建轮盘。双持时 `OpenForDualPistols(主手实例, 副手实例)`，其余情况 `OpenForWeapon(实例)`。
- 鼠标轴在轮盘打开期间只驱动指针（`FPSGAMECharacter::MoveAmmoPointer`），不转镜头。
- **左／右键不再切换手别**：手别完全由指针所在盘决定；轮盘期间点击只被吞掉，避免选弹时开火（`AFPSGAMEPlayerController::InputKey`）。原来的 `SelectAmmoWheelHand` 已删除。
- 松 R：取活动盘的武器实例与待切换弹种 → `StartAmmoSwitch` → `UPistolDualWieldComponent::SwitchAmmo` 按实例找到那只手，播放该手空仓换弹并在动画结束提交（沿用原有事务，未改）。
- 无待切换目标（盘心、两盘之间、当前弹种、零数量）时松 R 只取消，不触发普通换弹——与单盘一致。
- Esc、失焦、菜单、死亡、换枪、动作占用照旧取消整个选择。

## 盘心文案（双盘）

- 活动盘：待切换弹种名 + `N 发` + `松开 R 换弹`；无悬停时显示 `切换弹种` / `移动鼠标选择` / `松开 R 取消`。
- 非活动盘：显示**这只手当前装填的弹种名** + `移动鼠标至此`，扇区压暗到 60% 不透明度，避免误以为松 R 会改这只手。
- 两盘下方（居中一行）：`移动鼠标到左／右圆盘选弹 · 松开 R 换弹`、`移到两盘之间或盘心取消 · Esc 取消`。原来的“左键选择主手 · 右键选择副手”提示随点击选手一起删除。
