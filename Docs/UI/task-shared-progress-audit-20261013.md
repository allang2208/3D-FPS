用户要求复查本对话开发的任务栏、精英刷新/开门与商店，明确主客机共同完成任务。授权范围内做代码检查、必要修复、后台构建和无地图数据检查；不打开编辑器或启动双端游戏。

## 结论与修复

| 发现 | 影响 | 处理 |
| --- | --- | --- |
| 任务进度与建筑、场景状态共用分块快照，应用时先等建筑 | 客机目标更新可能被大量几何数据及加载状态拖住 | 使用始终相关的地牢生成器独立复制小型 SharedProgress；目标/房间事件即时发布 |
| 原快照没有目标进度版本 | 迟到的未完成状态可能覆盖新完成状态 | 以 RunId + Revision 接受更新，旧场景快照不再写任务字段 |
| 客机布局尚未绑定时无法应用进度 | 迟加入/加载顺序容易丢首份状态 | 生成器保留最新复制值，绑定后重放；首次看到已完成目标直接划线 |
| 房间探索、清除、整轮完成入口没有客机拦截；客机绑定会初始化本地运行档案 | 未来调用者可能误写本地任务状态 | 所有推进入口服务器限定，客机只更新镜像，不初始化/提交权威任务档案 |
| 生成器 RunId 只在 BeginPlay 创建，客机 Ready 后忽略新运行 | 同一生成器重开地牢可能沿用身份或不跟随重建 | 每次服务器运行时 Generate 产生新 RunId，客机按新身份重新生成 |
| 联机商店购买成功回执无条件清空待售栏 | 买食物会丢掉尚未出售的选择 | 记录待售交易及版本，仅匹配的出售成功清空；库存回执先应用再通知商店 |
| 联机出售在二次确认后没有执行单机同等的物品内容比对 | 确认期间改造/内容改变的物品可能按旧确认出售 | 确认快照比对移至共同分支；服务器继续核对库存版本、所有权、数量及报价 |
| 客机交易等待期间可修改选择，关闭后可能遗留等待标志；UI 无 128 组限制反馈 | 迟到回执影响新选择或出现无说明拒绝 | 等待期间不改待售选择，结束会话清除本地等待状态，单次 128 组与服务器一致并提示 |
| 禁售只核对目录，未核对实际物品任务标记 | 实例级任务物品可能进入出售选择 | 同时尊重实际物品的 questItem / unsellable 标记 |

编译另遇到 `FPSPerformanceMetrics.h` DLL 导出类的多变量 constexpr 声明 C2487，做最小声明拆分，原四个数值保持不变。

## 主客机共同完成链路

1. 大厅战斗由服务器观察所有玩家触发。目标精英在分流大厅首个实际生成请求中优先生成，原有导航/碰撞与调度预算保持。
2. 任意玩家造成的服务器有效伤害使目标精英真实生命值归零，`FacilityHallEncounter::RecordDefeat` 按原专用槽去重。没有“必须主机击杀”的筛选，也不接受客机直接宣称任务完成。
3. 服务器共享目标成为完成，同时发布 `SharedProgress`。三出口仍由服务器 `IsWelcomeEliteDefeated()` 控制，格栅形状/开度/碰撞锁沿现有 Actor 复制到客机。
4. 客机应用同 RunId 新版进度，任务栏在原 0.2 秒刷新节奏读取；主客机共享完成条件，副标题按各自真实区域显示。
5. 迟加入直接恢复当前进度；同版本重复接收不重复推进；旧运行消息被拒绝。任务完成不等于额外重复发放精英击杀奖励。

## 仍然保留的产品边界

- 首阶段有真实“击杀指定精英”目标；后续区域目前只有对应区域名与探索提示，尚未制定新的具体击杀/收集任务，终点旧 Boss 战斗已退役，不能称为整条地牢任务链全部制作完成。
- 统一任务栏支持新增任务/多目标，但显示注册不是自动联机：新增玩法目标必须遵守根目录 TASK-WORKFLOW 的服务器共享状态合同。
- 共享完成针对当前地牢运行；没有新增跨游戏关闭恢复精英死亡、断点续玩或奖励规则。
- 商店已有上下格子、分页、购买/待售和二次确认接口；NPC 仍按原安排后续制作。主客机商店库存、灵魂各自结算。
- 无地图合同检查不代表真实双端射击、网络丢包下的闸门动画、UI 排版或商店鼠标拖放已经实机验收。
