# 改造面板回查与布局修复

范围为装备改造面板内部模块：分类、预览、配件选择、改造说明、整枪数值和操作栏。

修复前代码证据（快照保存在 `trash/GunsmithLayoutReview-before-20260910`）：

1. `M4GunsmithOverview.cpp` 将全部配件放入一个 SHorizontalBox，且每项 FillWidth(1)。配件数量增加时卡片宽度持续缩小，无滚动入口。
2. `M4GunsmithLayout.cpp` 的点击回调使用 `Id==holographic` / `Id==large_drum` 转成布尔参数。新增合法 ID 会被选择为 false，即错误移除当前配件。
3. 所有属性变更都会清空并重建配件控件，造成点击后焦点丢失；加入滚动后还会影响当前位置。
4. 右栏将改造说明和整枪总览放在同一个滚动容器。改造说明增多时会把数值总览挤出首屏。
5. 预览副本创建后只同步变换和材质，同一组件更换网格资源时不会更新副本网格。
6. 成功保存后再次选择其他部件时，目录的选择操作未更新状态文本，会同时出现“待应用”和“已保存”。

复现与验收：在独立 WorkbenchAudit 存档、DayNight_Lighting 地图中运行 Slate 输入路由测试。压力模式仅向内存目录临时加入多项配件，不写正式 gunsmith.json。检查卡片宽度、滚轮滚动、末尾配件选择、选择后保留滚动位置、原厂复位、草稿及预览交互。原有保存失败、恢复、拖拽、关闭释放等检查保留。

## 已实施

- 底部使用固定 310×122 设计尺寸的卡片，配件过多时出现横向滚动条；普通鼠标滚轮即可滚动，不需要按 Shift。长说明以摘要展示，悬停可读全文。
- 配件数量和当前类别显示在列表标题中；切换类别回到开头，选择配件、切换数值对比不会重建卡片或重置滚动位置。
- 选择按钮传递目录中的原始 ID，修复新增选项被误选为原厂的问题。仍需按原有资产流程接入未来配件的实际模型和功能；临时测试条目不构成正式新增装备。
- 压缩分类栏间距并强化当前类别；当前九个类别可同屏展示。对比按钮显示选中状态，状态栏允许换行。
- 改造说明限高独立滚动，整枪数值独立滚动，收益/代价图例固定在下方。优化行距以容纳当前 14 项数值。
- 选择后刷新待保存提示；无变更的重复选择不再广播整个面板刷新。
- 预览同步会检查静态/骨骼网格资源替换，继续复用实际材质和姿态。

## 验证方法

运行 `Tools/UI/run_gunsmith_workbench.ps1 -RunId layout-final -Width 1920 -Height 1080 -LayoutStress`，并以 1280×720 复查。

`GunsmithLayoutAudit.cpp` 在现有回归后添加 12 个内存测试选项，加上原有两项共 14 张卡片。通过实际 Slate 鼠标事件验证滚轮、末尾卡片选择、位置保持、分类切换，以及同一配件组件的网格替换；最后撤销临时草稿并恢复原目录。原有改造数据文件和玩家正式存档不作测试改写。

首轮 1080p 已通过 44 项检查；视觉复查发现说明末行裁切后进一步修正。最终结果见 `SourceAssets/GunsmithWorkbench20260910/layout-acceptance.json`，不以首轮测试代替最终视觉验收。

最终验收：`layout-final-1920`、`layout-final-1280` 均 44/44 通过；缩短长说明摘要后，`layout-final-v2-1280` 再次 44/44 通过。已逐张查看正常布局和列表末尾截图，现有 14 项数值完整可见。编译通过；当前发布范围为开发模式实机验收，未执行完整打包。
