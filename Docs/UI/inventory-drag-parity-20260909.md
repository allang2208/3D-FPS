# 背包拖放与 Godot 交互补齐 · 2026-09-09

目标项目 `D:/FPS3D/FPSGAME`；只读参考 `E:/3d/3-dfps/ui/backpack_hud.gd`、`spatial_inventory.gd`、`item_rules.gd`、`equipment.gd`。

## 问题与修复

背包内原有 Move 规则已经支持不同占格物品交换。最初的真实 Slate 鼠标验收也能完成普通步枪→药水交换。失败的具体落点是：从 5×2 武器的非左上格抓起，直接落到靠上/左边界的药水本格，减去抓取偏移后产生负坐标，UI 拒绝且不显示原因。原验收只构造 Drag 对象并调用回调，未覆盖实际鼠标按下/移动/松开以及全部抓取格。

现在保留正常抓取偏移放置；若原候选失败且鼠标下是另一件物品，额外尝试该物品锚点。只有同一套 Move / ProposeWarehouse 规则验证成功才对齐，绿色预览和松手使用相同解析。空格越界、覆盖多件物品、被交换物品回不到原位置仍拒绝，并在背包下方给出即时原因。此“有效目标对齐”是 UE 交互增强；没有放宽 Godot 的矩形与原位返回规则。

单击固定浮窗从鼠标按下改为松开且移动不足 6px；超过阈值走拖动，避免按下时生成可交互浮窗。拖动显示按占格约束的图标及源物品淡化，完成、取消、关闭面板都恢复。失败的背包拖放会被 UI 接收，不向外冒泡成其他动作。

## 当前功能对应

| 功能 | 实现与入口 |
| --- | --- |
| 空间背包 | 18×4、长枪 5×2、覆盖格选中、逐格预览、空格移动、不同大小交换、边界和重叠检查 |
| 堆叠 | 同定义且实际元数据相同才合并；字典比较忽略 JSON 字段顺序和 Godot 指定的位置/实例字段；满栈拒绝，余量留在原格 |
| 装备 | 拖入或右键/双击穿戴；双手武器锁副手；替换、卸下优先记忆位置，空间不足保持原状态 |
| 使用 | 右键/双击/Enter；仓库打开时右键按源行为存入；消耗品连接实际 HP/MP 和冷却 |
| 拆分 | Shift+左键松开、X 或拆分按钮打开数量输入；默认一半，可指定整数；确认才提交，取消不修改 |
| 操作菜单 | Shift+右键或“物品菜单”：使用/穿戴、拆分、详情、确认丢下、整理、保存；M4 还可进入现有改造面板 |
| 快捷栏 | 拖入绑定、互拖交换、拖回背包/右键解绑；只变更绑定，物品数量/格位保持；键盘空格拿放同样支持解绑 |
| 整理 | 与 Godot pack 同序：占格面积降序，再按类别+名称+实例排序；保留堆叠实例，不偷偷合并 |
| 地面物品 | 原有确认整组丢下、脚边生成、靠近拾取、满包保留地面实例，继续使用事务保存 |
| 仓库 | 原有分页、拖放交换、堆叠、指定位置取出、批量与装备直存沿用共享提案与原子提交 |
| 输入与浮窗 | Tab 背包，CapsLock 属性；单击松开固定白底详情；F1 聚焦；Esc 取消当前交互；拆分弹层也响应 Tab/CapsLock |
| 持久化 | 保存成功才发布变更；失败、旧拖动来源或旧提案不改变物品；A/B 存档和校验继续生效 |

Godot 独立加工/强化/附魔 NPC、技能拖入和图鉴页面属于各自系统，不应把背包交互验收解释为这些独立系统全部迁移。现有 M4 改造接入保留；不恢复已废弃的六把 Godot 武器。
