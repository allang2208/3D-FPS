# 强化与附魔工作台

> 2026-09-13：本文保留早期实现和历史测试记录。当前布局、字体换算、玻璃与卡片规格已按改造台升级，见 [强化／附魔 UI 同步升级](enhancement-cold-glass-20260913.md) 及 [正式规则第 7 节](ui-cold-steel-design-system.md#7-强化与附魔工作台)。下文的 1600×900 固定画布、112／520 栏宽不再生效。

## 入口和布局

游戏中按 **K**，或在背包的装备菜单选择 **强化 / 附魔**。从背包进入时关闭后返回背包；直接进入时关闭后恢复游戏输入。Esc、Tab、K 和取消按钮均可关闭。选择背包中的另一件装备仅改变预览，不自动穿戴。

UMG 宿主内使用 Slate。布局参考当时 `M4GunsmithLayout.cpp` 的 1600×900 逻辑画布、112 宽选择栏、520 宽属性栏和固定页脚；复用 `ColdSteelUI::TextFont`、`NumberFont`、颜色和圆角边框。主属性强化与附魔使用同一套灰底银白选择样式。公共字体和配色现遵循 [正式规则 v2](ui-cold-steel-design-system.md)，数字为 JetBrains Mono，中文为 Noto Sans SC，替换旧 Consolas／宋体条款；本轮状态页更新未重排强化台布局。装备预览来自当前 `ColdSteelWeaponIcons` 的真实实例/配件渲染，背景复用现有工作台资产。

## 业务规则

规则在 `Content/ColdSteelData/enhancement.json`。当前装备表中的正式可操作武器为 M4 与 AKM；面板按实际实例列出，不放入虚构防具。带 `defense.base/perEnhance` 的防具可走防御强化和装备防御结算。

- 强化：每次 +1，武器最高 +15，防具最高 +10；消耗一颗强化石，金币为 `floor(100 × 1.5^当前等级)`。费用与上限参考归档 `archive/godot-before-ue5-20260910:ui/npc_config.gd`。原生 UE 枪械没有旧版攻击公式，采用可配置的每级增加武器基础伤害 5%，角色攻击独立相加，再计算附魔百分比。刷新/重载从基础重新计算，不重复累乘。
- 骷髅射手：一张卷轴与 400 魔法粉尘，额外穿透 2 个目标；仍被墙壁阻挡，同一发子弹每个目标只伤害一次。
- 狼蛛：一张卷轴与 200 魔法粉尘，命中叠加一层中毒。UE 持续伤害实现为每秒每层 1 点、5 次脉冲，命中刷新持续时间，上限 20 层；效果绑定命中目标及发射时的武器效果，之后切换装备不更改已发射子弹。
- 两种后缀互相替换，重新从保留的前/后缀构造效果，避免旧穿透/叠毒残留。相同词缀拒绝重复消费。原版沉重、锋利卷轴的剑类限制保留，当前枪械不能使用。
- 图稿中的百分比伤害与示例费用没有作为实际规则。附魔效果/粉尘费用来自归档配置及原版 `enchant-config.js`。

## 保存与数据

> 2026-09-13 当前规则：附魔卷轴仅从背包发现、显示和扣除；仓库中的卷轴不作为可用卷轴。魔法粉尘和强化材料仍按背包／仓库合计。下文历史统一材料扣除和旧验收场景不覆盖本次筛选调整。

`UColdSteelEnhancementSystem` 是本地单人业务入口：Quote 为只读结果；Apply 检查 Generation、重新验证实例与材料，再一次性提交装备 JSON 与所有材料扣除。背包材料优先，再扣仓库材料。装备仍保留原实例 ID、位置、弹药、冷却和配件，预览/关闭不移动装备。

数据保留在已有 `enhanceLevel`、`_enchantData`、`_enchantEffects` 字段，经现有 A/B 校验存档写入。无新存档容器或网络状态；多人写入仍由现有 CommitState 拒绝。补齐了原物品表缺少的 `gold` 定义，没有重置或补发正常存档。

实际伤害、装备防御、背包浮窗与改造栏读同一强化计算。命中效果覆盖飞行子弹和即时射线。模型事件刷新报价和按钮，图标完成事件刷新预览；销毁解除事件绑定。

## 验收

运行 `Tools/UI/run_enhancement_acceptance.ps1`，使用独立存档及新游戏进程，覆盖 1280×720 / 960×540，每个分辨率包含写入和全新进程重载。检查纯预览、精确扣费、过期报价、保存失败、等级上限、材料不足、卷轴兼容与替换、穿透与墙体、叠毒、实机按钮点击、切换装备预览、输入恢复、弹药位置保持和重启后实际伤害。

截图及日志在 `Saved/EnhancementAudit/`。已打开的编辑器仍可能运行旧模块，重开后才能使用新构建；独立验收不会更改用户的正常背包。

2026-09-10 实测：`20260910215617` 批次在两种分辨率均通过 29 项操作/业务检查和 3 项新进程读档检查，共 64 项、零失败。随后将窄选择栏的“已装备”缩为“装备”，960×540 的实际截图确认标签完整显示。最终源码以 `FPSGAMEEditor Win64 Development` 编译成功（构建后缀 2026091707）；同时将并行新增护手代码中遮蔽 ACharacter 成员的局部 Mesh 变量改名为 HandstopMesh，未改护手逻辑。
