## 2. 删除或改写的失效规则

| 原问题 | 本批处理 | 保留规则的原因 |
| --- | --- | --- |
| 默认启动 UE、Live Coding、重启、PIE、渲染或测试作为收尾 | 去掉自动执行要求；必要制作、导入保存与构建仍按当前任务进行，用户明确请求的检查单独启用 | 文档维护和制作授权不自动包含额外运行，正在运行的编辑器也可能持有未保存状态 |
| 修改反射声明便主动关闭编辑器、共享构建占用时干预其他进程 | 改为保护已有会话并等待安全接入条件，旧协调条款不构成发消息授权 | 构建和编辑器状态可能属于并行工作，不能由局部任务强行接管 |
| 固定工具名、固定最少节点数、所有版本 API 保证、默认 Clean 和一套万能重现流程 | 改为读取实际入口、已用引擎和工具 schema；短模板只保留适用任务需要的字段 | 名称和版本会变化，模板应帮助定位真实实现，不能新增无关步骤 |
| 有引擎模块名就先触发独立模块路由技能 | 模块表按需作为资料读取，已明确领域时直接使用对应入口 | 路由用于定位任务，不应制造强制前置层 |
| 工程和个人两边维护整份相同规则 | 323 份一致正文收敛为个人维护源，工程保留原章节定位与专属补充 | 单一正文减少规则漂移；不同的项目增补仍有独立职责 |
| LOCAL-HISTORY 中的旧默认流程继续充当现行指令 | 16 份改为历史索引，原件按字节保存在本批 before 目录 | 历史输入、失败和结果需要保留，但历史授权与旧“当前”不能约束新任务 |
| 旧手型称为当前基线、普通近战四段及旧格挡失败候选被视为现用 | 当前基线称呼归并到 V9；普通三段合同和独立动作边界明确；V18/V19 与后续 V21 结果按日期区分 | 版本路径可以是恢复输入，已经被替代的默认行为不能继续指导制作 |
| 旧火球本地单人描述、旧天气单机措辞与当前入口混用 | 文档对齐现有复制/施法入口和世界时钟边界，不改实现或数值 | 旧说明不能否定已经存在的路径，也不能据此宣称联机运行已验证 |
| 通用使用某次动作帧率、厘米阈值、旧性能门槛 | 参数留在对应案例，规则说明实际源时钟、采样与目标预算 | 个案数值依赖具体资产和采样条件，提升为全局要求会误导后续制作 |
| 图标、配件、材质、动作流程默认附带自检和回归 | 明确仅在用户要求对应检查时执行，已执行的历史结果仍保留原日期 | 作者制作、检查与运行验收属于不同任务内容 |
| 竖排“升／级”、正文误用数字字体、旧尺寸示例 | 现行规则统一横向文字和实际可用宽度，按文本角色区分字体；旧审计问题按历史记录说明 | 窄列逐字换行和字体角色混用会破坏可读性 |
| 在项目目录就直接提交推送、以未跟踪文件认定依赖缺失、旧 Git 地址当永久配置 | 发布以用户本次授权、实际文件归属和当前仓库状态为准 | 工作目录并不代表发布授权，生成文件与并行修改也不能被误删或误提交 |
| 外部视觉工具默认介入，旧宿主能力、固定图片数/大小被当成永久限制 | 按当前能力和明确外部复核请求使用，修正请求载荷说明 | 工具限制与图片访问方式需要对应实际入口，旧经验不能扩大外部传输范围 |
| 引用路径失效或把历史引擎扫描当当前保证 | 修正两处实际 Markdown 相对引用；旧引擎模块索引标明日期和历史性质 | 引用需要落到维护入口，历史索引只提供查找线索 |
