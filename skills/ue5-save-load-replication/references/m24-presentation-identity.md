# M24 部件身份、原生轴与联机覆盖

当同一配方在主客机显示不同、换件后远端错位或整套枪械特效未就绪时使用。只在用户要求相应检查时运行夹具。

- 最终部件清单不能依赖组件创建顺序。两端经历不同试装历史，即使 mesh 相同也可能生成不同 MotionSchema。先过滤无效/已移除组件，再沿现有协议以 mesh 路径、socket 和相对 transform 的稳定键排序；定义相同但状态不同也要测，不能只从同一个干净状态创建两端。
- 第三人称原生枪的前/上轴分别求解。M24 `SightUp` 与通用枪根轴不同；已有 `WPN_StockContact` 应保留。看到方向错误先读当前已保存骨架与 socket，不能根据旧导出猜测缺失接口，再造一套补偿挂点。
- FX 初始化可能把枪口、抛壳等多个条件合并为一个 ready。M24 当前源骨为 `WPN_Eject`，通用名称 `WPN_SOCKET_Eject` 不存在；一个名称不匹配可令整套 FX 关闭。按当前 mesh 局部解析并缓存实际 socket，保留其他枪的默认值，覆盖本机与世界枪，不把全局默认属性改成某一枪的特例。
- 新目录被字符串引用时，资产落盘不等于进入 cook。记录必要目录/引用与打包边界，未完整 cook 不称为打包已通过。
- 库存/枪匠权限、伤害、弹药扣除属于权威事务；外观配方、动作时钟、接触流与 FX 就绪属于表现。复制表现通过不能推断伤害或枪匠事务已通过。

M24 案例（2026-11-01 历史证据）：本机真实 UDP 监听主机、客机、新建客机重连；每端 60 ms 延迟、5% 丢包；六阶段两轮共 12 个主机记录，包含不同试装历史、原厂归一、先进机匣/骨架托/握把、空仓换弹及接触流过期。owner/remote FX 均就绪。没有覆盖公网、不同物理机器、打包游戏、连续渲染的手臂人体结构或完整伤害/弹药/枪匠 RPC 实战。精简回执见工程 `Docs/Publication/M24_20261101/HistoricalReceipts/`，不要把历史记录当成本次重测。
