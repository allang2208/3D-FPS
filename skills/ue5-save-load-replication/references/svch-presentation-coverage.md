# SVCH 配件身份与联机覆盖

用于改造历史造成远端部件错位、共享动作跨枪适配和“联机检查通过”范围判定。

- 拥有者在工作台预览过的隐藏配件组件可能比服务器更多。SVCH 卸载握把时清空不再使用的 mesh，并按稳定资产/插槽/安装身份排序后生成部件编号和 schema。动作中临时隐藏的已装配部件仍保留，不能放宽实例、schema 或数量校验来消除差异。
- 第三人称采样本枪、本握把的源手掌相对 idle 增量，再放到世界身体的持枪框架；使用世界身体自己的骨长。不要复制第一人称肩根为躲镜头所做的移动。
- 旧实例的 sniper 类型和基础暴击加成需覆盖本机读档、服务器客机影子、镜像恢复与物品提交；按目录赋值，不能每次恢复再叠加 +1。
- 快速近战的体力和伤害由服务端按接受的动作序号、Pawn 和影子资料裁决；同序号请求不能重复扣体力/伤害，旧 finish 不能清除新动作。外观包只重建表现，不结算伤害。
- 动画与动作执行器要共用源时间。只把加速倍率应用到命中组件，会使本地视模、复制进度和服务端持续窗口不同步；姿态时钟修复应与发生改变的执行器保持一致。

## 明确区分检查层级

SVCH 2026-10-20 的历史结果：

1. 五套 Profile 的实际动画图、握点、机械骨和序列化检查。
2. 隔离远端 Pawn 的真实 `ServerQuickCombat` / `ServerReportHit` 实现，检查授权、扣体力、伤害、去重、旧 finish、错误 Pawn 和体力不足；没有经过 socket。
3. 实际本地 UDP 主机/客机，每端 60 ms 延迟、5% 丢包，首次连接和新客机重连共 12 场景；覆盖指定 ADS、检视、普通换弹、空仓拉栓和表现过期恢复。它使用固定姿态夹具，不等于真实鼠标输入、完整换弹事务或同一玩家持久档案恢复。
4. 仍缺快速近战“客机输入→怪物受伤”的完整网络用例、连续第三人称画面与消音器怪物警觉实战。

前两层合计 376 项通过不能代替第四层。后续更换代码、资料或资产后，历史记录也不是新状态的自动验收。遵守用户默认不主动测试规则；只有明确要求检查时才运行对应层级。
