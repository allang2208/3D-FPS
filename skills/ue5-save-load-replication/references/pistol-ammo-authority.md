# 手枪装填与弹药确认

用于手枪补弹后服务器仍拒绝射击、切弹种后首发用旧数据、左轮中断循环或双手争用备用弹。表现同步与真实装填结算分别处理；历史结果不授权自动测试。

## 状态归属

- 服务器以 Pawn、枪实例、当前武器组和单调动作序号绑定装填计划，从已确认装备计算容量、速度、兼容弹种及接触时间。客户端传意图，不传最终装入量。
- 主手、副手、双枪和法杖副手使用各自真实执行器的时钟；单独左手不套用双持时间倍率。左轮逐发、快速装填器、空仓和只闭合动作分别安排接触事件。
- 插入时扣真实备用弹并更新真实枪内弹量；闭合时清除待闭合标志。两只枪共享同一服务器弹池。取消只保留已发生的接触，不能补足尚未装入的弹。
- 发射从这份实际枪内状态扣除。不要用“计时到期补满容量”、每次换弹重置发射账本或信任整个客机档案来绕过错误。
- 已发射弹的装备/弹种快照冻结在接受发射时。后来的换弹、改造和切栏不能改变在途弹；重复登记不能再次扣弹。

## 拥有者与迟到消息

- 拥有者预测动作和射击，弹药由服务器回执确认。用确认射击序号移除预测，显示服务器余弹减去尚未确认的预测。
- 换弹请求未确认结束时阻止空仓自动重复换弹；取消仍等待对应装填序号的确认。旧取消不能终止同枪的新动作。执行器自然结束不得伪装成取消。
- 切组、卸装、死亡、更换 Pawn 和断线先结束不再适用的计划，再保存实际弹量与待闭合状态。旧 Pawn 的消息不能写进新生命。
- 分块档案捕获时冻结弹药版本和动作序号；普通心跳、交易、营火等所有上行入口都要带同一组元数据。旧上传归并服务器之后的备用弹差额，并保留实际枪内弹量、弹种和闭合状态。
- 新库存版本与弹药回执要先对齐基线，再应用后续差额；不能吞掉拾取/交易所得，也不能把已包含的装填扣数再扣一次。
- 换弹种时按首次实际插入提交旧弹退还与新弹消耗。左轮旧弹壳计数同步清掉；逐发换弹种中断后只保留已经装入的新弹。
- 运行计划、预测和回执版本不写入物品存档；持久化的是实际弹药、弹种、弹壳与机械状态。

## 按授权核对

有检查授权时，使用实际换弹执行器与真实 RPC 覆盖：剩两发补满后连发、切弹种后立即发射、逐发中断后只闭合、快速装填器、切空栏、两枪争用不足弹池及法杖副手。固定影子档案的 UDP 检查不证明心跳上行、同档重连、死亡/换图或专服已通过。

FPSGAME 入口：`Multiplayer/ColdSteelPistolAuthority.cpp`、`ColdSteelPistolRecovery.cpp`、`PistolNetworkTypes.h`，以及角色与 `PistolDualWieldComponent` 的请求/回执接入。案例与公开/本地依赖边界见工程 `Docs/Weapons/pistol-authority-repair-20261024.md`。
