# 快速近战身份与实际联机检查

快速近战动作必须同时绑定动作序号、发起 Pawn、当前主/副手槽位、物品实例及定义。命中结算再次比对；换主手、换副手或换同型号的另一实例后，旧序号不能继续授权。结束动作清除绑定。重复请求不得替换已接受动作的期限、目标去重集或费用记录。

范围标记、物理面板替代公式、目标去重、遮挡与击退在服务器用影子档案复算；不能信客户端传入伤害。主机与客机修炼归属分别确认，不将客机费用写进房主 GameInstance 档案。

用户要求真实联机检查时：

- 使用实际 UDP 主机/专用服务器与客户端、隔离档案及既有批次互斥；记录真实网络模拟参数和双方退出码。方法级 commandlet 不能替代这条传输链。
- Controller RPC 带来的 Actor 引用可能尚未解析。测试设置在引用可用后才开始，周期重发设置保持幂等；不能把空观察者误判为增益没有复制。
- 无地板空地图内，客户端模拟代理仍可能落下，即使服务端角色被冻结。两端目标位置和移动组件按案例复位，避免测试场差异被误诊成距离/命中漏洞。
- 首次激活动画可能异步加载。就绪等待与效果执行期限分开，记录具体门槛；调整测试加载预算不得放宽身份、扣费、回执序号与到期断言，也不把等待变成生产进场阻塞。
- UE 编辑器已运行时保留其进程。审计夹具可用独立输出；仅替换检查对象的增量链接必须来自同一成功构建/ABI，不把混合对象结果当公共源码独立构建证明。

案例：`Docs/Publication/ConversationCombat20261109`；2026-11-08 六组 NullRHI UDP 检查通过，不包含互联网条件、画面或音频验收。
