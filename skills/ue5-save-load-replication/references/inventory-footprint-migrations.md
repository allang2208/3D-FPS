# 物品占格变更：旧档、共享库存与客机

适用于 FPSGAME 修改物品 grid_w/grid_h 后的接入。目录、PNG 画幅和已保存实例是三个独立层；当前实际迁移入口以源码为准。

- 先列出实例保存位置：个人背包/夹层/仓库、共享容器、共享地面掉落、主机保存的客机档案及房间内重连缓存。只修改本地 ReloadProfile 会遗漏服务端存储。
- 复用 ColdSteelInventory 的单件尺寸迁移和整档重新摆放。单件迁移仅改 Data、Width/Height 和规定朝向，不改 InstanceId、数量、世界位置；放入背包前按新尺寸判断空间。放不下时保留地面物品，不先删除共享记录。
- 共享地面旧档先恢复交易日志，再迁移权威世界快照，保存成功后生成拾取 Actor；单个/范围拾取使用同一尺寸规则。纯世界元数据迁移不搬移玩家物品。
- 客机迁移放在服务端影子档案创建和最终权威合并入口，覆盖磁盘档及缓存。库存版本冲突而保留主机 Items 时，也保留对应 WarehousePages、WarehouseLayoutVersion 和 StoragePages。不要在临时 NetView 投影或每次 AdoptNetMirror 时重新迁移。
- 扩大占格沿现有规则重新安置；可能移入主仓库并增加页数。整个方案成功才发布，失败保留原档。利用现有客机保存和基线同步，不另造无回执的跨档事务。
- 共享容器的 map-only 旧键改为 RunId 键时，键迁移本身也是待提交变更。记录键是否变化，恢复旧记录页数，提交前不能进入“已打开”快速返回；提交后通知查看者刷新。保留 bSceneLootResolved，禁止借迁移补刷。
