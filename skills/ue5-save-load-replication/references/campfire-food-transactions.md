# 篝火食品、共享订单与联机回执

此规则用于 FPSGAME 篝火与类似共享烹饪设施。遵守当前用户的后台制作与不主动测试规则；下述边界用于实现设计，只有用户要求检查时才执行对应验证。

- 食材与燃料是两笔账。F6 制作免材料只免食材，木材仍扣除并燃烧。开工时把 bMaterialsWaived 固定在活动／等待订单中，切换开关不追溯修改旧订单。拆除只返还已支付、未加工的真实食材实例。
- UI 可制作数量与服务端扣料共用 FreshCampfireCount：库存位置、容器状态、新鲜度一致。成品按类型汇总展示，服务端保留实例、数量和最早保鲜时间，不能把 UI 汇总对象当作库存载荷。
- 私有食材托管载荷不随共享炉况复制；玩家只提交意图，主机检查角色身份、距离、库存版本、批量与保存状态，主机结算后返回成功标记及库存版本。
- 回执与库存镜像可能先后到达。只有对应版本已合入才解锁；旧心跳上传不能覆盖主机扣料／产物和事务收据。客机档案按持久 NetworkProfileId 绑定主机槽，重连不能用临时玩家名或陈旧上传覆盖已提交结果。
- 已确认库存基线可省略重复上传，但要同时满足外观基线条件。未确认时冻结快照，可靠通道先上传后提交篝火意图；普通心跳不能替换正在等回执的快照。
- 食物使用服务器自然日增量；离线时间和手动跳时不增加腐败年龄。移动、拆分、退回食材必须保留原有食品时间表示。单独复制轻量食品时钟，避免每秒上传整个档案。
- VBX v13 在旧布局后追加食材托管，v14 再追加订单免材料来源。保持 v12 前缀可读；不能只改版本号而遗漏读写双方及旧档默认值。
- campfire-recipes.json 的 presentation 同时驱动穿签、掉落和第一／第三人称进食；新增食品必须一起提供模型、图标、物品、配方、动作档及 Cook 目录。
