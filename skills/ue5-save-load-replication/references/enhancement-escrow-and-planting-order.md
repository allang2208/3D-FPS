# 强化暂存与种植快照顺序

适用于 FPSGAME 的工作台暂存、共享事务初始化和种植状态接收。来源：2026-11-08 至 11-10 的强化／种植修复；是维护经验，不是再次运行测试的授权。

## 实例归属与事务

- `EnhancementItem` 是每角色持久化暂存位，不是背包物品的可装备预览副本。放入后从 Items／装备槽移出，保持实例 ID、配件、强化、附魔及运行弹药状态；暂存记录不能与 Items 同 ID。
- 替换在同一快照中放入新武器、归还旧武器。背包满、占格不兼容或保存失败时整笔不发布，不先移除旧武器。取回保留双朝向插入尝试；关闭面板、原台消失或断线不隐式删除暂存。
- 按钮、右键和拖动都复用原权威事务。服务端复核当前暂存身份 `ExpectedBenchId`、库存版本、有效工作台与距离；提交成功后才改装备表现。拖动开始、预览和本地落桌动画不拥有物品转移权。
- 陈旧客户端上传或镜像不能覆盖已经存在的权威暂存。保存结果不确定沿现有冻结规则，不把不确定失败当成可安全重试的成功交易。
- 网络物品尺寸消毒先撤销摆放旋转，再与目录／实例原始尺寸比较，最后恢复朝向。直接拿摆放 2×3 和目录 3×2 逐轴取最大会把 M1911 扩成 3×3。迁移后检查两种朝向及幂等性。

## 共享模型初始化

`ColdSteelHarvestAuthority.cpp` 的共享世界数据只含采集字段，不能把它当完整角色档案交给全角色校验。构造合法中性角色外壳，再复制共享字段；不拷贝房主物品，不放宽访客或正式档案验证。否则共享模型创建失败会表现为下游工作台事务普遍拒绝，应先看模型初始化与 StationReach，而非盲改交易条件。

## 同版本快照顺序

- `PlantingRevision` 描述作物提交，不足以排序保存失败锁定／恢复：`bSaveBlocked` 可在同一作物版本改变。
- `SnapshotSequence` 为当前 UWorld 的权威发布序号；先拒绝更低作物版本，再在同版本拒绝旧／重复序号。允许更新的同版本状态锁定，也允许恢复时解锁，不能永久粘住失败标记。
- 序号是运行态，不写进世界／角色存档。换世界重置发布者；断线或上下文重置清空客户端镜像，允许重启后的权威序号。重复快照不能无端推进 UI StateSerial。

## 夹具与证据边界

空快捷栏必须同时满足当前版本和合法槽数，保存种子失败立即停止。初始化自动补发装备不能随意从种子中去掉，否则重连自动授予可能与返回物品占格冲突，看似交易失败，实为客户端拒收已成功的回执。先核对服务端提交和磁盘版本，不重复执行已成功交易。
