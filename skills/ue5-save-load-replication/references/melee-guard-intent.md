# 近战格挡轮次、动作互斥与破防归属

用于复用近战防御规则、处理迟到 RPC 和多执行器中断。战锤 2026-10-15 案例的源码与历史证据见工程 `Docs/Publication/WarhammerCombat20261015/README.md`；本参考不自动授权运行测试。

## 装备身份与动作身份分开

同一件武器可以多次抬挡。装备实例 ID 只能识别武器，不能识别当前格挡轮次。每次新抬挡生成独立 intent serial，松键携带对应 serial，服务器反馈携带它实际处理的轮次。

- 在匹配装备身份后才接受新序号，错误武器请求不能抢占当前合法序号。
- 旧抬挡不能重新打开已结束动作；旧松键不能取消新动作；旧拒绝和受击回执不能夺取新姿态。
- 已发生的权威体力支出与表现资格分开结算。装备切换或动作结束不使已提交的费用作废，但迟到表现不应重新播放旧动作。沿用现有可靠回执/去重合同，不把“旧姿态拒绝”当成“旧交易免单”。

## 两侧入口都要检查互斥

本地输入限制不能替代服务器门槛。按普通攻击、蓄力/重击、冲刺、上挑、旋风、快速近战、格挡、破防分别列出执行器与时间窗，攻击申请排除当前格挡，格挡申请排除权威攻击占用。

快速近战的迟到命中报告容忍窗不是额外后摇。查询“是否正在执行”时使用真正动作结束时间，避免尾部容忍时间阻止下一次合法防御。

缓冲连击会在上一动作结束的同一帧发出，服务器就绪门槛需要小容差，同时把服务器时钟起点放在就绪时间，不能让容差变成提前出手；拥有端的命中表现预测只影响动画，权威结算与确认回执照旧。战锤做法见 [战锤战斗合同](../../ue5-weapon-workflow/references/warhammer-combat-contracts.md)。

客机快速近战获准时，服务器要取消该 Pawn 的旧战锤接触定时器和占用。不要调用会重新读取 GameInstance 本地档案的通用输入中断函数；那可能把主机资源套到客机。直接中断目标组件，并清理其权威 ready 时间。

## 一个来源拥有破防姿态

复制的破防输入锁组件负责启动破防动画，RPC 只处理对应状态/费用，避免两条到达路径重启动画。破防自己的输入锁是预期条件，不应被普通 CanUse 门槛当成取消理由；死亡、失去表现资格、真正模态界面仍可中断。

受击动画仅能在仍持挡时插入。回执迟到但防御已经收回时，不切回保持/受击。

共享双手剑判定不代表战锤伪装成剑：保留独立的工具装备身份、修正属性和视模，由共享防御控制器选择对应播放接口。

## 证据边界与后台进程

- 隔离 World 中调用生产权威函数、使用独立客机影子档案、读取已保存动画和序列化状态，可以检查这些路径；它不包含真实网络传输、延迟、丢包、重连和旁观者音画。
- 分别记录伤害/体力权威、动作复制、第三人称握持、一次性特效和空间音效。已有旁观者动作路径不代表挥舞、格挡、弹反音效也已同步。
- 战锤历史检查为 NetworkAudit 52 项、ModificationAudit 103 项通过。真实双端测试与普通挥舞/上挑/旋风/快速近战/格挡弹反的旁观者专用音效仍未完成，不能写成“全部联机完成”。
- `UnrealEditor-Cmd.exe` 既可运行 commandlet，也可用 `-game` 运行无界面主客机。按完整命令行判断，不能把所有 Cmd 进程视作导入任务或残留。保留已有进程与资产现场；构建仍遵守加载 DLL 占用和批次互斥。
