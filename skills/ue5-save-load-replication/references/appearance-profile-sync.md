# 外观选择、整档镜像与物品回执

用于持久化性别/头型/发型经玩家档案同步的项目，尤其有全档上传、服务端镜像和库存差量回执并存的情况。FPSGAME 入口为 `ColdSteelPlayerState`、`ColdSteelInventoryRequests`、`ColdSteelCampfireRequests` 和 `FPSPlayerBodyAppearance`。

- 区分玩家拥有的外观选择、服务端玩家影子档案和远端表现状态。头型/发型持久化；服务端为对应 Pawn 读取影子档案并复制外观 ID；客户端按本地已发布目录重建。不能从主机 GameInstance 单例给所有客机取外观。
- 迟到的服务端整档镜像可能产生于性别切换之前。即使当前档案等于 `LastSentBlob`，也只表示最近发送完成，不表示该镜像已确认新选择。合并时保留本地最新外观字段，或采用明确的外观版本确认；不要只靠全档“干净”判断覆盖它们。
- 库存摘要通常不包含外观。库存相同的快捷事务若取消正在上传的整档，再把当前完整档案记为已同步，会吞掉刚改变的外观。库存回执只能确认它携带的字段。
- FPSGAME 的修复记录待上传与最近完整上传的头型/发型。库存快捷分支要求当前选择与已上传身份一致；否则先发送冻结档案，再走同一可靠 Actor 通道的物品意图。重建库存比较基线时，未上传的外观仍保持待发送状态。
- 心跳、物品、篝火等所有整档生产者必须记录对应快照身份；在最后一片发送时更新实际上传身份，不能临时取可能已经再次改变的当前选择。拒绝/重试的旧 Pawn 请求不能确认新 Pawn 的状态。
- 保留原来的服务器物品/货币/战斗权威边界。不要为了外观同步从客户端整档反写服务端资源，也不要为了两个外观字段每帧重新压缩档案或增加全目录加载。

用户要求联机检查时，覆盖：主客机选择不同身体、切换后立即操作物品、旧镜像跨切换到达、外观与装备不同顺序到达、晚加入、重连、死亡重生、队伍换图。分别报告源码追踪、完整本机构建、隔离逻辑和实际 socket/跨机结果。2026-10-24 的两个缺口已修改并完成 Editor/Game 构建，未据此声称真实联机通过。

发布共享宿主时先读仓库规则。公开基线缺少本机依赖，保存本次差量及确切前置散列，注明恢复顺序；不能把整份混合工作文件提交来补齐别人的未发布功能。发布记录见 `Docs/Publication/Kaitlin20261024`。
