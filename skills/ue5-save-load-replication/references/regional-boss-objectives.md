# 区域首领目标、边界闸门与联机追踪

FPSGAME 医疗区和生态区案例。读取现有 DungeonRunSubsystem、DungeonThemeEncounter、DungeonRoomGate 和 FDungeonSharedProgress；沿用共享框架，不新增 HUD 侧胜负判定。本参考不自动授权测试或启动编辑器。

## 分开共享进度与每位玩家的视图

同一服务器 RunId 持有各区域独立首领标志和递增 Revision。客户端只接收当前 RunId 的更新版本；拒绝旧轮次和旧 Revision，允许复制早于本地地牢装配就绪时先缓存。医疗击杀不能使生态目标完成。恢复、晚加入和新一轮清空必须覆盖新增标志。

HUD 按 Viewer 所在房间/相连走廊选择目标，以 Task.Id + InstanceId + Objective.Id 标识条目。不同路线的玩家显示各自区域目标，共享世界进度；玩家个人库存、商店和奖励记录不因此合并。首领死亡即可解锁，不把普通怪全部死亡作为隐藏条件，也不伪造整间清怪记录。

## 两端封锁与只进不出

区域包含主题房间及两端都属于该区域的内部连接走廊。门边界按实际外侧连接和作者法线识别，不能仅靠图深度判断来路；分支合流处方向可能反转。玩家整个胶囊越过边界后开始封锁，内部房门仍可通行。

外部队友入场只对其本人开放方向屏障，同时驱动可见门板；门板抬起不等于内部玩家获得退出权限。服务器控制屏障、门板状态和击杀后的两端统一解锁，客户端不能凭本地重叠改变通行权。AI 可开病房门与区域目标闸门是两种权限，不应混用。
