# 脚架请求身份与拥有者确认

处理架枪 RPC、切枪后迟到部署、加成偶发消失或取消后重新激活时读取。以下经验来自共用脚架组件，不把其单进程检查当作真实联机验收。

- **请求绑定实例与请求代次。** 只传枪型或支撑位置，无法区分切换前后的同型号武器。`ServerDeploy` 与复制结果携带 `WeaponInstance`；服务器开始时对照影子档案中的已装备实例，维持时同时比较定义与实例。拥有者确认还须匹配当前实例和本地请求代次。
- **拥有者确认不要与网络属性共用存储。** RPC 与属性更新可能交错。即使 `OnRep` 拒绝旧序号，底层复制字段已经被覆盖；若加成继续读该字段，旧属性仍能撤销新 RPC 确认。使用独立 `ConfirmedDeployment`，RPC／OnRep 共用接受函数，拥有者的加成从已接受状态读取。
- **接受结果不能复活已取消请求。** 除了代次相等，还要求本地请求仍有效；新一代开始清空旧确认，匹配代次的服务器拒绝或解除撤销预测。序号比较保留当前有界递增及回绕语义，不改成普通大小比较。
- **服务器按安装状态授权。** M24、PKM、LMG201 都检查规范化后的实际脚架槽，并处理生产工具占手。当前安装 ID 分别为 `m24_foldable_bipod`、`pkm_bipod`、字符串 `false`；LMG201 的 `false` 是已有目录 ID，不是布尔值，拆除 ID 为 `lmg201_no_bipod`。新增武器重新读其目录，不能仅按型号放行。
- **支撑由服务器重新解析。** 客户端仅提交有界接触点和朝向，服务器重新碰撞检查，不信任客户端组件指针，也不依赖远端没有求值的第一人称姿态。
- **命中到达时间不是开火时间。** 不要在命中回执到达时，仅因玩家当前正在收架／换弹而拒绝先前发射的在途弹丸；射击许可、弹药与伤害沿现有权威链路核对。表现复制成功不能证明这些事务已通过。

用户要求检查时，按范围覆盖新 RPC 后到旧属性、旧代回执、取消后迟到接受、同型号不同实例、序号回绕和各枪拆装资格。直接调用真实处理函数可验证这些状态分支，但传输、监听主机／独立服务器、延迟丢包、晚加入和远端画面必须另记实际覆盖。

更改 RPC 或复制结构后，服务器和客户端使用同版本模块。源码、正式 DLL、已保存资产和网络运行结果分别交付。

2026-11-03 历史结果：74 项单进程原生检查通过，其中新增 16 项针对确认与安装状态；无实际网络传输。几何与动作规则见[共用脚架部署](../../ue5-weapon-workflow/references/shared-bipod-deployment.md)。
