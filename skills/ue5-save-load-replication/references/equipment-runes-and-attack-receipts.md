# 装备符文与攻击提交回执

用于已有近战改造的联机接入与用户授权的排错。遵守后台工作和不主动测试规则；以下覆盖清单不自动授权运行游戏。

## 远端材质按语义重建

UE 持久材质指针不能保存 MID 的选项、遮罩、颜色和 Overlay。装备描述记录武器定义、符文 ID、承载槽及实际局部尺寸；从该 Pawn 的权威／影子档案读取，不能取 GameInstance 的主机装备。观察端调用持握和预览共用的符文应用入口，再恢复尺寸，覆盖原生符文材质与叠层两条路径。

纯符文切换也进入装备缓存键，否则模型没换时远端不重建。原生自带刻纹与空改造状态分别处理，别把两者都当“没有符文”。新增复制 USTRUCT 字段使用正常 UHT／Editor／Game 构建；Live Coding 不能证明旧结构实例已更新。

## 消耗确认独立于动作确认

服务器接受攻击后返回实际扣费，而不是让客机按当前武器重新推算。按单调攻击编号去重；动作已结束、取消或换武器时，仍应消费此前已接受攻击的回执。动画反馈可以忽略过时动作，已提交资源不能一同丢弃。监听主机不再次消费客机回执。

武技提交回执带消耗、冷却剩余／总时长、单调修订号和服务器时间；先按服务器时间折算剩余，再交给既有档案镜像合并。旋风在起手提交，升龙在实际释放提交，触发点不同。共享档案合并仍负责旧上传、重连和资源账本，单个攻击回执不能替代整个协议。

## 持续刻印与双段攻击（2026-10-23）

- 持续数秒的目标刻印作为有界复制状态保存：武器实例、目标引用、相对附着点、服务器开始/结束时间放在同一快照中。新相关或首次建立通道的副本从当前状态恢复，不能依赖过去的不可靠 Multicast。瞬时命中闪光仍可使用短期表现事件。
- RepNotify 先置重建标记；苏醒属性、武器实例或目标引用晚到时继续等待。取消/到期/卸头/死亡由服务器移除状态并同步。完成事件早于移除属性到达时，保留完成尾迹，避免旧刻印快照再次覆盖它。
- 双段提交的每个计时回调核对当前实例、攻击编号与出招配件配置；缓存布尔值不能证明当前仍装备该改造。用独立接触序号区分两段，用“目标＋序号”回执阻止消耗后重放；资源确认继续独立于表现取消。
- 用户要求真实联机检查时，测试首次通道前已有刻印的恢复、重复可靠释放、客机回执与主机档案隔离。记录是否真的运行 NetDriver/UDP、是否抑制世界身体、是否使用原始伤害夹具；不能用这些结果代替第三人称动画或特效画面验收。

## 证据与边界

只有用户要求检查时才按实际改造列出普通、蓄满重击、冲刺、旋风、升龙以及拒绝、重复、延迟回执和换武器情况；覆盖本地、服务器客机影子档案与观察者重建。数值测试与真实传输分开记录。

2026-10-15 战锤案例的 47 项目录检查、103 项原生隔离回归及 Game／Editor 构建成功；隔离回归实际执行权威方法、结构回读和 MID 重建，但没有跨进程网络传输、延迟／丢包／重连或画面验收。不要用 RPC 函数直接调用通过来声称双端联机通过。源码入口为 `FPSBodyRuneVisual`、`ProductionBluntAuthority` 与 `WarhammerModificationAuditCommandlet`，发布说明在仓库 `Docs/Publication/WarhammerMods20261015/README.md`。

## 持续旋风与 CMC 的双通道顺序（2026-10-19）

- 施放请求和命中请求走同一 PlayerState 有序通道；CMC 移动包可能先到。移动先到时等待后续累计移动重试，不把该序列永久标为拒绝。服务端只授权已接受的施放，匹配移动序号、武器和角色，锁定起手方向，用已过时间及有限容差限制位移。
- 群体攻击以施放编号、冷却和目标集合限频，不使用枪械的逐命中 token 桶。十个同时命中的合法目标不能被六枚 token 截断。武技标记须排除枪械弹速残留，否则可能走投射物分支绕过墙体遮挡。
- 客机 ApplyHit 转发后返回零，写在其后面的眩晕、击退、易伤和修炼不会自动出现在服务器。由权威确认命中入口结算副作用，结束按实际命中一次结算经验；不能在客机再奖一次。
- 剑系旋风复用既有累计体力账本 `UppercutStaminaSpent`，保留字段名以兼容存档。多个武技消费必须共用单调累计值，旧回执不得回滚新消费；动画已结束仍合并已接受的扣费。冷却上传不能覆盖服务器提交值。
- 起手 CommitState 可能替换物品存储；提交前复制需要的武器身份／配置，不在提交后解引用旧 Item 指针。结束、拒绝、死亡、换武器、退出和换图都关闭施放授权；确认扣费与动画取消分别处理。

当前入口 `ColdSteelWhirlwindAuthority.cpp`、`FPSMeleeMovementNetwork.cpp`、`RuneSwordWhirlwind.cpp`。本轮 38 项隔离检查没有真实 NetDriver、客机进程或地图 BeginPlay；结构反射回读也不是网络包传输验证。

## 共用蓄能符文与观察者（2026-10-28）

不要用客机任意上报的修炼编号作为符文蓄能真相。普通／冲刺、快速打击、升龙、旋风和重击分别绑定服务器已接受的动作记录；重建每个目标的伤害快照时复用本动作的符文编号，不生成额外蓄能。修炼统计与符文身份可保留各自流程。组内双方刀刃、多个目标共享动作身份，状态施加另按目标去重。

持续激活用实例集合、装备修订和服务器结束时间复制，观察者由当前快照恢复，不能依赖过去的一次 Multicast。能量条只属于持有者，但需要其他玩家看到的刀光和手臂粒子不能只发 OwnerOnly。观察端没有本地库存或第一人称手模，按实际复制的世界武器实例、左右手、模块槽和符文材质绑定；装备与状态乱序时继续等对应部件，不从主机档案借配件。专用服务器不创建表现对象。

材质参数经过运行时 MID 或天气层时检查实际父材质。只以字符串加载的 HUD、粒子及表面目录要登记 Cook；编辑器已落盘与打包可加载分开记录。霜鸦 57 项后台隔离检查包含 23 项新增符文检查，均非实际 UDP、双客户端、丢包／重连或画面验收；不因整理发布重跑测试。
