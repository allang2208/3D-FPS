# 引擎与编译问题记录

仅按当前报错采用对应方法，读取目标工程实际头文件和日志；不保留“UE5.6–5.8 全部接口稳定”的承诺。原因：版本、访问权限和 Python 暴露都可能改变，旧错误清单不能替代当前签名。

- Unity 合并后名称冲突时，定位文件级 `using namespace` 或相同局部符号，优先限定名称和保留必要导入。原因：关闭 Unity 只能避开组合条件，不能修复源码的名称泄漏。
- UHT 参数冲突或私有物理字段报错时，按继承成员和实际访问权限选不同参数名、公开 setter 及所需类型头。原因：反射与 C++ 可见性共同约束合法声明，不能按旧代码直接写私有字段。
- 蓝图缺少类或接口时，读取真实类型、函数用途和已有反射元数据，再补必要声明并完成所需构建。原因：并非所有缺失都由同一种 specifier 引起，重建工程文件也不是通用修复。
- 包含环或链接缺符号时，区分定义缺失、目标未编入和循环依赖，再将实现依赖留在适合的源文件。原因：前置声明只能解决不需要完整类型的引用，不能产生缺失定义。
- 属性未复制时，读取反射标记、生命周期登记、拥有者复制状态和实际值变化；OnRep 未执行还需考虑首次初始化时点。原因：复制是多阶段路径，单加 DOREPLIFETIME 不能覆盖全部前提。
- RPC 被忽略时，读取拥有者、请求方向和服务器实际前置条件。原因：调用包装函数不代表请求已在正确权威对象执行。
- GameplayTag 未生效时，定位实际 tag 名和注册配置，沿现有错误处理修正。原因：标签缺失有明确数据来源，不应凭历史故障预先增加启动检查或兜底功能。
- CDO 或成员布局异常时，读取反射修改及依赖重建状态，完成必要构建；只有明确的陈旧产物证据才处理对应对象。原因：追加成员不能代替重编译，默认 Clean 或删除整份 Intermediate 会扩大无关成本。
- 运行逻辑使用可进入对应目标的 API；编辑器工具和反射查询仅留在所需宿主。原因：编辑器模块存在不代表打包运行可加载它。
- TObjectPtr 与裸指针的条件表达式用显式类型或清楚的分支，组件 setter 参数避免遮蔽继承成员。原因：隐式转换与同名成员会制造编译歧义或警告升级错误。

历史定位例包括 `GetSkeletalMeshAsset`、`FHitResult::BoneName`、`FBodyInstance::SetMassOverride` 和 `Engine/DamageEvents.h`；实际采用前读取当前目标接口，不把示例当版本迁移全表。原因：历史报错的修复范围小于完整引擎兼容合同。

必要构建照常完成；用户未要求时不追加运行、回归或编辑器验收。原因：构建输出与游戏行为属于不同交付证据。
