# C++ 类编写参考

- 沿用现有类与模块边界，仅在需求确实需要新类型时新增文件。原因：通用模板不应把小范围修改变成新的抽象层。
- 头文件只包含声明所需依赖，可前置声明的外部类型使用前置声明。原因：公共包含关系会传播到所有使用者，增加不必要的模块耦合。
- 仅在反射、编辑器或序列化确实需要时使用 UCLASS、USTRUCT、UENUM 和属性标记。原因：反射暴露会形成资产与类型布局合同。
- UObject 引用沿用工程已有的生命周期与 GC 管理方式；反射成员中的强引用按当前引擎约定使用 TObjectPtr。原因：裸指针的存活时间不一定与被引用 UObject 相同。
- 源文件先包含自身头文件，再包含实际实现依赖。原因：声明缺失的依赖不应被其他偶然包含的头文件掩盖。
- 按入口的真实对象与 World 生命周期处理可空状态，不为每行代码增加猜测性防御。原因：初始化、退出和异步回调有不同有效范围，约束应来自实际调用者。
- 改动现有函数即可完成时不要求交付新 .h/.cpp 对；需要模块依赖调整时明确实际使用点。原因：文件数量不是完成标准，新增依赖需要由真实类型使用支撑。
