# 复制与请求边界

- 明确需要复制的持久状态，并沿当前载体登记对应反射字段；需要客户端刷新时使用已有 RepNotify 或等价消费入口。原因：字段复制与表现刷新是不同阶段，并非每个字段都需要额外 OnRep。
- 客户端请求沿现有拥有者入口提交，服务器在修改状态前按真实资源、身份与阶段判断资格。原因：客户端输入不是权威状态，延迟期间条件也可能变化。
- 根据消息语义选择可靠性；关键低频事务与连续高频姿态分开，不强制所有请求为 Reliable。原因：可靠队列会保序重传，高频可替换状态不应堆积阻塞后续消息。
- 初始化后消费已经到达的状态，持久结果可供迟加入恢复。原因：RepNotify 可能早于依赖就绪，一次性事件也不会自动补发给新玩家。
- 用户要求排查时区分字段未复制、值未变化、依赖未就绪和只改客户端等路径。原因：相同可见症状可能来自不同网络阶段，文档不自动授权运行联机测试。
