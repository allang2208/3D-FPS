# 快速近战身份与实际联机检查

快速近战动作必须同时绑定动作序号、发起 Pawn、当前主/副手槽位、物品实例及定义。命中结算再次比对；换主手、换副手或换同型号的另一实例后，旧序号不能继续授权。结束动作清除绑定。重复请求不得替换已接受动作的期限、目标去重集或费用记录。 原因：异步消息可能在动作结束或装备切换后到达，只有匹配当前身份才能修改现态。

范围标记、物理面板替代公式、目标去重、遮挡与击退在服务器用影子档案复算；不能信客户端传入伤害。主机与客机修炼归属分别确认，不将客机费用写进房主 GameInstance 档案。 原因：客户端表现与服务器结算可能重复经过入口，权威路径必须保持一次有效事务。

用户要求真实联机检查时：

- 使用实际 UDP 主机/专用服务器与客户端、隔离档案及既有批次互斥；记录真实网络模拟参数和双方退出码。方法级 commandlet 不能替代这条传输链。 原因：共享编辑器串行处理操作，现有桥只能保护通过该桥提交的批次。
- Controller RPC 带来的 Actor 引用可能尚未解析。测试设置在引用可用后才开始，周期重发设置保持幂等；不能把空观察者误判为增益没有复制。 原因：未解析引用是网络初始化条件，设置未送达不能被解释为增益复制失败。
- 无地板空地图内，客户端模拟代理仍可能落下，即使服务端角色被冻结。两端目标位置和移动组件按案例复位，避免测试场差异被误诊成距离/命中漏洞。
- 首次激活动画可能异步加载。就绪等待与效果执行期限分开，记录具体门槛；调整测试加载预算不得放宽身份、扣费、回执序号与到期断言，也不把等待变成生产进场阻塞。 原因：异步消息可能在动作结束或装备切换后到达，只有匹配当前身份才能修改现态。
- UE 编辑器已运行时保留其进程。审计夹具可用独立输出；仅替换检查对象的增量链接必须来自同一成功构建/ABI，不把混合对象结果当公共源码独立构建证明。 原因：测试输入需要遵守真实产品条件，修改生产规则迁就夹具会改变用户行为。

案例：`Docs/Publication/ConversationCombat20261109`；2026-11-08 六组 NullRHI UDP 检查通过，不包含互联网条件、画面或音频验收。

## 队友看到的装备与快速近战

监听主机的第一人称镜片可能已换上动态玻璃，并临时隐藏模型上的准星。采集第三人称装备时，按组件、网格资产、材质槽和当前覆盖材质匹配本地绑定，取回开镜前的原材质。解除绑定或切枪时清除对应记录，让枪镜和弓镜都能保留玩家装配的表面。

柄尾打击与尖刺锤座前刺分别传递动作身份。第三人称按对应动作时钟、击停与恢复时点采样双腕和武器；收到显式击停时保留零速，避免按相邻网络快照反推速度造成穿过接触帧。

## 装备型消耗品的近战回执

以手持火把为例，客机预测普通攻击时，服务端在接纳出手序号时扣一次体力，挥空也消耗；重复请求沿用已处理的序号。快速近战还要核对当前角色、双手装备实例和实际出手侧。换弹、食物和药水的动作占用应在服务端双向裁决。

伤害与灼烧由服务端结算。敲击反馈回传出手序号和命中位置，持有者只向对应的动作播放反馈。触墙火星可本地预测，服务端核对出手、距离及遮挡后，每次挥击最多广播一次。

双持物品各自记录剩余寿命，存档同步按实例归属。客机的燃料推进复用角色的脏存档检查点，服务端保留已记录的消耗。隔离角色调用能检查动作互斥和重复扣费，延迟、重连及旁观者表现要以实际联网记录判断。
