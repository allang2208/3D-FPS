# 存档结构参考

- 沿用系统现有快照和容器格式，明确持久字段、稳定键及版本迁移。原因：旧档和现有消费者需要继续使用同一数据合同。
- 保存从当前运行状态构造快照，恢复按拥有者与依赖顺序应用；不持久化纯临时网络缓存。原因：短生命周期对象不能通过读档恢复成新的权威状态。
- 对读入数据沿用实际格式的数量、身份及范围处理，返回已有的成功或失败语义。原因：文件可解析不等于其中对象仍可在当前世界恢复。
- `BuildSaveData`、`RestoreFromSaveData` 与 `USaveGame` 是示意命名，接入时读取工程实际入口，不要求补造这些接口。原因：模板不应创建第二套与现有 JSON、二进制或影子档案并行的持久化系统。
