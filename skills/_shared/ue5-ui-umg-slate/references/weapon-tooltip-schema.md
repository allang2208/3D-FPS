**2026-10-09 展示范围更新**：默认仅写直接属性，不展开二段／三段攻击、附加伤害拆分或派生数值；只有用户明确要求时补充。下文分项名称与伤害组成规则只用于数值口径或明确要求的详细展开，不能据此自动生成分项行。见 [详情与介绍标准](../../ue5-weapon-workflow/references/attachment-detail-presentation.md)。 原因：同一个数值在不同区域重复或换口径展示会产生歧义，详情需要保留明确的数据来源。

## 固定结构

沿用现有冷白鉴定卡：物品标题与元信息 → 核心属性及数值条件 → 改造与附魔 → 详细参数 → 物品说明。详细参数先复用核心摘要，再显示物品信息、战斗参数及类型专属机制；同标签同值只显示一次。无对应机制不造字段，例如弓没有弹匣、空仓换弹。 原因：同一个数值在不同区域重复或换口径展示会产生歧义，详情需要保留明确的数据来源。

- 枪械六项：武器总伤害、攻击间隔（连发武器用组内射击间隔）、弹匣容量、有效射程、普通换弹、空仓换弹。
- 弓六项：武器总伤害、拉弓耗时、搭箭耗时、最大飞行距离、体力消耗、开镜耗时。
- 双手剑五项：武器总伤害、攻击间隔、体力消耗、最大攻击距离、格挡伤害减免。
- 双手锤四项：武器总伤害、攻击间隔、体力消耗、最大攻击距离。与剑共用近战摘要顺序、缩略／固定详情布局；没有格挡的锤不生成格挡项，距离说明使用普通挥击范围。攻击与强化公式仍在详情，三连击／蓄力砸地等独立机制由目录 `traits` 进入“特殊性质”，不在背景或核心摘要重复分段伤害倍率。案例见工程 `Docs/UI/warhammer-tooltip-format-20261014.md`。
- 工具四项：武器总伤害、攻击间隔、体力消耗、最大攻击距离。采集参数单列；不冒充战斗属性。

## 唯一字段表

代码名称统一取 `Source/FPSGAME/UI/ColdSteelWeaponText.h`；浮窗摘要、详情、改造总览、改造件明细和强化预览使用相同常量。不要在渲染层临时替换名称，也不要按武器类别重新造一份同义名称。 原因：各展示入口共用术语才能保持含义一致，渲染时替换同义词会让用户误以为是不同指标。

| 固定名称 | 数值含义／单位 |
|---|---|
| 武器总伤害 | 当前条件下基础物理、附加物理、附加魔法之和 |
| 基础物理伤害 | 经过现有角色、强化、改造等计算的基础物理分项，不等于目录原始值 |
| 附加物理伤害／附加魔法伤害 | 来自共用伤害评估；有对应分项才显示 |
| 基础伤害 | 改造倍率作用的基础分项；不能把它写成总伤害增加同样百分比 原因：派生值需要从同一基础和乘区计算，复用已经缩放的结果会重复应用加成。 |
| 攻击间隔／开镜耗时 | ms，整数；“挥砍间隔”“进入 ADS 耗时”不另作名字 |
| 体力消耗 | 当前动作条件下的消耗；“满拉”“含重击”移到数值条件 |
| 弹速 | m/s；枪弹和箭矢使用同一名称 |
| 弹匣容量 | 发；不用“弹容量”与其混写 |
| 弹药／弹种效果 | 枪弹与箭种共同使用 |
| 弹药修正后伤害 | 武器总伤害 × 当前弹种伤害倍率，仍未计目标防御与暴击 |

所有数值保留现有运行评估来源，不调整武器平衡。伤害详情由同一 `DamageRows` 按“总伤害 → 基础物理 → 附加物理 → 附加魔法”生成；公式说明行用“伤害组成”，不再次占用总伤害字段。名称、单位、公式和计算范围必须一致。 原因：总伤害、分项和公式说明承担不同显示角色，复用同一评估与命名才能避免重复口径。

## 条件与比较

- 公共属性名不夹带武器专属前缀。弓写“武器总伤害”，数值条件明确“满弓单箭，已计蓄力倍率”；枪械按单次射击、近战和工具按普通单次攻击。
- 弓蓄力阈值与倍率从 `ColdSteelBow::MinimumFireDrawFraction / DrawDamageMultiplier` 生成详细说明，不能把满弓数值误说成未蓄力基准。 原因：拉距阈值与倍率有实际公式，满弓结果不能当作未蓄力基础再计算。
- 明确哪些因素未计入：弹种、暴击／要害、目标防御、距离衰减按实际机制说明，不能杜撰伤害加成。 原因：每个实际命中目标和部位都有对应结算上下文，复用错误命中数据会改变伤害结果。
- 有效射程（全伤害范围）与最大飞行距离（箭矢飞行上限）含义不同，保留各自名称及比较键；拉弓耗时不冒充攻击间隔，连发组内间隔也不直接与单次攻击间隔相比。
- 伐木伤害对树木生命值结算，保持在采集参数。矿镐按有效命中次数采集；不要为表面统一而合并这两条业务。 原因：伐木与采矿分别依赖生命伤害和有效次数，合并会改变实际采集进度。
- 改造汇总按所属类型读取 Gun／Bow／Melee／Tool 的真实评估，弓不能落入枪械分支。 原因：不同武器族使用不同评估合同，错误分支会遗漏弓或工具的专属参数。
