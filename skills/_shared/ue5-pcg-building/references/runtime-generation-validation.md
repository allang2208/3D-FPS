# 用户指定的运行时生成检查

- 仅在用户要求 PCG 检查或测量时选择相关场景，不把本页作为每次制作后的必跑流程。原因：生成代码与运行验收的授权范围不同。
- 记录实际输入、种子、风格、源范围和更新方式，再比较生成结果。原因：同一 seed 只有在输入顺序和规则一致时才有可比性。
- 用户要求局部性检查时，观察生成源移动、半径缩小和局部风格替换影响的区域。原因：范围和清理生命周期决定旧实例是否残留以及是否误改相邻区域。
- 用户要求性能测量时记录地图、视角、平台、可见数量及实际帧时间。原因：旧模板中的 150 ms、8 ms、50 Actor、2000 实例并非项目确定的验收门槛。
- 删除上述固定阈值及无条件更改调度类的模板要求；预算沿用该任务真实目标。原因：硬件、图复杂度和交互对象需求不同，统一配额可能改变现有生成行为。
- 只对实际使用的碰撞、导航、分区和交互路径提出结论。原因：静态点集正确不能证明运行时通行和权威对象生命周期也正确。
- API 名称及刷新入口读取当前 PCG 插件，不保留跨版本“最小可运行模板”的保证。原因：调度对象与可用签名随工程安装版本而变化。
