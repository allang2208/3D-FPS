# 领域任务与工具能力

- 先选择当前项目实际存在的领域技能，再按本次操作读取工具 schema；不按旧工具白名单决定任务能否执行。原因：技能描述工作范围，工具名称与能力由当前桥暴露。
- 参数已知的操作沿用现有批次接口；动态依赖可使用编辑器内脚本。原因：前一步返回的对象和路径需要真实传递，固定的专用工具优先级不能解决依赖。
- 后台文件制作与必要构建不为连接 MCP 而启动编辑器。原因：此类产物可以直接落盘，接入工具不是开始工作的前置条件。
- 检查、测试、截图和运行只按用户明确要求启用。原因：它们出现在能力表中不代表每个领域任务都需要执行。

| 任务 | 按需使用的能力 | 保留原因 |
| --- | --- | --- |
| 蓝图 | 目标图读取、节点与引脚编辑、保存和必要编译 | 操作依赖真实节点签名。 |
| C++ / 架构 | 文件编辑、实际模块依赖读取、命令行构建 | 纯源码任务通常不需要编辑器世界。 |
| UI | 现有布局、样式和绑定源码；必要资产编辑 | 数据与输入归属需要沿用现有界面架构。 |
| 存档 / 联机 | 实际序列化、复制、请求与回执入口 | 运行状态和磁盘数据有不同生命周期。 |
| 世界交互 / PCG | 明确目标对象、生成参数及资产保存 | 修改范围必须对应实际世界对象与生成边界。 原因：生成范围与更新预算直接决定资源占用，全局重建会扩大局部修改的影响。 |
| 模型 / 材质 | 外部作者工具、适用后台导入；已有编辑器内的建模能力 | 制作源与保存资产需要明确交接。 |
| 用户指定排障 / 性能工作 | 相关日志和已有数据；明确授权的采样工具 | 工具输出只能支撑其实际覆盖的结论。 |
