# 技能维护与历史资料

- 共用工作流只在本机个人技能目录维护；工程专属增补继续放工程文档。原因：共用规则需要单一维护源，项目差异也不能被全量镜像覆盖。
- 工程入口使用仓库内的发布快照导航；修改共用规则仍回到个人源，只有用户授权发布时更新快照。原因：快照负责换机阅读和版本恢复，不应成为第二套手工维护正文。
- 先按功能列出最多三级范围和精确文件清单，再删除确已失效的规则；保留操作给出具体原因，原文已有明确因果则沿用。原因：按主题确定范围和理由，才能区分过时指令、有效约束与仅仅相似的文字。
- LOCAL-HISTORY 只保留历史主题、来源和失败/完成事实的入口；原始快照标明日期及历史性质。原因：历史授权、旧版本和旧“当前”不能自动指导新任务，但恢复证据仍有价值。
- 相同正文可以收敛为入口，不同项目增补单独保留；公开链接使用仓库相对路径。原因：相同规则多处维护会漂移，本机绝对路径又不能供远端读者访问。
- 发布快照按实际引用闭合范围导出，清单记录源路径、源散列和导出散列；同时保留被历史索引实际引用的文本。原因：只推送入口会遗漏个人目录中的正文，只有可追溯的完整依赖才能换机恢复。
- 一次性编辑器、分组草稿、重复日志和原件备份按任务清单归档到 trash，正式规则、恢复依赖与最终回执保留。原因：按用途归档能减少活动目录噪声，也不会丢掉可恢复输入；文件日期或名字不能单独证明无用。
- 案例参数和工具名只说明当时状态，实际 API 读取当前项目和工具；“已编译”“已导入”“用户认可”“已测试”分别陈述。原因：制作阶段与版本不同，旧证据不能替代本轮结果，也不授权默认探针或测试。
