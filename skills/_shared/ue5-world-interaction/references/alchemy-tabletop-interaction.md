# 炼药台的器具交互与连续表现

适用于 FPSGAME 坩埚分支及类似的台面制作小游戏。配方由手册传达，药液颜色、融合程度、沸腾和仪表提供过程反馈；状态栏保留必要信息，不把每一步正确操作都变成按钮提示。初级配方只保留能让玩家理解原料、火候和搅拌的必要操作，复杂步骤留给明确需要它们的配方。

- 交互目标、实际移动网格、倒出位置和悬停说明使用同一个器具身份。添加剂从对应原料容器倒出，成品瓶只用于装瓶；不要因为两者都像瓶子而共用错误的移动网格。按当前可操作性显示金色描边及短浮窗，禁用时说明原因，装饰物不冒充可点击目标。
- 搅拌拖动分为起始命中与持续捕获。按下时必须命中坩埚；捕获后用投影锅面的中心和轴计算连续转角，移出锅沿仍继续。中心保留死区，角度跨正负半周正确展开；松键、失焦、退出和目标失效都停止输入。持续输入按时间累积并限频提交，不能随鼠标事件频率发送可靠 RPC。 原因：视角和投影决定可见结构，方向未对齐的图无法作为同一对象的直接比较依据。
- 火力旋钮左右键沿同一档位表正向和逆向移动；标签、旋钮姿态、火焰和温度变化读取同一权威状态。仪表探针实际伸入液面，读数绑定真实温度；没有药液时显示无读数，不能把固定数字烘焙到模型上。 原因：旋钮、火焰和仪表需表达同一真实状态，固定模型数字不能反映温度和液体存在性。
- 倒入和装瓶用共同的动作时钟驱动容器姿态、嘴口、流束、瓶内液面与回收。流束起点取倾斜后真实嘴口，终点进入瓶口内部；考虑流体飞行延迟后再提升瓶内液面，收流、滴落和放回分别缓动。不要只把一条直流束连到静止瓶子上。 原因：姿态、机械事件与命中必须引用同一进度，分别累计会在变速和停帧时错位。
- 水面优先沿铁匠台既有水体材质和动态参数接入；瓶内液面与外层玻璃分别处理深度和透明排序。流束段、滴粒、蒸汽与气泡使用有界池和已有调度，不为改观感额外叠加一套无预算模拟。 原因：生成范围与更新预算直接决定资源占用，全局重建会扩大局部修改的影响。
- 台面网格、命中区域、流束接口和文本仪表共用作者生成的布局常量；不要分别手填近似位置。书本与器具的加载失败要结束准备状态并给出原因。 原因：共同布局常量保持视觉与交互对齐，失败结束准备状态才能避免界面永久等待。

当前代码入口为 `Building/AlchemyTabletopInteraction.cpp`、`AlchemyTransferVisual.cpp`、`AlchemyBottlingMotion.h`、`PotionWorkbenchVisualComponent.cpp` 与 `UI/ColdSteelAlchemyTabletop.cpp`。进入页数据与批次操作分别参考 UI 技能的 `product-preview-readiness.md`、C++ 技能的 `paid-workpiece-quality.md`。
