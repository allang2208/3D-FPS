# 生态组合、光照与运行成本

## 以两个主题组合七个生态层

正式关卡同一区域的 `SurroundingForestPCG` 持有丘陵资源，`RoadLandscapePCG` 持有道路资源。按主题来源分发已烘焙的点，记录稳定种子、原始位置、素材槽和所有者。普通点在本图按距两条路心 13.3 米的道路带分配，沿路倒木和林内木料分别保留来源，池岸及岸草归丘陵。R30 全生态主图和精选组合可在隔离宿主查看，正式地图只挂两主题，防止同一地块重复生成。

- **Trees／乔木**。用原树位、稳定格子和种子选择同生境树型。按最终坡面支撑和根盘范围埋根，保持树干大体竖直。风权重以根为零，经树干至枝叶递增。鹅耳枥等装饰树走实例，黑杨、山毛榉等可采伐树沿用资源身份、树干碰撞、砍伐掉落、树桩、幼树和成熟链，避免同位再放装饰树。
- **Shrubs／灌木**。依林缘和林下遮蔽变化成簇分布，石头与草可共生。检查枢轴、风动顶点权重及实际材质槽，整株上下浮动先修根部权重。
- **Grass／草类**。用世界地表遮罩保证所有适生坡面连续覆盖，近景流送细草，再用轻量分区 HISM 补轮廓。树下连续降低密度，避免树盘硬切。石块、枝条和灌木不排空草层。路肩用连续随机边界及概率渐变，路心、积水、作业面和露岩按实际占地退草。当前补充网格为 `SM_RainforestGrassLow` 配 `MI_HillsGrassLow`；R26 的 `SM_ForestMeadowCrown` 宽叶草在 R27 已退役。
- **Rocks／岩石与碎石**。按足迹、坡向和土深从石种池选择普通岩块、裸岩架、苔岩架及坡脚碎岩。岩架嵌坡，大石控制间距和总量，小碎石聚在堆积区。装饰碎石使用无碰撞、无投影和无光追的实例。可采石块沿用玩法所有权。
- **Deadwood／枯木与松枝**。林缘偏倒木与落枝，林内用苔木段、木桩。长木按两端及中段支撑和坡度复核落点，保持行走带可通行，细枝间距与大木密度分开控制。
- **Floor／林床**。分别控制林床网格、苔斑和泥斑贴花的密度及投影。路肩落叶由两侧概率场和图集直接绘入地表，可随天气变湿；逐叶 Actor 会扩大提交和更新成本。
- **Wetland／湿地**。从终版高程找能闭合蓄水的洼地，经溢流标高、坡度、间隔和保护区筛选，再按目标预算选池。同步烘焙水面、湿岸、莎草和玩法水深。R28 在这张图把上限从 6 调到 12；扩大数量时先核对有效候选和上限，两者都会限制结果。

使用工程已配置的 UE Python 制作宿主，并将 `Tools/WorldGeneration/ForestVillage` 加到 Python 搜索路径。配置和操作示例如下。

```python
import landscape_themes as themes

road = themes.preset("道路景观")  # 读取注册表，不写包
themes.build("道路景观")         # 读取该主题点集，重建组件并保存正式地图的制作副本
```

修改点位算法后先用 `landscape_theme_points.py` 按主题导出数据，再用 `themes.build(主题名, source=该主题目录)` 装配。两边的输入都要换时调用 `themes.build_all()`。只调材质、雾或落叶图集走各自入口，无需整图重烘。生态图按资源族分页，当前烘焙器每页 24 路，页满在本层续页。63 是此版本单上游节点的动态引脚裁剪限制，判断规模还要看点数、实例数、生成时间和内存。增新素材时登记来源、变体槽及现用材质绑定。

后台直接执行主题脚本时，`FPS_LANDSCAPE_THEME` 选择中文主题名，`FPS_FOREST_THEMES_SOURCE` 可指向隔离工作副本的点集根目录。走导入流程前按工程存储规则让将要写入的地图、图资产和数据页在宿主里各有可写副本；生产回写登记这些包、生成配方及上版恢复位置。

## 昼夜、天气与林雾

正式图由现有 UDS 和天气桥统一驱动太阳、天空、湿润度、基础高度雾与时间。把布光保留在独立摄影样板，只在正式地图的流式子关卡上下文移交光雾所有权；编辑器打开正式图和开始 PIE 是两个不同入口。处理重复光源或 UDS 转换提示，应在生成与加载处处理冲突 Actor，保留样板单独打开的原布光。

先定时刻、朝向和角色眼高，选一处背光林缘与一处林间空地。用该时刻的太阳方向看树冠能否投出断续光斑，用天光使暗部树根与道路可读，再以基础高度雾拉开中远景。晨间光束需要冠层缝隙、入射角和局部介质同时成立。若同机位白昼过亮，先单独对照曝光与太阳、天光的响应，再调雾；摄影样板的曝光补偿、镜头与离线采样属于作者机位。

本图晴天从样板读取雾密度 0.02、起雾 0 米、垂直衰减 0.2、体积散射分布 0.2、消光 1，R22 近景体积距离 60 米，远山交给高度雾和天空大气。按实际树位、坡向、洼地与池岸选局部雾，避开门槛、村中、路心和采石工作面。清晨 05:30–06:30 较浓，18:30–20:00 较薄；干燥白天保留基础雾，重雨和风压低局部雾，雨停后跟随地面湿度衰减。数值属于这张图。其他地图先读自己的样板参数、照明尺度和天气曲线。

查责任链时，从 `Source/FPSGAME/FPSUDSHillsAtmosphere.cpp` 追正式图接管，再到 `WorldGeneration/ForestVillageMistComponent.cpp`（相对 `Source/FPSGAME`）看选址、时段和本地更新。隔离基础雾与局部雾可在获准的场景检查中使用 `fps.Hills.ForestMist 0` 与 `fps.Hills.ForestMist 1`。保持同机位、时间、天气和曝光比较前后结果。

## 联机和性能按职责处理

- **服务端权威**持有世界身份、资源消耗、树木生长时钟、交互水深及客机附近需要的树干碰撞。站立点、变体与采伐身份稳定；重新生成、晚加入、重连和旧存档读取走同一条恢复路径。资源时钟单独同步，状态变动再发资源账本。服务器能独立为远离房主的客机提供碰撞，渲染半径按本地视点选择。
- **视觉实例**以世界种子、确定排序和保存的点集重建。近草流送、细草补充和全图地面覆盖各自负责一个尺度。远端小草和碎石优先关碰撞、阴影、光追与风动，保留地面连续性；分区 HISM、屏幕尺寸 LOD、遮挡和有限材质槽一起控制成本。局部雾按视点激活与平滑更新，专服跳过纯表现组件。
- **用户要求验收时**，固定同机位、FOV、时间、天气、分辨率与画质，在村门、路堑、林坡分别记录预热后的总帧和 GPU 中位／P95、阴影耗时和显存预算。草是否成片要看远坡实际画面；局部雾组件数仅证明创建。联机按隔离存档比较主客地形／碰撞、远端客机砍树、时间天气、重连及版本错配。无渲染联机测试不能给出客机帧率。交付注明实际采样条件与未覆盖项。

## 从参考林地扩展装饰

- 逐一核对参考图里的 PCG 组件、Landscape Grass 和独立摆放的 StaticMeshActor。以实际网格、材质覆盖、角色尺度、朝向及足迹建立对应。FPSGAME 样板里的两款浅色花岗岩与苔岩巨石来自独立 Actor；只导出 PCG 点会漏掉它们。外围补大石时优先等足迹替换既有林内石位，按稳定坐标和间距选点，并保留原路肩及湿岸归属。
- 枯木的网格枢轴、包围盒最低点与实际承重部位可能相隔很远。应用网格构建缩放、实例旋转和缩放，在木身纵向与分叉横向选取真实底部顶点，与最终碰撞三角地形拟合。按厚度埋入根部，以木身样点约束最大埋深。古树桩上翘的根尖、倒枝拱起的中段可以自然离地。
- 修改落地算法时分别保留现行实例数量、变体、剔除／淡出距离和阴影策略。基础槽和扩展槽可能引用相同网格。将旧细枝归到新的贴地分支时，应沿用原槽的显示距离；独立道路重建可保留共用槽号，跳过没有落点的丘陵大石几何读取。
- 用户要求复查时，在两主题分别对照实际材质槽与生成数量。长木按多个下部区段测与地面间隙，同时统计整件埋没、整件悬空及抽样量。一次枢轴命中无法判断另一端是否悬空。项目实现入口为 `ForestWoodDressing.cpp`、`ForestReferenceBoulders.cpp` 和 `ForestVillageRegionPCG.cpp`，均在 `Source/FPSGAME/WorldGeneration`。

## 读取用户导出的 F6 数据

从当前工程 `Saved/PerformanceReports` 找用户描述的导出，以 `session_id`、UTC 采集时间、地图、位置／朝向、视口和面板状态匹配样点。按其窗口计算帧 P50／P95／峰值、慢帧数及 GPU 和渲染线程时间。把显存样本的单调时钟裁到相同窗口，逐样本用量减预算，记录过预算范围和样本数。PIE 包含编辑器负载。

比较 RHI 资源清单的 `collection_render_frame` 和采集时刻。两个窗口可复用同一份早期清单，仅用其标出候选资源。用导出行的 Streaming 标志、贴图自身的 mip 设置和实际材质绑定核对优化入口。VSM 池分配、临时毛发缓冲和可见候选灯各自说明不同问题；阴影耗时、物理驻留与换页需要相应的测量。保留近景画质的试验，先从超出屏幕分辨能力的高 mip、远端发丝或次要补光阴影中一次选择一项，在同机位复测毫秒与 MiB。

## 迁移林图的渲染和联机预算

旧图与新图可能走不同的入场函数。沿正式入口核对驻留句柄、居民分批加载、游戏中 PCG 预算及退出释放。保留房主附近树冠与远端玩家权威树干的分工。近草按本地视角调度，采石场的服务端碰撞要考虑远端玩家的位置。可选装饰载入结束后按可用变体继续布置，空槽不应让整片植被一直等待。

调整 Nanite 前同时查网格默认材质和关卡组件实际覆盖的材质。将目标平台着色器落盘，并看网格构建后的回退 LOD0 实际面数。先判定地形、台阶是否以复杂三角形承担人物碰撞，再选可简化的道具。保持独立光追代理、主画面 Nanite 和碰撞三种用途的统计口径。若用户要求比较阴影收益，固定时间、天气、镜头和输出分辨率，交替恢复原配置，比较多轮总帧及阴影阶段毫秒数。

用户要求联机复核时，复制世界和角色档案到隔离目录，记录实测模块哈希。用阻挡角色的物理射线检查地面。让客机远离房主砍树、断线后用同一身份重连，核对采尽、幼树和成熟状态。最终结果要同时计入双端正常退出和正式存档哈希一致。注明监听服、专服和渲染画面的实际覆盖。需要排查完整预载时再读性能技能的“纹理预算与输入放行”。
