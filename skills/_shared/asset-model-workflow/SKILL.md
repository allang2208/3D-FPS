# 通用游戏模型生成工作流

本流程用于后续配件、枪械、怪物、建材等模型制作；2026-09-22 起先按下述形态与精度分流，再进入相应制作分支。个人技能为维护源，工程对应 SKILL.md 仅提供本机入口；维护方式见[约定](../ue5-auto-assistant/references/skill-maintenance.md)。 原因：共用规则只保留一个维护来源，工程独有约定仍需要自己的入口。

**执行边界：默认不主动测试、验收、启动游戏或生成验收渲染。** 资料读取、制作、必要构建、导出、导入及已授权接入照常完成；用户明确要求的预览、排查、测试只按指定范围开展。记录流程不触发生成任务、远端部署或资产替换。 原因：制作授权不包含额外运行或验收，交付应保留未测试的实际状态。

## 先按形态与精度选择制作路线（用户确定，2026-09-22）

- 当前 5080 图生 3D 管线优先用于本身不规则、粗糙的物体，例如冰锥、矿石、岩块、树干和树根；生成轮廓后按用途整理拓扑、尺寸和材质。树冠、叶片、LOD、碰撞与玩法仍需单独制作和接入。 原因：生成管线擅长不规则外形，但树冠、碰撞和玩法需要各自可控的数据与运行接口。
- 精细近景小物件、工具、灯具、机械接头、规则包装、薄壁或带准确孔槽/文字的物品，优先采用 Blender／Vibe3D 精确建模及明确的 PBR 制作。不要把增加 5080 步数、输出面数或贴图尺寸当成恢复精密结构的办法。 原因：旧实例已经保存了位置与身份，更新目录尺寸不能替代现有布局的迁移。
- 复合物体可以分工：5080 制作粗糙自然主体，安装面、接口、支架、金属附件与细节由本地建模完成。用户已经认可的资产继续沿用，不因本条批量替换。
- 这是基于用户对当前本机管线的实际反馈形成的默认分流，不是对所有生成模型的永久能力结论。用户明确指定生成路线或要求管线比较时按该次要求执行；下文历史高档参数仅供这一分支参考。

## 1. 参考与三视图先行

制作兽首配重、龙凤护手、云纹接座，或正面浮雕合格但侧面体积／下颌轮廓失真时，读取 [纹饰浮雕与立体轮廓](references/ornamental-relief-and-solid-shapes.md)。 原因：二维明暗和真实体积承担不同视觉信息，直接把颜色变成高度会制造不属于结构的起伏。

- 先确定对象身份、用途、目标引擎、尺寸、朝向、关键孔洞/细杆、分件和连接面。读现有宿主与源资产；配件读取实际枪体和挂点，怪物读取体型及动作参考，建材读取模块尺寸和拼接边。 原因：物体外包范围不等于实际装配界面，按外轮廓对齐仍会留下接缝或穿插。
- 默认先制作同一对象、同尺度、同姿态的三视图。按最能解释结构的正/侧/背或正/侧/顶选择，保留对称与非对称特征。只有单图时，遮挡侧是设计推断，不能称为精确还原。 原因：明确目标后才能复用正确的既有入口，准备步骤不应扩大已授权工作的边界。
- 栅格图制作使用 imagegen 技能及当前可用图像工具，保存原图、提示词和最终参考。去掉 UI、文字、背景底板及投影干扰，保留目标孔洞、透明区域和细杆。
- 拼图必须切成独立视角，再分别做前景处理，接入真正多视图节点。明确每张图的空间方向和节点输入映射；文件名 front/back 不足以证明模型真实朝向。裁切尺寸由本次图片决定，不照搬旧案例坐标。
- 三视图与目标接口冲突时先修参考；机械件的准确接口、建材的平直拼接面由本地建模保证，不寄希望于加步数。

已有模型的枪械配件 UI 图标使用 [改造配件图标标准](../ue5-weapon-workflow/references/attachment-icons.md)：按当前实际模型渲染，采用用户已接受的水平左向、透明背景与单件表达；不重新用概念生成图代替已确定的模型。

## 2. 生成与小批候选

- 选定 5080 自然粗糙物体分支时，当前生成起点为 **TRELLIS.2 三视角**；用户指定其他模型时遵从。先读取当前工作流、节点定义和可用服务以完成调用，历史地址/节点安装不等于当前可执行。具体入口见 [5080 案例与工具](references/5080-case.md)。
- 备选生成路线：**Meshy API**（2026-09-19 用户登记为备选，会员积分同池、Pro 起含 API）。用户指定 Meshy、本地 5080 对有机/角色造型反复出不了合格候选、或要给已绑骨怪物搜套现成动作（库 678 个，GIF 预览由用户挑选）时使用；分流、调用、积分表与 3 天保留/不退分等硬约束见 [Meshy API 管线](references/meshy-api-pipeline.md)。key 只走环境变量 `MESHY_API_KEY`，产物任务一完成就落盘归档，回执入库前剥预签名查询串。精确接口机械件与建材模块仍走 Vibe3D/本地 Blender。
- 精细候选参考起点：TRELLIS.2-4B、1024_cascade、结构分辨率 64、结构/形状/纹理 16/32/24 步、4K 纹理、50 万面母版导出目标。它是后握把成功生成的档位，不是跨类别最优参数，也不表示实际面数恰好 50 万。
- 有意图的机械孔洞保留：不要盲目开启 fill_holes 或 keep_only_shell。怪物、岩石等按自身封闭表面需求决定，不能将机械件开关推广成全局禁令。 原因：开放结构可能是模型有意保留的接口，自动补面会制造重叠或封死功能开口。
- 先做少量候选，冻结参考与主要参数，只改变 seed。用户允许继续抽取时分批推进，保留候选与选择理由；同类缺陷反复出现就修参考、改变视角或本地重建，不无限抽种子。用户选中后冻结母版，后续适配不擅自换造型。 原因：用户认可的是具体母版和观感，换成另一版本会改变已有接触或外观基线。
- 三个优化方向分别使用：结构分辨率 32/64/128 是结构探索；Pixal 单图是独立生成路线；MultiViewRefiner 是已有几何的细化。不要把三者串联当成强制步骤，安装完成也不等于效果已证实。128 和其他高档按显存条件试用，不默认保证 16GB 可完成。
- 记录完整 API 工作流、模型/节点版本、视角、seed、prompt_id、历史和输出。服务无新日志不直接判死；结合当前任务状态决定等待或处置，不重复提交同一已在运行的任务，不清空他人队列。 原因：日期化证据只对应当时的输入与修订，不能为当前状态补出不存在的结论。

## 3. 几何、材质与装配

面数预算、重拓扑、LOD 或高模是否应进入游戏，先读 [按用途分配面数](references/geometry-budgets-by-use.md)：复杂近景物体允许高面数，按屏幕占比、同屏数量、变形和渲染路线分配；区间不是强制上限，不为凑数损伤已认可的轮廓与关节。手套／衣袖的高模烘焙、毛躁、浅层视差和实体厚度，转 [手套衣物表面制作标准](../ue5-fps-arms-animation/references/glove-clothing-surface-production.md)。

地面金属条、侧轨、转角拼缝或织物缺少凹凸时，读取 [地面收边与织物细节](references/floor-trim-and-textile-relief.md)：按真实连接面生成连续轮廓，近景浅层视差与法线共享物理尺度，保留用户认可部分。

工作台、货架、维修工具墙等成组布景，先读 [可复用室内组合件](../ue5-pcg-building/references/reusable-interior-assemblies.md)：按实际支撑面和锚点装配；线缆连续路由，标签贴合载体，容器内物件用固定种子的受约束随机与离线落定。配置、组件及材质依赖一起维护，避免每次在关卡中逐个小件修正。

可替换枪托、护手、握把、配重锤等有精确端面要求的部件，读取 [模块连接面与局部重建](references/modular-part-interfaces.md)：复制原装接口、保留面角属性、连续过渡、长件端面平移，以及原厂件隐藏后宿主切口的封闭。

- 保存原始几何和带纹理母版，再另做游戏低模/LOD。增加导出面数、细分或平滑不能恢复已缺失的孔洞、薄片和规则棱线；这些部分局部重建。分辨率、采样步数、输出面数和纹理尺寸分别控制不同问题。 原因：作者母版与运行网格承担不同用途，保留母版才能重做细节、烘焙和距离档位。
- 减面依据实际视距、剪影和变形需要，保住孔洞、安装边、轮廓和材质分区；精细纹理由母版烘焙到低模。来源表面有重叠/坏法线时先整理再烘焙；仅有颜色图不能称完整 PBR。 原因：成本取决于实际可见量与变形和材质路径，统一面数阈值会损伤近景质量。
- 局部编辑保留未改区域的 UV、材质、法线和权重。新补面有自己的有效 UV/切线；避免用全网格重建破坏已有自定义法线。导入发现近零切线或重绑定警告时记录并针对性处理，不宣称已通过着色/动画验收。
- **装配基准是实际连接面，不是整个模型的包围盒或最高点。** 记录物体局部轴、单位、目标接口与根骨变换，每个宿主独立适配。翘尾、尖端、脚趾或装饰突出部不能冒充接触面。
- 空隙来自形状不匹配时，局部调整连接头并做与宿主轮廓一致的过渡；只移动整件可能破坏握持或动作。保留已认可的主体与握持区，以平滑过渡修接头。具体毫米数和骨骼缩放抵消量只属于对应资产。
- 枪械与配件：机械活动件独立，原厂件以独立对象/材质分区支持替换恢复；沿真实挂点驱动。材质以每把枪当前主体为准，保留其他任务已做的材质。
- 怪物：形状认可后进入专用重拓扑、骨架、权重和动作流程；AI 网格不等于可动画成品，保留体型、支撑点和攻击器官身份。
- 建材：结构模块以明确尺寸、网格步长、枢轴、平直拼接边和碰撞为准；生成模型提供外观细节，不能直接当精密模块。砖石等原料道具走物品分支；可重复墙板/梁柱走建筑模块分支。 原因：结构拼接依赖精确尺寸和边界，外观生成不能保证模块化安装精度。

## 4. 接入与交付

- 按已授权范围接入对应 ID、材质、碰撞、挂点、存档及打包目录；生成授权不自动扩大为替换所有既有资产。涉及玩法、动画或建筑放置时转对应领域技能。 原因：模型制作与全项目替换有不同影响范围，按目标 ID 接入才能保留既有资产和领域合同。
- 已加载资产优先在当前编辑器内通过 MCP/Python 修改与保存，不以外部进程覆盖同一包。并行修改冲突时使用独立修订路径，再按授权切换引用；保留旧资产与来源。原生改动按前述开发规则选择 Live Coding 或常规构建，不默认使用独立模块后缀绕过占用。 原因：进程中的对象和磁盘包可能不同步，外部覆盖会损坏当前未保存的工作。
- 交付原图/三视图、候选与选中版本、母版、可编辑源、游戏导出、作者脚本、导入回执及实际运行引用。原始参考的权利不因 AI 生成自动改变，复用许可与公开分发许可分别记录。 原因：可复用制作方法与可分发原始素材是不同权利范围，公开代码不能代替素材授权。
- 分开说明“已生成、用户选中、已导入、已编译、游戏已测试”。用户要预览时给实际模型渲染，注明 Blender 源模型或引擎画面，不能拿概念图替代；未测试交由用户测试，不把历史通过记录套用到新资产。 原因：源码、磁盘资产、二进制和运行效果属于不同交付阶段，需要各自的完成依据。
