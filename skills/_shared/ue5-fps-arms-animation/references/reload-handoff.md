# 换弹收尾与待机衔接

用于排查换弹末尾瞬移、二次回正，以及复用已认可动作时的衔接。先读取当前实际加载的动画和配件分支；测量、渲染与运行检查只在用户明确要求时执行。 原因：换弹尾部依赖实际动作与配件分支，沿用旧回执可能修错正在播放的序列。

## 分清哪一层没有归位

最终画面叠加了骨骼动画、动作混合、视模组件锚点和镜头偏移。先用相同求值模式和坐标空间比较当前换弹末帧与对应 idle：RAW 与 COMPRESSED 不混用，原厂、握把、弹匣各用自己的目标姿态。

末帧枪根已经吻合时，继续排查忙碌状态是否仍保持动作展示偏移。不要为了修运行时锚点交接，重新制作用户已认可的手指、插匣或拉栓动作。 原因：机械部件与手部动作需要对应实际武器状态，移植表现时不能替换原有机械事件顺序。

## 在动作的收尾段内交接

- 在最后一个必须保留的机械接触之后回收展示偏移，与骨骼收势同段完成。不要直到退出换弹状态才开始指数滤波，否则仍会出现一段突然或滞后的组件位移。
- 用户要求线性回位时，按源动画剩余时间计算 `clamp((end - source_time) / return_window, 0, 1)`；不要再对这段权重施加滞后滤波。动作入口仍可保留原有平滑。 原因：未改表面的着色与变形依赖现有面角属性，整体重建会扩大局部修改的影响。
- 使用现有 `ReloadSourceTime` 一类映射，与敏捷、快手、配件速度及弹鼓时钟一致。业务计时与另一套自由累加的动画计时不应在结束处各走一步。 原因：动画映射和业务时长必须使用同一速度修正，否则结束边界会出现额外一帧位移。
- 完成动作时清除其活动片段、动作权重和展示偏移，精确交给当前 idle/ADS/移动状态；避免下一 tick 的旧动作重新抬起偏移。
- 保持弹药提交、机械音效、拉柄接触与释放时序。固定帧号和窗口时长只属于对应作者源，不推广成所有枪的默认值。 原因：视觉播放、武器普攻和技能时长有各自的数值合同，重复缩放会改变节奏或伤害输出。

## 拉柄后拉、停顿、主动前推（PKM 低模分支，2026-09-23）

先从参考视频分清手部运动方向与实际可见接触；遮挡区域只能称三维适配。原动画即使有拉柄回程，手指过早松开或镜头持续向后也会造成方向错觉，需同时看手、机械件和镜头各自时钟。 原因：模型是否入镜取决于真实镜头和姿态，几何尺寸正确不保证所见轮廓合适。

- 将动作分成后拉、后止、前推、前止、松手、回握。主动前推时沿原导轨/行程保持指腹锚点，到前止点以后才放开；不能把前推做成弹簧回位后手在空中追随。 原因：手指应在机械行程完成后释放，提前脱离会把主动推送看成在空中追随弹簧。
- 沿用当前握姿，联动肩、肘、前臂、手腕、twist 与手指；过渡用局部旋转并保留骨段长度。整枪冲量若重定时，仍在接触的另一只手应一起受力。 原因：手部接触、骨段长度和关节弯曲共同决定姿态，单独满足一个数值仍可能破坏人体轮廓。
- 从旧烘焙中撤销已有运动时，必须重现旧插值函数再求差，不能用新平滑函数近似旧函数；本例旧整枪冲量用三次 smoothstep，新拉柄用五次曲线，两者不能互换。 原因：撤销运动需要求原曲线的反向差量，另一种平滑函数不等于原运动的逆。
- 音效队列、镜头和手臂共用源动画时间；新增事件后同步消费索引、最小事件数与末次到位判定，避免镜头仍读取旧的两个时点。镜头仅跟随和反馈，不再叠加一次已经烘焙到枪手的通用机械冲量。

本机 `Charge34` 仅覆盖 default/vertical/canted/prism/angled 五类空仓片段，依赖 `EquipCharge31` 的作者源；保留普通换弹和既有装备动作。该枪案例时点为 5.13/5.36/5.48/5.82 s，5.835 s 松指、6.27 s 回握，总长 6.60 s；不是其它枪的模板数值。动画和四段原声已保存，后台构建成功；尚无本轮实机同步验收。
