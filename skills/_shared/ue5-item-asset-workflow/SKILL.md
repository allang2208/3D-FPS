## 执行约定

遵守用户全局规则：后台制作、不主动测试、不跨对话协调。涉及 UE 构建或资产操作时，按需读取[后台开发与接入规则](../ue5-auto-assistant/references/editor-open-development.md)；已读则复用。 原因：制作授权不包含额外运行或验收，交付应保留未测试的实际状态。

# FPSGAME 物品资产工作流

## 统一模型生成入口（2026-09-13）

模型制作先采用 [通用模型工作流](../asset-model-workflow/SKILL.md) 的形态与精度分流：当前 5080 优先用于冰锥、矿石、树干等不规则粗糙主体，精细近景工具、灯具、容器及规则小件优先 Blender／Vibe3D 精确建模；本技能继续负责物品身份、写实材质、拾取、稀有度与存档。下文旧案例参数保留为历史记录；默认不因技能步骤触发测试或验收渲染。 原因：光源位置与方向决定照明覆盖和成本，仅增加亮度无法替代正确的层次与朝向。


适用宿主 `D:/FPS3D/FPSGAME`。用户于 2026-09-11 明确要求物品统一写实风格。个人技能是维护源，工程 `skills/ue5-item-asset-workflow/SKILL.md` 为同版镜像。

## 非枪械物品完整流程

手套背包图标使用 [手套专用图标规则](references/glove-inventory-icons.md)：单只空手套、当前原生手型、正交坐标架、自然分指；露指款斜看真实开口，不出现皮肤，不叠放第二只。此规则替代旧手套双只平铺案例。

分品阶药水瓶、同瓶改色、拾取映射和恢复数值／旧档同步，读取 [分品阶药水瓶与恢复数值](references/potion-tiers-and-recovery.md)。

地面原木空心、树皮碎裂、树桩断面贴图或封面制作，读取 [实心原木与断面](references/solid-timber-and-cut-surfaces.md)。树木倾倒逻辑转 `ue5-world-interaction`，不重复生成已认可的母版。

制作、改色或接入消耗品、材料、弹药包装、卷轴时，按需读取 [图标到模型及稀有度光效](references/non-weapon-items.md)。其中包含透明图标提取、薄壁烘焙、UE 材质变体、旧存档字段迁移、中心光晕与竖直光柱、废案归档和发布边界。 武器／装备取消稀有度及按强化分档的掉落光束也读该参考；共享传说色为鲜红 #FF3030。枪械模型、枪械配件及第一人称手臂不使用此技能替代其专用工作流。 原因：旧输出可能仍是当前作者链的输入，保留可追溯来源才能恢复现用资产。

## 写实风格合同

文件、检修材料、服务器硬件及其背包占格/图标，读取 [搜索收集物资产](references/search-collectible-assets.md)；包含当前条状物居中规则、原创标识、混合恢复链与旧实例兼容。

- 本项目新制及本次授权调整的物品图标、三视图、3D 模型和游戏材质统一采用写实风格；不可继续使用卡通、低多边形块面渲染或以平滑法线假装完成写实转换。此规则不自动授权批量替换既有资产。 原因：用户指定的是统一写实视觉，局部制作应满足该风格并保留未授权旧资产的现状。
- 先实际查看当前物品图标、已有模型及物品定义。保留轮廓、用途、颜色辨识、口径和包装身份，材质表现改为真实玻璃、液体、金属、纸板、岩石、粉末等。 原因：图标显示取决于可见轮廓和容器比例，重复边框或留白会缩小有效识别区域。
- 写实不是添加脏污、划痕或强高光。依据材质控制微表面、粗糙度、金属度、厚度、反射及自然磨损；不能所有物品共用塑料般高光。
- 魔法设定可以保留，但载体应可信：矿石有自然断面和矿脉，粉尘有细颗粒与合适的容器。保留参考中的包装；不要擅自添加容器或把漂浮光点与背景生成进主网格。 原因：列表、选择和实际扣除需要使用同一物品来源，否则界面会提供无法提交的操作。
- 与当前冷钢 UI 共存：写实规则约束物品资产，不改动已定稿的 UI 布局、字体和排版。
- 用户要求游戏内风格检查时，在 UE 实际场景、统一尺度和光照下比较。原因：生成图或外部渲染没有覆盖游戏内着色和照明，不能据此声称游戏内风格一致。

## 三视图与输入

- 先核对物品 ID 和名称；当前 `enhancement_stone` 显示名为“强化石”，`magic_dust` 为“魔法粉尘”。用户口头名称不同，先结合上下文确认对象，不直接改名或创建重复物品。 原因：列表、选择和实际扣除需要使用同一物品来源，否则界面会提供无法提交的操作。
- 同一资产使用一致尺度、部件位置、材质和液面，明确正/侧/背或正/侧/顶。逐张检查遮挡关系；背面不能仍显示仅正面可见的盒内结构。 原因：视角和投影决定可见结构，方向未对齐的图无法作为同一对象的直接比较依据。
- 三视图分别输入多视角节点，不能把整张拼图输入单视角模型并宣称完成多视角建模。 原因：视角和投影决定可见结构，方向未对齐的图无法作为同一对象的直接比较依据。
- 输入背景与透明材质分开处理，检查裁切和前景蒙版；不要将反光抠除、把背景底板带入模型。不能用明显矛盾的视图靠加步数补救。 原因：模型是否入镜取决于真实镜头和姿态，几何尺寸正确不保证所见轮廓合适。
- 栅格生成与修改遵循 imagegen 技能，保留提示词和最终文件。

## 5080 质量档位与证据

- 开始前读取现有工作流与本机服务 `/system_stats`、`/queue`、`/object_info`；不把节点选项上限说成硬件已验证的能力。远程历史入口是 `192.168.3.142` / SSH `r5080`，端口和队列必须实查。 原因：服务节点能力和硬件能力不同，历史地址与队列也可能变化，制作须依据当前服务接口。
- 2026-09-10 四款消耗品的实测基线：TRELLIS.2-4B、512、结构 12 步、形状 16 步、纹理 12 步、Euler、3 个独立视角、2K 贴图、导出目标 20000 面；这是较快的候选档，不是最高精度。
- 2026-09-11 查询节点显示：结构/形状/纹理步数上限各 100；管线含 1024、1024_cascade、1536_cascade；贴图可到 4096。以上只代表配置范围，不能保证 16GB RTX 5080 多视角任务全部跑通，不能把官方 H100 时间套用到 5080。
- 精细物品按上述分流优先精确建模。只有用户明确指定 5080 或要求管线比较时，才把 1024_cascade、16/32/24 步与 2K/4K 贴图作为候选实验起点；历史高档不构成精细小件的默认路线，也不保证轮廓、孔槽、薄壁或文字精度。
- 增加步数、分辨率、输出面数各自作用不同；100 步不等于最好。缺失的字样、薄壁、瓶内液体及锐利边缘须分别验证或重建。
- 先保存保有细节的高模母版，再按实际用途制作低模/LOD，烘焙法线；不要先减到 2 万面然后用细分声称恢复原始细节。母版与游戏版本分别记录实测面数。 原因：源码、磁盘资产、二进制和运行效果属于不同交付阶段，需要各自的完成依据。
- 保留 base color、roughness、metallic、normal、opacity 等实际生成/制作的通道，并检查 UE 连接；仅有颜色图不得宣称完整 PBR。 原因：表面观感由多个材质输入共同决定，单改颜色或统一覆盖会丢失原有材质身份。
- 保留回执、完整工作流、历史、原始 GLB、后处理脚本及可编辑文件。明确哪些来自 5080，哪些是人工/程序重拓扑或材质重建，不混称直接生成。 原因：异步消息可能在动作结束或装备切换后到达，只有匹配当前身份才能修改现态。
- ComfyUI 日志可能到采样阶段结束才刷新：本次 1024 级联的 HR 形状阶段曾耗时约 5 分 53 秒，中间日志仍停在 decoder 加载。不能仅凭数分钟没有新日志就判定卡死或中断；结合 GPU 活动、最终阶段记录和执行状态判断。相似的上游问题也不能替代本机诊断。 原因：阶段性日志可能缓冲，长计算阶段无新输出不等于任务停止。
- 2026-09-11 强化石实测：512 的 12/16/12 档完成约 102 秒，1024_cascade 的 16/32/24 档约 726 秒，均为三视角、2K、10万面目标导出；原始几何约244万/908万三角面。仅此物品确认高档完成，不能外推所有物品。粉尘512约324秒；粉尘1024首次运行期间主机失联；恢复后进入HR采样，用户接受已接入版本精度并叫停，未完成对比，不记为成功或显存失败。证据位于 `SourceAssets/EnhancementMaterials5080_20260911`。 原因：物品转移涉及来源与目标两侧状态，部分成功不能造成物品丢失或重复生成。
- 原始高模需检查法线和内层面后再烘焙。强化石908万面直接烘焙产生约48.4%负切线Z像素及黑斑，已淘汰；采用整理后的约10万面表面烘焙到2万面候选后异常明显减少，完成渲染检查。原始母版照常保留，不把有问题的原始细节强行灌入低模。

## 交付与接入

- 按用户授权阶段提供三视图、实际模型多角度渲染和文件。提出“开始前的问题”时先回答并完成明确要求的标准记录，再按后续授权推进生成。 原因：制作步骤与检查步骤需要分别获得对应授权，历史验收流程不能自动扩展当前任务。
- 接入时读取 `ue5-world-interaction`：匹配物品定义、真实尺寸、模型中心、简单碰撞与重力根；保留数量、拾取检查和落地位置/旋转存档。 原因：旧实例已经保存了位置与身份，更新目录尺寸不能替代现有布局的迁移。
- 透明瓶体与液体分件；实时玻璃近似需明示，不能宣称与离线路径追踪效果一致。接入时按当前材质类型选择可用网格路径，并完成材质槽和打包目录绑定。原因：透明外观由实际运行着色路径决定，离线路径追踪效果不代表实时近似。
- 验收分别报告导入、编译、实际运行；检查物品下落、落地不穿透、瞄准拾取、堆叠和存档重载。保留并行改动，不修改无关系统。

- UE 5.8 Substrate 下本次透明瓶体采用 Thin Translucent、Surface Per Pixel Lighting、透射色控制玻璃，根 Opacity=0 保留透射。转换代码会将透射色向黑色按 Opacity 插值；设为1曾出现不透明外壳。以当前引擎代码与运行渲染为准，不直接照搬离线 transmission 或其他 UE 版本的默认值。
- 本机 UE 5.8 `DeleteAllMaterialExpressions` 遍历时修改表达式集合，重复导入曾留下 Thin Translucent 输出并造成着色器编译失败。脚本改为复制 `get_material_expressions()` 列表后逐个删除，断言清空，再建图；导入成功不等于运行材质编译成功。
- 2026-09-11 两款材料地面模型接入 `/Game/Items/EnhancementMaterials`，14/16cm，运行审计 `EnhancementMaterialPickupAudit` 27项通过。冷启动发生编译卡顿时，以刚体实际落稳判定进入保存/拾取检查，固定两秒等待可能产生假阴性；正立材质对照截图与真实重力落地截图分别记录。

- 用户要求读图时使用当前宿主的图像读取能力；宿主不能接收图片或用户明确指定外部复核时，再按 [读图入口说明](../../../Docs/deepseek-vision.md) 使用兼容脚本。定量尺寸读取原图或几何数据。原因：固定工具名、旧宿主缓冲上限和供应商名称不能证明当前会话能力，外部描述也不能冒充直接看过像素。

- 2026-09-16 体素块（`voxel_block_wood/stone/marble`）：物品的"模型"就是建造用的 20 cm 体素方块，因此**不新建模型文件**，拾取物直接读活动调色板 `DA_VoxelBuildPalette` 的 `ExampleMesh` + `Surface`（缺省回落 `SM_Voxel20_Stone`），图标复用工程既有写实材质图（`Icons/wood|stone|marble.png`）。需要"方块造型图标"时再按图标流程补。残骸回收与范围拾取见 `Docs/UI/area-pickup-and-notice-bar-20260916.md`。

## 说明字段的生成格式（用户确定，2026-09-22/23）

新增物品时，**详细介绍**与**特殊性质**按下面格式生成。枪械与双手剑的完整版
（含 `traits` 的 `icon` 分类、配色与生效链路）见
[武器说明文字与「特殊性质」段](../ue5-weapon-workflow/references/weapon-copy-and-traits.md)。 原因：介绍与性质有独立显示和生效路径，统一格式可保留文案与系统字段的职责。

### 详细介绍：`items.json` 的 `desc`

- **≤200 字**，一段话讲清**来历、特征、怎么用**；优缺点一起写，让玩家知道什么场合用它。
- 现实存在的物品**参考百科**（设计者、原理、来源背景）；虚构物品**编写背景故事**。
- **禁止"最""第一/第二档""之首""唯一"这类排行与序数设定词**，也不要引用别的物品做定位
  （"介于 X 与 Y 之间"）——后续还会加物品，这类说法一加新的就自相矛盾。 原因：排行依赖未来物品集合，新增条目会让绝对序数或比较定位失效。
- **不重复实时数值**：数值由 `ColdSteelData` 目录提供并在提示里单独成行；
  文案里出现的每个数值都要回目录核对后再写（本项目实际写错过四处，见枪械参考文档）。
- **`desc` 是物品实例快照**：物品提示读的是实例 Data，不是直接读 `items.json`，
  所以只改目录时**已持有的物品仍显示旧文案**。生效要三步且顺序不能反：
  **构建 → 重启编辑器 → 进一次游玩**（编辑器不创建 game instance，子系统没实例就不会跑迁移）。

### 特殊性质：目录里的 `traits`

- 放**目录**（枪械放 `gunsmith.json` 的武器块，近战放 `melee-gunsmith.json` 的 `weapons` 条目），
  与 `base` / `allowed` 同级。**刻意不放 `items.json`**：目录每次读盘解析，
  改 `traits` **直接生效、不需要迁移**。
- 每条 `{ "icon": <语义标签>, "text": <一句话说明> }`，写 2–4 条；
  `icon` 由 UI 映射成颜色（`special` 蓝 / `magic` 紫 / `mechanic` 青 / `drawback` 红 /
  `neutral` 灰），所以新增物品**不必改 C++**。
- 只写玩家能感知的效果，例如：独有的技能或攻击模式、命中/击杀触发的收益、
  明确的代价（移速、换弹、散布）、可改造槽位。数值同样回代码或目录核实。 原因：描述应反映实际可感知能力，目录和代码才决定数值，不能编造差异。

## 交付检查（说明字段）

- [ ] `desc` ≤200 字，含来历/特征/用法，无排行词、无跨物品引用、数值已核对
- [ ] `traits` 已写入对应目录，条数与 `icon` 分类合理
- [ ] 改过 `desc` 时已说明"需重启编辑器 + 进一次游玩"才在旧存档生效
