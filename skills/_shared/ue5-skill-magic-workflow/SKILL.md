# UE5 技能与魔法开发



实际工程为 `D:/FPS3D/FPSGAME`。用户于 2026-09-14 确认火球左手 V3「基本达到预期」，指定本工作流为后续技能／魔法标准。此确认针对当前效果，不代表所有武器、联机或异常状态均经过回归。

## 1. 先确定现有入口和完整规则



范围、连锁技能被栏杆或镂空障碍误挡时，读取[范围与连锁遮挡](references/area-skill-occlusion.md)：复用独立栏杆标记与复杂碰撞，多点目标暴露判断，保留实体墙和楼板阻挡。



持杖举起／前挥、右手施法占用、火球／冰锥跟随至接触发射及预览不对线，读取 [持杖施法与瞄准](references/staff-cast-and-aim.md)：手势开始时选分支，同帧杖尖，松手确认与接触发射共用状态。

陨星和灼锋焰甲等火场／武器附魔先读 [陨星与灼锋焰甲](references/fire-magic-migration.md)：原版数值、陨星法杖限定、非魔法附伤隔离、整次修炼与火把特效副本。2026-09-30 用户要求陨星与冰墙仅当前装备法杖可施放，其他技能的范围按明确要求和当前配置执行。





圣光等敌伤友疗的锁定魔法先读 [圣光与敌伤友疗](references/holy-light-migration.md)：同组阵营、Alt 自愈、僵尸分类、治疗与伤害词条分离、续疗，以及现有 Holy Spline 光粒和原版光柱重建。



闪电等锁定连锁法术先读 [闪电与锁定连锁](references/lightning-migration.md)：目标与视线、起手提交、整次修炼、感电／过载以及现有 Spline VFX 的作者入口。当前迁移已接入，未进行实机验收。



雷暴领域与贯穿雷枪读取 [领域落雷与蓄力贯穿](references/electric-magic-migration.md)：随身雷云、松键释放、原版成长与感电增伤、墙面截断、Profile v19退款预留及电系资产作者。雷枪已于2026-10-05、雷暴领域于2026-10-12加入法杖限定；雷暴当前使用从百目黑烟派生的RollingV1乌云，保留室内净空适配，伤害范围与视觉尺寸分离。



电系光柱的粗细、密度、流动与棋盘格问题读取同一引用的「光束制作的可复用规则」；当前制作与恢复入口为ThunderFluxV3，参数和用户测试边界见工程记录。



冰锥或整组多枚投射物的迁移，先读 [冰锥与多枚投射物](references/ice-spike-migration.md)：源码全链、数量台阶、整组冷却／修炼、法杖联动及共享手势。2026-09-16 起冰锥与火球同口径：不再单独计算智力、总量比旧公式低约 30%、蓝耗随等级增长、基础冷却 12→8 秒；旧的「保留原版魔攻＋智力」条款作废，取数一律以当前 `skills.json` 为准。魔杖乘数接口 `wandSpellMultiplier` 已在火球公式预留。



- 原项目用于读取数值、触发条件、成长、修炼方式、动作意图和存档规则；不因迁移改掉技能身份。记录原单位到 UE 厘米的转换。

- 技能定义与每级效果、成本、伤害、经验和界面说明取同一数据入口；被动效果从当前等级派生，不在加载时反复叠加。

- 先列出主动／被动、解锁、等级上限、冷却起点、资源扣除时点、施法接触点、可打断阶段和动作占用。一个已展示但不能升级、保存或使用的卡片不算接入完成。 原因：冷却的起算时刻和倍率属于施放合同，界面与执行路径不能各自扣减一次。

- 当前入口：`Content/ColdSteelData/skills.json`、`Source/FPSGAME/Skills/ColdSteelSkillRules.*`、`ColdSteelSkillModel.cpp`、`UI/ColdSteelStatusModel.*`。专项参数可独立 JSON，原生数值与面板共用计算结果。



冰墙的凝聚、建筑式预览、R 切高／矮墙与发射成墙，读取 [冰墙迁移](references/ice-wall-migration.md)：原版物理伤害、整次修炼、连续碰撞／导航、脚架顶面和未释放退款。资产已后台保存，实机状态以工程案例为准。



## 2. 玩法、进度和快捷栏一起接入



- 技能组件管理玩家的请求、阶段和生命周期；投射物保留施法参数快照、飞行和命中表现；状态模型提交资源、冷却、修炼与存档。UI 发请求，不直接结算伤害或扣资源。

- 用户于 2026-09-15 指定：有指向的投射物魔法默认支持“实际直击要害必定暴击 + 随机暴击”，单次只结算一份暴击加成，范围波及目标不继承直击要害结果。开发此类魔法时读取 [投射物魔法暴击](references/projectile-magic-critical.md)，保留完整碰撞部位并接入共用暴击／修炼路径。 原因：每个实际命中目标和部位都有对应结算上下文，复用错误命中数据会改变伤害结果。

- 排队不扣费；动作实际开始后一次性提交成本。命中、击杀和多目标奖励按同一次事件合并，由同一状态入口提交经验和升级，再按现有策略持久化并通知界面。旧存档迁移补项，不重置已获得的技能。

- 明确死亡、退出、重载及未结束技能的资源／冷却处理。火球当前已有投射物复制、网络施法与权威伤害入口；修改沿现有网络合同处理，具体运行覆盖仍按证据说明。原因：本地与权威状态共同参与施法，不能再用早期“仅单人”规则指导当前接入。

- 冷钢技能列表、详情效果对照、修炼卡片和图标见 [UI 技能](../ue5-ui-umg-slate/SKILL.md)。拖动交换、技能／物品混放与 E 优先交互沿用项目快捷栏规则，不各写一套输入或持久化路径。 原因：「UI 技能」记录该任务的专属入口和边界，按主题引用可避免另写一套相互冲突的步骤。

- 新技能图标使用当前冷钢风格并接入 `skills.json` 和图标恢复脚本；不要仅生成图片或悄悄回退旧项目图标。 原因：正式图标需要数据引用及恢复链，单独图片不会被运行界面使用。

- 火球图标按 2026-09-14 用户要求改为火红主体，保留银框与石墨暗底；当前图源为 `Skills/fireball_ember_red.png`。元素辨识优先调整主体颜色，冷却／缺资源等状态继续由原 UI 处理；具体配色遵循项目冷钢 UI 正式规则。 原因：颜色与样式承担既有信息角色，局部重定义会让相同状态看起来含义不同。



## 3. 按动作实际占用协调输入



- 左手施法只在实际凝聚、发射及收手阶段占用左手。近战、采集、换弹、装备、检视、ADS 等已经开始的冲突动作自然完成，再执行一次等待中的施法请求。 原因：左手仅在实际施法阶段占用，已开始的冲突动作和等待请求需要明确交接以免丢失或重复触发。

- 左手被装备长期占住时（双持手枪的副手，`AFPSGAMECharacter::IsLeftHandHeldForCast()`）不排队等待：请求直接拒绝，快捷槽提示「左手占用」闪烁＋上跳 3 秒后消失，中途转为双持的排队请求同样丢弃。只有会自行结束的冲突动作才排队。提示计时与曲线见 `FPSLeftHandNotice.h`，记录见 `Docs/Skills/left-hand-occupied-notice-20260916.md`。

- 投射物法术统一输入：点按发射；悬浮状态下长按绑定槽显示红色弹道预览（共用 `FPSMagicPreview`），松手才发射。凝聚期间的按下仍是原排队行为，菜单打开会清掉预览；释放分支必须校验该法术的 `IsAimPreviewActive()`，避免预览随投射物消失后仍触发一次施法。记录见 `Docs/Skills/magic-aim-preview-20260917.md`。

- 新增投射物法术时按 [法术弹道预览](references/trajectory-preview.md) 接入：输入契约、解析弹道预测与绘制坑（虚线节奏、勿叠暗色宽线、每帧 Flush）都在那一份里，不要另写一套。 原因：高频显示路径会放大重复计算，按变化刷新才能保留同样内容而减少无效工作。

- 施法期间阻止新的左手冲突动作；枪械可腰射，空仓自动换弹延迟到收手结束。移动、跳跃、滑铲和闪避沿用既有自由移动规则。

- 火球采用脱手悬浮：凝聚后手恢复正常动作；后续发射手势从当时的持握姿态进入，球体从当前悬浮位置发射，不重新拉回手上。其他魔法是否持续占手按其设计决定，不强制套用火球。

- 动作、发射接触和特效交接共享时钟；重定时同步业务接触点。收手从实际退出姿态和进度开始，不跳到最终姿态。



## 4. 动画与特效制作



换用现有火焰包时，先读 [原生火焰材质与 Niagara 适配](references/native-fire-vfx.md)：Cascade 参数读取、图集/动态输入、黑焰曝光及重建依赖的归档边界。



- 动作前实际查看现有参考，读取时长、帧率、接触和左右手职责。自然节奏来自起势、加速、制动、收势与肩肘腕／手指先后，不只对两个姿态作同速插值。

- 制作施法手势或处理手臂变细时，读取 [施法与完整骨段](../ue5-fps-arms-animation/references/casting-arm-volume.md)，再修改现用左臂层；保持当前 Manny 网格、骨长、权重和右手职责。 原因：手部接触、骨段长度和关节弯曲共同决定姿态，单独满足一个数值仍可能破坏人体轮廓。

- 特效资产选择、缓慢燃烧、按速度向后拖尾以及棋盘格修复见 [火球 VFX 制作经验](references/fireball-vfx.md)。先辨认现有资产的输入和依赖，再创建项目专用副本。往现有系统里加**外部包的发射器资产**前，先确认那个资产原本的生命周期与输入口径：把 Vefects 火苗套成主体用的 `Self` 曾让整条火球系统静默失效（2026-09-18，见该引用文末）。

- 同步可编辑源、作者参数和引擎导出。火球游戏内使用程序化左臂层，源 FBX 作为继续编辑的交付；不要误称正在播放整副手臂 FBX。 原因：程序化运行层与可编辑 FBX 承担不同用途，交付源不代表运行时在播放该文件。

### 冷资源的待提交编译不能当作已在编译（2026-10-15）



龙息用户实测持续“火焰准备中”，原因是 UE 5.8 的 `HasOutstandingCompilationRequests(true)` 包含 `NeedsRequestCompile()`；不能因此只执行 `PollForCompilationComplete(false)`，否则请求从未真正提交。技能后台准备改用 `PollForCompilationComplete(true)`，只提交待处理的非强制请求，并按帧轮询，不能改成运行时 `WaitForCompilationComplete` 或进场等待。适用于龙息拥有者实例和通用技能渲染准备；后台顺序、逐项超时与场景放行保持。直接证据及会话接入记录见工程 `Docs/Skills/dragon-first-cast-preparation-20261015.md` 顶部。本次不更改 R6 火焰外观。
