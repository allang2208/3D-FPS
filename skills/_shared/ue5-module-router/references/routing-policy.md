# 模块到领域的路由规则

- 项目任务先服从当前 AGENTS.md 与用户范围，模块索引只帮助确定领域。原因：旧表的 TargetSkill 或行号不能覆盖工程实际存在的技能入口。
- 有精确模块名时先查模块，再参考 Build.cs 路径与别名；无匹配时按用户实际意图选择。原因：模块所属领域可以缩小查阅范围，但普通用户不需要提供引擎模块名。
- 选择一个主要领域流程，只有跨领域工作确实需要时才补次要流程。原因：同时加载多套流程会引入重复或冲突的默认步骤。
- 工具按当前已读 schema 和操作依赖选用，不保留旧白名单或固定优先级。原因：另一套 MCP 的工具名不能代表本项目桥的能力。
- 已知参数的独立操作可批处理，依赖中间返回值时使用适用的脚本编排；脚本不是必须耗尽其他工具后的最后手段。原因：工具选择应服从真实数据依赖，而不是历史工具名称。
- 不强制向用户返回路由 JSON、置信度标签或固定澄清问题；仅缺失信息确实影响工作时询问。原因：用户需要任务结果，内部路由字段不应成为额外产品流程。
- FPSGAME 编辑器接入沿用 `Tools/AssetPipeline/mcp_call_codex.ps1` 的批次互斥和后台优先约定。原因：共享编辑器需要统一串行入口，模块路由本身不授权打开或测试编辑器。
