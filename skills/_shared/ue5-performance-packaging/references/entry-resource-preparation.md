# 进入场景前的资源准备

用于 FPSGAME 启动主界面、两档加载以及纹理池不足的处理。入口为 `UI/TransitLoadingSubsystem.*`，就绪状态由 `UI/GameResourcePreparation.*` 管理。

## 完成条件

- 地面、碰撞、导航准备与纹理清晰度是不同条件。保留现有结构准备契约，在其结束后追加资源阶段；不能用固定延时、资源路径解析成功或进度条到 100% 代替就绪。 原因：结构就绪与纹理驻留不同，固定等待或路径存在无法代表资源已可用。
- 快速档沿用逐步流送；完整档收集当前已注册、可显示的组件及隐藏投影组件的实际材质/纹理，去重并分帧处理。预建但隐藏且不投影的其他枪型不属于当前装备。
- 完整档只覆盖收集到的当前世界，不承诺整个 Content、未来装备或尚未生成区域。虚拟纹理页面仍按引擎需求流送，不能将 resource 存在写成全部页面驻留。 原因：当前收集范围有限，虚拟纹理页面仍按需求加载，资源对象存在不等于所有页面驻留。
- 普通 2D 纹理按质量与已安装的非 optional mip 判断，排除未请求的 cinematic mip；`IsFullyStreamedIn()` 不是唯一依据。检查材质 shader map、资源初始化、异步流送及实际 PSO 任务，并在短暂稳定后再次收集延迟创建的组件。
- 保留有界超时、错误名称、重试与返回入口。失败不能自动改成快速档后宣称完整准备成功。 原因：响应丢失不表示写入未执行，盲目重放可能重复创建或覆盖资产。

## 预算与生命周期

- 区分纹理池、光追几何池、整卡显存，不能关闭提示或设置无限池掩盖不足。项目完整档当前使用 RHI 报告图形内存的 45%，准备集预算上限为该纹理池的 85%；这些是策略参数，未作实机性能验收。 原因：材质观察尺度和流送密度相互关联，扩大资源池不能修正错误的纹理坐标比例。
- 资源保护应在下一次场景切换、取消和 GameInstance 销毁时释放；页面淡出不能立即释放本次驻留保护，否则刚进入就可能回退 mip。
- 记录改动前的 cvar 值；恢复时确认当前值仍是本次设置的值，避免覆盖用户后续手动调整。不要为了改预算留下永久的高优先级 SetByCode 覆盖。
- 原生 Game 和 Editor DLL 是两种链接环境。`UTexture2D::CalcTextureMemorySize(int)` 在此引擎 Editor 目标未导出，改用已导出的 `CalcTextureMemorySizeEnum(TMC_AllMipsBiased)`；单体 Game 编译成功不能证明 Editor 链接成功。

## 启动与交互

- 原地图上的不透明启动菜单可以在玩家控制前暂停世界；负责处理菜单选择的 Tick 需允许 paused tick。资源阶段要让世界/流送推进，不能以全局暂停使等待条件永远不完成。 原因：资源等待依赖世界与流送推进，全局暂停会让自己的完成条件永远无法满足。
- 玩家保护记录并恢复移动 Tick、受伤、输入、鼠标和暂停状态。键盘事件只吞掉实际处理的键，保留 Tab/焦点导航给重试按钮。
- 模式保存、跨地图沿用、取消与重试属于同一状态机。必须如实说明这是覆盖原地图的启动菜单，而非未制作的轻量独立启动关卡。 原因：启动菜单覆盖原地图与独立轻量地图有不同加载成本，交付应反映实际实现。

## 温带丘陵的异步入场

- 先确定河道与洼地对地表高度的影响。出生地表计算可以和树木、岩石所需资源的异步读取重叠。角色释放前检查出生地表碰撞与可渲染的地面材质，并从实际材质收集纹理、按可用 mip 判断驻留。 原因：地表的实际渲染与数据编码决定材质输入，不能把另一种地形后端的节点直接套入。
- 快速档等待角色周围 16 m 内树木、岩石两层的 PCG 格。从各层实际图读取二维网格大小，按圆与格子边界相交计数。草丛、灌木与远景在解除输入锁后分帧启用。全局着色器、全局 PSO、无关编辑器编译不能充当本场景的进度。 原因：生成范围与更新预算直接决定资源占用，全局重建会扩大局部修改的影响。
- 完整档按已经发出的流送句柄收集实际加载对象，同时记录最后一批是否结束。区分空批次、无法建立请求和软引用类型错误，取消或返回后释放本次持有的资源。多个 PIE 世界共用进程级预算时，最后一个使用者退出才恢复原值。
- 分别跟踪主机的出生碰撞和来宾本地的准备状态。核查延迟加入时源范围是否仍受保护，并确认结束回调不会释放另一个场景的输入锁。构建与资产登记回读不能给出实际进场秒数。 原因：源码、磁盘资产、二进制和运行效果属于不同交付阶段，需要各自的完成依据。

## 纹理预算与输入放行

完整预载从当前平台和当前材质画质档枚举纹理，对纹理去重。可流送纹理按实际请求的非可选、非电影级 mip 计算累计字节；固定驻留纹理按该质量允许的占用计。预算比较与实际 StreamIn 调用共用目标 mip 数。画质档变化时失效材质纹理缓存。

诊断时记录同一 GameInstance 的 scene_prepared、preparation_failed 和 loading_owns_input，并保留实际需求与可用预算的 MiB。相机能移动或采到 GPU 帧时，玩家输入仍可能被加载界面占用。快速档与完整档分开报告；保持完整预载约定时，先定位可分区的已注册可见组件和多余高清纹理，再决定是否调整资源或预算。
