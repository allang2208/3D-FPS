# 设施区域刷怪的实际分派

用于新增主题遭遇或用户要求排查漏刷。资料读取和制作正常进行；运行采样只按用户授权。

- 先从当前保存目录确定路线/房间，再追踪 `DungeonRunSubsystem` → 区域绑定 → `FacilityHallEncounter::Configure` → 成员表/槽位 → `FindInitialSpawn` → `FindSpawn` → deferred spawn/FinishSpawning → 死亡目标 → 闸门与共享进度。旧文档、类名存在或“开始遭遇”日志不能证明实际刷出了完整组合。
- 建矩阵记录每间房的数量、普通/精英/首领品阶、触发条件、出生区域、失败阶段、重试、击杀开门条件。只审查代码会漏掉具体尺寸和场景碰撞导致的拒绝；须明确实际覆盖了哪些层次。
- 路线 `walk_mask` 与合法出生地面不是同一语义。生态区的螺柱/根冠在通行主路外；医疗螳螂在指定床位间。只给对应槽位/遭遇使用明确的作者地面，保留整个房间边界、地面支撑、导航规格、占位碰撞和失败重试，不能全局绕过这些约束。
- 胶囊查询的有效半高至少等于半径。缚群半径/半高均 225 cm，增加 3 cm 半径裕量后，旧的离地 3 cm 被吃光，导致自身地面阻挡出生。用查询形体实际半高加离地间隙定位，并保留真实场景构造后的碰撞判定。
- 闸门关闭会改变可通行区域；检查有封门的生产构造，而非只在空房放点。医疗、生态、货运、发电、焚化、生活区及终点分别记录，不借一个主题的成功代表其他区域。
- 生活区员工保留供体行为 tag，但 `StaffLivingEmployee` 跳过供体职业倍率，避免最终配置数值被乘两次。蓝图只设 MaxHealth，当前 Health 由权威初始化。
- 护士基类还包含螳螂和盲祷者；普通员工预热池和 Rank 覆盖必须按员工成员范围限制，不能把所有 `ANurseZombie` 子类降成普通怪。 原因：继承同一基类不代表同一怪物等级，扩大成员范围会改变精英定位。
- 开门条件、区域清空和击杀奖励分开。生活区按第三间盲祷者死亡开门，服务器发布同一个队伍目标；已有服务门复制是唯一姿态写入者，较慢的场景快照不能覆盖刚到达的门动画。 原因：目标完成、区域清空和奖励各有合同，单一姿态写入者可防止旧场景快照回退门动画。

历史教训：首次静态排查遗漏了医疗第三房缚群的胶囊接地拒绝；后续隔离生产装配增加了真实构造碰撞、封闭边界和逐失败阶段记录。隔离夹具未运行地图 BeginPlay、实际追击及真实主客机，交付必须保留此边界。 原因：测试输入需要遵守真实产品条件，修改生产规则迁就夹具会改变用户行为。

## 两厅普通职员的间距与通路（2026-10-29）

- 入口为 FacilityHallTraffic.cpp，仅接待／中转两厅的普通职员槽位；护士基类中的精英不得被一并接管。通道激活、完整首波、击杀阈值、总数、奖励和特殊物种移动不变。 原因：普通槽位路由只负责指定成员，扩大到精英会改变原有波次与特殊行为。
- 初始落点与服务门增援要求两角色胶囊半径之和再加 70 cm；增援等待原门位腾空，不能为凑数量移到厅中。失败仍保留原槽位及重试。 原因：刷怪和寻路必须使用相容的身体尺寸，否则可生成的位置未必能够通行。
- 复用既有目录解析，缓存两厅 scene_keep_clear；叠加实际连接门、检修门，以及 HallStairCorner20261010 作者楼梯合同的局部范围。这里只拒绝出生和主动选择的停留终点，不修改导航网格或封堵通路；房壳／楼梯重做时同步更新该合同。 原因：出生与停留位置需要避开现有设施，但通路仍应可穿行；复用目录范围可使放置规则随场景合同同步。
- 近身且可见、同层的目标使用分散接近点；两厅共同考虑活怪和一秒有效的弱引用站位。没有攻击令牌，不改变攻击冷却／距离。无安全候选时回到原追击，不因站位失败冻结敌人。
- 沿现有 BT 更新，每角色约 0.65–0.75 秒选点；全引擎帧最多两只、每只最多四次投影，最终走原完整路径请求与退避。没有额外 Tick、全世界 Actor 扫描或常驻资源池；死亡／换目标／换图的旧站位不继续占用。 原因：本条限制的是对应对象的规模或更新成本，局部新增表现不应无界累积现有资源开销。
- 这是源码实现约束，不是拥堵或性能实测结论。构建与待用户体验状态记录在 Docs/Performance/dungeon-nonlocal-buffer-evidence-20261029.txt 第十一节。
