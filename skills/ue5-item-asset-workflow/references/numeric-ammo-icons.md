# 仅数值弹药的等级图标

FPSGAME 弹药已由数字袋管理。新增弹种时只制作 UI 图，不触发三视图、3D 包装、物理拾取或背包占格流程；玩法配置转 [数字弹药袋](../../ue5-weapon-workflow/references/ammo-pouch-and-types.md)。

同系列复用已选图标的写实纸盒、弹药材质、镜头与构图，分别生成各弹种，保留一致的留白和文字尺度。用户要求等级底色时，包装和背景都按等级调整；当前 7.62x39mm 为 LP绿、PS蓝、AP红，5.56x45mm 为 M193绿、M855A1蓝、M995红，5.8x42mm 为 DBP87绿、DBP10蓝、DBP191红，.45 ACP 为 FMJ绿、+P蓝、AP红，.357 MAG 为 SP绿、JHP蓝、AP红，图片不内嵌会变化的战斗百分比。轮廓按口径出：步枪为小口径瓶颈弹壳（5.8 与 5.56 比例接近），手枪弹是短粗直壁（.357 为有底缘），不要互相套用。老口径的运行图可能是 256x256 的旧通用图标（如 `Icons/ammo_58.png`），它只适合当占位来源，最终等级图按 1024/1254 那一档规格制作。

配置和文字先交付、图片留待生成时，走占位路径：把最终 `icon` 路径按 `Icons/<批次>/<口径>_<弹种>.png` 写进 `ammo_types.json`，路径上先放一张同口径既有图标的逐字节副本（`Icons/ammo_556.png` 一类），并在 `SourceAssets/<批次>/runtime-images.json` 记 `status: placeholder`、来源路径与 sha256。占位图不是生成图、不带等级底板，界面上的档位区分此时只来自目录的 `tier_name`/`tier_color`。最终图覆盖同名文件即可，不改目录、不改文件名；替换后把占位条目移入归档记录。

**主体要顶满画面，底板色要克制**。等级图会在两类格子里出现：弹药袋／背包的大格子（整帧照片）与长按 R 轮盘的小图标（80–96 px，代码用 `AmmoIconFramed` 把 UV 收到中间 0.82 并中性凹槽承托）。已经出现的 7.62 那套把**整块不透明等级色**当背景，缩到轮盘尺寸后主体被色场淹没；同一张图还要服务两种尺寸时，主体占画面八成以上、四周少留纯色底板，或者底板压暗、把等级色收进包装本身。三档之间要靠弹头／包装可辨——现在 5.8 与手枪三档是同一张占位图，只能靠内圈标识弧认档。

**有本口径图标就接入，没有就留空**（用户 2026-09-22 规则）。接入字段有两个，都是 **Content 相对 PNG 路径、运行时 `ImportFileAsTexture2D` 导入**：`ammo_types.json` 的 `icon`（轮盘／弹药袋，`ColdSteelStatusModel::AmmoIcon`）与 `items.json` 的 `ue_icon`（背包格／提示／强化面板）；`items.json` 里 `res://…` 的 `icon` 是 Godot 归档遗留，UE 不读。空串即无图标——弹药袋行 `if(Row.Icon)` 不加图标槽、轮盘不画图标与凹槽、排版落到纯文字分支，**不需要改代码**，所以缺图不会出现破图或空框。**禁止跨口径复用**：不能用 5.56 照片给 .45 ACP/.357/12.7mm 当占位（本轮清掉 8 处这类引用），有图就接、没图就空着，路径留作将来美术的保留位置即可。全量对账与保留位置见 [弹药图标接入](../../../Docs/Combat/ammo-icon-wiring-20260922.md)。

透明背景和有色底板是不同交付。生成器画出棋盘格不代表真正的 alpha；用户改选有色底板后，以最终有色版本为准，旧透明尝试仅作归档来源。保留提示词、最终 PNG、运行相对路径和散列，不重跑随机生成来冒充相同原件。

图标、弹药袋卡片及轮盘的语义配色来自 `ammo_types.json`。轮盘上等级色只作标记（内圈标识弧与图标底板），扇区本身是中性玻璃；弹药袋卡片仍用等级底色。模型/弹药数值不根据图片标签自动推导。图片来源记录不等于可公开再分发许可；沿用项目 Content 的本地恢复边界。
