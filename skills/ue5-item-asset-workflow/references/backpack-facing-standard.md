# 背包统一朝向与背包栏正面展示标准

2026-10-24 制定，适用于 FPSGAME 所有现有及新增背包装备，包括单肩包。此标准定义制作结果，不自动触发重制、测试、运行游戏或重启编辑器。

## 正面定义

- **正面＝穿戴后朝外、用于辨识款式的主面**，通常有外袋、包盖、翻盖、扣具或正面织带。背包栏默认展示此面。
- **背面＝贴身体的一面**，通常有贴背垫、肩带根部、背负框架。不能把“角色的背后”与“背包的背面”混为一谈。
- 顶部为提手、顶盖／卷口方向，底部为包底。斜挎包以外侧翻盖／主袋面为正面，带子自然收整在包体后方或侧方，保留其单肩结构，不遮住识别面。
- 不按模型文件名里的 Front/Back、源相机或生成器朝向直接判定；以实际结构辨认，并在制作回执记录正面识别点。

## 展示源坐标

| 规范空间 | 约定 |
|---|---|
| 外侧正面法向 | −Y |
| 贴背面法向 | +Y |
| 上方 | +Z |
| 宽度轴 | X |
| 尺度 | UE 厘米，保持模型真实比例 |

这是**背包自身的展示源坐标**。穿戴骨骼网格使用各身体的原生参考空间；男女角色的安装旋转、背带蒙皮、衣物偏移与摆动参数继续按真实接触标定。不能为统一图标，整体旋转已经适配的身体／背带，或将图标 yaw 直接写入 `rigid_pack.rotation_quat`。

源模型方向不合约定时，在独立修订的展示源上做刚性旋转并应用变换，同时处理位置、法线和切线；UV、厚度、材质及非对称结构保持原样。禁止用水平翻转 PNG、负缩放或双面材质掩盖朝向问题。GLB 对象可能处于四元数模式，应使用实际矩阵／四元数变换，不能只修改未生效的欧拉角字段。

若穿戴本身也反向，按背包工作流同步修正包体、缝接点与背带；图标朝向修正不能充当穿戴修复。

## 背包栏构图

- **统一正面、正交、平视、顶部朝上**。默认不使用三分之四侧视、俯视、透视、斜放或额外翻滚；立体感由模型、法线和照明提供。详情预览可自由旋转，背包栏缩略图仍保持正面。
- 使用完整的独立展示件，保留包盖、外袋、侧仓、提手与肩带身份。带子不能穿过包体或摊开占满画布；不能裁掉侧仓来扩大主袋。
- 保持原比例，按最终可见轮廓居中；占满画布的限制轴约 **91%**，其余留白由占格宽高比自然产生，不拉伸填格。
- 透明 RGBA 背景，不把地面、投影底板、稀有度边框、文字或格线烘入图像。沿用当前装备图标棚的照明、曝光及材质读取，避免每款另设一套曝光。
- 基准高度 320 px，宽度为 `round(320 × grid_w / grid_h)`：2×3→213×320，3×3→320×320，3×4→240×320，4×4→320×320。用户在库存中旋转物品时，由 UI 旋转同一张正面图，不重新选择模型的侧面。

## 与当前 UE 消费者一致

`ColdSteelEquipmentIconMesh()` 优先读取物品的 `ue_equipment_icon_mesh`，否则由 `StaticOutfitMesh()` 读取 `player_body.outfits[id].inventory_static_mesh`，最后回退 `world_static_mesh`。`inventory_static_mesh` 用于需要规范旋转的独立库存展示件，不改变第三人称或拾取源；旧物品实例同样按定义 ID 使用此字段。以实际选择的路径为准，不能只修没有被使用的模型。

规范展示源在当前 `ColdSteelEquipmentIcon.cpp` 中采用：

| 参数 | 值 |
|---|---|
| `ue_icon_pitch` | 0° |
| `ue_icon_yaw` | −90° |
| `ue_icon_roll` | 0° |
| 拍摄方式 | 正交，相机位于模型 −X 侧、朝 +X |

这里的 −90° 是**图标棚对规范展示源的旋转**，不是原模型正面法向。七款背包目录使用上述消费者默认值。旧显示源如不符合 −Y 正面，应修正展示源后沿用统一姿态，不长期累积各款不同的图标角度来互相抵消。

正式 PNG 优先由同一 UE 图标棚、同一显示源和同一姿态导出。统一制作入口为 `Tools/BackpackIcons/run.ps1`，当前批次覆盖七款；`-Definitions` 可限定物品。底层 `ColdSteelWeaponIconCatalog -Definition=<物品ID>` 仍支持单款，也支持带引号的 `-Definitions="ID1,ID2"` 及独立 `-OutputDirectory=`。命令行批量列表必须保留引号，UE 默认参数解析会在无引号的逗号处截断。默认导出列表只列入登山包，不能把无参数运行视为全款已覆盖。该入口用于获授权的图标制作，不是游戏测试。

Blender 的独立棚拍可用于制作候选；其相机角、投影左右、构图及色彩响应必须与 UE 正式路径对齐后才能替代正式图。不同坐标系的“同名视角”不自动等价，不能事后镜像图像来凑一致。

## 一次更新的完整范围

1. 列出所有 `equipSlot=backpack` 的目录项、被选择的显示源、角度覆盖、`ue_icon` 及固定命名回退路径；新增背包同样纳入。
2. 确认展示源的真实正面；将姿态、显示源版本和图像作为同一制作修订。只改源脚本不表示 UE 包已保存。
3. 从当前显示源导出 `Content/ColdSteelData/Icons/<id>.png`。如果 `ue_icon` 指向另一路径，同步该路径；旧物品快照仍引用的有效路径也须读取到相同正面版本。
4. 各款制作器与发布器复用该正式出图结果，不能在后续发布时把旧的斜角／背面 `source_icon.png` 再写回活动目录。回执关联物品 ID、显示源、姿态和 PNG 散列。
5. 库存、装备栏、仓库、商店、物品详情及拖拽预览中凡使用同一物品缩略图的入口，复用相同正面身份。只检查本次授权范围；不能从文件一致推断这些界面已逐一运行验收。

`FPSBodyEquipment::OutfitDefinitions()` 当前每进程缓存显示源；实时图标和 PNG 刷子也有缓存。交付区分文件落盘与当前进程已刷新，必要时告知用户重启编辑器／应用，不自动重启。

## 标准与实施状态

2026-10-24 仅制定标准并记录五款差异；2026-10-25 已完成七款统一正面制作，详见工程 `Docs/Characters/backpack-icons-front-20261025.md`。行军背包和登山包使用独立规范展示件，其余沿用已正确朝向的实际源；七张正式 PNG 由同一 UE 图标棚输出并落盘。原始盘点保留在 `Docs/Characters/backpack-facing-standard-20261024.md`。这次完成的是资产与图像制作，没有运行游戏或联机验收；新增背包仍须辨认真实正面并登记统一制作清单。


## 当前源与贴图核对边界

七款统一生产配方为 `SourceAssets/BackpackIcons20261025/FrontR1/plan.json`；旧发布器不得将早期三分之四图覆盖回正式 PNG。独立展示模型旋转与穿戴 `rigid_pack` 分开保存。背包浮窗仅保留 `+N格子（N行）` 与夹层 `横×竖`，不重复分类和装备槽位。

获授权检查贴图时，从实际目录、当前展示源、材质实例父级和纹理参数追到文件；NullRHI 下 `get_used_textures()` 为空不足以判定缺图，可读材质表达式与父级链确认引用。此类引用核对不能代替画面验收。
