# FPS 玩家全身表现：独立于第一人称手臂

适用：在保留已采用手臂、枪械和动作时序的 FPS 中加入第三人称、世界装备与后续联机/换装接口。实现入口为 `Source/FPSGAME/Characters/FPSPlayerBody*`，配置为 `Content/ColdSteelData/player_body.json`。

## 表现与玩法的边界

- 第一人称继续使用原手臂与精细动作；第三人称用独立全身骨架、移动循环和简化上身动作。两套姿态可以不同，但开火、接触、施法释放和装备完成的业务时钟必须一致。
- 从实际动作执行组件读取阶段、进度、接触/释放窗口和左右手状态。不要用“左手忙碌”推断施法，该标志也可能包含枪托近战；施法阶段应向施法组件查询。
- 移动与上身动作分别记录。滑铲/闪避可以与持枪并存，翻越占用双手时隐藏世界武器。双持的装备、换弹、射击和砸击按手记录，位移和旋转必须作用到同一只手。
- 表现组件不结算伤害、库存或弹药。已有复制字段和 `OnRep` 只构成联机接口；本地表现成功不等于客户端输入、服务器裁决和远端角色已完成联机。

## 脚底、步频和蹲姿

- 胶囊中心到脚底的偏移须同时设置在 Character 默认 Mesh 和运行时初始化；仅在 BeginPlay 下移 Mesh 会在蹲起恢复默认偏移时重新浮空。更新初始 Mesh 偏移缓存，保留角色本身的蹲起插值。
- 先读实际源动画时长、循环与脚步标记，再按速度选择步行/慢跑并匹配相位。不能让几个不同周期的循环共用任意秒数，或只靠大幅提高播放率追速度。
- 蹲姿需要协调骨盆、膝盖弯曲方向和足部目标；单独下移根骨会把脚带入地面。将源足部目标转换到统一组件空间后解腿部 IK。

## 中断、回位和接触

- 施法进入 Recover 时捕获上一帧实际手部变换，按剩余恢复进度混合到当前持握目标；提前中断不能从完整蓄力/推出姿态开始恢复。避免通用短过渡提前覆盖整段 Recover。
- 翻越跟随原执行器的接触权重。Release 表示结束离手，而非从该时刻才开始离手；中断后立刻停止追踪旧墙面目标。
- 世界装备可保留与手部回位相配的短暂收起窗口，避免武器在手尚未返回握点时突然出现。

## 世界装备、可见性与阴影

- 从装备源复制世界武器与实际配件，排除手/袖/手套材质段；`Handguard` 是护木，不应按包含 `hand` 的字符串误隐藏。
- 源 viewmodel 的握点逆变换可能携带 100 倍导入缩放。转换到全身手骨时显式处理缩放，静态工具保留自身建模比例。
- 主手、副手武器及子配件都记录所属手。施法收起副手时，一起处理配件、普通阴影和隐藏阴影。
- owner 可见标志与阴影策略分开写；只在值改变时调用 setter。第三人称可见身体正常投影，第一人称诊断开关只控制本地隐藏身体；最终阴影策略集中应用，避免相机更新覆盖装备收起策略。
- F6 后移的是观察相机。交互距离仍从玩家眼部计算，不能把相机后移距离加入拾取距离。

## 皮肤、衣物和脸部扩展

- UE 模板作为本机骨架与动画来源；记录来源及许可边界，公开源码不附带未经核准的原始二进制资产。恢复说明须列出 Manny/Skeleton/动画/材质依赖，脚本只补缺失输入。
- 皮肤使用独立 Mesh 副本和自有材质，保留原 Manny 与第一人称资产。编辑器 Python 修改材质槽结构后，将结构写回数组并保存 Mesh，单独保存材质不能保证槽绑定落盘。
- 共用骨架衣物可由 Leader Pose 跟随身体，用配置隐藏覆盖的身体材质段；切换/脱衣时恢复原材质和可见段。需要独立骨骼、布料或脸部动画的部件须另外设计，不把 Leader Pose 当作完整换装/表情系统。
- 第一人称衣袖/手套与第三人称衣物分开配置，避免换全身皮肤时顺带改掉已采用的手臂。

## 交付边界

源码构建、资产落盘和游戏画面分别报告。默认不启动 PIE、不截图、不验收；仅用户明确要求相应检查时，才覆盖站立/蹲起、方向移动、单/双持、中断与视角切换。历史构建记录不能当作后续独立发布树已编译的证据。
