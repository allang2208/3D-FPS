# 已支付工件、评分品质与联机结算

适用于 FPSGAME 的木工、锻造及同类先扣料后操作的工作台。先读现有工件系统与库存事务，复用它们的语义，不把小游戏完成回调直接改成发物品。

## 工件生命周期

- 开始时原子保存扣料结果、唯一工件 ID、实际支付材料、产物快照和配方 ID。恢复同一工件不再扣料；通用直接制作入口也必须拦截小游戏专属配方，避免绕过加工。
- 调整、加工、暂停与结算分别建模。调整期间是否计时由玩法规则决定；暂停要保存加工掩码、板材姿态、撤销状态和已用时间。版本化快照写入同一工件，不能只保存 UI 进度。
- 结束后回到管理面板。领取成功才清空工件；背包放不下保留可重试结果。废弃按历史实际支付量逐项向下取整一半，与材料放置、清空工件一起原子提交，不按新配方重新算成本。
- 预览、按钮可用性与正式提交使用同一材料放置函数和成功返回语义；空格、堆叠与返回码要读库存实现，不能凭函数名假定。

## 品质只修正指定属性

- 木工现行公式为 `0.75 + 0.005 * clamp(score, 0, 100)`：50 分不变，80 分 +15%，100 分 +25%。通关阈值和品质得分是两套量，不把 80% 通关线误当成 80 分。
- 成品 JSON 保存版本、得分和属性通道；求值时由得分重算倍率。不要反复修改原始伤害，否则存档恢复、预览刷新和装备切换可能重复叠加。
- 弓只作用于物理伤害分量；法杖只作用于该法杖贡献的魔法攻击。角色基础魔攻、魔法书、其他装备和法杖物理敲击不受此木工倍率影响。面板、投射物与服务端伤害共用属性求值入口。
- 已完成未领取的旧工件可按保存的得分补品质；已领取且没有历史评分的物品不臆造分数。旧版部件仍有改造引用时保留定义与制作输入，不因新入口只做整把武器就删掉。

## 联机沿现有权威链接入

- 服务端根据加工状态计算评分、写入成品与结算材料；客户端提交输入和意图，不提交可信品质值。恢复、领取、废弃绑定工件 ID。
- 输入序号、库存修订、分块状态与当前 Pawn 身份共同约束异步回包。角色重生或切换后，旧工件回包不能覆盖新角色状态。
- 镜像与库存回执同时覆盖工件、品质和成品 JSON；比较变化时不能只看工件 ID。客户端上传已有物品时保留服务端记录的品质，避免旧上传覆盖已结算结果。
- 断线、离台、关闭与队伍切图走当前宿主的停止/保存路径。保留并行联机修复，不复制一套独立会话框架。

源码入口：`Building/WoodworkingSystem.*`、`WoodworkingJob.cpp`、`WoodworkingQuality.*`、`Multiplayer/ColdSteelWoodworkingNetwork.cpp`。UI 对齐见 [工作台面板](../../ue5-ui-umg-slate/references/crafting-workbenches.md)。

## 资产与交付边界

旧目录可能仍是当前几何或材质的恢复输入，先沿制作脚本的读取路径判断废弃范围。公开源代码仓库保留脚本、参数和出处，原模型、贴图、UE 资产、构建产物与日志按仓库规则留本机。共享联机框架未发布时，记录所需宿主基线并交付接入补丁；本机完整工程构建成功不能证明公开子集可独立构建。默认不启动编辑器、游戏或联机测试，按用户本次授权执行。
