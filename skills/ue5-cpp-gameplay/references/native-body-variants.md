# 原生身体变体、MetaHuman 与家具相机

适用于已有玩家换装系统加入另一原生身体。FPSGAME 的 Jason/Kaitlin 为案例，制作与公开恢复入口见 `Tools/KaitlinPlayer` 和 `Docs/Publication/Kaitlin20261024/README.md`。默认后台制作，不因本参考启动游戏或检查。

## 来源与装配

- Fab 下载的 `.mhpkg` 可能只是可编辑角色预设，不能当作已经装配的身体、脸和毛发。保留原包、来源散列及已绑定制作工程；原包、DNA、几何、贴图和 UE 包不随源码公开。
- MetaHuman Creator 的 Optional 衣橱/毛发依赖必须可用。缺依赖时加载会丢弃选择，不应保存这一状态作为完整导入。自动绑定需要授权时沿已有流程处理；已绑定预设继续装配无需重复绑定。
- 装配质量、输出 LOD 和作者展示条件分别记录。Kaitlin 使用 Optimized High，近景脸实际从原生 LOD1 起步。文件和材质与装配工程一致只证明复制连续性，不能证明与 Fab 预览的脸型相同，也不能仅凭优化档位认定差异原因。需同角度游戏画面再区分五官几何、表情、LOD、材质与光照。
- 已穿默认服装的装配身体可能裁掉胸腹等表面。换装母版应来自完整原生身体，沿原骨骼和实际顶点对应建立覆盖分区，不能拿被裁切的网格当裸身。

## 身体切换与外观生命周期

- 用稳定头型/身体 ID 选择已发布配置；身体、全身动作、衣裤/鞋靴配对、背包、帽子、本人视角和皮肤都属于同一变体。旧男性根配置保留，缺失女性配方不能用男性回退冒充适配完成。
- 切换异步加载目标身体、动作和当前穿戴配方，避免拉取所有武器/衣物。回调绑定弱对象和请求编号；换装/复制乱序到达后读取当前槽位，不提交旧快照。
- 换骨架前释放旧服装跟随者、第一人称身体、材质覆盖、姿态回调和挂载缓存。重新绑定骨索引、动作表与身体相关镜头；上一次身体的数据不能依靠“名字相同”继续使用。
- 头脸是独立骨骼件，身体驱动共享颈头链，脸部专用骨骼保持自身参考偏移。保留原生面部 RigLogic；只有确认与身体重复驱动时才关掉额外头部 IK。
- 毛发绑定、材质覆盖、LODSync 自定义映射和 SimulationSetup 都属于原生装配合同。Kaitlin 当时映射为 `[1,3,5,7]`，长发局部骨为 `head`，线/角速度比例为 0.5；这些值来自该装配，不能推广成所有角色常量。逐组物理与组件全局覆盖分开；本机 UE5.8 未启用覆盖时 `SetEnableSimulation` 不生效。

## 家具与检查边界

- 按所有 `Rest.<Kind>.<Enter|Idle|Exit>` 建覆盖表，比较实际源路径和包散列；已保存且 `remaining=0` 的批次仍可能被后续源修订淘汰。复用未变化资产，变化角色另存修订，发布前重新比对源。
- 家具相机从目标身体的实际动画和原生眼位生成，按选中身体缓存轨迹；不能把男性镜头坐标直接称为女性相机适配。业务阶段和服务端时钟保持共用，身体切换时更新采样数据。
- “能按 E”不能证明 StartRest 已进入阶段。需要排查时分别看交互门槛、实际 Rest 状态、运行 AnimInstance 的 Clips、图层权重，再看原生后处理。隔离图能坐卧不等于实际 E 键/联机通过。
- 2026-10-24 已完成本机构建与资产保存，隔离图中女性 Chair/Sofa/Bed 姿态可播放；真实主客机、接触穿模、脸部相似度及头发距离变化未据此验收。
