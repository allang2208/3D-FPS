# 饥饿、水分与 SAN

FPSGAME 的生存真源是 `Source/FPSGAME/Survival/FPSSurvivalComponent` 与 `FFPSSurvivalState`。HUD、档案、消耗品、喷泉和怪物攻击读写同一状态，避免在显示层另设一套数值。默认最大值 100；衰减系数在 `Content/ColdSteelData/survival.json`，启动时读取一次。

- 复用 0.25 秒组件调度和拥有者复制。按真实 DeltaTime 计算；跨越赐福到期或 SAN 耗尽时，按边界分段积分。资源耗尽后的损血从实际耗尽时刻累计，不能将整帧都算成耗尽时间。
- 饥饿或水分任一归零，每满一秒损失当时最大生命的 10%；同时归零共用一个计时器。该损血区别于敌人攻击，不触发普通受击的短暂无敌，也不重复扣 SAN。
- SAN 为 0 时，食水消耗乘 2，六维总属性乘 0.5。与感染和清泉赐福按倍率相乘；赐福乘 0.9，因此两者并存时消耗为基础的 1.8 倍。SAN 大于 0 后解除。
- 六维惩罚在基础、装备、附魔及属性型技能加成汇总后计算；不改写原始分配点或装备数据。`EffectiveAttributeMultiplier()` 是组合属性倍率，保留 `InfectionAttributeMultiplier()` 的单一感染语义。资源上限、武器公式、加工预览和提示使用一致口径；剔除技能加成时也用组合倍率，避免重复减半。
- SAN 归零／恢复边界立即通知所绑定角色的档案模型和状态效果；普通数值同步复用既有自动保存调度。重算上限并夹紧当前生命、魔法、耐力，恢复上限不直接填满资源。
- 新属性型耐力公式如果仍属于其他未发布改动，发布其 SAN 乘区补丁和依赖说明，不将该耐力功能混入本会话提交。
- 角色重生和原地复活均将饥饿、水分、SAN 设为 60。切图／读档保留实际剩余状态；归零惩罚由当前 SAN 推导，不保存额外的重复惩罚标志。

清泉赐福刷新至 720 秒，不累加时长或倍率。喷泉使用统一眼部视线与互动距离；大水盆不能用模型中心距离判断是否可喝。成功后捕获实时状态再保存，并复用饮水音效接口。具体制作与发布边界见 `Docs/UI/survival-consumables-publication-20261003.md`。默认后台制作、构建、落盘；游戏效果交由用户测试。
