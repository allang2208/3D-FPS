# 客机档案消毒、服务端攻击回执与联机准入

用于监听服务器联机的“客机整档上传 + 服务端命中裁决”改造。来源是 2026-10-19/20 的联机排查与修复批次；只记录可复用规则，不代表已编译或已联机验收。不要因读到此文自动启动编辑器、构建或测试。

## 先消毒，再合并，最后才建立影子档

客机上传的是**数据**，不是可信状态。整档进入 `ApplyGuestProfile` 后应先复制到临时档、执行主机侧 `Sanitize`，通过后才走原来的合并/影子档建立；不要在合并过程中边用边校验。

- 目录是权威：定义必须存在于主机目录，实例数值字段以目录调谐为准；近战基础伤害/攻速/削韧、弓的拉弓与伤害、枪械的伤害/换弹/射程/容量都属于目录字段，不应由实例 `Data` 覆盖。
- 只钳制不够，还要**按目录归位**。单纯 `Clamp(0, catalog*4)` 仍允许四倍伤害；对目录所有者字段应直接写回目录值，强化/附魔/改装由各自系统另行叠加。
- 服务器计数器不是客机状态：`ServerSoulCredits/ServerSoulDebits` 等水位在合并时用上一份影子档覆盖，首档直接归零；否则伪造水位可抑制后续服务器奖励。
- 结构上限放在消毒入口：物品数量、等级/经验、未分配点、属性总值、资源上限、仓库页数交给既有 `Validate`；物品 InstanceId、JSON 长度、堆叠、弹匣、网格占用逐件检查。
- `NetView.*` 是主机侧容器投影，上行前要剥离或清空；否则客机可把界面视图容器写进共享容器。
- 消毒失败要显式拒绝并回执，不能静默截断后继续采用——静默截断会把“部分物品丢失”伪装成正常上传。

## 每种攻击一条服务端回执

客户端 `AttackMeta` 只是语义请求。重击、冲刺、上挑、旋风、快速近战、格挡/弹反、裂斩、弓，都要有服务端自己记录的回执窗口，且窗口绑定武器 `InstanceId`。

- 重击：记录服务器蓄力起点与所需秒数，完成蓄力才打开释放窗口；释放时在服务端扣耐力，窗口给 0.5～0.75 秒。
- 不同 Actor 的可靠 RPC 可能乱序：释放 RPC 与命中/裂斩 RPC 不在同一通道。只等释放包会误拒合法攻击；应允许“命中先到”时把**已完成的服务器蓄力**转换为一 次释放回执并扣费，之后到达的释放包不重复扣费。
- 一次性窗口不要被复用的方式：同一蓄力只允许消耗一次；裂斩的节流间隔应大于释放窗口，避免一个窗口发两道波。
- 冲刺：移动通道授权 `EFPSMeleeMove::Dash` 时记录窗口，命中报告再查“最近授权的确实是 Dash”。
- 窗口接受的 `EFPSMeleeMove` 种类必须覆盖客户端**实际提交**的种类——弯刀冲刺走 `AirMomentum` 不是 `Dash`，只认 Dash 会把每次合法命中都拒掉。把一种近战移动拓宽到新武器族是四个面一起改：`AuthorizeMeleeMove` 的物品门、被接受的 move-kind 集合、服务端动量施加 `BeginMeleeDashMomentum`、命中表的 `MaxRange`/伤害分支；漏任何一面都是"动作能跑、命中全拒"。效果位（如 `0x80` 流血判定）也要覆盖新物品类，否则新武器吃不到旧词条。
- 格挡/弹反：重抬盾不能重置弹反窗口。服务端拒绝“已举盾时用新序号重抬”，并记录放下时间；再抬必须经过 `RaiseSeconds+LowerSeconds`。同一轮举盾只允许一次完美弹反，弹反成功置一次性标志，放下/重新举盾才清除。远程护盾组件要有同样的 `RemoteGuardLoweredAt + bRemoteGuardParried` 双门控，否则切盾可反复拿满层。
- 弓：`ServerSetBowDraw` 建立会话，射击时必须仍在同一会话、同一弓实例，`DrawAge` 落在按蓄力比例计算的下限与 `DrawSeconds+1.25s` 之间；无会话直接拒绝。

## 弹匣账本：客户端只报“请求量”

服务端维护 `(InstanceId, MagazineAmmo, ReloadReadyAt, LastShotStamp)`，不要相信客户端弹匣或 `bFiredRound`。

- 是否“真正开枪”由装备与攻击类型派生：近战/工具不算开枪；枪、弓、法杖算；快速近战/旋风不算。客户端清 bit 不能变成免费射击。
- `Rounds/ConvergenceRounds` 只作为请求量，按服务端容量与当前弹匣钳制后扣费；汇聚倍率也由服务端按实际扣弹数复算。
- 同一发的多弹丸/穿透目标要去重：用客户端开火时刻 + 服务端时间双条件，不能只看客户端时间戳（可伪造固定值）。
- 空仓进入换弹锁；死亡重生或换到新武器实例时重置账本，否则新命第一次射击会被死亡前余弹卡住。换弹/拾取回灌仍是需要实测的薄点。

## 连段与语义位都要服务端重建

- 连段阶段由服务端计数器推进，客户端上报的阶段只能“不大于服务端阶段+本次推进”；同一挥砍命中多个目标只推进一次（按开火时刻去重），换武器重置。
- 连段只能在几何/回放全部通过后提交，否则被拒的伪报也会把计数器推到第三段。
- `bMelee`、`AttackForm`、`bFiredRound` 由装备推导：枪械不能靠伪造近战位跳过弹药；攻击形式按武器族给（剑/弓→Blade、锤→Blunt、枪/杖→Impact、徒手/快战→Blunt）。
- 无武器声明的攻击只有徒手与快速近战；带 `UnarmedPunch::AttackMeta` 却声明了武器、枪械使用 cloven、非双手剑使用上挑/重击/裂斩，都应在服务端拒绝。

## 几何、骨骼与器官池

- 所有命中申报的服务端 LOS 从**服务端眼位**到命中点做遮挡；投射物也检查直线视线。客户端 `AimOrigin` 只能用于对账，不能定义回溯线段。
- 骨骼名不复制客户端值：在命中点取服务端最近骨骼，再走 `ResolveNetworkHit`；人类弱点用 `ResolveCriticalHit` 再校验一次。
- 器官池/多段怪物（如 `ABoundCongregate`、`AHeQueMonster`）需要骨骼才能解析器官：先用服务端最近骨骼，失败再按身体接触重试；预览类 Actor（如 `ARootCrownRigPreview`）走自己的 `ResolveRemoteContact`。
- 回溯用服务端眼位 + 命中点，目标胶囊插值到开火时刻，容差按胶囊半径+采样位移余量。

## 反序列化与 RPC 限流

- 属性归档在读取容器计数时就要设上限（数组/Map/Set 元素数、字符串字符数、Mask 字节数）；超限直接让整包失败，不能截断后继续反序列化。
- 客户端可每帧调用的“探测类”RPC（如翻越）要有令牌桶：按时间回充、容量有限，过期序号也收费；否则它就是一个免费 CPU 探测通道。

## 房间准入

- 监听房间至少要有口令和服务端人数上限：`InitGame` 解析口令，`PreLogin` 比对并拒绝，`MaxPlayers` 在会话创建后、登录前、`BeginPlay` 三处都钉住。
- 口令只允许字母数字，避免 URL 选项注入；创建时留空自动生成并显示/持久化；连接超时不要为了编辑器首载无限放宽，已连接无响应的超时要收紧。

## 排查与交付口径

先按“入口 → 服务端回执 → 服务端复算 → 客户端回执”四层列覆盖项，再分别记录源码阅读、编译和真实联机测试。服务端回执能拒伪报，不等于动作、音效、表现已同步；`未编译、未测试` 要明确写出。多个并行会话共用工作区时，精确暂存本次文件，避免把未验收模块一起发布。
