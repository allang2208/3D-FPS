# 通用游戏模型生成工作流

用户于 2026-09-13 指定本流程为后续配件、枪械、怪物、建材等模型生成的共同标准。个人技能为维护源，`D:/FPS3D/FPSGAME/skills/asset-model-workflow` 为工程镜像。

**执行边界：默认不主动测试、验收、启动游戏或生成验收渲染。** 资料读取、制作、必要构建、导出、导入及已授权接入照常完成；用户明确要求的预览、排查、测试只按指定范围开展。记录流程不触发生成任务、远端部署或资产替换。

## 1. 参考与三视图先行

- 先确定对象身份、用途、目标引擎、尺寸、朝向、关键孔洞/细杆、分件和连接面。读现有宿主与源资产；配件读取实际枪体和挂点，怪物读取体型及动作参考，建材读取模块尺寸和拼接边。
- 默认先制作同一对象、同尺度、同姿态的三视图。按最能解释结构的正/侧/背或正/侧/顶选择，保留对称与非对称特征。只有单图时，遮挡侧是设计推断，不能称为精确还原。
- 栅格图制作使用 imagegen 技能及当前可用图像工具，保存原图、提示词和最终参考。去掉 UI、文字、背景底板及投影干扰，保留目标孔洞、透明区域和细杆。
- 拼图必须切成独立视角，再分别做前景处理，接入真正多视图节点。明确每张图的空间方向和节点输入映射；文件名 front/back 不足以证明模型真实朝向。裁切尺寸由本次图片决定，不照搬旧案例坐标。
- 三视图与目标接口冲突时先修参考；机械件的准确接口、建材的平直拼接面由本地建模保证，不寄希望于加步数。

已有模型的枪械配件 UI 图标使用 [改造配件图标标准](../ue5-weapon-workflow/references/attachment-icons.md)：按当前实际模型渲染，采用用户已接受的水平左向、透明背景与单件表达；不重新用概念生成图代替已确定的模型。

## 2. 生成与小批候选

- 当前默认生成起点为 **TRELLIS.2 三视角**；用户指定其他模型时遵从。先读取当前工作流、节点定义和可用服务以完成调用，历史地址/节点安装不等于当前可执行。具体入口见 [5080 案例与工具](references/5080-case.md)。
- 精细候选参考起点：TRELLIS.2-4B、1024_cascade、结构分辨率 64、结构/形状/纹理 16/32/24 步、4K 纹理、50 万面母版导出目标。它是后握把成功生成的档位，不是跨类别最优参数，也不表示实际面数恰好 50 万。
- 有意图的机械孔洞保留：不要盲目开启 fill_holes 或 keep_only_shell。怪物、岩石等按自身封闭表面需求决定，不能将机械件开关推广成全局禁令。
- 先做少量候选，冻结参考与主要参数，只改变 seed。用户允许继续抽取时分批推进，保留候选与选择理由；同类缺陷反复出现就修参考、改变视角或本地重建，不无限抽种子。用户选中后冻结母版，后续适配不擅自换造型。
- 三个优化方向分别使用：结构分辨率 32/64/128 是结构探索；Pixal 单图是独立生成路线；MultiViewRefiner 是已有几何的细化。不要把三者串联当成强制步骤，安装完成也不等于效果已证实。128 和其他高档按显存条件试用，不默认保证 16GB 可完成。
- 记录完整 API 工作流、模型/节点版本、视角、seed、prompt_id、历史和输出。服务无新日志不直接判死；结合当前任务状态决定等待或处置，不重复提交同一已在运行的任务，不清空他人队列。

## 3. 几何、材质与装配

- 保存原始几何和带纹理母版，再另做游戏低模/LOD。增加导出面数、细分或平滑不能恢复已缺失的孔洞、薄片和规则棱线；这些部分局部重建。分辨率、采样步数、输出面数和纹理尺寸分别控制不同问题。
- 减面依据实际视距、剪影和变形需要，保住孔洞、安装边、轮廓和材质分区；精细纹理由母版烘焙到低模。来源表面有重叠/坏法线时先整理再烘焙；仅有颜色图不能称完整 PBR。
- 局部编辑保留未改区域的 UV、材质、法线和权重。新补面有自己的有效 UV/切线；避免用全网格重建破坏已有自定义法线。导入发现近零切线或重绑定警告时记录并针对性处理，不宣称已通过着色/动画验收。
- **装配基准是实际连接面，不是整个模型的包围盒或最高点。** 记录物体局部轴、单位、目标接口与根骨变换，每个宿主独立适配。翘尾、尖端、脚趾或装饰突出部不能冒充接触面。
- 空隙来自形状不匹配时，局部调整连接头并做与宿主轮廓一致的过渡；只移动整件可能破坏握持或动作。保留已认可的主体与握持区，以平滑过渡修接头。具体毫米数和骨骼缩放抵消量只属于对应资产。
- 枪械与配件：机械活动件独立，原厂件以独立对象/材质分区支持替换恢复；沿真实挂点驱动。材质以每把枪当前主体为准，保留其他任务已做的材质。
- 怪物：形状认可后进入专用重拓扑、骨架、权重和动作流程；AI 网格不等于可动画成品，保留体型、支撑点和攻击器官身份。
- 建材：结构模块以明确尺寸、网格步长、枢轴、平直拼接边和碰撞为准；生成模型提供外观细节，不能直接当精密模块。砖石等原料道具走物品分支；可重复墙板/梁柱走建筑模块分支。

## 4. 接入与交付

- 按已授权范围接入对应 ID、材质、碰撞、挂点、存档及打包目录；生成授权不自动扩大为替换所有既有资产。涉及玩法、动画或建筑放置时转对应领域技能。
- 资产被占用时，不关闭用户/其他任务的编辑器或强行覆盖。可在独立修订路径完成导入，再精确切换运行引用；保留旧资产及来源，避免覆盖并行材质修改。原生改动完成必要编译，使用独立模块后缀。
- 交付原图/三视图、候选与选中版本、母版、可编辑源、游戏导出、作者脚本、导入回执及实际运行引用。原始参考的权利不因 AI 生成自动改变，复用许可与公开分发许可分别记录。
- 分开说明“已生成、用户选中、已导入、已编译、游戏已测试”。用户要预览时给实际模型渲染，注明 Blender 源模型或引擎画面，不能拿概念图替代；未测试交由用户测试，不把历史通过记录套用到新资产。

## 已确认的生成器切换案例

手电在 TRELLIS 候选与本地硬表面重建后仍被用户否决，改用用户指定的混元 3D 3.1/PBR 后获游戏接入认可。参见 [战术手电案例](../ue5-weapon-workflow/references/tactical-devices.md)。不要把这一次选择升级为所有资产的默认生成器；保留新旧来源、最终母版及材质分区。

## 白模光滑、着色后扭曲的处理

用户要求排查时，冻结同一网格、相机和灯光，依次关闭结构法线、颜色贴图，再用常量材质比较；同时比较 raw、纹理导出与修整版本的几何。纹理导出可能包含减面，不能将前后差异全部归因于贴图。低反光材质只会弱化起伏，不修复孔洞和轮廓。法线重算、加面或提高纹理分辨率也不能保证修复形状；根据定位结果决定材质修正、局部制作或生成重抽。该诊断只在用户授权时执行，不成为默认验收。案例见 [5080 案例](references/5080-case.md)。
