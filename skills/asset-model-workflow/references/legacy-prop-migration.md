# 旧项目道具迁移：祭坛、门与可开盖容器

用于从旧项目图片或 Blender 源迁移可交互道具。本文沉淀制作和接入经验；资产保存不代表视觉／运行验收，不自动触发测试或打开编辑器。

## 源对象与交付身份

- 优先从实际配置引用追到正式素材，不凭文件名挑同名图片。旧 gamedev 的中央祭坛实际使用 `defense_base`，不是另一张 `altar.png`；它与大型主神空间建筑是不同对象。
- 只有图片时明确称为三维重建，遮挡部分属于设计推断；有旧 Blender 几何源而正式图片经过二次细化时，也不能声称完整搬运了图片细节。
- 保存原源、来源说明与采用版本，独立目录和材质区分宝箱、仓库箱等不同身份。公开作者脚本不等于可以公开原模型、纹理、完整网格／材质导出。

## 单位、朝向与可见内部

- 装饰性展示旋转不要带进游戏轴向。统一 UE +X 前向、厘米坐标和落地枢轴；Blender 数值、scene unit scale、FBX 单位及 UE Build Scale 需一致。UV 展开使用统一的物理尺度，不能随单位转换放大一百倍。
- 门框实体与能量幕分件；实体保留门洞碰撞，薄光幕单独关闭碰撞和投影。完整新资产可用后再替换运行外观，保持目的地与加载合同。
- 图片用模型可能是实心块加顶面暗板。宝箱开盖暴露内部后，必须有四壁、下沉箱底、内衬与开放箱口；拱盖需要内外曲面、壁厚和端板。单纯换 PBR 无法补齐缺失内腔。
- 修订已接入的容器时保留 Root/Lid 参考姿态、后铰链枢轴和附件权重；箱盖、金属箍与扣带随同一盖骨运动。关闭／开启静态姿态不是连续动作，原项目的图片淡入淡出也不是三维动画。

## Unreal Python 材质槽写回

SkeletalMesh 的 `materials` 元素是结构体。仅修改遍历取出的副本，可能没有更新原数组；编辑后构造显式列表，再 `mesh.set_editor_property('materials', edited_materials)` 写回并保存。三张材质资产存在不代表三个 mesh 槽已绑定；2026-09-23 宝箱棋盘格就是三个 `material_interface` 都为空。

保留材质槽名、映射和原骨架，修制作脚本而不只手改资产。切线提示按几何、UV、法线和导入设置分别处理；本例静态网格使用 recompute tangents、MikkTSpace、全精度 UV 与高精度切线，不将其推广成所有模型的强制设置。

## 接入与恢复边界

复用现有交互射线、遮挡和距离规则；只开发面板时，未知奖励／费用保留未知状态，确认动作交由宿主。开盖状态按 Actor 实例管理，单次动作结束保持末帧并停掉不必要的骨骼 Tick；生命周期计时器弱绑定，切图销毁后不回调旧对象。动画、奖励和存档的完成状态分开说明。

修正地牢模型优先保留已有资产路径，只更新目标条目和已有实例，避免顺带重生成整个地牢。关卡保存失败时保留未保存现场与失败证据；不得把“编辑器里已生成”写成“已落盘”。历史 helper 中的结束 PIE、Live Coding 不是后台默认入口。
