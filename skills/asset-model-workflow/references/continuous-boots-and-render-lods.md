# 连续长靴、渲染 LOD 与旧装备实例

适用于靴底分离、踝部断面、法袍内穿鞋靴，以及高精度装备的距离 LOD。制作和落盘沿用用户授权；下面的变形、读回与联网检查仅在用户要求检查时运行。

## 连接结构与材质

- 先区分真正的结构开缝、重叠壳体的着色断层和蒙皮权重分离。仅把鞋底与鞋面接上，仍可能留下另一个封顶的独立靴筒；它与脚背相交时会出现踝部断面。
- 以连续截面连接鞋面、踝部、靴筒和靴口，沿条与鞋面共享连接环；内衬、靴口回折、脚床要有合理厚度。装饰裁片和扣带可独立，但不能代替主体的连续结构。
- 同一接缝的重合顶点采用同一原生足部／脚趾权重场。保留 UV 和法线接缝，不通过全局焊接抹掉材质边界；位置相同而权重不同仍会在动作中裂开。
- 写实表面按皮革、补强皮、沿条、鞋底、缝线、金属和内衬分区。颜色、粗糙度、法线及高度共享物理尺度和磨损遮罩；避免独立随机噪声与过大的明暗差把柔软褶皱变成塑料块。
- 与裤脚比较时使用当前靴型配对网格；保留原生包络和法袍的连续内腿。模型适配、遮罩显示、装备属性分别维护。

## 确认真的生成了距离 LOD

- 同时核对网格、独立 `SkeletalMeshLODSettings` 策略以及 UE 5.8 的 `source_models`。修改一个减少比例，可能仍被绑定的旧策略覆盖；衣袖的保真模板也可能把所有档位设为 100%。
- 保留 LOD0。按屏幕占比、轮廓和踝部变形制作距离档位，不把本案例的 45%／18% 当所有装备的固定参数。保留边缘、材质分区、足部主要骨骼边界；渐变顶点色不宜被当成每条边都不能简化的硬边界。
- `GeometryScriptMeshReadLOD` 默认 `MaxAvailable` 会优先读取作者源数据。检查运行时面数需显式使用 `GeometryScriptLODType.RENDER_DATA`，记录实际顶点、三角形、材质分区和 LOD0 前后身份。源网格保留高精度不代表渲染 LOD 没减面。
- Geometry Script 的渲染网格副本不保证携带蒙皮权重。需要变形核对时读取真正的 `FSkinWeightVertexBuffer`，通过每个 `FSkelMeshRenderSection::BoneMap` 映射局部骨骼编号到参考骨架，按有效权重总和归一化。不要用最近源顶点的权重冒充最终渲染权重。
- 更新资产时同步更新重导入口。制作回执的版本标记还要包含作者内容散列，不能因为旧标记存在就跳过新作者数据的 LOD 重建。

## 装备接入与旧实例

- 穿戴外观可能按 `Definition` 查当前装备配方，而库存图标与共享掉落物仍读实例 `Item.Data` 中的旧路径。只改目录会出现“身上是新版，旧物品展示仍是旧版”。
- 可在确认这些路径仍属于同一物品后，更新历史展示资产的几何／材质和历史 PNG 回退，保留路径与实例属性；先保存备份。不要批量重建物品实例而丢失强化、附魔、实例身份或库存位置。
- 法袍普通／内穿变体应同步 LOD、骨架和材质分区；遮罩使用相应的内穿材质。源码、材质参数布局和实际保存的材质一起交付。
- 新裤装的精确配对、靴型配对和通用回退分别保留；缺少未来物品的精确映射时，回退不能恢复已知会穿插的宽裤或长上衣下摆。回退存在不保证所有未来轮廓已验收。

## 2026-10-22 案例与证据边界

FPSGAME 长靴 `TailoredV2` 普通／法袍内穿版：LOD0 214,916 面，LOD1 96,712 面，LOD2 38,684 面。保存后读回实际渲染数据；30 个离线姿态的重合接缝无测得分离，双向表面偏差最大约 0.38／0.79 mm。面数减少不是帧率提升百分比。

历史检查为同机 UDP 监听主机、一个客机及同档案重连，共 14 个场景，配置每端 60 ms 延迟和 3% 丢包；覆盖不同装备、快速换装、法袍／上衣、脱靴及旧共享掉落物。它不覆盖专用服务器、三端同时在线、跨机打包、GPU 帧率或渲染画面验收。后续修订不能沿用该结论。

工程入口：`Tools/LeatherBootsTailored/`；最终渲染权重读取：`Source/FPSGAME/Development/LeatherBootsAuditLibrary.*`；运行检查扩展：`MageOutfitWireAudit.cpp` / `LeatherBootsWireChecks.h`。本机证据位于 `SourceAssets/LeatherBootsUpgrade20261022/TailoredV2/Audit/`，公开恢复说明位于 `Docs/Publication/LeatherBoots20261022/README.md`。许可证未核准的原始扫描、模型、贴图和 UE 包留在本机。
