# 按用途分配面数：近景保真、分类预算与高密度资产

用户于 2026-09-29 要求纳入工作流。适用于新模型制作、重拓扑、LOD 设计，以及用户询问减面必要性。它不自动授权对现有资产减面、降低材质质量、开启 Nanite 或运行性能测试。

## 1. 决策原则

**复杂、近景、重要的物体允许高面数。面数区间是制作起点，不是强制上限，也不是必须填满的配额。** 不因数字大就降低已认可的轮廓、金属高光、厚度或动作质量；不要把“优化”默认解释成全网格等比例减面。

同时防止没有视觉目的的密度：平面均匀细分、布尔碎片、不可见重复壳层、全物体微小铆钉、重复实例中的多余结构，都可能消耗资源而没有相称收益。新增资产在制作时避免这些冗余，不必等掉帧才考虑预算。已有资产是否值得返工，则结合其用途、风险与实际性能证据判断。

分配预算时记录：目标平台／最低硬件、分辨率与内部渲染比例、目标帧率、最近视距与屏幕占比、同屏数量、变形方式、材质与渲染路线。未知项写待定，不假定开发机 RTX 5080 就是玩家最低配置。未明确平台时，下面的数字只能作为本项目的初始设计范围，不能保证某档帧率。

## 2. 先统一统计口径

| 数值 | 表示什么 | 不应如何解释 |
| --- | --- | --- |
| 制作高模顶点／多边形 | 雕刻、生成、烘焙源；可能包含四边形 | 不能当作游戏三角形或同屏量 |
| 游戏网格 LOD0 三角形 | 最高精度运行时资产几何 | 不代表全部 LOD 同时绘制 |
| 渲染顶点 | UV、硬边等拆分后的实际顶点 | 不等于 DCC 的位置点数量 |
| 材质分区／组件 | 影响提交、剔除和材质成本 | 不应简单当作整帧 draw call 实测 |
| 实际可见几何 | 当前网格、可见分区和选中 LOD 的组合 | 不包含所有视角、阴影和深度通道的重复量 |
| CPU/GPU 帧时间 | 特定硬件、场景和画质的测量结果 | 不能从面数按比例推导 |

同一手套的 M4、手枪、弓、Body、独立左右手等原生派生是替换关系；不能把整个资源目录相加当成一帧。角色主体、装备衬底、原枪械手臂有时互相隐藏，统计可见量时避免重复计算；隐藏分区也不自动等于内存和蒙皮开销归零。

Nanite 的源面数与传统 LOD0 预算分开记录。启用 Nanite 不等于无限预算；实例、材质、输出分辨率、变形、流送以及回退／光追表示仍有成本。使用具体引擎版本支持的路线，不沿用“所有骨骼网格都不支持 Nanite”的旧结论，也不未经任务需要将既有装备批量改成 Nanite。

## 3. 本项目分类起点

以下单位统一为**游戏网格 LOD0 三角形**，来自本项目当前资产和制作需求的建议，不是 Epic 或行业统一标准。

| 类别 | 初始参考范围 | 计数范围与分配重点 |
| --- | ---: | --- |
| 第一人称皮革／布手套 | 2–6 万 | 双手；指节变形、掌形、开口、袖口厚度 |
| 第一人称装甲手套 | 6–18 万 | 双手含衬底；甲片层次、倒角、关节和腕部连续结构 |
| 第一人称衣袖 | 1–4 万 | 双臂；肘部、褶皱轮廓、袖口与肩端 |
| 第一人称枪械 | 3–15 万 | 枪体，不重复计入原生手臂；近景曲面、孔槽、活动件 |
| 普通拾取物／小道具 | 1 千–1 万 | 单件；按观察距离、检视功能及同屏数量调整 |
| 普通角色／怪物 | 3–10 万 | 整身 LOD0；按近景需求、变形及同屏数量分配 |
| 大型雕像、岩石、复杂建筑装饰 | 单独制定 | 支持的 Nanite 路线可保留高密度源，不套用上述传统网格上限 |
| 高频重复的地砖、墙板、围栏、小零件 | 按模块和组合制定 | 先算可见实例数量、遮挡和视距，不能仅凭单件面数允许重复铺满 |

重要角色、复杂枪型、允许贴脸检视的道具可以超出区间，写明额外几何承担的形状与使用范围即可。简单物体低于下限无需补面。第一人称与掉落／第三人称分别制作，外观身份一致不要求同一网格密度。

## 4. 哪些细节应由几何承担

| 细节 | 默认处理 | 减面时的注意点 |
| --- | --- | --- |
| 外轮廓、明显曲面、孔洞、断面 | 真实几何 | 法线无法补回剪影和实际空隙 |
| 金属倒角、明显接缝、甲片厚度 | 真实几何，按视距分配 | 面角法线、倒角不足会改变移动高光 |
| 手指、虎口、腕肘的变形 | 有方向的环线与合理权重 | 平滑着色不能修复缺少变形自由度的拓扑 |
| 细针脚、颗粒、划痕、织纹 | 烘焙法线／粗糙度，必要时浅层视差 | 不要把低于观察尺度的微细节全做成游戏几何 |
| 会影响轮廓的粗绳、粗缝、翻边 | 近景保留几何，远处再简化 | 不能一律当作贴图细节 |
| 均匀平面细分、布尔碎片 | 优先局部整理 | 保留 UV、材质边界、硬边、接口以及必要插值字段 |
| 始终不见的内层 | 按实际用途处理 | 先考虑卸装、掉落、镜头运动和换装，不能凭参考姿态删掉需要的内壁 |

局部减面比全模型统一压比更适合复杂装备。保住已经解决过穿插的区域，尤其是手套的小拇指、拇指根、腕口及衣袖接续处。不能为了一个候选面数倒退到已被用户否定的形状。

## 5. 推荐制作流程

1. **读取活动资产与消费者。** 确定是外观升级、性能优化还是新物品；沿用当前装备 ID、骨架、材质分区、碰撞和动作合同。不要从旧文档路径直接重跑旧生成器。
2. **划分结构与表面。** 写出必须保留的剪影／关节／接口，以及可以烘焙的微细节。冻结已认可的结构母版，再做烘焙高模。
3. **给当前用途分配预算。** 在上述区间基础上结合屏幕占比、同屏数量和材质成本调整，超出时记录用途理由；不要为了满足表格强行改形。
4. **分别保留高模、游戏母版、远景表示。** 高模可以百万面；游戏导入脚本显式选游戏网格，不误导出细分修改器后的烘焙对象。不同 UV／拓扑需要相应烘焙，不强套同一图集。
5. **同时管理材质和纹理。** 记录贴图尺寸、压缩、mip／流送、材质分区、透明／双面、视差步数和骨骼影响等。把几何换成昂贵 POM 不必然节约成本；单靠减少面数可能完全没有解决当前瓶颈。
6. **用适当的 LOD／剔除路线覆盖使用距离。** 第一人称长期靠近镜头，不能指望远景 LOD 自动解决其成本；掉落、第三人称及场景实例需要自己的距离策略。Nanite 与手工 LOD 分开处理，不盲目强制所有组件的同一档位。
7. **按已授权范围保存和交付。** 制作中的实际错误照常处理；默认不追加测试、截图或采样。用户要求对比时，再固定硬件、镜头、分辨率、画质和动作，比较轮廓、高光、变形及帧时间。

只有几何数量，没有对应帧时间时，结论应是“存在可优化项”或“预算候选”，不能声称“必须减面”“帧率提升 X%”或“高面数没有任何成本”。

## 7. 资产制作记录建议字段

按任务需要在现有 manifest／制作说明中补充，不要求另建系统或运行时字段：

- 身份与来源：物品 ID、活动资源、母版、合法素材来源。
- 用途：第一／第三人称、掉落／检视、最近视距、同屏数量、平台与目标画质。
- 几何：高模多边形与类型、游戏 LOD0 三角形／渲染顶点、关键变形区、各 LOD 策略。
