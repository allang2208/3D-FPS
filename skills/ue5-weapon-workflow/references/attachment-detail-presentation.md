# 配件详情与介绍编写标准

用户于 2026-10-08 确定“能力增减卡片＋特效说明”，2026-10-09 根据剑刃精简方案定为后续编写标准。新增或修改枪械、近战、弓、法杖、工具的改造配件介绍时先读本文；整件武器背景介绍仍按 [武器说明与特殊性质](weapon-copy-and-traits.md)。

**最新用户裁定（2026-10-09）**：默认只列直接属性。二段／三段攻击数值、附加伤害拆分、连击与重击的派生结果均不写，也不转移到总览、浮窗或特效段保留；即使某段有独立倍率，也不自动列出。只有用户明确要求展示某项时，才按所指范围补充。本条取代此前“派生值留总览”“独立连段仍要显示”的规定，底层战斗计算不变。

## 信息分工与顺序

改造台沿用：名称／安装状态 → 简短外观 → 能力增减卡片 → 特效说明 → 基本配件说明 → 直接属性总览。外观和基本说明沿用现有位置，内容保持简短，不在两处重复同一句介绍。

| 内容 | 写什么 | 来源／位置 |
| --- | --- | --- |
| 外观、材质、风格 | 通常一句话，描述实际可见特征 | 配件 `description`／外观字段；次级正文色 |
| 直接常驻属性 | 装备后直接改变的指标，每项只列一次 | `stats` 经 Calculate／Evaluate 生成能力卡 |
| 条件效果、动作变化 | 触发或释放方式、作用及必要限制 | `special_effects`；绿色特效说明 |
| 直接属性总览 | 当前武器的核心属性及直接改造对照；不展开攻击分段或附加伤害拆分 | 原有总览区域 |
| 整件武器背景 | 来历、特征、用法，200 字以内 | 物品 `desc`，遵守独立的武器介绍规则 |

介绍不复述已展示的常驻数值，不把“伤害更高、消耗更多”换个说法再写一遍；没有特效不编造空栏，已有属性卡也不能隐藏独立特效。

## 能力卡：直接属性只写一次

- 显示“指标（改造增减）＋当前组合实值＋相对本槽原厂差值”。实值与差值来自同一评估器，比较时只将选中槽恢复原厂，其他配件保持一致。括号表示该改造项，右侧表示实际组合结果，不用目录倍率伪造最终差值。
- 一项伤害改造不重复展开总伤害、每段连击和重击伤害；一项攻速改造不再逐项列普通攻击、突刺等耗时；同一距离倍率只列一个统一距离指标。这些派生结果在总览中也不列。
- 物理伤害、攻击速度、攻击距离、体力消耗、穿甲等直接属性按当前改造显示；二段／三段伤害、对应削韧、附加物理／魔法伤害金额等默认省略，是否有独立 stats 字段不构成展示例外。卡片数由允许展示的直接属性决定，不强制三张。
- 高／中／低血量等互斥条件、命中触发、临时强化进入特效说明，不同时作为常驻收益。
- 收益用 `ColdSteelUI::Success`，代价用 `ColdSteelUI::Danger`；耗时和消耗降低属于收益。暴击率统一为“改造暴击率（+25%）”，实值／差值用 `%`，底层百分点相加的公式不变。

## 特效说明：少量短段，机制完整

目录使用 `special_effects: ["标题｜正文", ...]`，按独立机制组织。一段说明一件事，优先写“何时触发 → 发生什么”；仅补充该机制确实需要的持续、冷却、次数／层数、刷新／叠加、消耗和解除规则。简单效果不套满所有小标题，复杂效果可以分段，不为压字数删掉决定用法的条件。

- 特效栏标题、分段标题和正文均使用 `ColdSteelUI::Success` 绿色，标题与正文分开。
- 常驻加成已在卡片显示，特效段不重复；必要的直接条件加成写在对应触发段中；不借此补回默认省略的攻击分段或附加伤害数值。
- 明确有效攻击通道和目标条件；“命中”不能擅自替代“剑刃命中”“快速近战命中”或“确认击杀”。刷新、叠加、挥空是否消耗、换武器是否清除均按实际机制写，不凭通用模板补规则。
- 不在玩家文案中写文件路径、代码名、实现步骤、制作／测试状态等开发信息。

## 名称、数值与字段

共用 [武器字段格式](../../ue5-ui-umg-slate/references/weapon-tooltip-schema.md) 和 `ColdSteelWeaponText.h`。同一指标在卡片、总览和浮窗中保持同名、同单位、同计算范围。百分比写 `+N%`／`−N%`，倍率带 `×`，时间、距离、弹数沿用指标规定的 ms／s、m、发。

以下伤害口径用于作者理解和正确命名，不要求在玩家详情中展示分项或公式：

- **基础物理伤害**：仅基础分项受改造；不能写成全部物理或总伤害同比增加。
- **物理伤害**：基础物理与附加物理一起计算，魔法通道不变。
- **全部攻击伤害**／**魔法伤害**：按实际覆盖通道命名，不能与基础物理互换。

近战延锋刃使用 `physical_damage_mult`；`damage_mult` 仍是原有武器基础伤害改造。纯文案任务以现有玩法为依据，不为了让介绍成立而擅改战斗数值。

`description` 负责基本介绍；`special_effects` 负责独立机制；`effects` 继续服务旧列表／物品提示，不能作为新特效的唯一来源。共享读取入口为 `FGunsmithOption::ReadSpecialEffects`，详情展示入口为 `M4GunsmithSelectedDetails.cpp`。不要按武器 ID 或是否生成数值卡片增加显示特例。

## 物品浮窗与武器背景的边界

- **改造台详情**使用上面的能力卡和绿色特效区。
- **物品浮窗**沿用 2026-10-08 规则：说明文字用 `Note()` 整行宽、左对齐，具名机制用金色 `Section` 标题；长说明拆成短行，纯数值保持两列。不要把改造台绿色标题规则覆盖到浮窗；浮窗无需重复独立的纯外观段。
- **整件武器 `desc`／`traits`**继续按 [武器说明与特殊性质](weapon-copy-and-traits.md) 区分背景与玩法特征；背景不堆实时属性，不使用排行或跨武器型号比较定位。

## 编写示例

**延锋刃**

- 基本介绍：修长刃形与延展剑尖，保持流畅的切削轮廓。
- 三张能力卡：物理伤害（+5%）、最大攻击距离（+15%）、体力消耗（+5%）；实值和差值由模型填写，前两项收益、体力消耗为代价。
- 没有独立触发特效，不添加“特效说明”。必要范围说明用短句：“距离加成作用于挥砍、突刺，不影响快速近战。”

**腾云游龙刀身**

- 基本介绍：唐刀专属。弧形刀尖接修长龙脊，鎏金游龙交织流云与水波锻纹。
- 能力卡：攻击速度（+10%），使用正式指标名称及真实组合值；第三段伤害加成默认不写。
- 特效：“连段变化｜连段收尾改为升龙，准备时间缩短50%。”及“击飞｜升龙命中无韧性或已破韧的目标时，将其击飞。”不在此补写攻击分段伤害。

其他机制沿用相同分工：镇魔为暴击率卡＋暴击触发／随身法阵；金刚为防御常驻卡＋生命分段／吸血／清除；蟠螭展岳为格挡消耗卡＋蓄势、上挑释放与法阵牵引。

**法杖配件（2026-10-10）**

- 直接属性由 `ColdSteelStaffModificationUI.h` 的同一字段表供详情、总览和物品浮窗使用；不在浮窗回退到整段旧描述。
- 杖冠的专精条件、续疗、链式强化、加速、寒冷、眩晕和灼伤进入 `special_effects`。不把触发层数、持续时间、每跳伤害倍率或跳伤间隔拆成常驻属性卡。
- 灼伤说明保留触发通道及持续时间，默认省略附加伤害计算；加速等叠加时长按实际规则说明，不把每层时长写成整个效果的总时长。
- 法杖文案源为 `SourceAssets/ApprenticeStaff20260927/attachment_copy.py`；目录生成器调用同一入口，更新文案时同步正式目录，保留资产路径和底层效果数值。

## 后续执行与同步

编写前读取对应正式目录、数值评估和必要的运行时机制，再把内容分到属性、条件、外观三个位置。同步修改正式目录与作者／重导入口；保存静态特效文案时随数值源一起更新，避免重导恢复旧介绍。

本标准约束后续编写与修改，不代表所有旧界面已经完成运行时改造；2026-10-09 的本轮接入范围为近战改造详情与近战总览，其他既有界面按各自实施记录，后续编写均遵循直接属性标准。沿用现有滚动、自动换行、选择／应用／保存和输入焦点；不因整理介绍增加 Tick、重写存档或改变机制。纯标准／文案修改不自动触发构建、编辑器启动、截图或测试；必要制作和接入按用户已授权范围执行。
