# 武器状态刷新与输入归属

适用于 FPSGAME 的单持枪械、双持手枪与档案事务。2026-09-15 按用户要求实施；构建不等同实机测试。

- `SaveNow` 从当前控制器捕获状态，只执行持久化与档案/UI 发布；不能把保存视为重新装备武器。装备、属性、补弹等业务事务通过 `CommitState`，写入成功后应用角色。保留现有 A/B 存档与失败不提交语义，不借此调整保存周期或存档格式。
- 角色按主手实例、武器定义、可用状态及双持组合识别真正换装。先释放旧输入、停止旧控制器，再加载视模并应用数据；双持退出不能递归调用角色的档案应用入口。
- 单持 `bFireHeld` 只由角色输入流程维护；双持左右手各有 `Held` / `Pending`。公共移动逻辑使用 `IsWeaponFireHeld()` 查询当前控制器，不能让未启用的组件清空另一个控制器的输入。保持手枪一次按压一发；切换单双持输入映射时要求重新按键。
- 同一武器/双持组合的属性刷新不重置射击截止时间、动作时间、换弹播放率、已结算入膛次数或已播放音效。新属性从原始基础值重新计算，作用于后续动作，不能乘回上一轮结果。
- 配件通过 `ApplyWeaponAttachmentPresentation` 按槽位差异更新。枪匠预览和撤销使用相同入口；关闭后应用已安装组合。重建视模或真正换装时失效缓存。普通数据刷新不递归显隐所有子组件，避免重新显示已隐藏配件。
- 双持弹药按两只手的物品实例写回；角色主手弹量只是显示缓存，不能随后覆盖双持主手的数据。发射先扣弹并同步，再进入可能同步发放击杀/修炼奖励的命中回调。
