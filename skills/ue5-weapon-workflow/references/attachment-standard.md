# 改造配件标准工作流

适用于 FPSGAME 配件制作、装配和游戏接入；有手部接触的配件执行抓握分支。使用当前手模和用户选定模型，不能为了接触方便擅自换模型或缩放配件。

2026-09-12 用户确认 VRE 抓握迁移成功，并指定沉淀为配件标准。垂直握把、45° 侧倾握把和小阻手器优先复用已查看、已接受的成组抓握手型，按整手方向、握点和原手臂来向适配；不再默认逐指搜索贴合或以零相交改坏手型。配件 ID、分类和独立动作分支继续保留，穿孔三角握把仍按其专用接触处理。当前路径及作者入口见 [抓握母版与类别](../../ue5-fps-arms-animation/references/vertical-grip-family.md)。

## 1. 先确认来源与当前基线

- 读取实际角色加载、配件 ID、槽位、安装变换及动画选择优先级。查看原有待机、装备和普通/空仓换弹的实际模型渲染，记录 FPS、帧范围、接触段与机械事件。弹鼓独立识别。
- 原图、三视图、生成请求、原始模型与来源清单分开保留。三视图生成若输出多个独立造型，要明确选择了哪个；不能称为多视图融合。混元或 5080 管线按用户选择和同尺度实物对比决定，不把管线名称等同质量。
- 比较轮廓、尺寸、安装面、防滑细节、拓扑、UV、材质和实际游戏近景。面数是成本证据；减面后保住接触区和剪影，检查零面积、法线、开放边、非流形与材质槽。生成贴图不合格时修整或替换并记录，不能把常量材质称作完整 PBR 贴图组。

## 2. 统一装配坐标与数据闭环

材质制作执行 [枪身与配件材质统一](weapon-finish.md)：每个目标枪型分别匹配当前机匣涂层，覆盖握把、枪口、弹匣、瞄具、枪托的金属区域及活动件，保留非金属、标识和光学消光层。复用模型不等于可以复用另一枪型的材质；不能只改安装座或只调底色。

瞄具制作先读 [瞄具成像与验收](optic-presentation.md)：在生成/建模前确定 ADS 成像方式、有效镜内画面占比、安装尺寸和活动件拆分。面数、拓扑与分划中心通过不代表镜内视野可用；严重不规则旋钮/滚花先重建规则硬表面，不反复依靠平滑掩盖。

- 由真实安装基准构建正交、右手坐标系，记录单位及 local/rest 关系。把测量帧中的安装矩阵转换到枪根局部空间；只抵消一次 bind transform。作者场景和运行代码使用相同基准。
- 保留枪根、弹匣和机械骨骼层级。验证安装面贴合、动画跟随、互斥替换及拆卸恢复；各枪型单独校准，不能照搬 M4 偏移。

### 姿态与座位：以入枪接口表达，不要把资产"摆正"（2026-09-18）

扩容弹匣（`ext_mag`）连续两版"看不见/看着没插进去"的根因都在姿态，值得作为默认做法固定下来：

- **配件的几何姿态应当直接在该枪的挂点坐标系里表达**：取原厂装配（或接口基准）的顶点，变换进该枪的 `WPN_SOCKET_<槽位>` 帧，把原点定在接口面（弹匣＝喉部顶面）。这样**运行时座位退化为恒等**，只保留骨架 ×100 所需的 0.01 缩放补偿。参考实现 `SourceAssets/ExtMagUniversal20260917/Scripts/export_insocket_pose.py`。
- **反例（本项目已踩两次）**：先把资产"摆正"导出，再用座位旋转把它扳回安装姿态。这是双重变换，两处误差叠加；而且"摆正"很容易写成按 PCA/最长包围盒轴对齐——正是 [图标标准](attachment-icons.md) 禁止的"仅根据最长包围盒轴猜测机械方向"。摆正只允许用于**找长度方向做延长**，不允许用来定资产的朝向。
- **组装姿态本身就是"未摆正"的**：弧形弹匣（QBZ-191、AK 系）的顶端到底端连线与主轴不重合，摆正后仍会残留十几度倾角，光看渲染很像是"方向反了"。
- **座位数值用装配反推、不用手调**：`S = T_socket⁻¹ ∘ Align⁻¹`。手调的 rake 与真实井角能差 11°（QBZ 案例 13° vs 24.28°），视觉表现就是"没插到位"。
- **离线自证**：把运行时座位施加到资产顶点，与**原厂装配**逐点比对。本次 QBZ 案例误差从 3.7 cm 收敛到 1.7 mm（`Reference/seatcheck_left.png` 灰色＝原厂装配、橙色＝运行时模拟）。这个检查不需要启动游戏，应在导入前跑一遍。
- **导出对象带缩放时**：作者工程里拆出的配件对象常带 0.01 缩放（网格数据是厘米级）。写回顶点前先 `transform_apply` 烘焙对象变换，否则"世界→对象"的逆矩阵会用错，症状是导入尺寸对不上而 FBX 看着正常。
- 配件 ID、枪匠条目、草稿、应用、取消、保存失败、实例保存/重载、未装备实例、图标和实际角色使用同一装配入口。按变更登记打包目录；未给定属性时不虚构数值加成。
- 枪械展览默认水平侧视。包含所有配件的最终包围盒决定居中与取景，保留画面边距；检查枪口、握把及长枪托组合，附件迟生成后重新计算，不能只按裸枪尺寸或固定距离取景。

用户于 2026-09-14 确认枪托图标规则并要求推广：实际模型渲染、水平左向、透明背景、单件展示；机瞄只显示一个照门组件。来源选择、不同枪型覆盖、数值改造与审计方式统一见 [改造配件图标标准](attachment-icons.md)。不将方向统一扩展为修改游戏模型或 PBR UV。

## 3. 有接触的配件：先建立真正包握

- 先实际查看现成抓握源，再按手掌解剖方向和 rest 坐标转入当前手模；名称含 Grasp 不代表四指与拇指已闭合。保留四指成组弯曲和拇指横向扣向食指的关系，先调统一闭合幅度、整手方向和握点，只有明确可见问题才有限修指节。镜像、来源和导入细节见 [现成抓握迁移](../../ue5-fps-arms-animation/references/github-grasp-donor.md)。
- 实际查看掌侧、手背和真实玩家视点：配件进入掌心与弯曲手指围出的空间。小阻手器按本用户要求以自然握拳整体包住，内部穿模可以接受；不再强求四根手指分别贴住短件，也不为消除内部交叠把四指张开或拇指伸向手背前方。该许可不扩大到所有配件。
- 禁止以指尖最近距离或 BVH 零相交单独判定成功。棱镜失败版的掌面方向错误，手指在配件旁收拢，数值通过仍被用户否定。
- 使用变形后的真实手套表面评估接触，不能将 FBX 骨尾当作指尖。对适用的包握手指，可检查其截面投影包围配件中心，辅以表面距离、相交与侵入深度；凸包检查只是辅助，凹面和复杂造型仍看真实渲染。
- 使用原手臂、骨架、蒙皮与当前材质。固定骨长、scale、rest 和手指局部平移。整条锁骨—肩—肘—前臂—腕和 twist 一起求解，不能只移腕或大幅扭掌骨。腕轴接近直线也可能伴随严重前臂扭转；45° 配件先用真实本体轴定握点，再围绕握点参考原腕方向调整整手，同时检查肘平面、前臂 twist、袖口和玩家正面。具体适配见 [斜握把与阻手器案例](../../ue5-fps-arms-animation/references/grasp-canted-handstop.md)。

- 用户明确要求缩放配件时，保持安装接触点，按指定比例缩放几何并验证 UE 三轴尺寸；手与骨架不跟随缩放。重新明确穿孔手指和外侧贴合手指，检查退握中是否重新穿孔。
- 握姿已接受但腕肘衔接僵硬时，先保留接触关系，调整肩肘支撑和前臂方向；必要时才改变整手方向。具体诊断、逐指退握与案例见 [配件手部与整臂优化](../../ue5-fps-arms-animation/references/grip-arm-refinement.md)，不新增另一套配件工作流。

## 4. 专用动作与退握、回握

- 按实际动作映射制作待机、ADS、腰射/瞄准射击、装备以及普通弹匣/弹鼓的普通与空仓换弹。配件分支、弹鼓支撑、另一握把与原动作的优先级要显式验证。
- 换弹仅修需要变化的脱离和返回区间，保留取弹、插入、压实、拍击段及右手、枪根、弹匣机械轨道。沿用原动作时钟和音效事件，不因换握姿改补弹结算。
- 先检查松指扫掠，再规划手掌退让，最后进入原动作；返回反向合拢。不能将两处手腕目标直线插值穿过配件。确有穿插才增加侧方/下方途经点，不能把某次避障位移写成通用常量。棱镜修正掌面后可自然展开，旧版补偿位移已废弃。
- 连续四元数符号、分层局部矩阵重建和足够的烘焙采样共同保证链稳定。验证保留段时识别 q 与 -q 的旋转等价，不能把符号连续化误报为接触被改动。高采样率按运动/压缩误差选，不能用增加采样掩盖错误接触。

## 5. 验收与交付

1. 源检查：骨长、缩放、手指局部平移、非目标骨骼轨迹、保留接触区间与原动作比较。
2. 几何检查：稳定姿态、装备、退握、回握和换弹接触的密集采样；记录采样范围，零采样相交不等于连续时间或整枪整臂绝无穿模。
3. UE 导入读回：实际资产路径、时长、骨架、RAW/COMPRESSED 偏差及保留段误差；明确 commandlet 退出码和已有错误。PASS 标记不抹去非零退出码。
4. 新游戏进程：隔离存档 profile，验证装配、保存重载、ADS/射击、四种换弹及弹药、回握、装备、替换与拆卸；新原生模块编译后启动新进程。
5. 实际查看游戏内掌侧和正面近景、第一人称及关键过渡；腕肘优化另看手背到肘部近景，并与上一版握持关系比较。用户指出“没抓到”时撤销旧视觉验收，定位源姿态、安装空间或实际分支差异，修正后重新导出、导入和检查。
   - **先确认捕获夹具真的产出了文件**。`DrumGripAudit` 的侧面捕获（stage 5 把视模转 90° 拍 `side.png`）曾是死代码：等待与截图逻辑写在 stage 2/4 分支里，而 stage 递增到 5 的同一次调用就 `quit`，所以从未落盘。此后多轮"已验证"实际上没有视觉依据，只看到了没藏干净的原厂件残影。任何"截图通过"的结论都要连同**文件名与磁盘时间戳**一起记录。
   - **单看截图会被遮挡误导**：第一人称下弹匣区域常被右下角武器信息面板压住。给挂点类配件加一条数值诊断（可见性／世界位置／世界缩放／包围盒／挂点变换／相机位置），位置与缩放先由数字判定，截图只作辅助。
6. 保留可编辑 Blend/FBX、参数、导入入口、运行日志、预览和最终资产散列。静音 GIF 仅证明可见动作；音效改动另做实际音画检查。文档整理不重跑动画和游戏。

## 配件数值与说明分工（2026-09-17）

### 1 数据口径（`Content/ColdSteelData/gunsmith.json` → `options[<slot>][].stats`）

- `ads_percent` 是**开镜耗时**的倍率增量：`ADS = base.ads × (1 + Σ ads_percent)`。面板「开镜耗时」行直接显示 `ads_percent×100`——`-` 表示更快（绿色增益），`+` 表示更慢（红色代价），与用户书写符号一致。不要再做 `1/速度−1` 反推；历史用该写法存过的四个值已归一：钛金制退器 `0.15`、战术消音器 `0.05`、幻影后握把 `0.15`、稳固防滑后握 `0.10`。
- `ads_seconds` 是绝对秒（激光 `-0.2` = −200 ms），与百分比同时叠加。
- `recoil_mult` <1 = 后坐力指数下降（控制更好）；`stability_mult` 是 0–100 稳定性评分的倍率（>1 更好）；`hip_spread_mult` <1 = 腰射更紧；`reload_mult` / `fire_interval_mult` / `range_mult` / `bullet_speed_mult` 为倍率；`mag_delta` 为绝对发数。
- 倍率相乘、百分比相加；面板、实战与物品提示都读同一个 `UGunsmithSystem::Calculate` 结果，不在 UI 侧二次换算。

### 2 说明分工（单一来源，禁止手写百分比）

- 卡片与悬停的 `description` **只写基本描述**（几何、材质、安装方式、动作、风格），不写任何百分比或数值。
- 所有增减细节显示在右侧「配件详情」的对应行旁，例如 `开镜耗时  320 ms（+15%）`；颜色与差值一致（红=代价、绿=增益），负号对玩家是增益（如 −20% 腰射散布为绿色）。
- 逐行口径：乘性行取 `最终/原值−1`；ADS 行取 `ads_percent` 原值（耗时口径）；弹匣容量保留绝对值 `+20 发`。
- `effects` 供物品提示读取，必须与 `stats` 同义同数；能用定性文字就别写数字——例：大弹鼓实际换弹是 `×1.75 × 0.846 ≈ +48%`，提示只写“装填耗时更长”，百分比由详情行给出。
- 改一件配件要同步 `stats`、`description`、`effects` 三处；三者不一致时以 `Calculate` 的结果为准。
