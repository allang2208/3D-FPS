# 枪械专属音色与消音分支

用于替换开火声、制作消音音色或排查“换了音源却听起来没变”。默认只完成制作、导入与必要接入，不主动试听或启动游戏；主观听感由用户判断。

## 先找到最终播放分支

- 同时读取普通 `FireSound`、消音 `SuppressedFireSound` 和连射变体数组。只改单发引用可能被后面的通用变体库覆盖。
- 新枪复用 M4 的动画／事件时钟不代表应复用其声音。为目标枪建立独立声库，并保留其他枪型的引用。
- 制作记录区分原始录音、用户提供文件与加工衍生文件；来源许可逐音源继承。过滤现有 AR-15 录音得到的消音声只能称为设计音色，不能称为真实 ASH 消音录音。

## 用户要求只改音色、不降低音量时

- 在源声音上调整爆音频谱、低频主体、机械细节和尾部包络；保留用户已接受的音高、声道及节拍。具体滤波频段按源声音设计，不把 ASH 案例数值套给所有武器。
- 滤波本身会降低能量。制作时做响度补偿，同时保持 SoundWave 音量、声音类别和运行时播放乘数一致；仅维持峰值并不能保证整体响度相近。
- 极短枪声不足完整响度门限窗口时，可用同一时段的 RMS／无门限加权能量作制作补偿，记录所用指标；不得把它冒充标准 LUFS 或主观等响验收。保留峰值余量，避免补偿导致削波。
- 四个轻微音色版本、避免相邻重复、有限声部重叠尾音可沿用现有播放合同；不要为了声音变化改射击、弹药或伤害时钟。

## 按接触阶段裁取参考视频原声

参考是成品视频时，裁出的声音仍属于原混音，不能称为游戏的独立音效分轨。记录视频 URL、本机源 SHA-256、裁切区间、处理参数、目标动作时点和衍生文件散列；没有源音频再分发依据时，只发布制作脚本与元数据。

滑动摩擦与金属止点拆开处理：摩擦可保持音高伸缩至动作区间，撞击起音裁齐接触并保留原速，边缘短淡入淡出。统一整组增益保留相对力度，峰值余量不等于主观等响验收。SoundWave 的声音类别、音量、音高与播放端倍率分别记录，避免导入后又被回退音色覆盖。

事件使用动画源时钟，经现有速度映射触发，不用另一套墙钟。阶段数量变化时同时更新声音数组、镜头索引及最终到位事件。PKM `ChargeAudio35` 的四段为后拉摩擦、后止点、前推摩擦、前止点；与 `Charge34` 的 5.13/5.36/5.48/5.82 s 对齐。沿用 M4/ASH 反馈幅度只表示幅度参考，方向、接触顺序和时长仍按 PKM 处理。

装备音效按动作里真实发生的机械动作选源，不按枪型套用：PKM 装备片段 `A_PKM_equip`（0.90 s）没有拉柄行程，所以装备只播一次单发，用的是 `ChargeAudio35/S_PKM_ChargePullMove`（后拉摩擦，保音高时间伸缩段，与空仓换弹 5.13 s 同一资产），不再借用 AKM 的 `S_AKM_Equip`；不要顺手给装备加 cue 时间轴或补一个没有对应动作的拉栓。换装备音是换单发资产加回退，不新增接触点。

后台导入回执证明资产保存；常规构建证明原生模块完成构建；两者都不能代替游戏内听感与音画验收。工具请求超时也不能直接判为构建失败或成功，应读取对应实际 UBT 日志后描述结果。

## 换弹／机械动作的音效序列

按动作发生的机械事件排 cue，不按枪型套用；一个 cue 对应一次真实接触。装填次数可变时（逐发压弹、分次上膛），接触时刻按动作自身步长推导，不写死总数。

- **时间用动画源时钟**，经现有速度映射触发；统计属性缩放的是姿态时钟，不是声音。
- **录制音要补偿预卷。** 录来的单发音常在撞击前有一段无音高预卷，直接放在接触点上会让撞击迟到。逐音测出预卷长度（`LeadSeconds`），把**触发点前移 lead**，让撞击而非文件头对准接触；同时保留"素材缺失或短于自身 lead 就退回无补偿接触音"的回退分支。未补偿的素材不要混进同一序列。
- **重复接触音看紧促度，不看电平。** 同一动作连响多次时（如六发压弹），每个样本先量三个数再选：**起音时间**（10 %→90 % 包络上升）、**前 30 ms 能量占比**、**1.5 kHz 以上能量占比**。长尾素材连排会糊成一片噪声，即使峰值和响度都正常。实测对照（DW715 自带机械集，48 kHz）：

  | 样本 | 时长 | 起音 | 前 30 ms 能量 | >1.5 kHz | 峰值 |
  | --- | --- | --- | --- | --- | --- |
  | DryClick | 100 ms | 0.33 ms | 98.9 % | 81.1 % | −12.0 dBFS |
  | ChargeRelease | 180 ms | 0.54 ms | 89.7 % | 37.4 % | −6.4 dBFS |
  | MagSeat | 170 ms | 0.33 ms | 79.2 % | 27.0 % | −8.4 dBFS |
  | MagOut | 160 ms | 0.21 ms | 66.1 % | 29.1 % | −8.0 dBFS |
  | MagInsert | 200 ms | **24.44 ms** | 52.8 % | 64.0 % | −9.1 dBFS |

  `MagInsert` 的 24 ms 起音是"推入"不是"咔哒"，不适合当压弹接触；`DryClick` 最紧最脆，DW715 单发装填据此选为压弹音。**语义要对得上动作**：击锤/击针样本（DryClick）当压弹声只是紧促度最优解，不是机械上最贴切的解，选它要在代码注释里写明理由和回退项。
- **先确认引擎实际加载的是哪个文件，再动手分析素材。** 枪型分支常把通用 cue 名重定向到该枪自己的声库；对源目录里同名的通用文件做测量，得到的可能是引擎从不播放的版本，据此得出的结论会整体作废。查 `LoadAKMSound` 一类解析函数的枪型分支后再取样。

### C++ 陷阱：TObjectPtr 与裸指针混用

声音成员多为 `TObjectPtr<USoundBase>`。在条件表达式里与裸指针相遇会产生二义：

```cpp
// 编译失败：条件表达式 result 类型有歧义（TObjectPtr<USoundBase> 与 USoundBase*）
return Found ? Found : Fallback;            // Found 是 TObjectPtr
```

用显式类型加语句式分支，不要在返回位置写混合类型的三元：

```cpp
TObjectPtr<USoundBase> Recorded = RevolverSpeedloaderSounds.IsValidIndex(Index)
    ? RevolverSpeedloaderSounds[Index] : nullptr;
if (!Recorded || Recorded->GetDuration() <= Lead) { OutLead = 0.f; return Fallback; }
return Recorded.Get();
```

用户报告"换成机械音后不合格"时，先确认改动范围：只改被投诉的那一个 cue，不要把相邻已获认可的 cue 一起退回。已认可的声音（如转轮甩开）不要在同一轮里顺手替换。

## 录音里的风声／背景音：识别与处理

参考录音或成品视频截取的单发里混入环境声时，**先把环境声与被投诉的片段对应起来，再决定处理方式**。

识别用三种互相独立的口径交叉验证，任一条单独都不足以定案：

1. **频段电平**——量目标录音里环境声占主导的频段（风在 250–1000 Hz），与该录音的安静段底噪比。显著高于底噪（如 +6～8 dB）的片段就是候选。
2. **降噪有效性反差**——若原管线做过降噪，对比各片段的实际降幅。降得明显偏少的片段说明该处噪声不平稳，正是漏网处。
3. **逐 20 ms 切片对照**——统计"环境声频段高于机械频段"的切片占比；占多数即该片段以环境声为主。

定案后再做**频谱形状判定**：把可疑片段与"纯环境声参考""纯机械参考"分别算频谱距离，距离小的一侧就是它的真实身份。这一步常揭示一个反直觉事实：**可疑片段里真正的机械内容可能只有几个 20–40 ms 的爆发，其余 70–80 % 时长都是环境声。**

### 处理顺序：先查现成滤波器，再考虑重建

**最容易漏掉的正解是管线里已有的滤波器定得太低。** 若机械与风在频谱上几乎不重叠（如机械 1.5–8 kHz、风 250–1000 Hz），把高通从过低值提到两者之间就能直接切掉风而不动机械，**保留原录音、原窗口、原长度，只改一个参数**。

- 提高高通的代价是切掉该频率以下的一切，包括机械本身可能存在的低频厚度。**切多少要按目标录音自己的频谱定，不把某个案例的 Hz 数套给别的枪**；同时准备一个折中频率的试听版本供用户判断低频是否够厚。
- 补偿方式：只保峰值不变即可维持游戏内触发响度一致；整体 RMS 下降是被切掉的环境声，属预期。

优先级低于它的几条路，实测代价都很高：**原地谱掩蔽**（噪声不平稳时几乎无效，安静窗之间的归一化互相关低就说明模板减法不成立）、**剪短暴露段**（若片段本身大部分是环境声，剪掉哪一段都只是让剩下的环境声占比更高，会越剪越差）、**尾音重建**（依赖"尾段是机械衰减"这个前提，前提不成立就全盘失效）。先量环境声占比再选路线：占比很高的片段不要走剪短。

### 本机案例（2026-09-28，PKM 换弹全接触点去 BGM 尾音）

PKM 的参考源是**混合成品音轨**（`References/PKM_UserReloadReference.mp4`，BV1jHeA6sEmj），
裁切下来的每一段都带连续背景音乐床，**没有可用的独立分轨**。09-25 只修了开盖/合盖两声，
用户反馈"其余换弹声里还有 BGM"，09-28 把剩下的 5 个接触点补完。

可复用的四条经验：

1. **"修复没落盘"先查三件事，别急着重做。** 本例的真实原因是：修复脚本与记录一直是 `??`
   未提交；而已提交的恢复入口 `import_audio.py` 仍无条件读**原始带 BGM 的 WAV** 并
   `replace_existing=True`，照 Git 说明重跑一次就会把修复覆盖回去。**修复未回退，是恢复路径会毁掉它。**
   修法：抽 `tail_repair_manifest.json` 当唯一事实源，让恢复入口优先导修复版；
   另给一条 `apply_tail_repair.py` 一键重跑全部配方，并验证输出逐字节可复现。

2. **尾音重建的抑制度 == 供体的掩蔽余量。** 供体 = 接触音 + 床，供体带多少音乐，
   重建尾巴就带多少。所以选供体要**先定"要压多少 dB"，再去找余量足够的窗口**，
   而不是随便挑一段"听起来干净"的。本例全解码搜索后取 20.843–21.077 s
   （234.7 ms，最小余量 12.5 dB、均值 19.7 dB）。

3. **余量必须在"制作链真实的口径"下测。** 09-25 的供体是按无高通解码上的余量选的
   （100 % 帧 ≥6 dB），补上制作链实际使用的 80 Hz 高通后，同一窗口最小值掉到 **−2.3 dB**，
   中段 96–139 ms 只剩 2.5–5.1 dB。对当时 77.7 / 43.0 ms 的短尾巴无害，
   **推广到 130–224 ms 的长尾巴就会把音乐切回来**。高通削的主要是撞击的低频厚度，
   背景床几乎不变 —— 凡是"按掩蔽余量挑素材"，都要问一句判据是在哪个滤波口径下算的。

4. **判据用"最后一个达标帧"会漏掉中段空洞。** 触点短暂回升就会把前面一段音乐留在保留区
   （本例 BoxOut 267–341 ms 掉到 −2.3 dB，却在 363–373 ms 回到 5.5 dB 而被保留）。
   改用滞回：≥6 dB 归接触音、<3 dB 归音乐、中间为过渡带，从尾部往回走。

**谱域代理指标在这类素材上不可用。** `peakiness` / "音乐分音突出度" / 梳状对比度
都无法把背景床的谐波梳与宽带机械瞬态的共振峰分开 —— 本例干净供体窗口的梳状对比度
（5.7 dB）**比纯音乐床（4.0 dB）还高**；短窗（27–224 ms）还会让 `nperseg` 超过信号长度。
已退役到 `trash/pkm-reload-debgm-20260928/`。可用的验收是：保留段逐样本一致、
采样数与峰值不变、差值远低于本体、拼接跳变远小于本体最大阶跃。
**但"抑制度"要用污染源自己所在的频带量**：本例用 250–1000 Hz 的床频带能量比，
而不是宽带 RMS —— 宽带 RMS 恰好会掩盖下面第 5 条那个失败。

### 5. 尾音重建的两条铁律（2026-09-28 第二轮，用户实测"还是有 BGM"后补）

第一版交付后用户实测**仍然听得到 BGM**。回读配方发现失败在方法本身：

- **不要把替换材料"染成污染源的样子"。** 原配方把供体做 11 频带色彩传递到**背景床**的
  频谱，再用 `oenv/cenv` 把它的包络拉到**背景床的电平**。结果不是"没有音乐"，
  而是**用干净素材把音乐床重新合成了一遍** —— 频谱、电平、包络全都是床，当然还像 BGM。
  正确做法：保留供体自身的机械音色，给一段**合成衰减**（从拼接点电平衰减到比床低 30 dB）。
  物理上，没有音乐的录音在撞击之后是衰减到本底噪声，不是维持在床的电平。
- **只处理尾音不够。** 连续音轨的每一刀都带音乐，按 6 dB 判据**每条 cue 有 23 %–74 % 的帧
  音乐未被掩蔽**，头段和中段同样要处理（本例把它们连同尾巴一起纳入判据范围）。

改完后床频带抑制度从 **12.5 dB → 22.5–44.8 dB**，且旧尾音电平是**比床高 1.4–5.1 dB**、
新尾音是**比床低 3.1–21.9 dB**。

### 6. 高通要加在"替换材料"上，不要加在资产上

DW715 那次是直接抬资产的 800 Hz 高通。本例照搬前先量了一下，结论是不能照搬：
床是低频嗡鸣（250–1000 Hz 占 78–90 %，音调分音在 **340 / 504 / 680 Hz**），
理论上高通很对症，**但 PKM 的 ChargePullMove 能量几乎全在 1 kHz 以下，加 1000 Hz 高通会掉
5.4 dB 峰值、8.1 dB RMS**。改成**只给供体加 1000 Hz 高通**：滤掉替换材料携带的床，
保留撞击本体的低频厚度。凡是想抬高通，先逐条量"这条 cue 的能量在滤波器通带里还剩多少"。

### 7. 先量"污染源住在哪个频带"，再决定用什么手段

本例花在诊断上的关键一步是终于去量了背景床的**长时频谱**（此前几轮都假设它够宽、
滤波分不开）。结果是它高度集中在 250–1000 Hz。**这一步应该在选路线之前做**，
它同时决定了"高通能不能用""抑制度该在哪个频带量"两件事。

### 8. 污染源不是平稳的：不要用"一个全局背景电平"算掩蔽余量

本例逐帧余量一直用**一个全局床电平**（五个参考窗、逐 bin 取 70 分位后求和）。
用户二轮反馈"是原视频 BGM 截进来的短暂声音"后，回头量整段 51.57 s 的
250–1000 Hz 包络才发现：中位 −47.3 dB、p10 −54.7、**p90 −37.9**、最高 −22.1，**跨度 63 dB**。
也就是说**音乐走到较响段落时，全局值会低读数 dB，所有余量都偏乐观**。
实测每条 cue ±2 s 邻域内**仅 250–1000 Hz 单频带**的中位电平（−46 ~ −48 dB）就已经高于全局值
（reload −49.2 / charge −46.7），而单频带必然低于全带 —— 局部确实比全局响。

**做法：余量要对"污染源自己的包络"算，并对每条 cue 用局部电平**（例如邻域内撞击间隙的
底值），不要跨整段取一个数。凡是写下"背景床电平 −XX dBFS"的地方，都要同时写清
**这是哪个时间窗、哪个分位、哪个滤波口径**下的数 —— 本例这条记录缺失，导致下游两轮都被误导。

### 9. 别把"安静段"当成"不含污染源"

本例 `BGM_FINDINGS.md` 原文写着：09-25 的音色参考取"该片段自己的安静周边（9.05–10.00 s）……
不含接触声，**因此不含音乐**"。**这个推理是错的**：污染源是**连续**的，安静段恰恰是它最清楚的地方
（同文档另一处就写着"安静段实测 −45 dBFS"）。更硬的矛盾是 9.05–10.00 s **同时**被列为
背景床参考窗之一 —— 同一个窗口不可能既"不含音乐"又"是背景床参考"。
**"这里没有接触声"推不出"这里没有污染源"**，必须先证明该窗内污染源确实缺席（量它的特征频带）
再拿来做参考。

### 10. 只修尾音往往不够：污染是沿整条 cue 铺开的

连续音轨裁出来的每一刀都带污染，**相邻两刀取自音轨里不同的时刻**，所以用户听到的是
**歌曲的碎片**而不是连续配乐。本例逐帧扫描显示每条 cue **23 %–74 % 的帧**音乐未被掩蔽，
头段与撞击之间的空隙同样带床。**判据要扫全条 cue，处理范围也必须覆盖全条 cue**，
"保留撞击本体"只要求保撞击瞬态，不要求连它前面的预卷和中间的空隙一起保。

### 11. 先画频谱图再设计：只看数字会把"污染铺满整条 cue"看漏

本例前三轮（9-25、v1、v2）**全部只看标量**——掩蔽余量、频带比、RMS——四轮里有三轮
把处理范围定成"尾巴"。直到把已装资产画成频谱图才发现：**污染源是一条连续亮带
（本例在 ~500 Hz 以下），贯穿每条 cue 的整个长度**，而机械接触只是撞击处的宽带瞬态块。
**能分开两者的维度是时间，不是频率**：污染源从不停，接触总会停。

**做法：动手前先画一张频谱图（和一张"纯污染源"参考图同尺度并排）。**
判据要扫全条 cue，处理范围要覆盖全条 cue。一份标量报告足以让三轮都走错方向。

### 12. 分离手段选"时间门"时：前瞻 + 非对称攻放 + 精确单位增益

判据改成"逐帧电平 vs **该 cue 自己的**底值"（不要跨整段取一个全局值）后，
用**前瞻式向下扩展**处理：

- **前瞻**：判定结果过一遍最大值滤波，让增益在撞击**开始之前**就回到 1.0；
- **非对称攻放**：开得快（3 ms）、放得慢（本例 8 ms）。开得快且有前瞻，撞击一点不动；
- **判为"接触音所有"的采样，增益强制为精确 1.0** → 这些采样逐位不变；
  又因为 g ≤ 1 恒成立，**峰值不可能升高**，不需要归一化或补尝。
- 分辨率要够细：本例 10.67 ms 帧在 205 ms 的 cue 上只有 19 帧，
  一帧膨胀加前瞻就把几乎所有暴露帧保护掉了，门根本关不下去；改到 **2.67 ms** 才行。

**已知代价，交付时要一并说明**：释放越快越深，但越像硬门限；本例 8 ms 释放下，
两个撞击之间只有 30–100 ms 的空隙，所以有些 cue 只拿到 1.5–4.1 dB 抑制度。
**这是"方向正确 + 实测有改善"，不是"已确认干净"。**

### 13. 换手重建有天花板，门限没有

供体 = 接触音 + 污染源，供体带多少，重建就带多少 —— 本例实测供体余量上限
**12.5 dB**（全解码搜索后最好的一段，20 dB 只维持约 100 ms）。
**"抑制度 == 供体余量"这条天花板是结构性的，换更好的供体也突破不了多少。**
门限式处理没有这个上限，也不需要供体。先问"我需要的抑制度，供体给得起吗"，
给不起就别在换供体上耗时间。

### 15. 真正的教训：动手前先确认"污染源是否可分离"，而不是先挑工具

本例参考视频是**成品混音**——BGM 与机械声录在同一个文件里，在**时间**和**频段**上
都重叠，没有分轨。这意味着任何方法都只能近似，而"用户听不出来"这个门槛，
五种做法都没跨过去。

**正确的顺序是：**
1. 先测污染源与目标声在时间和频段上**是否可分**（一起画频谱图看，别只看标量）；
2. 若不可分，**直接判定"这段素材不能用"**，换干净音源重做；
3. 只有在可分的前提下，才去挑高通 / 换手 / 门限这些工具。
