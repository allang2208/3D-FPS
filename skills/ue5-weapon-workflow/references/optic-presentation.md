# 瞄具：建模、镜内成像与运行验收

先确定玩家在 ADS 中要看见什么，再决定模型内壁和相机方案。瞄具外观模型不是光学系统：透明镜片加一根空心镜筒不会形成真实目镜的出瞳。

## 制作前的决策

- 三视图统一镜框、镜筒和导轨安装面尺寸；确认输入是设计板、单视角还是管线真正支持的多视图，不把多图拼板直接当单物体生成。
- 薄框、镂空或玻璃生成严重扭曲时，先检查参考图透视、暗色轮廓、透明背景和多视图冲突。可改用单个浅灰实心造型、清楚的背景分离；镜片、分划和机械运动件单独制作。
- 安装面按枪械导轨匹配，用户要求缩窄底座时保留上方镜框尺寸，不整体等比缩小。变倍环/拨杆有独立枢轴，镜身与活动件分别导出。
- 连续镜筒、同轴圆环、均匀滚花、旋钮槽及螺钉优先在 Blender 重建规则硬表面；只对生成网格减面/平滑通常保留融化和不均匀齿形。粗糙度与法线负责细小表面纹理，几何负责剪影、倒角与接触面。若最终外形已参数化重建，应如实称为重建，不能称为直接减面。

## 镜内画面的两种实现

- 近全屏高倍镜：主相机负责场景倍率，独立光学镜框/分划提供圆形窗口，完整 ADS 时仅对持枪者隐藏实体视模。镜口屏幕尺寸与倍率解耦；不要继续把缩小 FOV 当作扩大有效镜口的方法。现有 LPVO 采用此方案，无第二次场景捕获。
- 镜外正常、镜内放大：独立 SceneCapture/RenderTarget 投到镜面；分别校准镜内 FOV、分划和视口尺寸，并测量额外渲染成本。只有用户需要这种表现才引入，不能把它作为所有瞄具必选。
- LPVO 案例清晰圆口为屏幕短边 85%，这是本项目已选构图而非通用光学常数。相机拉近可辅助过渡，但不会消除远端镜筒的几何遮挡；外观资产可保留，用独立 ADS 显示解决。
- 屏幕分划与射击方向必须使用同一相机/瞄准基准，包括后坐力。切换到屏幕分划后不能仍从隐藏模型的几何红点取射线。镜外分划与 HUD 命中反馈按当前产品要求处理。

## 变倍、可见性与实例状态

- 仅可变倍率瞄具且 ADS 生效时处理滚轮，消费该事件避免同时切枪；固定倍率和菜单保留原合同。初始最小倍率，上下限钳制；退出再开镜保留已调值。是否跨武器/存档保留应单独决定，不能把同次装备的记忆说成跨进程保存。
- 同一配件的周期性 profile 刷新不能重置倍率。换配件、重建武器与再次 ADS 是不同状态边界。
- 重建武器时先销毁倍率环等子组件，再销毁镜身；验收唯一实例、父挂点、局部位置和环的旋转，防止孤立活动件挡住镜口。
- 隐藏模型使用持枪者专属显示控制，保留实体挂接状态；退出 ADS、换弹、装备/拆卸和菜单交互恢复。只恢复本功能改过的状态，不强制显示原来已隐藏的配件。
- 本项目用户指定高倍 ADS 隐藏全部游戏面板，保留镜内画面与分划。顶层游戏 Widget 记录原始可见性，ScopeOverlay 除外，退出或开始菜单交互时恢复；倍率逻辑不依赖倍率文字可见。引擎显存/编译调试消息不属于游戏 HUD，不通过隐藏警告假装修好性能。

## 必须同时看的证据

1. 真实相机放大比：用半角正切比检查最小、中间、最大倍率；实际滚轮测试上下限、反向调节、退出再开镜与固定镜排除。
2. 实际镜内占比：在真实游戏截图中测量清晰圆口和边框，不能只验证中心有红点、某个天空像素可见或 FOV 数值正确。检查镜口随倍率是否意外缩放，枪身/内壁是否残留。
3. 恢复与交互：开火/后坐力、换弹、取消 ADS、切枪、拆卸、菜单、存档刷新。检查射线跟随当前可见分划，HUD 按指定策略消失并恢复。
4. 截图检查避免把暗色场景物体当镜筒遮挡，也不要采到 HUD 文本当黑边失败；数值结果后仍查看实际画面。保留出现过视觉问题的对照，不能用纯数学断言撤销用户反馈。
5. 多进程/显存压力下，记录启动超时、实际进程是否继续完成和独立失败项。计时器回调延迟可能影响开火次数；不修改阈值以凑 PASS，不把 HUD 检查通过写成整套回归通过。
