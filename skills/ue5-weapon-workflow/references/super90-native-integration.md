# Super90：原生导入与修订边界

这是 FPSGAME 的 Super90 制作经验，不是实机通过记录。手臂及快速近战转 [接触与收势](../../ue5-fps-arms-animation/references/quick-melee-contact-recovery.md)。

## 表面错位先追溯输入配对

- 当前 source FBX 和 source PNG 的正确映射由 `SourceAssets/Super90Mapping20261007/mapping.py` 集中处理：`(u, 1-v)`。此前借用了另一个转换 GLB 的旋转约定而同时翻 U，导致机匣标识及枪托贴图错位。这个结论只适用于该组原始输入；不要给所有 FBX 或 GLB 强制翻 V。
- 共享 `M_WeaponSurface`／WS1 能统一材质响应，不能修复错误 UV。确认源图、UV 层、导出约定和变换是否已应用，再替换母材质；用版本标记避免二次 UV 转换。
- 原 PNG 法线为 DirectX，UE 不再翻绿；Blender 预览使用独立 OpenGL 转换。不能为了修正预览去污染 UE 原始纹理。

## 独立弹药与机械部件

- 源模型含装填用独立弹药，也含枪侧挂载的红色备弹。按部件语义分别管理：隐藏脚边的装填道具，保留挂载弹；不要按“弹药材质”整组清除。
- 枪匠／图标／拾取模型的可见部件与取景包围盒都要排除独立装填道具；仅运行时缩小或隐藏骨头，不能保证预览 bounds 正确。
- 普通持续装填维持枪身侧倾，逐次在入弹点记账；空仓机构动作单独处理。裁掉源末发动作附带的检视前摇时，保留独立检视与空仓换弹合同。枪机不应因为共享源轨道而在普通动作中自行往复。

## 动作与数据的所有权

- 原生 walk/run 与战术冲刺 entry/loop/return 共用上层通道时，由动作所有权仲裁。先 Apply 冲刺再覆写 SprintClip 会混入双手跑步并跳过左手离握／回握；退出输入后也要等 return 权重归零才交回移动层。
- 用户指定“移动握姿正确、只修 idle”时，在枪根空间迁移完整左链，并逐前握把处理。不要通过重跑旧装填全量 importer 覆盖后来的 idle、近战条目。
- Python 中反射数组／结构体视图不能跨可能重建容器的 `set_shared_clips_from_json` 等操作长期持有；写入前保存需要的普通值和资产引用，再合并未修改条目。保存成功也不代表原生消费者一定可安全遍历。
- R9 与 2026-10-09 的 R10（`SourceAssets/Super90LoaderR10_20261009/`，替换了 R9 正式资产）先后被用户实机判定不合格，工作暂停并记入待办，两者都不是认可案例。几何采样覆盖范围、材质保存回执、离线渲染或构建成功都不能充当“动作完整还原”的证据。

## 快速装填 R10 的历史做法（已被否定）

以下保留历史参数，不是认可方案。尤其扭转增量、固定旋前窗口、限速和下方勾拉均不能直接作为当前动画模板；R12 的原生蒙皮返工见下节。

- **端点**：用实际安装的 idle 数据（IdleMatchWalk 的 `inputs.json`＋`idle_patch.json`）和各握把 idle 差量，经 `evaluation_to_author` 换到作者空间。装填作者不导出 idle。Profile 导入只替换 `…/Speedloader20261007/Animations/` 条目，不能顺手丢掉 idle 条目。
- **抓握**：新握件沿用 R3 竖握把供体，在 V7 蒙皮上用 SDF 拟合，只解腕刚体与指屈伸。连接端要避开虎口：顶部连接会穿入约 10 mm，改为小指端连接。
- **取景**：用重建的腰射相机做网格求解，约束包括画面位置、画外推送比例、可达比、腕偏、旋前范围、肘离镜头、枪托遮挡，以及管/手与枪体、右手的间隙。最优解若贴枪（管与扳机护圈仅 3.6 mm），按间隙改选次优并写明原因。
- **前臂扭转**：旋前作为有界量，按固定窗口取值（左 [−300°,60°)），不做逐帧展开，否则会累积整圈导致扭转骨“麻花”。在本骨架上，护木 idle ≈ −136°、竖握 ≈ −101°、斜握 idle 在量测环另一侧（≈ −286°）。换握用定向扭转插值：取件为旋后，回握为旋前；只对大于 60° 的转动强制方向，但强制值若超过约 170°（斜握 idle 到握件本需走近 150°）必须回退到最短方向，否则会绕远路拧臂。蒙皮扭转增量要逐帧续传（展开到连续值）并按 ≤8°/帧 限速，再在末 16 帧向待机基准收敛：否则斜握族取管段每帧拧 ~50°，空仓收尾会在循环点留下 ~160° 残余。
- **肘与上臂**：按“自然前臂轴”在两骨圆上选肘，每帧肘向变化 ≤5°。手在画外时下沉后退锁骨，把上臂截断端移出画面。
- **空仓**：在本相机下，左手过顶拉机柄会让上臂横穿画面，已弃用；现按参考改为左手从机匣下方勾拉拉机柄（对接侧倾把拉机柄转到朝向左手的一侧，拉栓期间保持侧倾），枪机复进在末发 +48。右手食指按释放钮的旧路径保留为 `empty_mode='press'` 备选。
- **导入**：重导骨骼网格会保留旧材质槽名并按名匹配。换槽名（Rod→Anodized）要在重导前改，否则新部件落到错误材质。
- **上肩**：Super90 待机时托底已在右肩窝（相机系约 (−12.7, 13.2, −20.2) cm，右上臂根为 (−18.8, 20.1, −23.8) cm）。装填动作要“枪托在肩”时，俯仰、偏航、侧倾都以托底为支点，托底滑移不超过 3 cm，不能以右手腕为支点整体平移。
- **推送全程入画**：在本腰射相机下，450 mm 装填管的尾端必然出画；要整段推送可见需缩短到约 280 mm 并抬枪口约 30°。取管期间手仍应完全出画，道具出现时沿管轴从左下滑入，避免空手在画面里取物或道具凭空出现。

制作入口、许可边界、保留依赖与当前状态见工程 `Docs/Weapons/super90-publication-20261009.md`。不自动启动检查或游戏；仅在用户明确要求对应检查时执行。

## 2026-10-09 R12 原生蒙皮与参考构图返工

用户重新选择「枪托抵肩，枪姿和取景按参考视频」，替代 R11 的下压要求。作者源 `SourceAssets/Super90LoaderR12_20261009/`；完整记录 `Docs/Weapons/super90-speedloader-r12-plan-20261009.md`。R12 是返工候选，离线观察不等于实机认可。

- **找真实皮肤铰链**：Super90 原生 bind 近乎直臂，V7 皮肤来源是弯臂。用 `v7_skin_basis.json` 与原始 `v7_to_native_warp` 分别传递上臂和前臂 hinge，不能直接拿原生两骨叉积当皮肤零位。本骨架没有上臂 twist helpers；加一个更新上臂 twist 的循环不会修到它。
- **写完整变形场**：R12 对 aux、twist_02、twist_01 按原生 0、1/3、2/3 站位分配绝对旋转；前臂份额 ±100°，余量同时传给上臂与前臂近端。连续旋转分支只消除 ±180° 符号跳变，不把源 idle 上已经存在的扭转再叠加一遍，也不让限速后的手臂旋转落后于固定接触的手腕。
- **接触决定腕，整链支撑腕**：拉栓是绕过机匣后勾住侧柄，不能误做成抬肘、手指向下再用折腕补偿。R12 用腕偏锥和真实骨长反解整臂，活动段腕偏 28°，已认可 idle 端点保持原样。旋掌分布在整段跨越动作中。
- **看真实开口而不是肩骨点**：当前裸臂开口在 upperarm 原点之外。应从原生网格边界环建立隐藏约束；只把 upperarm 骨点放到画外仍会露出截断面。
- **参考构图先量投影**：本轮固定托底、装填俯仰 13°／偏航 10°／侧倾 66°，来自参考装填口和枪口的屏幕位置；这些是本镜头参数，不跨枪套用。推送握钮方位 100°兼顾可见性和前臂旋转。
- **版本边界**：普通分支、管长和游戏事件时钟仍是适配项。只替换 15 个 loader 动画及四份 Profile 的 loader 条目，保存包前后散列；idle 和其他动作不重写。没有用户认可时不勾选自然度、无穿模或百分百复刻待办。

## 2026-10-12 当前状态与恢复

快速装填已经恢复开发，用户认可完整动作；当前 R24 姿态叠加 R25 分段播放时钟，新节奏待用户体验。普通空仓采用 NativeEmptyBolt＋PacingR2，快速近战采用 RightArmR9，移动右链统一认可的 idle。Super90 基础和最低射击间隔均为 60 ms；快速装填在压实点一次补齐可装弹药，普通装填仍逐发处理。镜头参考其他长枪的接触强度，不重复叠加枪手烘焙冲量。
