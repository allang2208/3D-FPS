# 武器说明文字与「特殊性质」段

新增或修改武器时，**详细介绍（`items.json` 的 `desc`）** 与 **特殊性质（枪匠目录的 `traits`）**
是两套字段、两条生效路径。用户于 2026-09-22/23 定下格式，之后新增武器按本文生成和填写。

## 详细介绍 `desc`

### 写法

一段话，讲清三件事：**来历、特征、怎么用**。允许并鼓励把优缺点一起写出来——
玩家看完应该知道这把武器在什么距离、什么节奏下用。**压在 200 字以内。**

按来源分两类（用户 2026-09-22 裁定）：

| 来源 | 写法 |
| --- | --- |
| 现实存在的武器 | **参考百科**：设计者、自动原理、服役背景，再落到游戏内手感与定位。 |
| 虚构武器（含生成的枪体、剑类奇幻武器） | **编写背景故事**，再落到游戏内手感与定位。 |

### 硬规则

- **不用"最""第一/第二档""之首""唯一"这类排行与序数设定词。** 后续还会加武器，
  排行式说法一加新枪就自相矛盾。
- **不引用别的武器型号做定位**（"介于 X 与 Y 之间"）。同样是新武器一加就失效。
- 现实武器的**前代型号**可以提（M16A2 提 M16A1 属百科常规写法），那不是游戏内排行。
- **不重复实时数值。** 射程、射速、伤害、后坐由 `gunsmith.json` 的 `base` 提供，
  在物品提示里单独成行；介绍只写性格与定位，避免两处口径打架。
- 描述里出现的每个数值都要**回目录核对**后再写。本项目实际发生过三处写错：
  ASH-12 写成"全枪种单发最高"（实为步枪中最高，左轮 68 更高）、
  M16A2 写成"射击间隔全枪种最短"（实为 A762 的 0.0667 s）、
  DW715 写成"手枪之首"（实为全枪种最高单发）、
  高地剑写成"攻击距离在双手剑中偏长"（三把剑同为 180 cm）。

### 生效路径：`desc` 是实例快照，必须迁移

物品提示读的是**物品实例 Data 里的快照**（`ColdSteelItemTooltipData` 经
`CombatItemFormula::Read(I)`），不是直接读 `items.json`。所以只改目录时，
**已经持有的武器仍显示旧文案**。

实测证据（2026-09-22）：改完 `items.json` 后，旧文案在 `ColdSteelPlayer_A.sav` 里
仍命中 1–2 处、新文案 0 处。

`ColdSteelProfileRuntime.cpp::ReloadProfile()` 里有目录同步：目录有非空 `desc`
且与实例存值不同（或实例根本没有该字段）时写回并走 A/B 校验提交。
所以改完 `desc` 后的生效链路是三步，**顺序不能反**：

1. **构建** —— 迁移代码要先在 DLL 里；
2. **重启编辑器** —— `items.json` 只在 `UColdSteelStatusModel::Initialize()` 读一次并缓存，
   编辑器启动必须晚于文案修改；
3. **进入游玩** —— 编辑器不创建 game instance，子系统没有实例就不会调 `ReloadProfile()`。
   实测编辑器里 `game instance: None`，要用 `EditorAppToolset.StartPIE` 触发。

## 特殊性质 `traits`

### 放哪、为什么

放**枪匠目录**（`gunsmith.json` 的武器块、`melee-gunsmith.json` 的 `weapons` 条目），
与 `base` / `allowed` 同级：

```json
"traits": [
  { "icon": "special",  "text": "按 G 唤出 4 把环绕身体的飞剑，最长驻留 30 秒……" },
  { "icon": "magic",    "text": "每次确认命中减少全部技能冷却 0.5 秒……" },
  { "icon": "drawback", "text": "移动速度降低 33%，收起武器后恢复" },
  { "icon": "neutral",  "text": "枪口、瞄具、枪托、后握把、下挂与战术槽全部可改造" }
]
```

**刻意不放 `items.json`**：目录是每次读盘解析的，所以改 `traits` **直接生效，不需要迁移**。
`icon` 只是语义标签，颜色由 UI 映射，新增武器不必改 C++。

| icon | 颜色 | 用于 |
| --- | --- | --- |
| `special` | 蓝 | 特殊攻击模式、键位技能 |
| `magic` | 紫 | 魔法伤害与冷却、符文 |
| `mechanic` | 青 | 供弹、后坐、弹匣、开镜 |
| `drawback` | 红 | 代价 |
| `neutral` | 灰 | 其余特性 |

### 写几条、写什么

2–4 条。每条一句话，**只写玩家能感知的效果**：击发方式与间隔、弹匣、后坐/散布特征、
换弹耗时、可改造槽位、独有的攻击模式或魔法效果、以及明确的代价。
数值要回代码或目录核实（例：机枪移速 −33% 来自 `machineGunMastery.movementMultiplier`，
符文剑命中减 CD 0.5 s 来自 `RuneSwordComponent.cpp` 的 `SwingCooldownReduceSeconds`）。

## 两个容易漏的坑

- `UGunsmithSystem::Weapon()` **只查枪械表**，近战在 `MeleeWeapons` 里；工具提示必须用
  `ModifiableWeapon()`，否则近战永远没有「特殊性质」段。
- 近战目录的 `weapons` 是**对象数组**（`{"id":..., "traits":[...]}`），加载时把条目本身
  存进 `FGunsmithWeapon::Source`；没有 `Source` 就读不到 `traits`。纯字符串写法仍兼容。

## 交付检查

- [ ] `desc` ≤ 200 字，含来历/特征/用法，无排行词、无跨型号引用、数值已核对
- [ ] `traits` 已写入对应枪匠目录，条数与 `icon` 分类合理
- [ ] 改过 `desc` 时说明"需要重启编辑器 + 进一次游玩"才在旧存档生效
- [ ] 改过 C++ 时完成常规构建；`traits` 只改数据无需构建
