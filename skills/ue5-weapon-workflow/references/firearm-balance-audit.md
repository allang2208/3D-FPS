# 枪械数值审计与联机／存档连带检查（2026-10-19）

调一把枪的数值从来不是只改一个字段。本文沉淀枪械平衡审计的口径、连带检查清单和联机核对点，配合 [武器基础与强化系数调参](weapon-formula-balancing.md) 使用。

## 1. 核对口径

同一张表里只用一种口径，否则结论不可比：

- **C 档基准**：属性 60/60、强化 +15、精通 30、无工艺与附魔。
- **内核**：`core = base + 15×enhanceFlat + Σ属性×(系数 + perEnhance×15)`。
- **面板**：`Round(core × (1 + 0.01×精通) + 精通×flatDamagePerLevel)`。
- **输出四件套**：单发、身体瞬时 DPS（`面板/间隔`）、持续 DPS（`弹匣×面板/(弹匣×间隔+空仓换弹)`）、要害（及要害＋暴击）DPS。
- 对比必须用同口径族带锚点；面板和单发混着比会得出相反结论。

## 2. 「优势只在条件满足时出现」的调法

用户要求某类武器只在「持续命中弱点」「吃到暴击倍率」时才压倒性领先时，顺序是：

1. 降 `base` 与 `perEnhance`，把**无条件输出**压到目标族带以下（不是压低整个族带）。
2. 把优势搬到条件项：`innate_weakpoint_percent`（与步枪精通的 0.30 相加）和 `critDamageBonus`。
3. 用四个数验收：身体瞬时/持续低于参照族带；要害略高于参照要害；要害＋暴击显著高于（2–3 倍）。
4. 区分同族两把枪时不要靠 DPS 差，用「单发 vs 射速」「射程/弹速」「主属性纯度」分工。

本轮实例（SVD/SVCh）：面板 1022/1024 → **740/640**，身体瞬时 2920/3413 → **2114/2133**（步枪族带 2312–2910 之下），持续 1262/1403 → **914/877**（步枪 835–1212 之下），要害倍率 1.30 → **2.20/2.00**，要害＋暴击瞬时 **9303/8533**（步枪要害 2540–3780 的 2.3–2.5 倍）。详见 `Docs/Combat/sniper-formula-audit-20261019.md`。

## 3. 改一个字段要连带检查的四处

1. `gunsmith.json` 的 `base`：显示与派生都读它。
2. `items.json` 的静态 `stats`：浮窗对武器会跳过「物理攻击」「弹匣容量」，但目录里别留过期快照（“两套数字”就是后面误判的源头）。
3. 依赖基数的选项：`mag_delta`、`reload_mult`。案例：201 轻机枪基数 30→40 后，125 发弹箱的 `mag_delta 95` 会变成 135，必须同步改 85。
4. 旧档迁移里的硬编码基数：`ColdSteelAmmoRuntime` 退役弹箱把余弹夹到 30，基数改 40 后要同步，否则旧档留下 30/40 的弹匣。

## 4. 目录调校字段与实例快照（最容易漏）

- 物品实例的 `Data` 是创建时的定义快照。新增 `innate_weakpoint_percent`、`innate_armor_penetration`、`critDamageBonus`、`weaponType` 这类目录字段后，**旧存档读不到**；联机时服务端影子档案同样读不到（影子由复制来的 profile 建立），静默按 0 处理。
- 两种修法，选一个并只留一个主机制：
  - **写时迁移**：在档案加载、`CreateShadowModel`、`AdoptNetMirror` 三处按目录补写实例 `Data`（工程内为 `ColdSteelProfileRuntime`）。
  - **读时兜底**：`ColdSteelInventory::Number` 在实例缺键时查定义目录缓存（首次解析一次 `items.json`，只缓存声明了该键的少数定义）。影子档案走同一函数，一次覆盖单机与联机，且不写存档。
- 排查顺序：`Number(Item,Key)` 与目录不一致时，先确认实例 `Data` 有没有这个键，再怀疑公式或面板。

## 5. 联机核对清单

- 客户端只上报「命中 + 语义 flag」，服务端按影子档案重新 `Snapshot` 结算；不要在客户端新增可信字段，也不要把伤害构成放进上报。
- 目录派生量（`EffectiveWeaponRangeCM`、`Spread`、`Capacity`）必须双端同源；改射程/散布后查 `ColdSteelSuper90Authority` 一类代码有没有硬编码距离或数量。
- 影子档案与本地档案一样会带旧快照，所以迁移/兜底必须覆盖影子路径，而不只是 `Saved/SaveGames`。
- 交付时把「配置推算」和「联机实测」分开写，编译通过不等于联机正确。

## 6. 交付边界

- 只改目录（JSON）不需要编译；改了 C++ 再构建 FPSGAME 与 FPSGAMEEditor，如实报告结果。
- 构建常被并行会话的半成品挡住：按报错文件判断归属，只重试、不替别人改；连续失败时把失败文件清单写清楚。
