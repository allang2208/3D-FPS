# 枪械腰射构图：批量标定与配置复用

适用于 FPSGAME 的步枪／狙击步枪腰射默认位置、新枪接入，以及模型或待机变化后的构图重算。2026-10-02 起采用“共用开发基准 + 按枪保存展示偏移”。手枪、机枪、弓和近战武器需要自己的构图配方，不能直接套步枪数值。

本流程用于后台制作与记录。读取制作输入、采样待机和计算候选属于标定制作；不自动启动编辑器、游戏、截图、渲染、自检或回归。用户要求检查／预览时才执行相应内容。纯 SKILL 更新不运行标定或构建。

## 标准化什么

统一厘米、相机坐标、枪轴／上方向、姿态采样方式、关键细节指标、记录格式和运行时入口。展示位置由各枪几何计算后保存，保留型号差异。不同枪的右手腕不必处在同一深度。

当前运行入口为 `Source/FPSGAME/Weapons/RifleHipFraming.cpp`：
- `Initialize()` 建立共同目标，并把 `PresentationOffset(Definition)` 加入一次。
- `SelectIdle()` 根据当前待机及握把 profile 求最终刚体位置与旋转，结果缓存。
- 构图求解在制作阶段完成；运行时只复用保存的偏移及现有换枪／换 profile 解算，不在 Tick 扫描几何、加载资产或逐帧追踪手腕。

当前已有的是八枪偏移表和单次排查脚本，尚无通用批量求解器。下文规定后续制作工具与标定任务应遵循的算法；记录 JSON 是制作记录，当前运行时不会自动读取它。

## 何时复用、何时重算

| 情况 | 处理 |
| --- | --- |
| 同一枪、同一几何／骨架／待机／相机配方 | 直接复用记录与偏移，避免重新逐次试位置 |
| 只改材质、音效或数值 | 沿用构图记录 |
| 新枪，或枪体尺寸、待机枪根／腕位、绑定、相机 FOV 发生变化 | 将受影响的定义放入一次批量标定 |
| 普通握把／弹鼓切换，已有 profile 合同仍适用 | 复用同一展示偏移，交给 `SelectIdle()` 重新解算 |
| 配件改变枪体轮廓或 profile 改变枪体与手腕关系 | 在该枪记录内新增受影响分支；不默认重做全部枪／全部配件 |

记录来源版本及配方版本；输入变化时更新对应记录，不根据文件名里的 Final 或日期推断实际运行版本。

## 一次批量制作

### 1. 整理输入，先统一空间

从当前 `FPSGAMECharacter.cpp` 和武器资源引用取得实际 mesh、idle、profile、瞄点及组件缩放。每枪采样基础 idle 的 0 秒，profile 的局部 delta 在累积骨骼变换前应用；累计父骨骼链后才得到组件空间。

共同基准沿用当前 M4：`/Game/Weapons/M4ContactImpactFinal/A_AKM_idle`，锚点 `(0, 7, -7)` cm、基准 `FRotator(0, 90, 0)`、当前组件 scale 为 1。枪轴由后瞄点指向前瞄点，上方向取同帧 `WPN_root`；用完整坐标系约束滚转。AKM 使用其实际骨骼局部瞄点，不能直接套共享标记。

FBX 根的 100 倍换算和组件 scale 分别按实际数据处理一次，避免把骨骼局部米直接当厘米。源几何先变到实际枪根／骨骼空间，再用对应 idle 姿态和共同腰射变换投到相机空间。源姿态与 UE 已保存动画采样分开注明；可获得已保存动画的后台采样时优先使用，不把 Blender 的作者帧直接称作游戏姿态。

### 2. 选关键细节区域与共同指标

每枪按机械身份标记机匣可见侧／上部、枪机或抛壳口、后部导轨／照门等区域。上部弹匣、护木可按枪型加入。使用部件名、面组或骨骼局部特征点保存区域，避免依赖每次分件后会变化的裸面索引。

不要拿包括枪托、隐藏原件和整条手臂的总包围盒决定距离；它会把需要露出的机匣挤出画面。枪体细节和手臂画面边缘分别记录。

目标优先继承该枪已有的用户认可构图；新枪继承同构型的认可配方（常规步枪、无托步枪、长枪分别选择）。共用 M4 坐标基准不等于每枪必须获得 M4 的画面轮廓。

没有认可构图时，制作初值为“选定的关键特征点全部入框，距四边至少 2%”，记录 `target_origin = production_candidate`。这是求解初值，不是用户已经认可的视觉标准。关键部件的投影面积／画面占比目标从相应参考记录继承，不编造统一的全枪覆盖率。

至少区分三种指标：
- 关键点是否入框：用于直接求距离及边缘余量。
- 分部件裁剪后的投影面积／屏幕范围：用于避免前移过多后细节变得太小；采用三角形裁剪、投影计算并记录方法。
- 遮挡与真实可见像素：需要渲染；只有用户要求相关工作时才测量。

顶点入视锥比例可辅助定位丢失部位，但受拓扑密度影响，也不包含遮挡，不能称作“可见面积”或游戏画面覆盖率。

### 3. 用投影约束直接求前移量

相机空间约定：X 向前、Y 向右、Z 向上，位置单位 cm。记录实际 FOV 轴、宽高比和近平面。当前工程参考配方是垂直 FOV 75°、16:9、近平面 1 cm；相机配置改变时按新参数重算，不能当作所有项目固定值。

垂直 FOV 下，令 `tV = tan(vFOV / 2)`，`tH = tV * aspect`。X 大于近平面的点投到归一化画面：

```text
u = 0.5 + y / (2 * x * tH)
v = 0.5 - z / (2 * x * tV)
```

保持共同旋转和 Y/Z，整体前移 d 后，点变为 `(x+d, y, z)`。对四边相同的横／纵余量 mX、mY，关键点所需距离为：

```text
d_i = max(
    near_clip - x,
    abs(y) / ((1 - 2*mX) * tH) - x,
    abs(z) / ((1 - 2*mY) * tV) - x
)
d = max(0, max(d_i))     # 全部选定关键点满足约束的最小前移
```

余量取值必须在 [0, 0.5)；近平面可在配方内另留小余量。这里的 max 只覆盖选定关键特征点，不能覆盖整枪所有顶点，否则会强制让枪托也完全入框。

需要分部件覆盖率时，对固定的语义采样点求阈值，或按三角形区域面积加权；不要对不同拓扑的全枪顶点数直接取同一百分位。计算最小 d 后，再计算关键区域投影大小；超出该配方的距离上限或无法同时满足细节大小时，记为目标冲突。

有目标冲突的枪进入同一次批量的第二阶段：在记录给定的小范围 Y/Z 候选中解算各自最小 d，按“满足关键区域目标 → 保留细节大小 → 改变量最小”排序。未设置 Y/Z 范围时保持为零。保持模型比例和共同旋转；不靠缩放模型、旋转滚转或改变全局 FOV 掩盖冲突。缺少必要输入的枪记录缺项，其他枪照常产出；不进入无记录的多轮肉眼试调。

### 4. 保存配方与一次接入

每枪复制 [标定记录模板](../assets/hip-framing-record.json)，保存为工程 `SourceAssets/WeaponHipFraming/<definition>/hip-calibration.json`。同一批任务只读一遍共同基准和相机配方，为受影响枪输出记录与汇总；不建立逐帧解算机制。

记录必须能回答：用了哪个源／UE 资产、哪一帧和 profile、什么相机参数、哪些细节区域、参照哪份构图、为何得到这个偏移。记录输入版本或导出签名、原位置、候选位置、指标方法与数值；未测项填 null，不能用零代替。记录配方修改原因，保留已有用户认可状态的来源。

实际接入集中修改 `RifleHipFraming::PresentationOffset()`，并同步制作记录。当前 JSON 尚未接入运行加载，写好记录不代表已应用。新增枪型还需纳入 `Supports()` 和已有装备初始化入口。共同基准、展示偏移、ADS 标定分别维护，不在各状态分支重复补数值。

整枪与双臂作为同一刚体移动，保留手部相对接触。偏移只加入一次；握把／弹鼓重新选择待机时从目标重新计算，避免累计漂移。换弹、检视、快速近战的原动作空间及收势窗口继续交回新的腰射位置。ADS 仍由瞄点、同帧上方向和眼距求独立目标，再按既有权重过渡。

### 5. 按实际完成阶段交付

区分“候选已计算”“源码已接入”“后台构建产物已保存”“用户视觉认可”。新偏移未经用户测试时保持 `user_visual_accepted = false`；不从构建成功推导画面或动作衔接通过。只有源码变更才做必要后台构建，纯记录／SKILL 更新不构建。

用户后来给出针对某枪的反馈时，回填对应目标或认可记录，再批量重算受影响项；保留共同计算方法，不回到各状态里手工加偏移。
