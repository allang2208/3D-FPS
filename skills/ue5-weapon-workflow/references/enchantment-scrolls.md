# 附魔卷轴：数据、限制键与战斗接入

一次附魔卷轴开发 = **四处数据 + 限制键 + 战斗消费点 + 同源提示**。审计与运行测试仅在用户明确要求时执行。涡轮增压（前缀、机枪、射速爬升）
与汇聚（后缀、狙击步枪、整匣聚合）是 2026-09-29 的两个完整案例，数值、取舍与验证边界见
[附魔卷轴「涡轮增压」](../../../Docs/Combat/enchant-turbocharger-20260929.md) 与
[附魔卷轴「汇聚」](../../../Docs/Combat/enchant-convergence-20260929.md)；
汇聚的曳光三层表现见 [Gunplay 与 Niagara 验收](gunplay-vfx.md) 的「表现分层」一节。

## 数据落点（四处，缺一不可）

- `Content/ColdSteelData/enhancement.json`：`id` / `item` / `name` / `slot`（`prefix`|`suffix`）/ `restriction` / `dust` / `description` / `effects`。同槽位的词缀互斥（前缀：涡轮增压 vs 骷髅射手；后缀：汇聚 vs 狼蛛）。
- `Content/ColdSteelData/items.json`：卷轴物品本身（`category: consumable`、价格、堆叠 99、图标沿用现有卷轴外观，不必新做美术）。
- `Content/ColdSteelData/dungeon_loot.json`：按深度分档的掉落权重与数量区间。
- `Content/ColdSteelData/tooltip-reference.json`：提示栏占位，漏了就缺项。

## 限制键：先看目录里真正存在的字段

`CanEnchant` 按 `restriction` 分流：`weapon` / `firearm` 是通用口径，类别键要读对字段——
**狙击步枪在目录里只有 `weaponTypeTag`**（SVD 的 `weaponType` 仍是 `rifle`，读 `weaponType` 永远不匹配），
机枪读 `weaponType == "machineGun"`。新类别键要在 `Supports` / `CanEnchant` / `MaxLevel` 三处口径一致，
用户要求审计时，在 `ColdSteelEnhancementAudit.cpp` 覆盖定义加载、类别正例与不适用类别反例。

## effects 的合并与消费

- 数值键在实例上**相加**合并，唯一例外是 `attackIntervalMul`（相乘）；非数值键直接覆盖（见 `ColdSteelEnhancementSystem` 的合流处）。同一键被多个词缀叠加时，语义必须可相加。
- 战斗侧**不要在开火循环里读 JSON**：在 `ApplyColdSteelProfile` 里解析成缓存参数（`ColdSteelCombat::TurboRamp` / `Convergence` → `TurboRampParams` / `ConvergenceParams`），开火时只做插值或系数计算（`EffectiveFireInterval()`、`FireShot()`）。
- 一次附魔的多个键同属一体：缺任意一项就视为未附魔，避免半套数据把行为改成未定义状态。
- 不写 `attackIntervalMul` 就不会污染静态面板：动态射速只在开火路径生效（代价是提示栏的静态"射击间隔"仍是目录值，要在提示里补实战两档读数）。
- **伤害类型沿用原枪械**：只需缩放伤害**标量**，伤害类型组成由 `Shot.DamagePanel` 的比例决定，缩放不改变类型。

## 必踩的坑

- **读附魔字段一律判空**。改造台的产品预览等物品没有 `_enchantEffects`，`EE` 为空；`EE->TryGetBoolField(...)` 直接解引用会崩在 `BuildColdSteelItemTooltip → RefreshProductPreview → NativeOnInitialized`。提示栏里只有被 `if(EE)` 包住的分支可以直接读，其余一律 `if(EE)` 再读。
- 命名空间内的前置声明会**遮蔽真实类型**：`namespace ColdSteelCombat { class UColdSteelEnhancementSystem; }` 会新建 `ColdSteelCombat::UColdSteelEnhancementSystem`；前置声明要写在命名空间外（本项目 `ColdSteelEnchantmentCombat.h` 的做法）。
- 射速爬升的期望值按积分算：`N(t) = (1/I)·ln(3/(3−2.5t/T))`（起 3 倍间隔、终 0.5 倍间隔时），不要拿两端点做平均。
- 提示栏、工作台预览、实战必须读同一份结果（枪匠的统一评估入口 + `WeaponStatEvaluation` 的伤害分解），不要各自换算。

## 交付与验证

- 编译证据：源 → obj → DLL 的时间戳链，加 DLL 内 UTF-16 宽串扫描新增的 CVar 与日志串。
- 表现类改动的"看不见"排查顺序：**先看诊断日志确认链路**（附魔是否生效 → 标记是否传到表现层），再调实时 CVar 定观感；不要凭观感直接改几何。
- 用户未要求时不主动测试、截图或跑 PIE；把"已编译未实测"写进交付说明与案例文档。
## 碎裂子弹：一次弹射与伤害继承（2026-09-29）

史诗后缀 `shatterBullet` / `enchant_scroll_shatter_bullet`，所有枪械；5 m 内随机一敌，直接击杀后向所有其他敌人各发一颗，子弹只弹射一代。当前案例：工程 `Docs/Combat/enchant-shatter-bullet-20260929.md`。

- 附魔参数在 `ColdSteelSkills::Snapshot` 中仅对 fired firearm 捕获，共用 `ApplyHit` 入口覆盖飞行、瞬发、枪口遮挡与双持。近战/弓箭/魔法不继承枪械触发。
- 继承 100% 时用原命中的 `FWeaponDamageResult::BeforeDefense`，包含原暴击/要害/距离倍率，保留四通道构成；新敌人自行减伤。不要复制 Applied（受原护甲和残血限制），也不要再次掷暴击或乘要害。
- 直接击杀标记须在原伤害结算后、后续 on-hit 效果前捕获。弹射子弹同时标记 `bRicochet` 并清空触发半径，从产生端和命中端阻断再次弹射。
- 用 Pawn 球形重叠查询、Actor 去重与墙体遮挡选敌，不按每发扫描全世界。群体分发每名候选各一颗；先放 Pending 队列，活动弹丸循环结束后再入池，避免 TArray 引用失效与递归爆发。
- 新卷轴补掉落模型分支：`ColdSteelPickupConsumable` 现在按 `enchant_scroll_` 家族复用正式卷轴模型，不再只识别早期四张卷轴。
- 当前源码/数据接入与必要构建不代表实机验收；用户未要求时不运行审计、测试或游戏。

### 紫晶碎裂表现（2026-09-30 用户选定）

- 三段：原命中点小型裂闪、真实弹道的淡紫亮芯与紫色窄光晕、弹射末端晶屑。击杀仅加强一次起点迸裂；只向实际弹射方向画线，末端不再裂射。设计与接入记录见工程 `Docs/Weapons/shatter-bullet-vfx-reference-20260930.md`。
- `UFPSShatterFXSubsystem` 为世界级独立视觉池，用「弹道组件 + 弹丸 ID」区分双持；切枪不清掉世界余迹。四组 ISM 批量绘制，固定 96 条弹迹、144 枚晶片、48 个闪光位和最多 2 盏短促无阴影灯，空闲停止 Tick；不要将视觉池数量变成伤害选敌上限。
- 真实弹速保持不变；默认到达后保持 0.04 秒，再渐隐 0.16 秒。空间轨迹来自实际 Trace 的终点，不预画整条预测连线。视觉随机流独立，不能改变选敌和暴击的随机序列。
- 双持对每只手传入各自 `H.Item`；枪口遮挡直接结算也要填写 `Shot.BulletSource=H.Ballistics`、`Shot.BulletFX=H.FX`。不从另一只手或角色主武器继承附魔。
- 作者入口 `Tools/AssetPipeline/build_shatter_violet_v1.py` 保存专属材质与原创八面体晶片；材质的局部位置和逐实例数据经 VertexInterpolator 传入像素计算。白芯与紫边独立配比，不靠高亮度把所有通道推白。用户选定的是设计，实际 UE 观感仍需用户测试。

### 感电的：近战击杀连锁（2026-09-30）

- 史诗前缀 `electrifiedMelee` / `enchant_scroll_electrified`；`melee` 限制与 `ColdSteelInventory::IsMeleeWeapon` 一致。近战命中有 25% 概率向 5 m 内随机一敌放电，近战直接击杀时为 100%；使用命中回执 `bKilled`，不把后续 on-hit 击杀混入。闪电击杀才向周围全部敌人分发，后代不再掷 25% 概率；可继续击杀连锁，每轮敌人去重。旧附魔实例直接采用公共触发规则。工程记录：`Docs/Combat/enchant-electrified-melee-20260930.md`。
- 复用 `LightningStats(max(10, 当前闪电等级))` 和 `ApplyLightningHit`，不把附魔最低等级写入存档技能。5 m 与分发规则覆盖普通闪电的目标数/跳距，其余伤害衰减、眩晕、感电、过载参数沿用技能；独立组件不占主动施法成本与冷却。
- 首击结束后排队，后代每 0.06 秒处理；不要在近战伤害事务内递归闪电。闪电本身不回调武器触发，自动附魔不额外修炼主动技能；正常击杀奖励仍结算。
- 剑身副本 `NS_ElectrifiedBlade` 使用局部空间、细 ribbon 与显式样条绑定，移除 Detail 发射器；V3 只保留最新武器电弧的一盏短促照明灯；运行期读取真实刃部点。剑身动画与世界连锁分别管理，换下武器只移除剑身效果。制作入口 `Tools/Skills/build_electrified_melee.py`，沿用现有闪电原材质，不重做已认可配色。
- 当前视觉为下节 V3 的断开闪电弧段与短分叉，完整圆箍已被用户否决。制作入口 `Tools/Skills/build_electrified_orbit.py` 仍写入 `OrbitV2/SM_ElectrifiedOrbit`、`M_ElectrifiedOrbit`，目录名不代表运行旧版。保留 `SourceAssets/ElectrifiedOrbit20260930` 原创源和当前资产；不要因 V2 名称误归档。只改变武器表现，保留 25%/100% 与世界连锁规则。
- 未实机验收；源码、保存资产、构建成功与观感认可分开报告。

### 裂空：剑类蓄满重击剑气（2026-09-30）

- 用户选定史诗后缀 `riftSlash` / `enchant_scroll_rift_slash`，仅剑类。蓄满重击接触开始帧释放一次，空挥也释放；未蓄满、出手前取消、普通攻击及其他主动近战技能不触发。
- 使用同次 `SwingDamage` 与 `SwingSkills` 快照，剑气伤害为该次重击的 100%，继承类型与穿透，目标各自结算暴击和防御。12 m、18 m/s、敌人穿透且 Actor 去重，遇场景阻挡停止伤害并溶解 0.20 s。换装不改变已经飞出的快照。
- 独立 `AFPSRiftSlashProjectile` 从瞄准原点做完整位移扫掠；不要直接在眼前偏移点生成而跳过近墙。通道扫掠越过身体后继续找墙，墙后目标不结算。次生伤害清除感电/碎裂触发，不重复提交重击档位修炼。
- 剑刃原命中保留，近处可能同时受到剑刃与剑气各一次打击。剑类限制必须在 `CanEnchant` 显式处理 `sword`，使用剑类改造目录 `IsMelee`，不要放行采集工具。
- 原创资产作者入口 `Tools/Skills/build_rift_slash.py`，源文件 `SourceAssets/RiftSlash20260930`，保存目录 `/Game/Weapons/RiftSlash20260930`。当前 V4 为面向发射视角的双尖轮廓、中间厚的蓝白能量剑气，边缘羽化，配淡蓝尾雾与少量 Niagara 流光；用程序材质，不使用 Fab 商品素材。运行期异步加载，不在发射回调同步加载。
- 详细合同见 `Docs/Combat/enchant-rift-slash-20260930.md`。后台制作与编译不代表实机测试；用户未要求时不自动测试、渲染或启动编辑器。
