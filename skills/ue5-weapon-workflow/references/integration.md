# 枪械接入、装配与运行合同

## 模型与材质

- 用户于 2026-09-25 指定所有新枪、新武器及动画以当前认可的 V7 裸手、裸臂为开发和默认显示基准；手套、衣袖作为装备外观适配。按本枪原生骨架制作派生，不为迁就旧动作替换手型。来源与接入规则见 [认可的裸手基准](../../ue5-fps-arms-animation/references/accepted-bare-hands.md)。

- 保留用户选定枪型与当前手臂外观。读取 `FPSGAMECharacter.cpp` 和对应武器资产头文件的真实加载路径；历史 M4HK416Replica、Cubic 手模或 M4InfimaV3 只作来源记录，不能覆盖当前 V7 派生入口。
- 源骨架、rest、逆绑定、单位、轴与材质槽一起审查。跨引擎转换按基底/四元数处理；Blender 源长度与 UE 厘米单位之间只转换一次。不要复制不匹配 rest 的局部旋转。
- 先处理几何连接、反向面、权重和材质槽，再调材质。金属、聚合物、皮肤、手套、衣料、光学镜片分别校准；保留有用的原生法线和受控粗糙度。游戏、枪匠预览和图标使用一致来源，检查迟生成配件的最终材质。
- 新衣服/手套需要合适网格、UV、权重与关节弯曲空间；材质不能生成衣服厚度或修正坏蒙皮。外观升级仍检查袖口、手腕、肘和所有接触姿态。Godot 的聚合物 shader 或历史统一染色数值不作为 UE 默认材质参数。

## 配件与 ADS

- 折叠机械瞄具由当前改造状态直接决定：装光学瞄具时保持折叠，卸下后立即恢复。切枪和重建组件时立即应用已有状态，不从展开姿态插值播放折叠动画。前后瞄具分别使用真实铰链与转轴，向远离光学底座的方向折叠。
- 枪身、弹匣和拉机柄保留独立分件及各自局部坐标；源模型已经拆分时不得合并为一个刚性蒙皮区。弹匣最终姿态以入枪接口决定，手掌在接触段跟随弹匣；拉栓以该枪实际机械侧别和行程重新适配。

配件制作、装配、展览与有接触配件的专用动作统一执行 [改造配件标准](attachment-standard.md)。旧案例只提供源资产和测量参考，不再作为第二套流程；以下保留 ADS 与跨枪型装配合同。

- 复用一套通用配件几何，各武器负责安装骨骼、局部变换与眼距。逐件验证接口贴合、原件替换、装卸恢复、动画跟随和实例保存；不得出现悬空、重复件或非设计性穿插。
- 用户现有瞄具偏好为顶部导轨中段，先用侧视/斜视确认安装空间，再校准 ADS；不能直接沿用其他枪的前移距离。
- 枪口、抛壳口、准星、照门、光学中心分别测量。将标记从实际测量帧变回对应骨骼的 rest/local 空间；世界坐标不直接当挂点坐标。
- 验证最终渲染相机、瞄线及真实射击射线。区分整体后坐力与机械活动点；不逐帧追逐枪机/套筒驱动双手反向补偿。腰射摆位不能不加区分地叠入 ADS。
- 用真实 FOV、近平面、光照及不同宽高比检查枪托抢镜、断臂和镜片可见性；中心截图仅证明该帧。迁移 Godot 的 FOV/轴时按实际源参数换算，历史 AKM 偏移不是 M4 标准。

## 腰射默认位置与机械瞄具 ADS（2026-10-02）

- 新枪与后续批量调整统一读取 [腰射批量标定与配置复用](hip-framing-calibration.md)，使用其相机投影约束、关键区域目标与 [记录模板](../assets/hip-framing-record.json)。共用右手腕开发基准、枪轴和枪根上方向，按枪保存展示偏移；已有配方复用，只批量重算输入变化的枪。
- 展示偏移在 `Initialize()` 的共同目标上加入一次，握把／弹鼓切换从目标重新求解，整枪与双臂一起移动；ADS 独立标定，动作沿原收势窗口交回最终腰射位置。当前八枪制作参数与源码／构建状态见上述标准及工程 `Docs/Weapons/rifle-hip-presentation-20261002.md`；尚未做游戏验收。
- 腰射摆正但 ADS 侧歪时，先比较两个状态是否都约束滚转。`FindBetweenNormals` 只对齐瞄线；使用同一作者瞄准帧的枪根/瞄具上方向，按 `MakeFromXZ(Axis, SightUp).ToQuat().Inverse()` 建立完整瞄准坐标系，再用该旋转重新计算照门位置。不要只补旋转而保留旧位置，也不要把一把枪的补偿角复制给其他枪。
- QBZ191 机械瞄具源姿态在旧单轴算法下残留约 4.88° 左倾；本轮已按 `WPN_root` 上方向修正。原厂及四种前握把的作者瞄准枪体坐标系一致，保留现有源动作与配件。定位记录见工程 `Docs/Weapons/qbz191-iron-ads-level-20261002.md`；本轮未做游戏或视觉验收。

## 接入实测坑（2026-09-23，SVD 案例）

以下均为本机实测记录，未做游戏或渲染验收；结论供新枪接入时先查，不要当成通用参数。

- **Python 新建的材质必须开用途标记**：`MaterialFactoryNew()` 建出的材质默认没有 `Used with Skeletal Mesh`，骨骼网格会整件回退默认材质（棋盘格），而静态网格看起来正常。日志签名：`LogMaterial: Warning: Material ... missing usage flag SkeletalMesh! Default Material will be used in game.`。做法是从该枪已认可的运行材质抄全部用途标记（M4 侧实测只开 `used_with_skeletal_mesh` 一项）后 `recompile_material` 并保存。**资产级检查（槽位绑定、实例父级、贴图覆盖、UV 范围）在这种故障下全绿**——只有运行时日志或实机能暴露，因此导入后要专门读一次日志。
- **非机瞄枪要自带一对瞄点**：共享 `WPN_RearSight/WPN_FrontSight` 位于 M4 机瞄处，光学为主的枪（如 SVD 的 PSO-1）需要像 `AKMSoviet::Rear/Front` 那样提供武器自身空间的点对。点对必须**由后向前**（目镜→物镜，指向枪口），单位为**骨骼局部米**（FBX 根带 100 cm 缩放），给反了开镜会把枪整体转 180°。核对方式：读 `GUNPLAY_ADS_CALIBRATED` 日志——轴向长度应等于两点距离，旋转应只等于基准偏航，且 `offset.X == EyeDistance + rear.Y`；三者对不上就是空间或符号错了。
- **共享枪口挂点按 M4 长度放置**：1.225 m 的枪相对 0.69 m 的 M4，真实枪口在共享 `WPN_SOCKET_Muzzle` **前方约 70 cm、下方约 7.6 cm**（M4 只需 4.84 cm 后偏、ASH-12 是 6.79 cm）。长枪的枪口烟火与曳光不能沿用 M4 的偏移量，否则火光从枪身中段冒出且不报错。
- **滚转要交叉验证口径，别在单一被污染的度量上直接烘修正**：面积加权上表面法线会被大斜面（木护木、贴腮板）带偏——SVD 朝上面积是 M4 的 4 倍，该口径给出 3.04° 的假差；窄带最高面口径对 SVD 恰好 0.000°（顶面本来就平），对 M4 又被导轨齿与准星污染；**顶点云主轴（PCA）**才给出可信的 0.658°。按前一个口径去"修正"，等于把本来没有的倾角拧进去。建议：先跑 PCA，再用平坦顶面或动画姿势复验，差值小于 M4 自身 aim/idle 散布（−0.03/+0.37）时不要修。
- **扫描枪的分件用壳体整块分组，不要裁切**：SVD 枪体是 758 个独立壳体，机械件与主体混在一起。按测量区域把既有壳体整块归组（弹匣/扳机/拉机柄/保险杆），**不裁切任何表面**，UV、法线与闭合性不变，面数总和与源一致即可自证无丢失。实现上注意：Blender 分离一次后**面索引会被重建**，用面索引做第二次选择会错或抛 `IndexError`；改为"按材质分组 + `separate(type='MATERIAL')`"。
- **FBX 往返坐标系**：UE 相对 Blender 导出场景的映射是 `(x, −y, z)`；用默认 FBX 导入器把导出的件读回 Blender 可以复现导出场景坐标，便于在同一空间里做对齐测量。判断朝向时不要凭单一特征推断，而要把两件（新枪与宿主枪）放在**同一个导入空间**里比同一组接触点。
- **UE Python 资产操作细则**：`SkeletalMaterial` 等结构数组元素按副本处理，要 `set_editor_property` 后把整个数组写回；`USkeletalMesh` 没有 `get_material/set_material`（走 `materials` 数组）；`FbxSkeletalMeshImportData` 没有 `combine_meshes`（那是静态网格属性）；**资产路径不区分大小写**——仅大小写改名会命中旧包，必须经临时名往返，且可能断掉材质实例父级，需重设 `set_material_instance_parent`；**编辑器加载着资产时不要从磁盘删 `.uasset`**（包变脏，后续导入会被守卫拦下），退役一律走 `EditorAssetLibrary.delete_asset`；Windows 上 `Path.write_text` 会写 CRLF。
- **半自动枪要复位触发语义**：项目原本只有手枪是"一按一发"（`bPistolShotPending` 仅对手枪生效）。给步枪加半自动时，用一个默认 false 的开关替换触发路径的四个判断点，并**在每次换枪的入口统一复位**——只在武器分支里赋值会让它粘到之后装备的所有武器上。

## 数据、枪匠与存档

- 沿现有 `FPSGAMECharacter`、`FPSGunplayAnimInstance`、`UGunsmithSystem` 和项目库存子系统接入；读取当前实现，不为换枪复制整套角色逻辑。
- 核对 `Content/ColdSteelData/gunsmith.json` 里的真实武器定义与配件 ID。旧报告曾发现 `weapons: []`，这是历史故障线索，不是当前状态结论。
- 目录数值口径与说明分工见 [改造配件标准](attachment-standard.md)：`description` 只写基本描述（可推导数字禁写，静态规格数字须注明权威来源），增减百分比与时长一律由 `stats` 经 `Calculate` 推导后显示在配件详情行旁，`effects` 与 `stats` 同义同数、同 id 跨枪逐字一致；行名统一「开镜耗时」「普通换弹」；基础数值（射程、射击间隔）改动同步枪匠总览、详情行与物品提示三处显示。改完跑 `Tools/Weapons/check_attachment_consistency.py` 自检。
- 枪匠要覆盖草稿、预览、应用、实例保存、重开读回和换回原件。UI 条目、候选模型或单独弹鼓测试不能代替完整改造功能。
- 保留弹匣容量、剩余弹、备用弹、拥有权、快捷切枪和 UI 数据同步。非空仓甩掉旧弹匣是当前动作风格，不隐含要求修改剩余弹药回收规则。
- 正常换弹、空仓自动换弹、按住扳机、重复按 R、切枪、ADS、冲刺、滑铲及滑铲跳按现有输入合同检查。动作繁忙期不重复启动声音、不重复补弹、不凭空补满。
- 按实际项目的隔离 profile 参数运行审计；不要在 UE 中照搬 Godot 的 `INVENTORY_SAVE_PATH`。本 M4 验收通过 `-ColdSteelProfile=<unique>` 隔离测试。

## 输出范围

按变更选择检查：模型/许可、骨架/压缩、装配/ADS、动作/音效、输入/弹药、库存/改造/保存。动画小改不自动要求重新制作整个枪匠；涉及某分支就验证该分支。报告仍存在的可见缺陷和未覆盖范围，不把数值通过包装为完美视觉。

## 近距离枪体与机械瞄具表面修整

- 先区分轮廓分段、硬边/平滑法线、法线贴图与粗糙度问题。4K 贴图和 Raw/Source 文件名不等于存在另一份高模；依据实际源包判断，不能把低清预览造成的损失当作源模型缺陷。
- 修整蒙皮枪时保留骨架 rest、权重、活动件身份、UV 和材质槽名称。机械瞄具的孔径、准星尖端与视线中心独立于倒角；不靠整体细分缩小瞄孔或改变挂点来掩盖粗糙。
- 对真实硬边使用小半径、限制重叠的倒角，再处理加权/分裂法线；避免将整枪所有面一律平滑。FBX 明确保留平滑组和自定义法线；含多边形面时可由 UE 计算 MikkTSpace 切线，不强行导出不完整切线。
- 保留源色彩和金属遮罩，将瞄具材质与枪体分开；粗糙度与法线强度按近距离用途调整。不要用降法线强度替代几何轮廓修复。
- 本机 QBZ 案例：`SourceAssets/QBZ19120260912/SurfacePolish`，瞄具 0.15 mm、枪体 0.25 mm 四段倒角、38 度硬边。仅作为可编辑起点；已导入，未做实机或渲染验收，不作为通用参数或视觉通过证据。


## 新枪接入的四项可量化检查（2026-09-17，ASH-12 案例）

新枪绑到共享 Manny 手臂后，除握持与接触外还要量这四项；前三项都有 M4 基准值可对照，第四项是从零建网格必验：

- **枪身滚转**：取枪身上表面的**面积加权法线**，与照门标记骨骼的"上"方向比较。M4 基准 aim −0.03° / idle +0.37°；ASH-12 首次接入为 +3.92°（源模型枪身相对自己的瞄准线就带 4.7° 右倾）。ADS 标定只把视线轴对齐、不约束滚转（`FindBetweenNormals` 只映射一个轴），因此这个倾角在开镜时就是玩家看到的"枪是歪的"。修法：装配矩阵绕握把接触点反向旋该角度。
- **开镜眼距**：`ADSRearEyeDistance` 不能照抄 M4 的 12 cm。照门在提把中段（而非机匣尾）时相机贴住枪尾、画面被枪体占满，实测 18 cm 才与 QBZ 同夹具的参考画面一致。
- **共享瞄具鞍座落差**：共享挂点把瞄具鞍座放在"照门标记线下方 3.2 cm"（M4/QBZ 的标记高于导轨）。若新枪的标记量在导轨面上，需按枪取 0，否则瞄具被压进枪体。
- **硬边完好**：从零 `from_pydata` 重建网格再导出后，用"同一顶点不同 loop 法线夹角"验证：源 ASH-12 有 113,832 对硬边、首次导出为 **0 对（最大夹角 0.0°）**，即整枪变成全平滑。原因是先 `normals_split_custom_set()` 后设 `use_smooth`，Blender 会丢弃自定义法线；先平滑再设法线可恢复。
