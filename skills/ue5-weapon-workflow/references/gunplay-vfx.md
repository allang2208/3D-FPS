# Gunplay 弹道、反馈与 Niagara 验收

## 发射与准心

- 分别记录物理枪口出口、实际发射点、瞄具中心。先取同一可见姿态的瞄具射线及附件出口，再播放开火动画与施加后坐力；不要从动画更新前后混取位置。
- 先由瞄具求目标，再由枪口指向目标。附件出口偏移仍须包含在遮挡检测内，避免枪口穿墙。不要为修正视觉把已发射的子弹绑定到移动摄像机。
- 腰射准心范围用实际散布模型投影到屏幕，考虑 FOV、窗口比例和 UI DPI。ADS 的水平后坐力是瞄准方向的变化，不是额外随机散布。
- 改造栏与装备浮窗使用同一后坐力公式，标注单位、单发/累计及适用模式。数值增减与收益分开判断：后坐力降低为绿色，稳定性提高为绿色。

## 烟、火光与曳光

- 不只检查 C++ SetVariable：读回发射器实际绑定。固定 InitializeParticle.Color 会使 User.Smoke Color 的透明度设置完全无效。
- 复制官方示例为项目资产，检查 emitter life cycle、loop、position offset、local/world space 和 user 参数。移除示例弹壳等已由游戏实现的重复发射器。
- 火光仅降低 RGB 可能在末帧留下暗斑；同时检查 Alpha 淡出。不要丢失原材质依赖的 HDR 色值。
- 烟量取决于 alpha、大小、寿命、生成频率、近距淡出和灯光。避免同时大幅降低所有项；在明暗背景、腰射和 ADS 逐帧查看。每发烟与停火热烟应有清晰的触发关系。
- 静止曳光段跨帧累积会在横移时形成历史残影。显示当前飞行段并及时清理；命中及射程结束后验证无残留。烟在世界空间自然留下并不等于弹道错误。

- 连射烟使用持续发射的世界空间烟流，以枪管热量衔接停火尾烟。新生密度、旧烟寿命及瞄准视线淡化分别调，避免为清空视线而把全部烟降到不可见。图集的行列数、有效通道、相邻帧混合和格内留边必须来自源资产；灰白 RGB 不等于烟的 Alpha。
- 贴图显示成马赛克时，先区分整张图集被直接采样、错误透明通道和缺失的 Niagara/ISM 材质 usage 排列；不能只改实例透明度。`PerInstanceCustomData` 用于像素着色时显式经 VertexInterpolator。
- 手枪火光按枪类缩放，避免共用系数连带缩小步枪。火光柔边要与 Alpha 一起淡出，并轻微变化侧瓣长宽、旋转和寿命，减少固定剪影。
- 曳光的物理轨迹与视觉宽度分开：可用 FOV、视深和视口宽度估计最低像素宽度并设上限；只显示当前飞行段，不让跨帧历史段变成拖尾墙。

## 抛壳与枪型反馈

- 弹壳从枪身实际抛壳 socket 采样一次，速度使用枪身参考坐标系；不要拿相机右/上方向代替侧抛方向。折叠瞄具不能作为随动作改变的抛壳基准，先从参考骨骼构造相对枪根的固定坐标系。
- LPVO 的 1x 仍属于镜内模式；按光学类型、瞄准状态和剩余过渡权重隐藏新壳，并回收已存在的壳。普通红点/机瞄不受此规则影响。
- 第一发、连射稳定段和松扳机回稳分别定义视觉脉冲；按事件时间积分，跨初段/回稳边界分段推进。换枪清空旧弹簧与连射计数。视觉调节不乘到伤害、弹道后坐力或射速。

- 按枪型对齐后坐力表现（2026-09-17）：程序弹簧（`GunKick*`／`GunFlip` → `UpdateViewmodel` 的姿势映射）通常是三把枪共用的，**枪与枪的观感差异往往在各自的开火动画资产里**——先量动画，再判断要不要动弹簧。本项目实测：M4 的开火动画（原包 `Fire`，24 帧 / 0.767 s）枪根在 33 ms 内走 1.93 cm、转 3.04°；QBZ-191 自烤的只有 0.49 cm / 0.73° 的软脉冲；AKM 的 6 帧残桩枪根三轴全零。量法用 `Tools/AssetPipeline/read_animation_curves_fbx.py`（读 FBX 源的 `WPN_root`，输出逐轴峰值与峰值时刻），不要靠帧数或文件大小推断。补差额的稳妥做法是在 `FPSVisualRecoil::FProfile` 里给缺动画的枪加一条 **clip 补偿层**（位移＋转角＋与参考同形的时间包络），并加在弹簧限幅**之后**——姿势层的俯仰 tanh 上限（约 2.58°）低于参考幅度（3.04°），加在夹之前会被削平。补齐层只随枪运动（整组手臂刚体位移），若要求手腕/肩部也参与吸收，必须重烤开火动画，属独立一轮。注意各枪骨骼主轴不统一（同一根枪骨，M4 主位移在 Z、QBZ 在 Y），按量值对齐后要用 CVar 让用户复核方向与配比。该层用实时 CVar 暴露（本项目 `fps.Weapon.ClipRecoil`，0 即关闭）。

- **腰射与开镜是两支动画，必须分开取值**（2026-09-17 当日复查）：本项目 M4 的 `A_AKM_aim_fire` 与 `A_AKM_fire` 性格完全不同——腰射 1.93 cm / 3.04°，开镜 2.32 cm / **0.48°**，即"整枪直退、几乎不转头"。开镜后枪的转角直接决定机械瞄具是否还留在视线上：把腰射幅度（尤其转角）套进 ADS 会把枪转头约 2° 并顶满轴向夹值，实机表现就是"开镜后看不到瞄具"。补差额要按 ADS 实测值单独给一组，且**按 1:1 叠加**——不要经过给弹簧设计的手感倍率（本项目 `ADSAxialScale 3.2`、`VisualRecoilScale 0.65`），套进去会把 2.32 cm 放大成 7.4 cm、把 0.48° 缩成 0.31°。高倍镜仍走既有的镜内收敛系数（`ScopeConvergence`）。

- **机械瞄具的 ADS 转角要按"照门—准星基线"约束**（2026-09-17 第三轮）：准星在缺口里的横向错位 = 枪身转角 × 瞄具基线。本项目 AKM 的 `AKMSoviet::Front - Rear` 是 **38.7 cm**，1° 就是 0.68 cm，而缺口只有几毫米——用户看到的现象是"开火后准星竖线直接消失、无法瞄准"，其实是准星被缺口壁挡掉。所以长基线铁瞄要**把 ADS 转角压到 0.4 倍以下**（本项目新增 `FProfile::ADSRotationScale`，AKM 0.4、短基线枪型保持 1），并让补偿层**在 ADS 只做纯轴向平移**：沿视线轴的平移既保持照门/准星对齐，也不改变"眼睛→准星"的射线方向，弹道方向天然不变；任何转角都会同时破坏这两件事。**弹道一致性由结构保证，不要再自行加修正**：本项目 `ComputeShotDirection()` 读的是**当前**视模变换（AKM 走 `WPN_root` + `AKMSoviet::Front`，其它枪型走 `WPN_FrontSight` 骨骼或相机前向），所以表现层怎么动、射线就跟着动，落点始终等于屏幕上准星的投影；改完跑 `AKMSightAudit` 复核（准星投影居中 <2 px、与照门对齐 <2 px、实弹落点与可见射线 <2 mm）。方向存疑时把补偿的倍率 CVar 设成**负值**当场翻转，比重新编译快（本项目 `fps.Weapon.ClipRecoil`）。

- 镜头抖动与"力量感"（2026-09-17）：开火镜头层（kick／jitter／trauma／FOV punch）和视模（枪口／枪身）弹簧是两套独立基数，用户说"抖动太小"时先问清是枪口还是镜头，不要一起放大。本项目镜头层由单一基数 `AKMSource::FeedbackScale` 压幅（旧值 0.5，使首发俯仰峰值仅约 0.06°、连射末发约 0.18°，看着"没打枪"）；提高基数后各层还需单独配比：kick 给方向感、jitter 给短促随机脉冲、FOV punch 给开火推力。`FireTrauma` 在渲染时取平方，改**每发增益**比改渲染幅度更能做出"越打越晃"的连射曲线，`ShakeDecay` 决定它能跨多发停留多久。换弹／装备的镜头脉冲在 `UWeaponActionCameraComponent`，`Strength / FollowStrength / ImpactStrength` 是 `Config` 属性——`Config/DefaultGame.ini` 的同名段会覆盖 CDO，改一处等于没改。整套强度用实时 CVar 暴露（本项目 `fps.Camera.Shake`、`fps.Camera.ActionShake`），交付时说明默认值即当前手感、设 0 可关。相机弹簧刚度／阻尼、`ADSJitterMultiplier`、`CameraMotionScale` 与 `WeaponHandling` 的回稳公式不要顺手改，否则 30/60/144 Hz 分区、ADS 回稳毫秒数与既有验收关系会失效。该层当前只覆盖 M4 的换弹／装备（`bM4Camera`），其它枪型要按各自源时钟单独接。

## 高倍镜内开火表现

- 高倍 ADS 会把整个第一人称枪模对持枪者隐藏（本项目 LPVO 1–6× 由 `GetScopePresentationAlpha()` 判定），世界空间的枪口 Niagara 只有极小一片落进窄视锥，玩家看到的就是“镜内一个小火光”。这类需求不要靠调亮世界火光解决，而是补**镜内表现层**：在镜口遮罩之上、分划之下绘制屏幕空间光斑。
- 镜内火光由开火时间戳驱动（只读事实：最近开火年龄与每发随机种子），时序分三段：近白尖峰（≈20 ms）→ 主衰减 `(1-t)²`（60–90 ms）→ 低橙余烬（≈180 ms）；冲击感靠分段而不是拉长单段，分划遮挡时间不增。镜内层通常还要配三件：镜口内缘泛光（同火光窗口）、常驻极淡镜片污渍（被火光短暂点亮）、射击后 150–250 ms 热浪烟丝（位置是开火时间的纯函数，包络偏斜让峰值后移，控件保持无状态）。
- **整镜口环境闪亮**是高倍下最强的“开火了”读感（2026-09-17 第二轮）：几十毫秒暖色冲刷盖住整个镜口、下缘更亮（光从镜口下方涌入）、每发亮度随机 ±20%。单靠一枚孤立光斑只会读成“玻璃上贴光晕”。
- 光斑要**贴镜口下缘并被镜框剪裁**才像“下方在爆”：默认偏移 0.75–0.95 镜口半径、半径约 0.4；Slate 自定义顶点不会被先画的黑色遮罩裁剪，出画顶点必须手动钳回镜口圆。只保留“内缘不过十字”的守卫，不要把光斑整体夹在镜内；少数（10–20%）光斑落在左右镜缘，对应世界层 side flash 随机。
- 每发形态随机（位置抖动 ±0.1 镜口半径、半径／亮度 ±15%、侧面概率）全部由每发种子经 `Frac` 乘数派生，控件保持无状态。
- 红线：特效层不写 `ControlRotation`、不改射击方向与射线；光斑必须避开分划中心并有硬性生命上限；不新增 `SceneCapture`、灯光或阴影；空闲时零绘制。参数走控制台变量（本项目 `fps.Scope.Flash*`），便于调手感而不改代码。
- 世界层做倍率补偿：按倍率（或 FOV 正切比）取 `pow(x,0.5)` 这类受控指数并设硬上限，同时把生成点沿枪口轴前移少量，让火光重新落进窄视锥；只改 Niagara 组件的位置与 `User.Global Scale`，不碰枪口 socket 与射线。2× 棱镜等不隐藏枪模的分支不适用镜内层方案，需单独判断。
- 只改呈现的验收点：分划与命中点不动、火光不覆盖瞄点、无新增渲染目标；实际画面仍需用户确认。

## 表面命中与落血

- 肉体、盔甲和环境表面用明确标签/物理材质/实际命中面分类；不要把合并多材质网格的第 0 槽当作全部表面。复用现有命中 FaceIndex，避免为分类再发射射线。任何特效限额只丢弃表现，不影响伤害与命中确认。
- 细粒子使用世界共享固定池、共享材质和批量实例数据；独立列出预留槽位、同时活动上限及触发速率。池满不临时创建组件、MID、灯光或刚体，空闲时停止 Tick。粒子数上限是实现预算，不是实测性能结论。
- 血雾、重血滴和地面血迹是三个环节。空中能看到血不代表已经落地：胸/头高度需要足够下落寿命；每个受限命中批次查询落点，斜向查询失败时补向下查询，再按落差计算重血滴轨迹和贴花延迟。可短时复用同一目标附近的落点，避免逐血滴碰撞/射线。
- 地面血迹不可只靠放大透明度修复：同时查看落点查询距离、坡面法线、接收贴花设置、投影深度及屏幕尺寸裁剪。程序化地面可能是 Movable，不能仅凭 Mobility 或某个 Actor 类名排除稳定地面。
- 血迹采用独立有限池，避免被普通弹痕立即替换；连续命中同一区域扩大/刷新现有斑迹，减少重复半透明叠层。初始落地尚未发生时，刷新不能提前取消落地延迟。
- 地面血迹用不规则轮廓、大小散点、随机形状和适度边缘扰动；湿血较低粗糙度，随后变暗、变粗糙再淡出。避免高亮自发光、统一圆形贴片和瞬间铺满大平面。
- UE `UDecalComponent::SetFadeOut` 即使 `DestroyOwnerAfterFade=false` 也安排组件寿命；池化组件需用 `SetLifeSpan(0)` 取消销毁，保留着色器淡出。可用 DecalColor 通道传随机值和出生时间，让共享材质完成湿/干变化，避免每迹一个 MID。
- FPSGAME 2026-09-14：用户确认血液落地可见性调整成功。当前案例为 192 个活动命中粒子、24 雾/96 滴预留槽、48 独立血迹及 24 普通弹痕；血迹约 22 s 停留+6 s 淡出。详细参数见宿主 `Docs/Weapons/flesh-impact-ground-v2-20260914.md`，这些是项目调校值，不是通用性能或写实标准。
- 命中目标音与武器种类分层（2026-09-16）：子弹落在怪物（Flesh 表面）时把该次撞击音换成枪械专属 cue
  （本例 `/Game/Audio/WeaponHit20260916/S_GunHit` 取代 Flesh 表面 bank），枪械同时不再叠加共用的 2D 怪物命中确认音，
  近战与冷钢技能保留该确认音；表面 bank 仍按 Metal/Wood/Stone/Dirt/Glass 区分，不要用一个音盖掉材质差异。
  换音前后都要确认「玩家听到的是撞击、挥动还是确认音」，只改其中一条时另一条会继续掩盖变化。

## 证据与整理

- 最少包含单发、连射、停火、左右横移、ADS，以及原装/改装枪口。数值通过不能代替实际画面；新原生模块需要新进程加载。
- 把最终生成器对旧候选的依赖解除，确认从合法原始资产可重建后，再归档旧候选。保留有用的前后对照、许可证、最终参数和本机恢复说明；不要公开上传第三方原始 uasset。
- FPSGAME 2026-09-11 案例以 build_muzzle_presentation_v5.py 和对应日期 Docs 为记录；烟量参数属于项目调校，不是所有枪械的统一标准。
