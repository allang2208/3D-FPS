# 长杖模块化制作与接入

长杖系列使用独立 `staffs.json`、`staff-gunsmith.json` 与 `Weapons/Staff`，不借用剑的连击／格挡或枪械弹药状态。第一人称、改造台、背包动态图、掉落物及角色持械应读取同一六槽装配配方；清理旧子组件后再切换武器族，不能只替换根网格。

- “Meshy 生成”与“Blender 重建”要分开说明来源。学徒长杖当前保留 Meshy 设计／源模型，木杆在 Blender 按三视图重建自然凹凸，顶部绳结和水晶分别制作修整；不能把最终重建网格全部称作未经加工的 Meshy 输出。
- 替换模型前保留握持区、六槽接口和施法尖端合同。学徒长杖案例的总长 160 cm、握点 `(0,0,32)`、握持区 `z=22..42`、晶头接口 `z=62` 与默认尖端 `z=80` 是该武器的参数，不是所有长杖的统一尺寸。
- 漏空分开排查生成体开放边、切割端盖、退化三角形、UV 通道和法线。UV 岛缝上直接切片再传最近三角面 UV，会同时留下开口和拉伸木纹；需要连续闭合表面和对应的轴向 UV。不同可替换部件保持独立封闭实体，不跨装配接触面焊死。
- 世界水晶“有厚度”与 UI “写入覆盖率”是两个问题。Thin Translucent 双源混合可能不改反向覆盖率 alpha，造成世界可见而预览完全消失；在预览副本使用写入覆盖率的专用材质，保留世界材质。实时与目录图共用材质替换入口、异步资源清单和装配逻辑。
- 武器回退图按 `Icons/<definition>.png` 查找，不能只修改 JSON 的另一张 `ue_icon`。导出器须读取长杖独立目录，并保持旧存档文件名别名；横竖缩放见 [运行时图标](../../ue5-ui-umg-slate/references/runtime-icon-pipeline.md)。

当前作者链：`BranchCrystalV18` Meshy 输入、`SolidRepairV19` 表面／PBR 输入、`BarkRebuildV21` 几何、`QuartzAimV22` 世界水晶、`WorkbenchPreviewV23` UI 水晶、`EquipmentIntegrationV24` 手部装备／图标接入、`IconOrientationV26` 横竖布局。旧版本目录可能仍提供当前输入，只归档确认已退役的备份及无运行引用的输出。

资产来源、当前本机恢复边界和发布清单见 `Docs/Weapons/staff-publication-20260928.md`；资产落盘、构建成功、用户视觉认可分别记录。

2026-09-28 用户反馈 V22 杖头过白，已恢复 V20 的透明相关参数：Opacity `0.24–0.42`、透光色 `(0.78,0.84,0.82)`，保留现用 V22 路径、粗糙度及 V23 预览覆盖率修复。后续重建读取更新后的 `QuartzAimV22/quartz_parameters.json`，不要按 V22 历史交付文本恢复高不透明度。实际材质保存和作者源记录见 `SourceAssets/ApprenticeStaff20260927/QuartzTransparencyRestoreV29/DELIVERY.md`；未进行本轮视觉测试。


## 晶辉照明（2026-09-28）

学徒长杖按 G 切换持续照明（初版为右键，现已迁移到武器特殊功能），不走技能扣费、冷却或修炼，无持续时间限制。用户纠正 V31 的持续举杖：V32 仅播放一次 `Raise` → 短暂停留 → `Recover`，随后恢复普通待机，灯继续开启；动作计时和照明开关分离。普攻与法术从实际手姿接管，恢复普通待机。`StaffIllumination.cpp` 在真实装配的杖头上缓存 MID 和单个可移动点光源；灯光与 MID 在武器姿态更新后统一提交，并对新增照明分支适配场景曝光。收起、更换及死亡熄灭，临时开关不写物品存档。五种水晶均只在实际持械 MID 中设置 `StaffLightAmount`，母材质默认值为零，保持 V20 透明度与 V23 预览覆盖率。实现、构建和落盘状态见 `Docs/Weapons/staff-crystal-light-20260928.md`；未做本轮效果测试。

水晶图重建保留 V30 修复：对 `get_material_expressions` 返回的快照逐个删除节点，不用当前 UE 的 `delete_all_material_expressions` 遍历删除，以免残留多个薄透明输出而显示默认棋盘格。`QuartzAimV22` 配方同时复用 `CrystalLightV31/material_emission.py`，避免重建丢失照明入口；NullRHI 保存成功不能代表实际渲染平台的材质编译成功。

## 免费改造、混合副手与资源刷新（2026-09-29）

- 改造预览成功不等于装备已改造。提交必须将六槽配方写回被选中的物品实例，经原有档案事务更新角色、背包、掉落和预览；重新打开改造台读取已安装值。当前法杖免费改造，不再读取或扣除不存在的 `reforge_ticket`，目录、按钮状态、提示和实际 Apply 路径一起改。
- 法杖是主手限定的单手武器。`IsDualWieldingPistols` 只代表双手均为手枪，`HasOffhandPistol` 覆盖法杖配手枪。左键留给法杖，右键交给副手手枪；空副手无右键交互。副手枪沿用独立实例、弹量、换弹、准星和扳机边沿，魔法书仅保留后续装备类别。
- G 键是当前武器特殊功能入口。照明以固定特殊快捷栏项展示，复用一次抬杖／收势循环；持久开灯状态与动作计时分离，收起或死亡时熄灭，不写物品存档。旧文档里的右键是历史绑定。
- 可视资源缓存键只包含实例、定义和实际网格配方，不用整份 `Item.Data`；属性或弹药刷新不能把相同视模重新隐藏。驻留资源直接应用，同实例换部件时保留已显示装配直到新部件就绪，真正换实例才隐藏旧装配。骨架没变就不重复 `SetSkeletalMesh`，完成装配后再开始装备动作。
- 角色还原档案后不能无条件进入单枪装备状态。若副手控制器接管更新却不推进单枪时钟，残留 `Equipping` 会让左右键一直被 `IsSwitchingWeapon` 拒绝。入口限定主手枪，副手分支清理历史残留装备／检视状态。
- 默认白水晶 V34 已被用户否决并回退。当前恢复链为 V22 路径、V29 透明参数、V30 图清理、V32 曝光适配；四个元素水晶继续使用 V33。不要重导废案或靠提高不透明度再次覆盖用户要求保留的外观。

完整接入与发布边界见 `Docs/Weapons/staff-offhand-special-20260928.md`、`Docs/Weapons/staff-publication-20260929.md`。这些是实现经验，未据此宣称本轮已完成游戏测试。
