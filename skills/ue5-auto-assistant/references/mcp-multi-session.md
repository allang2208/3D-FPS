**用户规则（2026-09-20）：禁止主动向其他对话/任务发送协调消息。** 不调用 send_message_to_thread 或跨任务消息工具询问占用、请求让位、通知释放、协商编译/重启；不通过轮询其他对话或共享留言板变相协调。接入等待交由桥的批次互斥处理，期间继续独立制作。真实文件/资产归属冲突或无法安全执行的编译/重启，保留现场，仅在当前对话向用户简要说明阻塞；不联系其他对话。此规则覆盖旧文中的“定向协调/集中协调”等要求；只有用户明确另行要求发送指定消息时才执行。

# UE MCP 多会话工作规则（2026-09-20）

默认后台制作、编译与落盘，不主动打开 UE（用户确定，2026-09-23）；具体打开条件见 [后台开发与编辑器使用条件](editor-open-development.md)。确需编辑器操作时使用短批次互斥。本版替代 2026-09-18 的“只读随意并发”“变更前逐条确认”等要求；多会话可以开发，但共享编辑器工具执行仍串行。

- 源码、源模型、贴图、动画及生成/导入脚本按文件与目标资产分工独立制作。既定分工内不询问其他会话；真实归属冲突保留现场并向当前用户报告。
- 仅剩必要编辑器操作且已有可用会话或符合打开条件时，通过 `D:/FPS3D/FPSGAME/Tools/AssetPipeline/mcp_call_codex.ps1` 提交短批次或编辑器内编排脚本。参数已知用 BatchFile；动态 handle 在编辑器内脚本中传递，不猜值。
- 桥使用同一 Windows 登录会话内、按端口区分的命名互斥锁，从握手前覆盖完整调用或批次，最后释放。只读请求也走桥，不能插入其他任务的批次。并行文件读取不受影响。
- 默认静默等待最长 60 秒；QueueWaitSeconds 可调整。竞争只输出一次 stderr 提示；等待超时返回 75，未发请求。保留批次、继续独立制作，不高频轮询或反复向其他任务询问。互斥不保证 FIFO，不是事务或自动合并。
- 同机桥会话缓存仍为 `%TEMP%\codex-ue-mcp-session.json`。NewSession 仅强制新握手，仍写入共享缓存；不提供资产隔离，也不能绕过批次锁。不同端点使用 Endpoint 指定。
- 锁只覆盖遵守本桥的调用；用户手动操作、旧桥、其他 MCP 客户端、外部编译与异步引擎任务不受锁保护。异步任务必须在批次内通过工具完成接口等待，或单独协调其整个接入窗口。客户端异常退出不等于服务端操作已结束。
- 同一资产、共享编译与必要重启出现真实冲突时保留现场并仅向当前用户报告。保持编辑器打开不意味着全程占用编辑器；不要杀进程或抢端口，不另起编辑器/commandlet 覆盖已加载的相同包。
- 不自动创建多代理，不自动测试、截图或启动 PIE。实际接入完成与待接入分别交付。

完整阶段、锁边界和失败处理见 [并行制作与接入](editor-open-development.md)。本文件说明实现约定，不表示已进行并发实测。
