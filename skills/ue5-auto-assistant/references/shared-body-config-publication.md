# FPSGAME 共享玩家配置与发布

触及 `D:/FPS3D/FPSGAME/Content/ColdSteelData/player_body.json` 的动画、身体、头部装备或衣物任务，以及旧动作恢复、发布遗漏排查时使用。

2026-10-20 战锤案例：39 个动作入口丢失，21 个本地动画包仍在；多个完整备份与制作回执可恢复入口，但找不到包含完整入口的已推送提交，不能归责某个会话。旧角色初始化器整份覆盖 `clips`、旧内存配置写回、混淆本地接入与 Git 发布都是具体风险。

- 当前工作文件是局部修改的底稿。只从历史配置提取明确恢复的键，不用 HEAD、索引裁剪副本或整份旧备份覆盖工作文件。
- 使用 `Tools/PlayerBody/config_transaction.py` 的 `commit(path, before_bytes, candidate, owned_paths=..., producer=...)`。动作逐个列角色键，头部装备列本物品字段；旧脚本重用前迁移到此入口。它拒绝删键、越界修改、陈旧读入和重叠写入，保留非目标文本、生成独立前后快照。冲突后从新内容重新合并，不跨会话要求让位。
- 旧 `Tools/PlayerBody/publish_jason.py` 初始化器已停用。战锤保留不同制作版本各自拥有的角色，不能将“最新编号”整批覆盖，也不重跑 V7/V8 覆盖后来的普攻。
- Git 发布采用当前索引为暂存基底，保留已有暂存工作；暂存候选绝不落回工作文件。功能清单包含动作配置及消费者源码，不能把“只暂存本会话内容”做成缺少依赖的部分功能。
- 远端祖先关系不够：后续提交可能再次删除入口，须核对远端当前分支尖端的具体值；JSON 动态动画的必要 Cook 目录也列入清单。文件/配置检查不证明 C++ 接入补丁已经应用，公开部分源码与完整本地集成必须分别报告。
- `published.json` / `assets-published.json` 只证明其实际记录的本地接入范围。分别记录资产保存、本地配置、提交 SHA、远端包含关系、用户认可；没有证据的项保持未完成。
- `Content/ColdSteelData` 不能一概作为不发布目录；按具体路径的跟踪、忽略及许可规则处理文本配置和资产二进制。

执行示例、已接入的 14 个发布入口、工具边界和战锤恢复清单见 [工程流程](D:/FPS3D/FPSGAME/Docs/Workflow/player-body-config-publication.md)。其他历史脚本尚未全部迁移，共用写入锁也不能拦截手工覆盖。

保护机制属于必要配置写入；独立排查、Git 发布及游戏测试仍按用户当次授权执行，不因此自动运行检查、启动 UE 或推送。
