# 枪械标准开发工作流

适用于新枪获取/制作、统一手模、动画迁移、ADS、音效特效、武器数据和背包接入。由 HK416 A7 接入及 AKM/P9 调整过程沉淀，2026-09-06 建立。下列流程是开发约束；HK416 数值是已完成案例，不是每把枪必须复制的常量。

## 目录

- 1. 范围与工作区
- 2. 素材获取与证据
- 3. 先看动作，再做迁移
- 4. 模型、统一手模与材质
- 5. 动画与状态合同
- 6. ADS 与射击反馈

- 10. HK416 可复用入口与记录模板

## 1. 范围与工作区

1. 先确认实际 `project.godot`、当前代码、AGENTS 和用户已授权阶段；不要把终端所在目录当成项目目录。此次实际项目是 `E:/3d/3-dfps`，而会话工作目录可能是 `E:/无尽轮回/3d`。
2. 用户已授权接入与测试时，连续完成到验收，不重复索要批准。仅选型/预览请求不自动扩展到替换正式资产、购买或重置存档。
3. 读取相关文件的现状和差异；保留并行开发改动，不批量回滚、清理、暂存或提交。不因历史“立即提交”惯例把归属不明改动提交进去。
4. 候选在独立 staging 目录生成；保留原始下载包、源工程、转换脚本和来源记录。先验证候选再更新正式引用，过程不能让正式场景引用断裂。
5. 风格统一优先改网格细节、材质与手模；若现成资产能满足目标，先评估其骨架和动画成本。原创建模也必须交付可编辑源、UV、材质、活动部件和动画，单张生成图片不能替代可用枪械模型。

## 2. 素材获取与证据

1. 核对具体型号/变体、作者、原模型与动画的不同作者、下载格式、动画清单、许可、署名与修改/发布条件；“免费”不等于 CC0。下载网站、模型、手模、贴图、音频分别记录来源，不混用许可。
2. 优先评估可合法直接获取的 FBX/GLB/Blend 源；Unity 样包可作为资产来源，但 Unity 脚本/材质/控制器不能直接视为 Godot 实现。不要为提取小模型默认启动大型编辑器下载；用户暂停的下载不得自行恢复。
3. 已领取、已点击下载、浏览器显示完成和本地可用是不同状态。报告下载完成前确认文件存在、大小合理、归档可读及核心模型/贴图完整。不要绕过账号验证或以不明转载代替已选资产。
4. 网站转换 GLB 出现蒙皮拉伸时，比较原始 FBX/Blend 的同一姿态、单位、rest/bind 和导入参数。此次原 FBX 正常、网站 GLB 异常，不代表所有 GLB 不可用。
5. 将作者链接、许可记录、文件名、改动说明写入资产 `CREDITS.md`，音效写 `SOURCE.md`；引用已有记录时标注其来源，许可不明不得宣称可发布。

## 3. 先看动作，再做迁移

1. **每个动作开始前**定位并实际查看已有 2D 动作表或源视频，读取帧数、播放时长、循环方式、接触帧和状态机配置。有 FBX/GLB 动画时再渲染源模型时间轴进行对照；不能只读动画名称就宣称看过动作。缺失参考时明确记录可用依据。
2. 建立动作表：动作名、源帧范围、源 FPS、时长、是否循环、起势/接触/收势帧、关键部件、左右手职责、重心变化、目标业务时间及转换方式。
3. 特别记录握把与护木接触、取出/插入弹匣、拉栓/释放枪机、食指位置和左右手差异。禁止先用通用对称动作替代。缺少背面或深度信息时标为三维重建，不宣称 100% 自动还原。
4. 先辨别动作是独立 clips 还是连续时间轴。HK416 源是连续动画，必须按实际姿态切片，而非把“7 个动作”理解为 7 条可直接播放的动画。
5. 导入前确定 FPS，验证首末关键帧与秒数。不要在导入后只改场景 FPS 而不重定时关键帧；这会改变动作速度。
6. 先交叉查看源动作与候选模型的关键帧，再进入动作精修；预览必须是实际蒙皮模型渲染，不能用示意图代替。

## 4. 模型、统一手模与材质

新枪与新改造件使用现行[分区聚合物标准](polymer-style.md)：连续轮廓、少量精细小砖、逐件装配与实际渲染验收。

### 4.1 区分静态枪体与骨骼视模

- 静态枪体可走 AABB/主轴校准、独立弹匣和程序动画。
- 带手臂动画的视模保留 rig、rest、Skin、轨道和活动部件关系。不得照搬静态管线的整体居中、逐件缩放或去骨架操作。
- 单位与轴转换应明确发生在何处；父节点、网格、骨骼和校准器不要重复变换。多个 Skeleton 时按所需骨骼识别枪体/手臂骨架，不能取第一个就用。
- 保留枪机、弹匣等机械部件身份；导入后检查 UV、法线、透明通道、材质槽、权重、绑定及全部动作的有限数值。

### 4.2 统一手模标准

1. 当前标准为 Infima `SK_FP_CH_Default_Cubic`：低多边形手型、露指手套、迷彩袖口，保持 AKM/P9/HK416 身份一致。新下载模型自带的手臂不自动成为新标准。
2. 保留标准手模的 UV、轮廓、左右差异和前臂材质。变更整个手模标准需要对应用户范围，不能因适配一把枪顺手改旧枪。
3. 不同 rig 的骨名、单位、局部轴、rest 姿态不相同；不能只重命名骨骼或直接复制旋转四元数。按肩—肘—腕、掌面、食指—小指方向建立解剖坐标映射，适配 rest 后转移权重。
4. 记录 twist 骨权重合并/映射，检查未映射权重、权重归一与逆绑定矩阵。不能把休息矩阵当逆绑定矩阵，造成顶点重复变换。
5. 检查左右腕和手指在持枪、ADS、射击、换弹及装备全过程的接触。只看静止握枪不足以证明迁移成功。
6. 使用实际游戏 FOV/近平面检查肩部断口和枪托裁切。确需裁去镜头外上臂时只修改视模导出版本并记录范围，保留完整可编辑源；不能默认删除每个模型的上臂。

### 4.3 风格与偏白排查

1. 在与旧枪相同的游戏相机、环境、光照下比较；先区分 albedo 过亮、金属度/高光错误、粗糙度不合适、曝光、色彩空间或重复着色，再调整。
2. 手/布料、聚合物、金属、弹药分别设置材质；避免整枪统一高金属度、低粗糙度或强白色高光。
3. 染色只应用一次，记录烘焙与运行时材质处理的边界，避免重复乘色。保留可辨识的结构与层次，不靠全场景压暗掩盖单个模型问题。
4. Blender 脚本按节点类型寻找 Principled 节点，不依赖本地化名称；转换后检查材质确实被修改。

## 5. 动画与状态合同

1. 优先复用 `infima_viewmodel.gd` 的动作接口，新武器适配器负责源轨道/部件差异；不为每把枪复制整套 Gun 逻辑。AnimationLibrary 修改须实例隔离，避免污染共用资源。
2. 覆盖持枪、ADS、装备、腰射/ADS 开火、普通换弹、空仓换弹；有收枪/检查则保留其明确入口。动作名、长度、循环和机械轨道均需验证。
3. 缩短换弹必须同时明确**源 clip 时长、运行时播放时长、补弹业务时刻、音效时刻**。不能只改计时器导致手还在换弹就能开枪，或视觉结束却长时间锁枪。
4. 按接触姿态重定时，开头从稳定持枪接入，结尾回到持枪；四元数用球面插值。不能用长淡入淡出掩盖弹匣/拉栓接触错误。
5. 导出原长 clip、运行时再压缩是允许的，但必须交付适配脚本并明确两套时长；不能宣称 GLB 已烘焙为最终时长。
6. 普通与空仓换弹分别验证：重复按 R 不重启动画/音频；换弹期间禁止发射；弹药只结算一次，备用弹不足时不凭空补满。
7. **换弹不会打断冲刺，冲刺不会打断换弹；换弹期间仍可滑铲与滑铲跳。** 移动状态与换弹计时独立；动作层不能借由冲刺姿态把换弹覆盖掉。
8. 保留 C 滑铲及 Shift 从下蹲恢复站起继续冲刺的已有合同；站起仍服从碰撞空间。验证滑铲跳的速度继承，不把参考游戏名称当成已精确复制其物理参数的证据。
9. 装备/换弹繁忙期的切枪策略明确执行，不能半切换模型、半保留旧动作。检查装备→ADS、ADS→换弹、冲刺→换弹、换弹→开火及快速切枪。

## 6. ADS 与射击反馈

### 6.1 对轴

1. 实际辨识照门孔中心与前准星尖端；机匣导轨、护圈顶端、装饰点都不能当作瞄准点。保存选点预览与原坐标证据。
2. 动画视模将标记转换到正确骨骼的 rest/local 坐标并随枪体运动；在某动画帧测量的世界坐标不得直接当作 rest 坐标。
3. 以照门→准星方向求解相机光轴，将照门置于合理眼距；Godot 相机前方为 -Z。验收使用投影/方向与实际画面，不要求所有枪具有相同 Euler 角。
4. 明确子弹实际求解方向、枪口特效位置和瞄具轴的关系；复用已有弹道/近墙处理，并检查短距离遮挡，不能为了视觉对轴另造一套伤害射线。
5. 稳定 ADS 时照门/准星居中；开火瞬间允许受控偏移，停火后回归。不能每帧反向追踪活动枪机/套筒，拖着整双手补偿，造成错误抖动。

### 6.2 改造、通用瞄具与稳定校准

枪械开发包含改造时，继续读取 [改造与 ADS 校准经验](gunsmith-ads.md)。新增枪械必须检查通用瞄具安装、双标记对轴、闭锁基准、镜片透明、真实骨骼挂点、原件替换、统一材质及实例保存；已有 AKM/HK416/P9 数值仅作案例，不直接复制。

### 6.3 可见但不变形的反馈

1. 分开控制弹道后坐力、镜头反馈、整体视模后坐力、机械部件运动。增强冲击力优先调整整体位移/旋转和镜头，不随机扭动腕骨。
2. ADS 与腰射使用一致的每发触发、包络和恢复机制；ADS 可调幅度，但必须肉眼可见。不得通过锁死模型消除抖动，也不能用双层反向补偿抵消反馈。
3. 源动画若包含连续扫射手臂抖动，不直接当单发 clip 每发重启叠加。可从稳定握持姿态抽取单次机械动作，整体震动由 Gun 提供；每把枪检查机械轴与行程。
4. 连射扩散须有单发增量、上限、停火恢复及 ADS/移动/空中修正，独立于视觉晃动。数组索引按长度取值/夹紧；未类型化 Array 元素显式声明类型，防越界与类型推断失败。
5. 至少比较 30/60/144 FPS 的回正、累积与左右手稳定性；有限骨骼数值只是基础，不能替代实际渲染检查。

## 7. 音效与特效

1. 先检查用户指定的 `game-dev` 音频和实际配置映射；同名 MP3/WAV 与目录中存在的专用文件不等于正在使用的资源。按用户选择接入并记录原路径、格式、时长及用途。
2. 开火、装备、普通/空仓换弹、机械声、环境尾音分开配置。已有完整装备声时关闭重叠的通用机械提示；重复输入不能重播整段换弹声。
3. 对照弹匣插拔、拉栓等接触帧与波形标注声音事件。缩短动画后重新验证声音时刻；文件已加载或静音 GIF 不能证明听感和同步通过。
4. 需要新声音时找许可明确的公开资源并保留署名要求；不能把模型许可证套到声音上。避免用整体变速把机械声音高低明显改变而不验听。
5. 火光使用有层次的短闪、火舌、火星与受控点光，不用大白团遮住机瞄；余烟随持续射击积累、停火自然消散，切枪清理发射状态。
6. 命中材质按可用的表面/标签信息映射金属火花、木石碎屑等，并提供未知材质兜底；外观反馈不改变伤害判定。
7. 同时检查弹壳出口、枪机、余烟与环境尾音，避免每发重启把前一发尾音截断。先使用项目现有音频/粒子管理，出现负载证据后再引入池化。

## 8. 武器、背包与存档

1. 正式接入包含模型/材质、视模适配器、场景、可玩 `WeaponData`、音频和来源记录。音频预设 `.tres` 不能冒充可玩的武器定义。
2. 新武器通过数据配置伤害、射速、弹匣、备用弹、扩散、ADS 与反馈；不要为换一把枪改全局默认值。
3. 切枪保存每把枪弹药状态，清理旧基准容量、配件倍率与动作状态，再初始化新数据并应用对应装备修正。防止旧枪备用弹上限截断新枪弹药。
4. 背包定义必须有真实 `weapon_data` 映射、名称、分类、装备槽、图标和实例身份；验证装备操作真的切换 Gun，不能只生成 UI 条目。
5. 图标使用实际模型渲染。验证右键装备、武器槽/副槽、快捷切枪、弹药 UI 和物品修正；只在拥有的武器中循环，不因兜底逻辑凭空授予枪。
6. 清空背包仅在用户明确要求时进行。实施前备份真实存档；清理范围按授权区分武器、其他装备和非装备物品，不连带删除金币、任务或仓库数据。
7. 重置使用显式一次性工具，默认 dry-run，正式写入才传应用参数；禁止放到每次启动。注意仍运行的游戏会自动保存旧内存状态覆盖修改，写盘前处理该实例，不能误停编辑器或别人的测试。
8. 所有测试、截图、冒烟通过 `INVENTORY_SAVE_PATH` 等现有入口使用隔离存档。正式修改后重新读取确认物品/槽位与保留数据，预览可用其副本。
9. 射击后切枪需要关注渲染资源生命周期；若 pending draw 仍引用旧材质，使用适当的绘制完成时机释放。无头环境不能等待永远不来的 `frame_post_draw`，须单独处理。

## 9. 验收与交付

按改动范围运行必要验证，不对纯文档修改运行游戏。对完整新枪接入，以下各层不能相互替代：

| 层次 | 必须检查 | 证据 |
| --- | --- | --- |
| 来源/转换 | 来源、格式、权重、部件、材质、clip 清单、源与运行时时长 | 来源记录、转换报告 |
| 导入/脚本 | 新资源导入、类型与数组边界、加载路径、脚本错误 | 导入与冒烟日志 |
| ADS/动作 | 稳态对轴、开火回正、左右手接触、机械行程、动作衔接 | 几何探针、实际模型连续渲染 |
| 业务/移动 | 弹药一次结算、切枪保持、冲刺换弹互不打断、滑铲跳 | 对应状态/物理测试 |
| 背包 | 真实装备驱动 Gun、拥有权、UI、存档保留 | 隔离存档测试与读回 |
| 视听 | 游戏 FOV/近平面/光照下无断臂穿模、不过曝、枪声与接触同步 | 游戏视角预览与实际验听 |

- 先读已有测试的前置条件，适配静态/动画管线；不照抄历史仅适用于某坐标轴的断言。等待渲染帧的测试不能直接用 headless 跑。
- 收集退出码和实际错误；区分新增失败与已有退出资源警告，不把“退出 0”称为所有视觉/音效验收通过。
- 交付可编辑源文件、导出模型、适配/转换脚本、来源记录、动作与数据配置、实际模型预览及简短验证结果。临时 staging 路径须写入项目记录以便继续工作。
- 报告源中缺失、三维重建、未验听或未实际输入测试的边界；不得把数值探针、静音 GIF 或资源存在当作完整体验验收。
