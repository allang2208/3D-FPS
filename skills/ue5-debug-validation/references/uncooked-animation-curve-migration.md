# 无界面游戏启动中的骨架曲线迁移

适用于 `UnrealEditor-Cmd -game` 在加载原生动画时崩溃，而同一资源可在编辑器／Python commandlet 中加载的情形。先保留失败日志并定位实际调用链，不把最后出现的资源名直接当成根因。

## 识别本案例的故障链

2026-10-22 FPSGAME 案例：`J_Twinblast_Idle` 是最后启动加载的包。只预热压缩缓存、重新保存动画，以及移除重定向参考网格，均没有解决；参考网格改动已恢复。

记录自己启动的进程的 DLL 基址后，对照本机 DLL 导出表，将未知地址缩小到以下调用链：

`UAnimSequenceBase::PostLoad` → `USkeleton::AccumulateCurveMetaData` → 添加曲线元数据 → `UEditorEngine::BeginTransaction`。

本机 UE 5.8 源码显示：旧版本动画／骨架的曲线标志会在 PostLoad 迁移到骨架。骨架缺少相关曲线时，迁移尝试启动编辑器事务；无界面 `-game` 没有 `GEditor`，导致空指针崩溃。导出表只能定位已导出函数和偏移，附近导出名不是完整调试符号；需结合实际源码，不能只凭最近名称定责。

## 有针对性的修复

1. 确认当前角色实际使用的骨架及触发动画，读取缺失曲线名单和旧版本迁移条件；不批量删曲线或禁用角色动画。
2. 在适用的编辑器 authoring／commandlet 环境加载目标骨架及当前同骨架动画，使已有的引擎迁移执行。
3. 比较迁移前后的曲线集合、骨骼数量和参考姿态；备份并保存**骨架包**。只保存动画包不一定会保存被它更新的骨架元数据。
4. 只保存本次明确的目标包，保留其他曲线与骨骼。保存前确认磁盘版本未被并行修改；已有编辑器／PIE 仍遵守共享批次与保存边界。
5. 用户要求验证时，在新进程重跑原失败入口，再继续原联机用例；commandlet 能加载不等于无界面游戏已修好。

本案例补齐 `mask_geo`，342 根骨骼及参考姿态不变，之后监听主机、客机和重连测试完成。`mask_geo` 是该资产族的名称，不应硬编码成所有动画修复的必备曲线。骨架保存是依赖闭环，不是全局重定向或网格重绑。

制作入口：`Tools/LeatherBootsTailored/repair_skeleton_curve_metadata.py`。它由该次诊断产生，重用前核对骨架、动画路由与授权范围；不要给普通 Git 整理附加引擎启动或测试。地址解析工具为同目录 `resolve_startup_exports.py`，输入为该次失败进程的日志和模块基址快照。

证据保存在 `SourceAssets/LeatherBootsUpgrade20261022/TailoredV2/Audit/StartupRepair/`。后续归档的失败尝试按发布清单到 `trash` 取回，不能用旧失败路径启动另一个未经授权的测试。
