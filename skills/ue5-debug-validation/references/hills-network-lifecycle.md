# 实际丘陵地图的联机检查边界

仅在用户明确要求联机检查时使用。适用于动物表现、共享拾取、同档重连、队伍换图与建筑室内状态。

1. 保留生产地图、GameMode、FPS Pawn、玩家影子档案与 RPC；隔离 `UserDir`、档案 ID、世界存档和 UDP 端口。轻量旁观者夹具可检查动画复制，但不能替代生产库存与保存路径。
2. 每个阶段等 Pawn、影子档案和复制 Actor 引用实际就绪再请求。初次资产编译会阻塞开发进程；区分资源准备停顿与网络故障。测试专用超时调整写入该进程参数，不能为通过夹具放宽正式校验。
3. 双人竞争拾取记录双方库存增量总和、拥有者回执及权威影子档案；返回地图后检查已消费掉落 ID 不再出现、未拾取掉落仍存在。
4. 真正断线时先结束本轮客机进程，让生产 Logout 清理旧控制器和 Pawn，再用相同 `UserDir`、档案身份重新连接。不能在测试中提前清理会话或换用新身份冒充恢复。
5. 换图走生产队伍准备、保存和 ServerTravel；目标地图上确认每个玩家都有新 Pawn。离开丘陵后分别检查服务端和客机的环境动物计数，避免把正常战斗犬类计成环境野狼。
6. NullRHI 没有 GPU shader map 或贴图驻留条件。若实际地图准备永久等待这些资源，在明确的无图形设备分支跳过纯 GPU 门槛，保留实际地形、碰撞、场景与玩法；不要全局强设地图 ready。

室内可用真实玩家视点调用生产 blendable，检查两位玩家在内外交换时的独立性与边缘曲线。这只证明逐视图计算；最终渲染、曝光历史适应和主观亮度仍需另有画面证据。门 RPC 与站姿胶囊扫掠也分别记录。

回执包含构建版本/模块散列、实际延迟和丢包日志、各阶段结果、各进程退出码及强制断线标识。旧 DLL、初始化失败和中途中断的运行保留原状态，不拼接成完整通过。`Tools/Wildlife/run_hills_closure.ps1` 是项目入口，使用前先完成相应本机源码接入与构建。
