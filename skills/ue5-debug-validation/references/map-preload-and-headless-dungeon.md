# 地图预加载与无界面地牢诊断

适用于“地图在磁盘却不能载入”、预加载后联机进图失败，以及无界面地牢准备卡住。本参考只规定诊断归因；运行对照和联机测试仍须用户要求。

## 文件存在但 LoadMap 失败

先区分不存在的依赖、损坏地图和内存中的不完整包。UE 5.8 的 LoadMap 会复用 FindPackage 返回的 UPackage，再寻找其中的 UWorld；包存在不代表该世界还在。

装备/身体异步预加载器不能把地图列为普通装备资源。扫描源码字符串生成的资产注册表可能误收 `/Game/GameMaps/`；提前加载的世界包跨过换图 GC 后，可能剩下没有世界对象的包，导致地牢载入失败，回退主地图也失败。

合阙案例用启动早期 `-DPCVars=fps.body.AsyncPreload=0` 做对照后连接成功，再在预加载路径筛选中排除地图。`-ExecCmds` 在此案例晚于首次预加载，日志能直接证明它不是有效对照。最终应恢复默认开关重试原载图流程；不得把长期关闭整个预加载器当作已修复。

## 无界面准备与资源压力

- 无界面双进程只验证本次玩法/网络合同，不代表 GPU、特效或音画效果。渲染预热状态不能用玩法资源载入百分比代替。
- 若无渲染进程停在某个怪物类，分别记录装配任务、软资源完成数、类提交游标及渲染状态。渲染等待和真正缺失的玩法依赖分开定位；不要通过跳过导航、伤害或门条件使测试通关。
- 可用 `FApp::CanEverRender()` 区分需要渲染的进程；无渲染路径仍需等待玩法软依赖。合阙的这项兼容改动截至 2026-10-15 仅落源码、尚未构建，不作为已验证模板。
- 批次互斥不限制用户手动打开编辑器或不使用桥的后台脚本。两个正式地图进程会复制大量资源；实测内存提交余量耗尽时只停止本任务确认归属的进程，保留失败记录和编辑器未保存内容，不杀其他会话。
- 用户取消自动测试后，撤销其后续排队与关闭编辑器请求，交付区分已保存资产、已链接 DLL、待构建源码和未完成的运行检查。

证据入口：FPSGAME `Docs/Monsters/heque-dungeon-e2e-20261015.md`；默认预加载下客机载图已恢复，完整通关/并发宝箱/全队返程没有取得通过结论。
