# 怪物标准开发工作流

以用户认可的角色身份和动作意图为真源。流程按当前请求阶段执行；修改一个动作时不强制重做整条管线。项目路径、工具版本和资产接口先从当前工作区确认，不能把历史绝对路径当成当前环境。

## 1. 先看参考，再做动作

- 用户于 2026-09-06 明确要求：每个动作开始前实际查看已有动作表或源视频，同时读取帧数、帧序、播放速度、循环、接触帧、有效窗口与状态配置。仅看文件名或首帧不算完成参考。
- 输出简短动作笔记：起势、重心转移、接触、收势、末帧；分别描述左右肢体、支撑点、拖行/跛行、身体旋转和位移。保留关键帧证据。
- 用秒记录时间合同，同时注明原帧号从 0 还是 1 开始、窗口端点是否包含；帧数不等于运行时间，核对实际播放配置。
- 概念图确定造型，动作图/视频确定运动意图。单视角无法证明的背面、深度与遮挡关节属于三维重建，不能称为精确动捕。
- 若源动作不存在，先说明缺项，依现有角色意图设计动作；不要虚构参考。已有授权足够时直接推进，不重复请求确认。

## 2. 选择模型与骨架方案

- 原创身份或特殊拓扑优先保留设计；现成 CC0 模型适用于用户接受通用替身的情况，不覆盖指定原画。
- 需要生成网格时可选用户已有 TRELLIS、Meshy 等可用管线；先确认服务、费用授权和输入要求。H3 等视频是动作参考，不能自动提供可靠三维骨架或蒙皮。
- 记录源图、提示词、生成器、模型版本、参数/seed、来源与使用条件。日志不保存密钥或访问令牌。
- 查看正/侧/背轮廓与关节附近几何，确认 UV、贴图、法线、尺度、轴向、脚底/支撑面。通过几何与视觉证据后才绑骨；坏身份或缺失肢体先修模型。
- 非类人怪物按功能建骨链：主体、支撑肢、推进肢、攻击器官、尾/触手/翅及附件。先定义支撑相、关节自由度和命中区域；不强套 Humanoid/Mixamo 或固定骨数。
- root 负责整体空间约定，变形骨负责姿态；明确原地动画还是 root motion，由哪一层实际移动，避免双重位移。

## 3. 蒙皮与动作制作

- 检查绑定姿态、逆绑定矩阵、骨链长度和关节朝向；按目标导入器限制权重数量并归一化。相近但分离的肢体不要因距离算法串权重。
- 用肩/肘/膝或等价关节的极限姿态检查塌陷、拉丝、穿插与蒙皮爆炸。UV 接缝造成的分片顶点数不等于真实网格碎裂。
- 待机保留呼吸/摇晃与角色重心；移动先处理支撑点和落脚，再处理躯干、头与次级摆动。跛行要体现在左右支撑时长、步长、抬脚高度、承重下沉，而非全身对称晃动。
- 攻击重建起势—接触—收势，保留左右差异及跨步；视觉接触与业务窗口对齐。死亡按参考分阶段失衡、接地、躺倒，单次播放停末帧，避免父类额外翻转或立即移除。
- 原地移动动作记录匹配速度，运行时按实际水平速度调整播放速度；记录调速对角色动作风格的影响。循环检查首尾骨骼姿态和接触连续性，非循环不得为凑循环改回站姿。
- 修改一个动作保持其他已认可动作及角色身份；交付实际模型渲染 GIF/视频、可编辑源文件、构建脚本和 GLB。GIF 为展示重复播放不代表 Death/Attack 在游戏循环；合帧后核对总时长，不能机械要求 GIF 帧数等于采样帧数。
- 导出后重新导入检查时长、首帧、关键接触与末帧、蒙皮和贴图；只看 Blender 源场景不算导出验证。

## 4. 接入与数值

- 预览认可与运行接入是不同阶段，按用户实际授权推进。先独立版本文件验证，再切正式引用；保持场景在切换期间可打开，不提前删除资源或无差别清缓存。
- 阅读当前敌人、玩家、伤害、Buff、击杀与刷怪接口。优先独立怪物控制器/场景，保持既有公共接口，不把通用敌人接近立即扣血逻辑叠加到时间窗攻击上。
- 区分业务状态与动画状态。业务至少覆盖可用动作及打断/死亡；AnimationPlayer、AnimationTree 或程序控制均按需求选择，不为形式增加一套状态机。
- 攻击采用一个权威时钟驱动动画与判定，配置起手、有效窗口、收势、冷却、转向锁定、射程/范围、遮挡与命中去重。低帧跨过整个窗口时仍按设计判定；多段攻击分别定义命中次数和重置时机。
- 定义眩晕、冻结、击退、恐惧、目标消失和死亡的中断语义。死亡清理未完成攻击，关闭伤害与碰撞，击杀通知仅一次，动画和保尸结束后移除。
- 数值表注明原始值、三维采用值、换算/调整理由：生命、伤害类型、护甲公式、移速、范围、警戒、冷却、尸体时间。二维像素不能直接当米；单个怪物样例参数不成为全怪物默认值。
- 逻辑碰撞、寻路占地、受击部位、视觉骨架分别定义；头或攻击器官命中体随实际动画位置，必要时用骨骼附着。保留现有 Buff 与击杀/奖励链路，不伪造进度。

## 5. 分层验收与交付

- 静态/导入：资源存在、动画名与时长、UV/贴图/蒙皮、UID、场景引用；使用当前引擎 console 可执行文件捕获日志和退出码。
- 行为测试：前摇无伤害、有效窗口/冷却、去重、躲避和遮挡、控制打断、死亡取消攻击和一次击杀、保尸移除。根据实际技能增减，不机械要求固定测试数量。
- 主场景：确认真实生成、实际位移、播放动作、落地高度/碰撞、伤害链路。仅 state==CHASE 不证明移动；仅水平位移不证明站在地面。
- 渲染：用项目默认渲染设置查看模型与关键姿态。按需要增加兼容渲染对照，记录实际 GPU/后端；不要把兼容渲染成功当默认设置通过。
- 截图测试中先 add_child 再设 current_scene；不要为冻结角色而禁用整棵世界树，可能使地板失效。只停需要冻结的角色处理，等待骨架和渲染更新，确认活动相机。
- 区分静态检查、自动行为、关键帧目检与完整人工试玩，报告确实完成的层次。失败先确定资源/驱动/测试夹具哪层有问题，不直接改造型掩盖测试错误。
- 交付正式场景/脚本、数值表、来源合同、动作预览、可编辑源/导出文件、测试入口与结果。复用细节参阅 [僵尸案例](references/zombie-case.md)。

## 6. 仓库沉淀

- 技能可安装到个人 skills，但项目保留同版技能以便版本管理；技能入口链接到详细案例，案例数值与标准规则分开。
- 发布前确认真实 Git 根与素材目录的区别，检查已有 remote、分支、暂存区与历史体积。共享工作区仅暂存本任务明确文件及共享文件对应补丁，不夹带他人改动。
- 用户授权推送后执行普通推送并核对远端提交；新远端为空不代表本地历史适合整包上传。失败记录具体原因，不自动强推、改写历史、迁移 LFS 或清理他人文件。
