# 设施搜索容器：投放、共享库存与存档

用于 FPSGAME 搜索柜、抽屉、工具箱和服务器柜的投放或联机调整。当前入口是 `ColdSteelSceneContainer`，概率源是 `Content/ColdSteelData/scene_search_loot.json`；具体物品和数值以该配置及 `Docs/Gameplay/facility-search-loot-20261013.md` 为准。

## 先确定范围和概率含义

- 用场景配方中的稳定 `ContainerId` 逐项绑定，记录模块、入口数和分组。随机分区的“第一个场景”不等于固定节点序号；不要扩大到同类外观的所有柜子。
- 分组与稀有度独立。当前四组为日常、文件、检修、机房；只投放已存在于目录、且有用途或明确回收价值的物品。设计清单中的未制作物品不自动进入池。
- 先抽件数，再按权重不放回选物品；同箱不重复品类，不同箱可以重复。`count_weights[n]` 表示出 n 件的权重，零件数也占一个数组位置。
- 当前31个入口采用 `[0,70,25,5]`，即首次生成1/2/3件分别为70%/25%/5%。这是当前平衡参数，不是所有容器的永久通用模板。调整上限必须一起修改 C++ 配置解析、抽样统计数组与逐件概率计算，不能只改 JSON。
- 条目权重不是“每柜出现概率”。文档须包含件数分布，并计算不放回抽样的边际概率；多件容器的物品概率合计是平均件数，不是100%。

## 一次生成与持久状态

- 当前正式地图范围为 `L_Dungeon_Randomized`。采用运行ID区分储物键，运行种子、容器ID及独立随机域决定抽取结果；玩家ID、搜索先后、Actor生成顺序和全局随机流不参与。
- 单人把物品、容量和 `DungeonRun.Claimed` 放进同一次角色档案提交；成功后才开门。联机只在服务器执行抽取，使用 `ColdSteelSharedInventorySubsystem` 的共享记录与现有交易日志/角色回执。
- 区分旧版 `bSeeded` 与 `bSceneLootResolved`：旧空柜可能仅建立过面板，没有生成过搜索物品。已经生成、此前为空或后来被取空的容器都属于已结算；改概率和重连不清除标记、不补刷。
- 首次搜索“必出”不代表重新查看必有物品。新运行获得新状态；上一运行留在箱内的物品和已取入背包的物品分别处理。
- 旧私有内容和共享内容不能跨两份角色档案无日志搬运。当前单人旧档转联机、尚有房主私有内容或领取记录时，由房主先开柜，通过同一日志完成迁移。已有内容保留，不再叠加首搜奖励。

## 联机交互边界

- 请求走实际所属 `PlayerState`/控制器的服务器入口；客户端不能提交物品结果、种子或自称权威的存档。
- 先验证场景、距离、遮挡、生存状态，再处理内容。返回失败请求的容器清单时也要验证访问资格，使用实际控制器的 Pawn，不能信任请求中的 Pawn 引用。
- 未搜索不得先提交移动；移动、拆分和批量操作校验共享 `Revision`。提交成功才递增版本并通知其他查看者刷新；旧版本操作被拒绝后，在仍可访问时回传新视图。
- `NetView.*` 是面板投影，不是玩家拥有的物品，持久化与网络档案合并前必须清除。内容提交失败不先发布门状态或消耗物品。
- 生成场景Actor有自己的稳定命名和晚加入恢复路径；不能仅添加 `DOREPLIFETIME` 就认为这些非复制生成Actor已经完整同步。

## 开发、记录与发布

- 概率配置只缓存读取一次，不在 Tick/HUD 刷新中读文件。新配置与二进制在新进程加载；不要为了刷新缓存自动启动或重启编辑器。
- 用户要求检查时，分开记录数据覆盖、固定种子/件数抽样、共享记录序列化和真实双客户端测试。内存中的版本拒绝测试不能证明弱网、掉线或实际抢取已经验收。
- 2026-10-13 的0～2件版本执行过两项原生自动化；后续1～3件版本完成 Editor/Game 构建，未重新测试。不能把前版抽样成功记为新版结果。
- 发布前确认共享库存底层是否已进入目标 Git 基线。只属于当前任务的接入差异可以带基线哈希发布为补丁；必须明确它依赖尚未发布的框架，不能把补丁称为仓库已完整集成，也不能夹带其他未完成模块。

## 随机家具与迁移补充（2026-10-15）

- 运行时 Run{seed}.Node{node}. 前缀和 Hospital.Bedside 动态族只在掉落池查找时归并；抽取种子、领取标记和存储仍使用完整身份，避免不同房间共用一个箱子。明确验证允许的身份格式，不把任意后缀映射为合法容器。
- 逐端生成的床边箱继承确定的父 Actor 名，子名含完整 ContainerId 的 CRC，并保持 NetAddressable；不能同时开启复制生成而制造两份箱子。摆放不依赖玩家/怪物的瞬时位置，沿现有静态建筑碰撞与局部占用表生成。
- 统计区分候选 ID、每局实际入口、动态容器族、设备布景和独立宝箱。配置扩展后同步更新既有测试的绑定数/池数/物品数；进程退出码 0 不等于自动化用例通过，要看具体测试结果。
- 尺寸及旧键迁移参见 [物品占格与共享库存](../../ue5-save-load-replication/references/inventory-footprint-migrations.md)。迁移后的已生成/已取空标记与当前回执一起保留。
