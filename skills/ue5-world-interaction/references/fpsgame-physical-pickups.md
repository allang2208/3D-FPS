# FPSGAME 模型掉落、重力与对准拾取

适用于 FPSGAME 本机单人运行。当前入口为 `Source/FPSGAME/UI/ColdSteelPickup*`、`ColdSteelProfileRuntime.cpp`、`ColdSteelWorldInteraction.cpp`。先核对实际源码与资源路径，再沿用本文的项目合同。

## 松手卡顿：先区分资产、装配、保存和 GC

- 在鼠标释放、模型装配、存档提交、世界生成和后续 GC 分别采样。资产已驻留不能排除卡顿：UE 5.8 的 `FPreviewScene` 释放路径默认受 `r.ForceGCOnPreviewSceneExit` 控制，会请求整轮垃圾回收；核对本机 `Runtime/Engine/Private/PreviewScene.cpp`，不要将此行为无条件推广到其他版本。
- 不为每次掉落新建并销毁预览世界。`UColdSteelPickupStudio` 按 GameInstance 生命周期复用隔离角色，按武器定义分开装配，关闭不必要的预览音频/灯光/物理；这些角色不能接管真实玩家、执行库存 AttachPawn 或启动玩法。
- 碰撞边界以武器定义和完整、排序后的配件组合为键缓存，保持容量有界；在图标准备阶段加载对应组合后预热。首次启动或尚未预热的组合仍可能需要加载，不把热缓存耗时表述成所有场景性能。
- 复用时重新设置当前组合的网格分段、姿态、配件可见性与变换。测试原装→改造→原装、不同枪型、GC 后再次装配，并检查先前生成的地面模型没有被后续改造影响。
- 缓存对象需有 GC 可追踪的持有关系；子系统释放时先结束预览角色生命周期再销毁预览世界。保留正常 GC，不用全局关闭回收来绕过掉落热点。

## 重力与库存事务

- 用物理碰撞组件作根，冻结的枪械姿态与可见配件附着于其上。碰撞边界覆盖实际可见模型，合适的重心、摩擦、阻尼和 CCD 用于落地；不是用浮动图标或固定高度假装重力。
- 探查附近地面和障碍后在地面上方释放，让刚体下落。区分释放位置与落地位置：同步/保存地面物品的实际位置、旋转，重新读档还原物件；恢复时不能把生成预览角色误当作玩家。
- Drop/Pickup 保留原存档事务及失败回滚。满包、失败保存、过期实例不应销毁世界物品或丢失背包物品；性能优化不能通过跳过保存校验实现。

## 对准、E 与面板状态

- 当前用户约定为镜头中心命中且在距离内按 E 才能拾取/打开仓库；范围仅作为资格判断。遮挡、距离、目标身份、UI 占用鼠标都应在执行时重新检查，近距离不自动触发。
- 仓库开启后的保活使用范围判断：进入 UI 后鼠标/镜头焦点改变，不能继续要求镜头射线命中，否则面板会刚打开就关闭。重新打开仍需对准。
- 物理物件会离开保存的释放坐标。审计应瞄准当前刚体位置；设置控制旋转后给玩家摄像机更新机会，再发拾取输入，避免同帧旧镜头缓存产生假阴性。不要继续断言物件立即位于旧的固定地面偏移。
- 当前射线路径仅支持 Standalone；这里的验证不是多人复制或服务器权威验收，扩展多人时另按相应技能设计。

## 已有验收入口

`Tools/UI/run_world_interaction_acceptance.ps1` 覆盖模型、下落/落地、满包、失败保存、遮挡、对准 E、仓库 UI 保活和新进程恢复。`run_drop_hitch_acceptance.ps1` 覆盖真实松手与缓存复用；日志中的显式 GC 测试阶段要与每次丢弃触发的 GC 分开解释。

历史证据在 `Docs/UI/drop-hitch-and-backpack-close-20260911.md`：2026-09-11 修复前每次预览销毁伴随约 21–44 ms GC；一次热缓存真实松手约 14.5 ms。它们仅是当时宿主采样，不能作为当前地图的帧率承诺。
