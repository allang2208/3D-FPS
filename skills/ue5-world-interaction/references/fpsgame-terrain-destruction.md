# FPSGAME 地貌破坏（高度场）——可迁移规则（2026-09-16/17）

适用于 `D:/FPS3D/FPSGAME` 的丘陵世界（`ATemperateHillsWorld`，运行时高度场 + 64 m 分块
`UDynamicMeshComponent` 流送）。详细数值与开关见 `Docs/WorldGeneration/terrain-destruction-20260916.md`；
体素线路已退役（`trash/voxel-terrain-retired-20260916/`）。

## 先做后端选择，再写玩法

| 需求 | 高度场 | 体素 |
| --- | --- | --- |
| 弹坑、挖低、回填、切台阶 | 够用，且**零地形数据内存**（高度是纯函数） | 可以，但代价高 |
| 竖井、洞穴、悬垂 | **做不到**（每 XY 只有一个 Z） | 必需 |
| 成本随什么增长 | 视野内分块数（面积）；编辑只重建覆盖到的分块 | 分辨率立方（体素尺寸减半＝体素数 ×8、表面 ×4）；与地图面积无关（LOD 流送） |

**不要为了一个局部功能叠加第二套地形管线**：两套并存时地形网格、碰撞、线程池各走一遍，
是性能最坏情况，而且"库里有免费插件"不等于可以白嫖（无 LICENSE 文件、默认值面向 demo）。
先问"这个玩法能不能用高度场表达"，能就用高度场。

## 编辑数据模型

- 一条地形编辑 = 纯数据 `FTerrainEdit{Type, X, Y, Radius, HalfX/HalfY, Amplitude, Lip, Seed}`
  （玩家可在大世界任意位置挖，不能存格坐标表；必须是"函数 + 差量"）。
- `Amplitude` 是**要加到生成高度上的带符号变化量**：负＝下沉、正＝抬升。所有调用点统一做
  `Height = Base + Offset`、`VertexZ += Offset`；**同一个公式里出现两次取负就一定会把坑做成包**
  （本项目踩过：`Height = Base - Offset` 而 `Offset` 内部已经是负 → 全图隆起）。
- 弹坑剖面：半径内 `Amplitude·(1-(d/R)²)²`、半径外一圈反号唇；两个剖面在边界处零斜率，
  这样坑外仍可沿用生成法线（只在影响范围内做数值法线）。
- 重叠处理：**方块步进相加**（每铲一层就低 20 cm），**弹坑之间用平滑最小值合并**
  （`SmoothMin`，k≈60 cm），否则相邻弹坑交界会出尖脊。
- 重复感：每个弹坑用位置派生的种子给轮廓/深度叠两个低频谐波（半径 ±11%、深度 ±10%）。

## 与 20 cm 建造网格对齐

- 挖掘/回填的单位是**整层 20 cm**，足迹取 20 cm 的整数倍（本项目 240×240 cm = 12×12 格），
  中心 `GridSnap(…,20)`；这样挖出来的坑正好能放建造体素。
- **一击一层**：表土的 `FProductionResource::HitsRequired` 设为 1（树/岩石仍是 3），
  每次完成就下沉一层，并重置该格采集进度让它可继续往下挖。
- 上限用 CVar 而不是硬编码：`fps.Hills.MaxDropCm`（默认 400）、`fps.Hills.MaxRiseCm`（默认 100）；
  到达下沉上限时把新编辑的深度**削到剩余额度**，额度为 0 则拒绝并让那一格保持"已采尽"。

## 工具与手感

- **瞄准距离 ≠ 采集触及距离**：工具继承的 `Reach`（3.2 m）会让玩家只能挖脚底下；
  铲子要单独给一个瞄准射线长度（`fps.Tool.DigReach`，默认 1000 cm），左键挖掘与右键回填都沿
  屏幕中心射线。
- 右键在"工具在手"时必须被工具吃掉（本项目：右键＝回填，而不是 ADS）；枪械/近战 ADS 不受影响。
- 回填要有对称经济：挖一层产出 2 个「泥土」，回填一层消耗 2 个（`ConsumeItem`），
  失败时在提示栏给出原因（泥土不足/到上限/陡坡河床）。

## 性能写法（大世界必须做）

- 一次编辑只把**覆盖到的分块**标脏：旧网格继续留在场上，新网格异步生成 + 碰撞烹饪完成后才替换
  （不会掉进地里，也不触发整片重新流送）；飞行中的旧网格用"编辑计数"判废，避免连续挖掘丢编辑。
- 编辑过的分块可以翻倍细分（`fps.Hills.EditMeshBoost`，1 = 关闭）；这是"棱角感"与开销的旋钮。
- `Height()`/`SurfaceNormal()` 会被植被/PCG 采样调用上百万次：编辑必须做**空间桶索引**
  （本项目 32 m 桶 + 3×3 邻域），不能每次采样遍历整张编辑表。
- 编辑要有数量上限（本项目 256 条，淘汰最旧的并重建那块地）。
- 顶层物件（草类 ISM）随编辑清除；PCG 分块流送会把实例带回来，所以对玩家附近的编辑按秒补清一次。
- 定位性能问题先 A/B + `stat`：`stat unit` → `stat game` → 各自系统的 stat；
  "加了一个局部系统后整张地图变卡"通常不是内存泄漏，而是那个系统的默认设置（例如为每个可见分块烹饪碰撞）。

## 存档

- 世界存档只存 `Seed/WorldId + 编辑数组`（版本化，旧版本读进来做迁移），编辑先落盘再公布；
  维护脚本 `Tools/WorldGeneration/Clean-HillsEdits.ps1` 可以只清编辑、保留世界身份（种子不变）。

## 已知边界（别当成 bug）

- 树/岩石不会随坑洼重新落地（PCG 实例不重算），只有新生成的点用新高度。
- 河道水面网格、远景 backdrop 用各自的高度，不参与地貌编辑。
- 主城是静态地板，不是地形，火球只留特效。
