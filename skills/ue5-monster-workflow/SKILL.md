## UE5 默认开发方式（用户确定，2026-09-23）

后台优先：不主动启动 UE 编辑器；不主动检查、测试、启动 PIE、截图或验收渲染；不向其他对话/任务发协调消息。完整规则与「按改动选执行方式」表见仓库根 `AGENTS.md` 和 [后台开发与编辑器使用条件](../ue5-auto-assistant/references/editor-open-development.md)。

# UE5 怪物标准工作流

## 统一模型生成入口（2026-09-13）

新怪物模型生成先用 [通用模型生成工作流](../asset-model-workflow/SKILL.md)，以三视图和当前 5080 候选路线为共同起点；用户明确指定混元或已有认可模型时沿用其选择。本技能接续专用拓扑、绑骨、动作、AI 与游戏接入。默认不主动测试或验收。


当前 FPS 宿主为 `D:/FPS3D/FPSGAME`；先读当前 AGENTS.md 和 WORKFLOW.md。旧 Godot/2D 工程只提供参考。默认采用 **三视图与 5080 候选生成 + 本地拓扑 + 专用绑骨 + 本地动画 + UE 接入**；用户指定混元或已有认可模型时保留该路线。按本次授权阶段执行；只改一个动作时保留其余已认可资产和动作。

## 已认可的人形路线（2026-09-14）

用户确认胖子僵尸的 **Meshy 生成模型并完成材质、蒙皮绑骨 → 选用成熟动作 → UE 原生 IK 重定向 → 按体型修正 → 战斗、死亡和残留物接入** 流程成功。遇到这类已绑骨的人形输入，读取 [Meshy 人形怪物与成熟动作复用](references/meshy-humanoid.md)，从已有模型继续；不要重新生成、强制改绑标准骨架或把本次归因于本地从零绑骨。新怪物生成仍尊重用户指定路线。选动作源时可用 Meshy 动画库接口按关键词/分类搜索 678 个预设（含受击族与死亡类，GIF 预览交用户拍板，套用 3 积分/个、产物 3 天内落盘），调用与约束见 [Meshy API 管线](../asset-model-workflow/references/meshy-api-pipeline.md)。

毒液僵尸步态、出生时固定移动、多供体随机近战和命中叠毒，读 [瘦长僵尸动作与战斗接入](references/spitter-locomotion-and-melee.md)。保留原蒙皮，先分清源动作、头部补偿、接地与播放速度；当前制作结果不作为已通过视觉验收的模板。

旧 Godot 动作迁移、跑姿选源、站立受击和废案整理读 [怪物动作迁移与归档](references/monster-motion-migration.md)。按真实运行引用确定源片段，保留有效动作后再归档混合制作包；已导入但未获用户认可的版本不作为成功模板。

从原生成模型修复长肢关节、背膜接触与视频参考跑姿时，读 [M-07 原模型迭代与完整姿态](references/blind-supplicant-m07.md)。区分几何／权重／参考帧／布料映射，局部掌面朝向不能覆盖整体屈肘姿态；制作源速度、游戏移速与播放周期共同匹配。V21 跑姿未满足用户预期；V22 腿脚获用户基本认可，V23 保留原步态并修订内向掌心及对侧摆臂，已保存、手部仍待体验，不扩大为整身认可。V24 重制联动施法、前移火球／冰锥蓄积中心并统一发射原点，已后台保存及完成必要构建，未测试。

狂奔人形、张开爪型、飞扑接地/提前量、追踪回家与表面修订读 [狂奔人形与飞扑](references/feral-humanoid-pounce.md)。当前案例已获用户基本认可；局部手部旋转不能破坏原身体配合，重建顺序与素材公开边界在专用参考中维护。

人形击飞、倒地起身与死亡布娃娃质量/预算读 [人形击飞与受限布娃娃](references/humanoid-knockdown.md)。2026-10-03 用户认可当前巫婆的移动、倒地和死亡效果，并要求推广；巫婆作为本次制作基准，其他怪物的推广仍待用户测试。公开源码恢复范围单独记录。

非人形死亡按用户于 2026-10-05 指定的 M-14 V19 连续软体方式制作，读 [非人形死亡标准](references/nonhumanoid-ragdoll.md)：各模型独立代理、完整表面绑定、变形法线、接地定姿与共享预算。人形及类人双足暂不推广；既有物理资产保留作为降级，活体击倒和恢复动作单独制作。推广资产保存与用户游戏体验分别记录。

站立眩晕、醉酒感摇晃循环与控制衔接读 [人形原地眩晕](references/humanoid-stun.md)。本地 CC0 `Dizzy` 可作源动作；最终适配、导入和用户认可分开记录。

成品怪物待机呼吸、软体／犬类微动与既有动画叠加读 [待机呼吸增量](references/idle-breathing.md)。按物种严格 Idle 门控和支撑骨保留；当前实例跳过盲祷者，不替换原动画或加入独立 Tick。

## 四足怪物与通用动作模板（2026-09-14）

裸皮犬、多骨架犬科重定向、F6 根单位异常及预测飞扑，补读 [Meshy 犬科与预测攻击](references/canine-meshy-and-hunting.md)。用户认可的跑姿模板是 MeshyV2 + GodotRunNaturalV3，勿与退役 WolfV3 混淆。

四足开发先读 [狼母版与四足动作模板](references/quadruped-animation-template.md)。Wolf 已接入 F6，跑姿与撕咬修订保留在原动作数据集；从狼派生僵尸犬时另读 [换皮与随机伤口](references/wolf-reskin.md)。动作 ID 和数据结构通用，目标骨架仍需重定向与体型修正；不把源包动画数量、保存记录或本轮材质认可当成新角色动作验收。

## 1. 建立造型与动作合同

- 先实际查看原画、已有动作表/视频，再读帧序、播放时长、循环、接触帧、伤害窗口和状态配置。记录起势、重心、左右差异、支撑点、接触、收势及末帧，不能以通用对称动作代替参考。
- 三视图保持同一角色的轮廓、比例、器官位置、尺度与姿态；背面及遮挡区域明确属于三维重建。缺少死亡等源动作时注明原创设计，不虚构参考。
- 动作合同使用秒，注明帧号基准和区间端点。统一记录原地/root motion、移动速度及音效时间；二维像素不能直接当 UE 厘米。

## 2. 生成与风格统一

已有怪物换皮、感染组织与毛皮衔接、跨角色材质协调时读 [感染材质与风格统一](references/infected-surface-style.md)。统一组织分区、细节尺度与干湿规则，保留每只角色身份；优先复用合法库内素材并烘焙到自身 UV，按需要做保留骨架的局部修形。

- 使用混元分支时，混元用于候选几何与贴图。复用已有任务 ID、缓存与下载结果，不因后续拓扑或动画问题重复付费生成。密钥使用现有加密凭据，不进入脚本、日志或技能；账户余额与模型启用/后付费权限分别检查。
- 记录参考图、生成模型版本、参数、来源和使用条件。免费资产也需核对许可、比例、轮廓、材质表现和骨架适配；用统一参考灯光、PBR 通道及纹理密度协调风格，不能仅套统一颜色。
- 先看正侧背轮廓和近景，再处理局部拓扑、法线与材质。加面不能修复错误结构。认可外形后再绑骨。
- 保持认可的角色身份及主体表面连续性。开口、变形应修改同一模型；不得通过隐藏原脸、显现另一张生成脸来冒充同一角色变形。独立附件可以存在，但说明来源、连接与驱动关系。

## 3. 本地拓扑、骨架与动画

低矮宽体的嘴部扫掠、近战／魔法并行、高面蒙皮 LOD 和客机奖励归属，读 [M-25 涡电匣](references/m25-vortex-coffer.md)。用户已认可优化后的怪物；最新战斗修复已构建但未游戏测试，地牢刷新明确留待后续。

- 按主体、支撑、推进、攻击器官及附件设计语义骨链；非常规怪物不强套人形自动骨架。检查尺度、朝向、支撑面、绑定姿态、权重归一化和目标权重预算。
- 局部重拓扑保留外边界连接，平滑过渡权重；跨 UV 岛补面时重投影纹理，检查闭合、中间和极限姿态的开缝、拉丝及贴图拉伸。
- 动作按参考制作 Idle、Move、攻击及 Death；循环检查首尾与支撑连续性，死亡单次播放并保持尸体姿态。GIF 重播只代表预览方式。
- 新增变形骨保持中性姿态，验证旧动作骨骼变换及未修改区域的变形。记录修改区域与实际误差，不宣称重拓扑后全网格完全不变。
- 导出后重新导入检查模型、材质、骨架、时长和关键姿态，并渲染实际导出模型。Blender 源文件预览不能替代引擎导入验证。

### 类人怪物与持械动作

- **输入分类（巫婆重建，2026-09-22）**：已认可且适用的蒙皮、未认可的自动蒙皮、仅可复用外观的角色壳分别处理。已认可 Meshy 胖子保留绑定；不能把此经验泛化为所有生成长袍角色都必须保留错误权重。完整人体/手脚、显示衣物、模拟代理、人体碰撞分别交付。
- 独立手指、掌心接触、前臂扭转和投掷松握都属于持械制作内容；无手指输入只能交固定握型候选。人体候选的认可只覆盖用户实际看过的动作，比较衣物影响须保持同骨架、同动作、同速度与驱动条件。

长袍角色反复修脚仍失败、但完整人体动作粗模可用时，读 [长袍人形与外观适配](references/robed-humanoid-recovery.md)。区分可用动作基础、模型/蒙皮问题与用户未认可的修补，不将失败参数升级为标准。

- 先确定与写实风格、体型、持械手、工具长度及负重相符的源动作，再投入该角色的精细外观与动作适配。双手采矿改成单手攻击、挥抓改成重型工具砸地属于重新编排，不能包装成直接采用成熟动捕。
- 复用成熟骨架与身体拓扑时，明确生成模型是外观参考、衣物附件还是整套新蒙皮；自动绑骨不能保证肩肘、抓握和工具接触自然。换生成平台也不等于解决持械动画。
- UE 人形优先使用原生 IK Rig / IK Retargeter 对齐骨链与参考姿态。干净源动作、重定向、抓握、工具适配分层保留，不在反复烘焙的失败结果上继续叠加修正。源意图不符时重新选源；按授权进行定制时如实标注修改范围。
- Meshy 双足骨名不保证按解剖顺序编号；按父链定义脊柱和四肢，保留已有蒙皮。重定向 FBX 的动画位移可能已经完成米／厘米换算，不能再用参考骨架尺寸比重复缩放；锁容器根也不能修复错误的骨盆键。胖子的单位、体型和循环修正见 [已认可案例](references/meshy-humanoid.md)。
- 抓握姿态、手腕、整条手臂和工具轨迹一起设计。保持已认可网格、权重与绑定，使用成组手指抓握和可达的肘位；不能靠无限转动手腕满足工具尖端约束。工具头、柄身和柄尾均需连续避开身体，具体经验见 [持械动作与矿工废案](references/humanoid-weapon-motion.md)。
- 用户判废后，历次局部认可不再代表该角色整体合格。只保留有适用边界的通用经验；失败脚本和参数不升级为标准模板。预览、检查和试玩仍按用户授权执行，不自动追加验收。

## 4. UE 接入、布娃娃及刷怪

- 将现有怪物接入随机地牢终点时，读取 [Boss 遭遇生命周期](references/dungeon-boss-encounter.md)：区分房间生成、入场刷怪、封门与完成状态。

- 随机地牢战斗房的运行时刷怪（目录驱动池、落点闸门管线、休眠/唤醒配方、警报传播、清房不重生、封门精英房、生成器三段式挂接与覆盖批次纪律）读取 [地牢刷怪导演模式](references/dungeon-spawn-director.md)。休眠与导航 best-fit 风险按该参考执行，不在怪物类内私加第二套调度。

- **F6 测试入口（用户要求，2026-09-20）**：新怪物完成游戏接入时，同步加入交互开发面板的“怪物生成”目录，使用户能够选择并实际生成该怪物。FPSGAME 的目录和生成入口位于 `Source/FPSGAME/Development/DevelopmentSpawnComponent.cpp`；名称、稳定 ID、实际角色类路径、占地半径与资源导入一起完成，复用现有数量、距离、导航落点和清除逻辑。不能只增加一个指向缺失类/资源的菜单项；交付说明 F6 操作入口及仍未完成的机制。此要求是开发接入，不授权自动启动 PIE 或测试。
- **导航规格随 F6 接入一起完成**：新怪物的胶囊、移动组件 NavAgent、项目 SupportedAgents、目标地图导航数据必须使用相容的尺寸；新增规格追加到列表，不改变旧规格索引对应的 Bounds Mask。UE 的 `FNavAgentProperties::IsEquivalent` 默认容差为 5 cm，接近的体型应共享足够大的规格或使用有明确间隔的独立规格；不能新建会被判重复的规格。采用额外通行净高时，显式保留移动组件配置并让 F6 使用同一来源，不能生成阶段用一套体型、寻路再用另一套。通过当前编辑器完成导航构建与地图保存，不绕过导航限制强行生成；构建不等于路径/实机测试，后者仍需用户明确要求。巫婆案例见工程 `Docs/Monsters/WitchMeshy.md`。
- 接入现有玩家受伤、伤害类型、防御、控制效果和击杀奖励接口；数值注明来源值与 UE 调整理由。以可配置属性维护生命、移速、范围、冷却、尸体与刷新时间。
- 业务状态覆盖待机、追击、返回、攻击、打断、死亡和布娃娃，动画状态按需求实现。攻击使用一个权威时间源，明确前摇、接触、收势、命中去重、范围、遮挡与转向；预警区域与实际判定一致。死亡取消所有后续攻击，奖励仅一次。
- 战斗时钟直接设置动画位置时，单改 RateScale 不会改变攻击节奏；统一时间缩放需同步接触窗口。状态过渡可用姿态快照与 Sequence Evaluator 混合，但不能只靠静止首尾相同解决任意行走相位硬切。移除或接入素材包专用伤害 Notify，避免与现有命中判定重复。
- 持续攻击显式定义首跳、间隔和末端是否包含；控制效果在到期、死亡及销毁时释放自己的输入锁和速度影响，避免 Tick 依赖环。
- Physics Asset 按主要承重骨配置刚体、约束和自碰撞；装饰手指不必逐个建刚体。死亡动画转物理时验证实际姿态交接、碰撞地形、有限速度、尸体接地及回收。`IsSimulatingPhysics` 为真不能证明布娃娃合格。
- 骨骼命中形体需同时符合实际近战和枪械的查询模式；只有简单胶囊时，复杂射线可能漏检。FPSGAME 按用户最新要求，在死亡片段约 60% 时同步该时刻姿态并开启物理，由布娃娃继续倒地；不要强制采样末帧或等待落地。地面残留物独立计时，扩散显示与伤害覆盖共用进度；详细实现与本例数值见 [Meshy 人形案例](references/meshy-humanoid.md)。
- 村庄生成点需检查地面、坡度、占地和玩家距离；接入追击/返回、单实例上限、失败重试、尸体回收后刷新。明确刷新计时起点；保存关卡并重新加载确认真实入口。局部避障不能报告为完整寻路。

## 5. 怪物行为模式开发

- 开发前读 [行为模式流程](references/monster-ai.md)，先定义触发条件、优先级、目标记忆、退出/打断和动作时序，再扩展当前 Behavior Tree。动画状态机只表现动作，不能并行决定追击和攻击。
- 从一个可验收的完整行为开始：感知目标 → 导航接近 → 技能前摇/接触/收势 → 恢复决策；加入受击、目标丢失、路径失败和死亡分支，再复用到其他怪物。多种行为不要求每个怪物复制一套树。
- 角色差异放在数值、技能选择与执行适配；新的移动形态先验证对应导航方式。当前地面 NavMesh 不能直接标记成飞行/攀爬 AI。
- 修改规则后同时验证实际武器入口、控制释放和已有怪物攻击合同；新增模式的验收独立记录，不能借用旧的 16/15/30 项通过数字。

## 6. 验收与交付

- 分别报告构建、导入、自动行为、实际画面和人工试玩结果。读取完成标记与失败列表；退出码为零或报告 complete 不等于全部通过。
- 运行验收按技能检查：真实武器命中、实际追击位移及接地、前摇无伤害、准时命中与去重、冷却、躲避、遮挡、打断、控制释放、死亡取消伤害、奖励一次、尸体可见且不穿地、回收与再次刷新。
- 使用隔离测试存档；测试夹具避免自动 AI 提前消耗待测技能冷却。发现夹具问题先修测试，不改玩法掩盖失败。
- 交付可编辑源、引擎导出、动作预览、动作/数值合同、来源记录、可重建脚本、正式资源引用和运行证据。失败明确保留，不将候选或编译成功标成完成接入。
- 个人技能与工程 `skills/ue5-monster-workflow` 同步。替换旧工作流不删除源模型、重建输入或游戏资产；退役规则及历史案例按项目要求归档。
