- 本次用户下载的 GLB 是静态外观母版，不含骨架；这不代表其他 Meshy 输入也无绑定。先分清可用蒙皮、错误蒙皮和纯外观壳，再决定骨架方案。

## 统一参考与真实动作导出

网格、动画、衣物代理和 Physics Asset 使用同一参考层级、骨名、骨长、单位及根变换。坐标换算只做一次：源米／厘米、FBX 单位转换和 UE Import Scale 应有明确分工。不能靠全局乘 100 或缩容器根修复错误参考矩阵、骨盆位移或局部骨变换。

M-07 曾出现“制作记录在动，游戏 T 字平移”：权重源保存为 Blender `REST`，动作作者继承该模式，FBX 烘焙了静止参考姿态。制作和导出前显式采用 `rig.data.pose_position = 'POSE'`，设置实际 Action／适用的 Action Slot、导出帧范围，排除仅供绑定的参考帧。循环、帧率、原地／root motion 与游戏合同一并记录；有关键帧不等于导出了运动。

角色站在原地也可能是导航速度为零，而非动画失败。按用户排查授权分清动画采样与真实移动；本例持久保存 `bForceRebuildOnLoad=true` 曾导致载图时长时间清空导航并重建，目标投影失败，速度驱动动作随之停住。导航制作、保存的 tiles 和运行追击是不同状态。

## 按真实解剖骨段求解，不沿显示骨尾猜轴

生成骨架的骨尾／局部 Y 轴不一定指向真实下一关节。髋—膝—踝、肩—肘—腕应以实际骨头位置及父链定义，而非骨名编号或骨尾方向。

- 股骨和胫骨独立做最短旋转，在参考膝弯方向相反时可能选到不同转轴，造成接近半圈的轴向翻转。两段使用同一个有符号膝铰链，平面随骨盆有限运输；肘链同理。保持原骨长、旋转连续性和可达范围，不能靠反向掰脚或无限转腕纠正轮廓。
- 肩、肘、腕和髋、膝、踝的蒙皮分别处理。沿真实骨段弧长、同侧连通表面和关节内外折面建立连续过渡，固定修改区边界；只按全局高度分带会跨到弯折的另一段。
- 金属腕箍可刚性随前臂，附近皮肤连续过渡；掌和五指保持各自解剖归属。组织折边不能误受腿骨覆盖，同位置的 UV 副本不能得到互相矛盾的权重。影响数和归一化按目标预算设置，不把本例上限变成通用要求。
- 重求局部权重时保留其他已采用区域；修改动作不必重导网格。源计算中的零扭转残差只说明制作矩阵，不证明引擎中极限姿态合格。

## 背膜尖刺先分清权重、代理和捕获

尖刺不一定是模型原有三角形。M-07 的来源包括共享折缝被后处理覆盖、膜边误绑腿骨、代理反法线／退化面、跨膜捕获以及更换三角形后沿用旧蒙皮贡献。

1. 共享折缝先统一权重，再沿原拓扑渐变进入各片骨链；真实身体附着边固定，不能让相邻模拟岛把共同根拉开。
2. 代理保留需要接触的有效组织表面，清理反向／退化折面；不因代理清理而删掉显示高模。显式片身份用于同片捕获，不能仅靠混合骨权重猜模拟岛。
3. 捕获同时拟合位置、法线和切线的法线棱柱，约束法线偏距、重心外推及局部法线一致性。数值不稳定时回退蒙皮，并沿表面连续混合；不要放宽为无界外推，也不要仅夹重心系数而破坏原位置。
4. 更换捕获三角形后，按最终三角形重新计算蒙皮贡献；肩根与失败区保留平滑过渡。UE 捕获过滤接口的三角形 ID 与索引数组偏移不是同一种编号。

多个膜片需要片间排斥时，可共享一个含多岛的粒子集合及对应显示捕获；六个独立衣物资产各自打开自碰撞，不等于建立了片间互碰。使用专用捕获类时，当前显示候选必须进入实际处理入口，不能因旧版本曾实现就假定新资产自动沿用。

## 手臂推组织：有界基础避让加近距布料

V12 扩大活动区、高密度代理和大量碰撞带来用户报告的严重卡顿。复用巫婆的分工，而非增加迭代来补缺失代理：显示层保留外形，低密度代理覆盖真实臂侧接触区，固定连接根；主要承重／接触形体用有限躯干和臂掌胶囊，避免逐个手指小刚体。

V18 在动画姿态上用每片少量探针与臂／掌线段求距离，仅旋转自由鳃骨；身体、双臂、腿和连接根仍按原动作。该六片案例最多 72 次距离比较，不做运行时整网格扫描或 CPU 蒙皮取样。基础避让同时驱动显示和代理，近处布料处理次级推挤，远处暂停模拟后仍保留骨骼避让；死亡／物理控制时让出骨骼驱动。

多层组织采用稀疏排斥、有界位移与低求解预算，减少重复碰撞。距离暂停应先渐退到蒙皮，再挂起模拟，恢复使用不同距离阈值形成迟滞；布料仍活动时维持相容的显示 LOD。具体距离、角度、点数和迭代数按角色设置。制作复杂度下降不是实测 FPS 提升，也不保证所有极端动作无穿模。

## 视频参考要保留整身轮廓和承重相位

先明确选中的角色、时间段和方向变体。M-07 采用用户视频 2:00–2:05 的前方中央 Jog；两侧是不同方向动作，不能当作同步侧视，更不能把两侧低伏姿态混成中央角色的持续深蹲。

参考核心是明显屈肘收爪、腰胯附近小回路、落脚后压重、支撑推起、后腿折膝收跟、摆腿经过身下，骨盆和胸肩反向配合，头相对稳定。仅保留脚抬起与对侧摆臂，或把源动作归一到少量零均值通道，会丢失整体平均姿态、轮廓和先后关系。

V20 为掌心朝后把肘过度放直，破坏了用户参考的屈肘轮廓。掌面由真实指根定义，左右镜像区分；朝向需求须放在肩、肘、前臂、腕共同可达的姿势中求解。前臂接近水平时，保持明显屈肘且腕部有界，未必能让掌心严格全程向后；保留参考轮廓和解剖范围，不用局部朝向压倒整臂。

原地动作的足底轨迹、源速度、AI 实速和播放倍率必须一起匹配。V19/V20 以源 270、AI 360 cm/s 播放时，把制作的约 1.33 秒周期加速成约 1 秒；只改局部姿态或 RateScale 无法保持参考节奏。V21 将源／游戏速度共同设为慢走 120、追击 210 cm/s，并重新制作支撑轨迹，属于本例可达腿长下的拟合选择，不是通用跑步速度或参考实测值。

视频重复帧估计的周期、单目观察的关节范围和像素比例，不能宣称为原始三维轨道、精确关节角或 UE 厘米。使用普通合法供体作基础再参考视频编排，应明确这是仿制候选，不是直接套用原付费动捕。

## 沉重步态：支撑先行，关节响应有先后

用户改要巨人／机器人式慢步时，重新编排支撑、重心和整身姿态，不把此前跑姿简单减速。V22 制作源是 `Tools/BlindSupplicantM07/author_heavy_gait_v22.py`，接入与保存边界见工程 `Docs/Monsters/BlindSupplicantM07HeavyGaitV22.md`；本版待用户体验，不能作为已认可动作模板。

- 先定义左右接触、双脚承重、足底压实、脚跟抬起及摆腿回收，再驱动骨盆侧移、落脚压重与恢复。支撑足的局部后移速度与实际游戏前进速度配套，不能让骨盆摆动拖走支撑足。
- 旋转支点随脚跟／前脚掌接触切换，脚趾与脚背分工；摆动轨迹在离地和落地处与支撑速度连续。必要可达修正只落在骨盆及其后代，不移动原地动画的容器根。
- 以同一接触时钟让骨盆先行、五段脊柱传递、胸肩反向配合、肩胛带臂、肘腕和自由背膜稍后回落。滞后用秒定义，头颈降低被动摆动；不要给每个关节叠无关的周期曲线。
- 本例慢走／追击为 3.2／2.4 秒，制作与游戏速度 42／86 cm/s，每脚支撑 68%、全周期双脚支撑 36%。这是原体型的制作参数，不是通用机器人标准。速度差还需与现有动作选择迟滞相容；只改两段动画引用时无需新增原生运行求解。

### V22 用户反馈：腿脚保留，掌心向内并随步摆臂

2026-10-03 用户提供截图并反馈脚腿基本没有问题，手部缺乏摆动、掌心向外。单帧截图用于理解掌面和轮廓，动态问题依据用户体验反馈；不把截图当作完整周期证据。V23 制作与实际接入状态见工程 `Docs/Monsters/BlindSupplicantM07InwardArmSwingV23.md`。

- “掌心朝内”是相对于身体中线的左右镜像方向，不是让左右手共同朝后。以前臂真实长轴和手腕／指根构成的掌面求解；不能直接改手骨某个欧拉角作为方向保证。
- 原始肘接近伸直时，直接使用两段骨向量的无符号叉积会给左右臂选择不同的解剖分支。先确定朝前屈肘的参考铰链并保留有符号参考屈曲，再用前臂旋转分担掌面方向；不改原骨架参考矩阵、不靠手腕翻转半圈。
- 以原步态的左右接触相位编排对侧摆臂，肩带先行、肘腕短暂跟随。保留腿脚时复制原 Action，只改锁骨及臂掌曲线，不重新烘写骨盆／腿脚／胸背原通道，不顺手调整移动速度。

## 近战时钟与真正出手时的提前量

V24 起，火球／冰柱的出手原点为真实掌骨世界位置加角色前向偏移；下文求解使用该共同原点，不能继续使用旧的无偏移掌骨位置。

横扫按蓄势、骨盆先行、胸肩跟随、快速横掠和收势制作；非攻击臂可以保留自然局部姿势，仅随躯干运动。攻击和恢复的臂掌姿态与待机衔接，不靠另一个静止首尾掩盖任意移动相位切换。

加快近战时，动画采样、接触窗口和全段持续时间使用同一倍率。本工程 Sequence Evaluator 由战斗时钟采样，单改资产 RateScale 不会加快权威时钟。低帧率越过短接触窗口时，采样真实窗口端点，保留每次攻击命中去重。

火球／冰柱在实际释放接触事件取得手掌世界位置、目标当前位置、完整速度及执行器弹速，求 `|R + Vt| = Speed * t`，使用射程内最早正根；无可达根则直接瞄准。采样发生在出手时，已过去的积蓄／推出时间不再重复计入。即时闪电取释放时目标位置，不虚构飞行时间。事件级恒速预测不新增追踪 Tick，不改变服务端伤害、碰撞、遮挡、打断或技能 CD 合同；目标转向仍可能避开。

## V24 施法联动与离身蓄积

用户随后反馈施法释放僵硬、蓄积火球／冰锥过近。V24 重制 Gather／Release：沉身与骨盆先行、胸肩跟进、肘引导手掌弧线、腕掌和手指稍后展开、右臂配重，接触后继续卸力再收手；两段各 1.10 秒，释放接触仍为 0.30 秒。共用蓄积终态，首尾接当前 V20 待机。延长恢复时让既有战斗时钟读取新片段全长，不只修改 RateScale。

需要前移蓄积中心时，不能只给掌骨附着一个固定局部位移：手腕翻转会把位移绕回身体。用实际掌骨世界位置加角色前向偏移，在现有骨骼最终变换回调中同步蓄积组件；冰系读取显式世界位置的 Niagara 参数也要同步。发射和提前量共用偏移后的同一原点，避免弹体回跳。回调随蓄积开始／结束注册／解除，不增加独立 Tick 或逐帧强制骨骼刷新。

本例只对怪物火球／冰锥前移 65 cm，闪电零偏移，不修改共享玩家特效。偏移量是本例制作参数，不是通用体型标准。实际状态见工程 `Docs/Monsters/BlindSupplicantM07FlowCastV24.md`，仍待用户体验。

## V25 前侧通道、表面避让与横扫
