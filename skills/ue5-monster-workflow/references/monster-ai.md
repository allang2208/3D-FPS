# Behavior Tree 怪物 AI 约定

用户于 2026-09-11 选定 Behavior Tree 统一怪物决策。正式实现和重建命令见工程 `Docs/MonsterAIWorkflow.md`。

## 从行为设计到接入

1. 先读当前控制器、Blackboard、执行组件、角色攻击时钟和源动画。写出行为表：模式名称、进入条件、目标/位置来源、优先级、退出条件、能否打断、冷却与失败处理。把期望看到的表现写成测试场景。
2. 区分感知输入与动作模式：视觉/听觉/受伤改变已知事实；追击、调查、攻击等由树选择。不能把“听见枪声”直接写成绕过控制和死亡判断的 MoveTo。
3. 为新模式选择最小扩展位置：新事实进入 Blackboard；组合规则放树分支/Decorator；短期动作放 Task；伤害、控制和技能时序留在执行组件/角色。只有重复出现的差异才抽公共接口，不预建所有怪物体系。
4. 定义中断合同：死亡最高优先，受控中止移动及可打断攻击；技能结束、任务 Abort、目标失效均释放自己拥有的移动/动画/输入控制。不可打断攻击也必须允许死亡终止。恢复时重新评估事实，不固定退回 Idle。
5. 配置导航体型和目标接受距离，先用独立障碍场景验证有效路径、实际位移和阻挡；再放入村庄检查坡地、狭窄通道和返回位置。路径不可达时按本模式选择等待、重新规划或放弃目标，并验证不会持续顶墙。
6. 在现有怪物上完成一个完整循环，再接入第二种怪物检验复用。数值保留来源和单位；每次只改相关蓝图/实例/动画引用，保存回读后启动新游戏进程。
7. 验收覆盖正常循环与抢占：看到/听到目标、最后位置调查、目标消失、路径失败、前摇被击中、连续控制、恢复攻击、死亡取消伤害。对已实现范围记录通过/失败和实拍；尚未实现的巡逻、搜索或飞行分支列为后续工作。

行为表示例（设计模板，不代表所有分支已实现）：

| 模式 | 进入条件 | 退出与抢占 | 验收重点 |
|---|---|---|---|
| 追击/调查 | 有目标或最后已知位置 | 进入攻击范围、记忆过期、受控、死亡 | 绕障、到达后重新决策 |
| 攻击 | 距离/遮挡/冷却满足 | 技能完成、允许的打断、死亡 | 接触帧、去重、取消后不补伤害 |
| 受控 | 硬直或眩晕触发 | 到期或死亡 | 不播放 Idle、连续命中不缩短控制 |
| 返回 | 超过活动范围或丢失目标 | 抵达出生点或死亡 | 可达路径、恢复规则、重新感知 |

## 已验证的实现经验

- 行为树独占待机、追击、调查、返回和攻击选择。角色的攻击/受击枚举只记录执行阶段，不再从 Tick 自行追击或重置 Idle；不并行运行另一套 StateTree 决策。
- 共用 MonsterAIController、MonsterBTNodes、MonsterCombatComponent；当前组件通过明确的护士/手脑适配访问执行接口。新怪物扩展适配或抽取接口，不能宣称任意骨架自动通用。
- 控制与死亡优先于攻击和移动。受击取消尚未生效的伤害窗口，停止路径跟随，播放专用受击片段。结束后交回行为树重新判断，弱命中不得缩短未到期的眩晕。
- 攻击保持一个权威时钟和命中去重。动画不能成为第二个伤害定时源。保留已接受的接触时刻、嚎叫跳数和死亡布娃娃合同。
- AI Perception 处理视听；伤害入口同步记忆攻击者。只缓存事件会在目标清空后漏掉持续可见玩家，应从当前视觉感知缓存重新获取。
- 使用 NavMesh 路径跟随，按怪物体型配置 Supported Agents。生成 NavMeshBoundsVolume 时必须建立真实 UModel/Polys/BrushComponent；Build 返回 true 但 Brush 空时范围仍为零。读回非零范围，再验证路径及实际绕墙位移。
- 蓝图默认控制器正确不代表关卡实例正确：保存后分别读取 CDO、放置实例和运行中控制器、Behavior Tree 引用。
- 受击骨骼轴不能假设 local X 就是后仰轴；先查看参考姿态，将模型空间的目标旋转轴转换到每根骨骼空间，再验证导入片段和游戏画面。
- 使用隔离角色档案和怪物夹具。近战预期扣血遵循当前防御规则，复活校验当前 MaxHealth；不要以过期固定值误判 AI，也不要直接移除失败断言。
- 新怪物至少验证真实枪击、控制期限、恢复追击、有效绕墙路径、攻击去重/躲避/打断、死亡和回收。记录实际运行报告日期；历史通过不替代本次回归。

本次基础树未涵盖巡逻、多点搜索、掩体/EQS、飞行或联机验收；后续行为应在同一决策入口下扩展。
