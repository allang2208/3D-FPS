# 守寝者：重定向失败经验与恢复边界

适用：已有智能绑骨、不对称巨臂的人形怪物出现僵硬、鞠躬、肢体不同步或脚底打滑。守寝者 V18 于 2026-10-17 被用户再次否定，已转待办；以下是定位经验，不是已认可动画模板。用户没有要求继续时，不因读取本文启动重做、测试或验收。

## 先定位动作在哪一层失真

用户要求排查时，分开观察源动作、UE 原生重定向、体型后处理、保存后的 RAW/压缩姿态、游戏中真实移动。只看作者数据或数值阈值，不能证明最终动作自然。守寝者 V18 的离线支撑/骨长/压缩检查通过后，用户仍判定不合格。

- 根据实际父链与参考姿态匹配骨段，不靠 Bone 编号猜解剖；保留用户智能绑骨和原始蒙皮。该模型不能直接套用 Meshy 预设动画，不能因此强制换骨架。
- 有 IK Rig / Retargeter 资产不代表有有效脚底约束。此例 RunIKRig 的 chains 为空，实际只是 FK 骨链迁移。
- 对比整条肩背—锁骨—手臂—骨盆链的相位。V17 逐根替换七根上身骨的平均姿态，又给巨臂独立延时，肩胯转动从原生约 22.48° 缩到 12.33°。修正静态朝向时保留周期变化，避免分段修姿切断联动；这不是禁止所有局部修正。
- 平均移速与片段时长对应，只解决时钟尺度。支撑期仍要看真实蒙皮足底、前后滑移、膝面、骨长与骨盆移重；踝关节高度不等于脚底高度。直线离线重放不覆盖转弯、起停、斜坡或游戏中的速度变化。
- 左手尖刺曾来自 26 个手指顶点误受左大腿权重影响，不能靠换动作解决。先区分拓扑/蒙皮与动画问题，保留原坐标、面、UV 和绑定，只修实证错误权重。

## UE 5.8 的平台重采样陷阱

此例作者数据与 Controller 设置为 60 Hz，新建 AnimSequence 的 `platform_target_frame_rate.default` 仍为 30 Hz。保存后偶数帧接近正确、奇数帧偏离；仅更换压缩器不能补回被重采样丢失的键。

```python
clip.get_editor_property('platform_target_frame_rate').set_editor_property(
    'default', unreal.FrameRate(60, 1))
```

外层 struct 属性只读，应修改嵌套 default。按片段实际作者采样率设置，不把 60 Hz 强制推广到所有资产。需要精确比较时，使用保存后重新加载的压缩姿态；发起新压缩缓存请求前先等待上一轮异步工作结束，避免重复 DDC 请求冲突。

守寝者曾为接地问题单独使用高精度骨压缩设置并禁止帧剥离。`AnimCompress_BitwiseCompressOnly` 可通过 `unreal.load_class(None, '/Script/Engine.AnimCompress_BitwiseCompressOnly')` 获取；本机默认编码为无量化平移与 Float96NoW 旋转，旧版格式枚举未直接暴露给 Python。这只是该片段的诊断/制作选择，不是全项目默认，也不能证明运动质量合格。

## 归档与继续工作的入口

- 当前断点为 V14 完整裸体/手指修复、V08 待机、V12 百目挥击、V18 被否定的行走；旧衣物不能重新接回角色。当前接入不代表用户认可。
- 先提取仍需要的输入再归档旧版本：V10 的完整皮肤/骨架提到 RecoveryInputs，V17 的源动作与原生重定向缓存保留，旧最终键仅作诊断对照。活动脚本不从 trash 读取。
- 查资产依赖闭包，并区分运行引用、作者输入和编辑器预览引用。此例 V07/V10 的旧网格仍被保留骨架/动作/重定向器当作预览依赖，所以不能按文件夹版本号整批删除；它们并未作为衣物装备。
- 编辑器在运行时先由互斥批次读取加载/未保存状态，不移动被加载或被保留资产引用的包；原路径、目标、字节数和 SHA-256 随归档保存。
- 公开配方不公开可还原 Epic 动作的密集键。GitHub 免费下载、可在游戏使用与可再分发原始资源分别判断；用户模型、Epic 资源和 100STYLE 各自保持来源边界。
