# 连续软体尸体：绑定与交接

用于非人形软体怪物死亡摊地、黑面、飞起、尖刺和附件拉丝的制作。当前用户指定方向为 M-14 V19；跨物种推广已后台保存，游戏表现仍由用户测试。此文记录制作机制，不将构建或用户选择方向写成视觉验收。

## 先区分驱动冲突与模型问题

- 活体模型和尸体使用独立网格、骨架与数据。致命伤时从实际姿势初始化代理，只让一个系统更新尸体；停止旧死亡动画、刚体、角色移动和击倒组件，不要用提高阻尼掩盖双重驱动。服务端与客户端复制死亡入口都要接入，仍保留原奖励、攻击清理和寿命。
- 金属、链条与组织若共享边或焊缝，应共同进入连续变形场。局部加硬边能维持结构，独立刚性附件加长拴接会把两套变换差异变成表面拉丝。M-14 的 V17/V18 独立金属驱动已被 V19 替代，不能作为新物种模板。
- 先读实际制作依赖再清旧版。V19 使用 V17 四面体输入、V18 变形法线材质及 V15 活体源；这些编号不是废案证据。

## 动态骨架和表面绑定

`FReferenceSkeletonModifier` 生命周期内新增骨骼时用 `GetRawBoneNum()` 取得追加序号；`GetNum()` 的派生缓存可能直到 modifier 析构才重建。曾把所有表面节点指到同一个 render bone，表现为死亡飞起、坍缩和黑面。修复须从未重绑的活体副本重建，不能在错误尸体网格上重复追加。

整张表面使用非负归一化四面体重心权重，焊缝重复顶点采用相同绑定。每个物种按自己的坐标和实际缩放制作代理；通用导出 `mesh_m` 不再套 M-14 的轴向约定。只处理明确的攻击替身重复面，例如手脑 `arm_mount` / `fan_mount`，不要按骨名猜测删除其他物种组织。

新增尸体只保留匹配新权重的 LOD。旧骨架权重的低 LOD 会在距离切换时破坏形体；要多级 LOD 必须逐级重绑。活体 LOD 不受影响。

## 接触、约束和光照

- 四面体体积等式约束与防翻转单边约束分别累计 lambda，不能共享累加器。接触投影以当前约束后位置处理，不能回写旧 sweep 命中点，否则邻接点会反复弹动。
- 软组织摊地使用无回弹接触、限制过度拉长和内部相对速度耗散。睡眠应依据实际接地与稳定，不能按固定时间冻结空中尸体。身体应在真实场景碰撞面上停止，不能用统一下沉偏移代替接触。
- 平移骨驱动能重建顶点位置，却不会自动旋转原切线。尸体材质从变形后的世界位置与 UV 导数重建切线框架，再应用原法线图；退化导数要回退，双面朝向只修正一次。保留材质参数、伤口随机值与 PBR，不用强制发光掩盖黑面。

## 通用接入与制作记录

`UMonsterCorpseRagdollComponent::TryStartSoftDeath` 读取活体网格上 `UMonsterSoftCorpseBinding` 的硬引用。死亡时不读外部制作文件、不生成密集绑定。当前求解器和数据类型保留 `M14` 名称以兼容已保存资产，已支持其他非人形。

`Tools/MonsterSoftCorpse/prepare_sources.py` → 外部 `author_cages.py` → `install_corpses.py`。实际保存尸体网格、骨架、数据、法线材质及活体元数据，脚本写好不等于接入。续跑用原始 `surface.bin`；源模型修改须建立新制作版本，避免导出已重绑尸体作为新源。巨手与小手共用实际源网格时可共用绑定。

复用共享尸体准入和死亡时钟，不增加活体持续软体 Tick。2026-10-05 的实现采用每代理不超过 700 点、120 Hz 子步每帧最多六步、每软体计 32 预算单位；这些是当前配置，不是性能测量结果。

嘴部弱点同时需要真实碰撞命中与统一判定入口。M-14 使用自身网格的 `maw` 及其后代，接入 `ColdSteelSkills::IsCriticalHit`，沿用共享伤害公式，避免再手动重复乘暴击倍率。

公开发布时保留原创脚本和 PositionBasedDynamics MIT 许可/来源；用户提供 Meshy 模型、PBR、密集权重、UE 包与回执留本机，未确认再分发权不放公开仓库。跨会话尚未发布的物种，只交付本轮接口补丁及前提说明，不把整套并行实现夹带发布。
