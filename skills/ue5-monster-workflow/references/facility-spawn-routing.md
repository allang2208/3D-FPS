# 设施区域刷怪的实际分派

用于新增主题遭遇或用户要求排查漏刷。资料读取和制作正常进行；运行采样只按用户授权。

- 先从当前保存目录确定路线/房间，再追踪 `DungeonRunSubsystem` → 区域绑定 → `FacilityHallEncounter::Configure` → 成员表/槽位 → `FindInitialSpawn` → `FindSpawn` → deferred spawn/FinishSpawning → 死亡目标 → 闸门与共享进度。旧文档、类名存在或“开始遭遇”日志不能证明实际刷出了完整组合。
- 建矩阵记录每间房的数量、普通/精英/首领品阶、触发条件、出生区域、失败阶段、重试、击杀开门条件。只审查代码会漏掉具体尺寸和场景碰撞导致的拒绝；须明确实际覆盖了哪些层次。
- 路线 `walk_mask` 与合法出生地面不是同一语义。生态区的螺柱/根冠在通行主路外；医疗螳螂在指定床位间。只给对应槽位/遭遇使用明确的作者地面，保留整个房间边界、地面支撑、导航规格、占位碰撞和失败重试，不能全局绕过这些约束。
- 胶囊查询的有效半高至少等于半径。缚群半径/半高均 225 cm，增加 3 cm 半径裕量后，旧的离地 3 cm 被吃光，导致自身地面阻挡出生。用查询形体实际半高加离地间隙定位，并保留真实场景构造后的碰撞判定。
- 闸门关闭会改变可通行区域；检查有封门的生产构造，而非只在空房放点。医疗、生态、货运、发电、焚化、生活区及终点分别记录，不借一个主题的成功代表其他区域。
- 生活区员工保留供体行为 tag，但 `StaffLivingEmployee` 跳过供体职业倍率，避免最终配置数值被乘两次。蓝图只设 MaxHealth，当前 Health 由权威初始化。
- 护士基类还包含螳螂和盲祷者；普通员工预热池和 Rank 覆盖必须按员工成员范围限制，不能把所有 `ANurseZombie` 子类降成普通怪。
- 开门条件、区域清空和击杀奖励分开。生活区按第三间盲祷者死亡开门，服务器发布同一个队伍目标；已有服务门复制是唯一姿态写入者，较慢的场景快照不能覆盖刚到达的门动画。

历史教训：首次静态排查遗漏了医疗第三房缚群的胶囊接地拒绝；后续隔离生产装配增加了真实构造碰撞、封闭边界和逐失败阶段记录。隔离夹具未运行地图 BeginPlay、实际追击及真实主客机，交付必须保留此边界。
