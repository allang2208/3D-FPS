# FPSGAME 性能开发约束

适用于 FPSGAME 的新功能、修改和资产接入，尤其是 HUD、角色属性、技能、装备、地牢、灯光与图标。性能在制作时处理；不要等用户发现掉帧才补缓存、更新频率和资源预算。只落实本次改动涉及的条款，不自动扩展为全项目审计。

2026-09-23 地牢案例：Trace 将周期性慢帧定位到 Slate 绘制期间的游戏 HUD NativeTick；组合优化完成后，用户反馈“帧数改善了”。这是用户体验反馈，尚无同条件复测数据，不能写出提升百分比或把全部收益归给某一个改动。

本参考不改变用户的执行约定：默认后台制作、必要构建与保存，不自行启动游戏、性能采集、测试、截图或验收。下面是实现约束，不是自动运行测试的授权。

## 1. 高频路径：先消除重复工作

- 新增 Tick、定时器、UMG 绑定或属性查询前，明确调用者、更新触发、单次工作量和实例数量。沿已有数据源与调度接入；避免同一 UI 更新里父函数和子函数重复刷新同一内容。FPSGAME 的 RefreshAmmo 已调用 RefreshQuickBar，不能再在外层补一次快捷栏刷新。
- 降为每 50 ms 调用，仍可能每次卡住几十毫秒。优先消除同步工作与重复解析，再按显示需要选择事件通知或定频更新；战斗时序、输入、冷却和施法接触时钟保持原合同。
- 热路径不要为读取几个字段反复反序列化同一份 Item.Data。复用 ColdSteelItemData::Read 和 CombatItemFormula::ReadOnly；缓存键覆盖完整 payload，以及参与合并的物品定义，按大小写精确匹配。不要只用实例 ID 或 Definition 当数据版本。
- 只读缓存必须有容量上限。FPSGAME 当前每个缓存为 128 项；这是现有参数，不是全项目统一配额。需要修改的 JSON 使用独立对象，不能修改缓存根对象或它指向的嵌套对象。字段缺失、解析失败和默认值行为保持一致。
- 优先缓存解析结果与稳定资源；最终属性仍使用当前装备、技能等级、临时状态和时间。若另外缓存派生数值，失效条件必须覆盖所有这些输入；背包 Generation 不能代替所有战斗状态版本。
- 上限、单一资源值等轻查询应提前返回，不先计算整套伤害／防御／暴击树。同一次刷新能复用的装备加成、属性快照只算一次。
- UI 数据变化后定向刷新相关条目，复用行控件和刷子；内容未变化不反复 SetText、SetMaterial 或重建控件树。图标就绪通知携带配方键，不触发整个背包重建。数据模型变化仍需正常布局和交互更新。
- 热路径不引入同步 LoadObject／磁盘读取、等待流送、FlushRenderingCommands、阻塞 GPU 回读或无限顶点遍历。资源提前异步请求，制作成本分阶段处理；UObject 和组件操作仍留在其要求的线程。初始化或离线作者流程的同步路径不要复用到运行时刷新。

源码入口（相对 FPSGAME.uproject）：Source/FPSGAME/UI/ColdSteelItemReadCache.*、ColdSteelHUDWidget.cpp、ColdSteelStatusModel.cpp、ColdSteelEnhancementSystem.cpp；Combat/CombatItemFormula.*、ColdSteelFormulaBonuses.cpp。

## 2. 地牢局部灯：新旧来源都接入调度

- 新增房间／模块／固定起始区灯时，同时定义所属区域、角色、阴影用途、距离与生命周期。灯多不等于必须全局关闭阴影；保留必要的近景主灯和遮挡。
- 复用 Source/FPSGAME/Dungeons/AuthoredDungeonLighting 的房间／门洞调度。已有关卡的 Point、Spot、Rect 灯也要覆盖，不能只处理带生成标签的灯。太阳和 SkyLight 不混入局部灯调度。
- 注册在生成／装配阶段完成，不为此每帧遍历全部 Actor。使用实际 cells 和连通关系，保留当前及相邻房间、门洞候选，并使用滞后和渐变，避免转身或过门突然灭灯。
- 为远处局部灯设合理的最大绘制距离和渐隐，尊重作者更严格的限制。保留原始强度、颜色及投影策略；重新生成、取消／清理或退出时，恢复被临时接管的旧灯状态。
- 当前实现限于独立运行；多人或额外视角接入需要明确所有视角的可见性策略，不能把单玩家视角裁剪直接变成全局权威状态。

## 3. 几何与导入：制作脚本不能把优化改回去

- 大面积重复地砖、栏杆、管线、房间装饰，按源几何密度 × 实例数量 × 覆盖范围决定制作方式。布尔切槽残留的大量碎片不应直接铺满地图；结合观察距离选择合理拓扑、材质细节、实例化及 LOD／Nanite。
- 对兼容的高面数刚体优先使用 Nanite；非 Nanite 对象保留合理 LOD。不能因为“有 Nanite”就忽视材质、实例、阴影、碰撞或光追回退几何成本。小网格、流体、薄透明面和变形对象按自身条件处理，不一刀切。
- 保留近景轮廓、真实缝隙、碰撞和交互。此批以显式切线与 100% 回退几何保护现有外观／碰撞；完整回退保留了成本，不把它描述成光追显存减半。以后改变回退比例需单独处理相应外观与碰撞影响。
- 制作回执只适合续接同一批次与资产版本；源文件重导或后续修改后，旧的 remaining=0 不能证明当前设置与构建数据仍有效。新制作应另存历史回执／备份并使用新批次记录，避免按旧名单跳过必要制作。
- 改资产时同步修改后续导入／重导脚本。不要在通用模板中硬编码 nanite.enabled=False 或强制仅 LOD0；派生新房间、楼梯和雕像时继承有效制作策略。
- 启用设置、构建 Nanite 数据、保存网格与依赖材质是不同步骤。必须完成实际制作与保存，并记录产物；只写脚本或只开复选框不算交付。Nanite 用途自动产生的材质修改也属于本批落盘内容；不连带保存归属不明的蓝图、地图。
- 静态附件克隆骨骼母材质时，按实际使用者设置 material usage。七通道接缝 UV 引发 GPUSkin 错误，应处理不适用的 skeletal／morph／cloth 用途；不要以删 UV、丢接缝或隐藏错误代替修复。

地牢生产入口是 Dungeons/AuthoredDungeonGenerator（复数目录），不要误用保留兼容引用的旧 Dungeon 生成器。房间合同见 [随机地牢](../../ue5-pcg-building/references/authored-dungeon-generation.md)。

## 4. 纹理与图标：预算、等待和失败都有限

- 区分纹理池超预算、光追几何预算与整卡显存耗尽。不要隐藏警告、把 PoolSize 设为 0（无限）或关闭流送来掩盖压力。
- 为 Lumen／RT、几何、渲染目标和编辑器保留显存余量。当前项目采用 PoolSizeVRAMPercentage=30 与 r.Streaming.PoolSize=-1，并保留显存限制；这些是当前 D3D12 项目策略，不是所有硬件的通用最佳值。新配置不要无意恢复固定 1000 MB 池或占满显存。
- 小尺寸动态图标只请求与最终捕获尺寸相符的 mip，不等待每一张 4K／8K 源贴图完全驻留，也不永久强制所有武器贴图驻留。IsFullyStreamedIn=false 不等于正在加载；optional mip 等条件可能令它持续为 false。
- 运行时资源加载、准备、渲染就绪与回读采用已有异步阶段。等待需要总尝试次数／单次时限、取消与清理，以及可用的目录图回退；资源等待年龄不能冒充 CPU 工作耗时。
- 当前图标以目标尺寸约两倍请求 mip、最长边不超过 2048；最多六次尝试，单次资源加载 20 秒、其余准备 10 秒。新增分支不能绕过这些预算或重新建立无限重试。更大交互预览和离线高质量导出按各自目标处理，不盲套背包图标阈值。
- 新武器／配方保留明确缓存键及目录 PNG 回退，配件变化能失效；缓存和资源引用有上限／释放时机。不要为生成图标修改玩家真实装备或存档。

具体装配与通知合同见 [运行时图标准备](../../ue5-ui-umg-slate/references/runtime-icon-pipeline.md)。

## 5. 定位与交付：使用真实证据

- 性能问题先确定 CPU／GPU／加载等待在哪条路径，再决定改变什么。Slate.WindowPaint 可以包含游戏 HUD NativeTick；不能只凭窗口名称把它归为编辑器外壳，也不能从显存／VSM 警告直接推导出整帧瓶颈。
- 保留 FPSGAME 已恢复的硬件光追、Lumen 和原有昼夜配光。不把再次全局移除光照当成默认优化动作；若确需改变光照方案，说明其视觉／配光成本并按用户授权处理。
- 用户要求采集或比较时，再在同地图、种子、机位、分辨率、画质、前台状态和运行模式下取得数据。掉出地图、黑屏、加载中、后台帧或不完整 trace 事件不混为稳定游戏样本。比较帧时间及 P95／慢帧比例，不只看 FPS 瞬时值。
- 父子 scope 不重复相加；Game／Draw／GPU 的并行时间不相加。源 LOD0 三角数 × 实例数不是实际绘制面数，灯光候选不等于实际 GPU pass。口径见 [帧预算统计](frame-budget-stat-semantics.md) 和 [性能面板归因](performance-panel-attribution.md)。
- 新增昂贵阶段沿用现有 CPU scope 与按需指标，避免为了观察性能又添加高频全场扫描、日志刷屏或全量 UI 刷新。
- 交付分别报告源码、构建产物、已保存资产、用户反馈和测量结果。用户说更流畅可以如实记录，不能换算成尚未测出的提升比例或承诺以后不会掉帧。没有测试授权就交由用户测试。
