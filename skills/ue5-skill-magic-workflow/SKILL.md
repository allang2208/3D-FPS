# UE5 技能与魔法开发

实际工程为 `D:/FPS3D/FPSGAME`。用户于 2026-09-14 确认火球左手 V3「基本达到预期」，指定本工作流为后续技能／魔法标准。此确认针对当前效果，不代表所有武器、联机或异常状态均经过回归。

默认完成必要制作、导出、导入、构建与接入后交由用户测试。仅在用户明确要求时运行检查、测试、预览或验收；发布时执行该次获授权的仓库检查。

## 1. 先确定现有入口和完整规则

冰锥或整组多枚投射物的迁移，先读 [冰锥与多枚投射物](references/ice-spike-migration.md)：源码全链、数量台阶、整组冷却／修炼、法杖联动及共享手势。2026-09-16 起冰锥与火球同口径：不再单独计算智力、总量比旧公式低约 30%、蓝耗随等级增长、基础冷却 12→8 秒；旧的「保留原版魔攻＋智力」条款作废，取数一律以当前 `skills.json` 为准。魔杖乘数接口 `wandSpellMultiplier` 已在火球公式预留。

- 原项目用于读取数值、触发条件、成长、修炼方式、动作意图和存档规则；不因迁移改掉技能身份。记录原单位到 UE 厘米的转换。
- 技能定义与每级效果、成本、伤害、经验和界面说明取同一数据入口；被动效果从当前等级派生，不在加载时反复叠加。
- 先列出主动／被动、解锁、等级上限、冷却起点、资源扣除时点、施法接触点、可打断阶段和动作占用。一个已展示但不能升级、保存或使用的卡片不算接入完成。
- 当前入口：`Content/ColdSteelData/skills.json`、`Source/FPSGAME/Skills/ColdSteelSkillRules.*`、`ColdSteelSkillModel.cpp`、`UI/ColdSteelStatusModel.*`。专项参数可独立 JSON，原生数值与面板共用计算结果。

## 2. 玩法、进度和快捷栏一起接入

- 技能组件管理玩家的请求、阶段和生命周期；投射物保留施法参数快照、飞行和命中表现；状态模型提交资源、冷却、修炼与存档。UI 发请求，不直接结算伤害或扣资源。
- 用户于 2026-09-15 指定：有指向的投射物魔法默认支持“实际直击要害必定暴击 + 随机暴击”，单次只结算一份暴击加成，范围波及目标不继承直击要害结果。开发此类魔法时读取 [投射物魔法暴击](references/projectile-magic-critical.md)，保留完整碰撞部位并接入共用暴击／修炼路径。
- 排队不扣费；动作实际开始后一次性提交成本。命中、击杀和多目标奖励按同一次事件合并，由同一状态入口提交经验和升级，再按现有策略持久化并通知界面。旧存档迁移补项，不重置已获得的技能。
- 明确死亡、退出、重载及未结束技能的资源／冷却处理。火球现有实现为本地单人；新需求涉及联机时另设计服务端权限，不能由现有本地实现推断支持复制。
- 冷钢技能列表、详情效果对照、修炼卡片和图标见 [UI 技能](../ue5-ui-umg-slate/SKILL.md)。拖动交换、技能／物品混放与 E 优先交互沿用项目快捷栏规则，不各写一套输入或持久化路径。
- 新技能图标使用当前冷钢风格并接入 `skills.json` 和图标恢复脚本；不要仅生成图片或悄悄回退旧项目图标。
- 火球图标按 2026-09-14 用户要求改为火红主体，保留银框与石墨暗底；当前图源为 `Skills/fireball_ember_red.png`。元素辨识优先调整主体颜色，冷却／缺资源等状态继续由原 UI 处理；具体配色遵循项目冷钢 UI 正式规则。

## 3. 按动作实际占用协调输入

- 左手施法只在实际凝聚、发射及收手阶段占用左手。近战、采集、换弹、装备、检视、ADS 等已经开始的冲突动作自然完成，再执行一次等待中的施法请求。
- 左手被装备长期占住时（双持手枪的副手，`AFPSGAMECharacter::IsLeftHandHeldForCast()`）不排队等待：请求直接拒绝，快捷槽提示「左手占用」闪烁＋上跳 3 秒后消失，中途转为双持的排队请求同样丢弃。只有会自行结束的冲突动作才排队。提示计时与曲线见 `FPSLeftHandNotice.h`，记录见 `Docs/Skills/left-hand-occupied-notice-20260916.md`。
- 投射物法术统一输入：点按发射；悬浮状态下长按绑定槽显示红色弹道预览（共用 `FPSMagicPreview`），松手才发射。凝聚期间的按下仍是原排队行为，菜单打开会清掉预览；释放分支必须校验该法术的 `IsAimPreviewActive()`，避免预览随投射物消失后仍触发一次施法。记录见 `Docs/Skills/magic-aim-preview-20260917.md`。
- 新增投射物法术时按 [法术弹道预览](references/trajectory-preview.md) 接入：输入契约、解析弹道预测与绘制坑（虚线节奏、勿叠暗色宽线、每帧 Flush）都在那一份里，不要另写一套。
- 施法期间阻止新的左手冲突动作；枪械可腰射，空仓自动换弹延迟到收手结束。移动、跳跃、滑铲和闪避沿用既有自由移动规则。
- 火球采用脱手悬浮：凝聚后手恢复正常动作；后续发射手势从当时的持握姿态进入，球体从当前悬浮位置发射，不重新拉回手上。其他魔法是否持续占手按其设计决定，不强制套用火球。
- 动作、发射接触和特效交接共享时钟；重定时同步业务接触点。收手从实际退出姿态和进度开始，不跳到最终姿态。

## 4. 动画与特效制作

- 动作前实际查看现有参考，读取时长、帧率、接触和左右手职责。自然节奏来自起势、加速、制动、收势与肩肘腕／手指先后，不只对两个姿态作同速插值。
- 制作施法手势或处理手臂变细时，读取 [施法与完整骨段](../ue5-fps-arms-animation/references/casting-arm-volume.md)，再修改现用左臂层；保持当前 Manny 网格、骨长、权重和右手职责。
- 特效资产选择、缓慢燃烧、按速度向后拖尾以及棋盘格修复见 [火球 VFX 制作经验](references/fireball-vfx.md)。先辨认现有资产的输入和依赖，再创建项目专用副本。
- 同步可编辑源、作者参数和引擎导出。火球游戏内使用程序化左臂层，源 FBX 作为继续编辑的交付；不要误称正在播放整副手臂 FBX。

## 5. 归档和交付

火球按用户要求调整后的伤害、范围、成长、消耗、冷却与修炼基线见 [火球数值优化](references/fireball-balance.md)。2026-09-15 已改为仅魔攻系数、蓝耗成长和 12→8 秒冷却；不要用旧迁移公式覆盖当前配置。

在项目根读取 `WORKFLOW.md` 第 4、5、8 节及 `Docs/AssetSetup.md`。只归档确认被替代且无有效调用的本次废案；生成链的中间输入、共享母版和当前源继续保留。按原路径、替代物、大小和 SHA-256 记录 `trash/<task>`，原地保留正式资产路径。

技能与参考文档同步个人目录和工程 `skills/` 镜像。公开 Git 只提交本次合法源码、配置、作者脚本及记录；Manny/Fab 二进制、完整源姿态、私人参考照和缓存保持本机。交付区分用户确认、历史构建、本轮检查和未测试范围。

当前实现与归档边界：项目 `Docs/Skills/fireball-left-hand-20260914.md`、`Docs/Skills/skills-magic-publication-20260914.md`；火球写实效果、要害暴击与冰锥后续整理见 `Docs/Skills/skills-magic-publication-20260915.md`。

## 快速进战（F 键主动技能，2026-09-17）

`quickCombat`：触发键 F（武器检视已让位到 L）。剑类走符文剑第四连击配重锤（`BeginQuickCombatStrike`，复用第四击节奏与单目标窄走廊）；单持手枪走程序化握把砸击（**用户否决，挂起待重做**，教训见 [手枪握把砸击尝试](../ue5-fps-arms-animation/references/pistol-grip-bash-attempt.md)）。命中 2m 单目标：伤害 25+5×等级+力量×(5+0.1×等级)，击退 1m、眩晕 (2.5+0.1×等级) 秒（怪物 `ReceiveStun`）；基础冷却 12s（预留-结束起跳合同）；修炼释放 +1、技能击杀 +15。数据入口 `skills.json:quickCombat`，动作参数 `QuickCombatPistolMotion.h`，案例与挂起原因 `Docs/Skills/quick-combat-placeholder-20260917.md`。
