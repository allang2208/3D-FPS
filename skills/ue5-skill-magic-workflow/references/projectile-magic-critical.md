# 指向性投射物魔法的要害与随机暴击

用户于 2026-09-15 指定：后续有明确飞行轨迹、能够直接击中目标部位的投射物魔法，默认同时支持真实要害触发和随机暴击。当前以火球接入作为实现入口。

## 结算规则

- 实际直击要害必定触发暴击；普通直击按施法暴击率减目标抗暴随机判定。目标抗暴只降低随机概率，不抵消要害触发，与当前武器规则一致。
- 最终判定是“直击要害 OR 随机暴击”，复用角色／技能已有暴击伤害加成。不要另外叠一层魔法要害倍率，也不要让同一击重复掷骰、叠加两次暴击或提交两份暴击经验。
- 要害依据实际碰撞结果的骨骼／明确命中区域，不能依据准星曾瞄到头部、爆心高度或离头部最近来推断。当前共用 `ColdSteelSkills::IsCriticalHit`，识别骨骼名包含 `head` 或等于 `cranium`（忽略大小写）；新怪物的其他要害需明确接入共享判定。
- 范围爆炸按目标去重。直击目标在同一集合内结算一次，保留直击无距离衰减；只有它能继承本次直击的要害结果。其他波及目标逐个随机判定，不继承直击暴击。
- 撞墙、射程终点空爆及没有有效要害部位的碰撞保持范围／普通随机判定。地面持续伤害等没有直接命中部位的效果不自动获得要害触发。

## 开发接入

1. 从投射物真实移动碰撞保留完整 `FHitResult`，直到技能结算；仅传 Actor 会丢掉骨骼信息。同步调用可借用 `const FHitResult*`，需要延迟结算时保存结果副本。
2. 使用会返回真实命中部位的碰撞通道和物理资产。现有怪物胶囊忽略 Visibility，骨骼网格阻挡 Visibility；没有部位信息时保留随机判定，不伪造命中骨骼。
3. 每个受伤目标分别建立 `CombatFormulaRuntime::MagicHit`，只有 `Target == DirectTarget && DirectWeakpoint` 时令 `bWeakpoint=true`。空爆无 DirectHit；AOE 遍历中不要复用上一个目标的要害标志。
4. 使用现有 `TGuardValue` 管理同步魔法上下文。承伤端将要害和随机结果合并，只应用一次暴击倍率，并通过 `CriticalResult` 返回实际判定。
5. 命中、击杀和暴击修炼沿用同一次奖励事务；显示文案同步说明直击要害、随机暴击和波及边界。参数快照继续取凝聚时的等级／属性，范围、成本和存档遵守各技能自己的规则。

## 当前入口

- `FPSFireballProjectile.cpp`：将实际 Hit 传入爆炸模型，保留碰撞骨骼。
- `ColdSteelFireballModel.cpp`：从 DirectHit 获取直击目标、要害结果；每个 AOE 目标创建自己的 MagicHit 并合并修炼。
- `CombatFormulaRuntime.h/.cpp`：共享 `MagicHit.bWeakpoint` 与单次暴击结算；默认 false，未接入的魔法继续沿用原规则。
- `ColdSteelSkillRules.cpp`：共用实际骨骼要害判定。
- `ColdSteelSkillPage.cpp` 与 `Content/ColdSteelData/skills.json`：火球、暴击详情及技能说明。

此条为开发标准，不代表运行测试通过。遵守全局规则：完成必要构建后交由用户测试；仅用户明确要求时运行要害／普通直击、波及、遮挡及修炼等测试。当前火球仍是本地单人实现。
