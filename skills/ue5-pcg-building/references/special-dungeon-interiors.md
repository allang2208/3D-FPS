# 特殊地牢房间：主体、布景与入池

用于已认可独立空间转为随机地牢模块，以及病区一类可破坏玻璃、可翻越家具和墙面标识。案例真源为 FPSGAME 的 `DungeonTransitStation20260928`、`DungeonIsolationWard20260929`；数值是案例配置，不是所有房间的固定标准。

## 主体到随机池

- 差异从平面、剖面、交通关系、视线和建筑用途产生。小幅尺寸/内装偏移未能满足用户差异化要求时，回到少量完整房型；不要靠批量近似配置补数量。
- 外部端口、实际净空与占位 cells 同步。扩大建筑时增加柱跨、墙段、灯位与台阶，门洞、轨距、台阶和贴图保持实物尺度。柱脚按门框外轮廓避让，不只比较中心点。
- 主体预览与随机入池是两阶段。按 [场景开发标准](scene-development-standard.md) 保存地图、GameMode 和出生点，默认交付控制台直达命令，不新增祭坛出征条目；用户明确要求打包预览时才添加临时烹饪项。用户确认且正式接入落盘后，同次收尾撤销临时地图、已有预览菜单/MapsToCook、专用 Actor/返回代码与安装入口，归档样板专属内容；保留生产共用配置、网格和运行组件。临时安装器不能被后续作者重建重新调用。
- 特殊房的候选资格按 run seed + module ID 只抽一次，最多数量与路线约束独立设置；候选比例不等于实际出现率。合法几何放不下可以跳过，不靠缩房或重复抽签强塞。
- 使用真实端口和可行走锚点接现有遭遇/铁闸，怪物不可出生在闭锁病室或轨道坑。只封旧外部入口时保留房间内部通道。用户认可主体不等于完成多种子、导航或战斗测试。
- 安装时从生成器现有 catalog 做增量合并，保存实际 ExternalActor 包与资产硬引用，再同步作者镜像；重建链末端保留新房扩展，不能用旧 catalog 覆盖。导入脚本存在不等于资产已保存。

## 门框和观察窗闪动

检查墙体、瓷砖、门框金属、胶条及端盖整个截面，不只移动相机侧横梁。优先连续闭合环形/U 形截面，避免多个盒体共面拼接；墙洞净空与外盖框剪裁分开处理。病区案例把砌体内缘埋入框后 5 mm、胶条端帽嵌入承托 3 mm。用当前精确源几何定位，不把 Nanite 导出回退几何误当原始边界。需要几何或画面检查时按用户授权范围执行。

## 独立门扇与可破坏玻璃

- 左右叶片分别实例化现有推门交互，共享静态门框；门扇铰链、阻挡/防夹、自动回关各自工作。把手安装到破碎后仍保留的金属竖梃上，碰撞跟随真实安装位置。
- 完整玻璃组件持有命中和阻挡状态；命中入口统一到 BreakHit/BreakInRadius。破碎当帧隐藏完整片、关闭碰撞、清除其贴花并抑制该次后置弹孔。射击、近战、工具、投射物、范围和目标技能各自实际入口接入；仅重写 TakeDamage 不能覆盖不走伤害函数的接触链路。
- 门/窗每片独立状态；门金属仍可交互和阻挡。破碎代理捕获受击时世界变换，脱离移动门扇；预制不规则碎片由 WPO 驱动，共享有界代理池，结束隐藏回收，避免每碎片 Actor/刚体。
- 装饰碎片没有查询碰撞，地面解析反弹不等于完整刚体。病区原创实现参考 NDD 的职责分离思想，未移植/启用 NDD 插件；不要误称插件集成或多人持久破坏。

## 有界随机布景

- 用模型实际渲染/碰撞包围盒和枢轴放置。随机 yaw、侧倒和倒置需要每姿态接地偏移及碰撞界，不能仅改欧拉角。网格放大要同步凸碰撞、姿态边界、净距和门扇活动区。
- 床、药车等可翻越物使用贴合的稳定简单碰撞和现有 traversal；输液架可无碰撞，但仍向同一个视觉占位表登记。共用墙距、开门扇区、主通道和相互净距；有限尝试，放不下少生成，不互相叠放。
- 模块运行 Actor deferred spawn，先配置再 FinishSpawning。结构和碰撞齐备后再一次性 Populate；生成器统一持有清理对象，失败回滚/换图不会留下旧家具或贴花。生产种子分出独立布景子流，避免改海报数量改变路线布局。
- 扫描血迹按原始长宽比、透明通道、法线方向和 ORM 色彩空间使用，密度/尺寸分别配置墙与地。贴花按可接收表面、法线、边界及遮挡限制落点；指定模块独有 receiver tag，防止贴到家具或邻房。已认可 scan 不因随机需求被重新换回程序色块；单张扫描的旋转/缩放不等于多形状素材池。
- 海报/门牌复用原图集网格，先读取真实朝向、枢轴和尺寸，挂在扣除门、窗、护栏和门闸的实墙矩形内。随机池无放回抽取，矩形相交拒绝，毫米/厘米级离墙防闪；唯一房号不足时用科室牌补位，不复用重复房号。出口、生物危害等按语义固定位置，不能把 X 光牌随机贴到无此功能房间。
- 展示件无交互需求时不添加 Tick、查询碰撞、导航影响、投影或可接收血贴花。故障灯罩与光函数共享 Time/Phase，避免灯罩亮暗与照明脱节；有限故障灯搭配稳定主路灯。

## 当前恢复边界

`build_pool_module.py` 生成结构、灯具、独立玻璃 Actor、家具和贴花配置，`WallArt/Scripts/author_layout.py` 追加受约束海报布局。`WardRoomAssembly`、`DungeonWallArt`、`WardBedScatter`、`DungeonBloodScatter`、`WardBreakableGlass` 为生产运行入口；临时测试专用 `WardWallArtSubject` 已退役。

保留作者 Blender/FBX、实际导入回执、来源与许可；发布脚本/配置/说明不等于公开第三方原件或可直接运行的完整项目。过时地图安装器、旧参数快照和被替代自动备份归档 `trash/<task>`，记录原路径/目标/大小/SHA256与替代物。用户游戏反馈、历史构建/保存、当前发布检查分别记录，默认不启动 UE 或自动验收。

## 机械细节、柜体变化和地面标识

- 铭牌和箱签优先把印刷 UV 放到实体牌的唯一正面，避免在底板上再加共面薄片。门框胶条、横梁、端帽也要按完整截面排除重合，单纯整体外移不一定消除内部闪动。
- 柜体变化按完整格槽/抽屉制作有限版本：满、半满、空格以及不同抽屉位置与开启量。内部背板、侧壁、滑轨和文件的实际位置随之变化，种子选择版本但不侵占主通道和门扇活动区。柜架和配电箱按最外侧背面贴墙，不能只按资产枢轴计算墙距。
- 管件需连续表面、正确绕序/法线、实际壁厚与端口连接。仅随镜头变化的缺面先区分背面剔除、LOD/Nanite 回退与剖面生成问题；不能直接用双面材质遮盖错误实体。手轮、液压缸、支架和吊钩按真实机械连接制作，近景保留倒角、转轴、锁扣和紧固件。
- 地面警戒线由可行走地面区域裁剪，扣除墙、基座、排水沟和楼梯口；端点、转角、线宽及轻微表面偏移统一配置。墙上告示牌要挂在栏杆可见侧，板厚和支架位置都避开横梁。
- Nanite 使用标记修正在母材质及作者导入脚本中同步落盘；不能只依赖编辑器临时自动修复。闪动或缺面不能一概归因于该标记。
- 统一翻越、浅柜顶部支撑与样板清理继续遵守 [场景开发标准](scene-development-standard.md)。本段是制作经验，不自动触发渲染或游戏测试。

## 多房主题样板

- 按用户指定的功能顺序设计整套主题；每间保留独立局部坐标、完整结构、端口与配置，同时制作连贯样板，便于用户体验相邻空间的节奏。不同用途通过平面、剖面与家具使用关系表达。
- 家具原型独立制作，部件和实例从同一作者配置派生；柜门、抽屉、座椅和壁挂件以使用朝向与实际承载面定位。更新摆放时同步可编辑源与已保存地图。
- 三间样板完成不等于新增生产路线。当前主题求解器要求三套核心；新增主题的抽选规则、遭遇和生产引用在用户确认后的接入阶段处理，不直接把第四套追加到现有固定三路配置。
- 本机案例：`SourceAssets/DungeonStaffLiving20261002`，制作记录 `Docs/Gameplay/dungeon-staff-living-theme-subject-20261002.md`。已后台导入保存，未进行运行或视觉验收；不据此触发后续自动测试。
