# 固定主题路线、错层连接与清房闸门

用于 FPSGAME 的主题组合、布局失败及「清怪后门仍不开」问题。几何规划、房间遭遇、推进闸门是三个职责；制作或构建成功不代表玩家通行已验收。用户未要求时不运行游戏或种子测试。

## 主题顺序与房池

- 先定义任务图，再做几何摆放。固定主题序列作为不可拆散的核心，基础设施过渡房只放在核心前后；双向搜索反转的是放置过程，不能反转玩家经过的主题顺序。
- 当前货运核心为货运转运间 → 货运仓库 → 地下车站；医疗核心为排水间 → 隔离病区 → 解剖教学剧场；处理核心为破损支护室 → 焚化处理厅 → 净化站。三路汇入唯一档案中心后连接 Boss。
- 每路前置 1–2 间、固定 3 间、后置 1–2 间；三路合计 15–21 间，另有公共前段 1–2 间、档案中心和 Boss，共 18–25 间主要房间。连接件、坡道及可选宝箱侧室另计。不要把每路数、全局房数和连接件数混报。
- 带专用闸门的货运房只通过货运主题槽位选中，从普通 `room_ids` 与过渡家族抽签中排除。主题配置允许固定槽位选中它，不能为了入主题又重新放回普通池。重建链的最后一步再次保留此限制。
- 通关条件是任意一条完整主题路线和档案中心均清除，不要求三路全清。公共前段也有遭遇，但不能把它误算成另一条待清支路。

## 搜索、错层和长度预算

- 房间是真实尺寸的刚体。二维闭合困难时允许整套主题核心换层，通过作者坡道在核心前后连接；不缩放房壳、破坏固定组合或跨过清怪闸门。
- 三维 `cells`、实际门位、相反端口朝向、宽高和可行走坡面共同决定合法性；平面投影重叠既不必然碰撞，也不必然安全。坡道本体、入口/出口接近段都计入占位和长度。
- 当前普通连接上限 12 m，主题平面闭合上限 24 m，坡道连接含接近段上限 46 m；这些是路径总长度，不是直线水平跨度。当前坡道高度档为 5.4 / 10.8 / 16.2 m，折返结构缩短水平占地。不要恢复已撤回的 60 m 平直兜底通道。
- 分支搜索必须允许回滚到末房的闭合候选。门口接缝、任务图、最终路线预算检查应位于完整候选的接受回调内；若三路刚闭合才发现预算失败，要继续搜索下一个合法候选，不能只报告整批失败。
- 总路线分成「房间和固定终点的作者步行估算」与「生成的连接距离」。改变每路房数或引入坡道后，不能仍用旧的固定全程上限拦截所有新布局；也不能只无限抬高全程上限。
- 当前逐路连接预算来自实际连接槽位，每槽 12 m；允许主题闭合的位置额外分配到 24 m，实际换层的核心前后连接分配到 46 m。全局通道总量上限仍独立执行。`authored_walk_cm` / `link_walk_cm` / `link_budget_cm` 随布局输出，估算步行距离不等于 NavMesh 实测。
- 搜索仍有统一时间和状态预算，失败保留原场景并允许取消。有限种子样本、某次重放或一次编译不能证明任意种子成功。

## 房间战斗锁与推进锁

- `DungeonSpawnDirector` 给所有具有怪物编成的非 Boss 战斗房建立 `DungeonRoomEncounter`；精英身份只控制编成和等级，不再决定是否封门。Boss 沿用自己的生命周期。
- 战斗门取自节点真实 `Doors`，入口估算只辅助触发。估算失败不应丢掉其他有效门，也不能以整房包围盒代替门洞净空。
- 玩家完整进入、胶囊离开门口安全区后锁定，再生成编成和播放落闸。全门洞 Pawn 阻挡立即启用，视觉门板随后运动；否则玩家或怪物会在动画空隙穿门。
- 封门后状态锁存：靠近门、离开触发盒或房间体积不能放行。完成条件同时检查存活数为零和待生成槽位为空；不能把第一批怪死完当成整房清除，也不能等待尸体销毁才清除。
- 全局怪物容量耗尽时，尚未开始且没有怪的新房暂不开战；已有部分编成的房保持封门并补齐余下槽位。失败生成继续走有界重试/放弃策略，不能靠超时删除真实活怪来开门。显式零怪房保持开放并登记完成。
- 死亡时可开门重试，但不登记清房、不销毁剩余怪物；重新进房再封门。当前单机规则不自动代表联机权威与多玩家防夹规则已实现。
- 房间清除只交给运行子系统登记。`DungeonProgressionGate` 读取该状态：普通推进口要求本房清除，档案出口还要求 `AnyThemedRouteCleared()`。战斗闸门与作者推进门不能分别维护互相矛盾的击杀计数。

## 定位「清怪了但门不开」

在用户授权排查时，沿 seed → 实际 node ID → route → 当前 room-clear → alive/pending → 对应门条件读取证据。视觉相同的房型可能出现多次，模块名不能替代节点身份。

- 若档案已清，先读取每条路尚未清除的节点；档案出口关闭可能是途中漏怪，不是档案怪物死亡事件丢失。
- 若槽位待生成，区分容量、导航/落点和旧距离/视线唤醒规则；入口遭遇负责完整编成，不让远处尚未出现的槽位无限占住清房条件。
- 若逻辑放行而仍有实体阻挡，分别定位动态门板、全门洞阻挡、作者封口板及连接件碰撞；不要同时盲目移动门或放宽全部条件。
- 等待原因只在状态变化或首次等待时记录，包含节点/路线/未清房信息；避免每个轮询 Tick 刷日志或全场 Actor 扫描。

## 分阶段装配的空实例组件

房间家具的 ISM 可能先创建、后填充。零实例组件不能作为物理状态创建失败的依据；家具填充后刷新其所属 Actor 的物理装配游标，并等待真正的异步碰撞完成。保留非空组件和真实碰撞的失败报告，不用跳过所有物理检查掩盖问题。
