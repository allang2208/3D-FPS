# 地牢墙体细节与稀疏渗水

适用于 FPSGAME 的墙面颗粒、剥落截面、霉斑和下垂水痕。先区分网格轮廓、主材质、实例覆盖和独立贴花，不能把所有“墙面粗糙”归为模型简面。

## 实际入口与重建

- 检查实际使用的网格槽、组件覆盖和实例父链，再确定发布入口。2026-09-24 主墙保留 `AtmosphereV2/Materials/M_Concrete` 身份，六个矿物入口由 `Tools/AssetPipeline/dungeon_wall_release.py` 指向新实例。仅制作候选，不会改变现有房间。
- 发布前保留旧材质备份；对照地图的旧组要显式绑定历史副本，否则替换共享入口后旧组也会升级。旧对照和恢复输入不是废案。
- 修改已保存资产时同步更新原导入脚本，避免之后重建恢复旧图。共享发布模块检查版本签名；发现签名变化应明确创建新修订，不能绕过保护覆盖未知改动。

## 颗粒、凹凸与图像来源

- 保留对应的颜色、法线、粗糙度/AO、高度通道配准和法线约定。扫描没有高度图时，不从颜色阴影伪造几何高度。
- 大尺度扫描与毫米级细粒分层；根据实际厘米尺寸设采样尺度。旋转房间与低质量 UV 的矿物截面用实例空间投影，法线转换与投影方向一致。
- 近景颗粒法线与浅层视差分别控制，保留距离/纹素衰减和步数上限。平面 POM 不改变轮廓与碰撞；纹理流送低 mip 也会损失细节，不宜通过无限提高法线强度补偿。
- 主墙入口可能同时服务水平面，修改时保留其原有分支。扫描原图、Fab 派生图和 uasset 的游戏使用许可不等于可单独公开分发。

## 稀疏污渍

- 先确认它是作者固定锚点还是运行时随机生成。固定锚点出现过多时，在成功装配后用独立种子流筛选，加入数量上限和近邻排斥；不消耗布局随机数、不在失败提交前改变旧场景。
- 保留作者指定位置与重力方向，形态变化限制在原投影盒内。不得复活作者已隐藏的旧层；再次生成时要能重新选择由算法隐藏的候选。
- 不用拉伸的混凝土噪声、高浓度黑绿色和圆形轮廓代替渗水。采用不规则湿源、收窄断续水道、吸水晕边和少量斑点，独立变化长度、宽度、镜像、浓度与粗糙度。
- 四种形态可以打包在一张 RGBA 遮罩，保留 alpha、线性采样、mip 和流送。采用 2 的幂尺寸，避开非幂次图导致的 mip/流送限制。
- UE 当前贴花 UV 使用局部 Z/Y；墙面下垂水痕按 `float2(UV.y, 1-UV.x)` 映射到水平/向下图像坐标，并结合实际投影朝向处理。只做颜色/粗糙度污渍时不写法线，避免覆盖原墙颗粒；限制投影深度以减少涂到邻近栏杆。
- 2026-09-24 项目实现：`AuthoredDungeonWallStains.inl`、`dungeon_wall_stains.py`，默认保留概率 0.32，近邻排斥 180cm。这是本项目参数，不是普遍标准；筛选覆盖已有三种墙面贴花锚点，不代表全场景新生成了随机污渍。

相关记录：工程 `Docs/Gameplay/dungeon-wall-material-release-20260924.md`、`dungeon-wall-stains-20260924.md`。本批完成导入、保存和必要构建，未运行游戏视觉验收；继续遵守默认不测试、不主动开编辑器的用户规则。

## 已认可样板向整站扩展

- 用户要求保留原墙地材质时，记录实际组件覆盖和网格槽，使用独立的浅表几何与颜色／粗糙度做旧层。新增表面明确关闭碰撞与导航影响，保留门窗、拱口和已认可样板的排除区域。
- 先按真实承接面制作板缝与墙裙厚度，再叠加磨损。板缝服从浇筑段、梁柱和施工尺度，大面使用错开的宽窄与高度；每小块都加同样缺口会在全景中形成明显重复。
- 做旧按成因分布。管线下方以断续渗水和局部剥落为主，墙脚以积灰与潮痕为主，主通道保留磨耗；每段墙用稳定独立种子控制宏观变化，法线和粗糙度继续与颜色配准。
- 墙裙浅色三角斑可能来自原网格的破损片和材质槽。先定位实际三角面与槽索引；Geometry Script 的截面索引与资产材质索引不能混用。整体复制／删面后若原已认可区域变化，退回原网格，采用限深、稀疏且贴合破损边界的局部做旧层。不要直接覆盖共享母版。
- 2026-11 货运车站采用 55 处饰面、三段墙裙局部做旧和两盏现有灯调整。这是该场景的制作结果，数量和灯光数值不作为其他房间标准。制作入口与本地资产恢复边界见工程 `Docs/Publication/FreightStation20261114/README.md`。

## 用户要求的固定机位对比

- 保存相机位置、完整旋转、FOV、分辨率与后处理。基线和修改后使用同一组参数，拼图保持原像素亮度，明确标注 UE 实景；截图亮度不能直接反推 PBR albedo。
- 暗部细节不可读时，按[照明层次标准](fixture-lighting-standard.md)先判断衰减范围、遮挡与灯色，再调整对应灯具。保留接触阴影和距离调度，局部参数变化不通过全局曝光补偿。
- 后台截图可使用隔离地图副本和 `UnrealEditor-Cmd -AllowCommandletRendering -RenderOffscreen`。宿主需要完整资源依赖；删减内容目录可能使金属和道具失去材质。隔离地图不等于隔离其联接的 Content，写入限于本次资产目录。
- 本机 UE 5.8 commandlet 若在启动时自动触发 SDK 检查，可沿用制作启动器中的 `UE_SKIP_UBT_SDK_SETUP=1`。等待自身进程完成并取得地图保存／截图回执；启动成功本身不表示已经落盘。
- 发布隔离副本前对照起始地图散列，遇到生产地图变化时增量合并。归档宿主时只移动联接对象，记录其目标；原图与对比图按用户要求归档，保留固定机位参数和最终保存回执。
