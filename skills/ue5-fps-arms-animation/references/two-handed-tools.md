# 双手采集工具：握持、举顶与沉重命中

用于 FPSGAME 伐木斧和矿镐的双手待机、装备、奔跑、攻击及停帧。旧 [单手工具动作](single-hand-tools.md) 保留迁移来源；当前双手工具不应再导回旧单手 Equip / Swing。装备、伤害和采集查询见 [采集工具战斗接入](../../ue5-weapon-workflow/references/harvesting-tools.md)。默认不额外运行测试或预览。

## 先确定当前动作家族

- 从 `production_tools.json` 和最终导入脚本定位每条动作的实际来源；同一工具的 Idle、Equip 与 Swing / HitRecover 可能来自不同修正阶段。
- 修手指只替换必要的局部旋转轨道；修肩肘则保留工具轨迹、握点和手指。每次派生从最新有效源出发，避免重跑旧生成器覆盖已修正的拇指或停顿。
- 改待机握姿时同步装备、攻击起止姿态与奔跑基准。双手奔跑可采样同一待机，再围绕双手握点中点叠加整体步态；不要让左右手分别漂移。

## 抬举与关节

工具与双手以固定的工具局部握点作为接触约束，肩、肘和前臂负责提供自然可达的支撑。

- “举过头顶”须同时定义镐柄方向和镐头位置。矿镐案例的蓄满长柄接近视线平行；仅抬高双腕、保留低举角度，会留下明显的直角屈肘。
- 左右臂从各自身体侧方伸出，分别选择肘平面。顶举时左支撑臂可自然伸展，肩点按动作抬升与前送；不要把肘一直钉在待机位置，也不要用延长骨骼补偿不可达握点。
- 用肘—腕连线、掌面方向和 rest 关系求完整前臂框架，上臂沿肘部弯曲协调轴向。辅助骨保留所属骨段的完整 rest-local 关系；该 Manny 视模不能只把主骨旋转、twist 骨仍留在旧框架中。
- 先连续展开旋转角并统一四元数符号，再做时间插值。跨过 ±180° 的 roll 或肘平面切换不应突然翻转。
- 大幅挥击需要整臂求解；小幅命中撬动可在固定接触姿态上，对双手和工具整体绕握持中心旋转，避免为几度摆动再次扭腕。

## 起势、命中与回收共用一只时钟

1. 区分较慢蓄势、短暂加载、快速下砸、接触制动、撬动、拔出和回收。不能用均匀线性速度走完整条轨迹。
2. 伤害/采集只在接触时结算一次。资源提交成功或敌人伤害确认后才进入命中分支；挥空继续随势挥过。
3. `HitRecover` 首帧必须等于 `Swing` 的接触姿态。先保持它，再撬动和抽回；不要一命中就反向抽走。
4. 源动画时间、游戏动作时间分开映射。延长停帧时同步动作结束时间和镜头采样；只对整条源片段减速会把下砸和拔出也拖慢。
5. 在角色合成镜头之前推进接触状态，手臂与镜头读取同一 age。低帧率跨过接触时将确认命中的 age 从零开始，防止跳过第一帧冲击。
6. 实际命中查询使用稳定眼位与控制朝向，避免镜头冲击改变下一次命中射线。停帧只冻结工具姿态，不用全局时间膨胀。

该用户要求镜头采用**单次沉重大幅下顿，再平滑回正**，不使用高频噪声或反复弹簧震荡。工具可小幅上下撬动，镜头不必跟着每次撬动；拔出时也无需追加第二次大冲击。

## 用户反馈“没有效果”时

先区分代码缺分支、命中未确认和实际进程仍在跑旧版本。此案例的怪物分支已接入，但编辑器重启后仅加载早于改动的正式 DLL；上一进程 Live Coding 成功不代表新进程含有补丁。

在获准排查时，对照当前进程启动时间、已加载模块、正式 DLL 和热更新记录，不凭“编译成功”认定游戏已经生效。需要重启后持久生效时按 [构建选择规则](../../ue5-auto-assistant/references/editor-open-development.md) 完成常规 Editor 目标构建。本案例于 2026-09-20 07:41 完成正式构建；构建结果与实机测试结果分别报告。
