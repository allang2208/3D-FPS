# 双持手枪、连续奔跑与左轮退壳

适用于当前 UE FPSGAME 的 Manny 手臂。用户未明确要求时，不执行测试、预览或验收；必要制作、导入和构建照常完成。最新运行资源必须以 C++ 加载路径为准，不能只凭版本号判定是否在用。

## 双持握姿与准星

- 先确定每只手相对枪柄的固定接触，再安排肩、肘、腕。调整取景或枪口方向时，枪与持枪手作为整体变换；前臂及辅助骨共同求解，不能把枪单独转向准星。
- 枪管真实前后点决定枪口轴，展示骨和枪根的局部前轴不一定等于枪管轴。作者坐标到相机坐标的映射须明确，视觉归中不能代替枪口方向。
- 当前 NaturalAimV3 使用 12 m 基准汇聚，运行时限制整臂动态汇聚幅度；这些是本项目参数，不是各枪通用数值。单持 ADS 与双持无 ADS 是独立合同。
- 双持输入为左右鼠标分别开火，左右实例分别保存弹药、弹壳、改造和动作时钟。动画修正不能改变这套装备/库存合同。

## 奔跑连续性

- 先区分“枪械摆动短暂停顿”和整体帧率问题。前者应关注动作导数与相位，不直接增加全局混合或修改画质。
- 每段关键帧均使用零速度 ease，容易形成反复起步/停步。循环摆动可用少量周期谐波表达主行程，使位置、速度和加速度在循环边界连续；冲击/落脚只作小幅叠加。
- 源动作一秒表示完整左右步周期，运行相位来自累计移动距离及已有脚步合同。退出/重新进入奔跑时保留连续相位，以独立权重平滑收放；不要因为翻越、占用动作或停跑直接重置到不同步相位。
- 保持两手错相、左右差异及不同枪型的惯性。起停混合处理权重，循环曲线处理持续运动，二者不能互相替代。

## 左轮双持甩仓

- 甩腕使用固定机械源时钟，不能按整个换弹长度归一化：装一发与装六发的总时长不同，但开仓仍须发生在主甩过程中。
- 本项目 V6 为反向预摆 → 向外主甩 → 回弹收稳 → 下移。右手向屏幕右外侧甩，左手向左外侧甩；机械弹仓的开合轴保持原枪结构，不能镜像整把枪来制造左手。
- 当前 `cv(x,y,z)=(-y,-x,z)` 将相机右映射为 Blender -X；侧倾符号按该变换推导。不要跨坐标系直接复制正负号。
- 空仓和速装器在可见退壳完成后下移，有余弹分支可更早下移；保留子弹、弹壳、速装器与音效事件的共同时间映射。

## 单持按压与自然腕肘

- 参考动作提供指节和腕肘关系，不等于提供了与目标枪一致的退壳接触。先分清 donor 是否真的有对应动作，再按本枪接触部件适配。
- 固定掌面法线正对杆轴会限制避让自由度。允许有限掌面倾斜、选择真实掌面接触点，再联合调整肩肘腕；避免只扭腕骨、缩手、改骨长或任意扭掌骨追接触。
- 稀疏掌心点、指尖和单个峰值帧会漏掉拇指根、虎口、手背和中间路径。制作拟合要考虑变形后的手套表面、各机械部件及接近/按压/轴向退出，不能只优化平均接触距离。
- 撤手先取得轴向间隙，再从外侧进入取弹。已经脱离的左手使用独立视模空间轨迹，不继续乘右手甩枪变换。
- 参考前臂姿态不自动等于目标接触下的中立腕。骨架轴线弯折、前臂轴向旋转、肘部弯曲平面分别处理；当前 Manny 的完整骨段辅助骨方法见 [施法与完整骨段](casting-arm-volume.md)。
- 几何误差或间隙是制作约束，不是人体工学证明，也不能证明整段动作绝无穿模。用户未授权验收时，如实交付待用户测试，不能把新候选写成已接受标准。

## GitHub 源与废案依赖

- `ZenXChaos/ThirdPersonShooter-AnimationSets` 的 `RevolverReloadInit` 可作参考，记录提交、许可、帧范围和实际采用部分。本例原始 FBX 有蒙皮顶点但无面索引；点云/骨段学习图不能称为完整网格渲染，也不能把缺面直接归咎于格式转换。
- 把已否定目录放入 trash 前，先提取仍在使用的库函数、导入器和合法来源记录到当前作者目录。新版本不得依赖 trash，也不要保留“执行旧废案脚本前半段”的隐式运行依赖。
- 旧输出与仍有效的作者输入分别判断。当前 LeftRecovery、Upgrade、初始双持网格恢复输入等仍被消费，不能因日期旧就一起归档。
