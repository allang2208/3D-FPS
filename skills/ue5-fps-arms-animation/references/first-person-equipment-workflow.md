# 第一人称手套与衣物标准工作流

适用于 FPSGAME 新增或修改第一人称手套、衣袖及其装备外观。2026-09-25 制定；工程根为 `D:/FPS3D/FPSGAME`，下述工程路径均相对该根目录。制作基准见 [认可的 V7 裸手](accepted-bare-hands.md)，旧材质分区案例仅按需读 [手部装备材质](hand-equipment-appearance.md)。

## 固定合同

- **以已认可的 V7 裸手、裸臂开发动画，基础视模直接使用裸手。** 保留掌形、指腹接触、腕部收缩和腕臂线条。装备适配身体，不为一件装备改全局裸手母版或恢复默认手套。
- **同一外观母版，按各原生骨架生成装备网格，复用已有动画。** 保留每个 profile 的骨架层级、骨长、局部轴、参考姿态及动作时序；统一外观不等于统一绑定矩阵。
- 新衣物默认不产生整套新动画。原版战术手套保留为独立恢复装备；历史原手模用于取原生绑定，不是新的可见制作基准。
- 默认后台制作、导入和保存。不自动启动 UE、游戏、预览或测试；只有用户明确要求时做相应检查与验收。按实际完成状态区分作者源、已保存资产、配置接入及运行表现。

## 1. 确定装备类型和覆盖范围

先读取本次相关的 `Content/ColdSteelData/modular_outfits.json`、`Source/FPSGAME/Characters/FPSModularOutfitComponent.cpp` 和目标 profile 作者源，沿用其当前合同。只改授权的物品与资产。

| 类型 | 制作内容 | 动画处理 |
| --- | --- | --- |
| 同版型换色、换皮纹 | 共享网格，新增材质实例与物品配置 | 复用 |
| 薄皮／贴身布手套 | 按 V7 拟合外形、权重和腕口 | 复用 |
| 厚衬垫／护板手套 | 优先把体积放到手背，保留掌心、指腹和指缝操作空间 | 必要时按握持类别局部修正 |
| 贴身衣袖 | 肩肘腕轮廓、收口、厚度及覆盖边界 | 复用 |
| 宽松袖身／下摆 | 蒙皮外形；需要物理时另做模拟接入 | 身体动作复用，布料独立处理 |
| 改变操作方式的装备 | 如不可弯曲机械手，先定义新的操作合同 | 按实际需要建立专门动作家族 |

按“步枪握把、手枪握把、剑柄、工具柄”等接触类别组织必要的局部修正，不按装备 ID 复制全部动作。通用厚手套修正层尚未实现；不能把这个扩展方向写成现成能力。原生骨架派生网格增加，不代表动画套数增加。

购买、免费或自制模型都作为版型来源。记录来源与许可；“免费”不等于可公开再分发原文件。完整衣服可保留为第三人称作者源，再提取肩部至袖口制作第一人称版本；裁切后仍需适配 V7、封口、蒙皮及材质，不能直接把裁下的袖子当成完成接入。

## 2. 在标准身体上制作外形与蒙皮

共同表面母版为 `SourceAssets/ModularOutfit20260925/BarePalmV7/M4_original.json`；各原生参考姿态及权重为同目录 `Authored/<Profile>.json`。从当前基准生成可编辑装备源，保留母版。

**手套：**

- 保持掌心、指腹及虎口的接触包络。厚度主要分配到背侧；每根弯曲手指用自身局部方向控制厚度，不能用整只手的同一平面处理。
- 当前手部区包含手掌、手指及腕部过渡。装备要覆盖实际被隐藏的整个区域；开放指尖或半掌款需要相应覆盖分区，不能隐藏整只手后依靠装备补洞。
- 同拓扑优先按原顶点对应继承权重。腕口与身体共边时沿用一致位置和权重；有实体厚度的开口做内外层连接，并让厚度平滑过渡。
- 缝线、护板避开指缝与关节弯折。调整装备几何优先于改动已认可的抓握动作。

**衣袖：**

- 沿肩—肘—腕建立版型，按裸臂实际截面保留活动余量。收口位置以腕关节和裸露区边界定义，不按旧手套衣褶的位置猜测。
- 袖口与保留的皮肤／手套适量搭接，并平滑过渡权重，避免仅在参考姿态下边缘刚好接触。袖口内壁、端面和镜头可能露出的肩端应有明确几何。
- 保留已有内外层时，不再整体 Solidify。只焊接正在重建的局部接缝；肩部可能存在位置重合但拓扑独立的封口，不能全局按距离合并。
- 新拓扑的权重转移限制在对应侧和解剖区域内，用对应三角形的重心插值；不要全局最近顶点混入相邻手指、另一只手或躯干权重。保留原网格未重建区域的权重与面角法线。

当前薄皮手套约 0.15 mm 接触面／0.70 mm 背侧厚度；毛衣袖口约 3 mm 内侧余量、2 mm 厚度、6.5 mm 搭接。这些是本次款式的制作参数，不是所有新装备的固定尺寸。

## 3. 材质与细节

- 轮廓、开口、厚度和大褶皱由几何处理；皮纹、织纹、细缝线与毛孔由法线、粗糙度等材质细节处理。高度贴图或 WPO 不能修复错误蒙皮、断口和手套外形残留。
- 皮肤、皮革、布料分开处理散射与粗糙度。皮肤材质只作用于裸露区；布料和皮革不继承皮肤散射或旧护板法线。
- 保持纹理实际尺度、UV 岛边缘和镜像切线约定；按具体贴图的 OpenGL／DirectX 约定处理法线，不能按素材网站统一翻绿。
- 换色共享网格和材质父级。运行时需要独立参数时使用角色自己的材质实例，不修改全局共用材质。
- 当前装备组件把物品的一份材质覆盖到该部件的各材质槽。多材质装备应采用兼容的材质分区方案，或在授权范围内扩展组件合同，不能只增加网格材质槽便宣称支持。

## 4. 生成原生骨架派生与保存 UE 资产

先在共同母版上制作外观，再转换到每个实际使用的 profile。保留完整绑定变换、单位和参考姿态；ASH12、M16 等不同 rest pose 不能直接复制 M4 的静态顶点或绑定。双持按实际网格与骨骼侧别派生，不仅依据文件名的左右后缀。

优先复用项目的原生数据导入路线，避免不必要的 FBX 重绑往返。UE／Blender 坐标和单位转换只处理一次，镜像转换后的面序、法线不能再重复反转。记录网格源、骨架、材质与目标路径，并保存可编辑源及适合第一人称的 LOD。

当前制作脚本位于 `Tools/ModularOutfit/`：

| 阶段 | 手套 | 衣袖 |
| --- | --- | --- |
| 制作与骨架派生 | `author_fitted_field_gloves.py` | `author_fitted_sleeves.py` |
| 保存可编辑源 | `save_fitted_field_gloves_blends.py` | `save_fitted_sleeves_blends.py` |
| UE 导入、保存和配置接入 | `import_fitted_field_gloves.py` | `import_fitted_sleeves.py` |

上述脚本是现有款式实现；新增款式先调整其输入、输出和目标物品，不能直接重跑覆盖另一件装备。当前覆盖 20 个第一人称 profile，实际新增时按配置处理，不把 20 写成永久上限。

导入过程遇到拒绝三角形、保存失败等制作错误时停止发布对应配置，不继续保存缺面结果。先生成并保存全部目标资源，再更新本次物品引用；保留旧路径与每个资源的保存回执。仅有导入脚本或进程退出码不等于资产已落盘。

## 5. 装备接入与默认裸手

当前运行配置根节点为 `items`、`profiles`。物品通过 `slot`、`part`、`material`、`rig_meshes` 指定装备和原生骨架派生；新物品还需接入物品目录及现有装备流程。沿用已有物品 ID、库存和存档，不通过清空存档解决显示问题。

| 当前合同 | 含义 |
| --- | --- |
| `native_bare_arms=true` | 裸手已经写入基础视模，首次可见就应是裸手 |
| `native_bare_skin` | 对应 profile 的独立 V7 裸臂基底 |
| V7 区域 0／1／2 | 上臂／小臂／手部与腕部过渡 |
| `shirt_covers: [0,1]` | 当前长袖覆盖上臂与小臂 |
| `glove_covers: [2]` | 当前全手套覆盖手部与腕部过渡 |
| 手套槽 3、衣服槽 7 | 当前项目装备槽，沿用数据合同 |

这些区域编号只属于 V7 基底，不是所有原始武器网格的材质槽。原视模按 profile 的 `hide_source_materials` 处理；禁止套用 M4 槽号到所有枪械，也不隐藏骨骼来隐藏衣物。短袖、露指款需定义能保留裸露皮肤的覆盖方式，不能直接沿用整区隐藏。

当前 `FPSModularOutfitComponent` 通过 `SetLeaderPoseComponent(Source)` 读取源视模姿态，部件自身没有第二套动画状态机，且关闭组件 Tick。沿用现有加载完成后才隐藏对应源区域的交接；基础视模裸手化必须落到资源，不能先显示原手套再异步替换。

配置在 BeginPlay 读取，保存 JSON 不等于当前会话即时刷新。按后台规则交付，由用户下一次进入游戏查看；不自动启动游戏。当前 `ue_original_gloves` 的 `first_person_mode: source_arms` 恢复原版整套手臂、手套与袖子，是特例，会覆盖普通衣袖表现。

原生写入后，旧全局 `native_bare_hands_default=false` 不代表基础模型仍戴手套；以实际基础资源与 profile 的 `native_bare_arms` 为准。历史 `register_equipment.py`／`register_native_skin.py` 会重建早期配方，不能直接重跑覆盖 V7 默认、原手套恢复路径和新款式引用。新增装备精确更新自己的字段。

第一、第三人称共享装备身份和风格，分别使用其身体骨架与装备网格。后续联机同步装备 ID／必要外观参数和动作状态，不逐帧同步装备顶点。第一人称完成不代表 Body 网格适配或网络复制已完成。

## 6. 布料物理：适用边界和巫婆经验

**截至本次制作，玩家贴合毛衣及手套使用蒙皮跟随，没有接入巫婆 Chaos 布料。** 厚度、褶皱和布料材质均不等于物理模拟。状态记录见工程 `Docs/Characters/fitted-sleeves-cloth-state-20260925.md`。

紧手套与贴身收口保持稳定蒙皮。只有需要摆动的宽松袖身、披风或下摆才考虑模拟；模拟范围避开握点、腕口等接触关键区。若任务包含实际布料接入，完整处理：

1. 低密度模拟代理及显示网格映射，肩口、袖口等固定锚点和渐变活动距离。
2. 与当前身体及动作空间匹配的碰撞形体；限制不必要的自碰撞、子步和求解范围。
3. 与源骨骼姿态兼容的模拟更新路径、LOD、显隐停用和恢复重置／混合。当前关闭 Tick 的 follower 不能只挂 Cloth 资产便称为可运行。
4. 稳定的显示映射：巫婆案例中过大正负重心系数在静止时抵消、运动时爆开；需要在绑定／重建路径修复，不依赖一次性的缓存补丁，无法稳定映射的局部回到蒙皮。

巫婆实现见 `Source/FPSGAME/Monsters/WitchRebuiltAuthoring.cpp`、`WitchRebuiltClothingAsset.h`、`WitchRebuiltMonster.cpp`。其迭代次数、20／24 m 距离迟滞和混合时间是怪物案例参数，不能照搬到紧邻相机的第一人称衣物。没有用户要求的性能采样时，不承诺具体帧率或“零成本”。

## 7. 交付与可追溯记录

保留作者源、可编辑 Blend、已保存 UE 资产路径、修改的物品／profile 以及导入回执。配置改动只覆盖本次字段，保留并行编辑；个人 skill 与项目副本同步同一标准，不整体覆盖入口中的无关内容。

整理时先保留制作依赖：V7 仍读取 V3／V6 对应数据，衣袖的 `M4_shirt_before.json` 仍是输入，Body 仍使用旧 NativeSkin。仅把确认被替代且无活动依赖的文件按清单移入 trash；正式 Blend 存在的自动备份可归档。含第三方几何、权重或采样数据的 JSON 与二进制同样留本机，公开作者脚本、配置与方法。工程恢复边界见 `Docs/Characters/modular-outfit-publication-20260925.md`。
