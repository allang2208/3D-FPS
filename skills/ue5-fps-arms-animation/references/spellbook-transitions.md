# 魔法书握持、阅读与开合衔接

适用于 FPSGAME 魔法书从手持到悬浮阅读、再落掌回握的动作。2026-10-12 用户确认主体动作已大体合格，要求在 V29 的 1.12 秒总长内落实自然度细调。当前 V30 制作手指与指节错峰、低速握稳衔接、肩肘支撑弧线及独立合指压紧，保留原握点、方向和终点。作者入口为 `Focus/IntegratedV30/author_motion.py` 与 `save_editable.py`，运行姿态及可编辑源共用 `motion-settings.json`／`motion.json`。中途取消平滑引入合指曲线，原回程路径继续复用；编译状态见 `Docs/Weapons/spellbook-focus-v30-20261012.md` 和 V30 `delivery.json`。本轮未做游戏或视觉测试，V17 暂停记录和 V11 recover 不再是当前实现。

## 区分三个方向

侧握的书本挂点、手掌法线和展开后的阅读方向不是同一坐标约定。先固定已认可的待机与阅读终点，明确书脊轴、书口方向、印刷内容顶部和玩家视点，再设计过渡。用户说“竖直落下”描述的是路径；本例另有“书脊朝掌心、两侧合拢”的朝向约束，不能只凭世界 Z 轴推断。

V16 失败原因是将松手朝向固定为阅读朝向，导致页面倒置。V14/V15 则在已经存在的书本转向前又加入整臂翻掌，引入重复转向和腕臂变形。不能为消除一次转向而删除正确的阅读终点，也不能保持一套手臂翻转、再让书自动对齐另一套相反的终点。

## 接触与变换

握持段从最终手骨和固定 `BookInHand` 求书本变换，手与书作为同一组设计。释放/收回触发时捕获实际姿态，避免从硬编码起点跳变；封面和书页用自身铰链展开，不把局部开合误作整本书的额外翻转。

本例 V7 手骨包含 scale-100 导入基底，挂点以厘米制作：组合挂点前去掉手骨导入缩放，保持与日常 carry 的处理一致。之前的收书数倍放大来自变换中的缩放继承，不能通过缩小模型掩盖。

落掌、合指、恢复待机必须共享接触帧和握点关系。抓稳后书直接随手；不要再叠加独立相机空间插值，让书滞后穿过手指。掌向改变要由肩、肘、前臂共同支撑；本例辅助骨应保留完整原生局部变换，不给已滚转的父骨再叠加分数 twist。细节按[施法与完整骨段](casting-arm-volume.md)处理，不能把本例方法推广到不同权重设计的所有 rig。

## 时序与轻量实现

2026-10-12 移动入场修订：不要把进入时的走跑关节旋转差持续乘到翻掌动作上，也不能在收书倒放时重新引入旧步态快照。当前以完整局部姿态短暂混合到专注作者动作（源时间 0.24 秒交接完毕），完整收书接回当下持书姿态；中途取消平滑退出已有入场差量。稳定阅读只保留小幅整臂平移，不按移动速度另加掌向旋转。V30 作者姿态、手指、开合时长和书本接触继续复用；排查证据及构建状态见工程 `Docs/Weapons/spellbook-focus-movement-handoff-20261012.md`，本轮未运行游戏或视觉验收。

使用有明确接触事件的分段曲线，表现蓄势、释放、上浮减速、合书、加速落下、合指和回收；密集烘焙的线性采样可以保留非线性动作，不等于整段匀速。

当前为七张双面活动书页加两面固定内页，共 16 面；每张活动页八骨。Open/FlipPages 使用 PagesV1 已保存资产。施法翻页 ×2 应累积到连续页相位，不能直接乘绝对时间，否则开始和结束施法会跳页。页面方向只在每个 atlas 单元内转 UV，保留图像、骨架和动画。金光以一次创建的网格和材质参数驱动；此实现选择不代表性能实测。

## 受击与近战共用时钟

受击先快翻页，再在掌上方合拢，完全闭合后垂直落下，接触时直接交给正常回握轨迹。当前阶段为 0.30 秒翻页结束、0.49 秒闭合、0.51 秒开始落下、0.75 秒接住；这些是本例参数。若开书还未脱手，则从当前源时间正常回收，不虚构掉书。

拇指穿模不能只靠拉开整只手解决：当前 V3 先给页面让开空间，再抬接书手；拇指沿真实书脊轴在手掌父空间做避让，收势后逐渐退出，保留骨长。落掌前合指与书本闭合分别安排，实际表面接触仍需视觉验收。

魔法书推击保留原姿态，按阶段映射到空手 `StaffQuickCombatMotion`：总长约 0.551667 秒、接触约 0.171667 秒。第一人称、第三人称、命中、镜头反馈、诊断和可编辑 Blend 的时钟一起更新；不能只改播放速率而保留旧接触比。原作者时轴仍是 0.43／0.14 秒，诊断也必须走同一映射。

## 保留与恢复边界

Photo V3 侧握与低位小幅移动是独立基线，不因修专注动画而重做。V2 握点 JSON、V9 落掌 JSON 虽版本旧，仍被当前作者入口读取；保留源依赖和最新完整可编辑 Blend。被否定的路线和旧备份归档到 trash，并从活动作者入口解除引用。后台保存、构建、用户视觉认可分别记录；用户未要求时不新增预览或测试。
