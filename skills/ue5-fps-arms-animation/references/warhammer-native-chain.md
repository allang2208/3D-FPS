# 双手战锤：原生握柄、关节连续性与动作交接

适用于长柄双手武器的作者动画与第一人称接入。2026-10-14～15 战锤案例包含多次用户否定；以下是问题与制作方法，不表示所有最终动作已获视觉认可。按当前授权制作，只有用户要求时才运行诊断、渲染或实机测试。

## 保留接触关系再改变动作

- 从可用待机记录双掌到柄的局部矩阵、握距和原生指形。武器与两掌共同平移、转动，再解肩肘；仅旋转武器、仅移动手腕或靠拉长前臂追握点都会造成失真。
- 用户要求“向右下退出”包含整体平移，不能只改柄的朝向。降低视模时同时考虑肩口、上臂截面和手臂在近裁剪面前的覆盖；锤头出框不代表手臂末端已安全。
- 全程保持双手握柄的招式，入场混合也应约束两手相对柄。上挑、砸地、快速近战、格挡分别有自己的握姿和可及范围，不将某个腕部补偿无条件套到全家族。

## 肘极和轴向旋转不能跳解

- V2 三连击曾在收势时因越过半身边界而突然切换肘极，产生几十厘米肘位跳动。骨长误差很小、双掌仍在柄上，仍然是坏动画。连续肩肘路径与局部关节姿态必须一起处理。
- 掌腕方向由前臂整体承接，旋前/旋后沿该骨架的实际辅助骨与蒙皮位置分配；先展开轴向角，再分配扭转。只转手骨会在腕口形成折痕；只转前臂主骨会在辅助骨处挤压。
- 原生绑定坐标里的滚转不是人体中立姿态的关节角。不能把统一的欧拉角限幅（例如 ±85°）当作解剖约束；战锤修订中这种夹紧会被求解器转嫁为过大的肩位平移。
- 输出时保持四元数符号连续，按层级把目标世界姿态转换到父级局部姿态，保留原骨长与绑定。求解器修正需要随整个收势释放，不能在最后几帧突然归零。
- 用户要求退回正常版时，恢复明确的旧骨链与接触基线。被否定版本的重握/肘极解不作为“更先进”的隐式前置；不过“旧版”也不自动等于已接受版。

## 节奏、惯性与单一时钟

- 蓄势、快速出手、接触、惯性带出和回收用分段时间曲线；整套骨架同源重定时，手、柄、镜头、音效和接触不能各自使用不同的动作年龄。
- 单手惯性外甩需要明确左手松握、退出视野、右手继续带动、减速回握的阶段。惯性主要来自武器轨迹和承重链，不能仅延长原地旋转或末尾硬停。回握时恢复实际柄上接触再回待机。
- 快速近战曾出现“只扣体力、没有动画”。排查时同时看动作占用、实际时钟推进者和工具视模采样，不能只确认 clip 引用存在。当前战锤由摄像机更新前的工具路径推进一次，组件自身 Tick 不重复推进。
- 格挡进入途中松键可反向走当前进入轨迹，完整撑挡后才切专用退出；受击插入不能把已松键的退出切回保持。

## 本案例制作依赖

战锤作者根为 `SourceAssets/SteelWarhammer20261014/`。本次保留的源链包括：

- `NormalComboV4` 读取 `RhythmClearanceV2` 的原生骨链；`SprintDragV1/author_sprint.py` 仍提供烘焙函数。
- 上挑 `UppercutRightAnatomyV7` 读取 `UppercutTiltClearanceV6` 的 Blend 与表面数据；快速近战 `QuickCombatLeftWristV7` 读取 `QuickCombatReachV6`。
- `GuardV1` 使用 `NormalComboV4` 待机和 `WhirlwindHandoffV5` 的求解函数。V1 的 0.22 秒进入、0.30 秒受击、1.50 秒破防是该动作参数，不是家族通用标准。
- 普通攻击 V2/V3 已被否定。源版本号与 UE 资产目录号不是一回事：新上挑/旋风可导入旧名包，不能按目录号删除仍被运行时引用的资产。

归档前沿脚本读取、AST 函数提取、Blend 和采样数据逐层保留依赖；日志、Before 和旧作者源分别判定。详见工程 `Docs/Publication/WarhammerCombat20261015/README.md`。
