# 副手刀：剪辑镜像、手臂修正与装备/换弹衔接（2026-10-26）

来源：手枪＋副手尼泊尔弯刀（`Source/FPSGAME/Weapons/Kukri/OffhandKukri*`，记录 `Docs/Weapons/dual-pistol-kukri-idle-20261025.md`，作者源 `SourceAssets/DualPistolKukri20261025`）。按问题读取；不授权自动测试。

## 把一只手的剪辑镜像到另一只手

- **先查矩阵缩放。** 主手弯刀剪辑（`Kukri20261020/Clips/*.json`）的世界矩阵带导入的 ×100 缩放。缩放矩阵直接转四元数（`qfrommat`）会算错角度（实测手部朝向偏 39°），对缩放矩阵求逆再乘握点会把厘米偏移缩成 1/100（刀挂到手腕上）。旋转一律先按列归一化。
- **按绑定推导逐骨修正，不要凭经验翻轴。** 左右手的局部轴关系不是 `diag(−1,1,1)` 共轭（实测指节误差约 10 cm）。用锤子镜像同一规则：`fix = Rref(源骨)ᵀ · MX · Rref(目标骨)`，镜像帧 = `MX · R(源骨) · fix`（`author_upper.py: mframe`）。先核对两套骨架绑定局部是否一致、源剪辑是否左右对称，再用。
- **武器镜像**反射整帧及刀面法线（局部 Y），保留刃向（+X）和刀身（+Z）；武器挂点以运行时挂法为准（弯刀 `SM_Kukri` 以单位变换挂 `WPN_root`）。
- **验收指标**：镜像后刀身与源剪辑刀身的偏差（应为 0 cm / 0°）、指节位置误差（约 0.5 cm 级）、腕部屈伸/偏斜逐帧对照（左右约定下屈伸号取反）。有现成的同侧已认可挂点时交叉核对（本例左手正握挂点 (7.25, −2.26, 0.23) cm 与 `KukriWeaponComponent::OffhandHandToBlade` 一致）。

## 手臂：手肘、上臂变细

- **手肘方向不对**：极点取剪辑的绝对肘位、肩根却留在本作待机肩位时，肩位差会让弯曲平面偏转甚至翻转（实测 46–91°）。让肩根随动作权重移到镜像剪辑肩位（两臂骨长一致即可完全复现剪辑肘位），肩根始终在画面外。
- **上臂近肩段变细**：V7 裸臂挂在相机下、未做 −90° 偏航，锁骨绑定朝向在相机空间指向后方（−X）；上臂抬到身前时肩部蒙皮被挤压（实测仅剩绑定半径 83–94%）。锁骨跟随上臂形变的一部分（0.7）绕肩关节转动可回到 95–99%；动作首尾份额为 0，待机不变。验证：蒙皮半径剖面（`diag_upper_skin.py`）+ 锁骨权重顶点是否入画（`diag_clavicle_view.py`）。直接套用剪辑锁骨反而只有 85–95%。
- 反握刀身不能顺着前伸的前臂指向前方（需约 50° 桡偏）；保持参考拳位，拟合最近的刀向/肘位，腕部限位内取解（`fit_thrust.py`）。

## 运行时变换顺序

- UE `FTransform A*B` 先应用 A 再应用 B。刀身世界变换 = `刀在手中 * 手（相机空间） * 相机世界`。写反成 `Camera*Hand*KukriInHand` 时刀模型挂载看着正常（那处写对了），但命中检测和刀身扫掠的点完全错位——表现为"快速近战打不中"和"多余的金属格挡音"。
- 近战"不出伤害"先查日志 `Saved/Logs/FPSGAME.log` 的 `[QuickCombat] 接触 … 接触数=`：为 0 是检测几何问题，非 0 才查伤害/服务端。

## 参考视频读数

- 参考视模视场约 44°，本作 75°：参考画面左缘约等于本作 NDC x −0.53。参考里"从画外进入"的动作，在本作要放到本作自身的画框之外，否则会提前露出。

## 装备、换弹与待机的衔接

- **一条下沉弧线统一所有收放**：拳先向身体回收再落出画面下方（二次贝塞尔），手腕同时把刀尖下翻；肩根不动、肘部 IK 重解。替代整条手臂直线平移，换弹、消耗品、装备入场共用。
- **装备入场**：拔枪期间副手接管左手（原生左臂隐藏），沿弧线反向升入持握；手枪的居中/侧倾取景按同一进度淡入，拔枪结束即待机。手臂资源仍在异步加载时不提前进入取景。
- **换弹**：副手放下时长按副手种类取（刀 0.30 s、书 0.55 s，`FOffhandReloadHandoff::LowerSecondsFor`，服务端 `GetReloadSeconds` 同函数）；取景随刀的下沉/抬起同步；原生换弹片段开头支撑手就在握把上，要从下方接入（`ApplyNativeReloadEntry`），否则会凭空出现。
