# SVCH：整手握点、V9 支撑与压缩帧间修订

用于“快速近战握把错位、腕肘扭曲、收势瞬间甩臂”这类返工。保留用户认可的动作和 V9；此案例的参数不能直接推广到别的枪型。检查、渲染和联机用例仍需用户授权。

## 先定位首次偏差

- 对比本枪、本握把的 idle 与实际动画图：`hand_r` 在 `WPN_root` 中的位置和朝向，以及各指骨的父局部变换。R6 的五指局部姿态基本相同，整掌却偏了约 2.5 cm / 7.16°；继续卷指会掩盖整手注册错误。
- 按源姿态 → Profile 差量 → 压缩采样 → 动画混合 → 组件锚点 → 蒙皮/修形逐层追踪。作者矩阵接触正确，不代表 Gunplay 图里的最终接触正确。
- V9 名称仍可能沿用 `BarePalmV7` 路径。确认实际母版和散列，不按文件名把它换回旧手。保留手型、指骨偏移、权重与 `JC_` 修形；先调整肩肘支撑和原生扭转分配。

## 支撑链按实际蒙皮配置

复用已有 M870 R3 / SVD 方法，而不是另造一套挥击动作。SVD/V9 上肘表面主要受 `upperarm_twist_02_r` 影响；只转主上臂骨可能骨点看似正确、表面仍折。前臂 `twist_02` / `twist_01` 按原生站位承接 50% / 100% 轴向扭转，腕部修形驱动读取末段辅助骨关系。

整手重新落回握把后，要连同肩、肘、前臂解算。不能把原肘位置原样接回一个已经改变掌向的手，也不要缩短骨段或平移指骨补接触。保留握点、腕部折弯、前臂轴向旋转和臂根开口是不同约束。

## 帧点合格而帧间甩臂

R5 的 120 Hz 采样没有暴露第 67–68 帧之间的异常；压缩源和 Profile 差量分别插值后，帧间手掌偏离约 27 cm。修复采用实际 **COMPRESSED** 源重新编码差量，保留原 120 Hz 锚点，只在问题窗口加密。

- 本案例使用全段 120 Hz、54–90 帧 960 Hz、66–70 帧 7680 Hz；这是针对已定位异常的采样配置，不是每个动画的标准。
- 复查使用没有写入轨道的中间时刻（1920 / 15360 Hz 的奇数点），并按 UE 保存后的 float32 时间、数值和四元数插值求值。复测编码键本身不能证明帧间已修好。
- 带 100 倍原生缩放的矩阵元素差既不是厘米也不是角度。分别比较平移距离、归一化旋转角和骨段局部偏移；原矩阵差只保留作诊断。

## 接触与混合只能有一份最终结果

R7 恢复本枪 idle 握点后，运行时再次对局部骨链做入场/退出混合，仍让手掌离把。此案例保留旧 Gunplay 已有的枪体、左臂入场和回位结果，将其烘焙入同一动作，右臂按同一枪体变换搬运，再仅对 SVCH quick melee 取消重复混合。不能只把 ActionAlpha 强制设为 1 而不制作相应起止衔接。

加速动作还需核对执行器时间：SVCH 改为在角色姿态求值前推进 QuickCombat 一次，视模读取同一源时间；组件 Tick 不再重复推进。命中前发布/采样准确接触帧，结束按实际完成时刻解除射击锁。源动画时长、接触比例与伤害参数保持。
