# 固定工位视角：手臂 IK 锚点必须落在工作手可达范围内

适用于 `AAlchemyWorldView`、`AForgeInteraction`、`AWoodworkingWorldView` 这类"把相机与手臂一起搬进工位"的第一人称工作视角。作者入口 `Building/AlchemyWorldView.*`、`ForgeArmsMeshComponent.*`；数据 `Content/ColdSteelData/forge-grip.json`。

## 问题的形态

- 台面上的物品正常漂浮移动，**看不到手**。
- 同时可能有一条 **约 1px、贯穿屏幕的浅金色细线**，只在操作时出现、跟着手上的工具走。
- `showflag.SkeletalMeshes 0` 后细线消失 → 说明线来自骨架蒙皮。

这两个症状常常同源：**骨骼被摆到够不到的位置，蒙皮在断点之间被拉成一条细带**。

## 根因模式

`Solve()` 用余弦定理摆肘，对够手距离有硬约束：

```cpp
const float D=FMath::Clamp(Distance(Wrist,Shoulder),
                           FMath::Abs(L1-L2)+.1f, L1+L2-.2f);
Shoulder=Wrist-Axis*D;   // 肩膀被反推到手腕后方
```

一旦"手腕目标"离"躯干锚点"超过臂展，`Clamp` 每帧触发，肩膀被强行搬到手腕附近。此时：

- 手腕仍然贴住工具（看起来正常），
- 但肩/上臂蒙皮一端跟着手到了台面，另一端还在绑定姿态的原处，
- 中间被拉开几十厘米，投影就是那条细线。

**关键：`ArmBones` 包含 clavicle 及其全部子骨**，所以折叠"非手臂骨"的补丁救不了它，肩部蒙皮本来就在折叠范围之外。

## 判断方法（按顺序，成本从低到高）

1. **先量够手距离**。取每只手的目标位置与躯干锚点的距离，和 `L1+L2-.2` 比。超了就一定是这个模式，不必再查渲染。
2. **确认锚点空间**。`Pose[]` 是 actor 空间（`Reference[]` 组件空间 × `Torso`）；而 `AAlchemyWorldView` 每帧 `SetActorTransform(Station->Body()->GetComponentTransform())`，所以**台面局部坐标就等于 actor 空间**。不要拿"世界坐标"和 `Pose[]` 直接相减，那会算出假的米级差距。
3. **确认权重范围**。读网格的簇/权重数据，确认有没有非手臂骨影响。若只有 24 根手臂骨，"折叠非手臂骨"必然是空操作。
4. **运行期验证**：`showflag.SkeletalMeshes 0` 能让细线消失，就锁定骨架蒙皮，可以直接排除静态网格、后处理、描边、镭射。

## 修复规则

- **锚点必须跟着工作手走**，不能固定在镜头后方。做法：从原锚点向"工作手中点"线性插值，取**第一个**让工作手进入安全带的位置——这样能尽量保留原有构图。
- **安全系数留余量**：目标取 clamp 上限的 90%，保证 `Clamp` 永不触发。
- **只约束真正握工具的手**。搅拌、计时这类单手操作，另一只手停在台面另一端的固定点；让它参与约束会让两组要求互相矛盾（几何上无解）。
- **不要用固定偏移硬推方向**。往"背离镜头"推会把躯干塞进坩埚，手臂整段埋进锅体。方向必须从"原锚点 → 工作手中点"的插值算出，而非取视线法向。
- 待机分支通常保持原锚点即可：静止手位不变，且拉伸出画不明显。

## 排查时容易走错的地方

- **"手看不见"≠"修复失败"**。细线消失与手入镜是两个独立症状，不要用一个的症状否定另一个的修复效果。
- **不要用 `-Rebuild` 恢复单个丢失的 obj**。全量重编会撞上并行会话里未完成的代码，产生大量无关错误。删掉该 obj 并让源码 mtime 更新即可逼出重编。
- **UBT 可能报 "Target is up to date" 却已把模块从链接列表里排除**。删 obj 后要回读 `Intermediate/.../UnrealEditor-FPSGAME.dll.rsp` 确认该文件真的在里面。
- **诊断代码不要写文件**。`FFileHelper::SaveStringToFile` 的多参重载签名容易写错，在 UI 打开路径上会直接空访问崩溃。需要日志就只用一行 `UE_LOG`。

## 边界

本页记录的是静态定位与数值验证方法；实际观感由用户在游戏内确认。本案例的手部入镜问题在本页写作时仍未解决，不要把它当成已验证结论引用。
