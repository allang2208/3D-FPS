# 手套与衣物：高模烘焙、材质分区、实体厚度与接入标准

用户于 2026-09-29 要求将黑色皮革 V4、三款伴随手套和灰钢锁子甲经验作为后续制作参考。适用于皮革／织物／装甲手套、衣袖和贴身锁子甲的新增与外观升级。

先按 [第一人称装备工作流](first-person-equipment-workflow.md) 确定 V7 基准、原生骨架与覆盖合同；预算读 [按用途分配面数](../../asset-model-workflow/references/geometry-budgets-by-use.md)。项目具体参数、作者脚本、路径与历史状态单独见 [制作配方与案例](glove-clothing-production-recipes.md)。不要把案例中的厘米数、4K 分辨率、材质模式或 22 个 profile 当成所有装备的固定要求。

目录：结构与厚度 → 表面分区 → 高低模与烘焙 → 蒙皮图集视差 → 金属与锁子甲 → 原生派生与装备接入 → 图标 → 失败诊断与交付。

## 1. 已确定的制作原则

- 以已认可的 V7 裸手／裸臂及各原生绑定为基础。装备适配动作，通常不产生整套新动画。只改表面材质时不改变掌形、权重或抓握动作。
- 复杂近景物体允许高面数；不要为了统一数字削掉手套轮廓、袖口厚度或关节结构。百万面高模是烘焙源，不默认进入游戏。
- 高模细节必须有实际形状或明确的表面场。空细分增加顶点而没有形状变化，不是细节升级。
- 真实开口、厚度和大褶皱由几何处理；颗粒、细针脚、细织纹和浅划痕由法线／粗糙度为主表达，按需要添加有界浅层视差。
- 皮革、织物、金属的表面逻辑分别处理。同步“制作方法”不等于把所有手套换成同一种材料或同一套参数。
- 背景制作、必要烘焙、导入、材质编译和保存照常执行；不主动启动编辑器、游戏、测试、截图或验收渲染。烘焙属于制作，用户要求的正式装备图标属于交付；不附带生成验证画面。

## 2. 结构先行：厚度、接触与视觉过渡

### 2.1 手套与袖口要有实体结构

先以当前开口的真实边界环和解剖方向建立截面，再形成外缘、端面、内侧壁和适度内回折。腕口厚度向手部平滑收薄，不做突然突出的均匀圆环。

- 厚度优先分配到手背、腕背和防护区域。掌心、指腹、虎口与指缝保留原有接触包络，不能整只手统一沿法线膨胀。
- 内腕和受挤压侧应更薄，左右两侧可有有限压褶和轻微不齐，以表达柔软材料。厚度变化与内回折同步，避免外层变化而内层仍是另一条轮廓。
- 新包边各环继承对应原生边界顶点的权重。位置重合但权重不同的两条边，在静止时贴合、动作时仍会裂开。
- Body 和第一人称切口可能不同；按各自真实开口制作，不把 M4 的固定腕坐标强套到 Body。
- 已有内外层时不再全局 Solidify；图标或掉落旧源中的展示内衬也要按当前结构处理，避免叠出重复壳层。
- 衣袖肩肘腕保留活动余量。袖口与裸露皮肤／手套有适度搭接；仅在参考姿态端点相碰不代表动作中不会开缝。

具体毫米数随款式、身体尺寸和摄像机改变。历史薄皮、厚包边、钢甲的数值互不替代。

### 2.2 装甲允许按视觉目标软连接

用户已指定当前钢甲以平滑、自然过渡为优先，可以放宽绝对刚性。手背—手腕—拇指需要连续时，使用共享边界、连续法线及平滑权重的连接壳；不必堆叠多个独立硬片强行拼接。

其余手指甲片可按指骨稳定区分段。刚性片不要跨两个关节；弯曲区用柔性衬层或有明确余量的连接。小拇指的邻指侧空间和换弹中的双手接触尤为敏感，不用缩窄整片手背来掩盖局部问题。

视觉柔化是当前装甲的设计选择，不要求所有盔甲都软变形。已有钢甲专用姿态修正保留；材质升级不重算曲线，不新增逐帧碰撞求解。若用户要求动作修复，再按真实源姿态定位首个错误层，另行处理。

## 3. 材质分区决定真实感

优先在作者空间构造连续、可复用的遮罩，供高模、颜色、法线、粗糙度、高度共同使用。每根手指按自己的掌向与骨段识别区域，不用整只手的同一平面把指侧误判成指腹。

| 区域 | 制作重点 | 避免的做法 |
| --- | --- | --- |
| 手背皮革 | 合理颗粒、柔和高光、裁片层次 | 全黑剪影、均匀亮点、深凹凸橡胶感 |
| 掌心与指腹 | 与抓握相关的压平颗粒、有限抛光和方向性摩擦 | 为增强细节而加厚接触面或全局加噪 |
| 指侧与接缝 | 局部针脚、针孔、轻微压槽与磨损 | 把所有 UV 接缝当成真实缝线 |
| 织物、包边和线体 | 局部短纤维与绒面反光 | 把整只皮革都做成毛绒布 |
| 内衬、腕口和露指口 | 真实暗内壁、清晰卷边、材质连续 | 用肤色封口或纯黑遮罩伪造空腔 |
| 甲片 | 金属度、粗糙度、方向性微纹与倒角高光 | 套用皮革 Cloth、把金属度清零 |
| 锁子甲／金属织层 | 物理尺度的重复环纹、金属 PBR | 每个小环都新增骨骼／刚体／组件 |

磨损不规定为一律变亮或一律变糙：抛光可能变平、稍暗、粗糙度降低；干燥毛边可能更糙，露出的线体也不同。以所选材料和部位决定，再让颜色、粗糙度、微高度一致响应同一遮罩。不要给所有区域叠统一白噪声。

针脚使用有长度的弧形线体：中段略高、两端进入针孔，槽底略下陷；弧长控制间距，在拐角处连续。裁片转角增加有限叠边和短褶，位置对应真实裁片结构。微小变化有边界，不能随机到像破损模型。

## 4. 高模与游戏网格分离

1. **冻结当前游戏母版。** 保存活动配方、来源、原生拓扑／权重／UV／材质槽及已有 LOD。表面升级从当前游戏资产派生，不从被替代的旧全指款恢复露指款。
2. **制作烘焙高模。** 复制母版，采用适合结构的细分方式，再对针脚、针孔、压槽、叠边、金属刻纹等实际位移。需要保持游戏轮廓时，不用无约束平滑把手型整体收缩。
3. **将高模标记为烘焙用途。** 作者场景明确区分 HIGH、游戏网格、展示网格；导出器显式选游戏网格。保留高模不意味着运行时加载高模。
4. **按 UV／拓扑分组烘焙。** 相同图集映射可共用表面图；Body、独立左手或其他拓扑不同者单独烘焙。共享外观不能替代实际 UV 适配。
5. **同源制作高度与法线。** 已有真实高模高度时直接使用相同字段；不从 BaseColor 的阴影猜深浅。如只有扫描法线而需近似高度，注明重建来源和限幅，不能称为扫描原始高度。
6. **控制投射范围。** 薄壁、相邻手指、腕口内外层需要局部 cage／射线距离，必要时分件烘焙，防止烘到另一根手指或对面内壁。案例 cage 数值仅用于相同尺度和间距。
7. **补齐图集边缘与 mip。** 颜色和法线做合理扩边；视差另按实际 UV 岛生成内侧衰减。整个纹理的 Clamp 不能阻止采样越过内部 UV 岛。

扫描材质先确认实际尺寸和来源，必要时用静止姿态的三平面投影帮助作者阶段取得均匀颗粒，然后烘到适合游戏的图集。早期 Manny UV 拉伸案例不代表所有 UV0 都不可用；新的专用图集不需要强行回退到三平面。

归一化骨骼方向与尺度分开处理：某些 Body 作者矩阵的轴尺度为 1，FPS 轴尺度为 100。坐标字段应使用一致的厘米长度和归一方向，避免将图案放大／缩小百倍；不要因此改掉真实绑定矩阵。

## 5. 贴图合同与 UE 材质

| 贴图 | 通道约定 | UE 导入约定 |
| --- | --- | --- |
| BaseColor | RGB 材料固有色；避免烘进强方向光照 | sRGB 开，颜色压缩 |
| Normal | 切线空间法线，与最终游戏 UV／切线一致 | sRGB 关，Normalmap 压缩；按实际来源处理绿通道 |
| ORM | R 遮蔽、G 粗糙度、B 金属度 | sRGB 关，Masks 压缩 |
| Relief，皮革／织物可选 | R 归一高度、G 短纤维遮罩、B UV 岛视差安全衰减 | sRGB 关，Masks 压缩；保持通道含义一致 |

本案例 Blender 烘焙法线按 OpenGL 输出、导入 UE 翻绿；旧项目也有已是 DirectX 的作者法线，所以不能对所有 Normal 一律翻绿。高度图不是法线图，Gloss 也不能无说明地与 Roughness 重复叠加。

第一人称 4K、Body 2K、金属内衬小尺寸平铺是本次配方，不是所有衣物默认 4K。按最终用途分配：颜色／ORM／高度可考虑较低分辨率，近看针脚的法线可单独保留更高精度；调整后同步图集尺寸参数、视差纹素限制及边缘遮罩。不同尺寸输入需要明确 Relief 的尺寸口径与其他纹理自身 mip，不能继续用一个未经解释的 AtlasResolution 指代所有贴图。

保留 mip 和纹理流送，不用全局 NeverStream、扩大纹理池或关闭流送来掩盖尺度错误。Opaque 材质中没有用途的 alpha 可在专门的贴图优化时去掉；是否节省显存取决于目标压缩格式，不能只从 PNG 文件大小推断。

皮革短绒可用受遮罩控制的 Cloth 绒面表达，主体皮革保持较低绒量；光滑皮革不强制 Cloth。当前传统 MakeMaterialAttributes 实现通过 Cloth 对应的 ClearCoat／CustomData0 入口提供 fuzz，SubsurfaceColor 用作绒色，不能把它解释为皮肤散射。引擎或材质体系改变时沿当前实现调整，不把旧 pin 名强套到 Substrate。

微法线与宏观法线需用正确的法线混合方法，或在作者端合成后统一烘焙；不直接把两张 RGB 相加。新增一层细节先考虑复用现有通道与遮罩，避免每次迭代增加一组运行时纹理。

## 6. 从地牢／地毯迁移的浅层视差方法

参考 [地面收边与织物凹凸](../../asset-model-workflow/references/floor-trim-and-textile-relief.md)。复用的是共享坐标、浅高度和衰减原则；手套是变形表面，不能直接搬静态地面的世界平铺坐标。

### 6.1 坐标与共享采样

- 在当前已蒙皮表面，用世界位置和 UV 的屏幕导数构造世界到 UV 的局部换算，按厘米控制浅层深度；保护退化三角形／接近零行列式，左右手镜像按实际 UV 手性处理。
- 所有颜色、法线、ORM 与最终 Relief 使用同一偏移 UV，避免缝线的颜色、阴影和高光各向一边移动。
- 采样使用未偏移 UV 的 `ddx/ddy` 梯度，避免视差搜索本身导致不稳定 mip；材质与骨骼一起运动，不能出现世界投影“贴图游泳”。
- 初始 Relief 的 B 通道参与岛边衰减，偏移后再读取高度与绒面。基于整张图集 Clamp 仍不足以保护内部岛缝。
- 高度归一化、零面、实际深度和生成高模的单位保持成套关系；材质 DepthCm 不是另一个随意的凹凸放大旋钮。

### 6.2 限幅与采样成本

黑色参考实现上限为 6 次粗步进＋2 次细化，UV 偏移最多 8 个原始图集 texel；距离、掠射角和 mip 变粗时衰减。衰减充分时，在条件分支内跳过搜索。它是有上限的浅表细节方案，不用于深洞或外轮廓。

完整近景分支最多约 13 次纹理查询，跳过搜索时仍有初始 Relief 和颜色／ORM／法线共 4 次。编译器对 Custom HLSL 返回 pixel texture samples = 0 不意味着没有采样；看实际代码，不能用这个零值证明“无成本”。

POM 不增加几何，不改变轮廓、碰撞或手指接触；WPO、透明毛发壳层和真实布料模拟也不是此方法的隐含组成。需要轮廓毛纤维或可摆动衣物时另行选路线并分配预算。

步数、深度、衰减距离可以按材质和用途调整。常规游玩／检视分档、Body／掉落关闭 POM 是后续优化方向，并非当前全部资产已实现的开关，也不因本标准自动降低现有质量。

## 7. 钢甲与锁子甲的迁移方式

- 外甲片和金属衬层分别保留材质槽。甲片采用 Default Lit 金属 PBR，刻槽、轻微锤纹和方向性拉丝来自高模／法线与粗糙度；外轮廓与倒角仍需要适当几何。
- 锁子甲用可平铺高模单元烘焙环纹，而不是运行时逐环建模。通过法线、遮蔽、金属度及粗糙度表达交叠，保持不透明底层连续。
- 从手套移到衣袖时按衣袖实际面积和 UV 标定物理密度。保持环尺寸一致，不是直接复制旧 Tiling 数字；贴身衣袖随原生骨架变形，避免世界空间投影滑动。
- 当前全覆盖灰钢内衬是既有外观选择，材质升级不能回退成早期棕皮衬底。旧文档中的“皮革＋甲片”两槽名称不代表当前可见材质仍是皮革。
- 同一装备形体与衣袖可以共用金属材质家族，但物品 ID、装备槽、防御和速度属性各自独立。新上衣不能自动继承钢甲护手的减速属性。
- 贴身锁子甲和紧手套默认沿用蒙皮；柔软视觉、绒面着色、高面数均不等于 Chaos Cloth。只有用户需求涉及动态布料，才按衣物工作流另做模拟代理、固定区、碰撞与更新路径。

## 8. 原生派生、材质槽与装备闭环

沿当前 `modular_outfits.json` 的 profile、`rig_meshes`、`skin_meshes` 和 `appearance_family` 选资源。保留每个原生骨架的参考姿态、骨长、局部轴、完整绑定与权重；外观统一不等于 M4 静态顶点可以直接放到任何武器上。

- 材质升级且几何已合格时，可复制活动游戏资产，逐槽替换材质，保留 LOD／蒙皮／形状；不需要把高模重新导入成运行网格。
- 当前组件只有 `material` 非空时才用单一材质覆盖部件全部槽。需要皮肤＋皮革或金属衬底＋甲片时，配方 `material` 留空，让网格自己的材质槽生效。
- 露指组合网格保留皮肤槽，只更新手套槽；使用 `skin_meshes` 和 `glove_in_base` 时，不再额外挂第二份手套。覆盖区域来自当前配方，不因物品类别一律隐藏整只手。
- 原视模手臂按当前 profile 的分区隐藏，不能隐藏骨骼来隐藏衣服；各武器原材质槽编号不同，M4 槽号不是全项目常量。
- 材质实例／动态参数按装备实例和当前合同管理，不在换装时修改共享全局父材质。当前 follower 用 LeaderPose 读取源动作，材质升级不新增动画状态机或 Tick。
- 保存候选资源完成后再精确更新本物品配置；发布时重新读取当前数据，只合并拥有的外观字段。保留原装备属性、动画时序、物品 ID、库存与存档；实际并行文件冲突只向当前用户说明，不跨会话协调。
- 优先后台 commandlet 和现有互斥入口；已经运行的编辑器按现有桥操作，不另起进程覆盖同一资产。仅有导入脚本不等于保存完成；按实际回执区分源、导出、已保存资产和配置接入。

2026-09-28 的战术手套已为独立装备家族，不能重新发布旧 `source_arms` 配方恢复整套原衣袖。历史工具仍可能是其他步骤输入，只在明确恢复旧版本时使用，不能按文件名推定它是当前入口。

## 9. 装备图标和掉落外观同步

完整构图标准复用 [手套装备图标](../../ue5-item-asset-workflow/references/glove-inventory-icons.md)，不另创一套尺寸。

- 当前穿戴网格／生产材质是外观来源；按 `appearance_family` 找实际家族，不能重新出图时退回旧光滑壳或旧皮革衬底。
- 单只空手套，不出现皮肤、手臂、人台或第二只遮挡物。自然松弛分指，保持骨段长度；露指款选择能读出真实开口与暗内衬的视角。
- 展示坐标架正交归一，避免非正交投影把掌形剪切；图标姿态是独立展示副本，不回写游戏动作。
- 当前 2×2 手套图标为 320×320 RGBA 透明底、正交镜头、主体主轴约 91% 填充；不裁掉手指或腕口。曝光从生产材质出发有限校准，Blender 出图不冒充 UE 实机。
- 背包、装备栏、仓库沿同一物品图标引用。正式 PNG、作者源 PNG 和后续出图入口同步；只替换目录 PNG 而保留旧生成入口会在下次制作时回退。
- 用户任务包括掉落外观时，单独导出／保存当前空壳模型与逐槽材质；单独出图任务不隐式重导游戏网格或掉落模型。掉落版本可有独立密度，不要求搬用第一人称全精度。

## 10. 典型问题与处理入口

以下是制作定位提示，不自动触发诊断脚本、预览或测试。

| 现象 | 优先定位 | 不应用什么掩盖 |
| --- | --- | --- |
| 手套像橡胶／塑料 | 物理纹理尺度、掌背分区、粗糙度、微法线与绒面量 | 全局提高对比度或所有通道强度 |
| 动作中表面滑动 | UV／rest／world 投影关系和同源坐标 | 减低纹理清晰度 |
| 视差图集边缘裂缝 | 岛边衰减、扩边、最大偏移、镜像与 mip 梯度 | 只把整张纹理设 Clamp |
| 腕口像纸片 | 实体外缘、端面、内壁及回折 | 加粗法线或增大 POM |
| 腕口像硬圆环 | 内外腕厚薄、压褶和渐变长度 | 整圈统一加厚 |
| 甲片弯曲时破碎／露缝 | 刚片跨关节、连续边权重、法线、真实覆盖 | 把整片缩小或重做全套动画 |
| 小拇指与邻指穿插 | 该指局部方向、骨段覆盖、双手动作空间 | 修改所有裸手或全局缩放 |
| 金属内衬变成皮革 | 配方单材质覆盖、材质槽、旧导入入口 | 单纯提亮颜色 |
| Body 纹理尺度异常 | 图集组、归一骨骼轴与厘米单位 | 改动实际骨长／绑定来迁就图案 |
| 图标与装备不同 | 活动家族、实际生产材质、旧展示场景和缓存 | 画一张与网格无关的概念图 |
