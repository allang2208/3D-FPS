# 左手施法与完整骨段变换

2026-09-14 火球 V3 获用户确认「基本达到预期」。适用于当前 Manny 第一人称手模上的单左手凝聚／发射；数值是该动作制作参数，不是其他骨架的统一限位。业务占用、成长和存档见 [技能／魔法工作流](../../ue5-skill-magic-workflow/SKILL.md)。

## 先保持动作身份

参考照片：凝聚缓抬左手、掌心向上、四指靠拢、拇指自然张开；发射掌心转下并快速前送。照片未给出完整运动，因此起势、蓄势和收手是三维动作设计。参考近战已采用的分段 Hermite 时间映射和连续弧线回握，肩、肘、翻掌、开指稍有先后。

当前时间：凝聚 0.95 s；独立发射预备 0.26 s、前伸 0.34 s、接触在前伸后 0.20 s；收势 0.44 s。凝聚后手释放，火球保持悬浮。再次发射从当前握持姿态进入；凝聚连按可直接衔接前伸。业务接触与动画用同一时钟，退出时记录实际阶段和进度。

## 手臂变细并不一定是骨长变化

火球 V2 与早期符文剑曾出现同类错误：前臂主骨完整翻转，蒙皮辅助骨却按沿臂距离套用累计扭角的 1/3、2/3。受它们共同影响的皮肤被拧细；跨越 ±180° 还可能留下残余旋转。仅声明两骨 IK 不拉伸不能排除此问题。

当前 Manny 修复：

- 先按原骨长解肩、肘、腕，再由手掌的相对 rest 旋转确定前臂 roll，将前臂轴摆到解算方向，避免依赖累计标量扭角。
- 上臂和前臂的辅助骨保留完整 rest-local 变换，与所属骨段统一运动。不要给已经完整旋转的父骨再混入另一份分数扭角。其他具有专门 twist 权重设计的 rig 应按其蒙皮规则适配，不一律禁用 twist。
- 增加前伸应协调肩带、锁骨、上臂、肘与腕。火球腕部终点 X=54 cm，肩部 X=-3.2→10.8 cm，肘部支撑同向前送 14 cm。三者沿同一发力曲线，保留自然屈肘。
- 该视模距离达到两段手臂总长的 93% 时，向前平移肩带支撑，继续保留骨长与缩放；不能只拉腕部或扩大骨骼 scale。此肩带平移属于第一人称视模，不能直接套到带躯干的第三人称角色。
- 世界／组件目标先完整求出，再按父子层级重建局部变换并混合；保留右手和武器骨。收手柔和交还当前武器姿态，避免将上一帧已修改的目标当成新的原动画姿态累计。

## 当前制作入口

工程相对路径：

- `Source/FPSGAME/Skills/FPSCastingMeshComponent.*`：后置左臂求解、完整骨段辅助骨和局部混合。
- `FireballCastMotion.h`、`FireballHandPose.*`：时间曲线、相机空间路径、手型语义。
- `FPSFireballComponent.*`：阶段时钟、进入姿态、退出快照和发射接触。
- `Content/ColdSteelData/Skills/fireball_hand_pose.json`：当前姿态参数。
- `SourceAssets/FireballCast20260914/author_cast.py`：读取同一配置、C++ 时长与曲线，300 Hz 烘焙可编辑 Blend 和七段 FBX。

参考修复在现有符文剑 `SourceAssets/RuneSword20260913/StrideThrustV16/arm_solver.py::apply_arm`；施法源母版仍使用 `GASPTraversal20260910/Native/TraversalArms_Editable.blend`，不是 RuneSword FBX。不要因为某文件是旧日期就移走实际作者依赖。

默认不启动游戏、生成预览或跑测试。用户要求检查形变时再覆盖掌心翻上／翻下、最大前伸与收手之间的真实蒙皮画面；骨长数值和编译通过都不能代替手臂轮廓判断。
