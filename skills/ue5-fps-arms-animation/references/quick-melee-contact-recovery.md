# 枪械快速近战：握点、腕臂与 recover 衔接

适用于枪托／握把挥击、跨枪动作迁移，以及动作末尾二次回正。遵守用户的默认不主动测试规则；下述测量方法只在用户要求排查、检查或验收时执行。制作前仍需读取当前运行资产、握把分支与动作时序。

## 先确认要保留的约束

- 「手指不变」与「手握住枪的位置不变」是两件事。五指局部旋转完全相同，整只手绕错误枢轴转动，仍会使所有手指偏离握把。
- 保持原抓握时，以本枪、本配件当前 idle 为基准，固定枪根空间中的手掌矩阵 `inverse(WPN_root) * hand_r`，同时保持手指局部姿态；左手也使用对应配件的握点。
- 整枪和双手作为一组改变位置／朝向，肩、肘、前臂随后解算。跨枪可以复用动作节奏与运动增量，不能直接复用另一个枪型的后握把枢轴、局部轴或绝对肩位。
- 一旦改变整手相对枪的方向，应明确它是握持调整，重新处理接触；不要称为“保持原握姿”。

## 腕部弯折与整臂扭转分别处理

1. 区分腕轴折弯、前臂轴向扭转、肘极方向及肩根伸入视野。只动 twist 骨不能纠正手掌与前臂接近直角的问题。
2. 固定肩、腕、骨长后，肘位只能在双骨链可达圆上变化。若最小可达腕轴折角仍很大，小幅肘部补偿没有可行解；应调整整枪持握方向／路径或肩部支撑，保留已认可的接触约束。
3. 完整大小臂骨段共同解算，辅助骨位置随所属骨段移动，扭转沿骨段分配。单独锁住前臂末端朝向可能把扭曲转移到整条手臂。
4. 肩根、袖口和近裁剪是另一层问题；手腕自然不代表肩口不会进入屏幕。缩短前伸或改变肩部支撑时，继续保持握点及骨长。

## recover 要同时归位所有表现层

可见姿态同时受动画轨道、动作混合、视模组件锚点和镜头层影响。clip 末帧等于源 idle，只能说明动画轨道回正。

- 如果忙碌状态一直维持动作展示位置，结束后才插值到腰射锚点，就会出现“先到近似待机，再回正一次”。应在 recover 内消除展示偏移，并在结束时落到精确终点。
- 动作末段平滑交给下层当前 idle／ADS／移动姿态，让当前枪型、握把和弹匣分支决定归位目标，不写死一个通用 M4 待机。
- 姿态与业务状态共用同一个经过时间；避免状态计时结束后，另一份 `ActionElapsed += DeltaSeconds` 还继续播放。
- 结束状态清除活动动作，保证晚一个 tick 结束的近战组件不会重新拉起展示偏移。保留命中、音效、冷却与伤害合同。
- 本案例采用五次平滑曲线 `1 - (10t^3 - 15t^4 + 6t^5)`；展示位置从总时长 60% 开始归位，动作权重从 78% 开始交接。这些是本案例参数，不是所有动作的固定比例。

## 需要排查时如何区分证据

- 在同一坐标空间比较枪根相对手掌矩阵、手指局部矩阵、骨段长度；另看实际蒙皮表面。接触邻近、骨骼吻合均不能单独证明没有穿模。
- UE RAW 和 COMPRESSED 必须各自与同模式、同 retarget 设置的 idle 对照。本案例 RAW 关闭额外 retarget，COMPRESSED 使用运行时 retarget；混用会产生数十厘米的伪偏移。该设置应按骨架确认，不能全项目照搬。
- 高速动作若关键帧接触正确、帧间漂移，检查插值和压缩。只在有该问题时提高采样；QBZ191 O 以 120 Hz 求平滑运动、480 Hz 重建导出，不代表所有动画都需 480 Hz。
- 源模型预览用于观察接触和形变；屏幕构图与最终手感由真实运行画面和用户反馈确定。历史检查结果明确日期，不冒充当前重新测试。

## 播放提速要同步占用与命中（M4，2026-10-06）

先确认实际加载顺序：共用握姿 Profile 的 quick_melee 可能优先于旧动画路径。读取选中的片段长度和 RateScale，再区分出手慢、长收势和多余状态锁定；不要只调序列 RateScale，显式时间采样可能根本不消费它。

统一提速时保留源姿态与源时钟，播放时长为 `源长度 / 播放倍率`。近战组件的阶段／接触时间、武器忙碌时长和收势混合使用同一播放时长，显式动画及差量采样使用 `播放经过时间 * 播放倍率`。不要仅缩短状态或仅加快画面。确认改动归属时避免用跨枪共用的 `bUsingM4Infima` 标志扩大范围。

M4 Base／Drum／Angled／Vertical／Canted／Prism 六份源仍为 0.9 秒；当前 `A_M4_QuickCombat_` 家族在运行入口以 1.5 倍播放，实际占用 0.6 秒、接触约 0.111 秒。作者动作未改，无需重制差量；若将来修改源姿态或源时长则按动画共享流程重制 Profile。Editor/Game 构建成功，尚无本轮游戏手感验收。见 `Docs/Weapons/m4-quick-melee-timing-20261006.md`。

## Super90 左臂反例与保留握点的重解（2026-10-09）

Super90 R4 已被用户否定，R5 只完成制作和五份资产保存，尚无用户认可。不能把低腕角、固定骨长或 commandlet 成功当成人体工学、无穿模或画面验收。

- 固定 donor 肩位再绕肩腕圆找肘，可能得到“肘在肩内侧、上臂回折”的低代价解。R4 允许过大的圆周旋转，正是此反例。保留双手握姿时，应优先用本枪当前 idle 的身体肩位、外下侧肘关系和实际臂长约束。
- R5 的候选做法是从被握点固定的腕出发：受手轴约束求前臂方向和肘位，再向本体 idle 肩位求上臂方向，最后移动肩与锁骨支撑；肘屈曲、肱骨旋转和肩移位同时约束。数值限幅是作者控制，不是通用人体角度标准。
- 骨架的 bind 肘铰链不一定等于蒙皮折痕。Super90 原生几乎直臂，V7 母版本身有明显肘屈曲；应通过实际 V7→native 网格转换分别求上臂和前臂的蒙皮铰链，不能直接复制 PKM 的 20° 偏置或辅助骨布局。
- 本枪没有上臂 twist helpers；前臂 aux、twist_02、twist_01 沿 0、1/3、2/3 站位承接旋前。重建父链后用 hand_l 的局部补偿保持世界握点，手指保持原样。默认和四种前握把分别以自身 idle 为依据，同步保存序列与 Profile 差量。
- 枪体摆向必须按自身真实瞄准线、原生 up 轴和运行相机锚点迁移。Super90 原生 up 为 -Y，后向为 +Z；复制 M4 的枪托轴或 PKM 展示锚点会让主体甩出画面。

当前源在 `SourceAssets/Super90QuickMelee20261008/LeftArmR5/`；旧 R1–R4 位于 `trash/super90-retired-20261009/SourceAssets/Super90QuickMelee20261008/`。当前输入已移入 R5 自身，不能再把旧目录当恢复前置。恢复与未验收状态见 `Docs/Weapons/super90-publication-20261009.md`。快速装填仍按用户要求暂停，不因近战修订而重开。

## Super90 近战与通用支撑的权重交接（2026-10-10）

用户随后截图指出横向挥枪时左肘／上臂凸入画面，R5 仍不是合格基线。R23 换弹修订新增的最终支撑节点会同时作用到近战：即使源动画重做了肘铰链，上层掌宽定轴仍可能再次改变肩肘和上臂滚转。修改源动画时必须追到最终姿态写入者，避免两套解算重复覆盖。

R6 的制作方式是下沉肩根并约束肘部低于腕部，同时用真实蒙皮铰链定上臂、让前臂辅助骨在腕端承接完整掌向。保留两掌世界握点、手指、枪体／右臂、时长与接触。基础及四种前握把分别重制左侧七条轨道。

近战专用 `Super90MeleeArmAuthored` 曲线随动作姿态一起混合：主体由作者轨道控制，起手、收势和中断按曲线及已有动作权重交回通用支撑；手掌接触仍在组件空间保持。没有该曲线的待机和换弹沿用 R23。曲线、序列与最终节点源码是同一个交付合同，不能只恢复其中一项。其他动画/Profile 条目保持当前安装数据。

当前近战源为 `SourceAssets/Super90QuickMelee20261008/LeftArmR6/`，依赖 R5 保留的骨架／相机校准及 V7 可编辑母版；不能归档这些依赖。五份资产和五种可编辑动作已保存，Editor/Game 必要构建成功。本轮没有游戏测试、截图、渲染或视觉验收，制作约束不是无扭曲证明。详细状态见工程 `Docs/Weapons/super90-quick-melee-20261008.md`。

## Super90 动作意图纠正：竖直收臂与枪托前送（2026-10-10）

用户否定 R6 的动作理解：左臂应靠近身体弯曲收回，肘尖向下，在竖直方向折叠，再由右手向前送出枪托。不能继续锁死旧横甩枪路，仅靠移动肩肘或降低扭转角去适配。用户对发力方式的最新要求优先于旧版本“枪体和右臂不动”的约束。

本类修改需先重做整枪、双手与身体侧支撑的关系：握点相对枪根可保持，但手掌世界路径和枪托路径随动作重做；左肘弯曲面按身体侧的竖直平面构建，不让掌向带着它绕肩腕轴水平打转。右臂承担前送，左臂承担收拢与支撑，回握再自然展开。只改 twist helpers 不能替代这一动作结构调整。

R7 对默认及四种前握把重做枪根和双侧腕臂，源为 `SourceAssets/Super90QuickMelee20261008/VerticalFoldR7/`。保留枪根相对握点、五指局部手型、0.9 秒源长及 1/6 秒接触；沿用 R6 的曲线交接机制和已编译节点，调整其起手／收势窗口。本轮不涉及新 C++；实际资产保存与未测试状态以工程 `Docs/Weapons/super90-quick-melee-20261008.md` 为准。R7 尚无游戏或视觉验收，不将“竖直折叠”的制作约束写成用户认可。
