# 基础动作与作者姿态差量

用于枪械、双持手枪、剑、弓、法杖及采集工具的动作复用与变体缩减。优先沿用已共享的序列或程序姿态；需要保留作者姿态差异时，用基础动作＋稀疏差量替代重复完整动画。保留原接触和机构时序。

## 新增与改版武器的统一流程（2026-10-02）

新增武器或动作变体时，动作复用属于接入制作的一部分。复用 donor 后再为每个变体导出整套序列，只完成了制作来源复用，尚未完成运行依赖缩减。

1. 从当前加载代码和目录数据列出基础动作、实际变体、原生骨架、动作角色和事件时钟。以当前 V7 裸手派生为准，不从历史同名动画挑供体。
2. 按差异选复用方式：同骨架、同轨迹直接引用同一序列；同骨架、同时长但握姿不同，制作差量；已经共用程序动作的武器继续共享参数/姿态键；装填机构、出手侧或时长不同则保留独立基础动作。不能仅凭动作名称跨骨架共享。
3. 完成作者动作与导入后，列出基础/变体配对，运行共用制作器并实际保存 Profile。新增加载分支应按动作通道、当前序列和同一个显式时间应用差量；组件最终混合、接触点、命中采样与衣袖跟随继续消费同一帧姿态。仅存了差量资产但没有运行消费者不算接入。
4. 动作重导入入口同时重制受影响 Profile。清单每份配置表达完整的当前配对；撤销角色或改换基础序列时同步移除旧条目，不能让过期 Base/Retained 引用留在配置里。
5. 交付记录实际保存配置、替代的不同完整变体、仍独立保留的动作、运行消费入口及构建状态。源动画留作重制输入；默认不运行游戏、测试、截图或视觉验收。

### 各武器采用的共享方式

| 武器 | 共用主体与变体 | 保留的动作合同 |
| --- | --- | --- |
| 步枪、机枪 | 原厂基础动作＋握把/托握差量 | 普通、空仓、弹鼓和布弹箱各自机构及补弹时钟 |
| 单持/双持手枪 | 基础动作＋配件姿态差量；双持按左右侧分别制作 | 套筒锁定、末发、左右手职责、空仓与转枪收势；左轮逐发/快速装填独立 |
| 剑、斧、矿镐 | 已共享动作前缀继续用；相容握柄变体叠差量 | 挥砍、突刺、格挡、采集用途和命中时钟 |
| 弓 | 共用手臂动作前缀、搭箭/走跑序列；部件、弦和弓体形变由同一动作驱动 | 搭箭、拉弦、蓄持、松弦、取消/续射与箭支消耗；不能把这些阶段合成一个循环。未来出现不同握姿时，接入弓自身的序列采样/最终骨骼链后再用 Profile |
| 法杖 | 共用 StaffGripPose、StaffChargeFlow、走跑及空闲左手；握柄差异用已有变体姿态键 | 蓄势/释放、普攻、照明、空左手或副手枪职责及各自事件时钟。已有程序共享无需再导出每杖整套序列；仅新增作者序列差异时才接 Profile 消费层 |

### 独立批次制作入口

`SourceAssets/WeaponAnimationSharing20261001/install_profiles.py` 是共用制作器。新批次保留自己的 `manifest.json`、`install_receipt.json` 和汇总，不覆盖历史批次统计。清单 `profiles` 的每行包含 `weapon`、`family`、`mesh`、`asset`、`pairs`；每个配对包含 `role`、`base`、`authored`，路径均为实际 UE 包路径。

用轻量入口传入 `ANIMATION_SHARING_JOB_ROOT` 和稳定的 `ANIMATION_SHARING_AUTHOR`；跨批次维护已有配置时，清单行可用 `author` 指定原制作归属。目标目录仍须与运行加载器、Cook 引用一致，不能仅按新批次日期另存后不改消费者。具体模板是 `SourceAssets/WeaponAnimationSharing20261002/prepare_manifest.py`、`install_profiles.py` 与 `run_install.ps1`。这是生产工具，不是自动验收工具。

## 制作与运行合同

- 配对当前实际加载的基础/变体动作。原生骨架及源时长相同时，离线制作局部位移、旋转、缩放差量；不兼容的条目直接保留原完整动画。M4 本轮的 20 个条目属于骨架例外，不应为了统计减少而强制重定向。
- 差量包含确有变化的左臂、手指、辅助骨，以及必要的右臂和枪体轨道。省略恒等轨道，常量轨道存一帧，动态轨道按制作精度缩减关键帧；四元数连续性和源动作时钟保持。
- 待机、瞄准、动作、冲刺进入及循环各通道先应用差量，再混合。不能在最终混合姿态上统一加待机偏移，也不能同时再叠旧 GripLayer56。配置缺失时继续原加载分支。
- 基础序列继续负责机械、音效、命中和补弹时间；普通、空仓、弹鼓、201 布弹箱仍保留各自基础动作。差量使用同一显式播放时间，没有第二套推进时钟。
- 配置在装备/切换时加载，骨骼索引按配置、序列和 LOD 缓存。腰射定位也使用基础待机＋相同差量，避免手型正确而枪轴定位仍来自旧动作。
- 双持按左右手实际开始的动作选择 fitted/long 层，保留出手侧、空仓和转枪收势。剑在原有入场、收势、施法与最终插槽发布之前应用差量；按实际手臂骨架决定能否使用长握柄配置。

## 后续修改不能只更新源动画

改基础动作或作者变体后，同步重制相关 profile 条目，否则游戏会继续采旧差量。HK416 普通/扩容空仓拍击修订已经按此刷新四款前握把，保留弹鼓等未修改条目。

UE Python 不跨 `BakeClip` 等会重建结构数组的调用持有 `Clips` 元素反射视图。先把需要的时长等复制为普通 Python 值并释放视图，制作后重新取数组；源动画和配置都实际保存后才发布完成状态。历史退出崩溃与“保存已完成”分别说明，不把桥超时当作全部资产写入失败，也不把已有回执当成新的运行验收。

## 维护入口与统计

- 运行实现：`WeaponGripProfile.*`、`WeaponGripProfileNode.*`、`WeaponGripComponentLayer.*`；通用家族入口保留在 `SVDGripProfiles.cpp`。
- SVD 制作：`SourceAssets/SVDGripProfiles20261001/install_profiles.py`。
- 扩展制作：`SourceAssets/WeaponAnimationSharing20261001/make_manifest.py`、`install_profiles.py`、`run_install.ps1`；基础或源动作更新时重新生成输入并制作受影响组，不执行已退役的一次性源码改写器。
- 原两批共替代 588 个不同完整变体的配置引用：SVD 48＋扩展 540。201 后续原厂托握另加一份 base 配置，不增加整套完整动画副本。统计需注明版本及口径，输入配对数不是去重后的减少数。
- 旧完整动画、作者源和骨架是重制与回退依赖，不能因不再直接播放就移到 trash。减少配置中的完整序列依赖，不等于工程文件数、Cook 包体、运行内存或帧率已经改善；这些需要各自范围的整理或测量。
