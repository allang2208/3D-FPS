# 步枪拍击、检视与运行握把层

适用于已有动作跨枪适配、拍击被握把姿态覆盖、或名为 inspect 的片段实际没有检视。案例为 HK416，2026-10-01；制作与保存完成不等于用户已接受观感。

## 先分清四个动作层

沿实际加载入口读取：基础 AnimSequence → 前握把／弹鼓家族 → 运行时 `UWeaponGripProfile` → 相机反馈。只替换基础或家族 FBX，旧 profile 的局部差值仍可能把旧动作叠回来。修改基础动作、接触帧或时长时，同步重烘涉及家族的该动作项，保留其他动作。

`FWeaponGripClip::Playback()` 可能返回 Base，也可能保留独立 Authored。不能从播放资产名判断握把层是否生效；查 `InitializeWeaponGripFamily` 和各动画通道实际挂载的 profile。没有对应项的家族可以沿用基础动作，不为凑齐列表创建无用层。

## 移植拍击和收势

- 用户指定复用已认可动作时，复制完整左锁骨、上臂、前臂、腕、手指及 twist 关系。在目标枪根坐标系做有界的整臂接触配准，不用单独转腕或两骨 IK 替换原动作意图。
- 区分源动画时钟和游戏换弹时长。HK416 普通／扩容为空仓源帧 130 拍击、162 结束；弹鼓是 116／148。这里是该枪案例，不是所有步枪的通用帧数。
- 回握窗口必须在最后机械接触和离开动作之后。旧 88–111 帧回握覆盖了拍击；本次普通／扩容改为 142–162，弹鼓 128–148。不要将 M16 右手拉柄尾段直接混入弹鼓拍击。
- 动作末姿态和视模锚点是两层。`RifleReloadHandoff` 在源动作尾段把相机空间位置、旋转及动作权重交回本枪待机，避免动作结束后再校正位置；不能靠延长全局混合遮掩瞬移。

## 检视不能只凭名字选素材

读取实际根轨迹、帧率、帧区间和双手关系。旧 `M4_inspect` 及其 M16/HK416 派生仅有待机轻晃，名字不代表有完整检视。

HK416 本次采用 AKM／SVD 已用的枪体检视轨迹，按本枪压小翻转和位移、重定时到 4.2 秒。普通、垂直、斜握把、阻手器、直角握把、弹鼓分别从自己的待机关系生成；枪体和双臂共同搬运，保持腕肘及手指局部关系，首尾回到该家族的待机。它适用于双手持续握持的通用检视，不自动适用于松手、拉栓或换握动作。

## 枪体震动不等于屏幕抖动

镜头层另查 `WeaponActionCameraComponent` 的实际分支、启用条件与强度。HK416 复用 M4 的普通／空仓和弹鼓分支，拍击脉冲使用机械声音的接触秒数及 `ReloadSourceTime`。不要在机械声音回调再叠一遍相同相机冲量。代码接入检查和实机强度观感分别记录。

## UE Python 数组视图的生命周期

`BakeClip` 内部会 `Clips.RemoveAll/Add`。先把需要保留的旧时长等读成普通 Python 数值，再释放 `get_editor_property('clips')` 返回的数组／结构体视图，之后才调用重烘；不能在数组重建后继续读取旧元素包装对象。

HK416 曾在资产保存后的 Python 收尾阶段出现访问冲突；这是已发现并修正的失效视图风险，不能据此断言该次崩溃根因已证实。保存回执逐项落盘，桥连接中断时从明确保存边界续接，不重复导入结果不明的整批资产。
