# 单手长杖：镜头方向、完整腕臂与空闲手

适用于相机空间的长杖待机、握持修正和走跑。参考握弓时迁移的是完整包握与骨段处理方法，不是照搬握弓侧的手腕角度。

- 先明确参考图里镜头看到手背还是掌心、拇指在哪一侧。FPSGAME 相机局部 +X 朝前、+Y 朝画面右、+Z 朝上；Blender 作者轴、原生骨架轴、握点局部轴需要显式转换。先固定用户认可的掌向，再调整穿模，不因求解残差更小而翻掌。
- 用当前 V7 原生手模的实际掌面、指腹及握柄表面拟合闭合抓握。右手保留右手原生骨长与绑定；参考左手握弓不能直接负缩放镜像骨架。四指包住杆体，拇指闭合虎口；握紧感不能靠把关节中心压进木杆获得。
- 保存锁骨至肩、肘、前臂辅助骨、腕及手指的完整局部姿态。局部混合后再转组件空间，最终以固定握点整体搬运手臂链。不要每帧回到 rest pose 重做腕部旋转，或单独给腕和辅助骨叠互不一致的扭转。
- 手掌正确而手臂占满镜头时，查看整个肩肘支撑链与镜头的关系。只把手调对、只把锁骨旋转，不能保证前臂轮廓成立。画面右移优先使用相机空间整体展示偏移，保留手和杖的接触关系。
- 握杖手指保持接触。自然移动来自肩肘带动和步频；空闲左手可以增加小幅分指滞后、松弛弯曲及走跑两套周期，并在停止时平滑归零。不要每帧随机抖指，或围绕手腕平移整条左臂导致肩部入镜。
- 新手臂网格还要按实际资源完整路径注册装备 profile。相同骨架和相同材质外观并不意味着已进入手套／衣袖系统；接入细节见 [第一人称装备](first-person-equipment-workflow.md)。

FPSGAME 当前案例：`Weapons/Staff/StaffGripPose.cpp` 的释放基础表使用 `StaffAuthoredReleaseAnatomy20261001.h`，积蓄使用 `ChargeFlow20261001` 修订 `2026100102`；两段统一按原生肘铰链与前臂 roll 混合。V13 与 `CastElbowRepair20260930` 保留为抓握和历史输入，不再直接承担当前释放右臂。`StaffFreeHandPose.cpp` 使用 V16 左手步态，`StaffCastMotion.h` 保留 V14 向右偏移和 V17 蓄力前移。作者链在 `SourceAssets/ApprenticeStaff20260927/`；V10 是掌向输入，V13→V14→V16→V17 仍是有效制作依赖。V12 和 V15 的旧运行头已退役，不能按目录版本号清空上游输入。

用户此前明确接受了掌向，但多次否定腕臂形态；这些方法和当前源码不等于整套动作已获视觉验收。以用户最新截图和反馈为准，编译、数学拟合与游戏认可分别报告。

## 两段施法右肘（2026-09-30）

V13 的抬杖、发射与收势存在上臂/前臂轴向关系不一致，裸臂与锁子甲共同继承；枪械检查不能推广到法杖。完整局部姿态、骨长正确和辅助骨随段运动都不能单独排除肘部塌陷。

当时的 `CastElbowRepair20260930` 保留各握柄的待机、掌向和指部接触，只修四个施法键的额外轴向旋转。按本 rig 实际站位，把修正分配到上臂、前臂和各自肘侧 twist_02；肩侧 upperarm_twist_01 与腕侧 lowerarm_twist_01 保持组件空间变换，通过局部补偿锁住手与辅助骨端点。肘侧辅助骨应随对应骨段完整修正；当时的半角方案增加局部边长，已在制作中撤换，不能把按站位线性分角视为普适正确。后续用户再次否定释放腕臂，本方案不作为当前释放母版；原历史比较范围仍保留如下。

用户授权的定向离线比较覆盖四握柄与两段施法及各自收势、裸臂作者表面和当前锁子甲三档 LOD，共 1176 样本；发射轴向差回到各握柄待机水平，局部压缩与边长改善，手指/握点保持。不是实机穿模验收。记录和可编辑源入口见 `Docs/Weapons/staff-cast-elbow-20260930.md`；默认不因此追加游戏或其他武器测试。

## 左键后举下砸（2026-09-28）

初版普攻使用独立的 `StaffPrimaryAttackMotion.h` 和 V27 完整局部姿态（已由下文 V28 替换），保留 V13 握点、掌向、指部及四种握柄接触。五个关键姿态覆盖抬举、后举、接触、下压和回弹；不能只转杖体、继续套待机整臂支撑。跨过水平线时使用连续旋转平面，避免每帧以杆轴重建坐标架造成整腕翻转。

动作、镜头和判定共用攻速缩放后的时钟；真实命中顿帧只暂停该动作，表现抖动不进入伤害扫掠。世界阻挡从实际接触姿态恢复，每次动作只给一次主冲量。角色在更新镜头前推进动作，PostPhysics 再发布同帧握点和整臂。姿态表编入 C++，Blender take 是同源可编辑交付，不代表另有 UE 动画包需要导入。

### V28：用户否定 V27 的腕部主导动作

用户仅认可 V27 的方向，指出整臂参与不足，允许手和武器后撤出屏。当前普攻改为 `PrimaryWholeArmV28`：用肩位置、上臂和前臂方向制作原生骨长的正向运动学，腕部相对前臂的握姿固定；先后撤到相机后方，再肩部前送、伸肘下砸。`StaffGripPose::BlendLocal` 对肩肘采用略有先后的局部混合，`ContactFromArm` 从同一真实父骨链推导杖握点。不要再次独立插值手／杖轨迹后，把混合整臂围绕手腕强行对齐；这会削弱肩肘运动的视觉主导关系。

## 持杖积蓄连续整臂试作（2026-10-01）

用户授权的新积蓄试作 `ChargeFlow20261001` 使用实际入场、轻收、肩部抬起、肘部跟进、压稳及既有 Raised 终点。初版 `2026100101` 保留 V7 抓握、原生骨长与 2026-09-30 肘侧辅助骨处理，但随后被用户指出肘与上臂严重扭曲；该版不是已认可的腕臂母版。五个新键作为一次连续 cubic B-spline 的控制点，不能在每键重新 ease 到停。运行与可编辑 Blender take 使用同一组正权重；控制点不要求逐个经过作者地标。

`StaffGripPose` 为普攻和积蓄分开缓存动作表；积蓄禁用普攻的额外肩肘局部相位偏移。骨骼与 `ContactFromArm` 使用相同局部混合，真实手父链生成握点，入场与恢复只保留必要整体 frame correction。提前释放准备从当前完整姿态接入。源码、源文件、构建生效范围见工程 `Docs/Weapons/staff-charge-flow-20261001.md`；这是供用户参考的试作，尚无实机观感认可，本记录不授权追加测试。

### 2026100102：按解剖铰链重建积蓄右臂

初版的握点和原生骨长保留，并没有排除肘部侧弯：肩、上臂、下臂局部四元数独立混合，肘逐渐收向画面内侧，再固定肩侧、腕侧辅助骨的组件空间端点做反向补偿，会继续扭曲骨段的轴向关系。2026-09-30 修肘源可保留为掌向与抓握输入，不能直接当作新轨迹中段的人体工学保证。

修订保留四握柄、五控制姿态的手与杖接触、掌向及手指抓握，重新制作完整肩—肘—腕。以原生两骨长度解算；本动作相机厘米空间的肩终点为 `(-9,16,-14)`，肘部 pole 从实际手掌与已认可的 carry 腕姿反推前臂方向，再按原生骨长解肘圆；固定镜头外侧 pole 会造成该掌向的手腕侧折，因此不采用。上臂框架从本 rig 真实 rest 弯曲平面建立，肘按固定铰链屈伸；前臂 roll 由实际掌宽向量的投影取得，幅度限制为 45°。这些坐标与上限属于本动作，不能直接套到其他骨架与握姿。

四根 upper/lower twist 保持完整 rest-local 关系，随所属骨段运动，积蓄不再固定辅助骨端点并做子骨反向补偿。运行时积蓄专用分支先按 spline 权重混合肘屈伸与前臂 roll 标量，再组装局部旋转；不能重新退回下臂任意四元数独立混合。可编辑 Blender take 使用同源规则。积蓄阶段停止额外 carry 肘扰动，让骨骼发布与 `ContactFromArm` 使用同一 FK。

既有技能时钟、四握柄手部接触及握点终点 `(49,26,-8)` 保留；该修订不改普通攻击或其他施法阶段。实际保存、构建与编辑器生效范围见制作目录 `ElbowRepair/integration-completion.json`；未进行游戏测试或渲染，观感交由用户体验，不把制作完成写成视觉验收通过。

## 释放与收势接续右臂（2026-10-01）

积蓄修订后用户提供截图，指出释放时右上臂和肘仍然扭曲。根因是积蓄终点使用 `ChargeFlow20261001` 修订 `2026100102` 的 `RaisedSettled`，释放下一帧却切回旧 `CastElbowRepair20260930` 的键 1..4；两套肩肘与辅助骨逻辑不同，肩位置相差约 24.3 cm、肘约 17.3 cm。旧 Release、Follow 的下臂轴分别偏离原生铰链平面约 62.8°、68.9°，合金握柄约 61°、67°。握点、骨长与此前离线比较并不能保证完整右臂连续，这次反馈撤销旧释放方案作为人体工学母版的依据。

`ReleaseAnatomy20261001` 保留 Idle、Run，Raised 完整复制当前积蓄终点；Windup、Release、Follow 从肩锚点、实际握掌和原生骨长重建。肘按固定原生铰链屈伸，前臂 roll 来自掌宽投影并限制在 45°；四根 twist 保持 rest-local 关系。四握柄的指部、掌向和手在握点中的变换保留，实际参数以新目录 `authored-parameters.json`、`full-pose.json` 为准。

释放与积蓄统一按权重混合肘屈伸、前臂 roll 标量，再组装下臂局部旋转。释放与恢复的杖握点由同一真实手父链 FK 生成，停止独立握点插值后围绕手腕拖动整臂；施法时也停止 carry 附加肘扰动。姿态缓存必须包含新释放与积蓄两张表的 revision。时序仍为 0.035 秒前置蓄势、0.18 秒接触、0.28 秒前挥、0.10 秒停留、0.42 秒恢复。

制作记录见工程 `Docs/Weapons/staff-release-anatomy-20261001.md`。可编辑源实际保存、构建与当前编辑器生效范围以新制作目录 `integration-completion.json` 为准，不将 Live Coding 补丁与基础 Editor DLL 更新混为一项。没有追加游戏测试、渲染或 UE 启动；新版尚无用户视觉认可。

## 副手手枪替代空闲左臂（2026-09-29）

法杖手模与副手枪各有自己的左臂来源。装备副手枪时，在法杖手模上隐藏 `clavicle_l` 子树并停止空闲左手和左手施法求值；卸下副手时恢复。自定义姿态若仍上传左链，统一折叠到同一肩部锚点，不能只把各骨缩放为零却保留不同位置，否则走跑时仍可能出现拉长残面。

只处理左链，保留右链与独立挂在相机下的法杖装配。若右手与杖延迟出现，先分清资源未就绪和可见性错误；不能据此继续扩大隐藏范围。整套资源驻留、异步完成及装备动作起点见武器技能的 [长杖接入](../../ue5-weapon-workflow/references/staff-modular-production.md)。

释放横向出杖时，carry 腕姿反推的 pole 只能作为肘圆搜索 seed；直接套用会选到反面弯曲平面。ReleaseAnatomy 在原生肘圆上联合约束实际腕姿与上一控制上臂的旋转变化，当前相邻上臂控制仅约 4–9°，肘保持腕下方；不把仅限幅 forearm roll 当作排除腕部扭转的保证。实际参数保留在作者源 authored-parameters.json，尚待用户观感测试。
