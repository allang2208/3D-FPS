# 旋转技能：镜头帧同步与连续蓄势

案例：大旋风V4，用户已确认旋转错位修复成功，后续蓄势优化后反馈整体没问题。动作与业务入口见 [大旋风技能](../../ue5-skill-magic-workflow/references/whirlwind-melee.md)。这些数值是当前剑的合同，不是所有武器通用参数。

## 先分清错帧与模糊

1. 先读取实际加载的动画、姿态层及挂点链。手臂和剑应共用同一骨骼采样及 `WPN_root`，技能活动分支应跳过待机、走路、普通攻击覆盖。只凭手和剑重影，不能断言存在两套动画。
2. 如果动作逻辑旋转相机，要看它相对 `PlayerCameraManager` 缓存POV的时序。UE5.8本案例原 `TG_PostUpdateWork` 晚于相机缓存，造成新前景姿态与旧渲染视角错一帧。技能活动时改为 `TG_PostPhysics`，保留角色tick前置依赖，结束/取消回到正常组；镜头、手臂和武器先更新，再让引擎缓存视角。不要通过同帧反复更新相机掩盖顺序问题。
3. 高速镜头运动的全屏模糊与TSR历史是另一层问题。当前大旋风暂时关闭全屏运动模糊，色调映射后只采样背景；前景手/肩/武器使用模板231和边缘保护。该遮罩不能消除已经进入TSR结果的历史重影。
4. 本案例为前景原材质制作独立副本，输出 Temporal Responsiveness，施放时复制动态参数并临时替换，结束恢复原材质、覆盖层和模板状态。依赖启动配置 `r.Velocity.TemporalResponsiveness.Supported=1`；原贴图和全局TSR保留。用户确认的是综合效果，不能把所有重影单独归因于TSR，也不能将这套材质强制应用到其他动作。

## 0.5秒蓄势的节奏

- 不要把回拉、蓄住、展开每一段都做独立零速度的 smoothstep；段数越多越容易形成停一下再走的跳帧观感。
- 当前V4使用共享节点速度的五次Hermite曲线，节点加速度连续：0–140ms回拉、140–340ms带微动减速蓄住、340–500ms展开。500ms节点带非零速度进入横扫；只在真正反向的轴上减速到零。
- 武器位置、握柄方向、刃面展示角共用作者时钟，双手以同一握柄为约束，保留抓握和骨段长度。镜头的-720度在运行时驱动，FBX不重复烘焙。
- 业务总时长1.82秒，480Hz资产为874个采样间隔，实际资产约1.820833秒；由运行时阶段映射处理，不用资产尾差改变接触或冷却合同。

## 从实际显示姿态进入

- 切换技能clip之前捕获当前显示的完整骨骼姿态。第零帧保持该姿态，前100ms混合至技能当前采样；这100ms包含在蓄势时间内，不额外增加施放延迟。
- 在骨骼父空间混合，保持骨段长度。武器骨与双臂共用权重；按两只手相对共同武器骨的握持变换求目标，之后两骨IK修正肩肘，必要时锁骨小幅协助。
- 手指与辅助骨保留局部关系。武器骨及其子骨作为握持目标，不随手臂IK再次搬动，否则会重现双重偏移。
- 本例由剑专用 `URuneSwordMeshComponent` 在骨骼缓冲区发布前完成姿态混合，再更新剑身挂点。混合到期或动作退出释放快照。不要让独立Tween在另一个tick中再次写手/武器变换。
