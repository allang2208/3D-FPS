# UE5 第一人称手臂与换弹动画

用于游戏视模动画。FPSGAME 默认工作区为 `D:/FPS3D/FPSGAME`，旧 Godot HK416 仅作用户指定的动作/音频参考。当前用户选择保留 M4，按 HK416 动作意图适配；不能为追求“100%”复刻而替换枪型或宣称不同枪体接触位置完全一致。

## 开始每个动作

先实际查看已有视频、动作表或源模型渲染，读取 FPS、帧范围、时长、循环、接触帧及运行状态。记录左右手职责、起势—接触—收势和机械行程，再制作；不能只读取 clip 名称。缺少背面/深度时说明是三维适配。

排查顺序：实际加载资产/弹匣分支 → 源姿态与 rest/权重 → 部件坐标与接触 → 导入压缩 → 运行时姿态层和事件时钟。先定位首次出现差异的层，不用全局缩放、长混合或大幅转指掩盖问题。

## 当前动作合同

- 项目统一手模：用户于 2026-09-10 指定以后所有枪械默认复用当前 M4 的手臂和手套（源 `SK_Manny_Arms_Export`），AKM 同样适用。保留网格与已接受的材质基线；用户要求衣物/手套替换时按下方装备表现标准调整，针对枪型适配骨架绑定及接触；不得自动退回旧 WRAD/Cubic 手模。最新运行源按角色代码核对。

- 普通弯弹匣：普通和空仓都先甩出旧弹匣；左手退到镜头外取新弹匣，完整抓握插入、压实。第一人称取弹不等于已制作背部实体弹匣袋接触。
- 非空仓装好后直接恢复腰射待机；空仓保留最后拍击/枪机释放。装备与切枪在该枪的腰射位置播放拉栓，避免先摆到画面中心。
- 右手食指保持自然弯曲；左手包握弹匣，不以指尖捏持。保留已确认的手型、甩匣和握持；弹鼓是独立动作分支。
- 当前空仓末次挥手比旧版快 50%，接触后有短促轻震；这是 M4 当前基线，不是其他动作的全局播放倍率。

## 读参考动作先分辨"哪只手做什么"（2026-09-17）

复刻参考视频的动作时，**不要按自己管线的既有分工去假设手的分工**。ASH-12（Oden）空仓换弹的参考里：枪身**向侧滚转约 60°**，**左手扶住护木不动**，**右手**离开握把去拔插身后弹匣井里的弹匣、再拉机匣右侧的拉机柄。这与本项目 M4 的"枪身基本直立、左手甩匣取匣"完全相反。

做法：先抽关键帧放大到能分辨手指与袖口，逐帧确认 ① 枪是否滚转（侧翻）还是俯仰让开；② 每只手在各阶段的位置与职责；③ 机械件（弹匣井、拉机柄）在侧翻后朝向哪只手。只看到"有只手在弹匣井附近动"就默认是自己管线里的那只手，会把整套动作做反——ASH-12 案例已发生过一次，返工整段。

### 换掉基底动作的机械层时要整层改写，不要叠加（2026-09-17）

用已认可的枪型动作当基底、只改"分工"时，**先逐帧量出基底自己动了什么**（`Scripts/measure_roll.py`、`inspect_base_motion.py`、`inspect_mag_track.py` 这一类脚本），再决定改写还是叠加。ASH-12 空仓换弹实测到的三处污染：

- M4 空仓换弹自带 `WPN_SOCKET_Magazine` 甩出 **0.7 m** 的弧线、右手**全程钉在握把**、机匣自身滚转到 ±100°（帧 18 −46°、帧 24 +101°）。本枪弹匣若按"叠加位移"写，会跑到井下 0.55 m；本枪的 60° 滚转叠上去实测到 141°，枪几乎翻过去。机械件的**位置与朝向**都要按 `pose[bone] = pose["WPN_root"] @ Translation(局部点)` **整体改写**；机匣表演取片段帧 0 的世界矩阵再叠加本片曲线。
- **手指也要一起冻结。** 只锁手骨不够——基底片段的手指仍在做它自己的取匣开合，会出现"左手扶在护木上却张合五指"。两手连同五指按帧 0 的**机匣局部矩阵**整体放置（`holds[side]`），位置由作者路径给、朝向固定为在这把枪上的自然持握。
- **机械音效的 cue 帧就是编排帧。** M4 系（含 QBZ191/ASH-12/M1911 之外的 `bUsingM4Infima` 分支）空仓换弹在**片段自身 21/54/80/130 帧**触发匣出/入匣/压实/枪机，按秒数直接比较。把片段重定时（时间扭曲）会同时把姿态推离声音：ASH-12 上一版实测出匣晚 0.38 s、压实晚 0.83 s。要改节奏就改 cue 表，不要只改姿态。

### 手臂路径先量可达性再写（2026-09-17）

写作者路径前先量 **肩点（机匣局部）+ 臂长**，再算每个目标点的占用比；`build.py` 这类脚本里应打印超伸告警。ASH-12 实测：右肩 `(-0.001, 0.342, 0.207)`、臂长 0.55 m；**支撑手在已认可的 idle 里就已占 97% 臂长**（护木抓点离肩 0.53 m），所以任何额外位移都会超伸。`shift_arm` 在 `d ≥ l1+l2` 时会**悄悄把肩点沿轴挪出去**，看起来就是肩关节断裂——超伸不报错，只会静默变形。过不去的一段改成"脱手让物件自己落出画面"（与 M4 合同的"甩飞旧弹匣"同构）比拉直手臂好。

### 复刻参考要先量出"哪一半在滚"（2026-09-17 第二轮）

只看"整段有侧滚"就把它铺满全程，是 ASH-12 第二遍返工的原因：第一版把 60° 滚转的峰值放在换弹匣那半段（帧 42/26%），而参考里**换匣时枪身只是斜着（25–35°），深度侧滚发生在拉栓那半段（62–90%），正是侧滚把机匣右侧的拉机柄转向右手**。四项分层各自占哪一段，要逐段量。

量法：① **HUD 弹药计数器是硬时间**——逐帧裁出计数器图，弹匣数跳变的那一帧就是"新匣入位"（ASH-12 参考里是整段的 31%）；② 帧差均值 >40 才是剪辑点，20 以下都是正常动作，别把快速动作当剪辑；③ 关键帧放大到能分辨手指与袖口，确认每只手在哪一段做什么。参考的整段时长量准之后，再把它按比例铺到工程片段的长度上（工程片段的长度与机械音效 cue 帧绑定，一般不动）。

### 换弹要量的两件事：看得见吗、穿不穿（2026-09-18）

**别用"好看的评审相机"判可见度**，那是自欺。改用游戏真眼位：从 ADS 标定反推（`ADSRearEyeDistance` / 照门后 18 cm 沿瞄准轴），再向目标顶点投射、统计首命中面属于谁（`probe_reload_visibility.py`）。ASH-12 实测：**斗牛犬弹匣只有下部约 35% 露在枪托外**，所以可见度上限就是 30% 左右；而滚转 15° 以下被枪托挡到 **0%**，30° 才 17%、45% 约 26%。结论：**换弹匣那半段的滚转不能省**，它不是为了好看，是让弹匣和井口从枪托后面转出来；想做参数取舍就用网格扫一遍（`sweep_mag_visibility.py`），别靠眼估。

**穿模要量网格，不能只探骨骼。** 骨骼原点、骨节末端的探针在 ASH-12 上只报出 5 mm，而手臂**网格**对枪体的实际穿透是 **116 mm**（数百个顶点在枪内）——用户一眼就看出来了。深穿透的常见根因不是手的位置错，而是**肘位**：`shift_arm` 这类 IK 默认继承当前姿态的肘，已认可持握的高肘会把前臂直接送进机匣/枪托。给 IK 加**极向量提示**（按阶段指定肘朝哪一侧摆）即可解决：ASH-12 取匣段肘朝下后方、拉栓段肘外展到射手右侧，拉栓段从 116 mm 降到 18.8 mm。

**量具自身的坑**：`BVHTree.find_nearest` + 法线朝内判据在离表面较远的点会误报（左前臂明明在机匣外 0.14 m 也被判"内部"）；奇偶射线判据在这套非流形网格上同样不稳。**只用相对量**（与已认可基线姿态的比值）下结论，不要相信绝对毫米数。

### ADS 手糊脸先量"眼到手"，别先怀疑手（2026-09-18）

ADS 下屏幕上一坨手/手臂，多半是**相机坐进了手臂**而不是手摆错了。判据：从真眼位到手臂网格的最近距离（`probe_ads_hands.py`）。ASH-12 实测 ADS 只有 **45.6 mm**（idle 10.7 mm）。根因通常两条：① 该枪的照门位置让 `ADSRearEyeDistance` 把相机推得比 M4 更靠后（本枪 18 vs M4 12 cm，等于比 M4 再退 14 cm）；② 换了布局的枪（斗牛犬枪托向后伸出 46 cm）与已认可的 M4 持握不兼容，前臂本来就插在枪托里（同一条量出 51–70 mm 进枪体）。**修法是给该枪的所有片段（不只换弹）加一条手臂极向量把肘绕到枪体之外，手不动**：ASH-12 实测眼到手 45.6→77.0 mm、进枪体 51.6→6.0 mm。顺带用 `render_ads_eyes.py` 按眼距渲染构图，别只调一个数就下结论。

### "手拿住东西"要量指尖到目标的距离（2026-09-18）

手的位置摆对了不等于**握住了**。按"腕点在目标右下几厘米"摆出来的手，实测指尖到拉机柄 **98 mm**——手悬在柄外一个手掌远。根因是冻结的手是**握把**的卷曲姿态，指尖相对腕点指向别处。改用**实测的腕→指节向量反推腕点**（`knuckle = index_01 − hand`，本机 0.098 m），腕点坐在目标后方一个指节长度处，指节就落在目标上：98 → 30 mm。同一只手还要配一个**拳**（各指节绕卷曲轴收紧），否则原姿态的扳机指会变成"戳出一根手指"。手朝目标转的角度要按 `TURN_SHARE` 分一部分给前臂，全压在腕上就是关节扭曲。

### 跨枪复用动作表要先对装配朝向共轭（2026-09-19）

同一张作者动作表搬到第二把枪上，**枪局部系合成的量**（枪偏移/倾角，`p['WPN_root'] @ …`）身体相对方向天然一致；**以臂架空间分量直用的量**（左手偏移、肘极、躯干平移）则会随装配朝向整体镜像。M1911 的 Manny 装配与其来源 715 在各自臂架空间里相差整整 180°（枪口 +Y/右手 +X vs 枪口 -Y/右手 -X，`WPN_root` 欧拉 (0,4.9,-180) vs (0,0,0)）——首版 1911 砸击 clip 因此左手甩向枪口方向、抬肘方向反、重心前后反，被用户判"动作语言不一致"。

- **判别法**：比对两枪 idle 的枪口方向与右手所在侧，一次采样就能量化装配差（`compare_idles.py` 的模式）。
- **修法**：由本枪 idle 枪口方向推 ALIGN（正则系→本枪臂架系的纯 Z 旋转），臂架直用量一律 `ALIGN @ v` 共轭；带断言"对齐后右手在正则系 -X 侧"防共轭方向搞反。绕 Z 的躯干偏航与装配朝向同轴、身体相对意义不变，不用共轭。
- **验收法**：正则系逐帧"动作增量差"（各自相对 idle 的位移再相减，消除 idle 框架差）。修复后 M1911 vs 715：左手 ≤3mm、枪 ≤5cm（残差是 1911 自带 4.9° idle 上仰，Z 分量≈0）、肘 ≤9.6cm（IK 非线性）。两枪 idle 框架本身差很大（左手位置差 28cm）时，直接比绝对位置没有信息量，会被基线淹没。

### 作者源基准必须核对"运行时那一代"（2026-09-19 第三轮）

可编辑源 blend 里堆着历代 action（M1911_idle / M1911_Contact_idle / M1911_P9_idle …），拿错一代
当基准，动作就会从错误朝向/错误持枪开始：M1911 砸击前两版分别表现为整段镜像（老代装配 180° 翻转）
与起收各一次 54cm 跳变（老代枪收胸口 vs 运行时枪前伸）。**核对法**：先在角色代码里查该动作运行时
实际加载哪条（如 `LoadAKMAnimation("A_AKM_idle")` → 每枪 `AnimationPath` 重定向到具体代目录），
再开 blend 取那一 action 采样；采样结果与运行时 idle 数值对不上（朝向/位置量级差）就停下查代。
另：判断"两枪动作语言是否一致"用各自 clip 相对**运行时 idle** 的增量差，不要用 blend 里随手取的
基准。M1911_Contact_idle 与 715 idle 逐位一致是巧合红利——同代装配直接同构，动作表原样直用，
共轭护栏（上一节）自动退化为恒等，仍值得保留防未来枪型。

### 视模动作的验收必须闭环到实机画面（2026-09-19 步枪砸击五轮教训）

**Blender 预览相机 ≠ 游戏相机**（游戏有视模组件偏移 + 运行时镜头层），同一版动作在预览里
"枪托穿过画面中央"、实机里"下沉出画"——离线的屏幕轨迹预测（自建相机模型）在标定前一律
不可信。步枪枪托砸击 A~H 八版里 D/E/F/G 都败在"离线模型自洽、实机读感相反"；直到用
`QuickCombatAudit` 夹具（`-game` 进程触发动作 → 逐帧记录枪托/枪口屏幕投影 + 相机/枪根
世界变换 + 30Hz 截图）拿到实机数据，才定位真因（G 实机枪托停在画面中心不再走、回旋仅
31°）并按实测方向性落参（H 版枪口横穿 + 枪托扫过中心）。

- **离线预览只做两类检查**：穿模/糊脸/手臂断裂这类相对量；节奏与曲线形状。
- **屏幕位置级验收只认实机**：量"打击端"（枪托/握把）的 u,v 轨迹 + 与相机距离。
- **骨架局部方向要用数据核**：M4 臂架 +Y 为前，枪托在局部 −Y——本轮探针 +0.26 量了一个
  假"枪托"（机匣前段）两轮才发现；作者脚本里的方向注释也可能写反，别信注释信投影数据。
- **方向性标定比全参数拟合可靠**：欧拉通道经轴变换强耦合，线性拟合残差自相矛盾；用
  配对实测（表值→游戏根旋转）取单调方向和量级，直接大胆外推再实测回收。
- 夹具跑法与产物结构见 `SourceAssets/RifleStockMelee20260918/README.md`（H 版段）。

### ADS 穿模要量"视锥+近平面+遮挡"，三维距离和纯视锥都会漏（2026-09-19 ASH-12 第七轮）

"眼到网格最近距离"不分方向——把网格移到**相机平面背后**后该指标照常报警，而背后根本不渲染；
纯视锥探针则把**近平面区**（forward < 几 cm）的顶点当"大 pitch/yaw 出锥"丢弃——恰好漏掉被
近平面切割、透视爆炸成大块楔形的部件（清晰斜边+尖角指向画面中部是近平面切割的特征签名，
NearClipPlane=1cm 的项目尤其如此）。三份实机图都分析漏掉右上角楔形、而"全组+遮挡"探针显示
右臂已清零，最后靠近平面探针（forward 5..80mm、右上象限、按材质分组）点名 38 个
upperarm_twist_01_r 顶点。**验收可见性的探针必须同时报：视锥内+遮挡后、近平面区、以及像素
级色块比对**（实体 vs 天空渐变，PIL 色带统计能救被视觉分析误判的结论）。

- 像素证据链：实体色（金属反天≈灰蓝 167,184,206）vs 天空白（230+）可分离；同色带 bbox 判范围。

### IK 只能动肘，肩根蒙皮要自己挪（2026-09-19 ASH-12 第七轮）

肘极向量/自然肘解算把手和前臂摆好后，**肩→肘的上臂连杆及其根部蒙皮仍横在 ADS 眼位旁**
（斗牛犬 18cm 眼距下肩根距相机仅约 7cm）。修法是给臂根解算加 `shoulder_shift`（解 IK 前平移
肩锚 A，肘随 IK 自动重解，手矩阵不变），把肩推到**相机平面背后**再下沉——上臂从画面下缘伸入，
即标准 FPS viewmodel 视觉。肩移后必须复测：视锥/近平面双探针、手臂陷枪体（防回退）、渲染构图。

### 臂架/机匣局部向量别直接当世界向量用（2026-09-19）

ASH-12 的机匣局部 +Y（枪口）经装配旋转映射到世界 **-Y**（且随片段姿态翻转）；按局部系直觉写
的"射手后方"肩移第一版推向了枪口方向。跨枪/跨姿态的清空偏移一律以**世界系**传入，或在注入
前用实测锚点（手/照门的世界坐标）验证方向——README 里写的坐标系约定和代码注释都可能与你
需要的方向相反，信探针输出不信注释。

### 换弹重定时用分段变速，别重写帧表（2026-09-19）

延长拔插弹匣段：编排帧表（滚转/路径/cue）全部保持在 M4 源帧空间不动，只在**导出时间轴**上
做分段变速（`BULLPUP_RETIME` 段表 (start,end,rate)，forward/backward 双射）——采样循环用
backward 映射回源帧，动画自然变长，60+ 个帧号一个都不用改。**cue 帧必须同步映射**
（21/54/80/130→23/66/100/158）并写进 C++ 的 ASH-12 专用分支——`bUsingM4Infima` 的 cue 值是
M4 共用的，直接改会错位其它枪。相机层曲线的中间锚点用 cue 相对表达式（(Out+Insert)/2 等）
而非硬编码秒，重定时自动跟随。json 的 reload 时长与动画新长度保持一致，播放速率才为 1。

### 相机动作层要按枪核对启用条件（2026-09-19）

换弹/装备相机层（`WeaponActionCameraComponent`）的启用条件里 `bUseM4Infima` 只在
`ue_m4a1` 为真——共享 Manny 姿态时钟的 ASH-12（`bUsingM4Infima=true` 但非 M4）**换弹全程
相机零抖动**且毫无报错。新枪接入动作相机层时逐枪核对 `(bUseM4Infima || bUseASH12)` 这类
条件，并给节拍不同的枪写专用 Follow/Impact 曲线（斗牛犬侧滚大，滚转跟随量级按 M4 的 1.5~2 倍）。

- 双手近战战术冲刺、左臂遮挡、就绪举剑、冲刺转攻击前摇和脚步同步：[近战战术冲刺](references/tactical-sprint-melee.md)。分开准备计时、姿态过渡和攻击接触时钟，保持两手握点。
