## 视觉落地

先找相邻面板的当前实现。工作台从 `M4GunsmithLayout.cpp`／`M4GunsmithOverview.cpp`／`ColdSteelEnhancementLayout.cpp` 复用结构；背包仓库从 `ColdSteelHUDWidget`／`ColdSteelInventoryWidget`／`ColdSteelInventoryPresentation.cpp` 复用。

主题只使用 `ColdSteelUIStyle` 的当前公共入口，`GunsmithUIStyle` 为像素字体兼容入口。中性黑灰、银白强调、低透明度玻璃；改变背景 Tint 不降低整个控件 RenderOpacity。保留原枪械库背景和工作台右侧完整详细汇总。子卡片共享模糊，分区用明度、细边和留白建立层级。

中文／普通 UI 为 Noto Sans SC，数字为 JetBrains Mono，工程内加载。字号档位、DPI 换算、玻璃参数和断点只查正式规则，避免在本参考复制数值后漂移。不要把 px 直接当 Slate 点数，也不要重复做 0.75 换算。

标题、页签、页脚和主要操作固定可达；内容独立滚动。平级按钮均分、同高同间隔，下拉标题整体居中并补偿箭头。长文本换行或提供全文入口；属性名与数值分列。仓库在左、背包装备在右，等大并保留开合动画。

## 数据规则不能随样式漂移

附魔卷轴：只使用背包中的正数量堆叠。同类汇总；未持有和仓库独有卷轴不生成卡片。持有但不兼容禁用；无卷轴显示空状态。列表、默认选择、报价、数量和 Apply 扣除同源；移出背包／用尽时取消失效选择。魔法粉尘、金币、强化石仍遵循原背包＋仓库来源。

仓库“存入同类”：操作开始时取得仓库已有 Definition 集合，排除武器和全部装备；沿用合堆、空间容量和一次保存事务。不要把换按钮文字当作完成业务替换。

空间背包：物品绘制、命中和拖放必须共用几何。拖动期间用源实例快照判定失效，最终提案提交继续核对 Generation；普通自动保存不应使未变化物品的拖动失效。详情见同目录 `fpsgame-inventory-input.md`。

数值对比：展示真实聚合结果，缺失值为“—”。收益／代价按指标方向判断，耗时与后坐降低为收益；不只看正负号。空装备槽、未持有卷轴、缺材料功能各自采用业务需要的显示／隐藏／禁用规则。

## 生命周期、图标与输入

- 显示由 OnChanged 等现有事件驱动；Construct 注册，Destruct 解绑。Tick 只处理必要几何和已有实时捕获。
- 模型负责 Quote／Proposal／Apply／Save；控件不能自己重复扣除材料或保存。
- 自绘 Slate 数据／画刷更新后使 Paint 缓存失效。动态图标始终保留目录图回退，成功后再替换成真实组合图。
- 图标完成只 SetImage 或更新画刷，不重建正被点击的按钮；保留选择、焦点和滚动位置。
- 复用图标子系统的失败退出和通知：一个任务的材质错误／超时不能阻塞整个队列；失败回退不能被描述为配件外观完全正确。
- 打开／关闭走现有控制器入口，保留输入模式、视角锁定、焦点恢复、拖动取消与菜单关闭顺序；关闭事件不能穿透为攻击。新 Tooltip／菜单按实际视口限位。

## 行内展开子菜单（2026-09-16，建造抽屉「其他构造」）

列表行需要「右侧按钮展开该行子项」时（建造面板材质行 → 其他构造），用**同级兄弟按钮**，不要把披露按钮放进行按钮的 content：Slate 里嵌套按钮的点击归属不可靠，点展开容易顺带触发行本身的动作。

- 结构：`CardList → Border(卡片底＋选中描边) → HorizontalBox[ 主按钮(Fill) , 披露按钮(固定宽) ]`；主按钮用透明常态 + 语义色悬停（`AttributeRow`）画刷，卡片底色与选中边框由外层 `Border` 负责，`RefreshSelection` 只刷这一层。
- 子项不新建浮层：直接插在主行下方（缩进 14px、深一档底色 `Content`、圆角 6px），与主列表同一滚动；展开状态放在 `TSet<FName>` 里，关抽屉再打开仍保持。
- 展开态不用箭头字形（Noto Sans CJK 的 ▲▾ 覆盖不稳定），改用**分类页签同一套「选中」样式**表示已展开，另把文案切成「收起构造」。
- 可见行顺序就是数字键顺序：重建列表时同步维护 `Cards`（控件引用）与 `VisibleCards`（浮窗数据），浮窗按同一个下标取数据，避免再按 ID 反查来源数组。
- 行内子项要携带**归属上下文**：形状条目点击时为「所属行 ID + 形状序号」一起提交（`SelectShape(材质, 形状)`），不要只发形状序号，否则选择会漂到别的行。
- 归属关系放数据（调色板字段 `Material`）而不是代码分支，后续新增构件只需改资产；空值落回通用分类。

## 图标卡片网格与统一取景（2026-09-16，建造抽屉「其他构造」）

一组同类条目（可建造的构造、配件、图鉴项）要"每个一张同尺寸卡片、等距横排、满行换行、卡里带图和名称"时：

- 布局用 `UWrapBox` + `SetInnerSlotPadding(间距)`，卡片用 `USizeBox` 固定宽高（116 × 150 px 量级），**间距与卡片尺寸都按 `PixelScale` 反算**，并在 DPI／视口变化时与字号一起重算；不要在建控件时把像素写死。
- 卡片结构：`Button(透明常态＋悬停提亮) → SizeBox → Border(Content/StatusCard, 8px 圆角) → VerticalBox[ USizeBox 图片 , 居中 12px 名称 ]`；选中态只改 Border 的画刷（`ButtonHover` + 2px `Accent`），和同一面板里的行卡片共用一套 `RefreshSelection`。
- 缩略图**不要另起渲染方案**：复用工作台的 `FPreviewScene`＋`T_StudioEnvironment`＋正交捕获＋`M_WeaponPreviewResolved`（`PreviewTexture` RGB→自发光、`PreviewCoverage` A→OneMinus→不透明度）双通道合成；`SetBrushFromMaterial(MID)` 直接贴到 `UImage`。
- **同一视角、同一缩放**的落地写法：固定一个旋转（如 `FRotator(-18,-35,0)`）＋正交投影；先算所有可见网格的世界包围盒，把整体平移到光轴中心，再令 `OrthoWidth = 包围盒最长边 / 0.78`。这样 20 cm 方块与 2.6 m 立柱在卡里一样大；要真实相对大小就改成固定 `OrthoWidth`（这是唯一需要跟用户确认的取舍）。
- 生成要**异步、限速、可缓存**：请求去重（键 = 形状/构件 ID）、每帧只跑一个捕获作业、结果按 LRU 缓存（上限十几个键），DPI 或缓存未就绪时先显示名称、就绪后只换图片，不重建卡片、不打断滚动。
- 体素类条目没有专用图标网格时，用同一枚体素方块网格按格中心（`格×20 + 10`）摆出形状即可；取景基于**包围盒**而不是 pivot，因此方块 pivot 在角上也不影响构图。
