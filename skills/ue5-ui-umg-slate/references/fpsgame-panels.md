## 视觉落地

先找相邻面板的当前实现。工作台从 `M4GunsmithLayout.cpp`／`M4GunsmithOverview.cpp`／`ColdSteelEnhancementLayout.cpp` 复用结构；背包仓库从 `ColdSteelHUDWidget`／`ColdSteelInventoryWidget`／`ColdSteelInventoryPresentation.cpp` 复用。

主题只使用 `ColdSteelUIStyle` 的当前公共入口，`GunsmithUIStyle` 为像素字体兼容入口。中性黑灰、银白强调、低透明度玻璃；改变背景 Tint 不降低整个控件 RenderOpacity。保留原枪械库背景和工作台右侧完整详细汇总。子卡片共享模糊，分区用明度、细边和留白建立层级。

中文／普通 UI 为 Noto Sans SC，数字为 JetBrains Mono，工程内加载。字号档位、DPI 换算、玻璃参数和断点只查正式规则，避免在本参考复制数值后漂移。不要把 px 直接当 Slate 点数，也不要重复做 0.75 换算。

标题、页签、页脚和主要操作固定可达；内容独立滚动。平级按钮均分、同高同间隔，下拉标题整体居中并补偿箭头。长文本换行或提供全文入口；属性名与数值分列。仓库在左、背包装备在右，等大并保留开合动画。

## 数据规则不能随样式漂移

附魔卷轴：只使用背包中的正数量堆叠。同类汇总；未持有和仓库独有卷轴不生成卡片。持有但不兼容禁用；无卷轴显示空状态。列表、默认选择、报价、数量和 Apply 扣除同源；移出背包／用尽时取消失效选择。魔法粉尘、金币、强化石仍遵循原背包＋仓库来源。

仓库“存入同类”：操作开始时取得仓库已有 Definition 集合，排除武器和全部装备；沿用合堆、空间容量和一次保存事务。不要把换按钮文字当作完成业务替换。

空间背包：物品绘制、命中和拖放必须共用几何。拖动期间用源实例快照判定失效，最终提案提交继续核对 Generation；普通自动保存不应使未变化物品的拖动失效。详情见同目录 `fpsgame-inventory-input.md`。

数值对比：展示真实聚合结果，缺失值为“—”。收益／代价按指标方向判断，耗时与后坐降低为收益；不只看正负号。空装备槽、未持有卷轴、缺材料功能各自采用业务需要的显示／隐藏／禁用规则。

## 生命周期、图标与输入

- 显示由 OnChanged 等现有事件驱动；Construct 注册，Destruct 解绑。Tick 只处理必要几何和已有实时捕获。
- 模型负责 Quote／Proposal／Apply／Save；控件不能自己重复扣除材料或保存。
- 自绘 Slate 数据／画刷更新后使 Paint 缓存失效。动态图标始终保留目录图回退，成功后再替换成真实组合图。
- 图标完成只 SetImage 或更新画刷，不重建正被点击的按钮；保留选择、焦点和滚动位置。
- 复用图标子系统的失败退出和通知：一个任务的材质错误／超时不能阻塞整个队列；失败回退不能被描述为配件外观完全正确。
- 打开／关闭走现有控制器入口，保留输入模式、视角锁定、焦点恢复、拖动取消与菜单关闭顺序；关闭事件不能穿透为攻击。新 Tooltip／菜单按实际视口限位。

## 行内展开子菜单（2026-09-16，建造抽屉「其他构造」）

列表行需要「右侧按钮展开该行子项」时（建造面板材质行 → 其他构造），用**同级兄弟按钮**，不要把披露按钮放进行按钮的 content：Slate 里嵌套按钮的点击归属不可靠，点展开容易顺带触发行本身的动作。

- 结构：`CardList → Border(卡片底＋选中描边) → HorizontalBox[ 主按钮(Fill) , 披露按钮(固定宽) ]`；主按钮用透明常态 + 语义色悬停（`AttributeRow`）画刷，卡片底色与选中边框由外层 `Border` 负责，`RefreshSelection` 只刷这一层。
- 子项不新建浮层：直接插在主行下方（缩进 14px、深一档底色 `Content`、圆角 6px），与主列表同一滚动；展开状态放在 `TSet<FName>` 里，关抽屉再打开仍保持。
- 展开态不用箭头字形（Noto Sans CJK 的 ▲▾ 覆盖不稳定），改用**分类页签同一套「选中」样式**表示已展开，另把文案切成「收起构造」。
- 可见行顺序就是数字键顺序：重建列表时同步维护 `Cards`（控件引用）与 `VisibleCards`（浮窗数据），浮窗按同一个下标取数据，避免再按 ID 反查来源数组。
- 行内子项要携带**归属上下文**：形状条目点击时为「所属行 ID + 形状序号」一起提交（`SelectShape(材质, 形状)`），不要只发形状序号，否则选择会漂到别的行。
- 归属关系放数据（调色板字段 `Material`）而不是代码分支，后续新增构件只需改资产；空值落回通用分类。

## 图标卡片网格与统一取景（2026-09-16，建造抽屉「其他构造」）

2026-09-19 当前建筑面板分类、字体、完整装配与预算统一见 [建筑面板标准](building-panel.md)。以下尺寸与取景条款已同步；后文有日期的故障记录保留其历史现场值。

一组同类条目（可建造的构造、配件、图鉴项）要"每个一张同尺寸卡片、等距横排、满行换行、卡里带图和名称"时：

- 布局用 `UWrapBox` + `SetInnerSlotPadding(间距)`，建筑卡片宽116px、最小高170px、间距8px。14px名称铺满102px内宽，横向排满才换行；长名称自然增高。**间距与卡片尺寸都按 `PixelScale` 反算**，并在 DPI／视口变化时与字号一起重算。
- 卡片结构：`Button → SizeBox → Border(Content/StatusCard, 8px 圆角) → VerticalBox[104²图片与状态占位, 居中14px名称]`；选中态用 `ButtonHover` + 2px `Accent`，和行卡片共用 `RefreshSelection`。
- 缩略图**不要另起渲染方案**：复用工作台的 `FPreviewScene`＋`T_StudioEnvironment`＋正交捕获＋`M_WeaponPreviewResolved`（`PreviewTexture` RGB→自发光、`PreviewCoverage` A→OneMinus→不透明度）双通道合成；`SetBrushFromMaterial(MID)` 直接贴到 `UImage`。
- 固定 `FRotator(-18,-35,0)` 正交视角；逐组件将局部包围盒角点投影到相机坐标后合并，按投影中心居中，较大投影尺寸除以0.84取景；单格减半占幅，即除以0.42。图片用 ScaleToFit 等比例完整显示，不拉伸、不裁切。
- 生成按需排队、去重，每帧最多一对捕获。键含 ID 与资源／装配签名；32项软 LRU 缓存保护当前列表，关闭取消待办和保护键。未就绪／失败有文字占位，就绪仅换图片，不重建卡片或打断滚动。
- 体素类条目没有专用图标网格时，用同一枚体素方块网格按格中心（`格×20 + 10`）摆出形状即可；取景基于**包围盒**而不是 pivot，因此方块 pivot 在角上也不影响构图。

## 让独立面板复用背包抽屉规格（2026-09-16，F6 开发面板）

已有面板要求「跟背包一样大小、一样的弹出收回动画、打开时一样的隐藏界面规则」时，不要复制一份新的动画参数，也不要把它塞进 HUD 控件树；按下面的最小改动做：

- **尺寸与位置同源**：`Anchors(1,0,1,1)`、`Alignment(1,0)`、`Offsets(-NavigationDrawerInset, 12, Width, 12)`，宽度 `min(视口宽 − RightInset − 12, clamp(视口宽 × 0.48, 720, 1040))`。改用 Canvas 的 `SetOffsets` 之后不要再留旧的 `SetPosition`/`SetSize`，否则锚点不同源，窗口变化时高度会回到旧值。
- **一条进度驱动全部动效**：`DrawerProgress = FInterpConstantTo(Progress, bOpen, Delta, 4.f)`，面板 `RenderTranslation.X = (1 − Progress) × 抽屉宽度`，全屏 40% 黑底与面板 `UBackgroundBlur` 的 `RenderOpacity = Progress`。面板与黑底在 `bOpen || Progress > KINDA_SMALL_NUMBER` 期间保持 `Visible`，进度归零才 `Collapsed`——基础实现里的 `SetPanelOpen` 会立刻收起，必须在覆盖函数里把可见性交还给动画。模糊补 `SetOverrideAutoRadiusCalculation(true)` 与低画质回退画刷，才和背包的玻璃一致。
- **让位规则合并进同一个标志**：HUD 侧新增 `SetExternalDrawerOpen(bool)`，把三处让位条件统一成 `bInventoryOpen || DrawerProgress > KINDA_SMALL_NUMBER || bExternalDrawerOpen`（右侧入口列、世界时钟、右下武器详情）。面板打开时置位，收回动画播完再复位；`NativeDestruct` 必须直接复位，否则销毁路径不会跑完动画，HUD 会一直缺这三块。
- **输入与层级**：打开沿用抽屉的 `FInputModeUIOnly`＋鼠标光标＋忽略移动／视角＋`SuspendWeaponForMenu`，关闭恢复 `GameOnly`。独立控件不在 HUD 控件树里，只能靠视口 ZOrder 决定覆盖关系：要像背包那样压暗 HUD 就必须高于 HUD（本项目 30，HUD 20）；代价是 HUD 内 ZOrder 90 的升级提示会被自己的压暗底盖住，所以这类面板要在面板内自带一行结果反馈。

## 开发面板类功能栏目（2026-09-16，基本调参页）

给开发面板加「生成物品／提升等级／提升技能」这类功能时，先确认哪一层是权威数据，再决定控件形态：

- **物品目录来自实际加载的数据**：工程从 `Content/ColdSteelData/items.json` 建定义表，开发面板不要另读一份 JSON 或在代码里写死清单；在模型上加一个只读目录入口（定义 id、显示名、归纳类别与排序键），首次访问时解析并排序，之后复用。下拉用一个 `UComboBoxString` 承载「类别 · 名称」即可满足分类，同类别条目靠排序键连续排列；条目控件 `SetAutoWrapText(false)`，避免长名称把行高撑开。
- **技能目录等于存档键**：可提升技能用 `ColdSteelSkills::Migrate` 建立的同一组键（当前 12 项），名称取 `MasteryDefinition`，等级取 `MasteryProgress`。不要用界面上的卡片顺序或临时表作为可选集合，否则会出现校验拒绝的脏键。
- **等级／技能提升必须满足存档校验**：等级提升沿用 `(20 + Level×20 + Level²×12) × 8` 的经验门槛（经验必须小于当前门槛）、每级 +3 属性点；技能满级必须把修炼值清零。全部走 `SyncRuntime → Snapshot → CommitState`，升级提示由既有 `QueueProgressNotices` 自动发布，控件不自己写存档或发通知。
- **开关型开发项要同时守住「扣」和「退」**：像「建造不消耗资源」这种闸门，扣料入口跳过时，失败退回入口也必须跳过，否则放置失败会给玩家凭空补一份材料。判定放在组件内的一个 `IsFreeBuilding()`，让两条路径共用。

## 选项条与数值框：同一面板内字号与高度同源（2026-09-21，F6 开发面板怪物页）

用户反馈「选项条里的字太小」时，先核对它属于哪一档，而不是随手加一两个像素：

- **角色判定**：下拉条目、数值输入框是**控件**，用 14px 档（Noto Sans SC 条目／JetBrains Mono 数值），不是 12px 辅助说明档。10.5px、13px 这类数字属于表外字号，正式规则 §4 只有 24/20/16/14/12/11 六档；同一面板的下拉共用一个条目生成函数，不要为某一页单列一个更小的 `GenerateXxxOption`。
- **高度同源**：控件高度取共享 `ColdSteelUI::ActionHeight`（36px），让同一面板的下拉、数值框与按钮等高。给 UMG 控件定高必须包一层 `USizeBox`，而 **`SBox` 只把子控件排到 `Min(可用空间, 子控件期望尺寸)`**：只设 `HeightOverride` 不设 `WidthOverride` 时，`UComboBoxString`／`USpinBox` 会缩回内容宽度（下拉条突然变窄）。两个 override 都要给。
- **宽度用实测值，不要用算式**：`UScrollBox` 的滚动条是否占位取决于内容是否需要滚动（`SScrollBar` 不可滚动时期望尺寸为 0），按「视口宽 − 滚动条宽」推算会算宽，右端箭头被裁。取**同页满宽兄弟控件**的 `GetCachedGeometry().GetLocalSize().X`（本项目直接用同页说明文本行）；它与选项条同在一个竖排，滚动条、抽屉宽度、视口变化都会同步反映。页面未显示时该值为 0，跳过即可，切页后下一帧自动对齐。
- **不要每帧写尺寸**：`SetWidthOverride/SetHeightOverride` 每次调用都让布局失效。写入前比较控件实测尺寸与目标尺寸，只有不一致才写；既避免无谓的每帧失效，也能在 DPI 改变（目标高度变化）后自动重算。
- **只改外观时别动反射数据**：这次改动全部落在 `.cpp` 函数体内（条目生成函数、`StyleChoice` 的 `SetContentPadding`、`StyleCount` 的字号、`NativeTick` 的对齐），不新增 `UPROPERTY`／成员变量、不删 `UFUNCTION`，因此可以直接 Live Coding 热更，不必为了几处字号让用户关编辑器重链。另注意 `SetContentPadding` 只影响收起态按钮的内缩；下拉列表的行距来自 `FComboBoxStyle::MenuRowPadding`，它只在 `SComboBox` 构造时读取一次，运行期 `SetWidgetStyle` 改不动它。

## 运行时缩略图缓存：不能淘汰"正在显示"的键（2026-09-17，建造抽屉）

异步出图的抽屉（建造面板的 `UVoxelBuildIcons`、改造台预览等）出现「部分卡片没有图片」时，先算**一屏需要的键数**，再对照缓存上限，最后检查控件有没有重贴路径：

- **症状与成因**：建造抽屉一屏需要 3 张材质行 ＋ 每材质 5 个体素形状＝**18 个键**，而 LRU 上限是 16。第 17／18 张出图时淘汰循环挑走 `Uses` 最小的键，也就是**最先出图、已经贴在卡片上的那两张**（木制材质行与木制「单格」）；`RefreshIcons` 只对"还没有画刷"的图片贴图，于是这两张被释放 RT 后就一直空白。表现是"某一栏的一部分条目没有图片"，且日志里**没有** `failed` 记录——不是捕获失败。
- **修法一：给显示中的键加保护**。子系统加 `SetVisibleKeys(TSet<FString>)`，抽屉重建卡片后把当前 `Cards` 的键整体声明进去；淘汰循环跳过这些键，全部都在显示时宁可临时超过上限也不让卡片变空图。集合相同时直接 return，避免每帧重建哈希表；用 `bIconPinsDirty` 在重建后置位，由 Tick 一次性提交。
- **修法二：画刷失效要能自愈**。`FCard` 保存建卡时的请求结构，`RefreshIcons` 改成：`Find` 命中但 `GetBrush().GetResourceObject()` 不是同一个材质实例就重贴；没有图且没有画刷时按原参数重新 `Request`（失败键由子系统去重，不会每帧排队）。只判断"有没有画刷"是不够的——被回收后画刷还在，重贴逻辑必须先比较实例。
- 排查顺序也可以是反向的：先看缓存上限是否小于"一屏键数"，再看出图／淘汰／贴图的时序（本例：重建 → 每帧出 1 张 → 淘汰 → 贴图被跳过）。

## 同类构造的取景归一化要留"按内容缩小"的口子（2026-09-17）

第四版定的规则是「所有条目按包围盒最长边归一化到画面 78%，卡里看起来一样大」。用户随后要求**单格 1×1 体素块缩小 50%**，说明"全部一样大"只适用于同一量级的构造：

- 在请求结构或子系统里留一个取景比例参数（`OrthoWidth = MaxDim / (IconFillFraction × FrameScale)`），而不是给不同卡片改图片控件尺寸；卡片网格、图片区、间距与 DPI 反算保持不变，只有画面内的物体变小。
- 按**内容**判定，不按位置判定：本例用 `Cells.Num() == 1` 识别 1×1 体素块，于是材质行左侧 28px 缩略图（键 `shape:<材质>:-1`）与「其他构造」里的「单格」卡片一起减半；1 平方米地块／墙面、1×5 直线与构件预览取景不变。改 `Image` 尺寸会让同一网格里的卡片大小不一致，用户会立刻看出来。

## 子菜单卡片的 ID 属于谁：形状归材质、构件归自己（2026-09-17，建造抽屉）

同一个 `AddGridCard` 同时服务两种行，ID 归属不同，写错就会"点了没反应"：

- **形状卡**（材质行展开出的 5 种体素构造）由所属材质行代持：`CardId = MaterialId`，点击走 `SelectShape(材质, 形状序号)`，一次动作同时设置材质与形状。
- **构件卡**（同材质构件、门）必须始终用**构件自己的 ID**：`CardId = Entry.Id`。建造抽屉曾写成 `CardId = bChild ? MaterialId : Entry.Id`，
  于是子菜单里的门／罗马柱点击变成"选材质 + 把构件清空"，画面表现是"选了还是停在之前的构件上"，且卡片永远不会亮起选中描边。
- 自检：卡片点击应产生成对日志——`点击卡片 id=<构件 ID> component=1` 之后紧接 `SelectComponent 请求=<同一个 ID> 生效=<同一个 ID>`；两者不一致就是 ID 归属写错了。
- `FCard` 同时存 `Id／bComponent／ShapeMode`，`RefreshSelection()` 的选中高亮也读同一份，所以 ID 修正同时修好点击与描边。

## 分类：先看材质，没材质才丢「其他」（2026-09-17 用户口径）

构件在抽屉里的归属由调色板 `Material` 字段唯一决定，**不要**再按"是否同时出现在两个列表"实现：

| `Material` | 出现位置 |
| --- | --- |
| 填了材质 ID（`wood`／`stone`／`marble`…） | **只**出现在该材质行的「其他构造」里 |
| 留空（`None`） | **只**出现在「其他」分类 |

`RebuildCards()` 的「其他」分支据此过滤 `Entry.MaterialId.IsNone()`；实例：三扇材质门分别挂 wood／stone／marble，
铁门留空只进「其他」。空列表要给出明确文案（「暂无未归类的其他构造…」），不要留一张空网格。

## 交互反馈：不要顺手占用提示栏（2026-09-17）

升级提示栏 `UColdSteelProgressNotification` **自带音效**，所以每次 `PostNotice` 都会有声。开关门这类高频、无信息量的操作
不要再往提示栏写文案（否则玩家每次开门都会听到升级音）；失败诊断写 `UE_LOG` 或走面板自己的状态行。
需要玩家看见的反馈（材料不足、背包已满）才用提示栏。

## 行式卡片与网格卡不能共用一套 DPI 重排（2026-09-19，建造抽屉）

一个控件树里同时有「行式条目」（材质行：36px 行高＋28px 缩略图）和「网格卡」（其他构造：116×150＋104² 图标）时，
`RefreshLayout` 里对 `Cards` 的无差别循环会把两类尺寸互相写坏——材质行登记进去的盒子拿到网格尺寸，视口或 DPI 一变
材质行就被撑成 150px 高的大卡片（首次布局不触发：那时 `Cards` 还空，所以只在改窗口后才暴露）。

- 判据放数据不放层级：`FCard` 加显式 `bGridCard` 标志。**不要**用 `bChild`（子菜单）推断——「其他」分类的网格卡也是 `bChild=false`。
- 重排循环按标志分流：网格卡重算网格尺寸，行式条目只重算自己的行高与缩略图尺寸（常量提成 `MaterialThumbPixels` 一类名字，不留在函数体里当魔法数）。
- 自检：改窗口宽高或 DPI 后，材质行行高、缩略图尺寸应与初始一致；不一致就是这个循环没分流。

## 抽屉的数字键归属要在控件与组件两侧同时收口（2026-09-19，建造抽屉）

抽屉（可见行编号）和建造态（调色板顺序快捷键）是两套数字键语义。只在控件侧做可见行映射是不够的：
控件未命中可见卡时若放行，组件侧 `HandlePanelKey` 会按**调色板顺序**兜底——材质分类只显示 3 行时按 `4`，
会选中一个当前没显示的构件并立刻关抽屉开建。

- 控件侧：`NativeOnKeyDown` 数字键只有命中可见卡才 `Pick`，未命中直接 `Handled()` 吞掉。
- 组件侧：`HandleInput` 里 `bPanelOpen` 时数字键完全归控件（组件返回 true 吞掉，不落调色板）；面板收起（建造态）才走调色板顺序。
- 两套语义的按键处理都必须以「面板是否打开」为总开关，不要试图用帧标记（`DrawerKeyFrame`）覆盖全部路径——帧标记只防同帧双发，防不了兜底分支。

## 独立抽屉要一次接全：位移＋压暗底＋玻璃淡入＋让位＋销毁清让位（2026-09-19，建造面板）

「和背包一样的弹出收回」= 同一条 `FInterpConstantTo(..., 4.f)` 进度驱动**四个**表现，缺一个玩家立刻看得出来：

1. 面板 `RenderTranslation` 滑出距离；
2. 全屏 40% 压暗底 `RenderOpacity = 进度`（`Border`，ZOrder 在面板之下）；
3. 玻璃 `UBackgroundBlur` 的 `RenderOpacity = 进度`（文字保持清晰，别对着外层整体降透明度）；
4. HUD 让位：打开时 `HUD->SetExternalDrawerOpen(true)`，**收回动画播完**（进度归零）才复位。

- 压暗底用 `HitTestInvisible`：建造面板没有「点外部关闭」，不能吞掉回到瞄准后的点击；有外部点击关闭的面板才给 `Visible`。
- 销毁路径不跑动画：`NativeDestruct`（控件）与 `EndPlay`（组件）各留一条直清让位的路径，否则 HUD 三块元素（右侧入口列／世界时钟／右下武器详情）会一直缺位。
- 参照实现：`DevelopmentPanelWidget::TickDrawer`（让位时序）、`ColdSteelHUDWidget::BuildInventory`（压暗底与玻璃层级）。

## 跟随光标的浮窗：关闭按钮要"够得着"（2026-09-19，建造抽屉）

浮窗每帧钉在光标外 10px（防遮挡）时，指针永远在浮窗外——`HideTooltip` 里「指针在浮窗内则保持」的分支几何上不可达，
关闭按钮永远点不到。修法不是删按钮，是给浮窗一个**跟随→钉住**的两段行为：

- 显示后跟随一小段时间（0.7s）自动钉住位置，之后指针可以真的移到浮窗上点 ×。
- 钉住后指针离开浮窗**和来源卡片**（含 44px 余量）才收起，避免浮窗挂在屏幕上不走。
- 换卡片要重置跟随计时（`bSameCard` 判定），不然悬停第二张卡时直接钉住、不再跟随。
- 指针命中判定用控件缓存几何的 `AbsoluteToLocal` 局部坐标＋余量，不要用屏幕矩形手算。

## 缩略图尝试计数只记失败，放弃只记一次（2026-09-19，建造图标）

异步出图的"尝试计数"如果成功也累加，被 LRU 回收后需要重建的键会在 3 轮后永久拒绝（卡片永久空白）；
放弃分支放在 `Request()` 里每帧打日志，抽屉打开期间就是逐帧刷屏。正确口径：

- 计数只在**失败**时递增、成功后清零（`GIconAttempts.Remove(Key)`）。
- 放弃改用一个 `GIconGaveUp` 集合：达到上限时加进去并打**一条**警告，之后 `Request` 静默跳过；`Deinitialize` 清空两者。

## 页签下标与枚举值不是同一套编号：必须显式映射（2026-09-24，图鉴品阶页签）

图鉴怪物页签是「全部／普通／精英／领主／首领」，刻意**不列** `Minor`（当时九只身份没有一只用它）。
过滤却写成 `Category != SortKey + 1`——这等于假设「页签下标」与 `EMonsterRank` 枚举值重合。两者不重合时**每一阶都错位一格**：毒蛆（Elite）显示在「领主」页签、手脑（Lord）显示在「首领」页签，且没有任何怪物能出现在「精英」页签下。

这个缺陷**只看「全部」页签时完全正常**，所以很容易漏过。正确口径：

- 页签一旦省略枚举中的某些取值，就**禁止用 `枚举值 + 偏移` 反推下标**；用「页签 → 枚举值」映射表比对。
- 加 `static_assert` 保证映射表与标签表等长，避免日后加页签忘记同步。
- 校对时逐个取值核对归属，不要只验证默认项（默认项就是会掩盖错位的那一项）。
- 对照：同一面板的武器页签与 `WeaponCategoryKeys` **同序同长**，按下标取用是安全的——差别就在"是否省略过取值"，判据是这个而不是"用了下标"。

## 窄列里 AutoWrapText 会把中文逐字竖排（2026-09-24，图鉴页签／卡片／返回按钮）

`AutoWrapText(true)` 放进等宽窄列（如页签、卡片战力格、居中按钮）时，中文会被**逐字换行成竖排**。图鉴的页签、返回列表按钮、详情行标题都中过这一条。

口径：**短标签、页签、标题、数值一律 `AutoWrapText(false)`**，只给成段正文和可换行长标题开自动换行。落地时把换行与否做成标签辅助函数的参数（图鉴里 `Label()` 默认换行，`TabLabel`／`LeftLabel`／`ValueLabel` 默认单行），而不是逐个调用点手写设置——漏一处就是一处竖排。
