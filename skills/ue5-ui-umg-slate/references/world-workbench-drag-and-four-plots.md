# 工作台拖动与四位置种植

FPSGAME 2026-11-08 至 11-10 的世界面板经验。保持现有冷钢 UI、背包格尺寸和统一事务；不是所有面板都应改成此布局。

## 世界武器交互

- 场景输入区不得覆盖背包。以真实 viewport host 将 Slate 绝对坐标转换为像素，使用 `USlateBlueprintLibrary::AbsoluteToViewport`，不要重新评估 DPI 曲线推算窗口原点；后者会造成能看见却点不中。
- 命中容差在屏幕空间根据实际展示范围设置；避免把用于防剔除的膨胀 BoundsScale 直接当作精确点击区域。拖动阈值、背包接收范围、被面板遮挡区域应分别处理；不能扩大到抢占背包或底部按钮。
- 台上拖动复用 `UColdSteelDragVisual`、当前装配图、目录图回退及细长物品等比尺寸。按背包响应格宽、占格和当前朝向显示，图标中心跟随鼠标；不要另做不一致的文字拖牌。
- 拖影只读取暂存快照；异步图标完成仅刷新活动拖影，不重建操作列表。松手、取消、失焦、关闭与销毁都移除覆盖层和回调。等待图标沿现有队列，不增加独立 Tick 或轮询。
- 只有背包接收且复核来源／会话／快照后才进入原取回事务。拖到台面、装备栏、外部或满包不移动物品。右键、按钮和拖动必须共享持久化与 Pending 规则。
- listen-host 的同步网络回执可能已经播放成功仪式；Confirm 不得随后再次刷新播放。金／蓝粒子、落桌回弹、轮廓和阵纹是展示，不提交第二笔交易。

## 强化／附魔面板

本次需求是材料用简短文字、不另加材料滚动条，删除重复消耗汇总，把空间留给详细强化前后数值；不是删除整个面板必要的正文滚动。固定标题和底部操作，真实武器卡片在正文中；不通过缩小背包适配窗口。附魔卷轴筛选、持有范围与可用性需同源于实际扣费数据。

## 四位置种植与旧 16 格

- UI 显示 2×2 四个完整种植位，不把存储的 4×4 小格直接露给用户。四位映射锚点仍为 0、2、8、10；新播种胡萝卜也占一个完整位置。服务端单株与批量入口都限制完整位置及每床最多四株，不能只在 UI 限制。
- 不迁移、删除或移动旧档小格胡萝卜、非对齐植株或超四株数据。按真实占地归属位置，同格多株可重复点击轮换并逐株收获；跨位置同一株只统计一次。先保留收获入口，再限制新增播种。
- 位置图保持 2×2；宽度足够时与详情并排，窄窗上下排列，不能变成误导容量的长列表。正文独立滚动；裁剪后不可见的格子不得抢占底部按钮点击。
- 等待权威回执时禁用提交／切换／拖动；新快照到达剔除已占用选择，关闭和失焦释放捕获。新 UI 不更改旧植物 ID、时钟、存档字段或网络格式。
