# 工作台面板、直接制作与枪械组装

## 先分清交互与结算

常规工作台和弹药制造选择配方、批量后直接结算，不放小游戏、假进度条或完成后废弃按钮。枪械组装沿用工件流程：支付材料、分件安装与校准、完成后领取或放弃返还一半。未来枪型走 `gun-assembly.json` 的配方、分件路径与目标/散件变换，复用同一运行系统；仍需制作分件资产和布局数据，不等于只填枪名。已支付工件保存实际材料、配方 ID、分件顺序，不能随新目录重排历史工件。

## 冷钢规格必须落到实际布局

- 对照当前打铁和枪械面板，复制共享字体、卡片内沿、数字列、状态语义与 36px 操作高度；单拷构建树会漏掉 `UpdateScale` 里的下拉按钮、行高、字体、菜单背景和箭头居中。
- 制造栏与背包等宽贴边：主抽屉先按双栏可用宽度夹取，制造栏 `WB=Width`、`WBDock=Width+RightInset`。从打开到关闭动画结束均用 `bWBOut` 保留几何，不能只在 `bWorkbenchOpen` 为真时布局，也不要再减一次剩余宽度缩窄副栏。
- 配方名必须在刷新时写入标题。预览尊重纹理真实宽高比；参数区允许独立滚动，窄栏改上下排，短标签不自动换行。
- 点击制造栏误收起，先读 HUD 的实际外部点击判断；常规栏与枪械栏要选当前可见控件做几何命中判断。打开/关闭动画期间由 HUD 传递 `SetInputReady`，防止穿透与误触。

## 下拉行的 UObject / Slate 生命周期

`UComboBoxString::OnGenerateWidgetEvent` 用反射 `UFUNCTION` 绑定。生成行返回拥有自身 `WidgetTree` 的 `UUserWidget`（本工程 `UColdSteelGunRecipeOptionWidget`）；裸 `NewObject<USizeBox>` 子树被下拉 Slate 缓存，关闭/切页和 GC 后可能留下无效 UObject 引用并崩溃。`UUserWidget` 的 `SObjectWidget` 承接跨层引用；DPI 行缓存用弱引用，菜单关闭后不过度保活旧行。父面板和点击代理仍各自遵守 `UPROPERTY` 与解绑规则。

## 数量、容量与提交是同一笔事务

- 材料上限、批量、产量分别显示；材料不足时最大批量为 0，不能强行显示可做 1 次。先夹取批量，再计算需求与不足提示。
- `CanCraft` 和 `Craft` 共用 `PrepareCraft` 的快照扣料、产物放置逻辑，再用 `CommitState` 提交；有材料但背包放不下仍不可制作。弹药走既有弹药袋，不能生成另一份背包弹药对象。
- 组装完成且未领取才允许放弃。逐材料对工件实际支付量向下取整一半，完整返料能放下才原子提交；清空工件与返料在同一状态内完成。面板预览与系统提交读取同一返还计算，不按当前配方重新估价。
- `OnChanged` 标记刷新并失效关联预览；解除绑定放在销毁流程。避免每帧全量查配方/重建材料行，也不能只缓存预览而忽略模型更新。

源码入口：`ColdSteelWorkbenchWidget`、`CraftingSystem`、`ColdSteelGunAssemblyWidget`、`GunAssemblySystem`、`ColdSteelWorkbenchHUD`。本机制作与公开仓库接入边界分别记录；交接补丁和已构建宿主不得混称。默认不启动编辑器或游戏自测，依照用户要求交付。

## 木工复刻铁匠面板时的具体边界

- “复刻”包括顶部配方下拉、配方序号、材料表、成品与属性预览、说明、底部操作，以及完成后返回同一管理面板的领取/半料返还流程。不能用选择卡片代替下拉，或用一张结果浮窗代替成品管理。
- 管理面板沿背包实际抽屉进度滑入/收起，同步裁剪与输入门控；小游戏相机和实景控件只在加工阶段持有。短文字默认横向单行，宽度不足调整布局，不逐字挤成竖排。
- 阈值、材料、工件状态与评分修正读取系统真源。木工现行 80% 废料清除、20% 主体损伤上限不是独立 UI 常量；品质得分另映射为 ±25%，显示实际伤害通道。
- Slate 绘制时若要把首点追加到点列闭合轮廓，先复制值再 Add；`Points.Add(Points[0])` 会触发 TArray 对容器内部元素别名的断言。
- 锯齿提示绑定真实锯片/刀口变换，避免使用固定屏幕偏移。红边材质要应用到实际可见材质槽，同时考虑顶点透明度与曝光；调整态/切割态沿同一刀口几何更新。资产导入保存与实际高亮观感分别记录，未运行不能宣称视觉验收。

状态与结算见 [工件品质契约](../../ue5-cpp-gameplay/references/paid-workpiece-quality.md)。
