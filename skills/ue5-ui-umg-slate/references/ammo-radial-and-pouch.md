# 动态弹种轮盘与弹药袋

用于 FPSGAME 的 R 轮盘、弹药袋子页及弹种图片。玩法事务见 [数字弹药袋](../../ue5-weapon-workflow/references/ammo-pouch-and-types.md)。沿用冷钢共享字体、按钮和布局，不新建一套背包主题。

- 用已开放兼容弹种数 N 等分整圆，绘制和鼠标选区使用同一角度起点及 `2π/N`。不得把“三种弹”写死为三选项，也不以无弹数量删扇区导致位置跳变。
- 一次打开固定目录顺序，余额可刷新。中心为取消区，扇区边界用小幅滞回减少抖动；当前实现半径归一化死区0.30、外界0.96，边界滞回取4°与扇区宽10%的较小值。参数是当前交互起点，不是其他轮盘的通用定值。
- 类型较多时减少环上信息：当前≤6展示图标，≤8展示名字/数量，9–24显示编号，更密时只画扇区，中心展示悬停详情。选区覆盖所有 N 项，不能用显示上限截断数据。
- 鼠标移动只改变预选，松 R 才提交；中心/Esc取消。轮盘拥有鼠标轴和点击，避免同时转相机、射击或滚轮换枪。双持手枪改为左右两个盘同时弹出，手别完全由指针所在盘决定，点击只被吞掉（2026-09-22，替换原来的左右键选手别）。HUD 在完成换弹前显示旧弹种及目标提示，不提前显示已装填。
- **双持＝一个组件画多个盘**。步枪那套盘面（等分、等级色、图标、中心文字、效果摘要）原样复用，只把“一个盘”改成“N 个盘”：每盘各自持有实例、标题、可选弹种与悬停；`ComputeLayout` 给出每盘圆心偏移（左＝副手、右＝主手，水平间距 `2R+间隙`，`4R+间隙` 必须放进视口宽度），双盘盘径小于 300 屏幕像素时扇区文字与图标按 `R/300`（下限 0.70）等比缩小，单盘恒为 1。**指针是共用的一根**：以组中心（两盘正中的中点，等于单盘的中心取消区）为原点做位移积分，双盘时不再钳在 0.96 半径内，改为钳在视口内（留 8px），因此可以自由穿行两盘之间；只对指针所在的盘结算扇区与滞回，另一个盘的悬停立即清空。松 R 只提交活动盘那一只手，两盘之间或盘心都算取消。非活动盘压暗到 60% 并显示该手当前装填，活动盘描一圈外沿。一只手取不到物品时退回单盘，不画空盘。
- **轴值不是像素**。`Turn/LookUp` 收到的是经过 `Config/DefaultInput.ini` 轴配置缩放后的值（`MouseX/MouseY` 的 `Sensitivity=0.07`），1 个屏幕像素只有 0.07。轮盘手感必须按像素定义：输入层用 `UPlayerInput::GetAxisProperties(EKeys::MouseX)` 还原成像素，轮盘内再按 `fps.AmmoWheel.PixelsPerRadius`（默认 180，下限 40）折算半径比例。2026-09-21 之前的实现直接按轴值除以 200，实际要跨屏约 2857 px 才走满半径，表现为“很难拖动”。相机侧的口径（`AddControllerYawInput`）本来就是按 0.07 设计的，不要在轴配置里改灵敏度去迁就某个面板。
- **刷新不得整树重建**。弹药袋页挂在 `Model->OnChanged` 上，而 `OnChanged` 每次成功存档都会广播，广播时显示内容通常完全没变。`ClearChildren` + 重建 `SScrollBox`／全部 `SButton`／图标会让行的悬停和按下态随旧控件一起丢失，看起来就是无操作闪动。做法：先按模型采集视图模型并生成内容键（DPI、武器、展开集合、分组顺序与总数、每行的文本／颜色／数量／可用性／图标），键不变直接返回；重建时才写 `SetScrollOffset` 还原滚动位置。键要覆盖所有会改变画面的字段，否则显示会滞后。
- **写盘频率决定广播频率**。存档是"落盘 + 回读 + 校验 + `OnChanged` 广播"的同步事务，一次约 101 KB。2026-09-21 之前是定时每 5 秒无条件写一次、训练待写盘时最快每 1 秒补写一次，并且击杀、闪避、近战命中、左轮逐发装填各自仍走即时事务；现在定时写盘由 `fps.Save.AutosaveSeconds`（默认 300 秒）驱动、只在有未写盘增量时写，进度型事务（击杀、命中与技能修炼）统一走 `StageTraining` 并入该周期，玩家主动事务、升级与退出仍立即写盘。做面板时不要假设"存档每秒都会发生"，也不要为了刷新及时而把周期调回秒级。细则与代价见 `Docs/UI/autosave-policy-20260921.md`。
- **盘面材质：整盘必须读作一块面**。用户 2026-09-22 反馈"中间有间隙、扇区没有拼合"：中心孔是**本意**（半径 30% 内的取消死区，同时承载盘心文案，提取为 `AmmoWheelDeadZone` 供绘制与命中共用），但扇区各缩进 `min(.016, Step×.04)`、只有外弧一根线、没有底盘，缝隙直接透出世界，这就是缺陷。做法：① 外沿 `R→1.055R` 暗环阴影；② `Inner×.92→R` 连续底盘（`Content`→`GlassTint`），扇区落在这块面上，缝里露底盘；③ 扇区三环渐变做玻璃厚度、角向缝收到 `min(.0045, Step×.012)`、悬停外沿抬升 1.03R；④ `Inner×.94→1.12` 内圈环（深—亮—深三环 + 两道 1px 细边）把所有扇区内沿连成一圈，中心孔因此是"凹陷玻璃中心"而不是断口；⑤ 等级色只作标记：内圈标识弧（可用＝等级色、当前装填＝银白、已用尽＝35%）与图标底板（`CardRadius` 圆角、底混 18%／边混 45%），**不给扇区整片染色、不做彩色描边**；⑥ 半径 `R` 一整圈 1px `Border` 收口，双盘时活动盘再描 2px 银白；⑦ 盘心两层凹陷玻璃，指针进死区时边线转银白。层级顺序：阴影→底盘→扇区→内圈环／标识／外沿→盘心→图标底板与文字→指针。
- **相邻元素留净空，缺图走纯文字分支**。用户 2026-09-22 第五轮反馈"调整弹药名称位置"：缩图标格时只算了图标本身，名称盒上沿（128.0）压在图标凹槽内沿（123.0）上整整 5 px——调元素位置必须逐对算**实际边界**（不只是中心距）。做法：`NameDrop` 8→18、`CountDrop` 29→26，代价由图形承担（图标格 86→80.2 px，中心裁切仍把主体放大 1.22 倍），结果凹槽↔名称净空 5.0 px、名称↔数量间隔 5.0 px、数量内沿 78.0 正好落在盘心外沿上。同时 `icon` 为空的弹种（.45 ACP/.357/12.7mm）**不画图标与凹槽**，只有名称与数量，按无图标分支排在中线 0.67R 附近居中——缺图不留占位、不留空框，也不要拿别的口径的图顶替。
- **矩形元素按"整格内接"算，不能只算外沿**。用户 2026-09-22 第四轮反馈"图标又超出了整个面板"：把内容挪到扇区中线之后，96 px 的图标格在 30°／150° 扇区**四角**距离达到 251 px > R=240 而戳出盘沿——轴对齐正方形相对中心在半径方向多出 `√2/2 × 边长 ≈ 0.707 × 边长`，只验算"沿半径的外沿 ≤ 0.97R"不够（12 点方向的格子碰巧不越界，所以前几轮没暴露）。改法：`Rim=0.97R`、`HubOut=Inner+6px`、`Side=clamp((Rim-HubOut-(NameDrop+CountDrop+12*Fit/Scale)-2px)/1.2071, 48px..96px)*Fit`（`1.2071 = 0.7071 角点余量 + 0.5 中心→内沿`）、`图标中心 = Rim − 0.7071×Side − 2px`；悬停放大**只向内长**（外沿与角点固定）。改完必须按扇区数复算一遍角点：3/4/5/6/8 档 + 高 DPI 全部过（6 档 240.0 ≤ 242.5、8 档 251.4 ≤ 252.2，已是 √2 最坏情况）。腾不出空间时按信息价值取舍：本轮把"当前装填／已用尽／待切换"从格内移到盘心（盘心本来就显示名称、剩余发数、松开 R 提示，当前装填另有内圈银白标识弧），图标格才从 71 px 回到 86 px。
- **格内内容必须沿扇区中线用极坐标排布**。用户 2026-09-22 第三轮反馈"各图标不在其扇形格子中间"：锚点虽然在中线上（`Center+Dir·0.67R`），但图标与三行文字都加的是**屏幕竖直偏移**（`-(0,24)`、`+(0,26/49/73)`），只有 12 点方向的扇区碰巧对齐，30°／150° 的扇区整组内容被推向一侧（实测切向偏心：图标 20.8 px、数量 42.4 px、状态行 63.2 px）。改成 `Dir=(cosθ,sinθ)`、`Along(ρ)=Center+Dir·ρ` 后，任意扇区数与角度切向偏心都是 0.0 px。同时先算清极坐标的几何上限：扇环 `Inner..0.97R` 只有 168 px（R=240），96 px 图标加三行文字就占满了，图标只能落在 0.77R——想让它居中于扇环中部就必须把文字移出格子（交给盘心），不要靠"再挤一点"。
- **小格子要裁切，不要缩整帧**。用户 2026-09-22 第二轮反馈"弹的背景色几乎把主体覆盖了"：等级图是整张不透明照片（7.62 那套的底板就是一整块等级色，5.56／手枪那套底色透明但主体同样只占约八成），轮盘图标只有 80–96 px，再加上一层等级色底板就是两层色块压着主体。做法：① 轮盘加私有 `UColdSteelAmmoWheel::FramedIcon(Id)`——复制模型那张共享画刷、只把 UV 收到中间 `AmmoWheelIconFrame`（0.82，一行常量），主体放大约 1.22 倍；**共享画刷不动**（弹药袋／背包／仓库仍用整帧）。裁切画刷放轮盘内部而不是模型：`ColdSteelStatusModel.h` 被大量文件包含，为观感调整让整模块重编不值当。② 图标格改**中性凹槽**（`Content` α150 + 1px `Border`），照片自带色场是这一格唯一彩色来源，等级色只留内圈标识弧；③ 图标 `min(96px, R×0.40)×Fit`，悬停 ×1.06——加大前先按 `Along(0.67R+24)` 验算外沿（96px 时 232.8 ≤ 0.97R）。弹药袋／背包格子大，继续用整帧照片。
- **UCLASS 头里插行会让单文件核对报假错**。`GENERATED_BODY()` 展开成 `<文件ID>_<行号>_GENERATED_BODY`，在 `UCLASS` 之前插了几行、而 UHT 生成头还是上一次的，`cl.exe` 单文件核对就会报 `C2143 缺少";"(在"class-head"的前面)` + `C4430 缺少类型说明符`；真实构建或 Live Coding 重跑 UHT 后自动消失。对策：能用既有包含链就别加前向声明行（`FSlateBrush` 在轮盘头里本来就有），必须加时按"行号会移动"预期结果。另两个同类坑：在 `UCLASS` 头里 `#include "Styling/SlateBrush.h"` 会先引入 `SlateBrush.generated.h`、打乱 `CURRENT_FILE_ID`（同样报 C2143/C4430，放在 `.cpp` 里则无碍）；`MakeShared` 返回 `TSharedRef`，`.Get()` 不能直接当裸指针返回，显式写 `TSharedPtr<T> X=MakeShared<T>(...)` 再 `X.Get()`。
- **HUD 径向控件不加矩形模糊**。抽屉用 `UBackgroundBlur`（强度 9／半径 21），但轮盘是圆形覆盖层、`UBackgroundBlur` 是矩形控件给不了圆形遮罩，硬加会破坏盘的形；改用分层中性玻璃表达同一套语言。这是 HUD 元素在本项目的既有取舍，写进设计规则第 16 节。
- 字号遵循六档 24/20/16/14/12：扇区名称 14、扇区数量 20（数字字体）、盘心标题 16、说明与提示 12～14；悬停项用 `TextFont(..., bMedium=true)`。非活动盘压暗只改**顶点色**（约 55%），不调 RenderOpacity，文字与图标保持清晰。
- 弹药袋接入“装备与背包”的子页，按兼容组聚合，现持枪组靠前；列表给出数量、状态和由目录数值生成的效果行。伤害百分比与穿透百分比分开描述。
- 行内右侧（数量、状态、分组总数）用**定宽列**：构建前按本页最长数量／状态量一次字宽，取最大值作 `SBox::MinDesiredWidth`，同一页所有卡片共用同一列宽；数量列 `HAlign_Right` 且 `AutoWrapText(false)`，位数变多时数字向左边延展。`STextBlock` 开着自动换行时期望宽度会跟着上一帧被分到的宽度走，右侧数字一旦被压到换行就会把那一行撑高，同页卡片高度随之参差——左栏（名称／效果／说明）应当是行内唯一可换行的内容。
- PNG 由角色子系统的 `UPROPERTY` 纹理缓存持有，Slate 画刷/按钮样式使用地址稳定的 `TSharedPtr` 缓存；不要把 TMap 值地址或临时 `FSlateBrush` 传给长期存在的控件。轮盘打开时预载图片，避免绘制过程中读盘。
- 等级配色使用 `tier_name` / `tier_color` 单一来源，同步列表卡片、图标底板与图片底色（轮盘上的等级色落在内圈标识弧与图标底板两处标记，不铺满扇区）。当前 7.62x39mm LP绿／PS蓝／AP红，5.56x45mm M193绿／M855A1蓝／M995红，5.8x42mm DBP87绿／DBP10蓝／DBP191红，.45 ACP FMJ绿／+P蓝／AP红，.357 MAG SP绿／JHP蓝／AP红；保持文字可读、选中轮廓独立可辨，不能只给包装改色而遗漏图标背景。档位多的口径按 N 自动多开扇区（5.56、5.8 与两种手枪口径现为三档），不把某一口径的档数写进布局。

概念图与运行 UI 分别记录。当前轮盘、图片及多类型布局尚无游戏内验收，不据概念图宣称实机效果已通过。2026-09-21 的轮盘灵敏度修正、弹药袋内容键修复与自动存档周期改动只有源码与逐翻译单元编译，实战手感、闪动是否消失、写盘频率手感由用户实测确认。2026-09-22 的双持两盘轮盘与盘面材质重做同样只有逐翻译单元编译（编辑器开着时可用模块自己的 rsp 直接调 `cl.exe` 核对，见 `Docs/UI/ammo-wheel-dual-pistols-20260922.md`），两盘位置、材质观感与提交手感待用户实测。
- **编辑器开着也能核对语法**：UBT 在 Live Coding 生效时会拒绝命令行构建，但 `Intermediate/Build/Win64/x64/UnrealEditor/Development/<Module>/*.obj.lc.rsp` 里留着该模块每个文件的真实编译参数。复制一份、改掉源文件与 `/Fo` 路径，在工作目录 `Engine/Source` 下用 `vcvars64.bat -vcvars_ver=<构建日志里的工具链版本>` 调 `cl.exe @rsp`，输出丢到临时目录，即可在不碰工程构建产物、不影响他人编辑器状态的前提下拿到逐翻译单元的编译结论。它不代替 UHT／链接／整模块构建。
