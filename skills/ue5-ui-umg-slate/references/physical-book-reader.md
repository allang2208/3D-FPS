# 物理书本阅读器与持续双面纸页

用于 FPSGAME 配方手册、装备书等把文字和图片直接画到模型纸面的阅读器。用户要求无背景板时，保留真实模型和直接交互，不另加不透明 UI 卡片。以下是已采用实现的约束，不要求所有书都使用相同尺寸、骨骼数或动画速度。

## 内容与纸页分工

- UMG 宿主负责打开、关闭、焦点和生命周期；页面控件负责目录/配方排版；预览桥负责输入和捕获；纸页组件只负责材质、骨骼和几何角色。通用纸页不拥有库存或制作事务。
- 私人目录与阅读页码是本地状态。只有当前操作者、当前已支付配方的页码意图才进入服务器工作站通道；浏览其它章节不切换制作配方，也不复制 RT/UMG 指针。
- 配方快照、页码及目录内容变化才重绘 RT。拖动只改变几何，静止阅读不按帧重绘文字。

## 翻完不刷新

FPSGAME 采用三个持久纸页实例、两个跨页 RT、各页正反独立材质。起动前先画目标跨页，仅绑定不可见的背面和下方待露出的纸面；正在面对读者的正面保持原纹理。

同一张纸翻动、落下并成为新的静止页。完成函数只更新逻辑页码、实例角色和 RT 的逻辑索引，不重新画字、不更换该页纹理、不隐藏落下的模型。被覆盖的旧纸页到下一次翻页准备时才复用。取消拖动让原纸返回；书签跳转也先准备目标内容再翻，不在动画尾部刷新。

固定 UV 的骨骼双面纸可以同时变形位置、法线和切线。按等长度分段驱动弯曲，保持两面厚度和对应关系。手动驱动的 PoseableMesh 在不 Tick 的预览 World 中仍需刷新骨骼变换；捕获白名单必须包含纸页，镜头范围使用稳定书壳，避免弯曲时取景跳动。

## 可读性、输入与释放

- 书签文字纹理的有效 UV 区域比例应匹配实体书签，不能只提高纹理分辨率。纸、布、金属分开处理反光；书签可采用适量可读性补光，不能用它掩盖错误的材质或 UV。
- 长按时间与实际位移分别判断。长按目录后未发生拖动，仍应允许点击；捕获丢失应回弹或结束拖动。首末页边界、目录和书签使用同一目标页解析。
- 关闭时取消异步加载/待翻页、释放 RT、页面 Widget 和渲染器，销毁前解绑捕获对象。迟到回调不能复活已关闭阅读器；再打开同一页也要重建已释放的印刷内容。
- UE 对象由 UPROPERTY/TObjectPtr 持有，Slate 资源在控件生命周期内保留。不要把材质、纹理或预览 World 的生命期寄托在临时裸指针或文件静态变量上。

## 导入后卡在加载提示

“异步资源已完成”不等于纸页初始化完成。材质槽名和槽数存在、但 `MaterialInterface` 为空时，MID 创建仍会失败，表面症状可能一直显示加载提示。

UE Python 的 SkeletalMaterial 数组元素是值拷贝：修改 `slot` 后需要 `materials[i] = slot`，再写回整个数组。检查实际材质引用及绑定到组件后的父材质，不只看槽名。详细材质/UV 处理见 [建模导入约束](../../asset-model-workflow/references/blender-hardsurface-checklist.md)。
