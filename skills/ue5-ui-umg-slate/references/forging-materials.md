# 锻造与制作材料的冷钢显示

适用于 FPSGAME 制作材料清单、已投入工件及领取／废弃界面。当前实例见 `Source/FPSGAME/UI/ColdSteelForgingWidget.*`、`Building/ForgingSystem.*`；颜色和字体以工程 `Docs/UI/ui-cold-steel-design-system.md` 与 `ColdSteelUIStyle` 为准。

## 颜色与排版

- 材料名使用 `TextPrimary`；所需数量、分隔符和表头使用 `TextSecondary`；来源说明使用 `TextTertiary`。只给持有数量及“已满足／缺 N”使用 `Success`／`Danger`，相等即满足。不要另造纯红纯绿或将整张卡片染色。
- 名称、数量、状态采用真实列布局。中文正文走 UI 字体，纯数字走数字字体，正文使用 14px，辅助表头和来源使用 12px，沿用 PixelScale 合同。数字右对齐并保持单行，长名称让出弹性宽度后换行；不要用空格对齐列。
- 缺额用文字表达，避免完全依赖颜色。数量统计与实际扣料调用同一模型入口；“背包＋主仓库”不能擅自扩展到世界储物箱、装备栏或祭品池。

## 区分需要与已经支付

- 准备阶段显示当前持有／需要。开始成功后改成“本轮已投入材料”，显示支付快照和灰白状态，不再因扣款后的库存不足标红。
- `GetPaidMaterials()` 是锻造已投入显示与返料报价的公共只读入口；旧存档缺少支付快照时复用系统的配方回退。不要在 UI 从折半后的返料数量反推投入，也不要为不同页面重复实现旧档回退。
- 实际领取、折半向下取整、背包空间检查及保存仍由制造系统事务处理。界面读取报价，不能先赠送返料再尝试清空工件。
- 有待处理工件时锁定配方并恢复它的成品预览；展示图不承担实景锤击评分。时长、目标总数、品质范围从系统字段生成，更新规则时同步所有摘要和说明。

## 行复用与交付

- 初始化按配方目录预建行，数据变更时复用；支付快照比当前目录多出的旧材料需要补行而非丢弃。新增行立即应用当前字体／DPI，因为全局 `UpdateScale()` 在比例不变时可能直接返回。
- 库存事件只设置脏标记；配方切换、开始、领取、废弃也触发更新。保留现有焦点、滚动位置、Construct／Destruct 解绑与抽屉输入门控。
- 增加原生成员需要完成基础 DLL 构建后才称为已落盘生效，不把仅写源码或 Live Coding 补丁当作下次启动可用。默认不启动游戏或视觉验收。

本实例材料分列已完成常规构建，未做游戏测试。审计中仍待实施的预览底板、时长摘要及窄窗重排，见 `Docs/UI/forging-cold-steel-audit-plan-20260927.md`；不要把计划写成已完成规范实现。
