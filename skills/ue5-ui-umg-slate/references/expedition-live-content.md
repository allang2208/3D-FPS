# 出征面板：真实奖励、规则与行前准备

用于冷钢出征/任务详情中空白的奖励或规则页。先按 `fpsgame-panels.md` 明确信息结构，视觉规格继续以项目冷钢设计规则为准，不另建一套颜色和字体。

出征页的控件角色以[冷钢正式规则第 3 节](../../../Docs/UI/ui-cold-steel-design-system.md#3-玻璃边框与布局)内的 2026-11-07 试点条款为准。单目的地也保留常驻下拉选择栏，多目的地使用下拉目录与筛选。横幅下方为任务情报和行前准备两张全高主卡；路线卡只列标题和主要奖励类别，按内容自然定高；其下增加怪物情况卡，列出大类与模糊活动描述，不列具体数量、点位或战斗数值。行前准备在各页签常驻，展示食物、水与饮品、药水以及当前武器备弹。出征资格与调整装备入口均沿用控制器。此试点只应用于出征面板。

用户指定的文字分层为金色标题、白色主要内容、灰色注释。复用 `HUDGold / TextPrimary / TextSecondary / TextTertiary`；具体用途与卡片、网格、分隔线均按正式规则。各张路线卡的名称使用金色，奖励类别使用白色，来源说明使用灰色；怪物大类为金色，活动描述为白色，情报范围为灰色。奖励物品名作为内容使用白色，奖励组名使用金色，浅底浮窗沿用其独立主题。

- 奖励候选读取实际掉落表的同一缓存，以只读 API 去重返回物品、可出现深度及最终档资格；不执行抽签或发奖。写明「可能获得」，最终数量倍率不代表所有候选都掉落。缺表时显示明确空态，不凭概念图编造物品。
- 名称、图标、稀有度和说明复用物品/弹药目录及共享浮窗。规则从已实现的进入条件、固定主题顺序、通关、返程、死亡和领取行为组织，不能把计划中的机制写成承诺。路线奖励摘要依据实际搜索池，注明主要类别，不承诺每次获得；怪物情报依据实际遭遇类，保持概括描述。 原因：物品转移涉及来源与目标两侧状态，部分成功不能造成物品丢失或重复生成。
- 物资只计背包与夹层中数量大于零的实际物品，按消耗效果分组，不计仓库。饮品同时列物件数量和剩余饮用次数；变质食物标注且不计可用量。备弹按当前武器弹种读取弹药袋，支持无限备弹、双持和独立副手，不含弹匣；法杖与近战显示无需备弹。缺项只是提示，出征资格仍由控制器执行。
- 「调整装备」隐藏并保留出征控件，同时打开现有个人主仓库与背包。关闭任一整备面板、Tab 或外部点击经同一关闭路径返回，Esc 优先处理拖动／详情。出征期间保留其自己的输入锁，整备关闭只释放背包的锁，随后恢复 UIOnly、光标、原目的地和页签，刷新物资；最终退出／换图取消返回回调并释放全部所属锁。HUD 析构先解绑，不能在卸载时重新打开面板。 原因：动作未正常结束也会离开当前状态，资源占用、费用和待结算结果必须有明确收尾。
- 大屏内容限宽居中，中屏重排，窄屏上下堆叠；奖励网格按可用宽度改变列数。信息缺失不靠增加空卡片或填满黑色区域解决。
- 奖励缩略图按可见页逐个后台解码并缩至有限尺寸，再在游戏线程创建纹理。纹理由 UPROPERTY 持有，异步回调使用弱对象并检查关闭状态，控件重建后的图片通过弱引用更新。源 PNG 不直接变成全尺寸 UI 纹理。
- 角色资料变化时刷新派生值和统计缓存；生命/魔法条读取轻量值。不要在 NativeTick 重复解析目录、重建整页或同步等待全部图标。 原因：高频显示路径会放大重复计算，按变化刷新才能保留同样内容而减少无效工作。
- 发布时同时携带新拆分的详情/准备 CPP、共享掉落预览接口、控制器声明和 ImageCore 模块依赖；只提交 Widget 外观文件会遗漏编译链。

案例入口：`Source/FPSGAME/UI/ColdSteelExpedition{Details,Preparation,Layout,Controller,Widget}`、`ColdSteelDungeonLoot`；规划记录 `Docs/UI/expedition-content-plan-20261001.md`。本经验源于该次制作，不代表自动执行过分辨率、输入或实机验收。默认由用户测试。
