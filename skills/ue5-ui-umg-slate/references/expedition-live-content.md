# 出征面板：真实奖励、规则与行前准备

用于冷钢出征/任务详情中空白的奖励或规则页。先按 `fpsgame-panels.md` 明确信息结构，视觉规格继续以项目冷钢设计规则为准，不另建一套颜色和字体。

- 奖励候选读取实际掉落表的同一缓存，以只读 API 去重返回物品、可出现深度及最终档资格；不执行抽签或发奖。写明「可能获得」，最终数量倍率不代表所有候选都掉落。缺表时显示明确空态，不凭概念图编造物品。
- 名称、图标、稀有度和说明复用物品/弹药目录及共享浮窗。规则从已实现的进入条件、固定主题顺序、通关、返程、死亡和领取行为组织，不能把计划中的机制写成承诺。主题顺序图标明它不是本局实际地图。
- 生命/魔法读取当前角色和档案；备弹取弹药袋并识别无限弹药，恢复品统计携带容器，不误计仓库库存。主背包空格数不承诺能容纳任意形状的大件。缺补给通常是提示，真正阻止出征的条件由控制器执行。
- 「整理装备」复用原关闭流程，释放面板自己持有的输入状态后打开背包。关闭/切页/角色更换要维持原焦点和输入合同。
- 大屏内容限宽居中，中屏重排，窄屏分页面；奖励网格按可用宽度改变列数。信息缺失不靠增加空卡片或填满黑色区域解决。
- 奖励缩略图按可见页逐个后台解码并缩至有限尺寸，再在游戏线程创建纹理。纹理由 UPROPERTY 持有，异步回调使用弱对象并检查关闭状态，控件重建后的图片通过弱引用更新。源 PNG 不直接变成全尺寸 UI 纹理。
- 角色资料变化时刷新派生值和统计缓存；生命/魔法条读取轻量值。不要在 NativeTick 重复解析目录、重建整页或同步等待全部图标。
- 发布时同时携带新拆分的详情/准备 CPP、共享掉落预览接口、控制器声明和 ImageCore 模块依赖；只提交 Widget 外观文件会遗漏编译链。

案例入口：`Source/FPSGAME/UI/ColdSteelExpedition{Details,Preparation,Layout,Controller,Widget}`、`ColdSteelDungeonLoot`；规划记录 `Docs/UI/expedition-content-plan-20261001.md`。本经验源于该次制作，不代表自动执行过分辨率、输入或实机验收。默认由用户测试。
