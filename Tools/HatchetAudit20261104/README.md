# 战斧接入检查（2026-11-04）

本轮检查覆盖当前战斧模块、三款通用斧刃图标、五种斧头的通用符文，以及单持／双持战斧的联机执行。后台运行，无 UE 编辑器界面，无画面渲染。以下区分已修复问题与未关闭问题。

## 已修复

1. **远端挂坠静止**：`ColdSteelModularSword::HangingDynamics` 仅构造武器 Definition 查找动态配方，但 `Catalog` 缺少战斧 Definition 对应的目录。补齐 `ue_tactical_hatchet → tactical-hatchet-modules.json`。实际 UDP 检查确认远端创建 `USwordTasselMeshComponent`，三款挂坠均覆盖。
2. **原装斧头第一人称符文失效**：导入脚本修改了材质槽结构体的临时值，没有写回数组。此前保存的原装 RuneCarrier 槽仍是 `M_TacticalHatchet`，与配方不符。改为结构体修改后写回数组，重新保存资产；独立进程冷加载确认独立槽名生效。第一人称及远端主副手都读取正确材质；拆除后恢复原材质。

源码修改、Editor Development 编译、修正资产保存均已实际完成。未创建发行版游戏包。

## 联机重击问题：已复现并修复

`Dedicated-20261104-160627` 曾出现双持重击无伤害，拒绝原因是 `heavy release not committed`。最初日志没有蓄力时间，随后普通复测和 8 轮重复通过均不能解释失败。继续排查后，使用真实 UDP 的包延迟改变稳定复现了同一拒绝链路。

- **修复前证据**：`Dedicated-20261104-164131`，客户端起手的 0.25 秒内将出站延迟从 60 ms 改为 400 ms，之后恢复；两端保留 3% 丢包。单持、双持各两次，共 4 次重击全部失败。客户端 `owner_assets` 日志显示手臂、单持／双持蓄力及释放动画全部已加载。
- **首个错误转换**：服务器以起手 RPC 的到达时间开始计时；释放 RPC 恢复正常延迟后，服务器只算出 1.633–1.668 秒，低于既有 1.85 秒门槛。拒绝释放后又清空蓄力记录，所以后续命中全部被拒绝。不是缺少重击动画。专用服 `animation_count=0` 是正常的表现资源隔离，结算不依赖第一人称动画。
- **生产修正**：`KukriHeavy.cpp` 起手 RPC 携带与普通攻击相同的同步服务器时间；限制回溯不超过 0.9 秒、未来不超过 0.1 秒，拒绝无效时间。活动蓄力不被重复起手重置，已取消起手不可重放，其他武器的停止消息不可清除当前蓄力。保持原有蓄力门槛和命中窗口。
- **体力结算**：正常帧扣费继续复用 `FPSStaminaModel`；成功释放时补齐规定蓄力时长中尚未被服务器帧扣费覆盖的部分，与出招体力一起检查并扣除。取消／普通点按不支付网络传输时间，重复释放不重复扣费。弯刀和战斧共用此修正。
- **同条件修复后**：`Dedicated-20261104-165305/receipt.json` 为通过，7 个场景全部通过：普通连击、4 次单持／双持重击、角色替换、同档案重连。真实命中仍经过重复报告检查；四次重击均只产生一次伤害事件，日志显示补扣 0.672–0.794 体力。服务器仍未加载第一人称动画。
- **确定性专项检查**：`HeavyClock-20261104-165614/result.json`，53 项检查全部通过，覆盖弯刀／战斧、单持／双持、资源未加载的专用服、过期／未来／NaN 时间、过早释放、取消、重复起手／释放／命中、命中先于释放消息、体力不足以及主副手卸装。夹具显式推进时间和扣除已观察时段的体力，不将这些函数检查冒充 UDP 实战；实际帧扣费由上述 UDP 复测覆盖。检查用临时世界现在正常关闭，退出无子系统销毁 ensure。
- **常规主机回归**：`Listen-20261104-165707/receipt.json` 为通过，14 个场景全部通过，含单持／双持六种攻击、角色替换和重连。此轮没有起手额外延迟，单持及双持重击日志均为 `catchup=0`。所有测试进程正常退出，最终 Editor Development DLL 已编译落盘；未打开 UE 编辑器界面。

复现参数：`run_combat_wire.ps1 -Mode Dedicated -HeavyCycles 2 -ChargeLagMs 400`。`KukriHeavyNetTrace` 默认关闭；延迟注入只存在显式启用的开发检查夹具。初次偶发失败没有完整时间日志，因此无法反推它当时的具体延迟数值；本轮关闭的是已确定并稳定复现的到达时间计时缺陷。

## 检查证据

- `saved-assets.json`：实际冷加载五种斧头 ×（无符文／三种符文），共 20 个组合；材质槽、实例、mask、等比制作参数、非斧头模块隔离；三款已保存图标的 UI 纹理设置。
- `catalogs.json`：改造目录与几何目录对应，三个最终 PNG 与部署文件一致；原厂模块注册脚本在隔离副本重跑后仍保留符文及原厂 carrier。基础距离弯刀／战斧都是 220 cm；间隔 0.8／1.05 秒，基础体力 7.5／10，战斧基础与强化伤害系数更高。
- `geometry.json`：读取真实 Blender 源网格并在实际 UV0 采样 15 张符文 mask；双面均位于预定斧头主体区域。厚背重劈／百炼弧锋无边界、非流形或零面积面。隼喙旧作者网格存在 4 个零面积微小三角；`saved-assets.json` 确认 UE 资产启用了 RemoveDegenerates。这项源网格遗留记录为制作清理项，不冒充已修改。
- `Wire/20261104-154934/host.json`：7 个真实本机 UDP 场景全部通过，覆盖晚加入、符文单独改变、换斧头、恢复原材质、卸装、重装、服务端保留实例后的重连。主副手、第一人称和双方第三人称材质逐一比较；不把预置库存夹具当作工作台上传测试。
- `Listen-20261104-160404/host.json`：14 个实战输入／服务器结算场景通过，含单持／双持连击、重击、上挑、风车、快速近战、冲刺攻击，以及角色替换、同档案重连。

- 网络两端配置各 60 ms 包延迟、3% 丢包；它们是模拟参数，不是实测 RTT。均为本机 UDP，不是跨机器公网测试。
