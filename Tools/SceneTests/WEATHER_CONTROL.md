# 村庄 / 战壕天气控制

项目：`D:/FPS3D/FPSGAME/FPSGAME.uproject`，UE 5.8.2。2026-09-09。

## 使用

- 游戏内按 **F6** 打开天气控制面板，点击所需天气；**F6 / Esc / 返回游戏**关闭。
- 左下角保留入口提示。使用现有 Alt 鼠标交互时也可以点击入口。
- 手动选择暂停自动天气，但昼夜继续运行；点击“恢复自动天气”重新根据当前时间排程。
- 雨量约 8 秒平滑过渡。面板显示场景、游戏时间、自动/手动模式、当前天气、实际过渡雨量及昼夜光照接入状态。
- 面板与背包互斥；打开时拦截移动、视角和游戏操作，关闭后恢复。
- 当前已运行的旧编辑器进程需要重启后加载新 C++ 类。新启动的独立游戏会直接加载已编译模块。

| 天气 | 目标雨量 | 室外雨滴发射率 | 水花发射率 | 音效 |
|---|---:|---:|---:|---|
| 晴天 | 0% | 0/s | 0/s | 停止雨声 |
| 阴天 | 0% | 0/s | 0/s | 无雨声 |
| 小雨 | 35% | 420/s | 63/s | 轻雨层为主 |
| 中雨 | 68% | 816/s | 122.4/s | 中雨层为主 |
| 暴风雨 | 100% | 1200/s | 180/s | 强雨层，沿用随机闪电及延迟雷声 |

这些是粒子目标发射率，不是现实气象单位。进入遮蔽物后，视觉雨量和音量分别按现有遮挡规则衰减。

## 检查发现与修正

两张测试地图都指定 `FPSGAMEGameMode`，该模式会在运行时创建一个 `FPSWeatherManager`，因此已有雨粒子、音效与自动天气入口。但两张地图都没有 `BP_FPS_DayNightManager`，原有导入光照没有随天气内部时钟变化。

为这两张地图补充运行时光照驱动：使用现有太阳光、天空光和村庄补光，根据同一个天气时钟更新。默认从 09:00 开始，一天维持现有 2160 秒；夜间用弱冷色照明保证基本可见度。村庄固定亮天空球在运行时隐藏，避免午夜仍保持白天天空。检测到原昼夜蓝图时优先同步其时钟，不对该路径重复驱动光照。

原有降雨已经分为三个等级。本次将三个等级分别接入按钮，并修正晴天轻雨音量计算不为零、离开暴风雨后已排队雷声仍可能播放的问题。手动初始状态不再被 BeginPlay 无条件改成自动排程结果。

修改的是项目 C++ 文件及本检查工具；没有保存或覆盖素材包地图、共享子关卡、Niagara 或材质资产。修改前四个现有源码文件保存在 `Saved/WeatherPanel/Backup`。

## 验证方式与边界

`inspect_scene_weather.py` 使用 UE 读取两张测试地图的 Actor 和游戏模式，证据见 `Saved/WeatherPanel/scene-weather-before.json`。其中 DayNight 主地图没有完整展开，不作为该主地图的检查结论；本任务的检查对象是村庄和战壕。

`-WeatherPanelAudit -WeatherPanelCapture` 是仅在显式传入参数时启用的独立游戏验收。它通过真实 UMG 按钮事件依次选择天气，检查单一管理器、角色生成、实际雨量、Niagara 参数、干燥状态音频停止、手动状态保持、恢复自动天气、面板输入占用及恢复，随后加速时钟检查太阳光强变化并截图。测试结束后自动退出。正常游戏不运行这些测试或加速时间。

日志和真实运行截图在 `Saved/WeatherPanel`；最终标记必须是 `WEATHER_PANEL_AUDIT_PASS` 且 failures=0，不能仅凭进程退出码判定成功。编译记录为 `build.log`。

最终结果：编译成功；`L_Normandy_FPS_Test-accepted.log` 和 `L_MilitaryTrench_FPS_Test-accepted.log` 都记录 `WEATHER_PANEL_AUDIT_PASS`、`failures=0`。实测村庄昼夜采样光强范围 1.308–78.574，战壕 96.656–5887.232。已查看两张地图的面板及昼夜运行截图；夜间保留低亮度可见场景。

本检查没有覆盖全部室内遮雨位置、全部地表的湿润材质响应、长时间天气概率分布或人工雷声音质验收。云和地表继续使用现有效果资产；这次没有重制云材质，也未宣称为整个场景所有材质接好了湿润参数。运行日志还存在项目既有 MCP / Python toolset 初始化错误，和本次独立天气检查的通过标记分开记录。
